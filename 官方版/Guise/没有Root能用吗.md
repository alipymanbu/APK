## 一、为什么绕不开 Root

Guise 不是独立应用，而是 Xposed 模块 —— 它必须由框架在目标应用启动时加载进进程，这个加载动作只有 LSPosed（或兼容 Modern Xposed API 的框架）能做，而 LSPosed 又必须装在已 Root 的设备上。官方兼容性表把框架列为硬性条件，四层依赖缺一层都跑不起来：

| 层级 | 你需要有什么 |
| --- | --- |
| Guise 模块 | 本身只是个 APK，装上不生效，等框架加载 |
| LSPosed 框架 | 以 Magisk 模块形式刷入 |
| Zygisk | 在 Magisk 设置里开启 |
| Root 与解锁 | 已解锁 Bootloader，Magisk 或 KernelSU 提供 Root |

环境这块的整体搭建顺序与安装步骤，见[下载与安装教程.md](下载与安装教程.md)。

## 二、「免 root 版」的说法别当真

一些下载站给 Guise 挂「免 root」「无需 root」的标题 —— 这与官方的兼容性要求直接矛盾。还要留意：来路不明的「免 root 特别版」安装包本身就有被篡改的风险，而 Guise 这类工具恰恰要处理设备标识与定位信息，装来路不明的版本得不偿失。要用就用官方发布页或[Guise 安装文件资源（夸克网盘）](https://pan.quark.cn/s/690562d910b8)这类可以核对 MD5 的渠道，核对方法见[下载与安装教程.md](下载与安装教程.md)第二节。

## 三、决定搭环境前先想清楚

- **解锁 Bootloader 通常清空数据**：动手前备份，并按你的机型查清解锁步骤与保修影响 —— 各厂商差异很大，有的机型根本解不了锁。
- **有变砖风险**：刷入不兼容的模块或操作失误可能导致无法开机；先弄清楚你的机型怎么进 Recovery、怎么救砖，再动手。
- **Root 之后部分应用会更敏感**：检测到 Root 后拒绝服务是这类应用的自保逻辑，需要另行权衡与处理 —— 这属于另一套课题，本篇不展开。
