## 一、硬件门槛

官方给出的最低要求是 **2 个 CPU 核心 + 6 GB 内存**，机器学习（人脸识别、智能搜索）、缩略图生成和视频转码都会再吃 CPU、内存和磁盘 I/O，图库大了以后这个数字只增不减。实际选型时注意：

- 存照片视频的目录（`UPLOAD_LOCATION`）要留够容量，且最好在大容量盘上；
- 数据库目录**不支持放在网络共享盘**（NFS/SMB 挂载），也不能用 NTFS/exFAT 这类文件系统，官方口径是本地 SSD + 原生 Linux 文件系统；
- 服务器需要有 Docker 环境和一个可访问的 **2283** 端口（或由反向代理的 80/443 接入）。

容量上另留余量：缩略图与视频转码平均会让图库体积再涨 **10%~20%**（官方口径）；一次性大批量导入（比如从 Google 相册搬家）时，官方工具建议预留约 **1.5 倍源数据**的空闲空间。

具体配置口径以官方 Requirements 页（[docs.immich.app/install/requirements](https://docs.immich.app/install/requirements/)）为准。

## 二、部署步骤（官方 Quick Start 路径）

前提：机器上已装好 Docker Engine 与 Compose 插件（安装方法见 [docs.docker.com/engine/install](https://docs.docker.com/engine/install/)）。

### 1. 建目录并下载两个文件

```bash
mkdir ./immich-app
cd ./immich-app
wget -O docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
wget -O .env https://github.com/immich-app/immich/releases/latest/download/example.env
```

浏览器也能下载这两个文件，但 `example.env` 下载后要改名为 `.env`。

### 2. 编辑 .env

至少要改这几项：

| 变量 | 填什么 |
| --- | --- |
| `UPLOAD_LOCATION` | 照片视频的存放目录，留足空间 |
| `DB_DATA_LOCATION` | 数据库目录，本地盘即可 |
| `DB_PASSWORD` | 换成自己的密码，**只用字母和数字**（`A-Za-z0-9`），不用特殊字符 |
| `TZ` | 取消注释并填时区标识，如 `Asia/Shanghai` |
| `IMMICH_VERSION` | 决定拉取的大版本线，当前已进入 v3；以官方 Quick Start 页当时显示为准 |

### 3. 启动

```bash
docker compose up -d
```

首次启动要拉取多个镜像（服务本体、机器学习、PostgreSQL、Redis），需要等一会儿。

### 4. 注册管理员

浏览器访问 `http://服务器IP:2283`，点 Getting Started 注册第一个账号——**第一个注册的用户自动就是管理员**，后续用户由管理员在后台添加。先在网页端传一张照片确认服务正常，再去装手机端。

## 三、日常更新与版本对应

服务器更新用两条命令：

```bash
docker compose pull && docker compose up -d
```

有一点要记牢：**手机客户端与服务器的大版本要保持一致**（major.minor 相同）。官方 FAQ 明确说过，客户端与服务器版本不匹配时会出现登录不上的情况。升级服务器之前，顺手看看手机端 App 是不是也在同一版本线上，两边一起动。

## 四、别把服务器当唯一副本

官方明确提醒过不要把 Immich 当作照片视频的唯一存放地。服务器本身也需要备份：媒体目录单独留副本、PostgreSQL 数据按官方文档定期导出、有条件再做异地一份。手机端「释放手机空间」这类功能会删掉本机文件，前提就是服务器这一侧是健康且有备份的。
