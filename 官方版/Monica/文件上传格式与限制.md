## 一、三条硬限制

按官方帮助页口径（截至 2026 年，以官方页面为准）：

| 项目 | 上限 |
| --- | --- |
| 单次上传文件数 | 20 个 |
| 单个文件大小 | 20MB |
| 文件内容总量 | 不超过 100K 字符 |

三条同时生效：哪怕只有 1 个文件，只要正文超过 100K 字符也一样会被裁剪或拒收。扫描版 PDF 的问题更特殊，见第三节。

## 二、支持哪些格式

**办公文档**：PDF（`.pdf`）、Word（`.docx`）、Excel（`.xlsx`）、CSV（`.csv`）。

**代码与配置文件**：覆盖常用开发格式——C/C++、C#、Java、Python、Go、Ruby、PHP、JavaScript / TypeScript、HTML / CSS、Kotlin、Swift、Rust、Dart、Lua，以及 JSON / YAML / XML / TOML / INI、Makefile、`.gitignore` 等。

注意两个容易踩的点：

- `.doc`（老版 Word）不在支持列表里，先另存为 `.docx`；
- 传 Excel 做数据分析时，`.xlsx` 可以直接读；如果是 `.xls` 同样需要转换。

## 三、上传失败的原因对照

「上传失败 / PDF 上传不了」基本是下面几种情况，逐条对号：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示文件过大 | 超过 20MB（文档问答口径） | 压缩或拆分文件；扫描版 PDF 尤其容易超 |
| 传上去但答非所问 / 只认前半部分 | 正文超过 100K 字符，超出部分被裁剪 | 拆成多个文件分批问；会员可开全文阅读模式（消耗高级积分） |
| PDF 完全传不上 | 纯图像的 PDF（扫描件）无法按文字解析 | 先用 OCR 工具转成文字版 PDF 再传 |
| 大文件被拒（另一条口径） | 聊天式读 PDF 的入口按 50MB / 100K 令牌拒收 | 不同入口的上限数值不同，以应用内提示为准 |

同一个文件从不同入口传，看到的限制可能不一样——官方不同功能页写的上限（20MB / 50MB）并不统一。碰到拒收时以**当前入口的实际提示**为准，别在两个入口之间反复试。

## 四、超长文档的实用处理

1. **先拆再问**：按章节拆成多个文件，一次问一个主题，比整本传上去的答案更准；
2. **先要目录再深挖**：第一问让它列出文档结构，第二问再指向具体章节；
3. **表格数据别走 PDF**：Excel / CSV 直接传，解析效果比塞进 Word 或 PDF 好得多；
4. **会员的全文阅读模式**：突破 100K 字符裁剪的限制，让模型读到完整原文，但每问都消耗高级积分，长文档反复提问前先算一下额度（见[免费额度与会员说明.md](免费额度与会员说明.md)）。

## 五、传不上时还差一步怎么办

按[常见问题排查.md](常见问题排查.md)第三节处理网络与响应类问题后仍失败，再回头核对本文第三节的对照表——多数「传不上」其实是超限，不是网络问题。功能入口在哪、每种文件适合怎么问，见[功能一览与基础用法.md](功能一览与基础用法.md)。
