## 一、五个工具各自回答什么问题

| 工具 | 它回答的问题 | 典型结论 |
| --- | --- | --- |
| Ping | 目标现在通不通、延迟多大 | 不通 = 目标关机/防火墙拦截/不在同一网段；延迟忽高忽大 = 链路在抖 |
| DNS 查询 | 域名解析成什么、解析服务器有没有出错 | 能 ping 通 IP 却打不开网页 = DNS 的问题 |
| 路由追踪 | 从你到目标经过哪些跳、哪一跳开始出问题 | 第一跳就卡 = 自家路由器；中间某跳开始丢 = 运营商段；末尾不通 = 对方服务器 |
| 端口扫描 | 目标机器上哪些服务开着 | 检查自家 NAS、摄像头的端口是否暴露 |
| WHOIS | 域名归谁注册、什么时候到期 | 查站点归属与 NS 服务器 |

## 二、ping：先分清「网不通」还是「目标不接」

对着一个 IP 或域名发起 ping，几秒内就能拿到可达性与延迟。你按这个顺序测，三步就能把范围缩小：

1. **ping 网关**（地址在 [首页 IP 信息页](WiFi分析仪和局域网扫描怎么用.md) 上，常见是 `192.168.1.1` 或 `192.168.0.1`）——不通说明你到路由器这段就断了，先去重启路由器或查 WiFi 连接；
2. **ping 一个公网 IP**（如 `223.5.5.5` 这类公共 DNS 地址）——网关通、它不通，说明宽带或路由器拨号出了问题；
3. **ping 一个域名**——IP 通、域名不通，问题锁定在 DNS，用下面的 DNS 查询接着查。

读数值：延迟平稳（内网通常 1~5ms、同城公网 10~30ms）就是正常；数值忽高忽低或成片丢包，说明链路在抖，接着用路由追踪找是哪一段在抖。另外注意，有的服务器禁 ping——「ping 不通」不等于「服务器挂了」，要结合端口扫描交叉验证。

## 三、DNS 查询：网页打不开但软件能上网时用它

DNS 查询可以指定记录类型查一个域名：

- `A` / `AAAA`：域名对应的 IPv4 / IPv6 地址，最常用；
- `NS`：这个域名交给哪几台权威服务器解析；
- `MX`：邮箱服务器记录（查域名是否在收邮件用）；
- `TXT`：各种校验记录，域名迁移后 SPF/DKIM 是否生效看它。

两个实战场景：一是「QQ 能上、网页全打不开」——查 `A` 记录没结果或结果是内网地址，就把路由器里的 DNS 换成公共 DNS（改完在 [路由器设置页](路由器设置页打不开怎么办.md) 操作）；二是「改了域名解析半天没生效」——对比不同 DNS 服务器返回的结果，一致了才叫全网生效。

## 四、路由追踪：看清楚卡在自家、运营商还是对方

路由追踪会列出数据包到达目标经过的每一跳：每跳是一个路由器，附带延迟。读法就一句——**看从哪一跳开始延迟飙升或再也不返回**。

- 第一跳（你的路由器）就超时：问题在本地，配合 [WiFi分析仪和局域网扫描](WiFi分析仪和局域网扫描怎么用.md) 查信号与设备状态；
- 中间运营商节点开始丢包：你没法改，记下跳数与时间找宽带客服，这张图就是给客服的证据；
- 末尾几跳才不通：对方服务器的防火墙或负载问题，你这边等它恢复即可。

追踪一个国内站点和一个国外站点各做一次，两者的分叉点基本就是问题段的边界。

## 五、端口扫描与 WHOIS：查自家设备的暴露面

端口扫描对目标主机逐个端口发起连接，返回哪些端口是开放的。典型用法是检查你自己的 NAS、摄像头、路由器有没有把管理端口暴露在外——`80`/`443` 是网页服务，`22` 是 SSH，`21` 是 FTP；家里设备扫出一堆不认识的开放端口，就该去路由器上关掉不必要的端口转发。

边界必须说清：**只扫你自己的设备和你有权限的网络**。对别人的主机做端口探测属于越界行为，本文不提供任何绕过访问控制的做法。

WHOIS 则是对着域名查注册商、注册与到期日期、NS 服务器等公开注册信息，换域名、判断「这个站是不是仿冒」时用得上。

## 六、一条完整排查链

把上面串起来，家里「网页打不开」时你从头到尾这样走一遍：

1. ping 网关 → 不通就查 [常见问题与排查.md](常见问题与排查.md)；
2. ping 公网 IP → 不通就重启路由器、检查宽带；
3. ping 域名 → 不通就 DNS 查询定位，再进 [路由器设置页](路由器设置页打不开怎么办.md) 换 DNS；
4. 都通但某个具体网站不行 → 路由追踪看丢包段，再用 WHOIS 查这个域名的状态。

到这一步，九成以上的家庭网络问题你已经能自己说清楚是哪一段的事了。
