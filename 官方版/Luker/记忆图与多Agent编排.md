# Luker 记忆图与多 Agent 编排开启指南

> 本篇讲 Luker 两个进阶功能怎么开、要额外付出什么代价：记忆图解决角色聊久了失忆，多 Agent 编排让多个角色互相搭戏。两个都会额外消耗 token，先看完成本再决定开不开。

## 一、先判断你需不需要它们

两个功能都不用抢着开。日常闲聊、单人短剧情，普通聊天模式就够；出现下面两种情况再回来翻这篇：

- **角色开始失忆**：聊了几百轮，早期约定的人物关系、世界规则它想不起来了——这是所有大语言模型的上下文窗口限制，不是你卡的问题。记忆图就是为此准备的。
- **想让多个角色同台**：群聊模拟、剧本杀式多角色互动、需要剧情自动推进的长线故事——这是多 Agent 编排的领地。

## 二、记忆图：五分钟开起来

开启路径：打开扩展抽屉 → Memory → 把 Enable 打开。默认配置即可用，真正要动手的只有一件事：**给「写入」和「召回」各指定一套模型配置**，因为这两步都会各自调用一次模型：

| 设置项 | 作用 |
| --- | --- |
| 写入 API 预设 / 写入预设 | 每轮 AI 回复后，从对话里提取值得记住的信息存进图里 |
| 召回 API 预设 / 召回预设 | 你发消息时，从图里找出与当前剧情最相关的记忆注入上下文 |

省钱的关键在这里：**这两步不必用你主聊天的旗舰模型**。写入和召回是结构化的提取、检索活，单独配一套便宜模型的连接（连接管理器里新建一个，见 [API连接与模型配置.md](API连接与模型配置.md)），开销能压下去一大截。

两个值得调的开关：

- **提取间隔（Extraction Interval）**：默认每轮回复都提取。设成 `2` 就是每两条回复提取一次，模型调用直接减半；剧情推进慢的聊天很够用。
- **召回方式**：默认的 LLM 召回最省事——复用你已有的 API 就行；另一种 RAG 召回更快，但要多配向量检索，先不碰它，用顺手了再研究。

## 三、多 Agent 编排：适合复杂剧情，也最烧 token

多 Agent 编排会在正式生成回复之前，先让多个 Agent 做剧情分析和编排，再交给创作模型输出。它有几种执行模式（预设流程、单 Agent、动态日程规划），配置可以绑定到角色卡上、随卡导入导出。

什么时候值得开：

- 群聊里多个角色互相接话、自主对话；
- 长线剧情需要自动推进、场景切换；
- 需要比单轮回复更复杂的思考时，拿来替代思维链。

代价也要清楚：每条回复前的编排流程都是额外的模型调用，**token 消耗明显高于普通聊天**。作者自己的说法是它「比较烧 token」。给编排流程单独配便宜模型、只在需要复杂剧情的聊天里打开，是控制开销的基本做法。

## 四、开了之后剧情记忆更好，但备份习惯别丢

记忆图的节点数据存在 Luker 的数据目录里。重装、换机之前照常整目录备份（方法见 [常见问题与解决方法.md](常见问题与解决方法.md)），记忆和聊天记录一起带走。从酒馆迁来的数据不含这些（它们是 Luker 新增的状态文件），用了一段时间后备份就会包含记忆图内容。

还没配好 API 的先走基础流程：[API连接与模型配置.md](API连接与模型配置.md)。捏卡相关的绑定玩法见 [角色卡导入与创建.md](角色卡导入与创建.md)。
