## 一、能直接播的网络来源

手机和片源在**同一个局域网**内时，下列来源都能在应用里浏览、点开即播，不用先把文件拷进手机：

| 来源 | 说明 |
| --- | --- |
| Windows 电脑共享文件夹 | 电脑上开 SMB 共享后，手机按 IP 连 |
| NAS（群晖、威联通等） | 开 SMB 服务，用 NAS 的账号密码连 |
| Samba / SMB / CIFS 共享盘 | 路由器 USB 口挂的硬盘、各类盒子开的共享都属于这一类 |
| 外接 USB 盘（OTG） | 严格说不是网络，但同样是从文件系统直接读播 |

前提只有一个：片源那边开了共享并且手机能访问到它。

## 二、添加共享的通用步骤

各版本界面入口名称略有出入（一般在主界面往「网络 / LAN」方向的标签里），流程一致：

1. 确认手机与片源设备连的是**同一个路由器**（不少路由器 2.4G 与 5G 是同一网络，没问题；但访客网络会隔离设备，连不上多半是这个原因）。
2. 在应用的局域网页面选「添加服务器 / Add server」，类型选 SMB。
3. 填片源设备的 **IP 地址**（电脑在「设置 → 网络」里查；NAS 管理页里看），账号密码填那台设备上开共享用的登录凭据，没有设访客权限的就填你的登录账号。
4. 保存后点开服务器，逐层进到视频目录点播。

播起来之后可以把这个共享目录设为启动页（设置里可指定 LAN 目录作为打开应用后的默认位置），日常追剧就少一步导航。

## 三、卡顿与起播慢：调缓冲

网络播放的缓冲有三档，官方给的参考量级如下：

| 档位 | 缓冲量级 | 适合 |
| --- | --- | --- |
| 小 | 约 1–3MB | 局域网内千兆 / 信号好，追求秒开 |
| 中 | 约 9–10MB | 一般家庭 Wi-Fi 的常用档 |
| 大 | 约 15–18MB | 信号一般、偶尔卡顿的场景 |

取舍很直接：缓冲越小，点开越快，但网络抖动时越容易卡；缓冲越大，起播等待越久，播起来越稳。播放高峰期卡顿就往大调一档。

另外有一个「高性能 Wi-Fi 模式」，Wi-Fi 流播不稳时可以打开，代价是更耗电；网线直连机顶盒类场景用不上它。

## 四、播 HTTP / RTSP 与 YouTube 地址

- 网络摄像头、电视直播源常用的 HTTP / RTSP 地址，在播放界面的打开 URL 入口里粘进去即可，操作细节见[支持的视频与音频格式](支持的视频与音频格式.md)第二节。
- YouTube 地址同样走这个入口；清晰度偏好设在 Network/Streaming 设置里。
- 直播流卡顿和本地共享卡顿是两回事：直播源卡多半是源服务器的问题，调本地缓冲帮助有限。

## 五、常见连不上对照

| 现象 | 先查什么 |
| --- | --- |
| 搜不到服务器 | 两台设备是否同一网段；电脑防火墙是否拦了 SMB |
| 提示账号或密码错误 | 凭据是片源设备的登录账号，不是应用账号；Windows 微软账号登录的机器常要填完整的微软账号邮箱 |
| 能连上但列表为空 | 共享目录权限是否对该账号开放 |
| 播放中途频繁缓冲 | 缓冲调大一档；离路由器近一点；NAS 硬盘是否在休眠唤醒 |

字幕随片源一起播、不用单独拷的做法，见[字幕设置与自动匹配](字幕设置与自动匹配.md)；后台听声音、弹小窗边看边干别的，见[播放设置与手势操作](播放设置与手势操作.md)。
