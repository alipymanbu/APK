## 一、什么时候需要手动加 Tracker

每个任务详情里都能看到当前连上的节点数与下载速度。速度长期为 0、节点数为 0，多半是任务自带的 Tracker 失效了——Tracker 负责「帮你找到同样在传这个文件的人」。Flud 自带 DHT 兜底，热门资源不靠 Tracker 也能连上；冷门资源 DHT 查不到人，就得手动补。

添加方法：打开任务详情，找到 Trackers（追踪器）一栏，通过该页的添加入口粘贴 Tracker 服务器地址，一条一行，可批量粘贴。入口位置随版本略有差异，以你手机上的实际界面为准。

Tracker 地址从哪来：公开 Tracker 列表有人长期维护，搜索 "public tracker list" 能找到最新的，比如 [ngosang/trackerslist](https://github.com/ngosang/trackerslist) 这类开源列表，把标记为存活的那几条复制进去即可。列表更新频繁，加完几分钟后回任务详情看该 Tracker 的状态是否正常。

列表里常见的几种失败状态及处理：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 超时 / 无响应 | Tracker 没有按时应答 | 等几分钟再看；持续超时就删掉这条 |
| 离线 / 无法连接 | Tracker 服务器挂了或过载 | 换别的公开 Tracker，冷门任务靠 DHT 兜底 |
| 403 / 被拒绝 | Tracker 拒绝了你的请求 | 公开 Tracker 直接删掉这条，换别的 |

## 二、连接类开关各管什么

Flud 支持的这些机制都服务于「让任务连上更多人」：

| 机制 | 作用 | 建议 |
| --- | --- | --- |
| DHT | 不依赖 Tracker，在分布式网络里找节点 | 保持开启，冷门任务的最后保障 |
| PeX | 与已连接的节点交换彼此认识的节点 | 保持开启 |
| µTP | 与受限网络环境下的节点协商传输 | 保持开启 |
| UPnP / NAT-PMP | 自动在路由器上开端口 | 家用路由器环境保持开启 |

这些开关都在 设置 → 网络（Network） 相关分组里（名称以实际界面为准）。能连上的人多，速度才有可能上去；速度问题先过一遍 [下载慢与常见问题排查.md](下载慢与常见问题排查.md) 的症状表。

## 三、加密与代理

- **加密（Encryption）**：与节点之间的传输可以要求加密，一般提供「关闭 / 启用 / 强制」三档，默认在「启用」（对方支持才加密），入口在 设置 → 网络（Network）。如果网络环境对 BT 流量有干扰，调到「强制」让全部传输走加密，有用户反馈这样能恢复速度；强制的代价是可连节点变少，速度可能反而下降，两头都试。运营商在流量网上限 BT 的完整应对见 [流量下载被限制怎么办.md](流量下载被限制怎么办.md)。
- **代理（Proxy）**：可以给 Tracker 与节点连接配置代理，类型按你手上的代理服务为准（如 SOCKS5）。配好后到任务详情看 Tracker 状态确认是否连通。
- **IP 过滤（IP filtering）**：加载 IP 黑名单文件，把某些地址段排除在连接之外，属于进阶用法，普通下载用不上。

## 四、端口那些事

主动连接能力取决于路由器是否放行你的监听端口。UPnP 能自动处理大部分家用环境；如果任务能连上 Tracker 但节点数始终个位数，多半是端口不通——先确认路由器的 UPnP 开着，或手动把 Flud 设置里显示的监听端口在路由器上转发到手机（手机需要固定内网 IP）。校园网、公司网这类大内网通常做不了端口转发，只能靠 DHT 与可连通的节点。
