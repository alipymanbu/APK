# WebToApp 预览正常但导出后失效怎么办

> 本篇针对一种很具体的落差：在构建器里预览一切正常，构建成 APK 装到手机上以后，某个功能没了、行为变了。讲清成因与逐项核对方法。

「预览好好的，装上就不对」是这类打包工具最常见的一类疑问。原因不神秘：**预览是在构建器里直接跑你这套配置，而导出后的 APK 独立运行，按你保存下来的那份配置去加载内容**。落差就出在「配置与素材有没有完整带过去」这道关卡上，所以排查方向不是怀疑网页，而是核对配置与素材。

## 一、落差只可能来自这四个环节

| 环节 | 典型表现 |
| --- | --- |
| 配置没保存就被拿去构建 | 改了开关、切回列表直接构建，改动没带上 |
| 素材没随包一起带走 | 本地 HTML、图片、字体、脚本注入的内容在导出后不存在 |
| 权限被裁剪 | 摄像头、定位、存储类能力预览时靠构建器的权限在跑，导出后没有对应授权 |
| 运行环境差异 | 预览用的是构建器当前环境，导出应用在目标手机上遇到不同的系统版本或内核 |

## 二、逐项核对清单

按顺序过一遍，每一步都能给出「是 / 否」的判断：

1. **改完配置是否先保存再构建**。这是最常被跳过的一步 —— 编辑界面里的改动需要保存后才进入应用定义，直接从列表点构建会用到旧的那一份。
2. **本地素材是否真的在包里**。凡是引用本机文件的配置（本地 HTML、离线内容、图片、字体、注入脚本），在手机上换一台设备或删掉原文件后就应该仍然生效；如果只在原机原目录下能用，说明素材是被引用而非被打包。
3. **权限类功能是否给了导出应用**。摄像头、麦克风、定位、文件读写这些，导出应用在目标手机上要单独授权，而且目标站点需要是 HTTPS 才不会被系统直接拦下。
4. **注入的脚本与模块是否都启用了**。注入类配置有生效时机与开关，漏开一项就不生效，详见 [扩展模块与脚本注入怎么用.md](扩展模块与脚本注入怎么用.md)。
5. **加密与隔离这类强约束选项是否改变了行为**。启用后会强制全量重建，也让运行环境与默认状态不同；先关掉构建一版做对照，能快速判断是不是这两项引起的。

## 三、一个高效的对照试验

不确定是哪一项导致的，用**二分法**定位，比逐项猜快得多：

1. 关掉全部可选功能（加密、隔离、后台运行、通知、脚本注入），用默认值构建一版，装到真机上验证；
2. 如果这一版正常，说明问题出在某个可选功能上 —— 每次只打开一项，构建、安装、验证，直到复现；
3. 如果连默认配置都不正常，说明问题在更底层（网页本身、权限、系统版本），按 [构建失败与安装报错怎么排查.md](构建失败与安装报错怎么排查.md) 第五节处理。

这个过程看起来笨，但它保证你每次只引入一个变量。反过来先全开、再一个个关，复现与排除都会慢得多。

## 四、把验证固定在真机上

预览只是节省时间的前置检查，**真正的验收标准是装到真机上的表现**。建议每次只对这几种情况做预览：确认目标网址能打开、确认新加的注入脚本没把页面改坏。其余关于权限、通知、后台运行、加密的实际效果，一律以真机安装后的表现为准。

另外，导出的应用一旦装到手机上，它就是独立应用了 —— 之后再改配置，需要重新构建并覆盖安装才会生效，改的是哪一项可以对照 [包名图标与签名怎么设置.md](包名图标与签名怎么设置.md) 里关于版本号与签名的说明确认能不能覆盖安装成功。
