给打包出来的应用加功能，最直接的办法就是往网页里塞一段自己的脚本或样式。这在 WebToApp 里有两条路径：**自己写注入**，或**安装现成的扩展模块**。前者灵活、只针对一个应用；后者拿来即用、可以复用到多个应用。搞不清该走哪条，就容易重复造轮子或者在错误的位置找开关。

## 一、两条路径的区别

| 做法 | 在哪里配 | 适合什么 |
| --- | --- | --- |
| JS/CSS 注入 | 应用的注入类配置卡片 | 一小段只服务这个应用的脚本或样式，比如隐藏某个碍事的横幅 |
| 扩展模块 | 应用的扩展配置 + 模块市场 | 通用能力（暗色模式、内容增强、隐私处理等），可复用到多个应用 |

两条路径可以同时用。冲突时的表现通常是「后加的覆盖先加的」，所以不要把同一个改动同时写在两处。

## 二、JS/CSS 注入：先选对生效时机

注入最关键的选项是**时机**。时机选错，脚本会因为目标元素还不存在而静默失效 —— 这是注入类问题里最常见的一种。

| 时机 | 什么时候执行 | 适合做什么 |
| --- | --- | --- |
| `document-start` | 页面刚开始加载时 | 需要抢在页面脚本之前做的改动，例如改 `navigator` 上的属性、提前注入样式 |
| `document-end` | 页面结构解析完毕后 | 操作 DOM 元素，例如隐藏某块区域、改按钮文案 |
| `idle` | 页面空闲时 | 不着急的收尾处理，例如延迟加载的模块再执行一次 |

把这段脚本放进注入配置，就能给应用的所有页面套上深色底：

```javascript
(function () {
  var style = document.createElement('style');
  style.type = 'text/css';
  style.innerHTML = 'html, body { background: #121212 !important; color: #e0e0e0 !important; }';
  document.head.appendChild(style);
})();
```

这段依赖 `document.head` 已经存在，所以应选 `document-end` 或 `idle`，选 `document-start` 可能拿不到 `head`。

## 三、扩展模块与模块市场

WebToApp 自带一组内置模块，并提供一个**模块市场**用来安装社区贡献的 JS/CSS 模块。除了模块形式，扩展体系里还支持油猴脚本和 MV3 格式的浏览器扩展，也就是说你在浏览器上已有的脚本资产有相当一部分可以直接搬过来。

使用时注意两点：

- 模块装好后还要在**目标应用上启用**，装了不等于生效；
- 内置模块通常带有对应模板，模板给的是可工作的起点，改之前先跑通一遍再动它。

## 四、内核会直接决定这些功能有没有

一个容易被忽略的前提：**在 GeckoView 内核下，广告拦截、JS/CSS 注入、自定义注入脚本、用户脚本、Chrome MV3 扩展一律不生效**。这不是设置漏了，而是该内核不提供对应能力。所以配置了注入却在导出后毫无反应时，先回去确认构建对话框里选的是不是系统 WebView，判断方法见 [浏览器内核选WebView还是GeckoView.md](浏览器内核选WebView还是GeckoView.md)。

另外，**开启资源加密的 HTML / 前端离线包类应用必须使用系统 WebView 内核**，加密与 GeckoView 无法同时成立。

现成的油猴脚本与 Chrome 扩展怎么搬进来，见 [油猴脚本和Chrome扩展怎么导入.md](油猴脚本和Chrome扩展怎么导入.md)。

## 五、边界：注入改不动的地方

- **网页用内嵌框架（iframe）承载主要内容时**，注入往往只作用于外层页面，框架内部拿不到；
- **网页自身设置了严格的内容安全策略时**，某些内联脚本会被挡下，表现为写了没反应；
- **广告拦截与注入是两套规则**，各自独立。排查「明明加了脚本却没效果」时，先确认不是广告拦截把目标域名一并拦掉了；
- **不要试图用注入绕过登录、付费或站点的访问限制**，这类用法既不稳定也不属于正常使用范围。

## 六、注入不生效怎么查

按这个顺序走，每一步都能收敛范围：

1. **确认生效时机**：把 `document-start` 改成 `document-end` 再试一次，这是排查成本最低的一步；
2. **确认内核是系统 WebView**：GeckoView 下注入类功能整体不生效，见 [浏览器内核选WebView还是GeckoView.md](浏览器内核选WebView还是GeckoView.md)；
3. **确认脚本真的被带进产物**：预览里生效、装上不生效的情况，按 [预览正常但导出后失效怎么办.md](预览正常但导出后失效怎么办.md) 核对配置是否保存、素材是否随包带走；
4. **用最小脚本验证**：先只留一行最直接的改动（例如改个背景色），确认注入通道本身是通的，再逐步加回你的逻辑；
5. **确认没有语法错误**：脚本里一处语法错误会让整段不执行，且不报错。

改完注入记得重新构建才能生效，流程见 [把网站打包成APK的完整步骤.md](把网站打包成APK的完整步骤.md)；构建时报错则看 [构建失败与安装报错怎么排查.md](构建失败与安装报错怎么排查.md)。
