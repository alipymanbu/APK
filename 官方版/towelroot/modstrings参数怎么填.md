modstrings 是作者给「冷门机型」留的后门：默认参数提不了权的机器，手动改漏洞参数再试。口径全部来自官方说明页 [towelroot.com/modstrings.html](https://towelroot.com/modstrings.html)（截至整理时仍可访问），不是社区猜测。

## 一、什么时候才用 modstrings

先说清楚边界：它只服务于**默认方式失败**的机器 —— 界面提示 `This phone isn't currently supported` 才轮到它。机型本身在不在支持范围，先用 [支持的机型与系统条件.md](支持的机型与系统条件.md) 的自查清单判断；流程性故障（闪退、没重启）先按 [常见问题与风险说明.md](常见问题与风险说明.md) 排查。

## 二、打开入口

1. 打开 towelroot，停在主界面；
2. 连点三下「Welcome to towelroot v3」这行欢迎文字；
3. 弹出一个输入框，把参数串填进去，点 make it ra1n。

## 三、参数格式：六个位置

官方定义的格式是：

```text
1337 method(0-3) align(0-1) limit_offset(0-8191) hit_iov(0-7) temp_root(0-1)
```

各位置的含义（照官方注释翻译）：

| 位置 | 取值 | 管什么 |
| --- | --- | --- |
| 第 1 位 | 固定 `1337` | 固定开头，不变 |
| method | 0~3 | 阻塞线程走哪个系统调用，官方建议全部试一遍 |
| align | 0~1 | iovs 用哪种内存对齐，也全部试一遍 |
| limit_offset | 0~8191 | `0` 大概率就是对的；要改的话取接近三星机型用值、且是 4 的倍数 |
| hit_iov | 0~7 | 覆写哪个 iov 来造成阻塞 |
| temp_root | 0~1 | 做一次**临时** Root：把 su 与 daemonsu 放进 /sbin，对 HTC、Motorola 机型有用，但不修复漏洞本身 |

## 四、官方给的现成参数串

| 参数串 | 官方标注的适用面 |
| --- | --- |
| `1337 0 1 0 4 0` | 大多数机型 |
| `1337 0 1 7380 4 0` | 较新的三星机型 |
| `1337 0 1 0 4 1` | 临时 Root（重启后 Root 失效） |

## 五、按什么顺序试

官方的建议是：**align 与 method 最值得调**（2 × 4 = 8 种组合），hit_iov 可以一试，limit_offset 实在没辙再动 —— 而且 `0` 优先，其次才考虑接近三星值、4 的倍数。

实际操作就三句话：

1. 先把官方三组现成串逐个试完，每组点一次 make it ra1n；
2. 不行再按「固定 align 换 method → 换 align → 试 hit_iov → 最后动 limit_offset」的顺序穷举；
3. 全部试完仍提示不支持，就基本可以认定这台机器与它无缘，不必再耗 —— 换 [现在还能用吗.md](现在还能用吗.md) 里说的其他路线。

`temp_root` 那一路要单独知道一件事：它是**临时的**，重启后 Root 就没了。适合 HTC / Motorola 这类难啃的机型先进去看看，或者只想临时用一次 Root 权限的读者。
