这一篇把用 towelroot 时最容易卡住的几个点按「先排查什么」排好序，再把动手前该想清楚的风险一次说全。

## 一、点了 make it ra1n 没反应或闪退

最常见的原因：这台机器的内核已被修补或本就不受影响，提权没成功 —— 表现为应用崩溃或手机自动重启一次。处理顺序：

1. 重启一次手机，再试一回（排除偶发因素）；
2. 仍不行就基本可以认定不在支持范围，按 [支持的机型与系统条件.md](支持的机型与系统条件.md) 的自查清单核对内核日期；
3. 确认不在范围就换其他 Root 方案，不必反复点。

## 二、提示 This phone isn't currently supported

官方 v3 内置了一个叫 **modstrings** 的手动参数入口，给默认参数打不开的机器用：

1. 在主界面连点三下「Welcome to towelroot v3」这行字，会弹出一个输入框；
2. 填入参数串 —— 网上流传的几组如 `1337 0 1 0 4 0`、`1337 0 1 7380 4 0`、`1337 0 1 0 4 1`，一组一组试；
3. 每填一组点一次 make it ra1n。

参数与机型强相关，没有放之皆准的答案。六个参数位各自管什么、官方给的现成参数串、按什么顺序穷举，官方说明页 [towelroot.com/modstrings.html](https://towelroot.com/modstrings.html) 有原始定义，整理版见 [modstrings参数怎么填.md](modstrings参数怎么填.md)。

## 三、Root Checker 显示没有 Root

按顺序核对：

1. 点按钮后手机**有没有自动重启过** —— 没重启说明提权流程根本没走完；
2. 内核构建日期是否早于 2014-06-03（见 [支持的机型与系统条件.md](支持的机型与系统条件.md)）；
3. 换一个检测应用再试 —— 不同检测应用的判定实现有差异，个别误报存在。

## 四、会不会把手机弄坏

公开反馈里，不支持的机型点按钮的常见结果是闪退或自动重启一次，成规模的「因 towelroot 变砖」反馈没有见到。但 Root 本质上是在改系统：成功之后误删关键系统应用、误改系统分区，一样能把机器折腾出问题。两条底线：动手前备份；不认识的授权一律拒绝。

## 五、保修与 Knox 的两种说法

- **保修**：Root 通常被厂商视为影响保修的操作，动手前把这一点当作既定代价来考虑，不要事后才想起；
- **Knox（三星机型）**：两种口径并存 —— 不少用户反馈 towelroot 这类内核提权**不会**触发 Knox 熔断置位；安全厂商的分析则提到在 Knox 环境里该漏洞利用会触发保护警报。如果你在意 Knox 状态，先去查自己这个具体型号的实测反馈，不要只听其中一种说法。

## 六、Root 之后的安全代价

- 没有权限管理时，任何应用要 Root 都拿得到 —— 成功后第一时间装 SuperSU，步骤见 [Root成功后的权限管理.md](Root成功后的权限管理.md)；
- 不安装来历不明的 apk、不点陌生链接 —— Root 状态下恶意应用的破坏力被放大；
- 部分官方系统更新（OTA）在 Root 状态下会失败或被跳过 —— 官方更新多为差分升级，要对 boot、system 这些分区做一致性校验，Root 动过就装不上或装到一半报错（XDA 社区指南与 TWRP 官方文档的口径一致）。想走官方升级，先解除 Root 或刷回官方固件，再收更新。

## 七、想退回去怎么办

装了 SuperSU 的，用它自带的「完全清除 Root（Full unroot）」功能走一遍，移除 su 相关文件、恢复常规权限模型；更彻底的办法是刷回对应机型的官方固件。两点预期要摆正：

- 解除 Root 不等于完全复原：bootloader 未必重新上锁，Knox 一类熔断标记通常也不会复位（第三方整理的口径）；
- 厂商侧有官方恢复通道 —— 例如华为为已 Root 的设备提供了手机助手系统修复与 eRecovery 恢复模式的官方指引，其他品牌以各自支持页为准。

解除后再检查一次系统更新是否恢复正常。要不要退，取决于你后续还用不用 Root 权限 —— 只是想清理预装、清完就收手的，解除 Root 是更稳妥的收尾。今天还在犹豫新机器要不要折腾的，先看 [现在还能用吗.md](现在还能用吗.md) 的现状分析。
