# ONPatch 与 LSPatch 的区别及版本说明

> 搜 ONPatch 的人十有八九会同时撞见 LSPatch、LSPosed 这些名字。本篇讲清它们是什么关系、免 Root 和需 Root 两条路线怎么选，以及本文档采用的 0.6.1 版本口径。

## 一、家族关系：一条线传下来的三样东西

把这几个名字捋清楚，选型就不纠结了：

| 名称 | 需要 Root 吗 | 干什么的 | 现状 |
| --- | --- | --- | --- |
| LSPosed | 需要 | 完整的 Xposed 框架，系统级生效 | 需 Root 设备的主流方案 |
| LSPatch | 不需要 | LSPosed 团队出的免 Root 版，把模块打进目标应用 APK | 官方仓库 2023 年底已归档停更 |
| ONPatch | 不需要 | LSPatch 思路的社区延续版本之一 | 持续有版本更新 |

也就是说，ONPatch 走的是 LSPatch 开创的免 Root 路线，包名（`org.lsposed.onpatch`）也带着 LSPosed 家族的印记；上游停更后，这类社区衍生版本接过了更新。它基于 GPL-3.0 开源体系，这也是各衍生版本能合法延续改进的前提。

## 二、免 Root 路线和 Root 路线怎么选

两条路线服务的是完全不同的设备状态：

- **手机没 Root、也不打算 Root**（锁 Bootloader 的主力机大多如此）：只有 ONPatch / LSPatch 这条免 Root 路线可用，代价是每个目标应用都要单独修补，修补后签名变化带来的重装、数据备份问题也要自己处理（见[模块注入与修补模式详解](模块注入与修补模式详解.md)）。另外，少数对「应用是否被修改」检测严格的应用（银行、支付类）修补后可能无法正常使用，这类就别修补了；
- **手机已 Root**（装了 Magisk / KernelSU / APatch 之类）：直接上 LSPosed，模块全局勾选作用域即可，不需要逐个修补应用，也不用忍受「应用更新就要重新修补」的循环。

一句话：**Root 是更省事的方案，免 Root 是不动系统的方案**。如果你的设备能 Root 且愿意折腾，LSPosed 体验更好；主力机求稳，就用 ONPatch 这类免 Root 工具，把修补范围控制在少数几个应用上。

## 三、版本口径：为什么网上找不到 0.6.1 的介绍

本文档写的 ONPatch 安装文件是 **0.6.1** 版（约 4.63 MB，包名 `org.lsposed.onpatch`），而大量中文下载站至今挂着的还是 **0.0.7** 的旧包，两个版本之间隔了相当长的开发距离，界面和功能都有差异。如果你按别处教程找不到文中提到的某个选项，先核对自己装的是哪个版本——核对 MD5 的方法见[下载与安装教程](下载与安装教程.md)。

这类工具版本号变动快、发行渠道分散，文中关于界面与选项的描述都基于上述版本，后续新版本如有出入，以你实际看到的界面为准。
