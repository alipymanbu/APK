# ONPatch 修补应用前后的数据备份与恢复

> 修补要卸载重装，重装就丢本地数据——这是免 Root 修补方案绕不开的代价。本篇讲动手前怎么把数据留住、修补装好后怎么恢复。

## 一、先弄清哪些数据会丢

修补生成的 APK 与原应用签名不同，系统要求先卸载原应用才能装修补版。卸载删掉的是**手机本地的应用数据**：

| 数据类型 | 卸载后的命运 | 原因 |
| --- | --- | --- |
| 云端有同步的（聊天记录云备份、游戏账号存档、网盘笔记） | 不丢 | 数据在服务器，重新登录即回 |
| 只存本地的（未同步的聊天记录、本地记事、离线缓存、单机游戏进度） | **会丢** | 随应用卸载被系统删除 |
| 登录状态 | 要重新登录 | 会话凭证随卸载清除 |

动手前逐个过一遍你准备修补的应用：它的关键数据在云端还是只在手机里。这一步在[模块注入与修补模式详解](模块注入与修补模式详解.md)的注入流程里排第一，不是走形式。

## 二、动手前的三条备份途径

1. **应用自带的云同步 / 迁移功能**：优先走这条。聊天类应用基本都有「聊天记录迁移/备份」，游戏看有没有绑定账号与云端存档；确认同步完成后（别只点了个开始）再卸载；
2. **系统自带的整机备份**：部分系统的备份功能能连应用数据一起备份，但恢复时通常面向「整机恢复」，对单个应用恢复不一定友好，作为兜底而不是主力；
3. **手动导出关键文件**：文档、下载的文件这类散装数据，直接复制到手机共享存储或电脑上，装好再拷回来，最简单也最可控。

判断标准就一条：**卸载之后，这块数据还能不能从别处完整找回来**。答不上来的，先导出一份再说。

## 三、修补装好后的恢复

装修补版的流程（先卸载、再安装）见[常见问题与报错处理](常见问题与报错处理.md)第一节，装好之后：

1. 打开应用，先登录账号，让云端数据同步下来；
2. 打开应用里的同步/恢复选项，把云备份的聊天记录、存档拉回来；
3. 手动导出过的文件，拷回应用可见的目录（个别应用要在自己的设置里「导入」）；
4. 验证关键数据完整后再继续启用模块——模块引起的问题和数据恢复的问题要分开处理，混在一起排错会很乱。

## 四、几类应用的处理建议

- **聊天类（微信、QQ 等）**：几乎必碰，聊天记录本地存储占比高，务必先用应用内的迁移功能把记录迁到电脑版或另一台设备，修补装好后再迁回来；
- **单机游戏**：进度多半只在本机，找「绑定账号/云存档」入口；实在没有云存档的游戏，权衡一下要不要修补；
- **银行、支付类**：这类应用对签名与完整性检测严格，修补版本来就可能无法正常使用，不建议对它们动手，也就不存在备份问题；
- **工具类小应用**：数据量小的话，导出配置文件往往几分钟就搞定，修补成本最低。

备份、恢复都做完了还有异常，去[常见问题与报错处理](常见问题与报错处理.md)对号入座。
