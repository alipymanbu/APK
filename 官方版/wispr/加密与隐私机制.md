## 一、VOBP：官方给加密体系起的名字

Wispr 的加密与校验框架叫 **VOBP**（Voice Over Blockchain Protocol），由开发商 CryptoDATA 自研。按官方 FAQ 的描述，它在产品里的作用可以拆成三句话：

- 消息、语音/视频通话、文件传输、共享位置全部端到端加密；
- 加密密钥只在你自己的设备上生成，不上传给 Wispr 或任何中心服务器；
- Wispr 自己也无法解密你的通讯内容。

第三点是关键：官方的定位是「连官方都读不到」，至于实际信任程度，你可以自行参考其隐私政策与条款，本文只转述官方口径，不做背书。

## 二、密钥的生命周期

理解几个时间点，能避免最常见的误解：

| 时机 | 密钥发生什么 |
| --- | --- |
| 安装并使用应用时 | 你的设备自动生成加密密钥 |
| 日常使用 | 密钥只存在本地，不向服务器上传 |
| 卸载应用 / 恢复出厂 / 抹除数据 | 密钥永久删除 |

由此带来一个必须接受的代价：**设备丢失或应用被删后，数据无法恢复**。官方明确表示不能帮你找回——没有密钥就没有内容。所以重要的聊天记录和文件，请在应用外自行做好备份（具体操作见[聊天记录备份与迁移](聊天记录备份与迁移.md)）。

另外两点细节值得知道：按官方说明，**密钥会随每一条消息变化**，不是一条会话用一把固定钥匙；如果你想**确认当前会话没有被中间人替换**，官方 FAQ 提到可以在设备上核对安全验证码——你与对方看到的验证码一致，才说明这条链路两端确实是你们双方。核对入口在具体对话的安全设置里，位置以应用内实际界面为准。

## 三、P2P 直连与中继的关系

Wispr 默认采用点对点（P2P）通讯：消息、通话、文件直接在两台设备之间传输，不经过中心服务器转发。官方给的理由是减少中间环节与元数据暴露。

但 P2P 不是万能的——防火墙、NAT 等网络条件下，两台设备可能直连不上，这时会借助中继（relay）帮忙搭线。要点是：

- 走中继时，内容仍然是端到端加密的，中继读不到你在说什么；
- 中继影响的是连接质量（延迟、成功率），不是保密性。

如果你的网络对 P2P 端口限制严格，直连握手可能反复失败——排查步骤单独写成了一篇，见[连接失败排查](连接失败排查.md)。

## 四、区块链在这里做什么

VOBP 里的「Blockchain」不是拿来存消息的。按官方 FAQ 的说明，消息内容从不上链；区块链承担的是信任层：

- 注册两台设备之间安全会话的建立事件，用于防中间人攻击；
- 确认公钥与用户/设备的对应关系，防止身份伪造；
- 密钥轮换、会话变更等事件被不可篡改地记录，但不暴露隐私信息。

一句话总结：**内容走端到端加密与点对点传输，区块链管「你是你、对方是对方」这件事**。

## 五、官方能看到什么、看不到什么

把官方隐私政策与 FAQ 里的口径汇总成一张表：

| 数据 | 官方能否接触 |
| --- | --- |
| 消息、通话、文件内容 | 端到端加密，官方声明无法解密 |
| 加密密钥 | 存在你设备上，官方不持有 |
| 头像 | 存储在官方服务器，其他用户可见 |
| 昵称等可选资料 | 官方称端到端加密，仅你和联系人可见 |
| 手机号、用户 ID 等账号信息 | 你注册时提供，官方持有 |
| 发送时间、会话双方 ID 等有限元数据 | 官方持有 |
| 离线排队消息 | 加密暂存，送达后服务器删除副本 |
| 媒体消息 | 中继服务器加密保留最长两周 |
| 通讯录匹配 | 可选功能，联系人数据转成哈希后用于比对谁也在用 Wispr |

两点补充：一是首条联系请求必须被对方接受，原因就是密钥交换必须完成，否则你的设备解不开任何后续内容；二是官方对执法调取的口径是「仅在有法律义务并附正式文件时按个案处理，且因技术设计协助能力极其有限」——这属于官方单方陈述，你自己权衡采信程度。
