## 一、Chat 与 Agent 的分工

| | Chat | Agent |
|---|---|---|
| 干什么 | 问答、总结、改写、翻译、头脑风暴、按上下文生成内容 | 理解任务 → 制定计划 → 调用工具 → 检查结果的多步工作 |
| 会不会动你的文件 | 不会，只产出对话内容 | 会在你授权后读写笔记、文件夹、记录 |
| 什么时候用 | 「帮我把这段改短」「列个大纲」 | 「把这三条记录整理进周报并更新目录」 |

不确定用哪个时先用 Chat；要它实际动手改东西，再切 Agent。

## 二、一次请求可以带上什么

请求不只有你敲的那句话，工具栏还能挂上：

- 当前输入和历史消息；
- **关联标签**里的记录（把某批素材直接塞进上下文，配合[记录与整理成笔记教程.md](记录与整理成笔记教程.md)的标签用法）；
- 选中的文件或文件夹、编辑器里选中的文字段；
- 图片附件、知识库检索片段、网络搜索结果及来源；
- 与问题匹配的记忆和 Skills。

工具栏本身可配置：模型、Prompt、回复语言、关联标签/文件、MCP、知识库、网络搜索、剪贴板监听、新对话、上下文清理——用哪个模型在[AI模型配置与切换教程.md](AI模型配置与切换教程.md)里配，这里只负责选。

## 三、Agent 能动什么，你要确认什么

Agent 的内置工具覆盖：读取/创建/修改 Markdown，新建与管理文件夹，查询与管理标签、记录和聊天，保存与检索长期记忆，获取系统与工作区信息，以及调用已启用的 MCP 工具。

把关规则：

- **只读和修改的风险不同**：需要时会弹确认面板，你可以允许一次、本会话允许，或拒绝；
- 改编辑器内容先显示 **Diff**，接受才写入，拒绝保留原文；多文件任务在变更面板逐项审阅；
- **删除、覆盖、调用外部工具前**，先看清目标和参数再点确认。

运行过程中你能看到计划、时间线、工具参数和执行结果。失败的任务可以在保留上下文的情况下继续；长任务有运行状态和等待队列，执行期间还可以追发补充要求——但如果目标或范围已经跑偏，**先停掉当前任务**，用更明确的约束重新开始，别指望它自己拐回来。

## 四、回答变乱、变贵时怎么收拾

- **新对话**：开独立会话，旧会话留在历史里；
- **清除上下文**：后续请求不再带此前消息，界面历史仍可见；
- **清空对话**：直接删掉当前会话的消息；
- **自动摘要**：长对话到阈值会压缩旧消息省 Token；
- **上下文托盘**：查看当前关联了哪些文件、记录、记忆、知识库和工具。

一条实用判断：**上下文越多不一定越准**。回答开始前言不搭后语、Token 花得心疼、或者总被旧信息带偏时，先减少关联文件、关掉不必要的知识库和 MCP，再不行就开新对话。

## 五、MCP、Skills、知识库、记忆、网络搜索各是什么

| 能力 | 作用 |
|---|---|
| MCP | 连接外部工具和服务 |
| Skills | 为特定任务提供可复用指令和允许的工具 |
| 知识库 | 从工作区向量索引检索相关片段 |
| 记忆 | 跨会话加载偏好，或按语义匹配事实 |
| 网络搜索 | 检索当前公开网页并返回来源 |

这些能力能组合使用，但每加一项，模型能看到的数据范围就扩大一圈——处理敏感内容前先把用不上的关掉。移动端只支持 HTTP 形态的 MCP，本地命令型 MCP 仅桌面端可跑（见[常见问题与故障排查.md](常见问题与故障排查.md)「手机端用不了的功能」）。

## 六、把 AI 的回复变成笔记

AI 回复可以直接**复制、朗读、翻译、查看模型信息**，也能**保存为记录或输出到笔记**——最后这条是对话和写作之间的桥：让 Chat 起草、存成记录或 md，再进编辑器接着改，正好接上「先记录、再整理、后成文」的完整链路。
