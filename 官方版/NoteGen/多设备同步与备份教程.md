## 一、不开同步也完全能用

NoteGen 是本地优先的：笔记和附件默认存在本机，没网也能记录、浏览和写作，文件就是**标准的 Markdown 文件**，不用打开 NoteGen 也能用别的编辑器读。同步只是「需要第二台设备时」的可选项，不是必需品。

## 二、六种同步方式怎么选

| 方式 | 适合谁 | 要准备什么 |
|---|---|---|
| GitHub | 有 GitHub 账号、想顺带拿版本历史 | 私有仓库 + 访问 Token |
| GitLab | 用 GitLab 的人 | REST API，Token 需要 `api` 权限 |
| Gitee | 国内网络环境（第三方介绍普遍推荐） | 私有仓库 + Token |
| Gitea | 自建 Gitea 实例 | 服务地址要填对 |
| S3 兼容对象存储 | 已有对象存储桶 | 存储桶与路径前缀 |
| WebDAV | 网盘/自建 WebDAV | 账号密码或地址 |

此外还支持**自托管 NoteGen Server**：同步服务和数据都放在自己手里（官方口径）。选型原则就一条：你本来就稳定在用哪个，就接哪个——同步目标是你要自己维护的。

## 三、GitHub 私有仓库怎么配

1. 在 GitHub **建一个私有仓库**（第三方使用教程普遍建议私有：笔记是私人内容，公开仓库等于公开发布）。
2. 生成访问 Token：已有的仓库通常只需要 **Contents 读写**权限；如果你打算让 NoteGen **替你新建仓库**，还要加上 **Administration 读写**。
3. 在「设置 → 同步配置」里填仓库地址和 Token，直到平台显示**「已连接」**才算配成。
4. 检查 Token 权限、仓库名、路径前缀——这三项是最常见的连不上的原因（详见[常见问题与故障排查.md](常见问题与故障排查.md)「同步失败或发生冲突」）。

## 四、要不要开「记录与配置自动同步」

开了它，记录、标签、聊天和允许同步的设置会跟着笔记一起上传。新设备上第一次开启时**先想清楚方向**：是把本机内容上传，还是从远程拉取——开反了会把一边覆盖掉。另外注意：工作区路径这类设备专属配置默认不跨设备同步，换机后要重设一遍。

## 五、冲突了怎么办

同一份笔记在两台设备都改过，同步就会报冲突，给你三个选项：

- **合并两边新增内容**——最安全，推荐先试这个；
- **远程覆盖本机** / **本机覆盖远程**——快，但会丢掉被覆盖那一侧没同步的修改。

动手前先导出一份本地 ZIP 备份（见下一节），确认没问题再覆盖。冲突频发通常意味着两台设备的同步方向或时间没理顺，回到第四节重新规划。

## 六、不开云同步的备份办法

1. **导出 ZIP**：排查文档建议在出问题前先保留本地导出的 ZIP——它也是降级后恢复的首选（新版数据库可能不被旧版兼容，恢复要用兼容版本创建的 ZIP）。
2. **直接拷工作区**：笔记就是普通文件夹里的 `.md` 文件，整夹复制即是一份完整备份；换电脑也可以先手动拷过去，再决定要不要开同步。
3. **版本历史**：有第三方介绍提到同步带有历史回滚能力，能把改动退回之前的版本——是否可用以你手上版本的界面为准。

## 七、开了同步之后的隐私边界

同步目标是你自己选的服务（GitHub、Gitee、对象存储……），上传内容是记录、标签、聊天与允许同步的设置。处理敏感笔记时：要么用私有仓库且不开「记录同步」只手动备份，要么干脆只留本地——选择权在你，数据在哪个服务上就受哪个服务的规则约束。
