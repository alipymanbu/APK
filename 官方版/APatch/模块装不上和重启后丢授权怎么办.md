# 模块装不上和重启后丢授权怎么办

> 三个高频故障的官方处理办法：模块报 os error、升级后模块全没、重启后 root 授权错乱。

## 一、模块装不上，报 os error 2 / 5 / 22

官方 FAQ 给的答案只有一句，但很管用：**到 root 授权页面，把 `shell` 的 root 权限取消掉**，再重新安装模块。

这三条报错是操作系统层面的错误码，别急着怀疑模块本身——先按上面这条改授权，多数情况就装上了。改完再试，仍然报错才去判断模块包是不是坏的。

## 二、升级管理器后，装过的模块全没了

这不是你的操作问题，是版本格式换代：

- APatch 在某个提交之后**放弃了对 `module.img` 格式的支持**；
- 官方点名的分界是 **CI build `10977`**：在更早版本里装的 APM，升级到 `10977` 及之后的版本会**彻底丢失**；
- 处理方式只有一个：**把之前装的模块重新装一遍**。

升级前该做的准备，是在模块页把当前装了哪些模块**记下名字**（截图或抄下来），升完照单重装。整体升级流程见 [升级系统后怎么保住Root.md](升级系统后怎么保住Root.md)。

## 三、重启后 App 自动拿到 root，或莫名丢 root

官方口径是**这个问题应该已经被修复**。如果你还遇到，按官方给的办法处理：

1. 删除 `/data/adb/ap/package_config`，这会重置 root 授权记录；
2. 重新打开管理器，把该授权的应用重新授权一次。

```sh
adb shell su -c "rm /data/adb/ap/package_config"
```

删掉之后所有应用的授权状态都会清空，等于回到刚装好时的状态，需要逐个重新点一遍授权——先记下你装过哪些需要 root 的应用，免得漏掉。

## 四、模块装在哪里、怎么手动清理

- 模块目录是 `/data/adb/modules`，每个模块一个文件夹，`module.prop` 是它的身份信息。
- 管理器的模块页可以对单个模块禁用或执行「卸载」——**开不了机时这一步要在安全模式里做**，流程见 [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md)。
- 模块自带的脚本（`post-fs-data.sh` / `post-mount.sh` / `service.sh`）只在模块处于启用状态时才会执行，所以「禁用」就能切断它，不必急着删文件。

## 五、模块的 WebUI 打不开

WebUI 特性是 **`10568` 版本**引入的。官方 FAQ 明确：APatch 的 WebUI 实现与 KernelSU 完全一致，**为 KernelSU 模块设计的 WebUI 可以在 APatch 上直接跑**。

打不开时按这个顺序查：管理器版本是否低于 `10568` → 模块本身是否带 WebUI → 模块是否处于启用状态。依赖 Zygisk 才能工作的模块则是另一套问题，见 [Zygisk与LSPosed支持情况.md](Zygisk与LSPosed支持情况.md)。
