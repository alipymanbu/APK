## 一、动手前先满足这五条

APatch 的安装方式是「把原厂 `boot.img` 修补一份，再刷回去」，所以前置条件比装普通 App 多。逐条对照：

1. **Bootloader 已解锁**（BL 解锁）。不解锁没法刷任何镜像，这是硬门槛。
2. **设备是 ARM64 架构**。官方明确写了只支持 ARM64。
3. **内核版本在 3.18 ~ 6.12 之间**。其中 6.6 内核官方只在小米和一加设备上测过，其他品牌以你自己的实测为准。
4. **内核配置支持符号表**，即 `CONFIG_KALLSYMS=y`（`CONFIG_KALLSYMS_ALL=y` 最稳，`=n` 属于初步支持）。查询命令：

   ```sh
   zcat /proc/config.gz | grep -w CONFIG_KALLSYMS
   ```

   这条命令要在手机终端里跑，或先 `adb shell` 再执行；**查配置这一步本身就需要 root**，所以没装过 root 的设备通常拿刷机包的内核配置说明来对照。
5. **你会用 adb 和 fastboot**，并提前把**原厂 `boot.img` 备份到电脑或其他设备**——这一步是后面所有翻车场景的退路。

`boot.img` 从哪来：从你当前系统对应的官方刷机包里提取，务必与手机上正在运行的版本一一对应。刷错版本的镜像是开不了机的常见原因。

## 二、装上 APatch 管理器

把管理器 APK 装到手机上（普通安装即可，这一步还不需要 root）。你要的那份安装包在这里：[APatch 安装文件资源（夸克网盘）](https://pan.quark.cn/s/97a3e4130374)，版本 **11142**、包名 `me.bmax.apatch`、大小 5.58M——如果你手机上已经装过管理器，先核对版本号，比它旧就顺手升级。官方发布的稳定版则在 GitHub 的 Releases 页面（`https://github.com/bmax121/APatch/releases`），同一个应用，版本号体系也一致（官方文档里提到的 `10888` 就是其中一版）。

安装后先别急着修补，把 `boot.img` 传进手机（数据线、MTP 拷贝都行），放在你能找到的目录，比如 `Download`。

## 三、自动修补 boot.img

1. 打开 APatch 管理器，点主页**右上角的按钮**，选 `选择一个启动镜像并修补`（英文界面是 `Select a boot image to patch`）。
2. 选中你传进来的 `boot.img`。
3. 在「超级密钥」卡片里设置一个密码。规则是 **8 ~ 63 个字符、含数字和字母、不带特殊字符**，它就是以后解锁 root 的口令。官方明令禁止 `12345678` 这类弱密码，新版管理器已经强制强密码——设定前先读 [超级密钥忘了怎么办.md](超级密钥忘了怎么办.md)，别在第一步就埋雷。
4. 点「开始修补」，等它跑完。成功后界面会给出修补产物的路径，形如 `/storage/emulated/0/Download/apatch_version_version_randomletter.img`。
5. 把这个修补好的 img 拷回电脑，准备刷入。

**管理器还没跟上 KernelPatch 新版时怎么办？** 官方给的替代路径是在电脑上用 `kptools` 手动修补，步骤见 [管理器没更新时怎么手动修补内核.md](管理器没更新时怎么手动修补内核.md)。

## 四、刷入手机

进 fastboot：

```sh
adb reboot bootloader
```

刷入修补过的镜像（路径换成你自己的）：

```sh
fastboot flash boot PATH/TO/boot.img
```

如果你的设备支持 `fastboot boot`，可以先用它临时引导一次，确认能正常开机再正式刷入；出了意外重启一次就能恢复原样。刷完重启：

```sh
fastboot reboot
```

**另一条路：第三方 Recovery 直接刷入**（自 `10888` 版本起支持，更早版本不认）。把下载的安装包后缀从 `.apk` 改成 `.zip`，例如 `APatch-10888-release.apk` 改成 `APatch-10888-release.zip`，再用 TWRP 之类的第三方 Recovery 刷入即可；类原生 ROM 常用的 `adb sideload` 同样可用。**注意：这条自动路线不会用你指定的超级密钥**，它生成的是随机密钥——想自己定密钥，开机后进管理器重新修补一次。

## 五、卸载

- **自动卸载**（`10888` 起支持）：把安装包文件名改成带 `uninstall` 字样的 zip，例如 `APatch-10888-release-uninstall.zip`，用 Recovery 刷入，同样支持 `adb sideload`。
- **手动卸载**：进 bootloader，把当前 ROM 的原厂 `boot.img` 刷回去即可：

  ```sh
  fastboot flash boot PATH/TO/original-boot.img
  ```

## 六、官方列明的四条禁忌

这四条不是建议，是官方文档里用警告块标出来的，照做能省掉大部分麻烦：

1. **无论什么设备，APatch 都只修补 `boot` 分区**。不要去修补或刷 `init_boot` 或其他分区的镜像，官方对由此造成的修补失败与启动失败不负责。
2. **不要拿被其他 Root 管理器修补过的 `boot.img` 再来修补**，容易出预料之外的结果。
3. **不要刷入别人修补好的内核镜像**——超级密钥是那台设备的控制权所在，来路不明的镜像等于把设备交出去。
4. 修补或刷入前确认你手上的 `boot.img` 与当前系统版本一致，刷错镜像的表现通常就是开不了机，处理办法见 [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md)。
