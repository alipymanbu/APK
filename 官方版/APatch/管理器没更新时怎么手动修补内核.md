# 管理器没更新时怎么手动修补内核

> KernelPatch 已经发了新版、你的管理器还没跟上时，用 kptools 在电脑上把内核拆开、补上、装回去。
> **相关文档**：[下载与安装教程.md](下载与安装教程.md) · [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md) · [升级系统后怎么保住Root.md](升级系统后怎么保住Root.md)

---

> [!IMPORTANT]
> **APatch 安装文件资源（夸克网盘）**：[https://pan.quark.cn/s/97a3e4130374](https://pan.quark.cn/s/97a3e4130374)

## 一、什么情况下用得上这条路

官方给的场景只有一种：**KernelPatch 更新了，APatch 管理器还没更新**。手动修补让你不必等管理器发版，直接用最新的 KP 文件在电脑上完成修补。

管理器能正常修出来的，就别走这条路——自动修补少一堆手工环节，出错面也小。自动修补的完整步骤在 [下载与安装教程.md](下载与安装教程.md) 第三节。

## 二、要准备的文件

到 KernelPatch 项目的 Releases 页面（`https://github.com/bmax121/KernelPatch/releases`）取两样东西：

- **`kptools`**：Windows 版是 `kptools-msys2-win.7z`，Linux 版是 `kptools-linux`；
- **`kpimg-android`**：修补用的镜像文件。

再加上你手机当前系统的**原厂 `boot.img`**（版本必须一致，见 [下载与安装教程.md](下载与安装教程.md) 第一节）。三样放同一个目录里开工。

## 三、Windows 上的三步

解开 `boot.img` 拿到内核，把内核改名为 `kernel-b`（这一步是手工完成的，官方同时注明：`kernel-b` 也可以换成其他第三方内核，但**第三方内核不做任何保证、也不在支持范围内**）：

```cmd
kptools.exe unpack boot.img
```

修补（`YourKey` 换成你自己的超级密钥，规则见 [超级密钥忘了怎么办.md](超级密钥忘了怎么办.md)）：

```cmd
kptools.exe -p --image kernel-b --skey "YourKey" --kpimg kpimg-android --out kernel
```

官方在这一步给了个更推荐的选项：**在 WSL 的 Linux 环境里跑 `./kptools-linux` 版本**，参数完全一样。

修补无报错后打包，产物就是同目录下的 **`new-boot.img`**：

```cmd
kptools.exe repack boot.img
```

## 四、Linux 上的三步

```sh
./kptools-linux unpack boot.img
```

同样把解出的内核改名为 `kernel-b`，然后：

```sh
./kptools-linux -p --image kernel-b --skey "YourKey" --kpimg kpimg-android --out kernel
```

```sh
./kptools-linux repack boot.img
```

`new-boot.img` 就是能刷的成品。

## 五、刷入与自检

拿到 `new-boot.img` 之后的流程与自动修补**完全一样**：拷回手机、进 fastboot、`fastboot flash boot`，见 [下载与安装教程.md](下载与安装教程.md) 第四节。

三条注意事项：

1. **修补阶段只要报了错，就不要把这个镜像刷进去。** 报错说明有东西没对上，硬刷的后果通常是开不了机，救回来的步骤见 [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md)。
2. **别用被其他管理器修补过的 `boot.img` 当底包**，从原厂镜像开始。
3. 想看 `kptools` 还有哪些参数，直接跑 `kptools --help`（Linux 版是 `./kptools-linux --help`）。

官方文档另外提到有一个**在线修补**的页面可用（`https://kernelpatch-on-web.pages.dev/`）。这条路要**把 `boot.img` 上传到别人的服务器**，镜像里带着你设备的信息——传不传你自己判断，稳妥做法始终是本机跑 `kptools`。

## 六、手动修补救不了的情况

手动修补只解决「管理器版本落后」这一件事。内核本身不满足要求（`CONFIG_KALLSYMS` 缺失）、架构不是 ARM64、内核版本超出 3.18 ~ 6.12，这些在官方要求里就是硬门槛，换工具也绕不过——判断方法见 [下载与安装教程.md](下载与安装教程.md) 第一节。
