# 和Magisk与KernelSU的区别

> 三个常见 Root 方案的定位对照：各自要求什么设备、装法差在哪、怎么按自己的机型选。

## 一、先说结论

三者都能拿到 root，最实用的分界线有三条，全部来自各家官方口径：

- **你手上有没有内核源码？** 官方 FAQ 的原话是：KernelSU 需要你设备的内核源代码，而 OEM 并不总是提供；**APatch 只需要你的原厂 `boot.img`**。拿不到源码的机型，这条直接筛掉一半选择。
- **你的设备在不在 KernelSU 支持范围内（GKI 内核）？** 不在的话，APatch 官方明确写了「适用于大部分安卓设备，不仅限于 GKI 内核设备」，覆盖内核区间 3.18 ~ 6.12。
- **你要不要 Magisk 那套模块？** APatch 的 APM 就是从 KernelSU 模块复制修改来的，运作机制与 Magisk 模块几乎一样，官方文档甚至直接说「熟悉 Magisk 模块开发的话大同小异」。

## 二、对照表

| 维度 | APatch | Magisk | KernelSU |
| --- | --- | --- | --- |
| 改的是哪里 | 直接修补 Android 内核 | 对启动镜像的 `ramdisk` 打补丁以修改 `init` 系统 | 在内核层面工作 |
| 装它需要什么 | 原厂 `boot.img` | 原厂 `boot.img` | 设备内核源码（OEM 不一定提供） |
| 架构要求 | 仅 ARM64 | 常见架构均可 | 随所用内核而定 |
| 内核版本范围 | 3.18 ~ 6.12 | 不按内核版本划定支持面 | GKI 设备为主；老内核需自行编译 |
| 是否限定 GKI | 否，官方明确不限于 GKI | 否 | GKI 设备走 LKM / GKI 两种模式 |
| 模块体系 | APM（类 Magisk 模块）+ KPM（内核补丁模块） | Magisk 模块 | KernelSU 模块 |
| 默认带 Zygisk | 否（与 KernelSU 一致） | 是 | 否 |
| 解锁 root 的凭据 | 超级密钥（SuperKey） | 管理器内授权 | 管理器内授权 |
| 主要依赖 | KernelPatch | 自身实现 | 设备内核 |
| 管理器来源 | GitHub Releases | GitHub Releases | GitHub Releases |

前两行与「默认带 Zygisk」一行取自 APatch 官方 FAQ 的对比条目；其余行分别取自三家官方文档。三方支持范围都会变，**以各家官方页面当时显示为准**。

APatch 与另外两家还有两处官方点名的差异：

- **SELinux**：APatch 可以选择不修改 SELinux 上下文，官方称这能让应用线程直接取得 root，不必另起进程做进程间通信；同时它也直接用 `magiskpolicy` 提供额外的 SELinux 支持。
- **KPM**：APatch 独有的内核补丁模块，能在内核空间执行代码。这类模块的门槛与风险都更高，出问题的处理方式见 [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md)。

## 三、几个容易踩的认知点

**「APatch 是给单个 App 打补丁的工具」是误读。** 它是整机层面的 Root 方案，动作是修补并刷入 `boot.img`，跟「改某个 App 的安装包」完全是两回事。

**内核版本不等于 Android 版本。** 手机升到 Android 14，内核可能还是 5.10。查 APatch 支持与否看的是内核版本与 `CONFIG_KALLSYMS` 配置，不是 Android 版本号——具体查法在 [下载与安装教程.md](下载与安装教程.md) 第一节。

**超级密钥是 APatch 独有的概念。** Magisk 和 KernelSU 没有对应物，它们在管理器里点授权即可；APatch 多了一层 8 ~ 63 位的密钥，忘了它没有找回入口，事前就要按 [超级密钥忘了怎么办.md](超级密钥忘了怎么办.md) 的口径设置。

**别在同一台设备上叠装两套 Root。** APatch 的文档反复强调不要用被其他管理器修补过的镜像；同一分区只该有一套方案，要换就先把原厂 `boot.img` 刷回去再装另一套。

## 四、APatch 自身的能力边界

APatch 依赖 KernelPatch 项目；它的管理器与模块框架，官方说明是「对 KernelSU 管理器与 KernelSU 的复制修改」。所以你会看到两边界面与模块目录高度相似，但**内核层面的实现不同，模块也不能默认通用**。

模块分两类：APM 是类似 Magisk 的模块，装在管理器的模块页里；KPM 是内核补丁模块，能把代码注入内核。后者门槛明显更高，出问题的后果也更重——刷错模块导致开不了机的处理方式见 [刷入后开不了机怎么救砖.md](刷入后开不了机怎么救砖.md)。

模块装不上、升级后模块丢失、重启后授权错乱的处理见 [模块装不上和重启后丢授权怎么办.md](模块装不上和重启后丢授权怎么办.md)；依赖 Zygisk 的模块与 LSPosed 另有专门说明，见 [Zygisk与LSPosed支持情况.md](Zygisk与LSPosed支持情况.md)。
