## 一、先决定：让它花钱到什么程度

不绑卡也能用它购物，只是流程停在前一步：它把商品找好、加进购物车，结账留给你自己点。有测评者让它买一个 7 美元的咖啡机配件，它选好型号加进购物车就停了，结账由人完成——这是天然的「半自动」模式。

绑卡之后它才能走完支付。中间还有一档可调：绑了卡、但把权限档位设成每次都问（见 [注册登录与初始设置.md](注册登录与初始设置.md) 第三节），每笔购买仍然要你点头。三档按放心程度自己选，不必一步到位。

## 二、绑卡在哪、卡号怎么被保护

绑卡入口在设置的 Wallet 一节，走 Stripe 的 Link 完成。它保护你卡号的方式有两种，取决于商家：

| 商家类型 | 支付方式 |
| --- | --- |
| 在 Link 网络内 | 直接使用你保存在 Link 里的支付方式扣款 |
| 不在 Link 网络内 | Link 生成一张**只对这个商家、这个金额、短期有效**的虚拟卡号 |

也就是说，你的真实卡号从头到尾不经过它，也不交给商家之外的地方。另外还有一条路：让它登录你在某个商店的账号、用你存在那里的卡支付——要不要把这条路也打开，自己权衡。

## 三、每一笔都会先问你

官方设计里购买属于敏感动作，默认逐笔确认。确认的方式有一个容易忽略的细节：**批准提示出现在应用界面（或 WhatsApp 的批准卡片）里，不在聊天记录里**。在对话框里回一句「同意」「好的」不算数，要点的是界面里那个真正的批准框。逐单核对本篇三样东西：商品对不对、金额对不对、有没有夹带你没要的东西（小费也算）。

这个设计反过来也提醒你：凡是弹框要你批准的，都值得停下来看一眼。绑卡授权一次之后，后续每个购物车只需要一句「go for it」就能继续——方便是真的方便，钱花起来顺不顺，分界线就在你有没有逐单看。

## 四、买错了、买重了找谁

出了问题按这个顺序走：

1. **先联系商家**，多数退款、换货商家自己就能处理；
2. 商家不受理时，走 **Link 的支持渠道**（`https://support.link.com`）发起退款请求，Stripe 可能在原始交易后 60 天内介入处理争议；
3. 金额较大或不属于 Link 覆盖范围时，走你**发卡行的争议（chargeback）流程**——这是卡组织给持卡人的正规通道。

通过 Link 的合格购买自带一层购买保护（物品损坏或丢失、降价、无手续费退货、退货保障），具体范围与适用条件以 Link 条款当时版本为准。你可以在 Link 账户里查订单历史、管理支付方式和订阅。

## 五、把花钱的口子收紧

- 权限档位调成「每次都问」：`Settings → Permissions`；
- 一次授权过后觉得太顺，随时回到 Wallet **解绑支付方式**，回到「它摆购物车、你来结账」的半自动模式；
- 大额购物（几千块的装备、机票）建议当场逐单跟，别让它攒着一个长清单一次跑完；
- 媒体实测里出现过大型电商直接拦截它的情况（Amazon 会提示 AI 代理违反服务条款并拒绝访问）——它会被迫转向别的商家，价格和运费可能因此不同，逐单确认时留意一下商家是不是你想要的那个。

## 六、还没上线的支付选项

官方在发布时预告了 Shop Pay 支持和 1Password 集成（后者让它能调用你已有的登录），截至本文写作尚未全面可用，以应用内为准。上线与否不影响本篇上面几节——链路仍然是 Link 与逐单确认。
