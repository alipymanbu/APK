# Meta Muse 连接器与账号授权设置

> 本篇讲 Meta Muse 的 Connectors（连接器）：怎么把邮箱、日历等服务接进来，读写权限怎么给，以及绑卡支付那一层怎么运作。

## 一、连接器在哪、怎么接

不接任何服务它也能用，但能干的事会很有限——它能直接上网查资料、填表单，碰不到你的邮箱、日历和购物账号。要让它替你处理邮件、订位、下单，就需要在连接器里授权：

```
Settings → Connectors → 选服务 → Connect → 按提示完成授权
```

也可以不走设置页，直接在对话里说「帮我把 Gmail 接上」，它会引导你走完授权步骤。

## 二、可以接哪些服务

媒体在发布报道里列出的连接器覆盖面大致如下（实际列表以你应用内的 Connectors 页面为准，上线节奏一直在变）：

| 类别 | 服务示例 |
| --- | --- |
| 邮件与日历 | Gmail、Outlook、Google Calendar |
| 文档与云盘 | Google Drive、Google Docs |
| 生活服务 | OpenTable（订位）、Ticketmaster（票务）、Spotify |
| 社交 | Instagram、Facebook |
| 购物 | Walmart、Best Buy、Gap、Sephora、Wayfair、Shopify 商品目录 |
| 出行 | Expedia 等 |

## 三、读写权限分开给

这是 Meta Muse 授权设计里最值得用的一点：**同一个服务，读和写可以分开授权**。比如接 Gmail 时可以只允许它读邮件，不允许它以你的名义发信；接日历时允许它看日程，不允许它替你建日程。

媒体实测里常见的稳妥做法是：邮箱先给「只读」，观察一两周它做的事都靠谱，再考虑放开「代发」。也有人干脆专门注册一个新邮箱给它用，让它的活动和你常用邮箱隔开。

## 四、列表里没有的服务怎么办

连接器列表之外的服务不一定接不了。它的能力覆盖任何有公开 API 的服务——列表里找不到时，直接在对话里说想接什么，它会带你手动走配置。有测评者用这个办法接上了 Notion。反过来说，某些既没有 API、又刻意拦截自动化访问的网站（比如 Amazon，实测会直接拦下它），它就进不去，这类边界在 [任务示例与能力边界.md](任务示例与能力边界.md) 里有更完整的清单。

## 五、绑卡与支付

要让它能替你花钱，需要到设置的 Wallet 一节绑定支付方式，这一步由 Stripe 的 Link 完成。运作方式有三个要点：

- 它经手的是 Link 生成的一次性虚拟卡号，你的真实卡号不暴露给它；
- 每笔购买默认要先经你确认，你可以逐单看清楚再放行；
- 通过 Link 的购买带有购买保护（物品损坏或丢失、降价、无手续费退货等，以 Link 条款为准）。

实际体验里，绑卡授权一次之后，后续每个购物车只需一句「go for it」就会继续——方便是真的方便，也正因如此，如果你不想让它花起钱来太顺，就把上面第二步的权限档位调成每次都问。

## 六、随时可以反悔

任何连接都可以随时在 Connectors 里改权限或直接断开，断开不影响你账号本身。支付绑定同样可以移除。给出去的权限不是一次性的承诺，按它实际表现随时收紧或收回就行。

服务接好之后，下一步就是派活——什么样的任务适合交给它、怎么把任务说清楚，见 [任务示例与能力边界.md](任务示例与能力边界.md)。
