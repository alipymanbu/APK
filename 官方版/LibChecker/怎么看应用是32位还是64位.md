# LibChecker 怎么看应用是 32 位还是 64 位

> 判断一个安卓应用装在手机上跑的是 32 位还是 64 位，看的就是它的 ABI 标签。本篇给出在 LibChecker 里的具体看法和各标签的含义。

## 一、三十秒看法

1. 打开 LibChecker，在应用列表里找到目标应用（可以直接搜应用名或包名）。
2. 应用列表的每一项都带架构标签，多数情况不用点进去就能看到结果。
3. 需要看细节就点进详情页：顶部是应用的 ABI 汇总，「原生库」一栏列出每个 `.so` 文件所属的架构。较新的版本还能在详情页里查看应用所有架构下的原生库信息（2.5.1 系列加入），同一应用各架构的库一眼看全。

## 二、架构标签对照表

| 你看到的标签 | 含义 | 位宽 |
| --- | --- | --- |
| arm64-v8a | 64 位 ARM，近几年手机的主流架构 | 64 位 |
| armeabi-v7a | 32 位 ARM，老设备与部分模拟器常用 | 32 位 |
| armeabi | 更早的 32 位 ARM 架构，如今罕见 | 32 位 |
| x86_64 | 64 位 x86，平板与模拟器常见 | 64 位 |
| x86 | 32 位 x86，多见于老旧平板与模拟器 | 32 位 |
| 无原生库 | 应用不含原生库（纯 Java/Kotlin 实现） | 不受架构限制 |

判断口径：带 `64` 的（arm64-v8a、x86_64）是 64 位；`armeabi-v7a`、`x86` 是 32 位。

## 三、标签同时出现好几个怎么办

一个应用可以同时内置多套架构的库，安装包里每套各带一份。你手机装上后实际跑哪一套，由系统按自己的架构挑选：64 位手机优先跑 64 位那套。所以要看「你这台设备上」的结果才有意义——同一个应用，在模拟器上查出来的结果可能和手机上不一样。

模拟器是常见的坑：部分安卓 9 内核的模拟器（如 LDPlayer、MEmu 的默认实例）会把应用装成 32 位，哪怕安装包本身带 64 位库。装完后再用上面的步骤复查一遍，就能确认实际装成了哪种。

## 四、什么场景用得上

- 排查兼容性：应用在你手机上闪退或功能异常，先看它是不是只有 32 位库，而你的设备或模拟器只跑 64 位。
- 装完模拟器复查：见上一节的做法。
- 看应用有没有适配 64 位：Google Play 自 2019 年起要求新应用提供 64 位支持，更早的老应用未必有。
- 新版本 LibChecker 在 Android 8 及以上的设备上还会标出 16 KB 对齐相关的标签，这些标签单独成篇：[16KB对齐标签是什么意思.md](16KB对齐标签是什么意思.md)。
- 设置里的「Tint ABI Label」选项可以给 ABI 标签着色（2.5.2 系列起也作用于详情页），列表里扫一眼就能区分 32 位与 64 位。

查出来的结果和预期对不上时，先看 [常见问题解答.md](常见问题解答.md) 里的排查条目。
