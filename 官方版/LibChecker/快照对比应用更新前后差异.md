# LibChecker 快照：对比应用更新前后的变化

> 应用升级后想知道「里面到底改了什么」：快照把升级前的应用信息存下来，升级后一对比，组件与库的增减直接列出来。

## 一、先存快照，再等升级

1. 打开底部的「快照」页面。
2. 点右下角的「保存当前快照」按钮，等保存完成——首次保存耗时较长属正常现象。
3. 保存成功后，页面顶部的仪表盘会显示这份快照的时间戳与应用数量。
4. 之后应用升级，再回来做对比。

对比结果里，新增与移除的组件、原生库会分开列出；列表项右侧的状态指示会按变化幅度显示（较新版本的行为，旧版以实际界面为准）。

## 二、怎么做对比

对比入口在顶部仪表盘里：点开仪表盘，选中两份不同的快照，点右下角的「比较」。任意两份快照都能互相比，不限于「升级前对升级后」——隔了几个版本看累计变化也可以。

想删掉不用的旧快照，同样在仪表盘的「管理」里操作。

## 三、应用更新了却没出现对比结果

快照对比只在这几种情况下触发：

- 新版本的 versionCode 比旧版大；
- 应用的安装时间（lastUpdateTime）变新了；
- 应用在「追踪」列表里。

系统预装应用的 versionCode 和安装时间常常长期不变，这类应用想让它参与对比，就把它加进追踪列表强制触发。

## 四、自动删除与备份恢复

- **自动删除**：2.5.1 系列开始提供「快照自动删除」，可让旧快照按规则自动清理，免得越积越多。设置项是否存在取决于你的版本。
- **备份与恢复**：目前只能整份备份、整份恢复全部快照。备份走系统的文件选择框架，依赖系统里「文件」应用（com.google.android.documentsui）正常工作——在精简过的 ROM 上备份失败，多半是这个原因。重要的快照建议定期导出一份留底。

## 五、典型用法

- **核对更新说明**：某应用更新后行为变了（比如后台活动变多），对比快照看是不是多了服务或广播接收器。
- **跟踪 SDK 变化**：关心某个库是否被移除，对比升级前后两次快照的组件与原生库差异。
- **换机留底**：迁移前备份快照，新机上恢复后可以对比两台设备的应用状态差异。

快照里某项看不懂是什么意思，去 [使用教程.md](使用教程.md) 的详情页一节对号入座。
