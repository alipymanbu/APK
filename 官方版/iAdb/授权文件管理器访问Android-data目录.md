# 授权文件管理器访问Android-data目录

> 本篇讲怎么通过 iAdb 给文件管理器授予 shell 级权限，让它能打开 `/Android/data`、`/Android/obb` 这类系统限制目录。

## 一、为什么文件管理器进不去 Android-data

从 Android 11 开始，系统不让普通应用直接读取 `/Android/data` 与 `/Android/obb`：你用自带或第三方文件管理器点进去，多半是空目录，或者提示无权限。这是系统层面的限制，跟文件管理器本身没关系。

处理思路是给文件管理器提一级权限：ADB shell 级。iAdb 的作用就是把这一步搬到手机上完成，不需要电脑，也不需要 Root——这正是它「权限管理」功能的主要用途。

## 二、动手前的三件事

1. 装好 iAdb（还没装看 [下载与安装教程.md](下载与安装教程.md)）；
2. 确认 iAdb 的无线调试已开启、处于运行状态（步骤见 [无线调试开启与配对步骤.md](无线调试开启与配对步骤.md)）；
3. 文件管理器要选支持 ADB / Shizuku 接口的那种：这类管理器的设置里通常有「Shizuku 授权」或「ADB 授权」入口，具体叫法以你用的管理器为准。

## 三、授权步骤（通用流程）

1. 先把 iAdb 的无线调试跑起来；
2. 打开文件管理器，在设置里找到 ADB / Shizuku 授权入口，发起授权请求；
3. 回到 iAdb，在权限管理里确认放行该应用；
4. 回到文件管理器再进 `/Android/data`，能列出各应用目录就说明授权成功。

不同文件管理器的入口与弹窗各不相同，上面是通用顺序；卡在某一步时，先确认 iAdb 还在运行，再重试授权。授权后仍进不去的，按 [常见问题与连接失败排查.md](常见问题与连接失败排查.md) 第三节核对。

## 四、授权之后能做哪些事

- 查看、整理各应用在 `/Android/data` 下的缓存与数据目录；
- 访问 `/Android/obb`，核对游戏主数据包（OBB）是否完整；
- 清掉已卸载应用留下的残留目录，腾出存储空间。

## 五、几条注意

- 授权拿到的是 shell 级权限：能碰系统隐藏目录，但删错文件同样会导致应用数据损坏，删除前先备份；
- 手机重启后，无线调试开关会回到关闭状态，文件管理器的访问随之失效，重新开启再授权即可，这是系统行为不是故障；
- 部分系统要求给 iAdb 授予「附近设备 / 本地网络」访问权限，不给的话配对与连接会一直失败，授权链路根本建立不起来；
- 把 iAdb 加进电池优化白名单：它切到后台被系统冻结或杀掉时，文件管理器的授权会跟着断，表现为用一会儿又提示无权限——重新打开 iAdb 再继续即可；
- 不用时在 iAdb 的权限管理里把对应应用的授权收回来，减少常驻的高权限。
