## 一、回复为空 / 服务商压根用不了

先核三样东西：**服务商类型**、**API 地址**、**API Key**。最常见的坑是地址末尾少 `/v1`：

```text
填对：https://api.xxx.com/v1
填错：https://api.xxx.com
```

还有一个容易忽略的：网页版受浏览器跨域规则限制，少数服务商在网页版调不通。同样的 Key 在网页版报错、在客户端正常，多半就是这个原因，换成 Android 客户端即可（平台差别详见[API服务商配置方法](API服务商配置方法.md)）。

## 二、按报错文案对号入座

报错直接发给模型报回来的原文，按原文搜下表最快：

| 报错原文（关键字） | 涉及模型 | 原因 | 你要做的 |
| --- | --- | --- | --- |
| `deepseek-reasoner does not support Function Calling` | DeepSeek | `deepseek-r1` 不支持函数调用，但你启用了带工具调用的插件 | 关掉带工具调用的插件 |
| `messages.1: all messages must have non-empty content...` | Claude | 上下文里出现了空消息，Claude 不接受 | 重新生成或编辑那条消息 |
| `GenerateContentRequest.tools[0].function_declarations...should be non-empty` | Gemini | Gemini 不兼容部分工具调用的参数类型 | 关掉不兼容的插件，或换个模型 |
| `Type validation failed: Value: {"id":"chatcmpl-…` | 不限 | 服务商返回的格式与官方 API 不符，校验没过，多见于逆向接口 | 换官方 API 或官转 API |

## 三、现象不报错，但结果不对

| 现象 | 原因与对策 |
| --- | --- |
| 用 `deepseek-reasoner` 看不到思维链（推理内容） | 服务商类型要选 DeepSeek 而不是 OpenAI（OpenAI 原版格式没有推理内容字段）；另外确认你的服务商真的返回推理内容——DeepSeek 官方和硅基流动支持，部分第三方不返回 |
| 插件开着但模型从来不调用 | 先去助手设置确认插件已启用，再到插件的「插件功能」页确认对应工具没被单独关掉（插件的全局设置和按助手设置是两处开关，见[功能入门与使用技巧](功能入门与使用技巧.md)） |
| 图片 / 插件一用就报 `Type validation failed` | 同上表最后一行，基本是接口格式问题，与本地配置无关 |

## 四、安卓上的已知反馈

截至本文整理时，官方仓库里还有两条与安卓相关的用户反馈可以参考：

- 「Android 端和 Windows 桌面版同步后出现显示问题」（Issue [#71](https://github.com/NitroRCr/AIaW/issues/71)）——如果你在手机和电脑之间开云同步后看到界面显示异常，先刷新或重新进入对话，再对照[数据备份与云同步](数据备份与云同步.md)导出一份保底；
- 「Glama 的 SSE MCP 插件在 Android 上安装失败」（Issue [#48](https://github.com/NitroRCr/AIaW/issues/48)）——在手机上装 HTTP/SSE 类型的 MCP 插件遇到失败时，有这条先例可查。

注意：项目已停止维护，新提的反馈未必有人跟进，重要对话勤导出才是稳的。
