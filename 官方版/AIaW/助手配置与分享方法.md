> 助手决定了「默认用什么模型、什么人设、开哪些插件」，本篇讲它的创建位置、提示词变量的写法和怎么分享给别人。

## 一、助手放在哪、归谁管

- **工作区助手**：只在当前工作区可见。新建工作区时会自动创建一个助手，作为这个工作区的默认助手；
- **全局助手**：在「助手」页面右侧边栏创建，任何工作区都能用；
- **改默认助手**：在工作区设置里换；
- **移动**：助手可以从一个工作区移到另一个，也可以移成全局（反之亦然）。

一个工作区可以建多个助手，发对话时选谁就用谁的人设、模型和插件组合。

## 二、角色设定：静态提示词

最简单的用法：在助手的「角色设定」里写一段固定提示词，比如「你是一名法律文书润色助手，输出保持原文结构」。这段话会进入系统提示词，对所有对话生效。

## 三、提示词变量：让模板可复用

如果提示词里只有一两个词每次都不同（比如「你是{领域}的面试官」），别复制出十个助手——用**提示词变量**：

1. 在助手的「提示词变量」处定义变量，填好**变量名**（模板里引用用）和**标签**（对话时输入框显示用）；
2. 在「提示词模板」里引用它；
3. 之后每次发对话，应用会让你填一次变量值，填进去再发送。

可选的变量类型有五种，对应关系如下：

| 类型 | 对应数据类型 | 适合收集什么 |
| --- | --- | --- |
| 文本 | string | 一句话需求、关键词 |
| 数字 | number | 字数上限、条数 |
| 开关 | boolean | 是否开启某要求 |
| 选择 | string（单选） | 语种、风格、难度 |
| 多选 | array | 多个标签、多个排除项 |

模板用 LiquidJS 模板引擎语法渲染，支持条件判断。有一个前提你要知道：**提示词模板是系统提示词的最后一道工序**，默认模板已经把「角色设定」和插件提示词拼进去了；要是你把模板清空，最终发给模型的系统提示词就是空的——角色设定写得再好也不会生效。改模板时保留默认结构、只往里加东西，最不容易出事。

几个开箱即用的内置变量（在模板里直接引用）：

| 变量 | 值 |
| --- | --- |
| `_currentTime` | 当前时间 |
| `_userLanguage` | 系统语言（如 `zh-CN`） |
| `_workspaceName` / `_assistantName` | 当前工作区 / 助手的名字 |
| `_modelId` | 当前模型 |
| `_isDarkMode` | 是否深色模式 |

另外还有**工作区变量**：在工作区设置里定义，纯文本、定义时给值，这个工作区里所有助手的模板都能引用——适合放「公司背景」「项目上下文」这类全体助手共用的信息，免得每个助手抄一遍。

## 四、导出与分享

- **导出单个助手**：助手设置页面底部有「导出」按钮，可以导出到剪贴板或存成文件；
- **导入**：在插件市场页面右上角的加号处，通过文件或剪贴板导入别人分享的助手；
- **发布到助手市场**：要补全描述、作者等信息后导出 JSON，提交到项目源码的对应文件走 PR——项目已停止维护，这条路能否走通以仓库现状为准。

分享前检查一遍角色设定里有没有你不想外传的内容（公司名、内部约定之类），导出的是明文 JSON。

只想让某个助手用特定模型或中转 Key，配置在[API服务商配置方法](API服务商配置方法.md)；助手开了工具类插件后报错，按[常见报错与解决办法](常见报错与解决办法.md)处理。
