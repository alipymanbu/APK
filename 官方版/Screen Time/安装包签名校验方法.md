# Screen Time 安装包签名校验方法

## 一、校验分两层，防的东西不一样

对一个 apk 的校验分两层：文件哈希证明「文件从下载到手里没被改过」，签名指纹证明「它确实出自原作者」。两层都对上，这个包才可信。它们防的不是同一种问题：

| 校验对象 | 防的是什么 | 对不上的含义 |
| --- | --- | --- |
| 文件哈希（MD5/SHA-256） | 文件在传输、转存过程中被改过 | 这个文件本身与预期不是同一份，别装 |
| 签名证书指纹 | apk 被重新打包、换了签名再发 | 内容或发布者不可信，别装 |

文件哈希只对「与你手里这份完全相同的文件」有效——换一个版本哈希就变了。**签名证书指纹跟着开发者走**：同一开发者的各个版本用同一本证书签名，所以无论你拿的是哪个版本，证书指纹都应该是同一组。

## 二、文件哈希：先对这一层

以网盘里这份 [Screen Time 安装文件资源（夸克网盘）](https://pan.quark.cn/s/7b9014fd5905) 的 v1.2.1 为例（截至 2026-09-23 的核对值）：

- MD5：`DCC7A7C6B610209729B4D903E921274E`
- 大小：1.78M（精确字节数 1869998）

电脑上算 MD5 后逐位比对，一致才继续。不一致先别急着下结论——确认自己比的是不是同一个文件（版本不同哈希必然不同）。

## 三、签名证书指纹：这一层才是「是不是原作者签的」

开发者在[源码仓库 README](https://gitlab.com/Atharok/ScreenTime) 里公布了签名证书的指纹（截至 2026-09-26，以 README 当时显示为准）：

```
SHA-256: e6cf1629d462a3686aa4ba2d37e02777257fd0a3bbe5540d8c70f80e12d111cd
SHA-1:   8d66ed4b5d105f7fecce6ebd07dddc569cab29b9
MD5:     ea0d7434b89110e49386132bb005bb6b
```

注意最后一行的 MD5 是**证书的**指纹，与第二节里**文件的** MD5 是两回事，别拿它去比文件哈希。

读出 apk 签名指纹最省事的命令（电脑上需装有 JDK）：

```bash
keytool -printcert -jarfile "Screen Time_v1.2.1.apk"
```

在输出里找 SHA256 / SHA1 / MD5 三行，与上面公布的值逐位比对：

- 完全一致 → 这个包确实出自开发者本人的证书；
- 有任何一位对不上 → 停止安装，换正规渠道重新下载（重新下载的入口见 [下载与安装教程.md](下载与安装教程.md) 第二节）。

## 四、系统这道关也会替你把一遍

同一本证书签的 apk 才能**覆盖安装**升级；如果有人改了内容再用别的证书重签，安装时系统会直接提示与已装应用签名不一致而拒绝。所以日常升级时留意系统弹窗——「签名冲突」本身就是一次被动校验（版本层面的注意点见 [版本更新记录与升级方法.md](版本更新记录与升级方法.md) 第三节）。
