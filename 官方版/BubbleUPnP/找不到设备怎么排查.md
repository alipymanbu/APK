## 一、先判断「完全扫不到」还是「扫到但播不了」

打开 BubbleUPnP 的设备列表：

- **列表里根本没有电视/音箱** → 设备发现问题，走本篇第二到第五节；
- **列表里有、点播没反应** → 不是扫描问题，直接看 [投屏到电视和Chromecast教程.md](投屏到电视和Chromecast教程.md) 第七节。

设备发现靠局域网广播（DLNA 用 SSDP、Chromecast 用 mDNS），任一环节被网络设置挡住，对面就「隐身」。下面按命中率排序。

## 二、最常见的原因：不在同一个局域网

逐条对照：

1. 手机和电视连的是**不是同一个 WiFi 名（SSID）**。手机在 5GHz、电视在 2.4GHz 且路由器把两个频段分成了不同名字——就不算同一个网。
2. 有没有连**访客网络（Guest）**。访客网络通常开「客户端隔离」，设备之间互相看不见。
3. 手机和电视的 IP **前三段是否一致**（如都是 `192.168.1.x`）。电视有线接、手机无线接，若接到的是不同路由器/交换机后面的网段，也对不上。
4. 有没有开 **VPN / 代理 / 加速器**。这类应用会把局域网广播流量一起吞掉，DLNA 设备直接全隐身——投屏时先关掉它们。

## 三、路由器侧的开关

用电脑进路由器管理页（地址通常写在路由器底标），挨个看：

| 设置项 | 要求 |
| --- | --- |
| AP 隔离 / 无线隔离 / 客户端隔离 | **必须关**。开着则同一 WiFi 下设备互相隔离，投屏必挂 |
| 访客网络 | 投屏设备不要接在上面 |
| UPnP / 组播 / IGMP Snooping | 建议开。运营商光猫路由一体机常默认关组播转发 |
| 双频合一 | 拿不准就先关，让手机电视明确连同一个频段 |

改完路由器设置后**重启路由器和电视**再试——组播成员关系要重新建立。

## 四、电视侧的设置

1. 电视必须**完全开机**，不是待机。很多电视待机时断网，扫不到；有「网络待机 / 快速启动」开关的可以打开。
2. 电视设置里找「DLNA 服务 / 多屏互动 / 媒体共享 / 局域网共享」，确认是开的（各品牌叫法不同，海信、康佳等常叫「多屏互动」）。
3. 电视自己的固件升级到最新——DLNA 接收端的 bug 常由固件修。
4. Chromecast 类设备看指示灯是否处于待命状态，用 Google Home 一类工具先确认它本身在线。

## 五、手机侧的权限与省电

1. **首次启动时的「附近设备 / 本地网络」权限要允许**。拒绝了就永远扫不到，去系统设置里给 BubbleUPnP 补开。
2. 手机的**电池优化**别把 BubbleUPnP 限制了。官方专门做过一个提示：启动时若发现系统电池优化开着，会弹一次说明——`More > 齿轮 > Disable system battery optimization` 可随时再看。关掉它才能保证后台与息屏时不断连。
3. 部分国产系统还要给它「后台运行 / 自启动」权限，否则息屏一会儿设备连接就被系统杀了。
4. 手机上如有带「广告拦截 / DNS 过滤 / 防火墙」性质的应用（NetGuard、AdGuard 类），可能拦 UDP 广播——投屏时先临时关掉验证。

## 六、还不行的两招

1. **重启一遍链路**：电视、路由器、手机依次重启，再打开应用下拉刷新设备列表。官方更新日志里多次修过「网络切换后设备扫不出」的 bug（如 3.6.10 提高 UDP 包 TTL、3.7 修网络变化后的设备发现），**先把 BubbleUPnP 升到最新版**，一半的问题到这一步就没了。
2. **缩小范围**：把电视临时用网线接路由、或手机开热点让电视连上来测——热点下能扫到，说明原路由器的问题（回第二节查隔离与组播）；热点下也扫不到，问题在电视端（回第四节）。

## 七、与官方 Server 相关的两个「扫不到」

这两个不是局域网扫描问题，别混在一起查：

- **Chromecast 转码设置是灰的**：说明没检测到电脑/NAS 上的 BubbleUPnP Server，是 Server 没装或不在同一网段，见 [免费版和付费版有什么区别.md](免费版和付费版有什么区别.md) 第四节；
- **远程库没出现**：那是 BubbleUPnP Server 的互联网连接没配好，不是设备扫描故障。
