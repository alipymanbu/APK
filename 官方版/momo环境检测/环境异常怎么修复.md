## 一、修复前先明确两件事

**Momo 只报不修。** 它给的是线索，每个动作都要你自己在系统里做。所以正确流程是：

1. 打开 Momo，把明细**整屏截图或抄下来**；
2. 对照下面的表，按「一次只改一条」处理；
3. 改完**重启**（挂载、属性、签名类改动不重启不生效）；
4. 重开 Momo 复查，看那条消了没有，再动下一条。

**改之前想清楚方向。** 每条异常都对应你自己（或你刷的模块）做过的一个改动，修复 = 把那个改动关掉、清掉或还原。如果你本来就想要那个功能（比如保留 Root），那就是**取舍**而不是故障——先处理那些「你并不想要」的改动，剩下的各条按你的取舍决定留不留。

## 二、逐条对照处理

| Momo 提示 | 常见来源 | 处理动作 |
| --- | --- | --- |
| 已开启调试模式 | 打开了 USB 调试 | 开发者选项里关掉 USB 调试 |
| 处于调试环境 | 系统开着全局调试 / 无线调试 | 关闭无线调试与全局调试，重启；改完仍报就查是否有模块在维持它 |
| 权限系统异常 / 包管理服务异常 | 装了放宽签名校验的系统工具，或官改 / 三改 ROM | 先在相关工具里关掉「禁用软件包管理器签名验证」，重启；依旧就卸载该工具再重启；系统自带的则属 ROM 固有状态 |
| 签名验证失败 | 同上 | 同上一行的步骤 |
| 数据未加密 | 刷机时没加密 / 解了密 | 属于刷机选项导致的状态，恢复加密通常需要重置数据——**先备份再考虑**，不确定就先放着 |
| SELinux 处于宽容模式 | 有模块或脚本把 SELinux 设成了 permissive | 到所用 Root 方案的模块设置里把模式还原为 enforcing；没有头绪就回想最近装过什么模块 |
| Seccomp 未开启 | 系统层配置被改 | 一般随 ROM 而来，第三方 ROM 上常见；能还原就还原，还原不了记为「ROM 固有」 |
| 存在 Magisk / TWRP 等可疑文件 | Root 方案残留、第三方 Recovery 残留 | 是你留的就归到「取舍」；不是你留的，检查有没有来路不明的模块与刷入记录 |
| 找到可执行程序 su / Root 探测命中 | 设备确实有 Root | 想保持干净就移除 Root；想保留则算取舍 |
| 找到 Xposed 框架 / 模块扫描命中 | 装了注入类框架 | 同上，按你的取舍决定 |
| Zygote 行为异常 | 注入框架作用于了全部进程 | 检查框架的生效范围；框架类工具应当只作用于目标应用，全量注入既伤性能也更容易被看出来 |
| 检测到 Frida / 注入识别命中 | 设备上跑着动态注入工具 | 关掉正在运行的注入工具即可 |
| Build 指纹异常 / 属性被改 | 有模块改过 `ro.build` 等属性 | 找到改属性的模块关掉；改过之后记得重启 |
| 处于调试环境（全局）仍消不掉 | 有模块在维持全局调试 | 按提示装「关闭全局调试」类模块的做法来自玩机社区（第三方经验），装之前先确认来源可信 |
| init.rc 被修改 | 第三方 Recovery 写入的改动 | 换用其他 Recovery，或刷回官方 Recovery |
| 分区挂载异常 | 修补 Root 镜像时勾选了 AVB / 校验相关选项 | 用原厂镜像恢复后重新修补，修补时不要勾选该选项（玩机社区经验） |
| 非 SDK 接口限制失效 | 有人改过系统的隐藏 API 策略 | 找回改过的设置项恢复默认；不会找就把最近改过系统设置的动作逐个还原 |
| Bootloader 未锁定 | BL 处于解锁状态 | 属硬件状态：重锁通常清空数据，按 [没Root也报环境异常怎么办.md](没Root也报环境异常怎么办.md) 第二节的取舍处理 |
| ART 参数异常 / 框架类提示反复出现 | 所用注入框架的版本问题（社区反馈集中在个别 CI 版本） | 换回该框架的正式版，或更新 / 回退一个版本再复查（第三方经验） |
| TEE损坏 | 解锁 BL、刷类原生系统，或刷入过针对 BL 的模块 | 刷模块引起的可卸载该模块复查；解锁 / 换 ROM 引起的**普通操作修不好**，只作为边界信息记住：依赖硬件密钥的应用可能受影响，见 [检测结果怎么看.md](检测结果怎么看.md) |

## 三、处理原则

**一次只改一条，改完就重启。** 一口气关三个开关、卸两个工具，最后消了也不知道是哪条起的作用——下次复发时你就没有任何线索了。

**分清「故障」与「固有状态」。** 第三方 ROM、改过校验的系统、保留 Root 的方案，都会让某些条目**永远消不掉**。这类条目处理方式不是「修好」，而是判断：

- 它**不影响**你的目标应用 → 放着；
- 它**可能是**目标应用闪退的原因 → 单独处理它验证，见 [应用闪退打不开怎么排查.md](应用闪退打不开怎么排查.md)。

**别信「一键修复」。** 网上有号称一键清除 Root 痕迹、一键恢复环境的工具，来路与副作用都没人担保；上面的表里每条动作都在系统设置或你的 Root 方案里完成，不需要再装一个来路不明的工具。

**改完做一次对照。** 修复前后各跑一次 Momo，保留两份结果：哪条消了、哪条还在，这就是你这台设备的「环境基线」。以后某个应用突然打不开，拿新结果和基线一比，多出来那条就是嫌疑最大的（比对方法见 [常见问题与故障排查.md](常见问题与故障排查.md)）。
