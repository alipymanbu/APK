## 一、先看顶部的状态摘要

Momo 的结果分两层：顶部一句**状态摘要**，下面是**逐项明细**。摘要有这么几种（按公开资料整理，以你装的版本实际显示为准）：

| 摘要状态 | 含义 | 要做什么 |
| --- | --- | --- |
| 环境正常 | 没发现对环境的修改，也没发现可疑迹象 | 什么都不用做 |
| 环境异常 | 环境已损坏，或检测没法继续往下跑 | 展开明细，按 [环境异常怎么修复.md](环境异常怎么修复.md) 逐条处理 |
| 检测到对环境的修改 | 你（或你刷的模块）改动过系统，且被看出来了 | 有明确修改来源的，知道是哪来的就行；来路不明的才需要查 |
| 检测到破坏行为 | 有东西在主动拦截 / 干扰检测本身 | 先查是不是装了带「隐藏」功能的模块 |
| 签名验证失败 | 系统的签名校验链路不对（常见于改过校验的系统） | 见第三节「签名验证失败」 |
| 服务无响应 | 底层服务挂了，多半是刚才改完系统没重启 | 重启后再看 |
| Zygote 行为异常 | Zygote 进程被注入过 | 查注入类框架（Xposed / LSPosed 一类）是否在作用于全部应用 |
| 存在 Magisk / TWRP 等可疑文件 | 系统里躺着 Root 或第三方 Recovery 的痕迹 | 判断是自己留的还是残留，见修复篇 |
| TEE损坏 | 安全芯片环境不对（部分改机方案会碰到） | 见第三节 |

**读法要点**：摘要只是一句结论，**真正的信息在明细里**。同一句「环境异常」，底下可能挂一条也可能是十几条——处理顺序按明细来，不要对着摘要猜。

## 二、明细里的七类检测项

明细按检测维度分组，各自看什么：

| 检测维度 | 它在找什么 | 你该关注的典型条目 |
| --- | --- | --- |
| Root 探测 | 传统 `su` 文件、Superuser 类应用 | 「找到可执行程序 su」 |
| 框架检测 | Magisk、APatch、KernelSU 等 Root 方案 | 「检测到 Magisk」 |
| 模块扫描 | Zygisk、Riru、Xposed 类运行时注入残留 | 「找到 Xposed 框架」 |
| 挂载监控 | `/system`、`/data/adb` 等目录的异常挂载 | 「Systemless 挂载」相关条目 |
| 注入识别 | Frida、ptrace 等动态注入痕迹 | 「检测到 Frida」 |
| 指纹校验 | `ro.build` 等系统属性是否被改 | 「Build 指纹异常」 |
| SELinux 审计 | SELinux 是否处于宽容模式、规则是否被改 | 「SELinux 处于宽容模式」 |

**为什么偏偏查这几类**：官方在项目说明里给过立场——它不反对 Root 与 Xposed，但倡议三件事：`su` 只挂载给需要的应用、不要关闭 SELinux 强制模式、Xposed 只注入目标进程。上面七类检测基本就是对着这三条来的：你（或你的方案）有没有把环境改得「影响到了无关应用」。理解了这一点，明细就好读了——**它报的不是「你干了什么」，而是「你的改动可能溢出到别人」的证据**。

**哪些条目真正要紧**：不是每条都影响你日常用应用。判断标准很简单——**你的目标应用（银行、支付、门禁、游戏）报的检测方法，和 Momo 这类公开检测的方法高度重合**。所以：

- 你只是想确认自己刷的模块有没有搞坏系统 → 看「环境异常 / 签名验证 / 加密」这几类；
- 你是为了排查某个应用打不开 → 只处理**该应用报错期间你手上没有把握的那几条**，逐条试，见 [应用闪退打不开怎么排查.md](应用闪退打不开怎么排查.md)；
- 无伤大雅的提示（比如你自己刚装的某个工具被指出来）→ 明知来源就不用纠结。

## 三、几条容易误解的说明

**Momo 不扫描已安装应用列表。** 这是官方在项目说明里明确写过的口径，理由有两条：靠包名判断装了什么应用太容易失效；Google Play 也早已要求新应用拿不到应用列表。所以会出现这种情况——**别的检测工具报「检测到 Root 应用」，Momo 什么都不报**。这不是 Momo 漏了，是它本来就不做这件事。反过来也成立：Momo 报了异常，别的工具没报，以明细里那条具体异常为准去查。

**「检测到对环境的修改」不等于中毒。** 你只要 Root 过、刷过模块、改过字体，就会被记上。它告诉你的是「这台设备不是原厂状态」，不是「有恶意程序」。反过来，**没 Root 过的手机报了异常也不代表出事**——调试开关、解锁的 BL、官改 ROM 都会触发，逐条对来源即可，见 [没Root也报环境异常怎么办.md](没Root也报环境异常怎么办.md)。

**签名验证失败**：一般来自安装了改签名校验的工具，或使用了官改 / 第三方 ROM。先去系统设置里关掉「禁用软件包管理器签名验证」这类开关，重启；问题依旧就卸载改校验的工具再重启（详细步骤见 [环境异常怎么修复.md](环境异常怎么修复.md)）。

**TEE 损坏**：涉及安全芯片，普通操作修不好，只能说明「这台设备的密钥环境不是原装状态」。有这类提示时，涉及硬件密钥验证的应用（支付、DRM）可能受影响——知道这个边界即可，别指望 Momo 能替你修。

**修复靠你自己，不靠 Momo。** 它只报不修：每条提示的处理动作都在 [环境异常怎么修复.md](环境异常怎么修复.md)，改完重新打开 Momo 复查。若改了两三轮还消不掉某条，别死磕——那条要么是你方案的固有代价，要么需要换方案，见 [常见问题与故障排查.md](常见问题与故障排查.md)。
