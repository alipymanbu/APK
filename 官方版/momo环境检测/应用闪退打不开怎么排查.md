# 银行类应用打不开用 Momo 怎么排查

> 某个应用在你手机上闪退、提示环境异常时，用 Momo 把嫌疑范围缩到具体哪几条——本篇讲排查顺序与判断边界。

## 一、为什么 Momo 能用来做这件事

银行、支付、门禁这类应用会检测运行环境，检测手法大多是公开的那几类：Root 痕迹、注入框架、调试状态、系统属性、签名与加密状态——**和 Momo 用的是同一套方法**。所以思路是：

> 应用打不开 → 大概率是它看到了环境里某条它不接受的痕迹 → 打开 Momo，看当前环境里有哪些痕迹 → 逐条处理、逐条验证。

这个方法的边界也要先说清：**Momo 报的都消了，应用也可能照样打不开**——对方可能用了 Momo 没收录的手法（如服务端校验、硬件密钥链）。这时排查就到头了，属于对方的策略，不是你设备的问题。

## 二、排查顺序

### 第 1 步：先确认问题真的在「环境」

依次试三件事，排除干扰项：

1. **换个网络**再打开应用——有些应用是服务端拒绝，与设备环境无关；
2. **清一次应用缓存**后重开——本地配置损坏也会表现为「打不开」；
3. 拿**另一台没改过的手机**装同一个应用——能开，说明确实与你这台设备的环境有关，继续往下；不能开，说明是账号或服务端问题。

### 第 2 步：跑一次 Momo，抄下全部明细

打开 Momo 等结果出来，把明细**完整抄下来**（别只看摘要那句）。此时的明细就是「对方可能看到的东西」的候选集。

### 第 3 步：按「对方在意程度」排序

不同条目被应用在意的概率差别很大，按经验优先级处理：

| 优先级 | 条目类型 | 理由 |
| --- | --- | --- |
| 先处理 | 调试模式 / 全局调试 | 关开关就行，成本最低，而且很多应用确实会看 |
| 先处理 | 签名验证失败 / 权限系统异常 | 属于系统状态被改的硬信号，优先排除 |
| 先处理 | 明确的 Root / 注入框架痕迹 | 这类应用最常见的拦截点 |
| 其次 | 属性被改 / 指纹异常、Build 指纹 | 常与前面几条同源，处理完前面的会连带消 |
| 最后 | TEE 损坏、Seccomp、数据未加密 | 多为 ROM 固有状态，改动成本高，先确认是不是它再说 |

具体每条怎么改，见 [环境异常怎么修复.md](环境异常怎么修复.md) 的对照表。

### 第 4 步：一次改一条，改完重启再开应用

节奏和修复篇一样，但这里的验证目标**是应用能不能打开**，不是 Momo 报不报：

```
改一条 → 重启 → 先开 Momo 看那条消了没 → 再开目标应用试
```

- 应用开了 → 收工，把这次改动记下来，它就是根因；
- 应用没开、Momo 那条消了 → 回第 3 步取下一条；
- 应用没开、Momo 那条也没消 → 改动没生效，回 [环境异常怎么修复.md](环境异常怎么修复.md) 检查步骤。

### 第 5 步：判断到头了没有

出现以下任一情况，说明排查到头，别再往下耗：

- Momo 已经**全绿**（环境正常），应用仍打不开 → 对方用的手法不在 Momo 覆盖范围，或问题根本不在环境；
- 反复处理的都是**你本来就打算保留的东西**（例如你就是要 Root）→ 这是取舍冲突：要么接受这个应用在这台设备上不能用，要么换一台干净设备专门跑它；
- 同一应用**昨天还能开今天不行** → 先看它是不是刚发了新版本（更新日志里常直接写「加强环境检测」），版本变化比你的设备变化更可能是原因。

## 三、留好两份结果

排查过程中至少留两份 Momo 结果：

1. **基线**：设备当前状态的完整明细（问题出现前如果留过更好，一比就知多了哪条）；
2. **过程**：每改一条之后的结果。

这样即使这次没解决，下次应用再出问题时，你有现成的对照组，不用从零开始猜。其他常见故障（Momo 自身打不开、结果读不出来等）见 [常见问题与故障排查.md](常见问题与故障排查.md)。
