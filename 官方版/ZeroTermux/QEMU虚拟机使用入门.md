## 一、QEMU 是干什么的、什么时候用

QEMU 走的是「模拟一台完整机器」的路线，跟 PRoot 容器（[Linux发行版安装与容器切换](Linux发行版安装与容器切换.md)）不是一回事：容器里跑的是 ARM 架构的 Linux，快且省资源；QEMU 能跑 x86 架构的 Windows 镜像，但开销大得多。只是想要个 Linux 命令行环境的话，用容器就够了，别用 QEMU 受那份罪。

QEMU 入口在左侧栏「常用功能 > QEMU」，官方 Wiki 列出的菜单：

| 选项 | 说明 |
| --- | --- |
| 海的QEMU | 可选线上脚本或写入本地脚本运行 |
| Zero | 打开 ZeroTermux 内置的运行窗口 |
| Win7模拟 | 写入 `qemu_win7.sh` 并发送运行命令 |
| WinXp | 写入 `qemu_winxp.sh` 并发送运行命令 |

## 二、相关文件放哪

QEMU 用到的文件按类型归进这些目录，跑之前先把东西放对位置：

| 目录 | 用途 |
| --- | --- |
| `/sdcard/xinhao/qemu/` | QEMU 相关文件 |
| `/sdcard/xinhao/windows/` | Windows 相关文件 |
| `/sdcard/xinhao/windows_config/` | Windows 配置 |
| `/sdcard/xinhao/share/` | 脚本运行时的共享文件（首次运行 Win7/WinXP 入口时会自动检查并创建） |

镜像、ISO 放进对应目录再启动，别散在 Download 里让脚本找不到。

## 三、跑 Win7/WinXP 模拟的流程

1. 确认已授予内部存储权限（首次引导那一步就给过的话可以跳过）。
2. 把镜像或 ISO 放到上表对应目录。
3. 打开「常用功能 > QEMU」，选 Win7模拟 或 WinXp——应用会写入对应的启动脚本并向终端发送运行命令。
4. 回到终端看输出。虚拟机启动和磁盘读写都很慢，**长时间没新输出不一定是卡死**，多等一会儿再下结论。
5. 产物或进度文件如果需要手动放置，按脚本提示操作即可。

Windows 系统镜像自备，来源与授权问题自己把握；QEMU 菜单里给的是运行脚本的入口，不是镜像下载入口。

## 四、性能与散热的现实预期

官方 Wiki 对 QEMU 有明确的性能提醒，这里展开成三条可执行的判断：

- **低内存设备用轻量镜像**：4GB 内存以下的设备跑完整版 Windows 会很吃力，从轻量镜像或精简版开始。
- **别同时跑多个重任务**：QEMU 运行时再开游戏、视频这类应用，卡顿和杀后台都会更严重。
- **散热**：虚拟机持续吃满 CPU，机身发烫、充电变慢都是正常现象，夏天长时间跑建议摘掉手机壳、远离被窝。

如果只是想体验「手机上的 Windows 桌面」，WinXP 这类老系统比 Win7 流畅得多；先跑小的验证流程，再挑战大的。
