## 一、先分清失败在哪一步

装不上分两种，处理办法完全不同：

| 现象 | 卡在哪 | 去哪查 |
| --- | --- | --- |
| 点「确认」就报失败，或「处理完成」提示没出现 | 工具处理阶段 | [去签失败常见问题与解决.md](去签失败常见问题与解决.md) |
| 出现了「处理完成」，拿到文件后**点安装**才报错 | 系统安装阶段 | 本篇 |

安装阶段的报错由 Android 系统抛出，报错文案本身就能定位原因。下面几类是出现频率最高的（多个独立公开技术来源互相印证，具体以你手机上的提示为准）。

## 二、提示签名不一致（INSTALL_FAILED_UPDATE_INCOMPATIBLE）

**原因**：手机上已经装着同包名的应用，而它与你手上这个包的签名不同——Android 不允许签名不同的包互相覆盖。旧版本可能在桌面找不到图标，但系统里还留着目录和缓存。

**处置**：

1. 设置 → 应用管理 → 找到该应用 → 卸载；
2. 重新安装手上的包；
3. **卸载会清空该应用的本地数据**（登录状态、聊天记录之类），装回前先想清楚有没有要备份的。

这是最常见的一类报错，也是唯一需要「先卸载」的一类——其余报错卸载没用，往下看。

## 三、提示包损坏或签名无效

**原因**：文件在下载或传输中不完整。典型来源是没下完就装、或经微信 / QQ 传输——聊天软件传 APK 会改后缀、也发生过截断（对应常见错误码 `-11`、`INSTALL_FAILED_INVALID_APK`）。

**处置**：删掉这个文件，重新下载完整的，下载完核对文件大小与 MD5（值见 [下载与安装教程.md](下载与安装教程.md)）。传文件尽量用浏览器直下或网盘 App，别走聊天软件转发。

## 四、提示版本过低 / 降级不被允许

| 报错含义 | 原因 | 处置 |
| --- | --- | --- |
| 系统版本过低（如 `INSTALL_FAILED_OLDER_SDK`） | 手机系统低于该包要求 | 系统要求是安卓 5.2 以上；不满足就别装 |
| 降级被拒（如错误 `-112`） | 手机上已装的版本号比这个包高 | 要装这个包，先卸载高版本（数据同样会清） |

## 五、只带旧签名方案的包在新系统被拒

错误码 `-29` 一类提示指向「签名方案过旧」：Android 14 及之后的系统对只带 V1 签名的包收得更紧（这条见于多个独立来源，截至 2026 年的公开资料，具体以你系统的实际提示为准）。你处理的是老包时容易撞上——换用别的时间更近的原始包重跑一次处理，比在报错上反复重试有用。

## 六、报错速查

| 你看到的提示 | 动作 |
| --- | --- |
| 签名不一致 / 无法覆盖 | 卸载旧版 → 重装（先备份数据） |
| 包损坏 / 签名无效 / `-11` | 重新下载，核对大小与 MD5 |
| 系统版本过低 | 不满足安卓 5.2 以上就放弃 |
| 不允许降级 / `-112` | 卸载高版本再装（数据会清） |
| 签名方案过旧 / `-29` | 换更近的原始包重跑处理 |
| 空间不足 | 清存储后重试 |

怎么让处理结果一次就少踩这些坑，见 [过签强度与Hook模式怎么选.md](过签强度与Hook模式怎么选.md)；处理阶段本身的排查在 [去签失败常见问题与解决.md](去签失败常见问题与解决.md)。
