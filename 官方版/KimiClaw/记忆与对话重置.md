# Kimi Claw 安卓版记忆与对话重置

> 昨天交代的事今天忘了？不是坏了——OpenClaw 默认每天凌晨自动重置对话。本篇讲重置机制、怎么把重要信息存进长期记忆，以及上下文超限和限频的处理命令。

## 一、为什么它好像「失忆」了

按官方帮助中心的说明，OpenClaw 默认在每天凌晨 4 点自动重置对话，用来清理过长的上下文，防止上下文太长导致回复质量下降。所以前一天聊的内容第二天不在对话里，是正常机制，不是故障。

关键是：对话会被重置，**长期记忆（Memory）不会被清**。你想让它一直记住的事，要主动放进 Memory。

## 二、把重要的事存进长期记忆

三个用法，都在你平时的聊天窗口里完成：

1. **直接说**：对它讲「记住 XXX 到 Memory 里」，比如「记住我对咖啡因过敏」。之后它会把这些内容存进长期记忆，对话重置也不会丢。
2. **随时查看**：在聊天里发送 `/memory` 命令，查看和管理当前已存的记忆。
3. **看原始文件**：记忆存在工作空间里，你可以在 Dashboard → 设置 → OpenClaw 工作空间中打开 `AGENTS.md`，找到 `#MEMORY` 部分查看已存的内容（工作空间的用法见 [备份恢复与换机迁移.md](备份恢复与换机迁移.md)）。

值得存进去的：你的固定偏好、常用指令的说法、账号昵称这类长期不变的信息。一次性的任务不需要。

## 三、上下文超限：回复不动了怎么办

对话拉得太长、或加载的技能太多时，可能超过模型的 token 限制，表现为它不再正常回复。按这个顺序处理：

```text
/new      新建对话，清空当前上下文
/compact  压缩当前上下文
/skills   查看已加载的技能，卸载不需要的
/reset    重置
```

先发 `/new`；如果提示仍然超限，多半是加载了过多技能内容，用 `/skills` 卸载用不上的，再不行用 `/compact` 压缩，最后才是 `/reset`。这些命令都直接在聊天窗口里发送。

## 四、提示 API rate limit reached

这个提示说明触用了限流，等一会儿再重试即可。想看自己还剩多少额度：

1. 前往 [kimi.com/code](https://kimi.com/code)；
2. 进入控制台；
3. 点「查看额度与频次」，能看到当前用量和限制。

如果经常撞上限流：一是把任务错开安排，复杂任务会密集调用模型，连着派几个大活就容易触发；二是升级会员计划获取更高额度（会员等级与额度以[官方定价页](https://www.kimi.com/membership/pricing)当时显示为准）。

## 五、它一直不回消息的完整排查顺序

不回消息、回得慢，和记忆无关但容易混淆，一并放这里。按顺序试：

1. **再发一条消息**——有时只是临时延迟；
2. **看 Dashboard**：网关状态是否「已连接」，显示「已停止」就点重启；
3. **重启网关**：设置 →「备份与重启」；
4. **查日志**：实时日志里按 Error 级别筛，看最后一次出错的时间点；
5. **发 `/status` 或 `/logs`**：让它在对话里报告系统状态和最近日志；
6. 都不行就走反馈通道，见 [常见问题排查.md](常见问题排查.md)。

排查完记得确认常用偏好还在 Memory 里——重置类的操作不影响长期记忆，但你可以在 `/memory` 里顺手核一遍。
