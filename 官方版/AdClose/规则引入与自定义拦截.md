# AdClose 规则引入与自定义拦截

> 本篇讲默认功能开关覆盖不到的广告怎么补拦：引入现成规则、手动添加拦截项、用「自动检测广告 SDK」生成自定义配置，以及用日志核对效果。

## 一、什么时候需要动规则

六项功能开关（见 [功能与作用域配置.md](功能与作用域配置.md)）处理的是官方清单内的常见广告 SDK。遇到下面两种情况，就要靠规则和自定义配置补：

- 某个应用的广告来源不在 [广告SDK拦截范围.md](广告SDK拦截范围.md) 的清单里，默认开关压不住；
- 应用改版后新出的广告位，现有版本还没跟上。

## 二、引入现成规则

- **入口**：模块内的规则引入界面（部分版本在页面底部点加号进入）。
- **做法**：把规则链接粘贴进去，确认引入，规则里的拦截数据即开始生效。多条来源对这个操作口径一致。
- **社区规则库示例**：`https://raw.githubusercontent.com/qq5460168/AD886/main/AdClose.txt` —— 网上流传较广的一份社区维护规则。它是第三方个人维护的文本，内容随时会变，是否有效以你引入后的实际拦截效果为准。

三条使用提醒：

1. 引入任何第三方规则前，自己判断一下来源是否可信，规则内容决定拦截什么。
2. 规则链接可能失效，表现是之前拦掉的广告又出现了 —— 换一条规则链接或等规则作者更新即可。
3. 规则不是越多越好，多份规则叠加可能误伤应用正常功能，出问题先留一份验证。

## 三、手动添加拦截项

不整份引入规则时，也可以手动逐项添加：支持按**应用包名**添加拦截目标，也支持按**广告域名**拦截请求。适合只对个别应用做微调、不想引入大而全规则的场景。

## 四、自动检测广告 SDK

这是针对「单个应用压不住」最直接的办法。作者本人在论坛答疑中给过操作步骤，把原步骤里的示例应用换成「目标应用」就是通用流程：

1. 先把目标应用打开一次（让它的广告 SDK 先跑起来）；
2. 切回 AdClose 的自定义页面，点底部的「自动检测广告 SDK」；
3. 弹出检测结果后，按导入；
4. 确认上面的启用开关已打开，然后把目标应用从后台划掉重开。

实测中会碰到的情况：

- **一直扫不出结果**：回到目标应用再切回模块，重新检测一次。
- **导入项很多，担心影响应用**：作者说明大部分导入项是兜底性质，实际并不会全部处理；具体生效情况到 **Log 页面**翻日志核对（Log 页面自 3.9.7 版本提供，4.3.2 修复过相关问题）。
- **个别应用导入后闪退**：有用户反馈过这种情况，把最近导入的项关掉即可恢复，处理思路同 [常见问题与故障排查.md](常见问题与故障排查.md) 第四节。

## 五、验证与回退

改完规则或自定义项后，统一用两步收尾：重启目标应用 → 到 Log 页面确认拦截记录。发现误拦（应用某个功能坏了、页面缺内容），把最近一次添加的规则或导入项撤掉再重启应用，即可恢复原状。
