BotHub 里所有能聊天的模型都来自你自己接的服务，所以「模型服务」是装完之后第一个要动的地方。这一节按填写的先后顺序拆开讲：每一项填什么、去哪里拿、填错会看到什么。配通一个之后，后面再加就是重复同样的动作。

## 一、一份模型服务由三样东西组成

界面上要你填的东西看着杂，其实只有三项是必须对的：

| 项 | 是什么 | 去哪里拿 |
| --- | --- | --- |
| API 类型 | 这套接口按哪种协议说话。选错后面全对也连不上 | 由服务商说明页给出，一般是「OpenAI 兼容」这一种 |
| 服务地址 | 请求发到哪台服务器，通常形如 `https://xxx.com/v1` | 服务商的接口文档页，不是它的官网首页 |
| API 密钥 | 证明是你本人的一串字符，多数以 `sk-` 开头 | 登录服务商后台，在「API 密钥 / 令牌管理」里新建 |

第四项「模型」不用你拼：选完服务商后应用会去拉一份可用模型清单，你从里面挑。

## 二、添加一个模型的完整步骤

不同版本按钮位置可能微调，顺序是一样的：

1. **点对话页最上方中间的「选择模型」**，这时模型列表还是空的，正常。
2. **进入「模型服务」**。这一页管的是「接哪家服务」，和对话用的参数不是一回事。
3. **用搜索或浏览找到想导入的模型**：可以按名称或 ID 搜，也可以从内置的服务商列表里翻。内置列表覆盖了 Ollama、DeepSeek、Groq、OpenRouter、SiliconFlow、智谱、Grok、MiniMax 等一批；列表里没有的服务商，走「自定义」自己填。
4. **填写 API 相关信息，点右上角的 √ 完成导入。** 填完回到对话页，模型列表里就会出现它。

导入之后建议立刻测一次：新开一个对话，挑刚加的模型，发一句短的（比如「你好」），能正常出字才算配通。**别等到写长内容时才发现配错了。**

## 三、常见服务商的地址怎么填

服务地址最容易错在两点：**自己加或自己删 `/v1`**，或者**把官网首页当成了接口地址**。判断标准只有一个：**照抄服务商接口文档里给出的那个地址，一个字符都不改。** 有的服务商给的地址带 `/v1`，有的本身就是不带 `/v1` 的完整地址（比如 DeepSeek），两者都对，错的是「自己按习惯补一个」或「自己裁掉」。下面这几个地址是各服务商官方文档给出的接口地址，供对照（会调整，以官方当时页面为准）：

| 服务商 | 服务地址（API 类型选 OpenAI 兼容） | 密钥去哪拿 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | DeepSeek 开放平台后台的 API Keys |
| SiliconFlow（硅基流动） | `https://api.siliconflow.cn/v1` | 后台「API 密钥」新建，新建后只显示一次 |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4/` | 智谱开放平台「API Keys」 |
| Groq | `https://api.groq.com/openai/v1` | Groq 控制台的 API Keys |
| OpenRouter | `https://openrouter.ai/api/v1` | OpenRouter 后台的 Keys 页面 |
| 本机 Ollama | `http://<跑 Ollama 那台机器的 IP>:11434/v1` | 本机自建一般不需要密钥；同一台手机上填 `127.0.0.1` |

关于 Ollama 那一行补两句：跑在你自己电脑上时，手机要填的是**那台机器的局域网 IP**，不是 `localhost`；填 `localhost` 只在本机自己调用时才对。另外 Ollama 默认只监听本机，**不改设置的话手机永远连不上**，具体改法与安全边界见 [连自己电脑上的Ollama怎么连.md](连自己电脑上的Ollama怎么连.md)。

## 四、填错了会看到什么

报错信息来自服务商，读法是有规律的，按状态码对：

| 你看到的 | 意思是 | 先改哪里 |
| --- | --- | --- |
| 401 / Unauthorized / 密钥无效 | 密钥不对、被删了，或复制时带了空格和换行 | 回后台重新复制一整串；确认没把「项目 ID」当成密钥 |
| 403 / Forbidden | 密钥有效但没这个模型的权限，或余额为零 | 看后台该模型是否开通、账上还有没有额度 |
| 404 / Not Found | 地址不对 | 检查是不是漏了 `/v1`，或把官网地址填了进去 |
| 429 / Rate limit | 请求太密或额度用尽 | 停一会儿再试；看后台用量说明 |
| 连接超时 / 一直转圈 | 地址写错、网络不通，或服务商在维护 | 先用手机浏览器打开该地址，能出页面说明网络通 |
| 提示「配置错误」 | 上面几项里至少有一项不匹配 | 按「地址 → 密钥 → API 类型」的顺序逐项对 |

有一个省事的判断法：**先在电脑上用官方给的调用示例把同一个密钥跑通，再回手机填。** 电脑上通、手机上不通，问题在手机这一侧（网络或填错）；电脑上也不通，那就是密钥或额度的事，跟 BotHub 无关。

## 五、密钥怎么保管

- 密钥只存在应用本机，但它是明文可复制的——**别截图发到群里，也别写进教程和笔记**。
- 一旦怀疑泄漏，直接去服务商后台**删掉那把密钥再新建一把**，比改密码干净。
- 多把密钥按用途分开建（比如「手机端」「电脑端」各一把），哪把出问题就吊销哪把，不影响其它设备。

## 六、配通之后可以顺手开的两项

- **搜索服务**：在设置里选一个网络搜索提供商，模型需要查最新信息时会走它。不开也能正常聊天，只是模型的知识止于它的训练时间。
- **MCP**：用来给模型挂外部工具。用不上就不必开，开了之后模型能调用的动作变多，授权范围也跟着变大，**只挂你自己了解来源的 MCP 服务**。

这两项的开关状态如果被关掉，表现为「模型能聊天但不会联网、不会用工具」，不是故障。模型服务的启用与停用、以及对话参数套装怎么切换，见 [Bots管理和模型参数怎么切换.md](Bots管理和模型参数怎么切换.md)。
