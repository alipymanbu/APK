# CatShare 连接失败排查方法

> 本文按「搜不到设备 → 连上发不动 → 传一半断」的顺序排查，附已知机型坑和给开发者报问题的日志收集方法。

## 一、对方列表里看不到我（或我看不到对方）

按出现频率从高到低查：

1. **蓝牙没开**——发现环节全靠蓝牙，双方都要开。
2. **定位没开**——安卓限制：定位总开关关着就扫不到周边蓝牙 / WiFi 设备。注意是系统设置里的定位总开关，不只是给 CatShare 授权。
3. **CatShare 被后台清理**——接收方把应用划掉了，就不再广播。重新打开，并检查「后台运行 / 省电策略」没有限制它。
4. **距离太远**——靠近再试。
5. **双端蓝牙配对关系异常**——有官方客服建议：两台设备若存在旧的蓝牙配对关系，删除配对后重试（来源：荣耀俱乐部官方答复，适用于联盟设备间互传的通用排查）。
6. **重启双方**——上面都试过还不行，两台手机各重启一次再试。

## 二、发送时报「MAC 地址」相关错误

发送方的 MAC 没配对，就会发不出去。逐项确认：

- **还没配**——按 [开启Shizuku发送教程.md](开启Shizuku发送教程.md) 走一遍，优先 Shizuku 方案。
- **Shizuku 停了**——手机重启后 Shizuku 不会自动启动，重新启动它，CatShare 才能继续自动读取。
- **手动填的值过期**——设备待机时与发起传输时 MAC 可能不同，重新抓一次（以发起传输那一刻为准）。
- **Samsung 机型**——部分三星设备的 WiFi Direct MAC 会周期性变动，手动配置对它无效，只能用 Shizuku / 自动获取方案。

## 三、发送端提示「接收失败」但对方收到了

这是已知兼容情况：**从 OPPO / 一加等设备接收时，发送端会提示接收失败**（开发者标注的已测试结论）。先去接收方的传输记录或文件管理器确认文件到底到没到——到了就不用管这个提示，没到再按第一节排查。同一批已测试设备的情况见 [互传联盟是什么意思.md](互传联盟是什么意思.md)。

## 四、连上后传输中断或很慢

- 双方靠近，中途别让其中一台锁屏后系统清后台（CatShare 以前台服务运行时通知栏有常驻条目，确认它还在）。
- 关掉会占用链路的功能再试：个人热点、网络共享、屏幕共享类功能开着时，有官方客服反馈会造成「对方忙」或连续失败（来源：荣耀俱乐部官方答复）。
- 传大文件分多次试，能定位是特定文件的问题还是链路的问题。

## 五、都试过了还不行：收集日志报给开发者

CatShare 是开源项目，问题可以报到 [GitHub issue 区](https://github.com/kmod-midori/CatShare/issues)，最好附上 adb 日志。收集命令如下。

正式版（release）：

```shell
# macOS / Linux
adb logcat --pid $(adb shell pidof -s moe.reimu.catshare)
```

```bat
:: Windows cmd
for /f "tokens=1" %i in ('adb shell pidof -s moe.reimu.catshare') do adb logcat --pid %i
```

测试版（debug 包）把包名换成 `moe.reimu.catshare.debug` 即可。

提报时把「什么时候开始发送 / 接收、对端是什么机型」标清楚，日志长的话用折叠块包起来，方便维护者定位。
