# 把生成的APK发给别人

> 用 WebIDE 打包出来的 APK 想发给朋友或同事装：发之前检查什么、对方手机上会弹哪些拦截、更新版本怎么发。

## 一、发出去之前

- **确认加密开着**：默认就是开的；要发的人里如果有可能拿包研究源码的，检查一下「代码加密」开关（位置见 [打包生成安卓APK步骤.md](打包生成安卓APK步骤.md)）；
- **先装自己的手机过一遍**：名称、图标、启动页、页面功能都点一遍，确认没问题再发——发出去的版本就定稿了；
- **把 APK 当文件发**：聊天软件里直接发文件即可。别发一个链接让对方在聊天软件的内置浏览器里打开下载——这类内置浏览器经常下载不了 APK，让对方收到文件后从文件管理器装，或者换系统浏览器打开。

## 二、对方手机上会遇到的拦截

对方点开 APK 安装时，几乎一定会碰到下面之一的提示，都属于安卓对非商店安装的常规机制，不是包坏了：

| 提示 | 对方要做的 |
| --- | --- |
| 「禁止安装未知来源应用」 | 按提示进设置，给**这次用来打开 APK 的那个应用**放行——从微信里收的给文件管理或下载管理放行，浏览器下载的给浏览器放行 |
| 「安全风险」/「风险应用」 | 华为、小米等国产系统的例行提示，读一眼选「继续安装」或「仍然安装」 |
| 「Google Play 保护机制」拦截 | 带 Google 服务的机型会有：点「更多详情」展开，选「仍然安装」 |

可以提前跟对方说一句，省得来回解释：这个放行是**按来源生效**的，下次换了个渠道再装，系统还会再拦一次，照做一遍就行。

## 三、更新版本怎么发

- **包名别改**：同一个应用的更新沿用原来的包名，新 APK 装上去直接覆盖旧版，最省事；
- **覆盖装不上、提示「应用未安装」**：让对方卸掉旧版再装新版。安卓对同包名的覆盖安装有校验，校验不过就是这个提示，不代表新包是坏的；
- **改了包名再发**：系统会把它当成另一个应用，对方手机上出现两个图标。确定你真要并行两份再这么改。

## 四、对方装好之后还是不对

应用打不开、页面白屏这类问题多半出在打包之前的项目代码上，让对方把现象收集给你——机型、系统版本、卡在哪一步——然后回到你自己的手机上按 [常见问题排查.md](常见问题排查.md) 的路子复现一遍，比隔着聊天窗口猜快得多。
