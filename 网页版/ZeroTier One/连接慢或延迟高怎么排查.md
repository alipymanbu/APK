# 连接慢或延迟高怎么排查

> 能连上但延迟高、传文件慢 —— 先判断是不是走了中继，再对路由器侧动手，多数情况就这一个原因。

## 一、慢的根子：直连 vs 中继

ZeroTier 优先让两台设备**点对点直连**（最快，流量不经任何人）；打洞失败时退化成**中继**—— 包要绕经 ZeroTier 的基础设施再转发，延迟升高、可能丢包；最惨的一档是 UDP 完全不通、退回 **TCP 中继**，那是公认的最慢形态。官方文档把后两档明确列为「慢下来」的原因。

所以排查顺序永远是：**先确认走的哪条路，再谈别的。**

| 形态 | 数据走哪 | 表现 |
| --- | --- | --- |
| DIRECT（直连） | 两设备之间直接走 | 延迟最低，速度取决于两端物理带宽 |
| RELAY（中继） | 经 ZeroTier 基础设施转发 | 延迟明显升高、可能丢包 |
| TUNNELED（TCP 兜底） | 走 TCP 中继 | 最慢，只在 UDP 完全被封时出现 |

## 二、怎么判断当前是哪条路

**电脑端能直接看命令。** 在怀疑慢的那台电脑上（Windows 用管理员终端，Linux / macOS 加 `sudo`）：

```bash
zerotier-cli peers
```

输出里找到对端设备那 10 位 Node ID：`link` 列是 `DIRECT` 就是直连，`RELAY` 就是中继；`path` 列没有 IP 地址 = 正在中继。再看一眼兜底状态：

```bash
zerotier-cli info
```

显示 `ONLINE` 正常；显示 `TUNNELED` 说明 UDP 不通、正走 TCP 中继 —— 这是最需要处理的信号。

**控制台也能粗看**：网页端成员列表里，该成员有 **Physical IP** 一项的多为直连成功；空着的可能在中继。手机端没有命令行，看间接信号：延迟持续几十上百毫秒且飘、传文件明显比预期慢，先按下面第三节处理路由器侧。

## 三、路由器侧该检查什么（提速的真正抓手）

官方路由器建议里，对打洞影响最大的几条，按性价比排：

1. **别限制出站 UDP。** 有的路由器 / 安全软件默认拦 UDP，直接判死刑。
2. **开 UPnP 或 NAT-PMP。** 让两端能自动映射端口，打洞成功率大幅提高。
3. **别用「对称型（symmetric）NAT」**，用全锥或端口受限锥形 NAT。对称 NAT 对 P2P 最不友好（顺带也会拖累视频会议、游戏这类流量）；多层 NAT（光猫+路由各做一层）同样要尽量避免 —— 能让光猫改桥接就改。
4. **防火墙放行 UDP 9993**（ZeroTier 默认监听端口），本地电脑上的防火墙同理；安全软件只放行了部分程序的，要给 ZeroTier 服务放行。
5. **关掉 Wi-Fi 的「客户端隔离 / AP 隔离」**之类功能 —— 同网段设备被隔离会逼着本该走局域网的流量绕公网。

路由器改完后，重新跑一次第二节的命令看有没有变 `DIRECT`。不支持 UPnP 或改不了光猫的环境（公司网、校园网），能做的有限 —— 那是环境限制，不是你配置错了。

## 四、几个容易误会的事实

- **付费不影响速度。** 官方 FAQ 写明性能与账号订阅等级无关，别指望升级套餐解决慢。
- **中继不限速，但绕路。** 官方说明中继不人为限速、也读不了加密内容，代价是物理距离变远、延迟和丢包上来 —— 所以「慢」要拆开看：延迟高基本是中继，吞吐低则还要看两端自己的带宽。
- **物理上限改不了。** CPU 加解密速度、两端宽带、地理距离都是硬约束；跨大洲的延迟谁也救不回来。

## 五、处理之后还是慢

把能查的查完（第二节命令确认直连、第三节路由器项都做了），延迟仍不正常，方向就剩两个，都在 [常见问题与解决办法.md](常见问题与解决办法.md) 里：

- 目标机器自己的防火墙拦了虚拟网卡上的流量（见该篇「换了 DNS 或网络后行为怪异」一节）；
- 手机端频繁掉线重连，体验上变成「时快时慢」（见该篇「状态一直不是 Online」一节，多半是后台被杀）。

排除完这两处仍无解，就是当前网络环境不适合打洞，属于客观限制，别再对着手机端反复开关 —— 那不改变任何底层路径。
