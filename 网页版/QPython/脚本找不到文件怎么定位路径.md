## 一、九成是「工作目录」和你想的不一样

报错原文长这样：

```text
FileNotFoundError: [Errno 2] No such file or directory: 'data.csv'
```

原因几乎只有三种：**路径写错了**（大小写、少个目录）、**文件根本不在那**、**相对路径的起点不是你以为的那个目录**——第三种最常见，也最容易被忽略：`open("data.csv")` 是相对**运行时的工作目录**解析的，不是相对脚本文件所在的目录（这条在多个独立的 Python 排错资料里口径一致）。

## 二、三段代码，一次把位置问清楚

在终端或脚本里逐段跑，每段都给你一个可执行的判据：

```python
import os

# 1. 当前工作目录是什么 —— 相对路径就从这里算起
print(os.getcwd())

# 2. 那个文件到底在不在
print(os.path.exists("data.csv"))

# 3. 列出当前目录里都有什么（大小写敏感，肉眼核对文件名）
print(os.listdir("."))
```

第 1 行打印的路径若和文件所在目录不一致，就是工作目录不对；第 2 行返回 `False` 而文件明明在手机里，说明路径或目录不对；第 3 行能直接看出是 `data.csv` 还是 `Data.csv` —— 安卓底层是 Linux，**路径区分大小写**，`data.csv ≠ Data.csv`。

## 三、两种修法，按场景选

**修法一：改成相对脚本本身的路径**（脚本和数据文件放同一个文件夹时最稳，换设备也不用改）：

```python
import os

script_dir = os.path.dirname(os.path.abspath(__file__))
file_path = os.path.join(script_dir, "data.csv")

with open(file_path, "r", encoding="utf-8") as f:
    print(f.read())
```

`__file__` 是脚本自己的路径，`os.path.dirname()` 取它的目录 —— 于是相对路径的起点从「运行时碰巧在哪」变成「脚本实际在哪」。

**修法二：把工作目录切到脚本所在目录**（一次性解决整份脚本里的所有相对路径）：

```python
import os

os.chdir(os.path.dirname(os.path.abspath(__file__)))
print("现在的工作目录：", os.getcwd())
```

只想临时验证一个路径是否存在，用 `os.path.exists("/storage/emulated/0/Download/data.csv")` 打印 `True/False` 就够，别一上来就改代码。

## 四、手机上数据文件放哪最省事

| 位置 | 读得到吗 | 说明 |
| --- | --- | --- |
| 脚本所在的那个目录 | 稳 | 首选：文件跟脚本放一起，用修法一永远找得到 |
| 应用自己的内部目录 | 稳 | 编辑器保存时选应用内目录即可，路径从 `os.getcwd()` 里看 |
| 公共目录（Download 等） | 看权限 | 要 QPython 拿到文件权限才行，被拒就是 `EACCES`，处理见 [常见报错与问题排查.md](常见报错与问题排查.md) |

**把文件弄进手机**：电脑上的文件用数据线拷进目标目录，或先传到网盘再在手机端下载后移动过去；一小段文本/代码还可以用主界面的「二维码」扫进来（见 [第一个脚本怎么写并运行.md](第一个脚本怎么写并运行.md) 第五节）。

## 五、还有一种「路径对了也读不了」

文件确实在、`os.path.exists()` 返回 `True`，但 `open()` 仍被拒 —— 那是**权限**问题不是路径问题（典型报错 `EACCES (Permission denied)`），转 [常见报错与问题排查.md](常见报错与问题排查.md) 第四节按权限处理；若报的是编码错误（`UnicodeDecodeError`），在 `open()` 里显式写 `encoding="utf-8"`，中文文件尤其需要。

**一句话顺序**：先 `getcwd()` 看位置 → 再 `exists()` 看存在 → 再核大小写 → 都对还不行才去查权限。
