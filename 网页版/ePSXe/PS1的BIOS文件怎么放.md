# ePSXe 的 PS1 BIOS 文件怎么放

> 没有 BIOS，这份模拟器一个游戏也进不去。本篇讲清它是什么、文件名与体积长什么样、放进哪个文件夹能被自动扫到，以及怎么用「Run bios」确认它已经生效。

PS1 的 BIOS 是原机固件的转储文件，模拟器要靠它完成开机自检、进入记忆卡管理和启动游戏。它不在安装包里，也不随应用一起装，版权属于索尼，需要你自己准备。这篇只讲「放哪、怎么确认生效」，不涉及从哪里获取。

## 一、先明确三件事

- **BIOS 要自备**：网盘里那份只是模拟器本身，不含 BIOS，也不含任何游戏。另外存在一种不装真实 BIOS 也能跑一部分游戏的内置模式，放在第七节单独说。
- **来源要合法**：BIOS 版权归索尼，通常的做法是从自己拥有的主机上导出。本文与网盘资源都不提供 BIOS，也不指向任何下载站。
- **不完整会白折腾**：常见文件名是 `SCPH1001.bin`、`SCPH7502.bin`，`SCPH7000` / `7001` / `7003` / `5502` 等其他型号 ePSXe 也认。它们有一个共同特征 —— **体积固定 512 KB**。这一条是最快的真伪判据：拿到一个明显不是 512 KB 的所谓 BIOS，基本可以先判定它不完整，不必再往下试。

## 二、放进哪个文件夹才会被自动扫到

从 2.0.16 起，ePSXe 不再全盘扫描存储找 BIOS，它只扫你首次启动时指定的那个「基准文件夹」（概念见 [下载与安装教程.md](下载与安装教程.md) 第四节）。

| 你的情况 | BIOS 放哪 | 要不要手动指定 |
| --- | --- | --- |
| 基准文件夹选在共享存储（推荐） | 直接放进这个文件夹，建议在它下面建个 `bios` 子目录 | 不用，会自动扫到并配好路径 |
| 基准文件夹选在私有存储 | 放进私有目录，或另放别处 | 要，手动挑一次 |
| 文件放在游戏目录、下载目录等别处 | 无所谓 | 要，手动挑一次 |

**顺序建议**：先把 BIOS 放进基准文件夹，再打开 ePSXe —— 这样它启动时扫描一次就能认出来，省掉手动指定的步骤。

## 三、手动指定 BIOS 路径

自动扫不到，或者想换一个 BIOS 时：

1. 进 **Preferences → Bios preferences → Bios file**；
2. 在文件选择器里定位到你存放的 `.bin` 文件并选中；
3. 返回主界面。Android 10 及以下的老版本还有「首次自动扫描 sdcard」的行为，扫不到时也是在这里手动指定。

换 BIOS 型号不需要重装应用，改这一处路径即可。

## 四、怎么确认 BIOS 真的生效了

主界面上有个 **Run bios** 按钮，它就是用来验证的：

1. 点 **Run bios**；
2. 过几秒应该能看到索尼开机的画面（PS 标志），随后进入一张记忆卡管理界面；
3. 到这一步说明 BIOS 已被正确读取，可以退出，去准备游戏了。

点下去没反应、长时间黑屏、或者直接回到主界面，按下面的顺序查：

| 现象 | 先查什么 |
| --- | --- |
| 点了 Run bios 没反应 | BIOS 路径没指定，或指到了别的文件 |
| 黑屏几秒后退出 | 文件不是 512 KB 的完整 BIOS，或文件损坏 |
| 提示找不到文件 | 文件被挪走了，或权限没给全（见下一节） |
| 之前好好的突然不行 | 基准文件夹被清理工具动过，或权限被系统回收 |

## 五、几个容易踩的点

- **从压缩包里解出来再放**：BIOS 不能以 zip / 7z / rar 的形式留在设备里，ePSXe 读不到压缩包内的文件，必须先解压出 `.bin`。文件名大小写不影响识别，`.bin` 后缀别改。
- **权限要给全**：Android 11 及以上，BIOS 放进去了却读不到，第一嫌疑是外部存储权限。按 [下载与安装教程.md](下载与安装教程.md) 第五节的六步开一次「全部文件访问」。
- **多份 BIOS 都放进文件夹时**，优先用 `SCPH1001.bin` 或 `SCPH7502.bin` 这两个最常用的型号，其余不必一起塞进去。
- **Android 11 上的分区存储问题**：2.0.17 这一版的更新内容里就包含「修复 Android 11+ 分区存储下的若干问题」。如果你手上是更早的 2.0.15 或更早版本，遇到 BIOS 读不到，先考虑升级到 2.0.17 再排查。
- **BIOS 与游戏是两件事**：BIOS 通了不代表游戏能跑，游戏文件本身的格式与存放位置是另一套要求，见 [游戏镜像格式与存放位置.md](游戏镜像格式与存放位置.md)。

## 六、没有 BIOS 会怎样

不会报一个明确的「缺少 BIOS」错误，而是表现为：游戏选进去了但一启动就退回主界面，或者卡在黑屏。这一点和「游戏镜像损坏」的现象很像，区分办法很简单 —— 点一次 **Run bios**。Run bios 正常出索尼画面，说明 BIOS 没问题，那问题就在游戏文件上，去 [常见问题与排查.md](常见问题与排查.md) 第二节按 `system.cnf` 那一条查。

有一种情况会让上面这段判断不成立：**如果你用的是第七节那个内置的 HLE 模式**，那么「没装 BIOS」本身不会再导致退出，取而代之的是兼容性问题 —— 表现可能是某些游戏进不去、画面异常或存档异常。判断方法仍然一样：装一个真实 BIOS 再试同一款游戏，问题消失了就是 HLE 模式的兼容性所致。

## 七、不装真实 BIOS 行不行：内置的 HLE 模式

答案是可以。ePSXe 从 1.9.25 起内置了一个高层仿真（HLE）BIOS，打开它就不再需要你自己准备固件文件。官方对这件事的原话是：**从这一版起 ePSXe 可以脱离官方 PS1 BIOS 运行游戏**，但给了三条限制 —— **兼容性更低**、**记忆卡支持有限**、**即时存档不互通**（真机 BIOS 与 HLE BIOS 的存档命名空间不同，两边互不兼容）。

怎么选：

| 你的情况 | 建议 |
| --- | --- |
| 已经有合法的 BIOS 文件 | 用真实的 —— 兼容性和存档完整度都更好 |
| 只是想先试一下能不能跑、暂时没准备 BIOS | 先用 HLE 模式启动，确认设备没问题再补 BIOS |
| 已经用真实 BIOS 存了一堆即时存档 | **不要切到 HLE**，切了旧存档读不回来；确定要切就先把进度存进记忆卡 |

一条操作上的经验（来自一份对该应用的公开分析，不是官方口径）：**自动识别对文件有条件 —— 体积要恰好 512 KB、扩展名要是 `.bin`**，不符合的文件即使内容没问题也可能扫不到；而且它是在你的存储里逐层往下找的，会跳过 `Android/data` 这类系统目录。所以把 BIOS 放进基准文件夹、最好是它下面的 `bios` 子目录，识别成功率最高；满足不了这些条件就走第三节的手动指定。
