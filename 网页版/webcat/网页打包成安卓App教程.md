## 一、打包前先确认项目能跑

打包是把你项目里的网页装进一个安卓壳里，**壳本身不会替你修页面的错**。打包前先在编辑器里点运行、确认预览正常——页面空白或报错就先改完再打包，否则打出来的 App 装上也是同样的错。项目还没建、预览还没通的，先走 [新建项目与运行预览教程.md](新建项目与运行预览教程.md)。

## 二、打包步骤

多份图文教程对 5.21 这版的步骤描述一致，就四步：

1. 首页右下角点 **+ 号**，新建一个工程（已有工程跳过这步）；
2. 在工程列表里**点进**你要打包的那个工程；
3. 点工程界面里**菜单入口**（教程截图中标注为箭头所指位置，通常在标题栏一侧）；
4. 选**打包**，等它在本地生成 APK。

打包全程在手机本地完成，不经过电脑、也不需要装 Android Studio 之类的开发环境。生成的 APK 在打包完成页或手机的下载/输出目录里能找到，直接点开安装（安装授权见 [下载与安装教程.md](下载与安装教程.md) 第三节）。

## 三、打包时能自定义什么

按官网说明，打包界面允许你自定义这些项：

| 项 | 说明 |
| --- | --- |
| 包名 | 决定它在手机里占哪个身份——**别填成 `top.webcat.editor`**（那是 WebCat 自己），也别和手机上已装的某个应用同包名，否则会被系统当成同一个应用去覆盖 |
| 应用名 | 桌面上显示的名字 |
| 图标 | 换成你自己的图 |
| 权限 | 勾选这个 App 要申请的安卓权限 |
| 版本号 | 你自己的 App 的版本 |

包名、版本号这类信息第一次填完建议记下来——以后出新版再打包，包名保持一致才能覆盖安装升级。

## 四、打包出来的 App 是什么形态

它本质是「网页 + 安卓壳」：你的 HTML/CSS/JS 被装进 WebView 里跑。因此两条边界要清楚：

- **页面代码里的网络请求照常走网络**——打包不等于离线化，需要联网的页面装上照样要联网；
- 壳能给页面多少原生能力，取决于版本：官网对新版（WebCatX）明确写了页面可调用读写文件、保存相册、拍照、分享、权限申请等安卓能力；你手里这份 5.21 是旧版打包插件的延续（该插件 2021 年的 3.07 版就重构过一轮，修掉长按闪退、音频无法播放、自定义名称/包名不生效等问题）。两版差异见 [旧版和WebCatX新版怎么选.md](旧版和WebCatX新版怎么选.md)。

## 五、打出来了但装不上

生成成功、点安装却失败，最常见的三个原因：手机存储空间不足、系统没给当前来源「安装未知应用」权限、新填的包名与手机里已装应用冲突。逐条排查见 [常见问题与故障排查.md](常见问题与故障排查.md) 的对应小节。打包前想先把项目源码存一份底，见 [代码导出与共享空间使用.md](代码导出与共享空间使用.md)。
