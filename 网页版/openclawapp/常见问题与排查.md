## 电脑端：装不上 / 命令找不到

**`openclaw: command not found`**

npm 的全局 bin 目录不在 PATH 里。先看全局前缀：

```bash
npm prefix -g
```

把输出路径下的 bin 目录加进 PATH（macOS / Linux 写进 shell 启动文件；Windows 在系统环境变量里加），重开终端再试。

**npm 全局安装报权限错（EACCES）**

把 npm 全局前缀改到用户可写目录，别用 sudo 硬来：

```bash
mkdir -p "$HOME/.npm-global"
npm config set prefix "$HOME/.npm-global"
export PATH="$HOME/.npm-global/bin:$PATH"
```

**Node 版本不满足**

`node -v` 查一下：官方当前要求 24.16+ 或 26.1+，推荐 26 系（以官方安装页为准）。版本太老先升 Node，再动 OpenClaw。装完跑一次 `openclaw doctor`，配置层面的问题它会直接指出来。

**Gateway 起不来或端口被占**

换个端口前台跑，顺便看完整日志定位问题：

```bash
openclaw gateway --port 18789 --verbose
```

## 手机连不上 Gateway

**发现列表里没有网关**

多半是网络隔离：路由器开了 AP 隔离、连的是访客网络、或手机在用流量。处理顺序：确认两端同一网段 → 不行就手动填电脑 IP + 端口（默认 18789）→ 跨网络就让两端进同一 Tailscale 网络再连。连接入口在 app 的 Connect 标签页（详见 [手机端配对与连接.md](手机端配对与连接.md)）。

**扫了 Setup Code 一直没反应**

配对请求要在电脑端批准才生效：

```bash
openclaw devices list
openclaw devices approve <requestId>
openclaw nodes status
```

认证信息变过的话，app 可能会生成一条新请求——批准最新的那条。

**连上又频繁掉线**

确认通知栏的常驻通知还在：前台服务被杀，连接就断。各厂商安卓的后台策略不同，把 app 加入电池白名单、允许自启动，通常能稳住。

## 配对与权限问题

**配对码过期**

私信配对码是 8 位大写（不含 0/O/1/I 这类易混字符），1 小时过期；每个渠道账号最多同时挂 3 条待审请求，挂满后新请求被忽略——等一条过期或批准掉，再让对方重新给 bot 发一次消息即可生成新码。

**私信批了，群里还是没反应**

私信批准只管私信；群组是另一份白名单（`groupAllowFrom` / `groups`）。别把两类权限混着查，判别思路与配置见 [安全设置与权限管理.md](安全设置与权限管理.md)。

**Telegram bot 在群里完全不说话（连 @它 也不理）**

逐层查：bot 还在群里吗 → 群的 chat ID 放进 `channels.telegram.groups` 了吗 → Telegram 侧的 Privacy Mode 是不是把消息挡了。第三层最常见：bot 默认收不到群里的普通发言，要么在 BotFather 用 `/setprivacy` 关掉、要么把 bot 设为群管理员，而且改完要把 bot 移出群再拉回来才生效（完整链路见 [Telegram渠道接入步骤.md](Telegram渠道接入步骤.md)）。

## 配置与更新

**想换模型 / 改渠道配置**

`openclaw configure` 重新走一遍配置；改完 `openclaw gateway restart` 生效。配了新模型却不生效的话，按顺序查两处：当前会话是不是还挂着旧模型（会话内用 `/model` 切，或开新会话）、Gateway 有没有重启。逐项对照见 [切换AI模型与APIKey配置.md](切换AI模型与APIKey配置.md)。

**升级电脑端**

```bash
openclaw update --channel stable
```

升级前先确认 Node 还在官方要求的版本线上。手机端 app 的更新与电脑端是两条线：网盘里那份安装包对应 10.0 版（获取入口见 [下载与安装教程.md](下载与安装教程.md)），新版本出来后以官方发布页为准。
