## 一、先说结论：0.8.1 就是手机版当前的最新版

很多人装完第一反应是「这是不是旧版，要不要升级」。事实是：官方安卓手机版的发布停在 **0.8.1**——F-Droid 页面上最新的就是 0.8.1（更新于 2021 年 3 月），手机版仓库的说明与发布页也停在这个版本号。所以你从任何渠道拿到的 0.8.1，就是官方手机版线当前的最新版本，不存在「装了旧版要升级」的问题。

项目的活跃度集中在**桌面版与浏览器插件版**上，它们与手机版是独立版本号、独立发布节奏，别拿桌面版的版本号（如 2.x）去对比手机版的 0.8.1。此结论截至本文写作时间，之后是否有新手机版本发布，以 F-Droid 页面 [https://f-droid.org/packages/com.listen1.app](https://f-droid.org/packages/com.listen1.app) 与发布页 [https://github.com/listen1/listen1_mobile/releases](https://github.com/listen1/listen1_mobile/releases) 的实际显示为准。

## 二、三个渠道的差别

| 渠道 | 特点 | 适合谁 |
| --- | --- | --- |
| 夸克网盘（本篇开头） | 安装包已备好，国内下载稳定 | 不想折腾的用户 |
| F-Droid 官方页面 | 官方收录，页面标注版本、权限、系统要求 | 想要可核对信息的用户 |
| GitHub 发布页 | 官方原始发布，能看到历史版本与更新说明 | 想查更新日志的用户 |

两个值得注意的细节：

- **F-Droid 页面自己的提示**：直接下 APK 装不会收到更新通知，它更建议装 F-Droid 客户端来管理；不装客户端、只用网页下 APK 也完全可以，只是要自己留意新版本。
- **签名差异**：F-Droid 页面的包由 F-Droid 构建并签名，与 GitHub 发布页的包**不是同一签名**。从 F-Droid 装的再换 GitHub 包覆盖安装（或反过来）会报签名冲突，得走「备份 → 卸载 → 装 → 恢复」流程，具体见[下载与安装教程.md](下载与安装教程.md)第三节。

## 三、系统要求与包体

F-Droid 页面标注 0.8.1 需要 **Android 4.1 及以上**，一台很老的手机也能跑。安装包覆盖 arm64-v8a、armeabi-v7a、x86、x86_64 四种架构，体积约 23 MiB，新旧设备都不用挑。

| 项目 | 值（F-Droid 页面标注） |
| --- | --- |
| 系统要求 | Android 4.1 及以上 |
| 支持架构 | arm64-v8a / armeabi-v7a / x86 / x86_64 |
| 包体大小 | 约 23 MiB |

## 四、权限清单（以 F-Droid 构建为准）

F-Droid 页面列出的 0.8.1 权限一共三项：

1. **拥有完全的网络访问权限**——搜索与在线播放必须；
2. **查看网络连接**——判断当前网络状态；
3. **运行前台服务**——播放持续进行所依赖的机制。

没有定位、通讯录、短信这类敏感权限。如果你在安装时看到它请求了比这三项更多的权限，说明那份包不是 F-Droid 构建的官方包，谨慎对待。

## 五、以后怎么知道有没有新版本

三个地方按顺序看：

1. F-Droid 页面的版本区（有更新会在这里出现版本号变化）；
2. GitHub 发布页（能看到每版改了什么）；
3. 官方主页 [https://listen1.github.io/listen1](https://listen1.github.io/listen1)（产品线整体动态）。

真出了新版本要升级时：先备份歌单（见[数据备份与恢复.md](数据备份与恢复.md)），确认新包与已装包签名一致就直接覆盖装；不一致按「备份 → 卸载 → 装 → 恢复」走。手机版平台集合与桌面版的差异、以及来源停服等问题，集中在[常见问题与解决办法.md](常见问题与解决办法.md)。
