排查这类「壳 + 扩展」的应用，有个通用原则：**先分清问题出在 Miru 本体，还是出在你装的某个扩展。** 验证方法基本就一个 —— 换一个源试同一件事。下面每条都按这个思路给判据。

## 一、装不上 / 装完打不开

| 现象 | 先查什么 |
| --- | --- |
| 提示「应用与设备不兼容」 | CPU 架构对不上。官方按 arm64-v8a / armeabi-v7a / x86_64 分开打包，到官方发布页对照机型 |
| 提示「签名不一致」「已存在同名应用」 | 手机里已有同包名的其他版本，先卸载旧的再装 |
| 装完点开闪退 | 重下一次安装包；仍不行，换官方发布页里对应架构的那个包 |
| iPhone 上找不到 | 官方没有 iOS 版，苹果设备只能走网页版 |

版本核对见 [下载与安装教程.md](下载与安装教程.md)；需要重新取包时，走 [Miru 安装文件资源（夸克网盘）](https://pan.quark.cn/s/4a0e1afd83af)。

## 二、搜索是空的

**最常见的是两个原因，占了绝大多数情况：**

1. **一个扩展都没装** —— Miru 本体不带内容，没装扩展时搜索必然为空；
2. **装了但类型不对** —— 你要搜影视，却只装了 manga / fikushon 类扩展。

排除这两条之后，就是源本身的问题：换一个同类源搜同一个词，别的源能搜到，就说明原源失效了。装扩展的方法见 [扩展怎么安装与管理.md](扩展怎么安装与管理.md)。

## 三、能搜到但播不了

按成本从低到高试：

1. **换线路**：视频条目一般有多条线路，换一条继续；
2. **换源**：同一部作品换个源打开；
3. **换网络**：切到流量或另一个 Wi-Fi 再试 —— 能验证是不是当前网络把这个域拦了；
4. **等一会儿**：源站在高峰时段会明显变慢，过一段时间再试。

## 四、扩展失效了

扩展本质上是「按目标网站的页面结构去取内容」的一段代码。目标网站改版，扩展的取法就失效 —— 这不是你能修的，正常做法是：

- **等扩展更新**：在扩展页看有没有更新提示，有就更；
- **换源**：官方仓库里同类源通常不止一个；
- **换自定义仓库**：官方源长期不更新时，社区仓库里常有在维护的替代源，添加方法见 [扩展怎么安装与管理.md](扩展怎么安装与管理.md)。

## 五、Windows 端相关

| 现象 | 可能原因 |
| --- | --- |
| 双击没反应 / 启动即退出 | 换另一种包型试：安装版 `.exe` 与免安装 `.zip` 互相对调 |
| 界面显示异常 | 更新显卡驱动，或改一下系统显示缩放比例再试 |
| 卸载后设置还在 | 卸载后手动删掉应用数据目录，再重装 |

Linux 桌面上官方已说明因依赖问题暂不支持，不必在 Linux 上花时间。

## 六、网页版和客户端不一样

官方提供网页版实例，但网页受浏览器限制，能用的功能有限，官方也建议优先用客户端。网页版里遇到的「装不了扩展 / 播不了」，多数不是 bug，而是网页版的固有边界 —— 想要完整功能就装客户端。

## 七、代理怎么设置

Miru 支持配置代理。某些网络环境下源站直连不通时，配代理是可行的解法，填法在设置里，前提是你自己有一份可用的代理地址。

填完仍然不通，先在别的应用里验证这份代理本身能不能用 —— 这样能把「代理坏了」和「Miru 配错了」分开，省掉来回试。

## 八、改完设置好像没生效

改设置后界面没变化，先**完全退出应用**（不是退到后台）再重开一次。官方在 1.8.1 的更新说明里修过「扩展设置未保留」这类问题，说明设置项偶有没存住的旧毛病，重开是最省事的验证。

安卓上还要注意系统的省电策略：应用被后台冻结时，播放和缓存都可能被中断。

## 九、升级、重装与数据

| 你做的操作 | 会怎样 |
| --- | --- |
| 覆盖安装新版本 | 设置、进度、已装扩展通常都保留 |
| 卸载后重装 | 设置、进度、已装扩展全部清空 —— 数据存在本机，不跟随账号 |
| 换一台设备 | 同上，等于从零开始，要重新装一遍扩展 |

此外，官方在 1.8.1 的发布说明里修过两条安卓端相关的问题，其中一条是「BT 服务器无法启动」。如果你在用的版本里，BT 相关的设置或功能一打开就报错，升级到包含该修复的版本是官方给出的修法。

进度为什么不跟着设备走，原因见 [搜索与播放怎么用.md](搜索与播放怎么用.md) 第五节。
