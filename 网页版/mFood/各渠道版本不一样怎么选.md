# mFood 各渠道版本不一样怎么选

> 同一个 mFood，在应用宝、下载站、网盘里的版本号对不上是常态。本篇讲清为什么会这样、以及你该装哪个。

## 一、先把事实摆出来：四处给出的版本号都不一样

截至 2026-09，同为包名 `com.m.mfood` 的安装包，各处标的是：

| 渠道 | 标出的版本 | 标出的日期/大小 |
| --- | --- | --- |
| 腾讯应用宝 | 6.9.5 | 2026-01-17 更新 |
| 第三方下载站 A | 7.3.6 | 2026-09-01，112.92MB |
| 第三方下载站 B | 7.3.5 | 2026-09-07，83.2M |
| 本文对应的网盘安装包 | **7.2.0** | 采集于 2026-09-22，112.89M |

**包名完全相同，版本号却横跨 6.9.5 到 7.3.6** —— 说明这不是多个应用，而是**同一个应用在不同渠道的上架节奏不同**：应用宝这一侧更新明显滞后（停在 1 月的 6.9.5），第三方下载站抓得快但大小标注未必可信（83.2M 与 112.9M 差了近 30M，其中至少有一个是旧包或裁剪包）。

另外注意大小口径：网盘里那份实际是 112.89M（约 118,369,492 字节），与标 112.92M 的那家基本一致，可以互相印证；标 83.2M 的那家对不上，别拿它当准。

## 二、还有个坑：商家版是另一个包

mFood 官网的下载区放了两个按钮：

- 顾客端 → `com.m.mfood`（你手上这套文档对应的包）
- **商家端 → `com.m.merchant`**（商户接单用）

两个应用名字都叫 mFood，装错了你会看到完全不同的界面。判断方法只有一条：**看包名**。你要点外卖，包名必须是 `com.m.mfood`。

## 三、怎么选：按你的目的定

| 你的情况 | 建议 |
| --- | --- |
| 手机能访问 Google Play | 直接从商店装，后续更新自动走商店，省心 |
| 想与网盘里那份完全一致 | 用网盘的 7.2.0（包名、大小、MD5 见 [下载与安装教程.md](下载与安装教程.md) 的表格） |
| 只想装个能用的、不折腾 | 应用宝能装，但版本停在 6.9.5（2026-01），**部分较新的活动/功能可能没有**——银联立减那类活动曾明确要求 V5.8.5 以上，版本太旧会直接拿不到资格 |
| 从第三方下载站下 | 先核对大小与包名；大小对不上的（如 83.2M 那个）跳过 |

**判断「版本够不够新」最实用的标准不是版本号本身，而是功能能不能用**：打开应用看结算页有没有立减栏、卡券页有没有最新那批券。能显示就是版本没拖后腿。

## 四、装了旧版怎么升

- 应用宝装的：在应用宝里更新，或改用商店/网盘包覆盖安装。
- 网盘 APK 装的：拿一个更高版本的 APK 直接覆盖安装即可，登录态与地址一般保留。
- 覆盖安装报「签名不一致」：说明两个包来自不同签名渠道，先卸载再装——卸载会清掉登录与设置，券码和地址先记下来。

## 五、版本号本身怎么读

mFood 用三段式版本号（`7.2.0` → `7.3.5` → `7.3.6`），从左往右逐段比大小即可。官方没有公布版本号命名规则，也**没有公开的更新日志页面**——第三方站上标着的「更新内容」多是它们自己拼的，参考价值有限。想知道新版改了什么，最可靠的是装上后自己看首页有没有新板块。

时效提示：上表里的数字是 2026-09 的快照，会随时间变化，以各渠道页面当时显示为准。
