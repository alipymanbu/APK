## 一、iOS / macOS 连不上局域网 OPDS 书库

症状：点家里局域网的 OPDS 目录（`192.168.x.x`、`10.x.x.x`、`.local` 主机名，或自己的 calibre 内容服务器）一直没反应，同一个地址在浏览器里却打得开。

原因与解法：iOS、iPadOS 与 macOS 15+ 的「本地网络」权限没给。到 系统设置 → 隐私与安全性 → 本地网络，把 Readest 的开关打开；如果列表里根本没有 Readest，先在应用里打开一次 OPDS 目录，让系统记录到这次访问再回去看。公网目录（Standard Ebooks、Project Gutenberg 这类）不走局域网，不需要这个权限。

## 二、calibre 服务器报 400 Bad Request

症状：连设了密码的 calibre 内容服务器时提示 `Failed to load OPDS feed: 400 Bad Request`，把密码关掉就正常。

解法：把 calibre 的认证模式从默认的 digest 改成 basic——calibre 里打开 偏好设置 → 通过网络分享 → Advanced，把 `auth_mode` 设为 `basic`，重启内容服务器后再连；命令行启动的加 `--auth-mode=basic`。

提醒：basic 模式下密码几乎等于明文传输，只建议在家庭局域网里、或服务器已挂 `https://` 时这么设。

## 三、Linux Flatpak 中文显示成方块

症状：Flatpak 装的 Readest 里中日韩文字全是「豆腐块」。原因是 Flatpak 沙盒默认看不到系统字体目录。

解法：给 Readest 只读开放字体目录，然后重启应用：

```bash
flatpak override --user --filesystem=/usr/share/fonts:ro com.bilingify.readest
flatpak override --user --filesystem=xdg-data/fonts:ro com.bilingify.readest
```

## 四、存储占用比预期大

每台设备都会留下「你在这台设备上打开过」的书文件副本，且不会被自动清理；用了一阵的手机占几个 GB 属于正常现象。一个常见误区是去点移动端的 Manage Cache——它只清临时文件，按设计不动你已下载的书。正确的清理入口是书详情里的 Remove from Device Only（只删文件、保留进度与标注），完整步骤与「批量删除会连云端一起删」的注意事项见 [多设备同步与备份](多设备同步与备份.md) 第五节。

## 五、校验安装包是不是被人动过

从官方 Releases 页以外的渠道拿到安装包时值得核对：

- **桌面安装包**（Windows / macOS / Linux）：官方用 minisign 签名，每个包在 Releases 页配有同名 `.sig` 文件，核对步骤见官方文档 Advanced 的 Verify release files 一节；
- **安卓 APK**：直接比 MD5，网盘这份 APK 的包名与 MD5 值写在 [下载与安装教程](下载与安装教程.md) 第二节。
