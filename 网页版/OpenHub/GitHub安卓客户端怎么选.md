## 一、什么情况下选 OpenHub

对照下面几条，命中越多越适合：

1. **设备偏老或存储紧张**：安装包只有 3.23 MB（本文以 3.2.1 版实测为准），还支持移动到 SD 卡；
2. **手机没有谷歌服务框架（GMS）**：OpenHub 明确不依赖 GMS 运行，国产 ROM、类原生系统上功能不受影响；
3. **想要中文界面**：简体、繁体中文都内置，语言覆盖在同类开源客户端里算全的；
4. **习惯多账号切换、离线浏览**：这两个是 OpenHub 相对早出的特性；
5. **在意开源可查**：GPL-3.0 协议，源码在 GitHub 公开。

对应的短处也直说：项目已较长时间没有更新，最终版本停在 3.2.1，GitHub 网页改版引发的页面解析类问题（如 Trending）可能不会再有修复，详见 [常见问题与排查.md](常见问题与排查.md)。

## 二、主要客户端对比

截至 2026 年 9 月，安卓平台上常见的 GitHub 客户端：

| 客户端 | 定位 | 维护状态（截至 2026-09，以各自仓库页面为准） |
| --- | --- | --- |
| GitHub 官方 | GitHub 自家移动端，功能跟着平台演进 | 由 GitHub 官方维护，持续更新 |
| OpenHub | 开源轻量客户端，浏览为主，不依赖 GMS | 最终版本 3.2.1，官方仓库较久无提交 |
| OctoDroid | 老牌第三方客户端，功能覆盖面广 | 老牌项目，存在时间长（现状以仓库页面为准） |
| FastHub | 功能丰富的早期明星客户端 | 已长期无更新（近 12 个月无提交） |
| ForkHub | 基于早期官方开源版本衍生 | 仓库同样较久无更新 |

这张表回答的核心问题：**如果你想找一个「还在活跃开发、功能跟得上平台新特性」的客户端，官方应用是唯一有把握的选择**；OpenHub 的价值在轻量、无 GMS 依赖和中文体验，而不在新功能。

## 三、和官方客户端的具体差异

用官方应用和 OpenHub 各用什么场景，差别集中在三点：

- **推送通知**：官方客户端的通知普遍依赖谷歌推送通道，无 GMS 的设备上可能收不到；OpenHub 不走这条路，但通知的及时性取决于应用自身的联网刷新（以两边的官方说明为准）；
- **功能深度**：参与开发流程（PR 评审、CI 状态、代码搜索的高级过滤）官方客户端覆盖更全；OpenHub 覆盖浏览、Issue、Star/Fork 这些高频动作；
- **包体与资源占用**：OpenHub 3.23 MB 对比官方客户端的体积（以商店页面当时显示为准），老设备体验差距明显。
