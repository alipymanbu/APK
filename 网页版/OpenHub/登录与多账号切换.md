## 一、登录方式：只有 OAuth 一种

从 3.2.0 版本起，OpenHub 移除了旧的 Authorizations API 登录方式，目前只支持 **OAuth 网页授权**：登录时你会先在应用内填入 GitHub 账号密码，应用随后打开 GitHub 的官方授权页，由你点确认后返回应用。

这个改动的影响：登录流程必须在能打开 GitHub 授权页的网络环境下完成；登录一次之后，日常使用走的是授权令牌，不需要每次都输密码。

## 二、授权登录步骤

1. 打开 OpenHub，进入登录页；
2. 输入你的 GitHub 账号和密码，点登录；
3. 页面跳转到 GitHub 的 OAuth 授权页，列出 OpenHub 请求的权限范围（读写仓库、Issue、通知等你的账号数据）；
4. 点 **Authorize**（授权）确认；
5. 自动返回应用，进入主界面即登录成功。

授权页上列出的权限范围决定了应用能替你做什么：能读你的私有仓库，是因为你需要在自己手机上看它们；能写 Issue 和评论，是因为你会在应用里参与讨论。接受哪些权限由你在授权页上决定，不点确认就不会登录成功。

两个会在这步遇到的常见情况：

- **授权页要求输入两步验证码**：说明你的 GitHub 账号开启了两步验证（2FA），在授权页按提示输入验证器动态码即可 —— 这是 GitHub 的正常流程，不是 OpenHub 多要了什么；收不到动态码先检查验证器应用的系统时间是否准确；
- **授权页打不开或一直转圈**：先换一个网络环境再试；仍不行，到 GitHub 状态页 [www.githubstatus.com](https://www.githubstatus.com/) 确认 GitHub 服务本身是否正常，状态页一片绿才轮得到怀疑应用或手机的问题。

## 三、添加第二个账号并切换

如果你同时有工作账号和个人账号，OpenHub 支持多账号：

1. 进入应用的设置（Settings）；
2. 找到账号管理入口，选择添加账号（不同版本界面的入口名称可能略有差异，以实际显示为准）；
3. 重复一遍上面的 OAuth 授权流程，登录第二个账号；
4. 之后在账号列表里点选即可切换，切换后整个应用的数据（新闻流、仓库列表、通知）都跟着换到对应账号。

## 四、撤销 OpenHub 的授权

不想继续让这个应用访问你的 GitHub 账号时，可以在 GitHub 网页端撤销：

1. 登录 GitHub 网页版，进入 Settings → Applications → Authorized OAuth Apps；
2. 找到 OpenHub；
3. 点 **Revoke** 撤销授权。

撤销后应用里的登录态会失效，下次打开会要求重新登录。注销账号、清理数据等操作只影响本机应用，GitHub 账号本身不受影响。

授权页打不开、授权完成后卡在登录页这类问题，见 [常见问题与排查.md](常见问题与排查.md)。
