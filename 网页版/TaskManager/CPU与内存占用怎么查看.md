## 一、先确认权限到位

TaskManager 的数据是靠 Shizuku 读出来的，所以看数据前先做两件事：Shizuku 主界面显示「正在运行」、TaskManager 已被授权。两件事没做，你打开只会看到空列表或报错提示，参见 [Shizuku配置与授权教程.md](Shizuku配置与授权教程.md)。

## 二、界面怎么分区

TaskManager 按资源类型分成几个标签页（不同版本的标签数量略有差异，以你装的那版界面为准）：

| 标签 | 你能看到什么 |
| --- | --- |
| CPU | 整机与各核心的占用曲线、每个进程占了多少 CPU |
| GPU | 图形相关的占用情况（部分机型/版本才有） |
| RAM（内存） | 已用/可用内存、每个进程吃掉多少内存 |
| 进程（Processes） | 正在跑的 Linux 进程列表，点进去看单个进程的详情 |

用法上就是「先看总量，再定位大户」：先在 CPU 或 RAM 标签看整机曲线，确认是真高还是瞬时抖动；再去进程列表按占用排序，找出一直霸榜的那个。

## 三、进程详情里的字段怎么读

在进程列表里点任意一行，会展开这个进程的详细信息，常见字段有：

- **PID**：进程编号，同一应用可能有多个进程，各自一个 PID。
- **内存占用（RAM usage）**：这个进程当前吃掉的内存量。安卓会尽量把内存用满，所以「占用高」本身不等于有问题，要看它是不是你正在用的应用。
- **优先级（priority）**：系统给这个进程的调度优先级，数字与含义和 Linux 的进程优先级一致；优先级低的进程在资源紧张时更容易被系统压制。
- **归属应用**：能对上包名的会标出来，方便你确认「这个进程是谁家的」。

判断卡顿来源的常见套路：开着 TaskManager 复现一次卡顿，回来盯 CPU 标签里哪个进程的曲线跟着窜——能持续复现的才是元凶，只跳一下的多半是后台例行任务。

## 四、几个看数时的提醒

- **进程列表很长是正常的**：里面混着系统服务与厂商常驻进程，不是每个都能关、也不该关。
- **杀掉的进程会被系统重新拉起**：尤其有推送、同步需求的应用，杀完过一会儿又回来，属于系统行为，不是没杀干净（详见 [结束进程与后台应用的方法.md](结束进程与后台应用的方法.md)）。
- **数据要 Shizuku 在线才刷新**：Shizuku 一停，曲线与列表会停在最后一次的数据上，先别急着怀疑 App 本体，看一眼 Shizuku 状态。

打开即闪退、列表始终为空、数据对不上号的处理办法，在 [常见问题与故障排查.md](常见问题与故障排查.md) 里逐条列了。
