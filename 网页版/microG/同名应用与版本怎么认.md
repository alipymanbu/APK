# microG 同名应用与版本怎么认

> 本篇把 microG 这一大家子里几个长得很像的包拆开讲：谁是服务本体、谁是商店替身、同一版本号下那几支变体分别给谁用，以及怎么在自己手机上确认装的是哪一个。

搜「microG」跳出来的页面里，至少混着四种不同的东西：官方服务本体、官方的商店替身、给打过补丁的应用用的分支版、还有已经停止维护的老版本。它们都叫 microG，装错了却会互相顶掉。这一篇只解决一件事：分清哪个包是哪个。

## 一、先认组件：microG 不是单个应用

官方把 microG 拆成几个可以单独安装的包，各自负责一件事：

| 组件 | 包名 | 负责什么 | 要不要装 |
| --- | --- | --- | --- |
| microG Services（组件名 GmsCore） | `com.google.android.gms` 等 | 服务本体：推送、定位、账号、部分 Google API 兼容 | 必装，就是你主要要用的那个 |
| microG Companion（旧称 FakeStore） | `com.android.vending` | 冒充 Play 商店的身份，供那些会检查「有没有装商店」的应用查询；它本身不下载应用 | 系统里没有官方 Play 商店时按需装 |
| microG Services Framework Proxy（GsfProxy） | `com.google.android.gsf` | 只服务很早以前的 C2DM 推送，请求会被转给服务本体，不能单独工作 | 绝大多数人不用装 |

「商店替身」这个说法容易误会：它不提供应用商店的功能，只是让应用查到「商店在」。真要装应用，另外配 F-Droid 或 Aurora Store 这类渠道。官方也提醒过，系统里已经有官方 Play 商店的话，Companion 那一步直接跳过。

## 二、再认变体：同一个版本号下的三支包

服务本体在同一个版本号下会同时产出三支包。它们功能同源，区别在包名和系统适配，认包的依据就是包名：

| 你手上的包 | 包名 | 官方给的定位 |
| --- | --- | --- |
| 自定义系统用 | `com.google.android.gms` | 官方发布说明里写明给「支持 microG 的第三方自定义系统」用的那一支，也是走官方 F-Droid 仓库分发的那一支 |
| 华为设备用 | `com.google.android.gms`（文件名带 `-hw`） | 给跑原厂 EMUI 或 HarmonyOS、且系统支持 microG 的华为设备用 |
| 开发预览 | `org.microg.gms`（文件名带 `-user`） | 官方发布说明的原话是「面向特殊情况的开发预览」，并注明不清楚自己为什么需要它就不要用 |

网盘里这份的包名是 `org.microg.gms`，属于第三支。这不是写错了，而是同一版本号下的一条并行产物；版本号、MD5 都能和官方对得上。

需要留意的正是这个差别：**同一版本号、不同包名，在系统眼里是两个不同的应用**。系统如果只对特定签名的 microG 放开签名伪装（较新的 LineageOS 官方构建就是这样，只对 microG 开这个口子），它认不认 `org.microg.gms` 这个包名，直接决定你装完能不能过自检。这部分见 [签名伪装与自检怎么看.md](签名伪装与自检怎么看.md)。

## 三、还有两个容易混进来的同名分支

| 名字 | 包名 | 什么时候才用 |
| --- | --- | --- |
| ReVanced 版 GmsCore | `app.revanced.android.gms` | 只有给打过 ReVanced 补丁的应用（典型是 YouTube 那类）才用它；和官方 microG 不是同一个包，不能互替 |
| Vanced microG | `com.microg.vanced` 一类 | 早期跟着 Vanced 分发的分支，早已停止维护，只有还在用老 Vanced 的用户才碰得上 |

再往后是历史遗留：早年网上流传的「microG + 一堆叫 NLP 定位后端的插件」那套玩法，在较新版本的 microG 里已经不再适用——现在的位置来源由 microG 自带的定位引擎和你选的在线位置服务负责，不再靠外挂插件拼。设置页里显示的项为准，见 [定位不准或搜不到位置怎么排查.md](定位不准或搜不到位置怎么排查.md)。

## 四、怎么在自己手机上确认装的是哪一个

按可靠程度排，三步就够：

1. **看包名，别看名字。** 设置 → 应用 → 找到那一项 → 应用信息页里会写包名。名字可以都叫 microG，包名不会骗人；
2. **看版本号。** 本页表格里那些变体共用同一个版本号（比如 `0.3.15.250932`），所以版本号只能告诉你新旧，分辨变体还得回到包名；
3. **动手能力够的话用命令核对**，一次列出手机里所有已安装的包：

```bash
adb shell pm list packages
```

在输出里找 `com.google.android.gms`、`com.android.vending`、`com.google.android.gsf`、`org.microg.gms` 这几个。装完多个组件之后，应该能同时看到服务本体、Companion、GsfProxy 各自的包名，对不上的那项就是装错的那个。

## 五、认错包的常见后果

| 你干的事 | 会怎样 |
| --- | --- |
| 在同一台机器上装两支变体的服务本体 | 包名不同，能并存，但系统与应用只会认签名伪装到位的那一个，另一个等于白装，还占一份后台资源 |
| 给打过 ReVanced 补丁的应用装官方 microG | 应用找的是 `app.revanced.android.gms`，找不到就报缺少服务 |
| 把 Companion 当成应用商店用 | 它不提供下载功能，进不去商店界面 |
| 用旧版 Vanced microG 顶替官方服务本体 | 两条线早已分家，版本停在多年前，新应用兼容性没有保障 |

## 六、版本号怎么读

官方发布用的是 `v0.3.x.<数字>` 这种标签，版本号后面那段数字与内部版本代号对应。对你真正有用的只有两条：

- **看首段。** `0.3.x` 是当前的主线；`0.2.x` 及更早属于历史版本，网上很多教程还停在那一代，里面的设置项名称和现在不一样；
- **看发布日期。** 网盘里这份 `0.3.15.250932` 对应官方 2026-04-24 的那次发布。官方之后仍在继续更新，新版可能在兼容性和权限上继续变化，想核最新状态去官方发布页（[github.com/microg/GmsCore](https://github.com/microg/GmsCore) 的 Releases 区）看，以官方页面当时显示为准。
