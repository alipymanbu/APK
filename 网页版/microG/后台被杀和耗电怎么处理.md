# microG 后台被杀和耗电怎么处理

> 本篇讲清 microG 为什么必须常驻后台、国内各厂商系统下具体要放开哪些开关，以及怎么判断「推送不来」到底是网络问题还是被判为后台耗电清掉了。

microG 要维持一条与推送服务器的长连接，连接断了，恢复得等下一次系统把它唤醒——推送就要么延迟要么干脆不来。所以官方把「关掉电池优化」直接写进了安装步骤，这不是可选的性能调优，而是功能能否成立的前提。

## 一、被系统清掉之后会怎样

| 现象 | 说明 |
| --- | --- |
| 锁屏一段时间后，一解锁集中跳出一批通知 | 最典型：连接断了，系统唤醒的一瞬间把积压的消息全推到 |
| Cloud Messaging 列表里应用长期显示未连接 | 后台进程被冻结，连接建不起来 |
| 地图类应用在后台不更新位置，打开才刷新 | 网络定位也跟着停了 |
| 待机一晚上掉电异常，或者反过来说「完全收不到消息也不掉电」 | 前者多是有应用在反复重试注册，后者多是 microG 被冻结 |

## 二、先做通用的那一项

不管什么系统，这一项都先做掉：**在系统的电池优化里把 microG 的服务组件设为「不优化」**。位置在「设置 → 电池 → 电池优化」，如果那里有一层「允许 / 不允许」的下拉筛选，先切到「所有应用」再找。

官方文档的原话是：Android 6 及以上要关掉电池优化，因为和原版 Play 服务一样，microG 需要维持一条稳定的后台连接。

## 三、国内厂商系统要另外放开的项

厂商的省电策略比原生安卓激进得多，只关电池优化往往不够。各家的入口不一样，对不上号的话在设置里搜关键词最快：

| 系统 | 要放开的东西 | 入口关键词 |
| --- | --- | --- |
| 华为 EMUI / HarmonyOS | 应用启动管理里关掉自动管理，改成手动并允许自启动、允许关联启动、允许后台活动；电池优化设为不允许；关掉省电模式；在电池的更多设置里打开「休眠时始终保持网络连接」 | 应用启动管理、电池优化、省电模式、更多电池设置 |
| 小米 MIUI / HyperOS | 自启动管理里允许 microG 自启动；电池的应用智能省电里不要限制它；WLAN 高级设置里保持「始终保持」 | 自启动管理、应用智能省电、WLAN 高级设置 |
| 其他厂商 | 思路一致：自启动、后台活动、电池白名单三项 | 设置里搜「后台」「自启动」 |

华为官方支持文档给的排查顺序是「检查更新 → 清理存储 → 逐项放开设置 → 清理后台 → 排除第三方管家类软件」，其中「逐项放开设置」那一节就是上面第一行列出的四项，可以直接照做。小米那几项来自社区总结，不同版本菜单名称会变，**以你手机上当时的菜单为准**。

一个补充技巧：把 microG 在最近任务里「加锁」（下拉卡片加锁），多数系统就不会被一键清理带走；系统内存紧张时它仍可能被清，属于正常现象。

## 四、还有一种被清，是自己设的

如果你开过开发者选项，回去看两条：

- **「不保留活动」**——必须关掉，它会在你离开界面后销毁进程；
- **「后台进程限制」**——设成「标准限制」，别设成只允许一两个进程。

这两条都在开发者选项里，属于「自己给自己下绊子」，排查时最容易被跳过。厂商支持文档里也把它们列进了要检查的项。

另外，第三方清理类、管家类应用会主动杀后台，装了的话先把 microG 加进它的白名单，或者干脆卸掉再观察。

## 五、耗电这件事要有合理预期

microG 维持长连接本身就要耗一点电，把它当成「零耗电」不现实。判断方法不是看数字，是看有没有异常：

| 情况 | 判断 | 怎么办 |
| --- | --- | --- |
| 待机耗电与装 microG 之前相近 | 正常 | 不用管 |
| 待机耗电明显变高，且耗电排行里能看到某个具体应用 | 多半是那个应用在反复发起注册 | 卸载后重新安装那个应用，见 [推送通知收不到怎么排查.md](推送通知收不到怎么排查.md) |
| 耗电排行里 microG 本身很高 | 连接在反复重连，通常伴随网络不稳 | 先按第三节把后台放开，再换一条网络观察一两天 |
| 完全不耗电、也完全收不到消息 | microG 被系统冻住了 | 回第二、三节 |

这里的「一两天」不是虚指：放开后台设置之后要经历一次锁屏、待机、唤醒的完整周期，才能看出效果。当天试几分钟看不出来。

## 六、判断链条

推送不来时，先分清是哪一类原因，再决定动不动系统设置：

1. 两个后台开关开着吗（设备注册、Cloud Messaging）→ 没开先开，见 [推送通知收不到怎么排查.md](推送通知收不到怎么排查.md)；
2. Cloud Messaging 列表里有没有这个应用 → 没有是注册问题，与后台保活无关；
3. 有但未连接 → 才是本篇管的范围，按第二、三、四节逐项放开；
4. 放开之后仍然未连接 → 换网络、重启，再回到 [推送通知收不到怎么排查.md](推送通知收不到怎么排查.md) 第四节。
