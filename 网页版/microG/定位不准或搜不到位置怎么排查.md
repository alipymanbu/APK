# microG 定位不准或搜不到位置怎么排查

> 本篇讲清 microG 环境下位置是怎么来的、设置里那几个位置开关各自管什么，以及「只有 GPS 能用、室内定不了位」这类症状该怎么查。

microG 负责的是「网络定位」那一半：靠周围的 Wi-Fi 和基站快速给一个大致位置，让你一进地图应用就能落到附近，而不是干等卫星。GPS 那一半由系统自己负责，和 microG 无关。所以位置出问题时，先要分清坏的是哪一半。

## 一、先分清是哪一半坏了

| 症状 | 说明坏的是 | 去哪一节 |
| --- | --- | --- |
| 户外开阔处能定位，一进室内就定不了，或者要等很久 | 网络定位 | 第二、三节 |
| 户外也定不了，一直卡在搜索卫星 | 系统 GPS | 这一篇管不了，先查系统定位开关与权限 |
| 位置有，但偏差几百米到几公里 | 网络定位在起作用，只是精度低 | 第四节 |
| 地图应用直接提示没有位置来源 | 定位提供者没注册进系统 | 第五节 |

一个简单的判断：把地图应用打开，站在窗口或户外。几十秒内能落到自己所在的位置，说明链路是通的；一直悬在别处或干脆不落点，就是网络定位没接上。

## 二、设置里那几个开关要动的项

microG 设置里的「位置」区域，需要你逐个确认：

| 位置 | 要动的项 | 说明 |
| --- | --- | --- |
| Wi-Fi 定位 | 打开「从在线服务请求」 | 不打开，microG 不会拿 Wi-Fi 去查位置 |
| 移动网络定位 | 打开「从在线服务请求」 | 同上，走基站那一侧 |
| 三点菜单 | 「选择在线位置服务」 | 在这一项里选一个具体的服务方 |

在线位置服务是可以选的，microG 把扫描到的 Wi-Fi 与基站信息发给选中的那一家、换回一个坐标。这一项里能选到哪些服务、各自叫什么名字，**以你设置页里那一项当时显示为准**；BeaconDB 是常被提到的一家，覆盖不够的地方可以换一家试试。都不合适时再考虑关掉在线服务、只用 GPS，代价是室内基本定不了位。

顺带提一个老教程里的坑：早年流行「装一堆 NLP 定位后端插件，在 UnifiedNlp 设置里全勾上」。较新版本的 microG 已经不再走外挂插件这条路，位置来源改由自带引擎加在线服务选择来管。照老教程找 UnifiedNlp 设置页，大概率是找不到的——**以你自己的设置页当时显示为准**。

## 三、装完了还是只有 GPS 能定位

这类情况的根源通常在系统侧，有两种可能：

1. **你的系统版本比较新（Android 7 及以上），而系统没打那条配合补丁。** 官方文档给的说法是：要么给系统打上额外的位置相关补丁，要么把 microG 装成系统特权应用；
2. **microG 是当普通应用装的，没有特权位置。** 特权装法是把服务本体放进系统的 `priv-app` 目录，例如：

```bash
adb push gmscore.apk /system/priv-app/GmsCore/
```

（`gmscore.apk` 换成你手机上下载到的那个文件名，网盘里这份的服务本体包名是 `org.microg.gms`。）这一步需要设备的系统分区可写（通常是 root 环境），做完要重启。拿不准的时候，优先用在系统板块里已经验证过 microG 的方案，比自己在实机上试错省事。

还有一条与系统相关的已知干扰：部分机型的系统里预置了厂商自己的定位组件，会和 microG 的位置提供者抢位置，导致后者虽然装上了却没注册进系统。这一节的对策在社区里有讨论，但各家系统差异大，**固定做法不通用**，遇到时按你的机型去查更靠谱。

## 四、有位置但精度差得离谱

先按这个顺序排除：

1. **看是否只走了基站。** 关掉 Wi-Fi 再试一次，如果位置变得很粗，说明 Wi-Fi 那一侧没生效，回第二节检查「Wi-Fi 定位」的开关；
2. **扫描权限。** 系统的位置权限里，microG 要设成「始终允许」；部分系统还要求开启 Wi-Fi 与蓝牙扫描（即使 Wi-Fi 开关本身是关的，系统也允许用它来辅助定位）；
3. **在线服务的覆盖度。** 网络定位服务靠数据库，换了家服务方、或所在地区数据稀疏时，前几次定位会明显不准；
4. **耐心一次。** 数据库类服务对同一区域的重复查询会逐步稳定，第一次偏差大不说明后面也这样。

## 五、地图应用提示没有位置来源

按这张表从上往下试：

| 要查的事 | 在哪查 | 不通过时的表现 |
| --- | --- | --- |
| 系统定位总开关 | 系统的位置设置 | 开着也没用，microG 拿不到数据源 |
| microG 的定位权限 | 应用 → microG → 权限 | 权限被拒，网络定位直接停摆 |
| 位置提供者是否注册进系统 | microG 自检页的位置相关分组 | 分组显示未注册，多见于刚装完还没重启 |
| 是否重启过 | 装完组件后的第一次重启 | 官方把重启列为必做步骤，跳过会出现各种莫名状态 |

重启之后再回自检页看一遍，是最省时间的一步。

还有一类表现容易被误判成定位坏了：**只有在后台时才不更新，打开应用就立刻正常**。这种不是定位链路的问题，是 microG 被系统冻结了，处理方式见 [后台被杀和耗电怎么处理.md](后台被杀和耗电怎么处理.md)。

## 六、关于隐私的一点点事实

网络定位的原理决定了：microG 必须把周围可见的 Wi-Fi 与基站信息发给所选的在线服务，才能换回坐标。不同服务方的数据来源与开放程度不一样，你能做的选择就是**在设置里换服务方、或者干脆关掉在线服务只用 GPS**。

另外别忘了，任何走网络的定位都在「系统定位总开关」的控制之下，不想让它工作时直接关系统开关即可。至于具体某个服务怎么处理你的数据，属于那家服务自己的说明，不属于 microG 的范畴。
