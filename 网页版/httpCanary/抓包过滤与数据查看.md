## 一、抓一次的最短闭环

1. **先装好证书**，否则 https 只有密文，见 [HTTPS证书安装与配置.md](HTTPS证书安装与配置.md)。
2. 设置 →「目标应用」→ 添加你要观察的那个应用。不加也行，但设备上几十个应用的请求会一起涌进来，找包很痛苦。
3. 回列表页，点右下角**小飞机**开始抓包；状态栏会有提示，通知栏也常驻一条。
4. 切到目标应用里操作几下，让它真正发出请求。
5. 切回 HttpCanary，点小飞机（此时是暂停）停抓。
6. 用搜索或过滤找到那条请求，点开看详情。

一条经验：**先清后台再开抓**。刚启动的抓包是空的，把目标应用从后台彻底划掉再重新打开，能保证它新建的连接都走你这条 VPN，不会漏掉启动时那批请求。

## 二、只抓想要的：两个范围开关

| 开关 | 位置 | 作用 |
| --- | --- | --- |
| 目标应用 | 设置 → 目标应用 | 只记录被勾选应用的流量；不勾任何 = 记全部 |
| 目标 Host | 设置 → 目标 Host | 只记录匹配域名/IP 的请求，适合盯着一个后端看 |

两个开关是「同时满足」的关系，排查时建议先放开其中一个 —— 什么都抓不到，往往不是网络问题，而是过滤条件收得太死。

设置里还有一个 **DNS 服务器**项，内置若干公共 DNS，也可以点右上角 `+` 自定义。它影响的是域名解析：遇到域名解析到奇怪地址、或者某些域名只在特定 DNS 下才通，改这里比重装网络快。

## 三、把那条请求找出来

HttpCanary 默认记下设备上所有请求，一次几分钟就能攒几百条。找包的三条路：

- **搜索**（列表右上角）：按 URL、关键字、请求头、状态码等条件搜。比如只想看登录接口，直接搜路径里的 `login`。
- **协议/类型过滤**：按 HTTP 方法、状态码、数据类型筛，把图片、字体这些噪音一次滤掉。
- **手眼配合**：先开着抓包复现操作，**再点暂停** —— 暂停之后列表就固定了，慢慢翻不会被新包顶走。

搜索是针对**已捕获内容**的，没抓到的搜不出来。所以顺序永远是：先抓 → 再搜。

## 四、看懂一条请求

点开一条记录会进详情页，主要看这几块：

| 区块 | 你会用到它做什么 |
| --- | --- |
| 概览 | 请求方法、完整 URL、状态码、耗时、请求/响应体积 |
| 请求头 / 请求体 | 看服务端收到了什么：`Content-Type`、`Authorization`、表单或 JSON 参数 |
| 响应头 / 响应体 | 看服务端回了什么：状态码、缓存头、返回的数据 |

响应体的查看方式是切换视图：

- **Text / Raw**：肉眼直接读，JSON、XML、HTML 都在这看；
- **HEX**：原始字节，二进制协议、加密串排查时用；
- **Header**：只看头部；
- **预览**：按类型自动渲染 —— JSON 格式化成树、图片直接显示、音频能播放、表单与 Cookie 摊平成键值。

编码类的东西不用你手动处理：`gzip`、`deflate`、`chunked` 这些 HttpCanary 会自动解开再给你看。

长按一条记录会弹出操作菜单，常用的有：**收藏**（标星后可单独筛出来）、**备注**（写一句这条是干嘛的）、**保存请求体/响应体**、**复制为 cURL 或文本**、以及 [断点与注入器使用.md](断点与注入器使用.md) 里讲的注入入口。

## 五、存下来与带走

- **保存的请求/响应文件**默认落在内部存储 `Documents/HttpCanary/download/` 下，用文件管理器进这个目录就能导出到电脑。
- **会话导出**：把整段抓包记录导出成 `csv`、`json` 等格式，方便丢到电脑上分析或附在问题单里。
- 记录也可以**分享**给同事 —— 分享的是请求数据本身，里面可能带 token、手机号这类敏感字段，发出去之前自己过一眼。

## 六、记录多了会卡，顺手清一下

HttpCanary 是边抓边解析的，列表堆到几千条后滚动会明显变卡，也会占存储。两个习惯：

1. 一次排查结束就点清空（列表页的垃圾桶图标），重要的先导出；
2. 需要长跑时收窄「目标应用」，别让它全量记录。

如果清空后列表行为异常、或者抓到一半数据莫名消失，多半是记录保存位置没权限了 —— 去系统设置确认 HttpCanary 的存储权限为允许，详见 [抓不到包怎么排查.md](抓不到包怎么排查.md)。
