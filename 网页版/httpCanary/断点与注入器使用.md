## 一、这两件事的区别

抓包是**只看不动**，断点与注入是**看着改**：

| 功能 | 什么时候用 | 副作用 |
| --- | --- | --- |
| 断点 | 想在请求发出去之前最后一眼看清、甚至临时改一下 | 请求会停在你这，不点放行就一直等着，目标应用可能超时 |
| 静态注入 | 同一条改法要反复用（每次命中自动执行） | 规则留着就一直生效，忘了关会一直改你的流量 |
| 动态注入 | 临时改一次、要实时生效 | 只在抓包运行中有效，处理慢了目标会超时 |

前提是同一个：**证书得先装好**，否则你看到的请求体是密文，改了也没意义 —— 见 [HTTPS证书安装与配置.md](HTTPS证书安装与配置.md)。

另外先说清适用范围：这套能力是给**你自己开发或经授权测试的应用**做接口调试用的（改参数看不同分支、伪造响应测前端兜底）。拿它去改别人应用的服务端判定不成立，也不该那么用。

## 二、断点：让请求停在你面前

1. 进设置，打开「断点」相关开关，并配好命中的条件（可按方法、URL 关键字等筛）。
2. 开抓包，正常操作目标应用。
3. 命中的请求会停在断点页，你能看到完整的请求行、请求头、请求体。
4. 这里改完点放行，请求才会继续发往服务端；响应也可以再断一次，改完再回给应用。

不用断点时把它关掉。断点挂着没放行，目标应用会表现为「点了没反应」「一直转圈」—— 这不是抓包坏了，是请求还在你手里扣着。

## 三、静态注入：把一次改动变成规则

静态注入适合「每次都要这么改」的场景，比如把某个参数固定成测试值、或者把响应里的某个字段换成你预设的内容。

1. 在列表里**长按**一条相关请求 → 选「静态注入」。
2. 给这条规则起个能认出来的名字。
3. 切到要改的一侧：
   - **请求**：可改请求参数、请求头、请求体；
   - **响应**：可改响应行、响应头、响应体。
4. 响应体这类字段点编辑按钮进入在线编辑，改完保存。
5. 点右上角的飞机图标启用这条注入器。

保存后规则会被缓存，下次抓包自动命中，不用重新配。可改的范围覆盖请求与响应的完整四件套（参数/头/体 + 响应行），所以「让接口返回我预设的 JSON」这种前端联调需求一条规则就够。

**容易踩的坑**：规则开着就一直生效，改完测试忘了关，之后看什么数据都不对。做完一次验证就回模组管理把它停掉。

## 四、动态注入：改完立刻生效的那一种

动态注入用于实时修改，和静态的差别在执行时机与限制：

- **必须在抓包服务运行时**才能用，停了抓包它就不工作；
- **不支持大体积的请求体与响应体**，别指望拿它改一个几 MB 的上传包；
- 处理要快，慢了目标应用会等超时，表现为请求失败而不是被改成功。

拿不准用哪个时：**要反复用 → 静态；只改一次且马上要看效果 → 动态**。

## 五、规则的统一管理：模组管理

设置 →「模组管理」，所有注入器集中在这：

- 启用 / 停用某条规则（排查「数据怎么不对了」时，第一个动作就是全停一遍再逐个开）；
- 删除不用的规则；
- 看规则的使用情况。

建议按目标应用给规则命名（例如带上应用名与字段名），规则一多，靠名字分辨比点开看省事得多。

## 六、规则不生效怎么查

按这个顺序过一遍，基本能定位：

1. **抓包本身有没有数据** —— 列表空的是抓包问题，跟注入无关，见 [抓不到包怎么排查.md](抓不到包怎么排查.md)。
2. **规则是不是启用状态** —— 模组管理里看开关，灰的就是没生效。
3. **命中条件写窄了没有** —— URL 关键字拼错、方法限定与实际不符，都会一条都不命中。先把条件放宽验证规则本身能触发，再逐条收紧。
4. **HTTPS 明文拿到了吗** —— 证书没装好的话，看到的是密文，基于内容的匹配自然对不上。
5. **动态注入超时** —— 逻辑太复杂就换静态注入，或者简化改动。
