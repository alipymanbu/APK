# MMRL 常见问题与故障排查

## 一、打开后提示没有 root 管理器 / 检测不到 Magisk

MMRL 不做 root，它要接上你手机里已有的 root 管理器。按顺序查：

1. 手机上确实装了 Magisk / KernelSU / APatch / SukiSU Ultra 中的一种，且打开它能正常显示 root 状态；
2. 在 MMRL 的设置里重新选一次 root 管理器 —— 首次启动选错（比如实际用 KernelSU 却选了 Magisk）就会一直提示检测不到；
3. root 管理器刚升级或刚刷入的话，重启一次手机再试。

还没装 MMRL 或版本太旧的，先按[下载与安装教程.md](下载与安装教程.md)重装一份。

## 二、点安装后失败或报错

一次装不上，按可能性从高到低查：

1. **模块与你的 root 方案不匹配** —— 有些模块只适配 Magisk，有些只适配 KernelSU/APatch，详情页里看模块说明的适用范围；
2. **在黑名单里** —— 官方黑名单 [mmrl.dev/blacklist](https://mmrl.dev/blacklist) 公开可查，被限制的模块会装不上；
3. **仓库地址失效** —— 仓库里报加载失败，说明这个仓库的地址打不开了，去仓库主页核对最新地址（加仓库的方法见[添加模块仓库与安装模块教程.md](添加模块仓库与安装模块教程.md)）；
4. 个别模块本身安装脚本报错 —— 换个时间重试，或去模块的发布页看有没有已知问题。

## 三、显示安装成功，但功能没生效

模块是开机时挂载的：**装完必须重启手机**，更新、禁用、卸载同样要重启才体现。重启后回到已安装列表确认状态。

另外两个容易忽略的点：

- **KernelSU 用户**：模块如果需要修改 `/system` 下的文件，还得装一个 metamodule（如 `meta-overlayfs`）才能挂载成功；只跑脚本、改 `system.prop`、写 sepolicy 规则的模块不需要（见 KernelSU 官方常见问题 [kernelsu.org/guide/faq](https://kernelsu.org/zh_CN/guide/faq)）。
- **禁用状态**：卡片上模块处于禁用就不会加载，再点一次启用后重启。

## 四、某个模块搜不到

三种可能：仓库没加（先加仓库，见[添加模块仓库与安装模块教程.md](添加模块仓库与安装模块教程.md)）；仓库地址失效换了新地址；或该模块在官方黑名单里。逐项排除即可。

## 五、设置里找不到 JavaScript API 选项

这个开关的路径随版本变化，5.32.43 以上在「设置 → 模块与权限」，5.32.43 以下在「设置 → 安全」，且部分新版本已移除该选项 —— 完整对照表见[WebUI X 配置界面怎么用.md](WebUI%20X%20配置界面怎么用.md)。

## 六、装 APK 时提示解析失败或被拦截

安装包损坏或系统禁止了该来源：重新下载 APK（网盘里的固定版本是 5.31.42，见[下载与安装教程.md](下载与安装教程.md)），安装时按系统提示为该来源开启「允许安装未知应用」。装上后闪退则先确认系统版本是否满足要求（本地记录标注为安卓 5.2 以上）。

## 七、想彻底卸载某个模块

在已安装列表里点移除按钮（按钮位置见[模块卡片上的按钮和标记怎么看.md](模块卡片上的按钮和标记怎么看.md)），重启后模块文件即被移除。若模块的说明里写了自带反安装脚本，按它说明的方式执行即可。
