# KernelSU OTA更新后如何保留root

> 系统更新（OTA）之后 root 还在不在、LKM 与 GKI 两种模式分别怎么保住 KernelSU，以及更新前要准备什么。

## 一、OTA 会不会把 root 冲掉：分模式回答

- **LKM 模式**：基本不用担心。LKM 不替换内核、只动 ramdisk（出厂 Android 13 及以上的设备是 `init_boot`），系统 OTA 之后在管理器里「安装到另一个分区」一次即可继续使用，官方文档明确把这一条列为 LKM 的优点。
- **GKI 模式**：OTA 会把内核整个换回原厂，KernelSU 随之消失，需要用与新系统匹配的内核包重新刷入 boot 分区。

不确定自己是哪种模式的话，打开管理器看首页状态：显示「工作中 <LKM>」就是 LKM，「工作中 <GKI>」就是 GKI。

## 二、动手前：认清 A/B 分区这个前提

「安装到另一个分区」这项能力依赖设备的 A/B 分区（系统分两个槽位轮流更新），近年出厂的 GKI 设备基本都是 A/B，不确定可以用设备信息类应用查一下。OTA 的工作方式是：更新包写入**当前未使用的那个槽位**，重启后切换过去。

所以 LKM 模式下保留 root 的核心动作就一句话：**在重启进入新系统之前，把 KernelSU 也装到那个还没启用的槽位上**。

## 三、LKM 模式的 OTA 更新流程

1. 在系统设置的系统更新里正常下载 OTA 包并安装（安装完成的提示出现即可）；
2. **先不要点重启**，打开 KernelSU 管理器 → 右上角安装图标 → **安装到另一个分区**；
3. 管理器会自动修补官方固件并写入未启用的槽位；
4. 这时再回到系统更新的界面重启（或直接手动重启）；
5. 重启进入新系统后，管理器应继续显示「工作中 <LKM>」。

顺序错了会怎样：如果先重启进了新系统再想补装，当前槽位已经是新系统，这时只能走「直接安装」重新修补一次——通常也能装回去，但中间会有一段时间没有 root，而且增量 OTA 场景下官方建议保留的原厂镜像备份会更稳妥。管理器「直接安装」时自动备份的原厂 boot（存放在 `/data/adb/ksu/ksu_backup_$SHA1`）就是为这类场景准备的。

## 四、GKI 模式的 OTA 更新流程

GKI 模式没有「另一槽位」可搭便车，内核被 OTA 换掉了就得重新刷。流程：

1. **别急着更新，先等包**。确认有你新系统对应的 KernelSU 内核（GitHub Releases 按 KMI 与安全补丁级别选，规则见[内核版本与设备支持说明](内核版本与设备支持说明.md)）再更新，避免更新后干等；
2. OTA 更新并重启后 root 消失（这是预期行为，不是故障）；
3. 用 fastboot 把与新系统匹配的 boot.img 重新刷入（命令同[下载与安装教程](下载与安装教程.md)第五节）；
4. 模块数据在 `/data/adb/modules`，OTA 一般不清 data 分区，模块配置通常保留，但改 /system 的挂载是否恢复取决于 metamodule 与新系统的兼容情况，重启后逐个核对。

第三方内核用户要注意：如果你刷的不是 KernelSU 官方通用内核而是社区内核，OTA 后要等该内核维护者放出新系统对应的版本，不能拿旧包硬刷。

## 五、更新前后的核对清单

| 时机 | 要做的事 |
| --- | --- |
| 更新前 | 确认 boot.img 备份还在手里（换机型/刷过其他内核后尤其要重新确认） |
| 更新前 | LKM 用户：确认管理器能正常打开、版本可用 |
| 更新前 | GKI 用户：确认目标内核包已发布且 KMI/补丁级别匹配 |
| 安装 OTA 后 | LKM 用户：先「安装到另一个分区」再重启 |
| 更新完成后 | 看管理器状态行、抽查模块是否生效、root 授权是否还在 |

更新之后如果开不了机，处理路径在[常见问题与救砖方法](常见问题与救砖方法.md)——绝大多数情况是槽位上的内核与新系统不匹配，刷回原厂 boot 即可回到官方状态。
