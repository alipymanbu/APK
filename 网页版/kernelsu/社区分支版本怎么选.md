## 一、为什么会有这么多「XXSU」

KernelSU 是开源项目，任何人都可以 fork 后按自己的方向改。围绕它逐渐出现了一批社区分支，常见的有 KernelSU Next、SukiSU（及其 Ultra 版）等，各自侧重不同的内核覆盖范围与模块功能。它们与原版共享同一套核心思路（内核层 root、模块系统、管理器），但**内核补丁、管理器、模块细节并不完全通用**。

截至 2026 年中，各分支仍处在活跃变动中，本文只讲稳定不变的判断原则，具体功能清单以各项目页面当时显示为准。

## 二、原版与分支的典型差异

以 KernelSU Next（受众多、资料多的社区分支，项目在 GitHub 开源）为例，它相对原版的主要差异是：

- **内核覆盖更宽**：官方 KernelSU 主打 GKI 2.0（内核 5.10 起，旧内核需自行编译）；Next 官方页面标注支持 4.4 到 6.6 的内核，其中非 GKI 内核 4.x~5.4 走 LTS 模式——这让一批「管理器显示不支持」的旧设备多了一条路；
- **管理器功能不同**：Next 的新版管理器加了模块备份与恢复、批量安装模块、授权列表备份等便利功能；
- **更新节奏与维护团队不同**：原版由 tiann 维护、节奏求稳；分支的更新更快，激进功能也先出现在分支上。

SukiSU 等其他分支的差异点各有侧重（挂载方案、内核补丁集等），选择前建议直接读各项目自己的说明页，不要依赖二手转述——二手资料里版本号和功能名经常张冠李戴。

## 三、三条选型原则

1. **优先按设备支持面选**。你的设备是 GKI 2.0、内核 5.10 以上，原版就是最稳的选择；「不支持」的旧内核设备，分支才成为值得考虑的选项（原版路线见[内核版本与设备支持说明](内核版本与设备支持说明.md)）。
2. **内核与配套管理器必须成套**。刷了哪个分支的内核，管理器就必须用同一个分支的——内核层接口不同，跨分支混用管理器会出现识别异常甚至误判状态。换分支时按新分支的安装流程完整重来，不要只换 APK。
3. **模块通用但有细节差异**。常规模块（脚本、systemless 修改）大多在两边都能跑，但模块挂载的启用方式、个别特殊模块的适配跟着分支走。从原版迁去分支时，模块最好重装一遍而不是直接沿用。

## 四、本套文档的口径

这套文档里的所有操作说明都以**官方 KernelSU**（tiann 维护、文档发布在 [kernelsu.org](https://kernelsu.org)）为基准撰写。如果你用的是某个分支，大框架（刷入流程、模块概念、救砖思路）是相通的，但管理器菜单、内核包命名、功能开关的位置可能与文中描述对不上——以你所用分支的官方文档为准。

从原版迁去分支或反向迁移前，把 boot 镜像备份重新做一遍；迁移过程中开不了机的自救方法在[常见问题与救砖方法](常见问题与救砖方法.md)。分支的安装入口与内核包通常也放在各分支的 GitHub Releases，不要从来路不明的镜像站下载。
