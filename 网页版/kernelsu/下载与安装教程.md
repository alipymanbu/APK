## 一、开始之前：三件必须先做的事

KernelSU 是工作在 Linux 内核层的 Android root 方案，安装过程绕不开刷写分区，所以下面的准备步骤不是可选项：

1. **解锁 Bootloader**。没解锁就无法刷写 boot 分区，这一点没有变通办法（解锁方法各品牌不同，小米要在官方页面申请并等待，Pixel 只需在开发者选项里开 OEM 解锁）。
2. **备份你的原厂 boot.img**。这是整个流程里最重要的一步：刷错内核、刷错压缩格式导致无法开机时，只有刷回原厂 boot 才能救回来。备份方法通常是从与机型对应的官方固件包里提取 boot.img（卡刷包可用 payload-dumper-go 提取）。
3. **会基本的 ADB 与 fastboot 操作**。后文的命令都基于这两个工具，完全没接触过的话先单独学习再用。

另外注意：任何刷机操作都有变砖风险，手机里有重要数据的话先做整机备份。

## 二、获取 KernelSU 管理器

管理器是一个 APK，装在手机上用来查看支持状态、执行安装、管理授权与模块。本地留有一份 KernelSU 安装文件资源（夸克网盘）：[https://pan.quark.cn/s/c98ba101d9d3](https://pan.quark.cn/s/c98ba101d9d3)，也可以从 GitHub Releases（`https://github.com/tiann/KernelSU/releases`）获取最新版。

装好并打开管理器，首页会显示两种状态之一：

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| 未安装 | 设备被官方支持，可以继续 | 按本文继续 |
| 不支持 | 没有开箱即用的内核 | 看[内核版本与设备支持说明](内核版本与设备支持说明.md) |

KernelSU 官方不会为「不支持」的设备提供可刷写的 boot 镜像，所以状态是「不支持」时不必反复尝试刷入，先看设备支持那篇理清思路。

## 三、两种安装模式怎么选

从 0.9.0 起，GKI 设备有两种运行模式，装之前先想好用哪个：

| | LKM 模式 | GKI 模式 |
| --- | --- | --- |
| 原理 | 以可加载内核模块方式挂进原内核，**不替换内核** | 用 KernelSU 的通用内核镜像**替换**原内核 |
| 对原内核的影响 | 保留原内核 | 完全替换 |
| 升级 | 在管理器里直接安装，无需再碰 fastboot | 每次都要重新刷 boot |
| OTA | 系统更新后装到另一个槽位即可 | OTA 后需重新刷入 |
| 临时取消 root | 可卸载 LKM，甚至不用重启 | 只能刷回原厂 boot |
| 适用 | 手机（官方推荐优先） | 模拟器、WSA、Waydroid，或三星 KNOX 等特殊机型 |

官方对手机的建议是优先 LKM；LKM 修补的是 ramdisk，所以出厂 Android 13 的设备改的是 `init_boot` 分区而不是 `boot`，这点和 GKI 模式不同。

两个已知的例外情况：三星开启了 KNOX 的设备 LKM 模式无法运作，只能走 GKI；而部分联发科机型与较新的系统（如 Android 15 起）直接刷 GKI 内核可能点不亮，社区教程里这类设备多推荐改走 LKM 修补。拿不准就先用 4.1 的 `fastboot boot` 临时启动验证一遍——临时启动失败不伤系统。

## 四、LKM 安装：管理器修补法（推荐）

### 4.1 支持 fastboot boot 的设备（最简路径）

1. 下载与设备 KMI 一致的 KernelSU GKI boot.img（哪下、怎么对版本见下一节）。
2. 手机进入 Bootloader（`adb reboot bootloader`），执行 `fastboot boot boot.img` **临时启动**——重启就会失效，不影响系统。
3. 临时启动后设备拥有了临时 root，打开管理器，点右上角安装图标，选**直接安装**，管理器会自动修补当前官方固件并刷入。
4. 重启后管理器显示「工作中 <LKM>」即为成功。这种方式不用手动提取 boot.img，也是日后升级的主要路径。

### 4.2 不支持 fastboot boot 的设备

需要先手动获取官方固件，提取原厂 boot.img（出厂 Android 13 及以上的设备提取 `init_boot.img`），然后在管理器里选**选择并修补一个文件**，把固件文件交给它修补，再把修补产物用 `fastboot flash boot 新文件名` 刷回去。

不想在手机上操作的话，也可以用官方命令行工具 `ksud` 在电脑上完成同样的修补：

```sh
ksud boot-patch -b <boot.img路径> --kmi android13-5.10
```

`--kmi` 填设备的 KMI（怎么确认见[内核版本与设备支持说明](内核版本与设备支持说明.md)），输出目录会生成修补后的镜像，刷入即可。

### 4.3 安装时的备份行为

用管理器「直接安装」时，它会自动备份原厂 boot（或 init_boot）镜像到 `/data/adb/ksu/ksu_backup_$SHA1`；3.3.0 起首次无 root 安装时也可以在修补界面选「备份为原厂镜像」，把备份存进管理器内部存储，进系统后自动归档。这个备份日后想卸载 KernelSU 时用「卸载 → 还原原厂镜像」就能恢复。

## 五、GKI 安装：直接刷通用内核

### 5.1 下载正确的 boot.img

到 GitHub Releases 下载与你设备 KMI、安全补丁级别一致的 boot.img。同一个 KMI 下通常有 `lz4`、`gz`、不压缩三种格式，格式选错会无法开机：

- 小米设备通常是 `gz` 或不压缩；
- Pixel 的 boot.img 是 `lz4_legacy` 压缩，直接刷通用镜像多半点不亮，要走下面 5.3 的手动修补；
- 不确定的话用 magiskboot 查原厂 boot 的压缩格式，或问同机型的人。

### 5.2 刷入

```sh
adb reboot bootloader
fastboot flash boot boot.img
fastboot reboot
```

如果设备支持 `fastboot boot`，建议先 `fastboot boot boot.img` 临时引导验证能正常开机，再执行 `flash` 正式刷入。开机后管理器显示「工作中 <GKI>」即成功。

### 5.3 手动修补（Pixel 等特殊格式设备）

1. 准备原厂 boot.img 和与设备 KMI 一致的 AnyKernel3 包（Release 页下载），解包 AnyKernel3 取出 `Image` 内核文件。
2. 用 `magiskboot` 解包原厂 boot：`./magiskboot unpack boot.img`，得到原厂 `kernel` 文件。
3. 用 Image 替换它：`mv -f Image kernel`。
4. 重新打包：`./magiskboot repack boot.img`，得到 `new-boot.img`，按 5.2 的方式刷入。

Magisk 官方的 magiskboot 只能在 Android/Linux 上跑，Windows/macOS 上可以用社区的 magiskboot_build 版本。不建议用 Android-Image-Kitchen，它可能不保留安全补丁级别等元数据，部分设备会直接点不亮。

### 5.4 用 Recovery 或内核刷写 App

手上有 TWRP 的设备：下载 AnyKernel3 开头的 zip，进 TWRP 后 `adb sideload` 或在图形界面里刷入即可。

已 root 的设备也可以用 Kernel Flasher、Franco Kernel Manager 这类内核刷写 App 装 AnyKernel3 包——这个「已 root」可以是别的方案给的，所以「先装 Magisk 再借它的 root 刷入 KernelSU 内核」也是官方认可的变通路径之一。

## 六、装完之后

装好只是开始，接下来大概率会碰到这几件事：

- **想改 /system 或装模块**：看[模块与Zygisk使用指南](模块与Zygisk使用指南.md)，注意修改 /system 类模块还需要另装 metamodule；
- **管理应用拿 root 的权限**：看[root权限授权与管理](root权限授权与管理.md)，默认的授权弹窗和 App Profile 都在管理器里配；
- **开机卡住进不了系统**：先别慌，看[常见问题与救砖方法](常见问题与救砖方法.md)，音量键安全模式能救掉大多数模块类故障；
- **系统推送了 OTA 更新**：先看[OTA更新后如何保留root](OTA更新后如何保留root.md)再动手更新，LKM 模式重启前要先装到另一个分区，顺序错了 root 会断档。
