## 一、先分清是哪种「砖」

刷机失败开不了机，原因不同、救法不同。按出现时机分两类：

| 现象 | 常见原因 | 救法 |
| --- | --- | --- |
| 刷完 boot 就开不了机 | 压缩格式刷错 / KMI 不符 / 安全补丁级别倒退 / 需要关 avb 验证 | 刷回原厂 boot（第一节） |
| 装模块后开不了机 | 模块有问题或互相冲突 | 音量键安全模式 / ksud / Recovery 清理（第二、三节） |

第一种情况的前提是你**刷机前备份过原厂 boot.img**（安装教程反复强调的那一步）。没备份的话，找同机型的人要，或从官方固件包里提取一个，然后：

```sh
fastboot flash boot 原厂boot.img
```

刷回原厂 boot 系统就能正常启动，之后排查清楚原因再重来。

## 二、模块变砖：音量键安全模式（首选）

KernelSU 内置了安全模式，进入后所有模块自动禁用，系统就能正常开机。触发方法：

**开机第一屏之后，连续按音量下键超过三次**——注意是按下、松开、按下、松开的节奏，不是按住不放。

两个使用要点：

- 部分系统自带的安全模式也联动：进系统自带安全模式（有的机型长按音量下，MIUI 在 Recovery 里开）后，KernelSU 同样进入安全模式；
- 键监听只在开机第一屏后到开机动画前这一小段时间生效，启动太快的设备可能按不进去，多试几次把握时机。

进入安全模式后，打开管理器的模块页，所有模块都已被禁用，把出问题的那个卸载掉，重启恢复正常。

## 三、模块变砖：安全模式救不回来时

### 3.1 能连 ADB：用 ksud 处理

如果设备能进系统或能通过 ADB 拿到 root shell，直接用命令行管理模块：

```sh
adb shell
su
ksud module list        # 列出所有模块
ksud module disable <id> # 禁用问题模块
ksud module uninstall <id> # 或直接卸载
reboot
```

Recovery 模式下 GKI 设备会继续加载 KernelSU 内核模块，所以在 Recovery 里运行 `/data/adb/ksud` 的多数功能也可用（需要先挂载 metadata 和 data 分区）。

### 3.2 连 ADB 都不行：Recovery 手动清理

前提是设备有第三方 Recovery（如 TWRP）。删掉 KernelSU 的模块加载入口，重启后它就跳过所有模块：

```sh
mount /data
rm -f /data/adb/ksud
mount /metadata
rm -f /metadata/ksu/modules.rc
rm -f /metadata/watchdog/ksu/modules.rc
reboot
```

重启进系统后，再打开管理器处理具体模块。（data 分区可能需要按你的设备方式先解密。）

### 3.3 都救不回来

如果模块做了恶意操作或以其他方式损坏了设备，剩下两条路：清除数据后线刷完整官方系统，或找售后。这也是反复强调「不要刷来路不明的模块」的原因——模块有 root 权限，破坏力是真实的。

## 四、安装与兼容性高频问题

**管理器显示「不支持」**：官方没有你设备的开箱即用内核，看[内核版本与设备支持说明](内核版本与设备支持说明.md)确认出路，反复重装 APK 不会改变结果。

**Android 版本和内核版本对不上**：正常现象，刷机永远以内核版本为准，原因与规则见[内核版本与设备支持说明](内核版本与设备支持说明.md)。

**KernelSU 需要 Magisk 吗**：不需要，两者是独立的 root 方案。共存的前提是 KernelSU 里不启用任何模块（模块挂载会整体压垮 Magisk），只用 `su` 时两者可以同时工作。

**装完模块不生效**：改 /system 的模块需要先装 metamodule（如 `meta-overlayfs`），只装模块本体是不生效的，详见[模块与Zygisk使用指南](模块与Zygisk使用指南.md)。

**想用 LSPosed / Zygisk 模块**：本体不内置 Zygisk，装 ZygiskNext 模块后即可正常运行 LSPosed，路径见[模块与Zygisk使用指南](模块与Zygisk使用指南.md)。

**能改 hosts / 用 AdAway 吗**：可以，装 systemless-hosts 模块即可，KernelSU 没有内置 hosts 修改。

**KernelSU 会替代 Magisk 吗**：官方自己的回答是不会、目标也不同——Magisk 是用户空间方案，KernelSU 提供的是内核层接口，两者长期共存。

**系统更新（OTA）之后开不了机 / root 不见了**：LKM 模式 root 消失多半是重启前没装到另一槽位，GKI 模式是 OTA 换回了原厂内核——两者都有标准处理流程，见[OTA更新后如何保留root](OTA更新后如何保留root.md)。

**搜索时看到 KernelSU Next、SukiSU 这些名字**：是围绕 KernelSU 的社区分支，内核与管理器不与原版混用，选型原则见[社区分支版本怎么选](社区分支版本怎么选.md)。

**安装后怎么卸载**：LKM 模式下在管理器里「卸载 → 还原原厂镜像」即可（前提是安装时保留过自动备份）；GKI 模式则用 fastboot 刷回备份的原厂 boot。

**临时取消 root**：LKM 模式可以卸载 LKM 模块实现，不需要刷写分区，甚至不用重启；想再要 root 时重启设备即可。这是 LKM 相对 GKI 模式的一个独特便利，安装方式见[下载与安装教程](下载与安装教程.md)。
