Animeko 自己不存视频，能看什么完全取决于它找到的源。卡顿、没资源、加载失败这几类问题，最后大多落在「换一条源」或「换一种源类型」上，所以先把两类源分清楚。

## 一、两类数据源：BT 与在线

| | BT 源 | 在线源 |
| --- | --- | --- |
| 数据来自哪 | 公共 BitTorrent P2P 网络，由做种者分享 | 其他视频网站分享的内容 |
| 首次打开速度 | 慢，要先缓一段 | 一般较快，也要等资源拉取 |
| 人多时 | 同时看的人越多越快 | 受该站带宽与连通性影响 |
| 冷门老番 | 可能无人做种、几乎下不动 | 取决于该站是否还留着 |
| 需要注意 | 应用会自动做种（上传分享数据） | 连通性看该站与你所在网络 |

内置的 BT 抓取源包括动漫花园与 Mikan（蜜柑计划）；在线源走聚合项目，官方 README 指向 `https://github.com/creamycake-anime/ani-subs`。

**用 BT 源时应用会自动做种**，也就是把已下载的数据分享给别人 —— 这是这类应用能运转起来的前提，用之前心里有数即可。

## 二、选源：让应用选，还是自己选

默认情况下 Animeko 会**自动选源**，还会记住你对在线源的选择偏好，第二次打开同一部番更快。设置里能看到数据源的 Tier（分级），用来判断优先级。

需要手动介入的情况只有几种：

- 自动选的那条播不动；
- 你想要特定字幕组或特定清晰度；
- 某条源的字幕 / 音轨和你的需求不匹配。

换源入口在播放界面里，选源列表有简单与详细两种展示，详细模式能看清分辨率、字幕组、体积这类信息。

## 三、加自己的数据源

除了内置源，也可以自己加：

1. 打开设置，进入**数据源管理**；
2. 点新增（`+`）；
3. 填入订阅链接，确认添加。

加完要想一下是否值得留：**来源不可信的源不要加**。数据源决定你播放的内容从哪来，只加你能确认来源的。

## 四、卡顿与加载失败的排查顺序

按这个顺序走，多数情况在前两步就能解决：

| 现象 | 先判断什么 | 动作 |
| --- | --- | --- |
| 第一次点播放一直转圈 | 是 BT 源还是在线源 | 在线源本来就要等一段；BT 源等更久，先让它缓一会儿 |
| 转了很久还是不动 | 是不是冷门老番 | 老番可能无人做种，改用缓存或换在线源 |
| 播几秒就停、反复缓冲 | 网络到该源的连通性 | 换一条源；仍然如此再考虑用代理 |
| 只有某一条源不行 | 单源问题 | 直接换源，不必折腾网络 |
| 所有源都不行 | 网络出口问题 | 先确认其它应用能正常联网，再考虑代理 |
| 加载出来是白框 | 版本偏旧 | 更新到较新版本（官方 FAQ 指出旧版有此类问题） |

两点补充：

- 官方对这类问题的口径是：**不保证每个在线源的连通性**，让用户先检查自己的网络，再换源或使用代理。
- 桌面端第一次播放在线源同样要等资源拉取，那不是卡死。

## 五、BT 不稳定时的替代方案

BT 源受做种情况影响大。后来版本里加了 **PikPak 云端离线下载**，作为 BT 播放不稳定时的备选：把资源先存到云端，再从云端播，能绕开本地做种不足的问题。它不是默认路线，只在你确实被 BT 拖住时考虑。

## 六、播放页上的几个开关

播放页上还有几项与「选哪条源」无关、但每天都在用的设置：

| 开关 | 作用 | 什么时候用 |
| --- | --- | --- |
| 自动跳过 OP / ED | 自动跳过片头与片尾 | 连追多集时省掉每次手动拖进度 |
| 画面拉伸 | 改变画面填充方式 | 老番比例不标准、画面两侧留黑边时 |
| 连播下一集 | 一集结束自动接下一集 | 通宵补番；不想连播就关掉 |

两个前提要知道：**自动跳过 OP / ED 只覆盖部分新番**，老番与冷门集数不一定支持；**连播依赖剧集顺序正确**，后续版本修过一次剧集自动切换错误，遇到接错集先更新版本再判断。

## 七、和缓存的分工

**播不动不等于只能等，很多时候该改用缓存。** BT 老番和冷门在线源都适合提前缓存下来再看，缓存之后不再依赖播放当时的网络与做种情况。具体操作见 [离线缓存与没网时怎么看.md](离线缓存与没网时怎么看.md)。
