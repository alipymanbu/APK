## 一、屏幕异常时的第一道防线：10 秒自动撤销

先别急着重启。Screener 自带一道保险：应用之后 10 秒内你没有任何操作，参数会自动退回修改前的状态。所以刚应用了一个黑屏或花屏的数值时，把手拿开等 10 秒，多数情况屏幕自己就回来了。

等了 10 秒没恢复、或者你已经误点确认了，再走下面的 ADB 恢复。

## 二、ADB 强制恢复（官方给出的方法）

官方仓库的说明里明确给了恢复命令，就是 Android 自带的 `wm` 命令：

```bash
adb shell wm size reset
adb shell wm density reset
```

操作前提是一台电脑和一条数据线：

1. 电脑装好 ADB 工具（Android 官方 platform-tools 就够用）；
2. 手机打开「USB 调试」并连接电脑，弹出授权提示时允许；
3. 在电脑终端里依次执行上面两条命令；
4. 执行完屏幕参数即恢复系统默认值。

如果当初把原始分辨率记下来了（[修改分辨率与DPI的完整步骤.md](修改分辨率与DPI的完整步骤.md) 第一节），也可以用 `adb shell wm size 宽x高` 直接指回原值，效果一样。没记下来也不要紧——`adb shell wm size` 能直接读出硬件原始值（`Physical size` 那一行），具体输出格式与排查见 [ADB恢复屏幕参数命令详解.md](ADB恢复屏幕参数命令详解.md)。

## 三、常见问题

### Screener 提示没有权限、参数应用不了

九成是 Shizuku 没在运行，或者授权没给到。回 [Shizuku授权与启动步骤.md](Shizuku授权与启动步骤.md) 逐项核对：Shizuku 主界面显示「正在运行」、授权列表里 Screener 是允许状态。

### 重启手机后 Shizuku 怎么又没用了

无线调试方式受系统机制限制，每次重启后都要重新点一次「启动」，这是正常现象。参数本身的保留情况因机型与系统版本而异——别依赖重启来恢复参数，恢复用 reset 命令最稳妥。

### 应用商店搜不到、怎么拿新版本

它的官方分发渠道就是 GitHub 开源仓库 `jiesou/Android-Screener`（[https://github.com/jiesou/Android-Screener](https://github.com/jiesou/Android-Screener)）。注意官方 Releases 页面的安装包更新不及时，作者自述项目仍在开发中；仓库 Actions 页面的构建产物可能已过期，下载不到时按官方说明 fork 重新构建。本页使用的 1.0 版安装包可以从页面顶部的网盘入口获取。

### 修改对单个应用生效还是全局生效

全局生效：改的是整块屏幕的显示参数，所有应用、桌面、状态栏都受影响。想验证某个应用在特定参数下的表现，看完记得切回来——存一个「默认参数」的显示模式，一键切回最方便（见 [帧率调整与显示模式管理.md](帧率调整与显示模式管理.md)）。

### 会不会把手机改坏

参数层面的修改是可逆的，上面两条 reset 命令就能恢复默认；它不改系统文件、也不需要 root。真正要注意的是别在屏幕已经显示异常时反复叠加新参数——先等 10 秒自动撤销，救不回来再用 ADB。

### 恢复之后还有两件小事

- 有玩家文档建议**下次重启设备前先恢复默认分辨率**：带着覆盖值重启，部分设备可能出现布局错乱、触控错位、应用闪退等异常（因设备而定）；
- 个别应用在恢复分辨率后布局仍不对，重启那个应用或重启设备即可。
