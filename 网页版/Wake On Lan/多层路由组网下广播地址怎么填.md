# Wake On Lan 多层路由组网下广播地址怎么填

> 家里是「光猫加路由器」或「主路由加子路由」的多层组网时，局域网唤醒常常莫名失败，问题多出在广播地址的填法上。本篇讲两种广播地址的区别与对应填法。

## 一、两种广播地址，覆盖范围不一样

发唤醒指令时，应用往一个广播地址发 UDP 包。广播地址有两种写法，覆盖范围不同：

| 写法 | 例子 | 覆盖范围 |
| --- | --- | --- |
| 受限广播 | 255.255.255.255 | 只在本机所在的物理网段内传播，不跨路由器 |
| 定向广播 | 192.168.0.255（网段加 .255） | 面向整个 IP 网段，跨层组网时更有机会送达 |

网络排查资料与实测记录都指向同一个结论：电脑和手机之间隔了一层路由器时，255.255.255.255 经常送不到，改填电脑所在网段的定向广播地址（如 192.168.0.255）就通了。这也是 Wake On Lan 里 Broadcast IP 一栏要求填具体广播地址的原因。

## 二、先看清你家是哪种组网

手机和电脑分别看自己拿到的 IP：前两段一致（192.168.31.x 对 192.168.31.x）算同一网段；不一致就是隔了层。对号入座：

1. **光猫桥接、路由器拨号**：设备都在一个网段，按普通填法即可；
2. **光猫拨号、路由器当交换机用**：一般也是一个网段，普通填法；
3. **主路由下又接了子路由**：电脑接在子路由下、手机连主路由 Wi-Fi 时，两边隔了一层 —— 要用定向广播地址，且子路由不能开 AP 隔离；
4. **电脑连的是光猫自带的 Wi-Fi**：电脑与手机大概率不同网段，最稳的做法是让它们连到同一个路由器下。

## 三、对应到应用里的填法

- **同一网段**：Broadcast IP 填电脑 IP 末段改成 255，如 192.168.31.255；
- **隔层组网**：填电脑所在网段的定向广播地址（电脑在 192.168.0.x 就填 192.168.0.255），同时确认中间那层设备放行广播。家用路由器一般默认转发广播；企业交换机、跨 VLAN 的环境需要在交换机上开定向广播（如 Cisco 的 `ip directed-broadcast`，HP/Aruba 下的 Forward Net Directed Broadcast），家用场景碰不到这一层；
- 填完先在局域网里测一次（设备添加见《添加设备与局域网唤醒操作》），通了再考虑外网（见《外网唤醒与路由器端口转发》）。

## 四、改了还不通的点

定向广播也送不到时，剩下的多半是中间设备的策略：AP 隔离开着、广播包被过滤、或那层设备压根不转发广播（部分光猫自带的 Wi-Fi 就这样）。逐项排一遍仍无解，就让电脑和手机回到同一个路由器下 —— 组网越简单，唤醒越稳。其余原因看《唤醒失败的原因排查》。
