## 一、为什么外网唤醒要多配一步

局域网唤醒发的是广播包，广播包出不了路由器 —— 人在公司或用 4G/5G 流量时直接发，家里的电脑收不到。官方的处理方式是在应用里把广播地址填成设备的**公网地址**，并配合远程网络的配置把包送进去。前提是局域网唤醒已经先调通（见《添加设备与局域网唤醒操作》）。

## 二、路线一：路由器端口转发

思路是把公网某个 UDP 端口收到的包转发进内网：

1. 给电脑在路由器里绑定固定内网 IP（DHCP 静态分配），并记下电脑的 MAC；
2. 在路由器的「端口转发 / 虚拟服务器」里新增一条：外部端口 `9`（或 7）→ 协议 `UDP` → 内部目标填电脑的内网 IP；
3. 应用里编辑这台设备，Broadcast/Hostname 填家里的公网 IP 或 DDNS 域名，端口填 9；
4. 手机关掉 Wi-Fi 用流量，发一次测试。

两个常见拦路虎：

- **不少路由器不允许转发到广播地址**，只能转发到具体 IP；对已关机的电脑，ARP 缓存失效后包可能送不到，需要在路由器里做静态 ARP 绑定（把电脑内网 IP 与 MAC 绑死）。各家路由器支持程度不同，以自家路由器功能为准；
- **公网 IP 会变**（宽带重拨后就可能换），所以配一个 DDNS 域名（路由器自带 DDNS 或第三方 DDNS 服务都行），应用里 Hostname/FQDN 填域名而不是 IP；
- **有用户反馈部分运营商环境会过滤 9 号端口**：内部端口保持 9，把外部端口改成 9090 之类的再转发，应用里端口填外部那个值试一次。

另外注意电脑要**正常关机**：长按电源键强制断电或拔电源线后，网卡进不了待机监听状态，怎么转发都唤不醒。

## 三、路线二：VPN 回家网络（更推荐）

在家里路由器或 NAS 上开一个 VPN 服务（WireGuard、OpenVPN 等，多数中高端路由器内置），在外面手机先连 VPN，连上后手机等于就在家里局域网里，Wake On Lan 按局域网用法直接发，不用改任何设备配置。

相比端口转发，VPN 只暴露一个加密通道，不会给家里网络开一条直通公网的口子。如果同时还有远程桌面、文件访问的需求，VPN 一次配置全部复用。

## 四、安全上要注意的

- 端口转发方案等于在公网开了一个唤醒入口。唤醒包本身能造成的影响有限，但暴露了「这个网络里有可唤醒设备」这个信息，建议配合路由器防火墙限制来源，或干脆走 VPN；
- 检查路由器管理密码与远程管理功能，别为了唤醒把管理后台也暴露出去；
- 不确定宽带是不是大内网（运营商级 NAT）时，对比路由器 WAN 口 IP 与网页查询到的公网 IP 是否一致：不一致说明没有真公网，端口转发方案走不通，只能走 VPN 或内网穿透。

## 五、配完还是唤不醒

外网唤醒的失败面比局域网大得多：路由器不支持广播转发、ARP 绑定没做、宽带没有公网、运营商封端口，任何一环断都不行。排查思路见《唤醒失败的原因排查》—— 先保证局域网 100% 稳定，再回来逐环检查外网这一段。
