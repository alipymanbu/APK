## 一、模块是怎么挂到系统上的

SukiSU Ultra 的模块系统沿用 Magisk 的 Magic Mount 机制：模块不直接改写 system 分区，而是在启动时把文件「盖」到系统路径上。你卸载模块，系统就恢复原样 —— 这也是它比直接改系统分区安全的原因。前提是 root 环境已经装好，没装好的话管理器里的模块页面是空的或不可用，先回 [下载与安装教程.md](下载与安装教程.md) 把内核侧搞定。

## 二、装一个模块的标准步骤

1. 拿到模块的 zip 包（来源自行甄别，来路不明的模块以 root 身份跑，风险自担）；
2. 打开管理器 → 模块页 → 从本地安装，选中 zip；
3. 等安装日志跑完，出现成功提示后按提示重启；
4. 重启后回到模块页，确认开关是打开状态，再验证模块功能是否生效。

验证方法因模块而异：改系统参数的看设置页变化，改 hosts 的打开一个被拦的域名，做优化的看它自己给的检测命令。

## 三、能用哪几类模块

| 类型 | 说明 | 注意 |
| --- | --- | --- |
| Magisk 生态模块 | 大部分 Magisk 模块可以直接装 | 依赖 Zygisk 的模块需要额外配 ZygiskNext 这类配套 |
| KPM 内核模块 | 内核补丁模块，作用层级更深 | 要求你的内核开了 `CONFIG_KPM=y`，否则装了也不生效 |
| susfs 相关模块 | 配合 susfs 做环境隐藏 | 要求内核带 susfs；管理器设置里能直接管理部分 susfs 项时，可以少装一个模块 |
| WebUI 类模块 | 在管理器里以网页界面呈现操作面板 | 走 WebUI X 实现，由 MMRL 提供，模块本身要标明支持 |

装之前先看模块说明里的兼容条目：写着「仅支持 KernelSU 某版本」或「需要 susfs」的，对不上就别硬装。

## 四、一次只装一个，出问题好回退

这是模块使用里最值钱的一条纪律：

1. 每装一个，重启验证一次，确认没问题再装下一个；
2. 装完开不了机或功能异常，进 recovery（或用管理器的临时环境）把**最后装的那个**模块禁用或删除，再重启；
3. 不确定是哪个模块引起的，按安装顺序倒着逐个排除，别一次全删 —— 全删了你也不知道凶手是谁。

## 五、升级与卸载

- **升级模块**：一般直接装新版 zip、重启即可，个别模块要求先卸旧版，看它的说明；
- **卸载模块**：管理器模块页里删除，重启后生效；
- **升级系统（OTA）**：系统大版本更新可能让模块失效或行为异常，先逐个确认模块是否还适配，再决定留哪些（OTA 后怎么保住 root 见 [常见问题与故障排查.md](常见问题与故障排查.md)）。

## 六、模块相关的界面扩展

管理器本身支持界面定制：自定义背景、调整 DPI 等设置项都在管理器的设置页里。带 WebUI X 的模块会在管理器内直接出现一个操作面板，不用再跳出去开浏览器。找不到某项设置时，先确认模块开关与管理器版本 —— 老版本管理器可能还没有这个入口。
