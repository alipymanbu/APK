## 一、这套远程控制是怎么串起来的

远程控制延伸的是**电脑上已经在跑的任务**：电脑端（Qoder CN 桌面应用或 Qoder CN CLI）开着任务，手机端登录同一账号后就能实时看进度、在需要确认的节点点批准或拒绝、任务问你问题时补一句回答，还能直接下发新任务。产物文件仍然保存在电脑上，手机只负责指挥和查看。

前提有三条，缺一条就连不上：

1. 电脑处于开机且任务进程活着（电脑睡眠或关机，远程就断）；
2. 手机 App 与电脑端登录的是**同一个账号**；
3. 手机和电脑都能连上 Qoder 的服务（公司网络拦截时见[常见问题与故障排查.md](常见问题与故障排查.md)）。

## 二、用 CLI 连：远程控制模式

适合你已经在电脑上开了一个 `qodercn` 会话、临时要走开的场景。

1. 电脑终端里在运行中的 `qodercn` 会话输入：

```text
/remote-control
```

2. 开启成功后屏幕上会给出二维码和 URL。用手机相机扫码，或把 URL 复制到手机浏览器打开。
3. 手机上打开 Qoder CN Mobile（同账号），会话列表里就能看到这个已连接的 CLI 会话。
4. 连上之后你能做的事：
   - 实时看本地 CLI 的运行状态；
   - 对需要审批的操作点批准 / 拒绝；
   - 从手机下发新任务，比如「帮我优化这个项目页面的交互」——这条任务由**电脑上的终端**执行，产物落在电脑里。
5. 回到电脑前想断开，在会话里输入：

```text
/remote-control stop
```

查看当前连接状态用 `/remote-control status`。

## 三、用 CLI 连：守护进程模式

适合你打算让电脑挂着待命、人在外面随时发新任务的场景，不需要提前开 `qodercn` 会话。

1. 在项目目录里直接运行：

```text
qodercn remote-control
```

2. 同样会出二维码和 URL，手机扫码连接。
3. 手机端点右下角「+」新建任务即可，**不用等上一个任务做完**，可以连着发；每个任务的状态和结果在列表里独立显示。
4. CLI 会顺序或并行处理这些任务，生成的文件都在跑 CLI 的那台电脑上。
5. 退出守护模式按 `Ctrl+C`。

## 四、手机上能做的四件事

| 动作 | 什么时候用 |
|---|---|
| 看进度 | 任务在跑，你想知道它到哪一步了 |
| 审批 / 拒绝 | 它要改文件、执行命令，卡在等你点头的节点 |
| 补充回答 | 它向你提问，你不回它就一直等着 |
| 追加指令 | 跑到一半你想改需求，直接补一句话 |

任务跑完后，产物和代码改动（Diff）可以直接在手机上翻，先判断改得对不对，回到电脑前再决定要不要合入。开着 Plan 模式时，执行前的方案也能先在手机上过一眼。

## 五、浏览器也能管

不想在手机上装 App，或者手机没电了，用电脑/平板浏览器打开 `https://qoder.cn/agents`，登录同一账号，能看到同样的远程任务列表——和 App 是一套数据。

## 六、这条链路的边界

- 远程控制**不替代电脑端**：写代码、跑构建的重活还在电脑上，手机是「关键节点拍板」的入口。
- 电脑断网、睡眠、关机，连接就断；手机端会看到任务停在最后同步的状态，此时不是 App 坏了。电脑恢复后按第二节重新扫一次即可。
- 长时间离开工位又必须让任务继续，更省心的做法是把任务丢到云端跑，见[云端任务与GitHub仓库绑定.md](云端任务与GitHub仓库绑定.md)。
