## 一、云端任务和远程控制的区别

远程控制是「电脑干活、手机看着」，电脑必须开着；云端任务则反过来——**任务跑在云端环境里，你本地机器全程不用参与**，手机 App 关掉、电脑关机都不影响它继续跑。适合人在外面、手边只有手机，或者不想让本机被长时间占着的场景。

云端环境按需启动、自动管理资源，你只管把需求描述清楚，产物仍会落到你指定的代码仓库上。

## 二、四步发起一个云端任务

1. **选运行环境**：在 App 的 New Task 页面找到环境选择，切到 `Cloud`。
2. **绑定 GitHub 仓库与分支**：选定云端环境后关联 GitHub 账号，再挑这次任务要改的仓库和分支——这一步别跳，选错了改动会落到别的代码上。
3. **写清需求并发送**：输入框里描述任务，越具体越好（例如「根据这张截图生成 UI」这种一句话需求也能跑）。
4. **回会话列表看进度**：云端任务和本地任务并排出现在同一个列表里，进度、状态、待审批项都在同一处集中显示，不用换个入口再找一遍。

## 三、仓库列表里找不到目标仓库

这是授权范围的问题，不是仓库不存在。点列表下方的 **Manage repository access**，在你要用的那个仓库里安装 Qoder AI App，装完该仓库就获得访问权限，回到 App 里重新选即可。

公开仓库通常直接能选；私有仓库必须走这一步授权。

## 四、交付物怎么验收

任务跑完后，改动以代码 Diff 的形式在会话里给出。你在手机上先把关键改动翻一遍：

- 改动范围是不是只落在你选的那个仓库分支上；
- 有没有碰到你这次不想动的文件；
- 需要的话在会话里追加一句让它调整，让它继续改。

确认没问题后，回到电脑上走你平时的代码评审 / 合并流程。产出推回仓库后，你照样能在 IDE 里接着审。

## 五、什么时候用云端、什么时候用远程控制

| | 云端任务 | 远程控制 |
|---|---|---|
| 电脑 | 不用开机 | 必须开机且任务在跑 |
| 代码在哪 | 云端环境，按需连接 GitHub / 工作区 | 你电脑本地 |
| 典型场景 | 通勤、会议、出差路上直接交付 | 短暂离开工位，任务已经开了 |
| 产物落地 | 推回 GitHub 仓库 | 存在你电脑里 |

两者的任务在会话列表里是并排显示的，你在[远程控制电脑任务教程.md](远程控制电脑任务教程.md) 里学会的看进度、审批、追加指令，在云端任务上同样适用；账号与登录要求见[手机登录与消息提醒设置.md](手机登录与消息提醒设置.md)。

如果你在电脑上常用 Qoder CN CLI，也可以用 `qodercn remote-control` 守护模式把任务挂在本地、由手机派单，那条链路和云端任务的区别在于产物留在本地电脑。
