## 一、这些开关都在哪

电脑端 qBittorrent → Tools → Options（工具 → 选项）→ Web UI。下面说的几项都在这一页里；qBittorrent 版本不同，名称与位置略有出入，以你设置页当时显示的为准。

## 二、Host header 校验：账号密码对也报未授权

qBittorrent 默认开启 Host header 校验（第三方资料多提到 4.6 起强制执行）：请求头里的 Host 与服务端认得的值对不上时，即使账号密码正确也会被拒。手机浏览器直接开 `http://IP:8080` 一般不受影响——Host 就是 IP 加端口；但一旦中间隔了反代、面板，或改过端口，就常在这里摔倒。官方 API 文档也要求请求的 Referer/Origin 与 Host 头完全一致，这正是第三方客户端与网页面板容易被拦的原因。

处理思路：

1. 没走反代的，检查应用里填的端口与实际访问端口是否一致（Host 头里带着端口）；
2. 走了反代的，优先修反代配置，把 Host 原样传给 qBittorrent，或在 Web UI 设置里把域名登记为受信任的代理；
3. 配置文件里把 `WebUI\HostHeaderValidation` 设为 `false` 能关掉校验，但这属于降低安全性的动作，临时排障用，排完改回来。

## 三、CSRF 防护与反向代理

qBittorrent 日志里出现 `WebUI: Referer header & Target origin mismatch` 就是 CSRF 防护在拦：请求来源与目标对不上。Web UI 设置里两处相关：

- **CSRF 防护**：拦来源不一致的请求。关掉同样降安全性，先修反代或来源，再考虑其他；
- **反向代理支持**：走反代时打开这项，新版 qBittorrent 还要求填受信任的代理地址列表。

这个安卓客户端（v4.9.2）的官方更新日志里，4.8.x 前后修过与反代相关的兼容问题。挂了反代还连不上时，把「手机浏览器直接开 Web UI」和「应用直连」两种方式分开试，先确认问题出在哪一层。

## 四、登录失败封禁：输错几次后连对的也进不去

Web UI 自带防爆破：连续失败达到次数上限后，你的 IP 会被封禁一段时间，期间密码再对也进不去。次数与时长在 Web UI 设置里可调，默认时长各资料说法不一（官方 API 文档示例是 3600 秒，也有第三方资料写 15 分钟），以你设置页显示为准。急着用可以重启电脑端 qBittorrent，封禁立即解除。

所以排查连接问题时别反复试密码——试错次数攒够，只会把局面弄得更糟。

## 五、白名单：给固定设备开免认证通道

Web UI 的 IP 白名单（子网白名单）可以让列表内的地址跳过认证，比如只写自己家里的局域网段。两点提醒：

- 白名单是「跳过认证」，不是「放行访问」——不在名单里的设备仍要账密，别把它当访问控制用；
- 免认证只留给可信内网，面向公网的入口永远保留强密码加 HTTPS。
