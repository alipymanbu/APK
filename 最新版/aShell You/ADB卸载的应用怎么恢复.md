# ADB 卸载的应用怎么恢复

> 用 aShell You 执行过 `pm uninstall --user 0` 之后想反悔？讲清哪种能救、哪种救不回、用什么命令救。

## 一、先分清两种「卸载」

| 命令 | 实际发生的事 | 能否恢复 |
| --- | --- | --- |
| `pm uninstall --user 0 包名` | 只把包从当前用户（用户 0）的安装记录里移除，**包本体还留在系统分区** | 预装应用可以恢复 |
| `pm uninstall 包名` | 真正卸载 | 自装应用删了重装即可；系统分区的包一般删不动 |

对预装应用，`--user 0` 的效果是「对当前用户不可见」而不是「删除」，所以留了反悔的余地——多个独立来源（如 XDA 的厂商精简指南）对机制的描述都是同一口径。

## 二、恢复命令

在 aShell You 里执行（需要 Shizuku 或 root 权限在线，配置见 [Shizuku配置教程](Shizuku配置教程.md)）：

```bash
cmd package install-existing 包名
```

执行成功后，应用会重新出现在桌面上。

## 三、什么情况救不回来

- 包不在系统分区——比如你卸的是自己后来装的应用，`install-existing` 对它无效；
- 包本体已被真正删除——普通 Shizuku 场景做不到这一步，一般碰不到。

## 四、动手前的自保顺序

1. `pm list packages` 先确认包名（命令参考见 [常用ADB命令示例](常用ADB命令示例.md)）；
2. 对拿不准用途的系统包，先查清再动手；
3. 优先用 `--user 0` 而不是真卸载，给自己留反悔的余地；
4. 万一删错系统关键组件、`install-existing` 也救不回，剩下的手段就只有恢复出厂——所以第 3 步不是可有可无。

执行命令时连不上、报权限错误，先看 [常见连接问题排查](常见连接问题排查.md)。
