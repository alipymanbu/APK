# Shizuku 重启后自动启动怎么做

> 无 root 设备重启后 Shizuku 服务会停，这是系统限制。本篇按设备情况整理「重启之后怎么让它回来」：root 的开关、官方的自动启动条件、社区做法。

## 一、先对号入座：你的设备属于哪种

| 设备情况 | 重启后 | 恢复方式 |
| --- | --- | --- |
| 已 root | 可以自动启动 | 应用内设置开「开机自启」 |
| 未 root，安卓 13+ 且常连固定 WLAN | 官方支持自动启动（有条件） | 见第三节 |
| 未 root，其余情况 | 服务会停 | 手动点启动，或参考第四节 |

## 二、已 root：设置里就有开关

已 root 的设备，在 Shizuku 的设置里开启「开机自启」，重启后服务随系统起来，不用任何手动操作。同时按 [常见问题与故障排查.md](常见问题与故障排查.md) 的做法允许后台运行——厂商的省电策略连开机自启的进程也一样拦。

## 三、未 root：官方自动启动的条件

官方从 v13.6.0 起，在安卓 13 及以上、连接受信任的 WLAN 时支持免 root 自动启动（以官方发布页为准）。版本、系统都满足时，到应用内设置里找自动启动相关开关开启；「受信任 WLAN」由系统认定，换了网络环境可能就不生效。

不满足条件（版本旧、或所在网络不被信任）的，重启后打开 Shizuku 点一次「启动」是最稳的路径——无线调试已配对过的话，这一步只要几秒，不需要重新配对（流程见 [无线调试配对与启动方法.md](无线调试配对与启动方法.md)）。

## 四、社区做法（非官方，自行评估）

- 有第三方教程介绍用第三方维护的 Shizuku 分支实现免 root 开机自启，做法是给应用授予系统设置写入权限。这属于非官方构建，来源与更新情况需要自己确认，具体步骤以对应项目的说明为准；
- 也有用户用自动化工具在开机后自动执行启动流程，部分机型（如三星 One UI）上有社区分享的现成方案，能折腾但维护成本高。

想省事，官方路线里最接近「免维护」的组合是：安卓 13 及以上 + 受信任 WLAN + 保持无线调试开启。

## 五、自动恢复不等于永不掉线

即便成功自启，无 root 设备运行中途仍可能被系统杀掉，重新启动服务即可。掉线频繁的排查见 [常见问题与故障排查.md](常见问题与故障排查.md)；root 设备有开机自启兜底，日常基本不用操心这一层。
