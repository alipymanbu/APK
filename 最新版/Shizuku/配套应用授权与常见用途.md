# Shizuku 配套应用授权与常见用途

> Shizuku 本身不直接实现什么功能，它的作用是给其他应用提供一个「借道系统接口」的入口。本篇讲授权怎么给、哪些应用用得上、用不了时先查什么。

## 一、授权一个应用只要一次

前提：Shizuku 处于「正在运行」状态。还没启动的先看 [无线调试配对与启动方法.md](无线调试配对与启动方法.md)。

1. 打开支持 Shizuku 的应用，它会检测到 Shizuku 服务并弹出授权请求；
2. 在授权对话框里选「允许」；部分应用会提示选「始终允许」，选它可以在 Shizuku 重启后自动恢复授权，不用每次手动确认；
3. 回到应用继续操作，原来做不到的动作能正常执行了，就说明接通了。

反向管理：Shizuku 应用内的已授权应用列表里，可以随时取消某个应用的授权。

终端类工具的接入方式不同：aShell 这类内置 Shizuku 支持的按上面流程授权即可；Termux 这类不支持的终端，走官方的 rish 方案，见 [rish终端命令怎么用.md](rish终端命令怎么用.md)。

## 二、哪些应用会用到它

配套应用名单会随时间变化，下面是几类典型场景（各应用自己的安装与使用以它的说明为准）：

| 用途 | 典型应用 | 借 Shizuku 能做什么 |
| --- | --- | --- |
| 应用权限管理 | App Ops | 调整普通界面碰不到的权限项 |
| 卸载/停用预装应用 | Canta | 对自己设备上不想要的预装应用做卸载或停用 |
| 后台应用管控 | 黑域（Brevent） | 配合 Shizuku 激活后管控应用的后台行为 |
| 命令行工具 | aShell / rish | 在手机上直接执行 ADB shell 命令 |
| 字体替换 | zFont 3 | 借 Shizuku 权限读取系统分区完成字体应用 |

挑选配套应用时只认你自己信得过的来源——Shizuku 授权出去的是 ADB 级别的系统接口，给错应用等于把钥匙交出去。拿不准一个应用为什么要这个权限，就先不给。

## 三、授权后用不了，先查这两个

- **Shizuku 没在运行**：手机重启过、或服务被系统杀了后台，配套应用就会报「Shizuku 未运行」。回 Shizuku 重新点「启动」，再回到配套应用刷新；
- **只给了临时授权**：有些场景下每次重启后授权都会失效，配套应用反复要求授权时，在弹窗里选「始终允许」。

按上面两步查完还是不行，对照 [常见问题与故障排查.md](常见问题与故障排查.md) 排查服务本身的问题。
