# Swift Backup 换机还原与数据迁移

> 本篇讲换新手机或清机之后怎么把 Swift Backup 的备份还原回去，以及清机前怎么把本地备份带出来。

## 一、还原前先对齐两件事

1. **登录方式必须与备份时一致**：匿名模式下做的备份只能在匿名模式下还原，Google 云备份要用同一个 Google 账号。新机装好后先别急着选登录方式（安装与首次启动的完整流程见 [下载与安装教程.md](下载与安装教程.md)）；
2. **想清楚要还原哪一层**：只把应用装回来（APK），还是连登录状态、进度一起恢复（私有数据）？这决定你需要什么权限，见下面第三节的要求表。

## 二、还原应用的流程

1. 新设备装好 Swift Backup 并完成权限授予；
2. 进入 Apps 页签，用 Quick Actions 里的 Restore all apps，选择 From Device（本地）或 Clouds（云端）；
3. 逐个选中要还原的应用，点 Restore Options 决定还原哪些部件（APK / 外部数据 / 私有数据等）；
4. 批量还原需要 Root 或 Shizuku 服务在跑；两者都没有就逐个手动还原，效果一样，只是要点很多次。

## 三、各部件的还原要求

| 部件 | 内容 | 备份要求 | 还原要求 |
| --- | --- | --- | --- |
| APK | base.apk 与各分裂包 | 无 | 批量需 Root/Shizuku；手动逐个无要求 |
| Data | /data/data/ 私有数据 | Root | Root（Shizuku/ADB 模式无法访问） |
| 外部数据 | Android/data/ 下的文件 | Android 10 及以下无要求；11+ 需 Root/Shizuku | 与备份一致 |
| 扩展与媒体 | OBB 大文件、媒体文件 | 以应用内显示为准 | 以应用内显示为准 |

官方 FAQ 的建议：大多数应用用 APK + Data 还原即可恢复原状，个别应用需要试错，先还原一个验证再批量处理。

## 四、短信、通话记录与壁纸

- **短信**：Android 只允许默认短信应用写入短信库，还原时按提示把 Swift Backup 临时设为默认短信应用，还原完成后再切回原来的应用；
- **通话记录**：授予对应权限后即可还原；
- **壁纸**：备份的是你当时已应用的壁纸，还原时会把它们重新应用上去。

## 五、清机前把本地备份带出来

官方 FAQ 专门有一条「要把设备格式化/清空，本地备份怎么移出去」：本地备份就是设备存储里 SwiftBackup 文件夹中的文件，数据线复制到电脑、拷进 SD 卡或 U 盘、或者先传到任意云端都可以。搬运时把 SwiftBackup 文件夹**按原结构整体**复制，不要单独挑里面的子文件夹搬——官方 issues 页把「手动拷贝时移动不完整、内部文件夹结构错乱」列为新设备读不到备份的最常见原因。新设备上把文件夹放回与原来一致的位置（或用同一个 Google 账号登录读云备份），再走第二节的还原流程；放回去还是读不到，按 [读不到备份与还原失败排查.md](读不到备份与还原失败排查.md) 处理。

## 六、还原完的核对清单

- **应用权限**：无 Root 时权限不会跟着 APK 过去，把要用的应用逐个重新授权；
- **电池优化等特殊状态**：只有 Root 备份的特殊应用数据能还原回来，无 Root 全部要手动重设；
- **默认短信应用**：确认已经切回你原来的短信应用；
- **备份文件**：确认新设备上的本地备份或云备份可读，再清掉旧设备。
