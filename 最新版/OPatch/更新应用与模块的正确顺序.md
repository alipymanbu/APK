# 更新应用与模块的正确顺序

> 本篇讲被修补过的应用出新版之后怎么办、模块出新版之后怎么办——直接在应用商店里点更新会把修补版覆盖掉，这里的顺序值得照着走。还没修补过的先看 [模块注入与修补教程.md](模块注入与修补教程.md)。

## 一、先堵住自动更新这个口子

修补版应用和官方原包签名不同，应用商店一旦自动更新，新包会把修补版整个覆盖，模块随之失效。所以修补完第一件事就是关掉这个应用的自动更新：

- 应用商店内：对该应用单独关闭「自动更新」（多数商店的应用详情页或长按菜单里有这一项）。
- 想彻底省心：在商店设置里关全局自动更新，改为手动逐个更新。

## 二、应用出新版：两种修补方式对应的更新路径

应用的新版安装包从官方渠道或你信任的发布页拿，别用来路不明的「去验证版」。拿到新版 APK 后，按你当初选的修补方式走：

**本地模式（模块不嵌入包里）**

1. 在 OPatch 里对新版 APK 走一遍修补（选存储目录里的新版安装包，而不是已安装应用——本地模式更新走这条路径更顺）。
2. 修补完成后安装，与手机上正在用的修补版签名一致时可直接覆盖安装，应用数据保留。
3. 模块不用动，重启应用即可。

**集成模式（模块已嵌入包里）**

1. 确认模块本身兼容新版应用（见下面第三节）。
2. 在 OPatch 里对新版 APK 重新修补，并勾选要嵌入的模块。
3. 安装修补好的新包；签名一致可直接覆盖，不一致就先卸载旧修补版（数据先备份）。

两种方式更新应用都绕不开重新修补，这是这类免 root 框架的固有流程；区别只在模块要不要跟着重嵌一遍。修补方式怎么选的对照，见 [模式选择与设置说明.md](模式选择与设置说明.md)。

## 三、模块出新版：跟着修补方式走

- **本地模式**：直接安装新版模块，覆盖旧版，然后重启被修补的应用。模块本体装在手机上、由 OPatch 统一挂载，所以更新不需要动应用。注意：本地模式下模块卸载后应用里的功能就失效，只能升级、不能卸。
- **集成模式**：模块是打包时嵌进应用里的，更新模块等于重新修补一次应用，按上面集成模式的步骤走一遍。

更新模块前顺手核对模块的更新说明里有没有「不支持免 root 框架」「不支持集成模式」这类字样——部分模块作者对这类框架做了限制，之前能用、新版未必还能用。

## 四、更新前后的三个检查点

| 检查点 | 怎么做 |
| --- | --- |
| 模块兼容性 | 模块说明里标的应用版本范围是否覆盖新版应用；只支持 64 位的模块配 32 位应用不生效 |
| 应用数据 | 签名不一致需要先卸载时，聊天记录、登录态等本地数据会丢，先备份 |
| 修补产物 | 每次修补都在输出目录生成新包，旧包自己清理，别装错新旧版本 |

装完新版后发现异常的，按 [常见问题与故障排除.md](常见问题与故障排除.md) 的顺序排查。
