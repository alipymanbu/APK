## 一、修补前要备齐的东西

修补是把目标应用的安装包「重打包」一遍，开始前把材料备齐，中途不用到处找：

1. **目标应用**：要么已经装在手机上，要么手里有它的 APK 安装包，两种都支持。
2. **模块包**：你想挂载的 Xposed 模块，先装到手机上（本地模式会直接读已安装的模块）；模块从模块作者的发布页拿，别用来路不明的包。选模块时对三样东西：模块说明里支持的**应用版本范围**是否覆盖你手机上这个应用的版本、模块要求的**安卓版本**、模块是 32 位还是 64 位——只支持 64 位的模块配上 32 位版本的应用，修补完也不会生效。
3. **输出目录**：修补生成的新安装包要有地方放。第一次操作时 OPatch 会让你选一个目录；注意**直接选手机根目录会被系统拒绝**，要在选择器里新建一个子文件夹（比如 `Download/opatch输出`）再确认，之后生成的文件都在这里，好找好删。
4. **电量与空间**：修补过程要解包再打包，目标应用越大耗时越长；手机剩余存储最好留出目标应用体积两倍以上的空间。

## 二、完整修补流程

下面的按钮位置按社区教程整理，不同版本界面文字可能略有出入，以你手机上实际显示为准：

1. 打开 OPatch，等启动动画播完进主界面。
2. 切到**应用管理**页（底部导航的标签，找不到就点左下角的方块图标）。
3. 点右下角的**「+」**按钮，第一次会弹出存储目录选择，选你准备的输出文件夹并确认——这一步是在告诉 OPatch「修补完的包放这里」。
4. 回到列表，选中你要修补的目标应用；如果目标应用没装、只有安装包，就走从 APK 修补的入口。
5. 选择修补方式：**本地模式**或**集成模式**。两者差在哪、怎么选，见 [模式选择与设置说明.md](模式选择与设置说明.md)，不确定就先看那篇再回来。
6. 勾选要一起注入的模块（集成模式才会出现这一步；本地模式模块由管理器动态挂载）。
7. 点**开始修补（注入）**，然后等。期间不要杀掉 OPatch、不要锁屏离开太久。
8. 修补完成后，输出目录里会出现一个新安装包，点安装（或自己用文件管理器装）。
9. 装完打开被修补的应用，模块就生效了；个别模块需要重启一次该应用或按模块自己的说明初始化。

## 三、修补之后与原版的四个区别

修补生成的应用和官方原包不是一回事，这几个变化你要有预期：

| 变化 | 影响 |
| --- | --- |
| 签名变了 | 有签名校验的应用会出问题（登录回调失效、检测到非官方包等），这是这类免 root 框架的固有限制，无法在免 root 前提下彻底解决 |
| 不能从应用商店更新 | 商店更新的新包会覆盖掉修补版；应用出新版后要在 OPatch 里对新一版重新修补 |
| 数据是否保留 | 覆盖安装且签名不一致时，系统通常要求先卸载原应用，应用本地数据可能丢失；装之前先备份重要数据 |
| 模块更新方式 | 本地模式更新模块后重启应用即可，但模块只能升级、不能卸载（卸了应用里的功能就失效）；集成模式要重新走一遍修补，修补完成后模块本体反而可以卸掉（已嵌入包里） |

签名校验失败、更新冲突这些问题的具体表现与处理，集中在 [常见问题与故障排除.md](常见问题与故障排除.md)。

## 四、怎么验证模块生效了

- 打开被修补的应用，看模块声称修改的那处行为是否出现。
- OPatch 的日志页会记录模块加载情况，模块列表里看该模块的加载状态。
- 没生效时按这个顺序排查：模块作用域是否覆盖这个应用 → 模块本身是否支持免 root 框架 → 换另一种修补模式重试。逐条的排查思路在 [常见问题与故障排除.md](常见问题与故障排除.md)。
