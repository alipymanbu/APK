## 一、主界面的两个常用入口

0.1.7 的主界面底部主要有两个标签：

| 入口 | 用途 |
| --- | --- |
| Terminal | 像聊天窗口一样输入指令，AI 在这里执行并回复 |
| Agents | 管理供应商与模型：补密钥、换模型、查看已有配置 |

日常大多数时间你只跟 Terminal 打交道，Agents 只在加模型、换模型时才进。

## 二、发第一条指令

进 Terminal，用大白话把任务说清楚即可，例如：

```text
帮我把这段话翻译成英文：……
```

```text
查一下今天人民币对美元的汇率，整理成三行以内发给我
```

它的工作方式是把你的指令拆成步骤再执行，所以指令里**把目标和格式说清楚**（要什么、整理成什么样、什么时候要）比多打客套话有用得多。

一条好懂的指令通常包含四样：**背景、要做什么、交付格式、边界**。对比一下：

```text
整理一下这段稿子
```

```text
把下面这段会议记录改成待办清单：只保留行动项，每条一行，标上负责人和时间，没有的写"无"：……
```

第二种 AI 不用猜你想要什么，返工自然少。任务复杂时，先让它「列出执行计划，确认后再动手」，偏了当场纠正，比跑完再返工省得多。

定时任务也是同一套写法，把「什么时间、做什么、结果给谁」说全即可：

```text
每天早上 8 点，查一下今天上海下不下雨，一句话告诉我带不带伞
```

到点它会自己执行并回复——前提是后台白名单配好了，设置步骤见 [后台常驻与省电白名单设置.md](后台常驻与省电白名单设置.md)。

## 三、可以派给它的几类活

结合内置工具与多步执行能力，常见用法有这几类：

- **信息查询**：让它联网查最新信息并直接汇总结论，而不是甩一堆链接给你；
- **文档与表格处理**：整理销售数据、把长文提炼成要点清单、生成对比表；
- **跨应用协作**：在不同应用之间传递内容，按步骤完成一件多环节的事；
- **重复性自动化**：定时盯一个网页或数据源，有变化就通知你——这类活交给定时任务；
- **口述场景**：开车或不方便打字时，口述让它记日记、设提醒。

实际效果上限取决于你接的模型：同一个指令换成更强的模型，拆步骤与执行的质量可能差很多。

## 四、内置工具：按需用

0.1.7 里能看到这些工具方向：

- **联网搜索**：回答涉及时效信息时靠它；
- **HTTP 请求**：让 AI 去访问你给的接口地址取数据；
- **视觉多模态**：把图片发给它，让它看图作答（前提是所选模型本身支持视觉）；
- **沙盒脚本**：让 AI 在受控环境里跑一段脚本完成计算或批量处理；
- **定时任务**：到点自动执行，不需要你在场。

工具是否默认全开、在哪里逐个开关，以应用内设置页为准。

## 五、后台常驻：划掉应用它还在跑

它以前台服务的形式常驻后台，应用被划掉后任务仍会继续，通知栏会留一条常驻通知。两个实际影响：

- 那条常驻通知别随手禁掉，部分系统会连带把后台进程一起收掉；
- 发现指令发出去迟迟没动静，多半是系统省电策略把后台杀了，各品牌白名单的完整设置见 [后台常驻与省电白名单设置.md](后台常驻与省电白名单设置.md)。

## 六、多窗口并行

多个聊天窗口可以同时跑不同任务，各窗口还能选不同模型——比如一个窗口挂长任务慢慢跑，另一个窗口随手问答。窗口开得多时，留意 API 用量也会随之上涨，费用按各供应商的计量规则走。

还没申请密钥或想换模型，回 [API密钥获取与配置.md](API密钥获取与配置.md)；想先弄清它和普通聊天 App 的差别，看 [小龙虾助手是什么.md](小龙虾助手是什么.md)。
