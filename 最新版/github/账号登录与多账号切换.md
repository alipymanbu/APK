## 一、登录前先确认账号来源

应用登录用的就是你在 GitHub 网站上的那个账号。如果你还没有账号，先去 [github.com](https://github.com) 注册一个再回来；公司发了企业账号的，找管理员确认两件事：企业服务器版本是否 3.0 以上、管理员有没有开启移动端支持——少一样都登不进企业账号。

## 二、三种登录方式

### 1. 账号密码

最直接的方式：输入用户名（或邮箱）与密码。如果你给账号开过双重验证，密码通过后还要再过一道验证码，见下一节。

### 2. 社交登录（Google / Apple）

用 Google 或 Apple 账号一键登录。但有个前提条件：**你的 GitHub 账号当初必须是直接用 Google 或 Apple 注册的**，后来才绑的不行。另外官方文档写明这条路只对 GitHub Free 与 Enterprise Cloud 用户开放。

拿不准自己账号当初怎么建的？直接用账号密码方式登录最稳妥，登进去后在网页端设置里能看到绑定的登录方式。

### 3. 企业账号（Enterprise Server / GHE.com）

登企业账号和登个人账号是两个入口：

- **GHE.com（Enterprise Cloud 数据驻留）**：需要客户端版本 Android 1.178.0 以上。
- **GitHub Enterprise Server（公司自建）**：需要客户端 1.4 以上、服务器 3.0 以上，且企业管理员开启了移动端支持。

企业环境的两个已知限制，先有个预期：

- 公司要求走 VPN 才能访问企业实例的话，客户端可能用不了；
- Enterprise Server 的推送走后台轮询，推送到达会明显比个人账号慢，不是你手机坏了。

## 三、双重验证（2FA）怎么过

给账号开过 2FA 的，登录时输入密码后还会要求第二道验证。选 GitHub Mobile 作为验证方式时，流程是这样的：登录的设备（比如电脑浏览器）上会显示一个数字，GitHub 同时给你的手机应用发一条推送；打开推送或应用，把浏览器上显示的那个数字输进手机应用里批准，登录才放行。

还没开 2FA 的账号也有一次会用到这个应用：**新设备首次登录时的设备验证**。GitHub 会把验证请求发到你装着 GitHub 客户端并已登录的手机上（而不是发邮件），同样是把登录页面上显示的验证码输进应用里确认，验证码一小时有效。所以换新电脑登录时，手机上装着客户端能省去翻邮箱的麻烦。

如果你还没开 2FA，登录后建议顺手在账号设置里开启。收不到验证、数字对不上之类的具体状况见 [常见问题排查与解决办法.md](常见问题排查与解决办法.md)。

## 四、多账号同时在线与切换

客户端支持把多个账号同时挂着——GitHub.com 个人账号、GHE.com 账号、Enterprise Server 账号都能并存，不用来回退出登录。

操作入口都藏在底部导航栏的 **Profile** 上：

| 想做什么 | 操作 |
| --- | --- |
| 添加企业账号 | **长按** Profile → Add Enterprise Account，按提示登录 |
| 切换到另一个账号 | **长按** Profile → 点选要切过去的账号 |
| 退出某个账号 | **长按** Profile → 在账号上左滑 → Sign out |

点按（而不是长按）Profile 会进入个人页，从那里的头像进 **Manage Accounts** 也能完成上面这三件事，两条路随你习惯。

## 五、登录之后

账号挂好了，接下来通常做两件事：把推送通知按需调好（[通知与收件箱管理.md](通知与收件箱管理.md)），或者直接开始处理仓库里攒着的 Issue 和 PR（[手机上处理Issue与PR.md](手机上处理Issue与PR.md)）。
