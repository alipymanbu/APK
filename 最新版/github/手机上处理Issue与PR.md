# 在手机上处理 Issue 与 PR

> 本篇讲 GitHub 安卓客户端里 Issue 与 PR 的实际操作：能做哪些、入口在哪、怎么审怎么合并，以及哪些活儿留在电脑上做更省力。

## 一、先说清楚：手机上能走到哪一步

把你日常在 GitHub 上的协作按「找事 → 看事 → 办事」拆开，客户端能覆盖到「办事」这一步：

- **找**：搜用户、仓库、组织；在指定仓库里搜代码；
- **看**：读 Issue 与 PR 的完整讨论、看 PR 的文件改动（diff）、看仓库的 Release 与附件；
- **办**：回评论、贴表情回应、打标签、指派人、放进项目、提交 PR 审查结论（Comment / Approve / Request changes）、直接改 PR 里的文件、合并 PR。

也就是说，同事在群里 @ 你说「帮忙看一眼那个 PR」的时候，你掏出手机就能把审查做完，不用非等回到电脑前。

## 二、从事找起：三条常用路径

1. **从通知进**：最高频的路径。收件箱里点开那条通知，直达对应的 Issue 或 PR，见 [通知与收件箱管理.md](通知与收件箱管理.md)；
2. **从仓库进**：搜索或从关注列表进仓库页，切到 Issues / Pull requests 标签翻；
3. **直接搜**：顶栏搜索框支持搜用户、仓库、组织；进了某个仓库后还能在该仓库范围内搜代码——定位某段实现在哪个文件时用得上。

## 三、Issue 的日常操作

打开一个 Issue 后你能做的：

- **回复与回应**：写评论、给别人的评论贴表情回应；
- **整理**：加标签（label）、指派负责人（assignee）、关联到项目（project）——维护者在外面临时分派任务靠这三样就够；
- **状态**：关闭、重开。

给 Issue 指派给 Copilot（让它接手处理）这类较新的能力，客户端里也有入口；能不能用取决于你的账号计划，以应用内实际显示为准。

## 四、审查与合并 PR

一条 PR 从打开到合入，手机上完整走一遍的路径：

1. **看改动**：进 PR 切到文件改动视图，逐个文件看 diff；
2. **行内评论**：对着某一行提意见，和网页端一样落到那一行上；
3. **小修直接改**：改动文件视图里支持直接编辑文件并提交到这条 PR——发现个错别字、想补个配置，不用开电脑；
4. **给结论**：Comment（只评论）、Approve（批准）、Request changes（要求修改）三种审查结论都能提；
5. **合并**：审查通过后点合并按钮完成合入。用哪种合并方式（普通合并、压缩、变基）取决于仓库的设置，你在手机上按仓库既定配置合就行。

看 CI 检查结果也能做：PR 页里能看到检查（check）的通过与失败情况，Workflow 屏幕里能看每个步骤的运行状态。

## 五、这些活儿留给电脑

直说客户端的边界，省得你在手机上较劲：

- **跨多文件的大改动**：编辑文件是给小修补用的，成规模的修改回到本地开发环境；
- **大仓库的代码浏览**：仓库内搜索能定位代码，但长时间读代码、连续跳转引用，网页或桌面端舒服得多；
- **仓库/组织级的批量管理**：批量操作、权限、仓库设置这类管理动作，网页端更全。

顺手把该关注的仓库 Watch 设置调好（怎么调见 [通知与收件箱管理.md](通知与收件箱管理.md)），手机上剩下的就只有真正需要你的事了。如果连登录都还没搞定，先回 [账号登录与多账号切换.md](账号登录与多账号切换.md)；还没装应用的话从 [下载与安装教程.md](下载与安装教程.md) 开始。
