## 一、收件箱和网页端是同一份数据

应用里的通知收件箱和 GitHub 网页版的通知中心是互通的：你在手机上标已读，网页那边也跟着变，反过来一样。所以不用两头来处理通知——挑一个顺手的地方清就行。

## 二、哪些事件会推送到手机

不是仓库里一有动静就响，推送集中在**直接找上你的**事件：

| 事件 | 会推送吗 |
| --- | --- |
| 有人 @ 你的用户名 | 会 |
| 有人请你审查某个 PR | 会 |
| 你被指派了任务 | 会 |
| 需要你批准某个受保护环境的部署 | 会 |
| 团队提及（@某个 team） | 不推送 |
| 团队收到的审查请求 | 不推送 |

后面两类被刻意排除在推送之外，就是为了防止你的手机被别人的动静刷屏。这些事件依然会进收件箱，想看的时候去收件箱翻。

## 三、推送开关在哪调

### 全局推送类型

1. 点底部导航栏的 **Profile**；
2. 进入设置（齿轮图标）；
3. 点 **Configure Notifications**；
4. 按类型开关推送。

### 免打扰时段（Working Hours）

同一个设置页里有 Working Hours：指定一个时间段，期间推送全部静默。下班不想被工作追着跑、或者只想在固定时段处理开源项目的，把这个时段设上，收件箱照常收，只是不响。

### 单个仓库的 Watch 设置

某个仓库噪音太大但又不舍得取关？进到那个仓库页面点 **Watch** 按钮，可以像网页版一样只订阅部分动作，不用全有或全无。

## 四、收件箱里的分流操作

收件箱不只是个列表，每条通知都能直接处置：

- **点开**：进入对应的 Issue 或 PR 正文；
- **滑动手势**：在收件箱列表里横滑通知条目有快捷动作（标记已读、完成、取消订阅这类，具体按钮以你版本的实际界面为准）——处理完一条滑一下，列表立刻清爽；
- **筛选**：列表顶部可以按仓库、按通知原因（被提及、被请求审查、被指派）过滤，只看某一类时不用在一堆通知里翻。

一个已知的小坑：有用户反馈安卓端的横滑手势偏灵敏，快速滑动列表时容易误触把通知标成「完成」；被误清掉的通知去「已完成」里找，别以为丢了。

## 五、收不到推送时先查这几处

按命中率排序：

1. **系统通知权限**：安卓系统设置里这个应用的通知权限被关了，一切免谈；
2. **应用内推送开关**：第三节那个 Configure Notifications 里对应类型被关了；
3. **Working Hours**：正处在你自己设的免打扰时段里；
4. **省电策略**：部分国产系统会杀后台，把该应用加入省电白名单；
5. **企业账号**：Enterprise Server 的推送本来就慢（后台轮询机制），不是故障。

这五条只是入口级检查；每一步的系统设置路径、分品牌的省电白名单做法、以及「重置推送通道」的三个动作，在 [收不到推送通知的排查步骤.md](收不到推送通知的排查步骤.md) 里逐条展开。

推送调顺之后，通知列表里攒着的事就该处理了——审查 PR、回 Issue 这些操作的入口和做法在 [手机上处理Issue与PR.md](手机上处理Issue与PR.md)；登录环节出问题导致的收不到通知，要先从 [账号登录与多账号切换.md](账号登录与多账号切换.md) 那边查起。
