# Manus 手机端和电脑端怎么配合

> Manus 的任务在云端执行，手机、网页、桌面只是不同的入口。本篇讲清在哪儿发起、在哪儿看结果，以及共用账号要注意什么。

Manus 的常见误解是「手机上装了个 App，所以任务跑在手机上」。实际情况相反：任务在云端执行，客户端只负责把指令发出去、把进度和成果展示出来。想明白这一点，就能解释两件常被问到的事 —— 为什么手机关屏任务还在跑，以及为什么换个设备登录还能看到同一个任务。

## 一、有哪些入口

| 入口 | 形态 | 适合的场景 |
| --- | --- | --- |
| 网页端 | 浏览器打开官方站点即可，无需安装 | 电脑上临时用、不方便装客户端 |
| 安卓 App | 手机客户端 | 随手交办任务、随时查看进度 |
| iOS / iPadOS | 手机与平板客户端 | 同上 |
| 桌面端 | macOS / Windows 客户端 | 长时间任务、频繁处理文件 |
| 聊天渠道 | 在消息应用里连接后使用 | 不在电脑前、也不方便开 App 时 |

各端是否提供、以及当前支持的系统版本，都会随版本更新变化，以官方下载页当时列为准。安装步骤见 [下载与安装教程.md](下载与安装教程.md)。

## 二、账号是同一个，任务跟着账号走

- 用同一账号登录，**任务、对话历史和产出都与账号绑定，不跟随某一台设备**。手机上发起的任务，在网页端刷新就能看到进度。
- 因此不存在「换设备要重新开始」这回事；反过来，用错账号就会找不到之前的东西，登录后先确认账号再往下做。
- 同一账号可以在多台设备上同时登录，但**同时能跑多少任务有上限**，跟套餐有关，不是按设备数算的。

## 三、三种实用的配合方式

1. **手机发起、电脑收尾**：通勤路上用手机把任务丢出去，回到电脑前打开网页端接着看结果、下载产出。
2. **电脑做重活、手机看结果**：建站、长文档这类耗时任务在桌面端发起，之后用手机随时查看进度，不必守在电脑前。
3. **完全不在设备前**：把聊天渠道连上（在工作区打开对应标签页 → 连接 → 扫码 → 开始对话），之后直接在聊天里发指令、收结果。连接过程不需要命令行、配置文件或令牌。这类连接通道与其它工具的接法，见 [连接 Gmail 和 Slack 怎么设.md](连接 Gmail 和 Slack 怎么设.md)。

## 四、手机端适合做什么、不适合做什么

| 场景 | 说明 |
| --- | --- |
| 适合 | 一句话交办任务、随时看进度、确认或补充说明、取用结果 |
| 适合 | 上传手机里的照片、截图、文档作为任务素材 |
| 不太适合 | 上传体积很大的素材（受手机网络与本地存储限制，容易在中途出错） |
| 不太适合 | 需要反复比对、编辑产出的收尾工作（屏幕小，效率低） |

## 五、跨端要留意的两点

- **积分按账号算，不按设备算**。换端登录不会多一份额度，也不会把额度分开计。
- **不同客户端的消耗口径可能不完全一致**。官方帮助中心对桌面端的积分消耗有单独说明，如果你很在意记账差异，以官方那一条说明为准，别拿网页端的行为直接套到桌面端上。

跨端用起来之后，最容易忽略的反而是最基础的一件事：**任务描述写得好不好，决定了它在哪个端跑都一样省心还是都一样返工**，见 [怎么提任务才不容易返工.md](怎么提任务才不容易返工.md)。
