# Manus 任务卡住或失败怎么办

> 任务跑一半停住、报高负载中断、运行环境异常，是使用里最常遇到的三类问题。本篇先把它们分开，再讲什么时候该申请退积分。

「跑不动了」在 Manus 里对应好几种完全不同的原因，处理方式也不一样：有的等一会儿就好，有的要重置运行环境，还有的可以拿回积分。本篇按「先分类 → 再处理 → 再决定要不要申请退款」的顺序讲。

## 一、先分清是哪种情况

| 你看到的 | 属于哪一类 | 第一步做什么 |
| --- | --- | --- |
| 进度很久不动，但界面正常、任务没被结束 | 排队或高负载 | 先等一段时间，别立刻重发 —— 重发等于再跑一遍，又要花一份积分 |
| 弹出与运行环境（沙箱）相关的提示 | 执行环境异常 | 按提示重置环境，然后继续原任务 |
| 任务被判定结束，或出现高负载中断类错误（如 10091） | 服务端压力触发的中断 | 记下提示原文，换时段重试 |
| 任务正常结束，但结果明显不对 | 结果问题，不是故障 | 补一句说明让它改，或在原任务上继续 |

**先说一件容易误会的事**：任务停下来向你追问信息，不算卡住。它需要你补一个条件，你回一句它就继续 —— 这种情况不用重开任务。

## 二、高负载中断

高峰期服务端资源紧张时，任务可能被中断并给出错误提示。处理办法比较朴素：

1. 记下报错原文与出现时间（后面如果怀疑是平台问题，这是证据）。
2. 避开高峰时段重试；同一时间不要并发太多重任务。
3. 如果反复出现同一条中断，按第五节的办法判断是否符合退积分条件。

## 三、运行环境（沙箱）异常

任务是在一个隔离的运行环境里执行的，这个环境可能因为长时间断连而异常。按官方说明：

- **长时间无法重连时，环境会被自动重置**，这是恢复可用性的保护机制。
- **长期不用也会被回收**：免费用户 7 天不使用、付费用户 21 天不使用，环境会被回收。
- **回收后再打开会自动建一个新环境**，任务数据与工作记录还在，可以接着处理原有任务。
- **环境里的文件能恢复多少，官方两处口径不一致**：帮助中心说重置会丢失环境内的文件；产品博客说产物、上传的附件、幻灯片与网页开发这类重要文件会被自动恢复，运行过程中的中间代码与临时文件不会恢复。不管采信哪一边，**要留的东西跑完就下载到本地**，别指望它一直躺在任务里。

所以遇到环境提示，正确动作是**按提示重置，然后继续任务**，而不是把整个任务推倒重来。任务里到底留了哪些文件、分享出去会暴露什么范围，见 [任务文件和分享链接要注意什么.md](任务文件和分享链接要注意什么.md)。

## 四、结果不对但任务「成功」了

这类不属于故障，走的是另一条路：

- 在原任务上补一句说明，让它基于已有成果修改，比从零重开更省积分，也不丢上下文。
- 如果方向从一开始就偏了，那就回到任务描述本身改一遍再发，见 [怎么提任务才不容易返工.md](怎么提任务才不容易返工.md)。
- 主观上不满意（风格、设计、写法不合口味）**不属于退积分情形**，这一点提前知道能少走弯路。

## 五、积分到底能不能退

判断标准只有一条：**问题是不是出在平台这一侧**。

| 情形 | 能否退还 |
| --- | --- |
| 内部服务器错误、工具故障、系统崩溃导致任务没跑成 | 可以 |
| 工具被以违背官方说明的方式误用，导致任务失败 | 可以 |
| 无正当理由中途停止，且没有交付任何结果 | 可以 |
| 任务开始后你改主意、不想做了 | 不可以 |
| 指令模糊、互相矛盾或不完整导致结果不符预期 | 不可以 |
| 对结果的创意或主观方面不满意 | 不可以 |
| 第三方网站或接口本身故障导致的失败 | 不可以 |
| 触及预设的安全 / 资源 / 知识库限制而停止 | 不可以 |

申请时**必须提供出问题那次对话的可分享链接** —— 官方要靠它定位任务、核对消耗的积分。只描述现象、不给链接，一般无法受理。此外，涉及「上下文继承失败」的，要同时给出前后两次会话的链接。

退款申请由官方的审核流程处理，核实后按该任务实际消耗退还。计量口径与扣费顺序见 [积分怎么算与怎么省.md](积分怎么算与怎么省.md)。

## 六、重发之前先做三件事

1. **存证**：把出错提示原文、发生时间、任务链接一起记下来。
2. **改描述**：多数「跑不动」其实是任务太模糊或太大 —— 拆小、写清再发。
3. **接上下文**：把上次已经产出的素材和结论带进新任务，别让它从零开始，也别重复花一遍积分。

任务能不能顺利跑完，很大程度在发出去之前就决定了。如果这篇里的现象都对不上，可以去官方帮助中心按提示原文搜一下关键词，那里对具体错误码有单独条目。
