# 把脚本打包成独立应用

> 脚本写好后，你可以用 Autox.js 的打包功能把它变成一个独立 APK——不装 Autox.js 也能给别人用。本篇讲打包入口、各项配置、签名怎么建，以及打包产物最常见的三类问题。

## 一、打包能解决什么问题

直接跑脚本的前提是对方手机上装着 Autox.js。打包成独立应用之后，你的脚本、界面、图片资源都被装进一个普通 APK，接收方只需要装这一个文件、给它开权限就行——适合把小工具发给别人用，或者把自己常用的脚本整理成独立入口。

v7 分支在打包上做了明显增强：支持把基于 Node.js 引擎的脚本一起打包、提供签名管理、还能在打包配置里声明需要的特殊权限。具体支持项以你所用版本的打包界面为准。

## 二、打包入口与基本流程

1. 在 Autox.js 里把脚本整理成一个**项目文件夹**（一个文件夹里放 `main.js` 入口和其它模块、资源文件；单文件脚本也可以直接打包）。
2. 在脚本列表里对该项目（或文件）点开菜单，找「打包应用」一类入口（不同版本菜单位置有差异，一般在三个点或长按菜单里）。
3. 填写打包配置：应用名称、包名、图标、版本号；按需勾选权限与「开机自启动」之类选项。
4. 选择或创建签名（见下一节），点打包。
5. 打包完成后，APK 会生成在脚本目录附近（找不到就在「脚本」文件夹里搜 `.apk`），按普通 APK 的方式安装即可。

打包配置里如果列出了 ABI 架构（CPU 架构）选项，主流 64 位手机选 `arm64-v8a`。

## 三、签名：默认签名与自建签名

打包需要一个签名，Autox.js 内置了默认签名，什么都不改也能打出来。但签名是 APK 的「身份」，涉及两个实际影响：

- **升级覆盖**：两个 APK 只有签名一致、包名一致，新版本才能覆盖安装旧版本。你以后要给自己的应用发更新，就得一直用同一个签名——所以自己的工具建议一开始就创建一个签名并保管好。
- **安装兼容性**：有用户反馈打包产物在部分品牌手机上装不上，自己创建签名重新打包后可正常安装。多个教程提到过这个现象，与官方「打包功能已完善」的说法并存——遇到装不上时，优先试一次自建签名。

自建签名在打包界面或「签名管理」里创建：填一个密码和别名（记下来），生成后选择它再打包。签名文件丢了就无法对已发布应用做覆盖更新，只能换包名重发。

## 四、打包产物的三类常见问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 装不上（安装器直接失败） | 签名/架构与机型不匹配 | 自建签名重打；确认架构选了 `arm64-v8a` |
| 装上了但点了没反应 | 打包产物也需要授权，无障碍、悬浮窗等一个没开就不动 | 按 [权限设置与无法运行排查.md](权限设置与无法运行排查.md) 给这个新应用开权限 |
| 被安全软件报毒 | 无障碍 + 自动化点击的行为组合容易被误判 | 确认来路可信后加入白名单正常使用 |
| 脚本里的图片找不到 | 图片没有随项目一起打包 | 把图片放进项目文件夹、用相对路径引用，重新打包 |

## 五、发给别人的注意事项

- 打包产物是独立应用，接收方**不需要**也不能装你网盘里那份 Autox.js 来运行它——两码事。
- 提前告诉接收方要开哪些权限，比让他自己排查省事得多。
- 想让脚本定时跑的，接收方设备同样要做后台保活，方法见 [定时运行与开机自启.md](定时运行与开机自启.md)。
- 打包过程或产物异常，先看是不是打包时的报错信息，再到 [常见问题与报错处理.md](常见问题与报错处理.md) 对照。
