# 找图找色与文字识别

> 控件选择器对付不了画面（游戏、自绘控件、视频区域）时，就得靠「看图做事」：截图、找色、找图、识字。本篇讲这四件事在 Autox.js 里怎么做，以及每件事最常踩的坑。

## 一、前提：屏幕录制授权

所有截图类操作都建立在拿到当前屏幕画面上。第一次执行截图请求时，系统会弹「将开始截取屏幕内容」的确认框，点「立即开始」后脚本才拿得到画面。几个要点：

- 授权是**每次运行脚本都要来一遍**的（弹出确认框，你点一下就行），不是永久授权。
- 弹窗点拒绝或错过了，脚本里的截图函数会报错或返回空，重跑一次重新授权即可。
- 从后台调起这个授权弹窗，在新系统上会无反应——先回到 Autox.js 里把脚本跑起来再让它请求，见 [权限设置与无法运行排查.md](权限设置与无法运行排查.md) 关于「后台弹出界面」的说明。

具体函数名在不同版本间略有差异（如 `requestScreenCapture` 一类，较新的版本还加入了不跳转的传统授权方式），以你那版内置文档为准。

## 二、找色：颜色判断最轻量

拿到截图后，最常见的轻量判断是「某个位置是不是某个颜色」——比如判断一个按钮是不是亮了、进度条是不是满了：

```javascript
if (!requestScreenCapture()) { toast("没有截图权限"); exit(); }
sleep(1000);                       // 等截图通道就绪

let img = captureScreen();         // 抓当前屏幕
// 检测 (100, 200) 处颜色是否为 #11ff33（默认允许一定色差）
let ok = images.detectsColor(img, "#11ff33", 100, 200);
toast(ok ? "颜色匹配" : "不匹配");
```

要点：

- **颜色值从哪来**：截一张图存下来，用任意取色工具（或 Autox.js 的界面/图片查看功能）读目标点的色值，别靠猜。
- **色差阈值**：屏幕色彩、压缩都会让色值漂移，`detectsColor` 这类函数默认带一个相似度容忍（文档默认值 16），判断不稳时调大阈值，误判多时调小。
- 找颜色**出现的位置**而不是只判断真假，用 `findColor` 一类函数，它返回坐标。

## 三、找图：拿一张小图当模板

游戏里一个按钮形状固定、文字却变了（图标按钮），适合用找图：

1. 截一张包含目标按钮的图，裁出**只含按钮**的小图存进脚本目录（这就是模板图）。
2. 脚本里用 `findImage` 一类函数，在整屏截图里找这张小图：

```javascript
let tpl = images.read("button.png");       // 模板图放脚本目录
let p = images.findImage(captureScreen(), tpl);
if (p) {
    click(p.x, p.y);
} else {
    toast("没找到按钮");
}
```

要点：

- 模板图与运行时屏幕**分辨率必须一致**——你用什么分辨率截的模板，目标手机也得是同样分辨率，否则匹配率暴跌。跨分辨率分发脚本时这是第一大坑。
- 模板越小、越独特，找得越快也越准；别拿半张屏幕当模板。
- 图片文件路径用相对脚本目录的写法，将来要 [打包](把脚本打包成独立应用.md) 时，把图片一起放进项目文件夹即可。

## 四、文字识别（OCR）：把屏幕上的字读出来

画面上只有文字没有控件（比如图片里的说明文字、聊天内容），需要 OCR。v7 分支内置了 PaddleOCR 模型，开箱可用；不同版本的函数形式差异较大（初始化、参数都可能不同），**用之前先翻你这版的内置文档或示例**，别照抄老教程。

使用的整体套路一致：

1. 截图（先过授权那一关）；
2. 把截图交给 OCR 模块，拿到识别出的文字和位置；
3. 对文字做判断（比如「识别到『开始』就点击它的坐标」）。

OCR 比找色找图慢得多（首次运行还要加载模型），能控件、能找图的场景就别上 OCR。识别中文时准确率已经不错，但对艺术字、小字号、低对比度仍然不稳，脚本里要留「识别不到怎么办」的分支，而不是默认每次都认得。

## 五、四条路线怎么选

| 场景 | 首选 | 原因 |
| --- | --- | --- |
| 页面是普通应用（设置、微信等） | 控件选择器 | 最稳、最快，见 [脚本编写入门.md](脚本编写入门.md) |
| 按钮位置固定、颜色会变 | 找色 / 颜色检测 | 最轻量，几乎不耗资源 |
| 图标固定、颜色文字都变 | 找图 | 模板匹配，注意分辨率一致 |
| 只有文字可依赖且无控件 | OCR | 最重但唯一能「读懂内容」的路线 |

四条路线经常混用：控件找外框、坐标点中心，截图判断状态，OCR 兜底认字。跑不通时先怀疑截图授权，再到 [常见问题与报错处理.md](常见问题与报错处理.md) 对报错。
