# Autox.js 连接电脑开发调试（VS Code 插件）

> 在手机上敲代码又慢又难调试。把 Autox.js 连上电脑的 VS Code 之后，你在电脑上写、保存，一键就能在手机上运行，报错也直接在编辑器里看。本篇讲无线与 USB 两种连接方式，以及连不上的常见原因。
> **相关文档**：[脚本编写入门.md](脚本编写入门.md) · [常见问题与报错处理.md](常见问题与报错处理.md)

## 一、准备三样东西

1. 电脑装好 [Visual Studio Code](https://code.visualstudio.com/)。
2. VS Code 里安装插件：在扩展市场搜索并安装 **Auto.js-Autox.js-VSCodeExt**（插件 ID：`aaroncheng.auto-js-vsce-fixed`，即 Autox.js 官方 README 里给出的那个 PC 端开发插件）。
3. 手机端 Autox.js 已安装、无障碍服务已开启（连接本身不依赖无障碍，但运行脚本依赖）。

## 二、无线连接（同一局域网，推荐）

手机和电脑连**同一个 Wi-Fi**，然后：

1. VS Code 里按 `Ctrl+Shift+P` 打开命令面板，输入 `auto`，执行 **Start All Server**（开启全部服务器）。
2. 执行成功后，VS Code 右下角会显示一个 IP 地址（形如 `192.168.x.x:9317`），这就是服务端地址。
3. 手机上打开 Autox.js，从侧边栏菜单进入「连接电脑 / VS Code」页面，**开启服务**。
4. 在输入框里填入第 2 步看到的电脑 IP，等待连接成功。

连接成功后，你在 VS Code 里打开任意 `.js` 文件，按 `F5`（或用命令面板执行 Run）就会推到手机上运行，`console.log` 的输出会回到 VS Code 的输出面板。

插件的命令面板里还有 **Show QR code**（显示二维码），手机端支持扫码连接，省去手输 IP——手机和电脑不在一个网段时这招不管用，还是得先解决网络问题。

## 三、USB 数据线连接（ADB 方式）

Wi-Fi 不稳、或公司网络隔离设备时，用数据线：

1. 手机进入「开发者选项」，打开 **USB 调试**（找不到开发者选项的，先到「关于手机」连点「版本号」7 次解锁）。
2. 电脑上需要有 ADB：安装 [Android 平台工具](https://developer.android.com/studio/releases/platform-tools)（国内镜像 [developer.android.google.cn](https://developer.android.google.cn/studio/releases/platform-tools) 下载更快），解压后在该目录执行：

   ```powershell
   adb start-server
   adb devices    # 确认手机出现在列表里
   ```

3. VS Code 里再次执行 **Start All Server**，右下角出现 `ADB: Tracking started` 说明插件已经识别到设备。
4. 手机端 Autox.js 侧边栏开启 ADB 调试，插上数据线，插件会自动识别。

USB 方式跑起来更稳，还能配合 scrcpy 之类投屏工具边看手机边写代码。

## 四、连不上时逐项排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 手机填了 IP 但一直连不上 | 不在同一局域网 / 路由器开了 AP 隔离 | 确认两台设备连同一个路由器；关掉路由器的「AP 隔离 / 访客网络隔离」 |
| 电脑防火墙拦截 | Windows Defender 防火墙挡了入站端口 | 允许 VS Code（或 9317 端口）通过防火墙，或临时关防火墙测试 |
| 右下角没有 `ADB: Tracking started` | ADB 服务没起来或驱动缺失 | 先跑 `adb start-server`；`adb devices` 看不到设备就装手机对应驱动 |
| 手机弹「允许 USB 调试」后仍不识别 | 授权模式选错 | 把 USB 用途选成「传输文件」而不是「仅充电」，重插一次 |
| 之前连得好好的突然不行 | 电脑 IP 变了（换了网络 / DHCP 续租） | 重看右下角显示的 IP，手机端重新填 |

连上之后怎么写脚本、跑通第一个例子，直接回到 [脚本编写入门.md](脚本编写入门.md)；运行中报错的处理见 [常见问题与报错处理.md](常见问题与报错处理.md)。
