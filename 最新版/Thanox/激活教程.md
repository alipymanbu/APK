## 一、为什么装完还要激活

Thanox 的大部分功能不是在这个普通应用里完成的，而是要在 Android 的系统进程（`system_server`）里运行——所以官方的设计是：APK 只负责给你一个操作界面，核心能力要对系统"打补丁"之后才存在。这也解释了两件事：

- 为什么激活必须依赖 Xposed 框架、Magisk 或 Shizuku 这类能伸进系统进程的环境；
- 为什么每次更新 Thanox 之后，往往要重新勾选模块或重新刷补丁。

## 二、三种激活方式怎么选

| 方式 | 系统要求 | 官方定位 | 功能完整度 |
| --- | --- | --- | --- |
| Xposed 模式 | Android 6+ | 官方文档写明的主力方式 | 功能最全 |
| Magisk 模式 | Android 11+ | 官方标注"实验性" | 功能相对较少 |
| Shizuku | 无需 Root | 官方更新日志确认支持（5.1.2 版本起提及）；免 Root 环境下的精简路线 | 多位第三方资料说功能少于 Xposed 模式，以应用内实际显示为准 |

没有 Root 或不想折腾框架的话，先看你设备上已有的环境：已经装了 LSPosed 等 Xposed 类框架就走 Xposed 模式；只有 Magisk 就走 Magisk 模式；两者都没有，还有一条免 Root 的 Shizuku 路线，见[无Root激活教程](无Root激活教程.md)。

## 三、Xposed 模式激活步骤

前提：设备已经正确安装并启用了 Xposed 框架（LSPosed 或其他支持 Xposed API 的框架）。

1. 安装 Thanox（见[下载与安装教程](下载与安装教程.md)）；
2. 打开 Xposed 管理器（如 LSPosed），在模块列表里勾选 Thanox；
3. 勾选后重启设备；
4. **作用域**：支持作用域的框架，至少要勾选"Android 系统"（系统盒子）；如果你还想对某个应用用隐匿功能，需要把那个应用也勾进作用域。

注意：**每次更新 Thanox 后，建议重新勾选 Thanox 模块再重启**，这是官方明确写的要求。

## 四、Magisk 模式激活步骤（实验性）

前提：设备已装 Magisk，且满足以下之一——安装了 Riru 框架（Magisk v23 及以上），或开启了 Zygisk 模式（Magisk v24 及以上）。

1. 安装 Thanox 应用；
2. 打开 Thanox 的 设置 → 关于 → 补丁状态，导出 Magisk 补丁；也可以直接把 Thanox 的 APK 文件改名为 `.zip`，它本身就是补丁包；
3. 在 Magisk 的模块页面刷入上一步得到的补丁；
4. 重启设备。

注意：**每次更新 Thanox 应用，都要重新导出（或用新 APK 改名）并刷入新的补丁**，旧补丁对应旧版本。

把两边口径都放在这里：官方文档目前仍把 Magisk 模式列为可用激活方式；有第三方资料提到这条补丁路线"当前不维护"。用这条路线遇到问题时，先换 Xposed 或 Shizuku 路线。

## 五、激活失败的排查清单

按出现概率从高到低查：

- **框架本身没生效**：先确认 Xposed 管理器或 Magisk 显示框架状态正常，再谈 Thanox；
- **作用域漏勾**：Xposed 模式必须勾选"Android 系统"，漏了它等于没激活；
- **更新后没重做动作**：更新 Thanox 后没重新勾选模块（Xposed 模式）或没刷新补丁（Magisk 模式），是最常见的失效原因；
- **管理器权限被限制**：有用户反馈，更新后模块识别失败与限制了 Xposed 管理器的广播权限有关——不要限制它的广播权限，或更新后手动重新勾选并重启；
- **用了 Magisk 模式却觉得功能缺**：官方自己标注这是实验性模式、功能相对较少，不是你操作错了；
- **卡在开机进不去系统**：Magisk 与 Xposed 类框架都有各自的模块开关或安全模式入口，从框架侧临时停用 Thanox 的模块或补丁即可回到系统——这也是官方建议更新前先做备份的原因。

激活完成后回到首页，各功能入口即可正常使用；个别功能的额外前提（比如隐匿要给目标应用勾作用域）见[隐私与权限管控](隐私与权限管控.md)，更新后的维护动作也写在[下载与安装教程](下载与安装教程.md)的更新一节。
