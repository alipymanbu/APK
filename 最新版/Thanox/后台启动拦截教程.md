# Thanox 后台启动拦截教程

## 一、这个功能拦的是什么

应用之间互相拉起（官方叫"关联启动"）是国产应用生态里最常见的后台行为：你打开 A 应用，A 在后台把 B、C、D 都唤醒了。Thanox 的后台启动功能就在系统层拦截这类启动请求——注意它拦的是"后台被启动"，你自己点开应用不受影响。

## 二、总开关与默认行为

1. 先打开"后台启动"功能的总开关；
2. 默认情况下 Thanox **允许所有应用后台启动**（系统自带的安全管家拦不拦，Thanox 不干涉）；
3. 想拦谁，就在下方的应用列表里把那个应用的开关关掉。

也就是说它的用法是"默认放行、按应用拉黑"，而不是反过来。这个设计对你有利的一面是不会误伤，代价是每个要管的应用都得你手动关一次开关。

**别拦被依赖的组件**。官方给过一个典型例子：华为运动健康需要启动 HMS Core，如果你把 HMS Core 的后台启动拦了，运动健康可能无法正常登录。拦了之后发现某个应用登录不上、收不到推送，优先怀疑这类依赖关系。

## 三、启动记录：看懂每一条允许与阻止

想搞清楚"这个应用刚才为什么被拦/被放"，进后台启动功能，点右上角菜单里的启动记录；图表中间有个大数字，点它进入记录详情，每条记录都会标注处理结果（允许或阻止）和原因代码：

- `BYPASS_XXX` 开头 = 这一条被**放行**了，后缀说明放行原因；
- `BLOCKED_XXX` 开头 = 这一条被**阻止**了，后缀说明阻止原因。

常见代码对照（官方文档口径）：

| 放行原因代码 | 含义 |
| --- | --- |
| `BYPASS_WHITE_LISTED` | 目标应用在白名单 |
| `BYPASS_CALLER_WHITE_LISTED` | 调用方（拉起者）在白名单 |
| `BYPASS_ACCESSIBILITY_SERVICE` | 目标应用开启了辅助功能 |
| `BYPASS_UI_PRESENT` | 目标应用正在前台展示 |
| `BYPASS_DEFAULT_IME_SERVICE` | 目标应用是默认输入法 |
| `BYPASS_PROCESS_RUNNING` | 目标应用已经在运行中 |
| `BYPASS_SAME_CALLING_UID` | 应用调用的是自己的组件 |
| `BYPASS_USER_RULE` | 你的后台启动规则放行了它 |
| `BYPASS_DEFAULT` | 没命中任何分支，默认放行 |

| 阻止原因代码 | 含义 |
| --- | --- |
| `BLOCKED_STRUGGLE` | 目标应用刚被杀死，短时间内阻止它再被拉起（对抗"拉活"） |
| `BLOCKED_IN_BLOCK_LIST` | 你在列表里关闭了它的后台启动 |
| `BLOCKED_COMPONENT_IS_DISABLED` | 要启动的组件已被禁用 |
| `BLOCKED_STANDBY` | 目标应用开了乖巧模式（见[智能冻结与后台清理](智能冻结与后台清理.md)） |
| `BLOCKED_USER_RULE` | 你的后台启动规则阻止了它 |
| `BLOCKED_BLOCK_API` | 通过拦截接口阻止 |

查记录比猜有用：比如发现某应用"坏了"，记录里显示 `BLOCKED_IN_BLOCK_LIST`，把开关打开就好；如果显示的是 `BLOCKED_STANDBY`，问题出在乖巧模式而不是后台启动开关。

## 四、用规则精确控制

开关是"全拦/全放"，规则可以更细：只允许某一对应用的组合。规则由三段组成——**行动 + 启动者 + 目标**，行动只有 `ALLOW`（允许）和 `DENY`（拒绝）两种；启动者和目标写包名，`*` 代表任意应用，`THIS` 代表应用自己，另有 `SHELL`、`ROOT` 两个系统角色代号可用。

```
ALLOW com.tencent.mm com.tencent.qq    允许微信拉起 QQ
ALLOW android *                        允许系统拉起任何应用
DENY * com.tencent.mm                  拒绝任何应用拉起微信
ALLOW SHELL com.tencent.qq             允许 Shell 角色拉起 QQ
```

规则的判定会体现在启动记录里（`BYPASS_USER_RULE` / `BLOCKED_USER_RULE`）。配合"默认放行"的开关逻辑，典型用法是：对常被拉起的应用关掉开关，再用一条 `ALLOW` 规则放行你信得过的那一个调用方。

## 五、拦不住时先看这两处

- 总开关没开，或只加了规则但应用开关没关——开关是前提；
- 某些 ROM 自带的安全管家也在管后台，两套拦截可能互相看不到对方拦了什么；排查时先把 Thanox 的启动记录和系统管家的拦截记录都翻一遍。
