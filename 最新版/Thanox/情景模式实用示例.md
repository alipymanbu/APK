## 一、任务被划掉就杀掉应用

场景：在最近任务里划掉应用卡片时，顺手把它的进程杀干净（官方示例以微信为例，包名换成你自己的）：

```json
[
  {
    "name": "Kill on task removed",
    "description": "任务移除时杀死微信",
    "priority": 1,
    "condition": "taskRemoved == true && pkgName == \"com.tencent.mm\"",
    "actions": [
      "ui.showShortToast(\"正在杀死微信\");",
      "killer.killPackage(pkgName);"
    ]
  }
]
```

效果与手动杀后台一致；被杀到下次打开之间的推送会漏，要不要这样做看你对这个应用的取舍（见[冻结后收不到通知怎么办](冻结后收不到通知怎么办.md)里同一类问题的分析）。

## 二、新通知转成屏幕弹幕

场景：收到通知时不用下拉通知栏，直接以弹幕形式在屏幕上滚一条，带应用图标（官方示例；弹幕能力为较新版本支持）：

```json
[
  {
    "name": "弹幕通知 Danmu notification",
    "description": "收到通知时用弹幕展示",
    "priority": 1,
    "condition": "notificationAdded && !notification.isForegroundService && pkgName != \"android\"",
    "actions": [
      "ui.showDanmu(\"app://\" + pkgName, thanos.pkgManager.getAppInfo(pkgName).appLabel + \" \" + notificationTitle + \"\n\" + notificationContent);"
    ]
  }
]
```

条件里排除了前台服务和系统应用，避免弹幕刷屏；想只看某几个应用的通知，用 `pkgName == \"包名\"` 收紧条件。

## 三、指定页面出现时自动点按钮

场景：官方文档给出的示例——某应用的启动页出现"跳过"按钮时自动点一下。条件用 `componentNameAsShortString` 精确到页面：

```json
[
  {
    "name": "AD Skip",
    "description": "广告页面点击跳过",
    "priority": 1,
    "condition": "activityResumed == true && componentNameAsShortString == \"com.nowcasting.activity/.SplashActivity\"",
    "actions": [
      "ui.showShortToast(\"尝试点击跳过...\");",
      "ui.findAndClickViewByText(\"跳过\", \"com.nowcasting.activity/com.nowcasting.activity.SplashActivity\");"
    ]
  }
]
```

照抄要点：把组件名换成你的目标页面（获取方法见[移花接木教程](移花接木教程.md)里的"显示当前活动"），按钮文字换成页面上实际显示的文字；页面组件名在应用更新后可能变化，失效了重新抓一次。

## 四、蓝牙连上设备时提示

场景：蓝牙连接成功时用 Toast 列出设备名，并判断连上的是不是特定耳机（官方示例）：

```json
[
  {
    "name": "BT Connection State",
    "description": "蓝牙连接状态监听",
    "priority": 2,
    "condition": "btConnectionStateChanged == true && btConnectionStateConnected == true",
    "actions": [
      "ui.showShortToast(\"蓝牙连接连接到新设备了，所有设备名称为：\" + btBoundedDeviceAliasNames);",
      "ui.showShortToast(\"包含MDR-XB650BT设备吗？\" + btBoundedDeviceAliasNames.contains(\"MDR-XB650BT\"));"
    ]
  }
]
```

把 `MDR-XB650BT` 换成你的设备名，就能做"连上某耳机自动放歌"这类联动的前半段。

## 五、用全局变量管一组应用

场景：一条规则要作用于多个应用时，把包名放进一个全局变量列表，条件里用 `globalVarOf$变量名` 判断——以后增删应用只改变量，不动规则（官方示例）：

```json
[
  {
    "name": "Use var example",
    "description": "前台应用在变量列表 apps 中时，Toast 输出包名",
    "priority": 1,
    "condition": "frontPkgChanged == true && globalVarOf$apps.contains(to)",
    "actions": [
      "ui.showShortToast(to);"
    ]
  }
]
```

规则字段、转义写法与触发条件的完整说明在[情景模式入门教程](情景模式入门教程.md)；示例里的冻结/杀进程动作与手动冻结是同一套底层，行为对照见[智能冻结与后台清理](智能冻结与后台清理.md)。
