# Thanox 情景模式入门教程

> 情景模式是 Thanox 里的一套规则引擎：把"什么时候（条件）"和"干什么（动作）"写成一条 JSON 规则，系统事件一发生就自动执行。本篇讲规则结构、常用的条件与动作清单、两个可直接抄的例子。

## 一、它是什么，要会什么

官方对情景模式的一句话定义是"什么时候，干什么"：condition 是触发条件，actions 是要执行的动作。写规则需要：

- 基本的 JSON 语法；
- 条件与动作用 mvel 表达式写，长得像 Java 的一行代码。

它解决的是那些"每次都要手动重复"的小动作：进某个应用就开某个开关、划掉某应用就顺手杀掉它、点到某个快捷方式就锁屏。

## 二、一条规则长什么样

官方入门示例——应用切换时用 Toast 显示当前应用的包名：

```json
[
  {
    "name": "Current pkg",
    "description": "应用切换时，使用Toast显示当前应用的包名",
    "priority": 2,
    "delay": 2000,
    "condition": "frontPkgChanged == true",
    "actions": [
      "ui.showShortToast(activity.getFrontAppPackage());"
    ]
  }
]
```

各字段含义：

| 字段 | 含义 |
| --- | --- |
| name | 模式名，**用英文，多个模式不能重名**（重名会被覆盖） |
| description | 描述，随意写 |
| priority | 优先级，决定多条规则间的执行顺序 |
| delay | 动作延迟执行的时间，单位毫秒 |
| condition | 触发条件，mvel 表达式 |
| actions | 要执行的动作，mvel 表达式，可以写多条 |

语法注意：JSON 里的双引号要用 `\"` 转义，条件里拼接字符串时最容易在这翻车。

## 三、常用触发条件（事实）

事件发生时 Thanox 会发布"事实"并带上参数，条件里直接引用这些参数名：

| 事件 | 关键参数 |
| --- | --- |
| 前台应用切换 | `frontPkgChanged`、`from`、`to`（包名） |
| 应用任务被移除（划掉卡片） | `taskRemoved`、`pkgName` |
| 应用安装 / 卸载 / 更新 | `pkgAdded` / `pkgRemoved` / `pkgUpdated`、`pkgName` |
| 某页面显示 | `activityResumed`、`componentNameAsShortString`、`pkgName` |
| 亮屏 / 灭屏 / 解锁 | `screenOn` / `screenOff` / `userPresent` |
| 电量变化 | `batteryChanged`、`batteryLevel`、`isCharging` |
| 蓝牙开关与连接 | `btStateChanged`、`btConnectionStateChanged`、`btBoundedDeviceAliasNames` |
| WiFi 状态变化 | `wifiStateChanged`、`wifiState`（含 `enabled`、`ssid`） |
| 新通知到达 | `notificationAdded`、`pkgName`、`notificationTitle`、`notificationContent` |
| 系统启动完成 | `systemReady` |
| 桌面快捷方式被点击 | `shortcutLaunched`、`shortcutValue` |

条件支持 `&&`（并且）、`||`（或者）、`!`（非）组合，例如"微信回到后台"写成 `frontPkgChanged == true && from == "com.tencent.mm"`。

## 四、常用动作（handle）

动作通过"handle.方法()"的形式调用，常用的有：

| 写法 | 作用 |
| --- | --- |
| `killer.killPackage("包名")` | 杀死指定应用 |
| `activity.launchMainActivityForPackage("包名")` | 打开应用主界面 |
| `activity.getFrontAppPackage()` | 获取当前前台应用包名 |
| `power.sleep(0)` | 立即锁屏 |
| `power.wakeup(1000)` | 1 秒后亮屏 |
| `power.setBrightness(亮度)` | 设置屏幕亮度（0~255） |
| `task.removeTasksForPackage("包名")` | 移除应用的最近任务 |
| `task.clearBackgroundTasks()` | 清理所有最近任务 |
| `ui.showShortToast("文本")` | 弹短提示 |
| `ui.showNotification(标签, 标题, 内容, 是否重要)` | 发一条通知 |
| `ui.showDanmu("文本")` | 屏幕弹幕（较新版本支持） |
| `hw.enableBT()` / `hw.disableBT()` | 开 / 关蓝牙 |
| `hw.enableWifi()` / `hw.disableWifi()` | 开 / 关 WiFi |
| `data.setDataEnabled(true)` | 开关移动数据 |
| `pkg.disableApplication("包名")` / `pkg.enableApplication("包名")` | 冻结 / 解冻应用 |
| `audio.setRingerMode(0)` | 铃声模式：0 静音、1 振动、2 正常 |
| `sh.exe("命令")` | 执行 shell 命令 |

## 五、两个可直接抄的例子

**例 1：一键锁屏快捷方式。** 先在情景模式里创建一个"快捷方式引擎"，得到一个桌面快捷方式；再添加规则监听它的点击事件：

```json
[
  {
    "name": "Profile shortcut",
    "description": "监听一个快捷方式启动事件，以一键锁屏为例",
    "priority": 2,
    "condition": "shortcutLaunched == true && shortcutValue == \"turn screen off\"",
    "actions": [
      "power.sleep(0);"
    ]
  }
]
```

**例 2：打开微信时自动打开蓝牙。**

```json
[
  {
    "name": "Enable BT",
    "description": "打开微信时，打开蓝牙",
    "priority": 2,
    "condition": "frontPkgChanged == true && to == \"com.tencent.mm\"",
    "actions": [
      "ui.showShortToast(\"蓝牙状态\" + (hw.isBTEnabled() ? \"开启\" : \"关闭\"));",
      "hw.enableBT()"
    ]
  }
]
```

把包名、`shortcutValue` 换成你自己的值就能跑；跑不通用 `ui.showShortToast` 在各个环节打提示，很快能定位是条件没触发还是动作出错。更多可直接抄改的例子（通知转弹幕、任务划掉杀进程等）整理在[情景模式实用示例](情景模式实用示例.md)。

## 六、延迟与全局变量

- **延迟**：直接用规则里的 `delay` 字段（毫秒）。早期的 Actor 写法已被官方废弃，别再照旧帖子的例子写；
- **全局变量**：可以先定义一个字符串列表变量，规则里用 `globalVarOf$变量名` 引用，例如条件写 `frontPkgChanged == true && globalVarOf$apps.contains(to)`，就能对一组应用共用一条规则，不用把包名硬编码进去。

规则跑起来之后，它能调用的能力和后台启动、冻结这些功能是同一套底层——比如用 `pkg.disableApplication()` 写自动化冻结，行为与[智能冻结与后台清理](智能冻结与后台清理.md)里手动冻结一致；需要复制页面标识时，方法见[移花接木教程](移花接木教程.md)。
