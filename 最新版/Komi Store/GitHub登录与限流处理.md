# Komi Store 登录 GitHub 与限流处理

> 刷一会儿列表就加载失败、详情打不开？多半是撞上了 GitHub 的接口限额。本篇讲登录的三种方式、各自适合什么网络环境，以及登录不上的排查。

## 一、为什么需要登录

Komi Store 不登录也能浏览和安装，但 GitHub 对**未登录请求按 IP 计数限额**：同一个出口 IP 每小时约 60 次，学校、公司、公共 Wi-Fi 这类多人共享的网络很快就会触顶，表现为列表为空、详情打不开、下载失败。**登录自己的 GitHub 账号后**，限额按账号计算，提升到每小时数千次——这是 GitHub 的公开规则，具体数值以 [GitHub 官方文档](https://docs.github.com/)当前说明为准。

可以放心的一点：登录信息保存在你自己的设备上（官方说明凭据经加密存储），发给 GitHub 的也只有 GitHub 本身。详情页里的 Star 数、下载量这类统计数据由 Komi Store 自己的服务端提供，**看不看得到这些数据与是否登录无关**，也不消耗你的限额（官方仓库的说明，截至 2026-09）。

## 二、三种登录方式怎么选

| 方式 | 适合谁 | 一句话流程 |
| --- | --- | --- |
| 浏览器授权 | 手机浏览器能正常打开 GitHub 的你 | 应用内点登录 → 跳浏览器 → 确认授权 → 自动跳回 |
| 设备码（Device Flow） | 浏览器打不开 GitHub、或跳回失败的你 | 记下应用给的一串码 → 在**任意**能打开 GitHub 的设备上输入授权 |
| 个人访问令牌（PAT） | 前两种都不顺、或想精细控制权限的你 | 在 GitHub 网页生成令牌 → 粘贴进应用 |

三种方式登录的都是同一个账号，效果没有区别，一种不行就换下一种。

## 三、设备码登录（推荐先试这种）

1. 在 Komi Store 的登录界面选择设备码方式（不同版本入口叫法略有差异）；
2. 应用会显示一串一次性代码，先记下来（或复制）；
3. 在任意设备的浏览器打开 `https://github.com/login/device`，输入这串代码；
4. 用你的 GitHub 账号确认授权，回到应用，稍等几秒会自动完成登录。

手机浏览器打不开 GitHub 时，可以用电脑、甚至另一台手机完成第 3、4 步——代码不挑设备。

## 四、个人访问令牌（PAT）登录

1. 在浏览器登录 GitHub，点右上角头像 → **Settings** → 左栏最底部的 **Developer settings**；
2. 进入 **Personal access tokens**，生成一个新令牌（classic 或 fine-grained 均可，以 GitHub 当前界面为准）；
3. 权限选择：**只用于浏览和安装公开应用时，不勾选任何额外权限即可**；要连自己的私有仓库，才勾选对应的仓库读取权限；
4. 生成后**立即复制**令牌（只显示这一次），粘贴进 Komi Store 的令牌登录框。

令牌相当于账号的一把钥匙，不要发给别人；不用了就回 GitHub 的同一页面撤销。

另外，如果你在多个托管平台（Codeberg、Gitea 等）都有仓库，可以给**每个主机单独配令牌**（Per-host token），互不混用——这是 Komi Store 支持的做法，私有仓库场景用得上。

## 五、登录不上 / 登录后还是失败

- **浏览器授权跳回失败**：换设备码方式（第三节），绕开「跳回应用」这一步；
- **授权页面打不开**：网络对 GitHub 有限制，先把浏览器的代理/加速通道开好，或在另一台设备上完成设备码授权；
- **登录成功但列表照样空**：退出应用重开一次；仍不行看[常见问题与解决办法.md](常见问题与解决办法.md)的网络与镜像部分；
- **登录状态莫名丢失**：个别清理类工具会清掉应用数据，把 Komi Store 加入清理白名单后重新登录。

## 六、桌面端登录的差异

Windows、macOS 桌面版的登录同样走浏览器。Windows 端在 1.9.2 修复过「浏览器授权完成后回不到应用」的问题（官方更新日志），遇到这个现象先把桌面版升到最新版再试。桌面端各系统安装方式见[电脑版安装方法.md](电脑版安装方法.md)。

登录完成后，把常装的应用关联上更新提醒，接着看[安装GitHub应用步骤.md](安装GitHub应用步骤.md)第五节。
