# 用 Komi Store 安装 GitHub 应用的步骤

> 前提是你已经装好了 Komi Store（还没装的看[下载与安装教程](下载与安装教程.md)）。本篇讲从浏览、挑版本到装上一个 GitHub 应用，以及让已装的应用以后能自动提醒更新的完整流程。

## 一、找到你想装的应用

打开应用后，主要有这几类入口（以 1.9.2 版界面为准）：

- **趋势 / 热门发布 / 最多人装**：按平台排好序的榜单；
- **Explore（每日推荐流）**：按天更新的推荐内容，往下刷会继续加载；
- **Top Charts**：趋势榜、新发布榜、最受欢迎榜；
- **话题分类**：隐私、媒体、效率、网络、开发工具这类主题聚合；
- **搜索框**：按项目名直接搜，范围是 GitHub 以及你在设置里添加的其他主机（Codeberg、Forgejo、Gitea 等）；可以按平台、编程语言筛选，也能按「最近更新」「最近发布」排序（以 1.9.x 的搜索选项为准）。搜索历史会留在本地当下次建议；从别处**复制过 GitHub 项目链接**再打开应用，它会识别剪贴板并提示直达；已登录的用户还能用「从星标添加」，把账号里标过星的仓库一次挑出来。

## 二、看详情页，确认「是不是它」

点进项目后，详情页里有 README、更新日志、Star 数与开发者信息。建议养成两个习惯：

1. **先读 README**：确认这是你要的那个软件、功能对得上。英文 README 可以用应用内翻译功能（需在设置里填自己的翻译服务 key，支持 Google、有道、DeepL 等，支持哪些服务以应用内显示为准）。
2. **再看更新日志**：确认最新版本改了什么、有没有你避不开的变化。

## 三、点安装：版本与安装包怎么选

- 详情页的「安装」按钮默认给你**最新发布版**里适合你设备的安装包。1.9.2 起会按手机的 CPU 架构自动挑（如 arm64-v8a），不再默认给体积更大的 universal 包。
- 想装别的版本：进该项目的 **Releases 列表**逐个版本里选，每个版本可用的文件都在资产列表里。
- 有些项目同一个版本会发多个变体（universal / arm64 / Play 签名版等）。你选过的变体会被记住，这个项目下次更新时默认还是同一种，不会被换掉；也可以对单个项目**固定变体**，或写一条安装包文件名过滤规则（支持 glob / 正则），开发者改文件名也不怕更新抓错包。
- **测试版想不想装自己定**：每个应用可以单独切换「包含测试版 / 仅稳定版」，切回稳定版时若存在干净的稳定版本会自动回退。
- **装之前可以先体检**（安卓端）：安装前可以查看这个 APK 的应用名、签名指纹、最低系统版本和按保护级别分组的权限清单，心里有底再装。

## 四、完成安装

点下载后交给系统安装器，流程和装普通 APK 一样；第一次会跳到「允许安装未知应用」的授权页，允许后返回继续。

想让这一步更省事（点完不用再手动确认）可以在 **设置 → 安装** 里换安装后端：

- **Shizuku / Dhizuku**：静默安装，Shizuku 方式要求 Android 11 及以上；
- **root**：Magisk / KernelSU / APatch 用户可选用 root 后端。

这些不是必选项，默认的系统安装器完全够用。Shizuku 的完整配置步骤（含「手机重启后要重新启动一次」这类坑）单独成篇，见[Shizuku静默安装设置.md](Shizuku静默安装设置.md)。

## 五、把「已经装了的应用」挂上更新提醒

把已有应用关联起来，之后出新版本你就不用自己隔三差五去项目页查了。三种关联方式：

1. **扫描**：在应用列表页的菜单里用「扫描 GitHub 应用」，它会比对手机上已装的应用（含侧载、F-Droid 装的），把能对上号的关联到对应仓库——高置信度的自动关联，拿不准的列出来让你逐个确认；
2. **手动关联**：在应用详情页里手动把本机的某个应用绑到这个仓库；
3. **从 Obtainium 迁移**：导入你在 Obtainium 里已经配置好的追踪列表，不用逐个重来；之后也能随时导出回 Obtainium，两个工具之间来回搬不留死账。

关联之后，这些项目出新版本你会收到通知。**在应用外更新的也不怕**：更新判定按应用版本号比对，你在 F-Droid 或手动覆盖装的新版会被识别并同步记录，不会误报「有更新」。已装的应用也能直接在 Komi Store 里打开、卸载或降级。不想被某个版本打扰的，可以对单个应用设置「跳过此版本」或「忽略更新」。

## 六、关于登录 GitHub

不登录也能浏览和安装。但 GitHub 对未登录请求按 IP 限额，刷一会儿就可能遇到列表为空、详情打不开的情况；登录自己的 GitHub 账号后限额会高得多。三种登录方式（浏览器授权、设备码、个人访问令牌）的逐步操作和登录不上的排查，见[GitHub登录与限流处理.md](GitHub登录与限流处理.md)。

装的过程中遇到报错，同样优先翻[常见问题与解决办法.md](常见问题与解决办法.md)。
