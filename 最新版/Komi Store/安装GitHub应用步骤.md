# 用 Komi Store 安装 GitHub 应用的步骤

> 前提是你已经装好了 Komi Store（还没装的看[下载与安装教程](下载与安装教程.md)）。本篇讲从浏览、挑版本到装上一个 GitHub 应用，以及让已装的应用以后能自动提醒更新的完整流程。

## 一、找到你想装的应用

打开应用后，主要有这几类入口（以 1.9.2 版界面为准）：

- **趋势 / 热门发布 / 最多人装**：按平台排好序的榜单；
- **Explore（每日推荐流）**：按天更新的推荐内容，往下刷会继续加载；
- **Top Charts**：趋势榜、新发布榜、最受欢迎榜；
- **话题分类**：隐私、媒体、效率、网络、开发工具这类主题聚合；
- **搜索框**：按项目名直接搜，范围是 GitHub 以及你在设置里添加的其他主机（Codeberg、Forgejo、Gitea 等）。

## 二、看详情页，确认「是不是它」

点进项目后，详情页里有 README、更新日志、Star 数与开发者信息。建议养成两个习惯：

1. **先读 README**：确认这是你要的那个软件、功能对得上。英文 README 可以用应用内翻译功能（需在设置里填自己的翻译服务 key，支持 Google、有道、DeepL 等，支持哪些服务以应用内显示为准）。
2. **再看更新日志**：确认最新版本改了什么、有没有你避不开的变化。

## 三、点安装：版本与安装包怎么选

- 详情页的「安装」按钮默认给你**最新发布版**里适合你设备的安装包。1.9.2 起会按手机的 CPU 架构自动挑（如 arm64-v8a），不再默认给体积更大的 universal 包。
- 想装别的版本：进该项目的 **Releases 列表**逐个版本里选，每个版本可用的文件都在资产列表里。
- 有些项目同一个版本会发多个变体（universal / arm64 / Play 签名版等）。你选过的变体会被记住，这个项目下次更新时默认还是同一种，不会被换掉。

## 四、完成安装

点下载后交给系统安装器，流程和装普通 APK 一样；第一次会跳到「允许安装未知应用」的授权页，允许后返回继续。

想让这一步更省事（点完不用再手动确认）可以在 **设置 → 安装** 里换安装后端：

- **Shizuku / Dhizuku**：静默安装，Shizuku 方式要求 Android 11 及以上；
- **root**：Magisk / KernelSU / APatch 用户可选用 root 后端。

这些不是必选项，默认的系统安装器完全够用。配置这类工具遇到问题，见[常见问题与解决办法.md](常见问题与解决办法.md)。

## 五、把「已经装了的应用」挂上更新提醒

Komi Store 的价值一半在更新提醒。三种把已有应用关联起来的方式：

1. **扫描**：用「扫描 GitHub 应用」，它会比对手机上已装的应用，把能对上号的关联到对应仓库；
2. **手动关联**：在应用详情页里手动把本机的某个应用绑到这个仓库；
3. **从 Obtainium 迁移**：导入你在 Obtainium 里已经配置好的追踪列表，不用逐个重来。

关联之后，这些项目出新版本你会收到通知。不想被某个版本打扰的，可以对单个应用设置「跳过此版本」或「忽略更新」，也能用正则只匹配特定命名的安装包。

## 六、关于登录 GitHub

不登录也能浏览和安装。但 GitHub 对未登录请求按 IP 限额，刷一会儿就可能遇到列表为空、详情打不开的情况；登录自己的 GitHub 账号后限额会高得多。三种登录方式（浏览器授权、设备码、个人访问令牌）和登录不上的处理，见[常见问题与解决办法.md](常见问题与解决办法.md)。

装的过程中遇到报错，同样优先翻[常见问题与解决办法.md](常见问题与解决办法.md)。
