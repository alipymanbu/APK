# 把开机动画替换进系统的几种方法

> 本篇讲动画包做好之后有哪几条路能把它装进系统，各自需要什么条件，怎么挑。

## 一、先对照五条路，挑一条

前提是同一条：**动手前把系统里原来的 `bootanimation.zip` 原样备份一份**。下面五条路按「折腾程度」从低到高排：

| 方法 | 需要什么 | 适合谁 |
| --- | --- | --- |
| 免 root 通道 | 什么都不需要 | 想先试试运气的：成功与否完全看机型给不给 |
| root 文件管理器手动替换 | root + 一个 root 文件管理器（如 MT 管理器） | 大多数人走的一条，图形界面点几下 |
| adb 命令替换 | 电脑 + adb + root | 习惯命令行、想精确控制权限的时候 |
| Magisk 模块 | root + Magisk | 想要「随时卸载即恢复」的管理方式 |
| Recovery 卡刷 | 能用的 Recovery + 对应刷机包格式 | 系统起不来、或不方便进系统时 |

## 二、免 root 通道：先试，别抱太大期望

- 部分系统会读 **`/data/local/bootanimation.zip`**：把包放这里重启看效果，能成就省了所有权限操作；很多新机型封了这条路，放了没反应属正常。
- 有的系统层（如 MIUI 的主题体系）自带开机动画更换入口，在主题里换不需要 root —— 但那是主题商店的资源，不走你自制的 zip。
- 结论：这条路**成本最低、成功率也最低**，先花几分钟试一次就知道成不成，不成再往上走。

## 三、root 文件管理器：最常用的一条

1. 打开 root 文件管理器，进系统里动画所在的目录（`/system/media/` 或 `/product/media/`，不确定就看[替换后不生效的排查.md](替换后不生效的排查.md) 第三节的定位方法）。
2. **先把原厂 `bootanimation.zip` 拷出来备份**（存到 `/sdcard/` 即可）。
3. 把你做好的包拷进同一目录，**替换**同名文件。
4. 长按新文件核对：属主/属组是 `root`，权限至少 `0644` —— 这是最容易漏的一步。
5. 重启验证。

## 四、adb 命令：权限一步到位

电脑连手机，一条链走完（需 root 终端配合）：

```bash
adb push bootanimation.zip /sdcard/bootanimation.zip
adb shell
su
mount -o remount,rw /system
cp /sdcard/bootanimation.zip /system/media/bootanimation.zip
chown root:root /system/media/bootanimation.zip
chmod 644 /system/media/bootanimation.zip
reboot
```

好处是属主和权限在同一条链里设完，不用事后补。命令的详细解释与常见报错见[替换后不生效的排查.md](替换后不生效的排查.md) 第四节。

## 五、Magisk 模块：换完还能一键还原

装了 Magisk 的话，可以把动画包做成模块刷入，而不是直接改 `/system` 分区：

- 模块方式不动系统文件本体（挂载时覆盖），**在 Magisk 里卸载模块、重启，就回到原厂动画** —— 比手动替换少一层风险。
- 有的开源工具（如 `BootAnimationMaker` 这类）能把图片序列或 GIF 直接打包成带安装脚本的动画模块；也有模块支持安装期把 MP4 转成 `bootanimation.zip`。工具的具体用法以各自说明为准，本文不展开。
- 你已经会手动替换的话，模块只是把「拷文件 + 改权限」那两步固化下来，理解成本不高。

## 六、Recovery 卡刷：不进系统的替换

有的教程把动画做成 Recovery 可刷的 zip，在 Recovery 里刷入。这条路的价值在**系统本身起不来、进不去桌面**时仍能操作；代价是包格式要按对应 Recovery 的规矩做（与普通的 `bootanimation.zip` 不是一回事），格式不对会被拒绝刷入。没有遇到「改完开不了机」这类场景时，不必优先选它。

## 七、选哪条：一句话建议

没 root 先试第二节，成了就结束；有 root 走第三节手动替换（最直接）；想要可回退的管理方式走第五节 Magisk 模块；adb 那条给习惯命令行的人。无论哪条，改完重启后没生效都回到[替换后不生效的排查.md](替换后不生效的排查.md)逐项对 —— 卡点基本只有路径与权限两个。
