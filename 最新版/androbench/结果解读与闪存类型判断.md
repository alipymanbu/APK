## 一、先认识成绩单上的每一项

一次完整测试后，你会拿到这样几组数字：

| 成绩项 | 单位 | 读法 |
| --- | --- | --- |
| Sequential Read / 连续读取 | MB/s | 拷贝电影、压缩包这类大文件时的速度上限，验机最看这一项 |
| Sequential Write / 连续写入 | MB/s | 往手机里存大文件、录 4K 视频时更依赖它 |
| Random Read / 随机读取 | MB/s 与 IOPS | 打开应用、翻图库时系统在频繁做的小块读取，IOPS 是每秒操作次数 |
| Random Write / 随机写入 | MB/s 与 IOPS | 安装应用、聊天软件落盘数据时的表现 |
| SQLite Insert / Update / Delete | QPS | 模拟短信类应用数据库的增删改吞吐，反映日常数据操作 |

随机一项的数值天然远低于连续读写——旗舰 UFS 3.0 机型的 4kB 随机写入也只有几十 MB/s，这不是异常，是工作方式不同，别拿它跟连续读取比。

## 二、连续读取对照：你的手机属于哪一档

下面是各代闪存的连续读取经验区间，来自社区多年实测汇总与媒体评测（不是官方判定标准，实际成绩还受文件系统与使用状态影响）：

| 闪存类型 | 连续读取经验区间 | 参考实测 |
| --- | --- | --- |
| eMMC 5.1 | 约 150~300 MB/s | 某千元机实测读取 138 / 写入 21 MB/s |
| UFS 2.0 | 约 350~600 MB/s | 搭载 UFS 2.0 的机型实测读取 390 MB/s 左右 |
| UFS 2.1 | 600~800 MB/s 及以上 | 小米 6 实测读取 727~752 / 写入约 200 MB/s |
| UFS 3.0 | 超过 1000 MB/s | Galaxy Fold 实测连续读取 1478.85 / 写入 383.62 MB/s |

对应的实用判断口诀：连续读取低于 300 MB/s 基本就是 eMMC；600 MB/s 往上是 UFS 2.1 的门槛；上千的属于 UFS 3.0 一代。随机读取 IOPS 可以辅助验证——UFS 3.0 机型能跑到 3 万以上（Galaxy Fold 为 37635 IOPS），SQLite 三项也同步上一个量级（插入约 2449 / 更新约 3519 / 删除约 4201 QPS）。

写入这一栏要单独看：上表几组参考实测里，连续写入普遍只有读取的几分之一——eMMC 机型常常只剩零头（138 对 21 MB/s），UFS 2.1 约三分之一（727~752 对约 200 MB/s），UFS 3.0 也不到三成（1478.85 对 383.62 MB/s）。所以判断闪存代际以读取为主，写入远低于读取本身不是毛病。

## 三、为什么同一型号会测出天壤之别

这套工具被大众熟知，正是因为 2017 年的「闪存门」：某型号手机同一批次被曝混用 eMMC 5.1、UFS 2.0、UFS 2.1 三种闪存，官方随后确认了混料。同一型号的连续读取从此出现了「有人 700+、有人不足 300」的分化，用户拿实测成绩对照才发现自己的机器用了哪种料。

即使没有混料问题，成绩也会被这些因素拉开：

- **文件系统**——开发者自己的研究论文就指出，闪存类型与文件系统都显著影响存储性能，同一种闪存换个文件系统成绩会变；
- **存储占用**——越接近写满，写入速度衰减越明显；
- **当时系统在忙什么**——后台更新、索引、同步都会吃掉带宽；
- **单次波动**——同一台机器连测几次，数字差 5%~10% 很常见。

所以给一台机器「定性」之前，先按第二节区间粗判，再用下一节的办法复核。

## 四、不放心时的复核思路

成绩落在两档交界（比如 500~600 MB/s）时，别急着下结论：

1. 换个时段再测两次取平均，排除偶发干扰（排查思路见[测试结果偏低与常见问题排查.md](测试结果偏低与常见问题排查.md)）；
2. 对照结果界面里其他机型的排名，看自己的位置是否与预期档位一致；
3. 拿连续读取这一项为主、随机与 SQLite 为辅——三项同时落在同一档，判断才可靠；
4. 想跳过成绩推断，直接用终端命令读出闪存类型——见[终端命令查闪存类型.md](终端命令查闪存类型.md)，两条独立路径指向同一结论再定性。

复核后仍远低于预期档位，多半是测量条件在捣乱，按[测试结果偏低与常见问题排查.md](测试结果偏低与常见问题排查.md)的顺序过一遍即可。
