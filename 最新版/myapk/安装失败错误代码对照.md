## 一、先认这几条最常见的

从商店以外装包时，系统会做一连串检查，任何一步不过就抛一个错误码。高频的几条：

| 错误码 / 提示 | 真实原因 | 处理 |
| --- | --- | --- |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 手机上已有同包名应用，但**签名不同** | 先卸载已装的那份再装新包（卸载会清掉该应用的数据，先确认要不要留） |
| `INSTALL_FAILED_INVALID_APK` / 「软件包似乎已损坏」 | 文件没下完整、传输中损坏、或签名无效 | 重新下载，装前核对文件大小与校验值（见 [管理手机里的APK安装包.md](管理手机里的APK安装包.md) 第四节） |
| `INSTALL_FAILED_NO_MATCHING_ABIS` / 错误 -28 | 包里的 CPU 原生库与你手机架构不符 | 换与你机型匹配的包；老包只带 32 位库的，在纯 64 位新机上装不了 |
| 错误 -11 | 签名无效 —— 多半是文件被截断 | 删掉重下；别用会改文件的聊天工具传包 |
| 错误 -24 | 同包名、不同签名，覆盖被拒 | 同第一条：卸载旧的再装 |
| 错误 -29 | 签名方案太老（只有 v1），新系统拒收 | 换新一点的包版本 |
| 错误 -112 | **降级被拦**：要比已装版本号低 | 先卸载高版本，再装低版本（数据会清，先备份） |
| 错误 -110 / 空间不足 | 存储没地方了 | 清出空间再装 |

## 二、两大主因展开说

### 签名冲突（最常见）

同一个包名，系统要求前后两份包必须是**同一把签名证书**签的，否则视为「别的应用想冒名接管」，直接拒。图标一模一样也照样拦。

你会撞上的典型场景：从商店装了一份，又拿另一个渠道的同名包去覆盖 —— 必失败。处理顺序：

1. 在 My APK 里打开两份包的详情，**比签名与版本号**（见 [查看应用详细信息与启动隐藏界面.md](查看应用详细信息与启动隐藏界面.md) 第一节）；
2. 签名不同 → 决定留哪个：要换装，就先去系统设置里卸载旧的（数据会清，聊天记录之类先备份）；
3. 再装新包。重下同一个冲突包**不会**让签名变一致，别反复下。

### 降级被拦

系统不允许低版本号覆盖高版本号，报错往往也只有一句「应用未安装」，容易误判成文件坏了。判据：详情页里看两份包的版本号 —— 要装的这份**更低**就是降级问题，重下没用，先卸载高版本（或放弃降级）。你手里是网盘那份 2.9.0、手机上已装商店新版的话，装回去就会走到这条路。

## 三、用 My APK 缩小排查范围

装失败别急着换包重试，先在 My APK 里把三件事看清楚，能排掉一大半原因：

1. **版本号**：比已装的高还是低 → 排除/确认降级问题。
2. **签名**：与已装的那份一致吗 → 排除/确认签名冲突。
3. **完整性**：文件大小对不对、Hash Checker 算出的校验值与拿到的值一致吗 → 排除文件损坏。

这三步做完还失败，再看错误码是不是架构（ABI）或空间问题 —— 那两类属于「这个包不适配这台机器 / 机器没空间」，换包或清空间，不是操作错。

## 四、几条通用注意

- **卸载重装是双刃**：解决签名冲突与降级都靠它，但它会清空该应用的数据。先确认数据不要了再动手。
- **聊天工具传包容易坏事**：常见工具传文件会改名、截断，装上就报 -11 或损坏。传包用文件直传或数据线。
- **同一个错误别重复试三次**：重试只在「文件可能没下完整」这一种原因下有意义；签名、降级、架构这三类，重试多少次都一样。
