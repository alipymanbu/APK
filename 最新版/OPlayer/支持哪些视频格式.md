多数人挑播放器就是为了一件事：从网上存下来的文件，不用转码就能直接播。下面按官方列出的格式范围整理，并说明这些清单该怎么读 —— 光看容器后缀名，容易得出错误结论。

## 一、视频格式

| 类别 | 格式 |
| --- | --- |
| 主流容器 | MKV、MP4、M4V、AVI、MOV、3GP、FLV、WMV、TS、M2TS |
| 老格式与光盘类 | RMVB、RM、ASF、VOB、SWF、蓝光（BD）目录 |
| 编码相关 | DivX、Xvid、H.264、H.265（HEVC）、WebM |
| 分辨率 | 官方口径支持到 4K 超高清 |

## 二、音频格式

| 类别 | 格式 |
| --- | --- |
| 常见有损 | MP3、AAC、WMA、OGG Vorbis、AMR |
| 常见无损 | FLAC、APE、WAV |
| 多声道影视音轨 | DTS、AC3、EAC3 |
| 其他 | MIDI、CUE（配合整轨无损使用） |

音频不只是「听歌」用途：视频里的音轨用的就是这套编码。影视片源里的 AC3、DTS、EAC3 音轨是「有画面没声音」的高发区，处理方式见 [字幕加载与音轨切换.md](字幕加载与音轨切换.md)。

## 三、字幕格式

| 类别 | 格式 |
| --- | --- |
| 文本字幕 | SRT、ASS、SMI、SUB、TXT |
| 内嵌字幕 | 已封装进视频文件的字幕轨道，自动识别 |

文本字幕要放在与视频同目录、主名相同的路径下才会被自动挂上；图形类字幕（IDX + SUB 成对）需要两个文件都在。文件名匹配规则见 [字幕加载与音轨切换.md](字幕加载与音轨切换.md)。

## 四、网络流与共享协议

| 协议 | 典型用途 |
| --- | --- |
| HTTP / HTTPS | 直连媒体地址 |
| FTP | 连家里的 FTP 服务 |
| SMB（SAMBA） | 播电脑或 NAS 共享目录里的文件 |
| UPnP / DLNA | 自动发现局域网内的媒体服务器 |
| RTP / RTSP / MMS | 网络串流地址 |

局域网播放的完整配置步骤在 [局域网与NAS播放设置.md](局域网与NAS播放设置.md)。

## 五、这份格式清单该怎么读

**第一，容器和编码是两件事。** MKV 只是一个「盒子」，里面装的可能是 H.264，也可能是 H.265 —— 两种情况在低端机型上的表现完全不同。清单里写支持 MKV，指的是这个盒子能打开，不代表里面任何编码都流畅。

**第二，能播和播得流畅是两种结论。** 硬件解码依赖芯片支持的具体编码，芯片不支持时会退回软件解码。软件解码能出声出画，但高分辨率下会掉帧，同时耗电和发热明显上升。同样一部 H.265 4K 文件，在中端机上可能流畅、在几年前的老机器上只能一格一格走，这属于正常差异。

**第三，清单覆盖的是常见格式，不是全部。** 官方口径是「几乎所有的视频和音频格式」，但遇到冷门封装或冷门编码（例如某些专业摄像机导出的格式）仍然可能打不开。这类文件先用工具转成 H.264 加 MP4 容器，成功率最高。

**第四，老格式要留个预期。** RMVB 这类早期网络视频格式能播是能播，但片源本身分辨率普遍不高，别按高清的标准去要求画面。

## 六、判断某个文件能否直接播的步骤

1. **看后缀**：在上面的清单里能找到，基本可播；
2. **看编码**：用电脑上的媒体信息工具查一下视频与音频编码，重点确认音频是不是 AC3 / DTS / EAC3 这类；
3. **直接试播一分钟**：拖动进度条、切换音轨和字幕，都正常就说明这一份文件在你的这台设备上没问题。

连打开都失败时，先怀疑装错包：确认手机里那份安装包来自同一处（统一从 [OPlayer 安装文件资源（夸克网盘）](https://pan.quark.cn/s/96e8372920fa) 取用），避免不同包名线的版本混装后行为不一致。

只有一部片子出问题时，先按上面三步确认是文件本身的问题，再去看 [常见问题与排查.md](常见问题与排查.md)，避免把片源问题当成播放器故障来回折腾。
