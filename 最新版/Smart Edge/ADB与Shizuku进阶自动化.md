## 一、先说结论：大多数人用不到

Smart Edge 的核心功能（面板、手势、分屏、主题）只靠引导页那三项权限就能跑完，本套文档前面几篇讲的就是这些。本篇面向想再进一步的用户：官方功能清单里有一项 **System Automation（系统自动化）**，描述是「通过 ADB / Root 集成自动切换系统的多任务相关设置」；应用的权限清单里也确实声明了两项进阶权限 —— `WRITE_SECURE_SETTINGS`（写系统安全设置）与 **Shizuku** API 权限。这两样系统不会在设置界面里给普通用户开，只能通过下面的方式授予。

给自己手机上的应用授这两项权限属于正常的本机设置，不涉及别设备、别账号；不想折腾就跳过本篇，不影响任何日常用法。

## 二、它要这些权限干什么

按官方说明与应用声明的权限，用途对应关系是：

| 权限 | 干什么 | 不给会怎样 |
| --- | --- | --- |
| `WRITE_SECURE_SETTINGS` | 让应用能改系统级设置项（多任务相关开关） | 自动化类功能不生效；其余功能不受影响 |
| Shizuku API | 在无 Root 的情况下借 ADB 通道使用上述能力 | 同上 |

另外从权限清单还能看到它申请了「开机后启动」「忽略电池优化」等常规保活权限（不同版本权限数量略有差异，1.3.4 为 12 项，完整清单以 [F-Droid 页面](https://f-droid.org/packages/com.imi.smartedge.sidebar.panel/)当时显示为准）。

## 三、授予方式 A：电脑 ADB（最直接）

适合手边有电脑的用户，一次操作即可：

1. 手机开启「开发者选项 → USB 调试」，用数据线连电脑。
2. 电脑装好平台工具（Android SDK Platform-Tools），命令行执行：

```bash
adb devices                          # 确认手机已列出
adb shell pm grant com.imi.smartedge.sidebar.panel android.permission.WRITE_SECURE_SETTINGS
```

执行完无报错即授予成功。注意：**卸载重装后权限会回收**，要重新执行一次；命令里的包名照抄即可（`com.imi.smartedge.sidebar.panel`）。

## 四、授予方式 B：Shizuku（无电脑、无 Root）

不想开电脑就用 Shizuku —— 它通过「无线调试」配对在本机起一个 ADB 权限的服务，应用借它拿到同样的能力：

1. 装 Shizuku（F-Droid / Google Play 均有），手机开启开发者选项里的「无线调试」；
2. 在 Shizuku 里按提示完成配对并启动服务；
3. 通过 Shizuku 的授权入口把权限授给 Smart Edge（或在终端里执行与上面同一条 `pm grant` 命令，只是换成 Shizuku 的 shell 环境）。

两个注意点：

- **重启后服务会停**：Shizuku 的 ADB 服务默认不跨重启存活，重启手机后要么重新启动一次服务，要么在 Shizuku 设置里开启开机自启相关选项（部分方案需要额外配置，以 Shizuku 官方文档为准）。
- 各厂商对无线调试的限制不同，配对失败先确认开发者选项里的「停用 ADB 授权管理」没有被安全策略关掉。

## 五、Root 路线

Root 用户可以直接授予，一条 `su` 下的 `pm grant` 即可，不再赘述。但为一个侧边栏工具去 Root 不划算 —— Root 会带来解锁 Bootloader、支付环境检测等一连串代价，本篇只把它列作「存在这条路线」，不作推荐。

## 六、给完权限之后

回到 Smart Edge 的设置里，对应的功能开关才会真正生效（具体哪些开关依赖它，以应用内设置页当时显示为准 —— 官方在 1.3.6 才重整过交互设置的分组，新旧版本位置可能不同）。如果给了权限却不起作用，先按 [侧边栏不显示怎么排查.md](侧边栏不显示怎么排查.md) 确认服务本身还活着，再核对包名与版本（见 [版本更新与下载渠道.md](版本更新与下载渠道.md)）。
