## 一、九成问题在前两步就解决

电脑打不开 PlainApp 的页面时，按顺序过下面五条，别跳步 —— 官方故障排除指南的结论是多数问题止于第二步：

1. **手机上服务跑起来了吗？** 打开 PlainApp，确认状态是已启动、界面上显示着地址（`http://192.168.x.x:8080` 之类）。没启动就点「启动」；有报错就停一次再启。
2. **手机自己能打开吗？** 在手机浏览器里输入同一个地址。手机都打不开 → 是服务本身的问题，重启服务，不行就重装应用（安装包见 [下载与安装教程.md](下载与安装教程.md)）。
3. **两边在同一个 Wi-Fi 吗？** 手机不能挂着移动数据，电脑不能连着别的 Wi-Fi 或 VPN。这是最常见的翻车点。
4. **地址抄对了吗？** 照 PlainApp 界面上显示的**原样**输入，端口（`:8080` / `:8443`）不能省；给了多个地址就挨个试，包括 `plainapp.local`。
5. **弹证书警告了吗？** 「连接不是私密的」属于正常现象，点「高级」→「继续访问」，或改用 `http://` 地址。

## 二、用 ping 判断问题在哪一侧

五步走完还不行，在电脑上打开终端（Windows 用命令提示符或 PowerShell），执行：

```bash
ping 192.168.x.x
```

IP 用 PlainApp 界面显示的那个。结果分两种：

| 结果 | 结论 | 下一步 |
| --- | --- | --- |
| 有回复（`来自 192.168.x.x 的回复…`） | 电脑能碰到手机，问题在浏览器侧 | 换浏览器试、检查端口、处理证书警告 |
| 请求超时 / 无响应 | 两台设备根本不通 | 走下面第三、四节的网络项排查 |

## 三、网络层的四个常见原因

- **路由器开了 AP 隔离**：很多路由器（尤其访客网络）默认隔离互连设备。登录路由器管理页，关掉「AP 隔离 / 无线客户端隔离 / 访客网络隔离」这类选项。
- **手机和电脑不在同一网络**：比如手机连的是 5G、电脑连的是另一个访客 SSID，或电脑挂着 VPN 吞掉了局域网流量。统一到同一个 SSID、关掉 VPN 再试。
- **防火墙 / 安全软件拦截**：电脑上的防火墙、杀毒软件可能挡局域网访问，临时放行或加白后再测。
- **手机 IP 变了**：重启路由器后 DHCP 重新分配，旧地址就失效了 —— 回手机看 PlainApp 当前显示的地址，用新的。

## 四、特殊情形

- **`plainapp.local:8080` 打不开**：这个发现域名依赖局域网组播，部分路由器/系统不支持，直接改用 IP 地址即可，不算故障。
- **浏览器警告「不安全」**：自签名证书导致，处理见第一节第 5 条；介意的话全程用 `http://` 地址。
- **在外面想连家里的手机**：它的设计就是同一网络内访问，官方给的兜底方案是**开手机个人热点、让电脑连这个热点**，两台设备被拉进同一网络后照常访问。
- **镜像 / 投屏跟着一起失效**：镜像和 DLNA 发现走的也是这条局域网链路，网络通了它们自然恢复，入口见 [屏幕镜像与电视投屏.md](屏幕镜像与电视投屏.md)。
- **亮屏正常、锁屏后才断**：这不是网络问题，是系统省电把后台服务杀了 —— 处理办法见 [锁屏后断开与后台保活设置.md](锁屏后断开与后台保活设置.md)。

## 五、还不行的兜底顺序

1. 手机上停掉服务再启动一次；
2. 重启路由器；
3. 电脑换个浏览器；
4. 换一台设备（另一部手机或平板）连一次，用来判断是手机侧还是电脑侧的问题；
5. 用手机热点法（上一节）绕开路由器问题。

以上都试过仍打不开，就到 [官方故障排除指南](https://plainapp.app/zh/docs/troubleshooting) 对照更细的条目，或去 [GitHub Issues](https://github.com/plainhub/plain-app/issues) 反馈。连接恢复正常后，从 [电脑浏览器连接教程.md](电脑浏览器连接教程.md) 继续开始使用。
