## 一、触发器：决定什么时候执行

官方口径是数十种触发条件。常用的有这些：

| 触发器 | 典型用法 |
| --- | --- |
| 定时 | 每天固定时间执行打卡、提醒类流程 |
| 打开指定应用时 | 进入某应用后自动做一串操作 |
| 按下某按键时 | 把音量键当快捷键用（新版本支持音量上＋下同时按触发） |
| 收到短信 / 通知时 | 验证码转发、重要消息提醒 |
| 屏幕点亮 / 熄灭 / 解锁 / 锁定 | 开屏自动亮码、锁屏自动执行收尾动作 |
| 到达指定位置时 | 到家自动执行一串动作 |
| 设备姿态改变 | 手机放上桌面、背面朝上、装进支架时触发（较新版本加入，支持录制重力数据） |
| 敲击屏幕 / 敲击侧面 | 敲两下手机执行脚本（较新版本加入） |

注意：标了「较新版本加入」的项来自官方 1.3.x 的更新日志，你手里如果是老版本（比如 1.1.9），触发器列表里没有就是还没有，以应用内实际可选列表为准。另外，定时触发在部分机型上有延迟（官方 1.3.6 更新日志修复了这一问题），老版本用户遇到「到点不跑」可以先怀疑这一点，排查见 [脚本不触发排查指南.md](脚本不触发排查指南.md)。

## 二、动作指令：决定执行什么

官方口径是上百种动作指令，可以自由排列组合。按用途归成几类：

| 类别 | 常用动作 |
| --- | --- |
| 应用 | 启动应用（较新版本可选小窗模式启动） |
| 屏幕 | 点击、滑动、等待、屏幕内容拾取、操作屏幕控件（较新版本） |
| 输入 | 输入文本 |
| 系统 | 执行 Shell 命令、设置亮度、获取系统属性（较新版本） |
| 通知与消息 | 发送通知、发短信、读取短信 |
| 文件 | 读取 / 写入文件、发送文件（较新版本） |
| 媒体 | 录音、语音识别 |
| 逻辑 | 条件判断、执行分支、变量传值、数学计算 |

没标版本标注的是基础能力，标了的以你手上的版本为准。每一类下细分动作有多少，以动作选择器里的实际列表为准——官方更新日志里「优化动作分类」「优化动作选择器」出现频率不低，这份清单一直在变。

## 三、拼组合的几个思路

- **先手动后自动**：一条流程先不设触发器手动跑通，再挂触发器；
- **等待是粘合剂**：凡是要等页面、等网络的动作之间都插一个等待，宁可多等一秒；
- **权限提前开**：动作里用到了短信、位置、麦克风，先把对应权限开了（对照 [首次启动权限设置.md](首次启动权限设置.md) 的按需权限表）；
- **别人的成熟脚本先拆开看**：仓库里的现成脚本就是组合范例，下载一个同场景的，看它的动作顺序与参数怎么配（用法见 [自动化仓库与社区用法.md](自动化仓库与社区用法.md)）。
