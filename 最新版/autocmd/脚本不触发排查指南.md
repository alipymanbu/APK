# AutoCMD+ 脚本不触发排查指南

> 脚本建好了却不自动执行，多半不是脚本写错，而是权限、后台或机型在作怪。本篇按「先权限、再后台、后脚本」的顺序排一遍。

## 一、先分清三种「不触发」

- 手动运行也失败 → 多半是权限掉了，或动作参数有问题；
- 手动能跑、挂上触发器就不跑 → 权限、后台或触发条件没配对；
- 以前能跑、某天突然不跑 → 大概率是无障碍服务被系统收回，或后台被清理。

对号入座之后，按下面三节排查。

## 二、权限掉了：开关看着开着，服务已经停了

最隐蔽的一种：无障碍开关显示「开」，但服务实际已被系统停止——表现为定时任务不发、点击没反应。这是安卓系统对无障碍类服务的管理行为，厂商官方文档普遍确认该现象（华为官方支持页就专门列了「第三方应用的无障碍开关自动关闭」这一条）。处理顺序：

1. 设置里搜「无障碍」，找到 AutoCMD+ 的服务，**关一次再开**——多数情况这一步就恢复；
2. 给应用加锁：多任务界面里对 AutoCMD+ 的卡片加锁（华为是下拉卡片出锁形图标；其他品牌入口各异，找不到就跳过）；
3. 改启动管理：手机管家里的「应用启动管理」把 AutoCMD+ 改为手动管理，打开允许自启动、允许关联启动、允许后台活动（华为口径，其他品牌对应各自的「自启动管理」）；
4. 电池优化白名单：设置 → 应用 → AutoCMD+ → 电池，选「不受限制」或「无限制」。

还是反复掉线？还有两个少见但要排除的来源：有用户反馈部分银行类应用使用后会关闭无障碍服务（单一来源，未必所有机型如此）；多个应用同时占用无障碍时可能互相冲突——把其他自动化 / 点击类应用的无障碍关掉、只留 AutoCMD+ 试一次。

## 三、后台被杀与机型差异

- 国产 ROM 清后台最凶：锁屏充一夜电、早上定时任务没跑，基本是夜间清理干的。把上面第 2、3、4 步做完基本能压住；
- 部分机型存在「定时触发延迟」「应用列表为空」的问题——官方在 1.3.6 的更新日志里修复了这两项，反过来说明老版本在部分设备上真实存在这些问题。你手里的版本旧、又命中这类机型，升级新版本是一条出路；
- 锁屏后不触发：在电池与权限管理里允许「锁屏运行」（各品牌叫法不同，通常在电池或应用行为管理里）。

## 四、脚本本身的问题

权限、后台都正常还不跑，回头看脚本：

1. 打开运行日志，找最后一条成功执行的动作，它后面那条就是卡点；
2. 卡在点击类动作 → 坐标写死、换设备后点偏。用按控件选择的动作替代裸坐标更稳（较新版本提供按控件操作的指令）；
3. 卡在启动应用之后 → 页面还没加载完就执行了下一个动作，在中间插入更长的等待；
4. 触发条件从来没满足过 → 打开触发器设置核对一遍，比如「打开指定应用时」里选的应用名对不对、定时的时间与重复规则是不是你以为的那样。
