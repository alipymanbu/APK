## 一、什么人需要自建

官方在线服务（网页端 [desk.hsslive.cn](https://desk.hsslive.cn)）开箱能用，普通个人用户不需要自建。要动这个念头的通常是两类：

- 流量不想经过别人的服务器，希望信令与中继都落在自己的机器上；
- 要统一管一批设备（比如家里几台电脑、一台常开机的 NAS），需要后台管理界面。

## 二、自建要准备哪些组件

服务端与后台都是独立的开源仓库，各起一个服务：

| 组件 | 仓库 | 作用 |
| --- | --- | --- |
| 服务端 | [billd-desk-server](https://github.com/galaxy-s10/billd-desk-server) | 信令、中继等后端逻辑 |
| 管理后台 | [billd-desk-admin](https://github.com/galaxy-s10/billd-desk-admin) | 设备与用户的后台管理 |
| 客户端 | [billd-desk](https://github.com/galaxy-s10/billd-desk)（网页/电脑）· [billd-desk-flutter](https://github.com/galaxy-s10/billd-desk-flutter)（安卓） | 连到自己的服务端 |

按官方说明，v1.0.0 起支持 Docker 一键部署与私有化部署；部署步骤以各仓库 README 为准——这个项目文档常常滞后于代码，README 里没写清的去 issue 区翻，别自己硬猜配置。

## 三、客户端里改哪些地址

客户端支持自定义接口，共三类：API 地址、WebSocket（wws）地址、中继服务器地址。都在客户端的设置项里，把默认指向换成你自己服务器的域名或 IP 即可；安卓端入口的具体位置以你手上的版本界面为准。

改完做一次完整验证，三步各验一层：

1. 两端都填新地址后能走到「输入连接密码」——说明信令（API / WebSocket）通了；
2. 能看到对方画面——说明打洞或中继通了；
3. 能点击操作——说明控制链路完整。

哪一步卡住，就说明对应那一层没配对，回到上一步检查地址与端口。

## 四、自建前想清楚的三件事

1. **版本配套**：客户端与服务端必须一起升级，这个项目新旧版本不兼容是常态，升级前先看仓库的更新说明。
2. **稳定性预期**：官方自己标注「未发布稳定版，不建议用于生产环境」。自己折腾没问题，铺给同事用就要想清楚出问题了谁兜底。
3. **Pro 版的边界**：官方另有一个不开源的 BilldDeskPro，重写旧架构、修复了权限与控制两个已知问题，普通用户免费用、源码付费订阅，差异对比见[官网价格页](https://desk.hsslive.cn/#/price)。如果你的核心诉求恰好是被控端权限稳定，先看看 Pro 免费版能不能满足，再决定要不要自建开源版。
