## 一、宏能帮你省掉什么

调试蓝牙设备时经常有一套固定动作：连接 → 订阅某特征 → 写一段数据 → 等回复 → 断开。手动每次点十几下，测十轮就烦了。宏（Macro）就是把这个序列录下来，之后一键回放。

宏功能从 4.4.0 版本起提供，你装的是 4.28.0，自然包含。主界面进入宏（Macro）页签就能用。

## 二、录制一个宏

1. 进宏页签，新建一个宏，开始录制。
2. 像平时一样操作：扫描、连接、读、写、订阅——每一步都会被记进宏里。
3. 停止录制，给宏起个名字保存。

回放时选这个宏点播放，它会自动把整个序列跑一遍。回放不是死板复刻：你可以在宏的步骤列表里编辑参数（比如把每次写入的数据改一下）、在步骤之间加延时、加循环次数。

宏可以导出成 XML 文件分享给同事，也可以把别人给的 XML 导进来直接用。批量产线或多人调试时，标准流程统一成一份 XML 会省很多口头沟通。

## 三、用 XML 脚本做自动化测试

宏是「人在手机上点」，自动化测试则更进一步：把测试场景写成 XML 脚本，由脚本驱动手机上的 nRF Connect 去跑，适合做**稳定性测试和压力测试**——比如让设备连续连接断开几百次、反复读写特征看有没有丢包或掉线。

官方文档里给了可下载的示例 XML（HRM-DFU、HRM-Scanning 两个样例），里面同时带全套可用指令的说明，照着改就是自己的用例。文档随应用一起挂在 Nordic 官方的 [Android-nRF-Connect 仓库](https://github.com/NordicSemiconductor/Android-nRF-Connect) 里，进仓库看 documentation 部分即可。脚本结构大致是：

```xml
<test>
  <set name="DEVICE_NAME" value="MyDevice" />
  <!-- 扫描、连接、读写、断开等步骤按顺序排列 -->
</test>
```

执行方式：

1. 把 XML 和官方提供的 `test.bat` 复制到电脑上。
2. 手机开 USB 调试、连电脑，确认 `adb` 能识别设备。
3. 运行：

   ```bat
   test.bat [-d device_id] [-E KEY EXTRA]* test.xml
   ```

   `-d` 用来指定多台手机中的哪一台；`-E` 可以在命令行传键值对，脚本里用 `${KEY}` 引用，同一个 XML 就能跑不同参数。
4. 测试结果在手机端和脚本输出里都能看到。

两个限制要知道：

- 官方只提供了 Windows 的批处理脚本，Mac 和 Linux 需要自己把 `test.bat` 里的命令换成本平台的 `adb` 调用，命令本身是一样的。
- 脚本里能用的指令集以官方示例 XML 里带的文档为准，不同版本的应用支持的指令略有差别。

## 四、压力测试的实用建议

- **从小循环开始**：先跑 10 次连接/断开确认脚本没问题，再放大到几百次，避免脚本本身有错导致整夜白跑。
- **盯日志**：测试时开着日志记录（需要 nRF Logger），掉线、报错的时间点都留在里面，比事后猜强。
- **控制变量**：测稳定性时把手机放固定位置、设备固定供电，无线环境一变，结果就没法对比了。
- **区分偶发与必现**：偶发掉一次线不代表有问题，连续多轮都在同一步骤断，才值得去查固件。

宏和脚本跑起来后，如果设备固件本身要升级，走的是另一条路——DFU 无线升级，见 [DFU固件无线升级教程.md](DFU固件无线升级教程.md)。操作中碰到扫描异常、权限问题，先翻 [常见问题与使用技巧.md](常见问题与使用技巧.md)；还没装应用的话从 [下载与安装教程.md](下载与安装教程.md) 开始。
