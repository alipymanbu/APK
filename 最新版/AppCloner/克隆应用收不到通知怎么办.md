# 克隆应用收不到通知怎么办

> 克隆装好了、消息却收不到，多半不是克隆坏了，而是后台进程被系统杀掉了。本篇按代价从小到大给处理顺序：电池白名单、自启动、克隆选项，最后说清哪些情况修不好。

## 一、先弄清是哪种「收不到」

克隆应用收不到通知（尤其退到后台之后），先分两种情况：

- **前台能收、退后台就丢**：推送靠后台常驻进程，进程被系统的省电/内存策略杀掉了，通知自然断。这是最常见的情况，能救，看下面几节。
- **前台也永远收不到**：部分应用的推送机制绑定原签名证书或包名，克隆后推送通道本身就断了，官方博客举的例子是 Skype。这类没有修复办法，直接跳到第五节确认。

## 二、把克隆加进电池白名单（官方步骤）

1. 在 App Cloner 的 **Cloned apps** 标签里，打开对应克隆的上下文菜单。
2. 选 **Show app info**（显示应用信息）。
3. 进 **App battery usage**（应用电池用量），选 **Unrestricted**（不受限制）。

想在生成克隆时就自动处理：克隆设置里打开 Launching 选项组的 **Request ignore battery optimizations**，克隆装好后会自动弹窗请求加入电池优化白名单。

克隆装得多、逐个点太麻烦的话，有 ADB 环境可以直接批量操作白名单：

```bash
# 加入白名单（加号紧跟包名，中间不能有空格）
adb shell dumpsys deviceidle whitelist +<克隆包名>

# 移出白名单（换成减号）
adb shell dumpsys deviceidle whitelist -<克隆包名>

# 查看当前白名单里有哪些应用
adb shell dumpsys deviceidle whitelist
```

## 三、国产 ROM 还要多开两处

电池白名单之外，国产系统的后台管理更细，常见还要动这两处（菜单名各品牌不同，以你手机的实际设置为准）：

- **自启动**：在应用信息页给克隆打开自启动开关；部分系统上还要给 App Cloner 本体也开。
- **省电策略**：把克隆的省电策略改成「无限制 / 不限制」，别停留在「智能限制」。

这两项不开的话，克隆退到后台几分钟就会被杀 —— 这也是「刚装好能收到消息、过两天又收不到」这类时好时坏现象的常见原因。

## 四、用克隆选项自救

上面不够用时，官方在克隆设置里还留了几手：

- **Persistent app**（持久应用）：把克隆标记为常驻，降低被杀概率。克隆多的时候会占内存、拖慢整机，酌情开。
- **Manifest 克隆模式**：媒体播放类通知的按钮（播放/暂停/切歌）失效时，改用 Manifest 模式重新克隆 —— 对部分应用无效，官方点名 Spotify。
- **User-Agent workaround**：官方说明对部分应用的通知也有效果，当最后一试的选项。

改完任何一项都要重新克隆并覆盖安装才生效，流程见[克隆应用完整步骤.md](克隆应用完整步骤.md)第三节。

## 五、确认修不好的情况

推送绑定原签名证书或包名的应用（官方举例 Skype），克隆后通知就是收不到，调什么设置都没用。判断办法：

- 前台开着能收、退后台就丢 → 走上面几节，能救；
- 前台也永远收不到 → 大概率属于此类，这个应用别指望克隆版替你收消息，重要通知留在原应用上看。

顺带一提：这也解释了为什么这类克隆「消息要打开才刷新」—— 没有推送通道，只能靠打开应用时拉取。

## 六、通知能收但不想要

克隆设置里的通知选项做的是反向的事：Notification filter（过滤指定通知）、Quiet time（免打扰时段）、改通知声音与震动、调整通知优先级与可见性等。与其在系统层面一刀切关通知，不如在克隆层面留下有用的、挡掉吵的。
