# Stellar 与 Shizuku 的区别和兼容性

> Stellar 是 Shizuku 的深度定制分支。本篇讲它相对原版移除、新增、重新启用了什么，兼容层怎么工作，以及你该选哪个。已经决定换用、只想看操作的话直接去 [无线调试激活与配对教程.md](无线调试激活与配对教程.md)。

## 一、两者是什么关系

Shizuku 是知名的开源特权 API 框架：用 ADB 或 Root 拉起一个高权限服务，普通应用借它调用系统级 API，不用自己拿 Root。Stellar 在此基础上做了深度定制，项目开源在 GitHub（仓库 `https://github.com/roro2239/Stellar`），代码以 Kotlin 重写。

对使用者来说，两者的核心使用逻辑一样：开服务 > 授权应用 > 应用里用。差别集中在权限管得多细、驻留能力、以及一些 API 的取舍上。

## 二、移除了什么

- **rish**：Shizuku 内置的 root shell 工具，Stellar 不带；
- **Sui**：对 Zygisk-Sui 的 API 支持被移除。

用不到这两样的普通用户不受影响；依赖 rish 写脚本的进阶用户需要留意。

## 三、新增了什么

- **细分权限系统**：不再是一个权限管全部，授权可以按类型给（核心 API 访问、伴随启动等），具体条目见 [应用授权与快捷命令怎么用.md](应用授权与快捷命令怎么用.md)；
- **一次性授权**：授权只对当次生效，适合试一个不熟悉的应用；
- **跟随启动机制**：应用可注册为服务的伴随进程，服务启动时一起唤醒；
- **降权激活**：Root 启动后可降权到 Shell 用户运行，减少特权暴露。

## 四、重新启用了什么

Shizuku 新版本标记弃用的两个功能，Stellar 保留支持：

- `newProcess()` API——直接创建特权进程；
- 运行时权限授予/撤销——通过 `grantRuntimePermission()` / `revokeRuntimePermission()` 给其他应用授予或收回运行时权限。

某些仍在调用这些旧接口的应用（或你自己写的工具），在 Shizuku 上可能已经拿不到预期行为，在 Stellar 上可以继续用。

## 五、兼容层怎么工作

Stellar 内置 Shizuku 兼容层，**默认开启**：

- 使用 Shizuku API 的现有应用无需任何改动，直接连 Stellar 的服务用；
- 兼容层会自动拒绝来自 Shizuku Manager 本体的请求，避免两套管理器互相干扰；
- 设置里有「Shizuku 兼容」开关，没有特殊理由不用去动它。

也就是说，MT 文件管理器这类 Shizuku 生态应用，换到 Stellar 后使用流程不变：应用里触发操作 > 授权框确认。哪些应用值得接过来、各自的权限边界，见 [适合搭配的Shizuku应用.md](适合搭配的Shizuku应用.md)。

## 六、怎么选

| 你的情况 | 建议 |
| --- | --- |
| 已经用着一堆 Shizuku 应用，想试试细分权限、一次性授权 | Stellar 可以平滑替换，兼容层兜底 |
| 依赖 rish 脚本或 Zygisk-Sui | 留在原版 Shizuku |
| 在意服务驻留（跟随启动、Root 降权） | Stellar 多了这几项手段 |
| 想跟随上游最新特性与文档 | 原版 Shizuku 更新更勤，生态文档更全 |

两者可以共存安装，但管理授权这件事交给一个就好；同时都开着服务时，注意别把同一批应用授权搞混。装完 Stellar 之后从哪里开始配置，见 [下载与安装教程.md](下载与安装教程.md)。
