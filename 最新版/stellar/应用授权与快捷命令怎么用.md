# Stellar 应用授权与快捷命令怎么用

## 一、给应用授权

在「授权应用」页面能看到已授权应用列表。给一个应用授权的时机通常不是在 Stellar 里主动找它，而是：**先在那个应用里触发需要高权限的操作**，它弹出授权框时，你再到 Stellar 里确认。

授权时分两种类型：

- **永久授权**：授一次，之后该应用一直能调用服务（直到你撤销，或服务重启后需要重新确认的场景）；
- **一次性授权**：只对当次操作生效，下次再触发要重新批。

拿不准就用一次性授权试——先让操作跑通，确认这个应用行为正常，再改成永久授权。想收回时到授权列表里撤销即可，权限可视化展示能让你看清每个应用拿到的是哪几项。

## 二、授权时看到的两个权限名

Stellar 把权限拆得比原版框架更细，授权页你可能遇到这两个名字：

| 权限 | 给了它能干什么 |
| --- | --- |
| `stellar` | 核心 API 访问权限，调用服务提供的基础能力 |
| `follow_stellar_startup` | 服务伴随启动权限，应用跟着服务一起被唤醒 |

第一条是绝大多数应用要的；第二条是给那些「希望服务启动时自己也跟着启动」的应用准备的。授权框里出现别的细分项时，看清楚再勾，不需要的可以不给。

## 三、给 Shizuku 生态的应用用

Stellar 内置 Shizuku 兼容层（默认开启），所以 MT 文件管理器这类原本要 Shizuku 的应用，不需要改任何东西就能直接用 Stellar 的服务：应用里触发操作 > 弹出授权框 > 确认，流程与用 Shizuku 时一致。兼容层可以在设置里关掉，但没有特殊理由不必关。

一个注意点：兼容层会自动拒绝来自 Shizuku Manager 本体的请求，避免两个管理器打架。所以如果你设备上同时装着 Shizuku Manager，管应用授权这件事交给其中一个就好，别两头都插手。哪些应用值得授权、每类能干什么，见 [适合搭配的Shizuku应用.md](适合搭配的Shizuku应用.md)；两套框架的取舍分析见 [与Shizuku的区别和兼容性.md](与Shizuku的区别和兼容性.md)。

## 四、授权前后的把关

这类权限高过普通应用权限，给谁、留多久值得花十秒钟过一遍：

- **看来源再授权**：只从官方仓库、官方商店等可靠渠道装应用；来路不明的应用不给永久授权；
- **先一次性、后永久**：拿不准的应用先用一次性授权跑通，观察行为正常再换永久；
- **用完就撤**：不再用的应用随手到授权列表里撤销，高权限留着就是风险面；
- **高危动作留退路**：改系统设置、停用应用之前记下原值；停用优先于卸载，改坏了重启也能救。

## 五、快捷命令

「命令」页面用来保存和快速执行特权命令：把常用的命令建好，之后进页面点一下就执行，不用每次手敲。

- 新建命令时填好命令内容，命名用一个自己看得懂的名字；
- 执行结果会在界面上回显，跑完可以核对输出；
- 想清理某条不再用的命令，长按或进编辑入口删除（入口位置以你手上的版本界面为准）。

这个页面适合放那些你已经验证过、会反复用的命令；不熟悉的命令别在这里乱试，服务拿到的是 Shell 级权限，误操作同样会影响系统设置。

## 六、让服务少被打断

授权和命令都依赖服务在跑，几个减少中断的做法：

- 应用列表里把 Stellar 排出电池优化（部分系统叫「允许后台活动」）；
- 经常用的授权对象考虑注册为伴随启动——服务醒来它也醒，省得你手动重开；
- 每次重启手机后记得回 Stellar 拉起服务，这一步目前没有免手动的方式（Root 设备的例外见 [无线调试激活与配对教程.md](无线调试激活与配对教程.md)）。

授权后应用仍然提示不可用的情况，多数是服务停了而不是授权丢了，逐项排查见 [常见问题与故障排查.md](常见问题与故障排查.md)。
