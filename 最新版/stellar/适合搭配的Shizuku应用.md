## 一、先说权限边界

Stellar 通过兼容层接住整个 Shizuku 生态，所以「支持 Shizuku 的应用」基本都能直接用。但这类框架给到的是 **ADB/Shell 级权限**，不等于 Root，能力上有明确的上下限：

- 能做：读写受保护的系统设置（`Settings.Global/Secure/System`）、给应用授予或收回运行时权限、停用或冻结应用、以特权身份执行命令；
- 不能做：写系统分区、访问 `/data/data/` 下的应用私有数据、彻底删除预装应用的系统分区文件——这些要 Root。

对应的实际表现：无 Root 时「卸载预装应用」类工具多数是**停用/冻结**（图标消失、不再运行、存储占着），真要彻底清掉系统分区文件只有 Root 做得到。

## 二、按用途分类的常见搭配

| 用途 | 代表应用 | 授权后能干什么 |
| --- | --- | --- |
| 处理预装应用 | Canta、Hail、冰箱（Ice Box） | 停用/冻结厂商预装、恢复被停用的应用 |
| 权限管理 | App Ops | 按应用细粒度查看与撤销权限，含系统层权限 |
| 备份还原 | Swift Backup | Android 11+ 访问 Android/data、批量还原应用 |
| 主题定制 | DarQ、zFont 3 | 按应用强制深色模式、替换系统字体 |
| 系统设置修改 | SetEdit、System UI Tuner | 读写设置表里普通界面摸不到的条目 |
| 手势与交互 | Tap, Tap | 移植背敲手势等系统级交互 |

这张表只列「常见且口碑稳定」的几类；同一类里选哪个看个人习惯，互相之间不冲突。

## 三、去哪找全量清单

社区维护的 [awesome-shizuku](https://github.com/timschneeb/awesome-shizuku) 仓库收录了几十款支持 Shizuku 的应用，按「定制与系统控制 / 应用与包管理 / 网络与隐私 / 电源管理」等分类整理，每款都标注了开源协议和它拿 Shizuku 权限做什么，另有中文版 README。清单持续更新，以仓库当前内容为准。

挑的时候看两处：一是「Key Shizuku Use」一列，确认它要的权限用途你能接受；二是开源协议栏，优先选开源可审计的。

## 四、授权前的把关

给一个应用授高权限之前，按这个顺序过一遍：

1. **看来源**：只从官方仓库、官方商店或可靠渠道装；来路不明的「功能特别强」的应用不给永久授权；
2. **先试一次性授权**：Stellar 支持一次性授权，陌生应用第一次用先给一次性的，行为正常再换永久；
3. **用完就撤**：不再用的应用随手到授权列表里撤销——高权限留着就是风险面；
4. **高危动作想一步**：改系统设置表、停用系统应用这类操作，执行前确认自己知道怎么恢复（比如记下原值，或优先选「停用」而不是「卸载」，改坏了重启也能救回来）。

授权与撤销的具体操作见 [应用授权与快捷命令怎么用.md](应用授权与快捷命令怎么用.md)。

## 五、接不上时的检查顺序

生态应用里偶尔有「提示需要 Shizuku 但连不上」的情况，多半不是应用不兼容，而是状态问题：服务没在跑、应用没被授权、或者设备上同时装着 Shizuku Manager 造成混淆。按 [常见问题与故障排查.md](常见问题与故障排查.md) 第三节的顺序排查，再回来看 [与Shizuku的区别和兼容性.md](与Shizuku的区别和兼容性.md) 里兼容层的那两条注意点。
