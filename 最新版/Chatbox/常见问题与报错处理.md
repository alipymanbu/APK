Chatbox 的问题大多不在应用本身，而在它背后连的模型服务：报错原文通常直接来自 OpenAI、DeepSeek 这些提供方的接口。本篇按报错场景归类，每条都给出对应的排查动作，先看报错原文属于哪一类，再照做。

## 一、API Key 无法使用

报错指向 Key 无效（如 `invalid api key`、`401`）时，按顺序核对：

1. 在提供方后台确认 Key 还在、未被删除或吊销；
2. 确认账户有可用余额 —— 有 Key 但账户欠费，请求同样被拒；
3. 确认粘贴的 Key 完整：前后有没有带空格、有没有漏掉结尾几个字符；
4. Key 确认失效就在后台重新生成一个，旧 Key 作废不影响新 Key。

## 二、提示额度不足

两类「额度」要分清，处理方式完全不同：

| 报错来自 | 原因 | 处理 |
| --- | --- | --- |
| Chatbox AI（登录账号路线） | 免费额度当日用尽，或套餐到期 | 等次日额度刷新、订阅套餐，或改用自带 Key 路线 |
| OpenAI 等提供方（自带 Key 路线） | 平台账户余额不足 | 到该平台的 Usage/Billing 页面查用量并充值 |

免费档是每日重置的 10,000 计算点数，用完当天只能等第二天，各付费档的额度量见 [免费额度与订阅套餐.md](免费额度与订阅套餐.md)。OpenAI 用户建议同时在后台设置每月用量上限（usage limit），避免跑大量长对话时账单失控。

## 三、网络连接问题

报错含 `connection`、`timeout`、`fetch failed` 这类字样，多半是设备到模型接口之间的链路不通：

1. 先确认要访问的接口本身在你的网络里是否可达（OpenAI 的 `api.openai.com` 在大陆网络通常不可直连）；
2. 若依赖代理，检查系统代理是否生效，或在 Chatbox 设置里单独配置代理；
3. 换一个网络环境（如切换 Wi-Fi / 流量）再试，排除是当前网络的限制；
4. 用第三方中转服务的，确认 API 主机拼写无误、服务本身在线。

网络类报错与 Key 无关，反复重新粘贴 Key 没有意义，先解决链路。

## 四、响应速度慢

回复迟迟不出字或一字一顿，通常有三个来源，按影响从大到小：

1. **模型本身慢**：推理型模型生成本来就慢，换同家的轻量模型（mini / flash 档）对比一下就知道；
2. **上下文太长**：一个对话塞了几百条消息，每轮都要把上下文发给模型，新建对话会明显变快；
3. **网络延迟**：链路绕行或代理不稳，按第三节排查。

## 五、装到的应用不对 / 商店同名应用

官方自己提示过：应用商店搜「Chatbox」会出现同名的其他应用。辨认办法：

- 安卓优先从官网下载页或本文网盘资源拿 APK 直装，绕开商店搜索；
- 装完核对应用名与开发者信息，与官网标注一致再登录账号或填 Key；
- 已经装到山寨应用并填过 Key 的，立刻去对应平台把 Key 作废重生成。

安装阶段的「解析包错误」「签名冲突」等提示的处理，见 [下载与安装教程.md](下载与安装教程.md)。

## 六、卸载或换机之前

聊天记录只存在本地，卸载、恢复出厂、换手机都会把它带走且无法从服务器找回。动手前先在「设置 → 数据管理」里导出一份 JSON，到新设备再导入，完整步骤见 [聊天记录备份与迁移.md](聊天记录备份与迁移.md)。

## 七、报错原文在哪里看

对话界面报错一般是摘要，完整报错可以在该条消息的错误详情里展开。找模型提供方客服或查资料时，把完整报错原文（含错误码）一起带上，定位效率高得多；错误码与「一、二、三」节的对应关系记住一条就够：`401/403` 找 Key，`429` 找额度与限频，`5xx` 与超时找网络。
