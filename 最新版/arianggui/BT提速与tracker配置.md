# BT 下载提速与 tracker 配置

> BT 的速度取决于有多少在线节点在给你传数据。本篇讲没速度时的完整排查：tracker 列表怎么加、DHT 为什么要等、什么情况属于资源本身没救。添加任务的步骤见 [磁力与BT下载指南.md](磁力与BT下载指南.md)，挂机保活见 [后台下载保活设置.md](后台下载保活设置.md)，其他报错见 [常见问题排查.md](常见问题排查.md)。

## 一、先弄清楚速度从哪来

BT 下载没有「服务器带宽」这个概念，速度 = 所有愿意传给你数据的节点之和。应用通过两条途径找人：

- **tracker**：每个种子内置的协调服务器，告诉你「谁也在下这个文件」；
- **DHT 网络**：不依赖任何服务器的分布式节点网络，冷门资源、内置 tracker 失效时的兜底。

所以「没速度」本质上就是「没找到人」。下面每一步都在解决找人的问题，按顺序做。

## 二、第一查：资源还有没有人

点开任务详情看连接节点（peers）与健康度：

| 观察结果 | 结论 |
| --- | --- |
| 节点数为 0，做种为 0 | 资源已死，加多少 tracker 都没用，换源 |
| 有节点但速度 0 | 对方没给你传（可能限速或互相不可达），继续往下排查 |
| 一直卡在「获取元数据」 | DHT 还没找到持有种子信息的人，等 3~5 分钟，仍不行按第四节处理 |

这一步能省掉后面所有折腾——死资源没有提速手段。

## 三、追加 tracker 列表

种子内置的 tracker 可能失效或被墙，追加一批公共 tracker 能明显提高找到节点的机会。

**列表来源**：`https://github.com/ngosang/trackerslist` 是公开维护的 tracker 汇总项目，几乎每天更新，里面有按协议分类的多个列表，`trackers_all` 是全量版。列表地址与内容会随时间变化，以项目页面当时提供的为准。

**怎么加**：在应用的 aria2 设置里找到 `bt-tracker` 选项，把列表里的地址用**英文逗号**连成一串填进去，格式示意：

```text
bt-tracker=udp://tracker-a.example.com:6969/announce,https://tracker-b.example.org/announce
```

（上面的域名只是格式示意，实际内容从你取到的列表里复制。）改完不需要重启任务，下一个 announce 周期生效。

**PT 任务例外**：PT 站的种子自带私有标记，追加公共 tracker 既无意义又可能违反站点规则，PT 保持默认、遵守站点要求即可。

## 四、给 DHT 一点时间，并确认它开着

DHT 找人是靠节点间互相介绍，刚启动应用或刚加任务时它手里几乎没有节点信息，**前几分钟速度为 0 是正常的**。它跑得越久、下载过的任务越多，节点缓存越丰富，冷门资源起速越快。

如果任务卡元数据超过 10 分钟：换个网络环境（比如换 Wi-Fi 或用流量）重试一次——部分网络会拦截 DHT 所需的 UDP 流量，拦截时 DHT 完全失效，这是少数换个环境就立竿见影的情况。

## 五、端口与网络环境的门槛

- **端口**：BT 需要外部节点能主动连入你，aria2 默认监听端口为 BT 的 `51413` 与 DHT 的 `6881-6999`（可在设置里改）。aria2 没有自动端口映射功能，路由器环境下想完全「可连入」需要在路由器上手动做端口转发，动手门槛较高；不做也能下，只是会漏掉一部分同样不可连入的节点。
- **运营商 / 校园网限制**：不少校园网和部分宽带对 P2P 流量限速甚至阻断，表现为一切 BT 任务都没速度而直链正常。换个网络对比一次即可判断。
- **流量计费网络**：BT 上传与下载同样消耗流量，用移动数据挂机前想清楚套餐余量。

## 六、以上都做了还是慢

那就到了收益递减的地方：节点少、对方慢、传输链路差，三者叠加出来的慢，客户端侧无解。最后两个务实的选项：

1. 同一资源找直链版或网盘版替代；
2. 挂机等——BT 任务不会因为暂时慢而坏掉，配合 [后台下载保活设置.md](后台下载保活设置.md) 让它整夜挂着，冷门资源常见的曲线是「几小时后突然起速」。

任务反复报错而不是单纯慢的话，回到 [常见问题排查.md](常见问题排查.md) 对号入座。
