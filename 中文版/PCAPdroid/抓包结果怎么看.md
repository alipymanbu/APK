## 一、四个标签页分工

抓包跑起来之后，你要看的东西分四处放：

| 标签页 | 看什么 | 典型场景 |
| --- | --- | --- |
| Status（状态） | 抓没在跑、当前导出模式、流量与连接计数、应用过滤器（App Filter） | 开始/停止前确认设置 |
| Connections（连接） | 一行一条的连接明细，主要工作区 | 找「哪个应用连了哪里」 |
| Apps（应用） | 按应用汇总的流量统计，点进去有安装日期、版本、权限 | 找哪个应用传得最多 |
| Stats（统计） | 整体流量汇总、当前用的 DNS 服务器 | 看总量、查 DNS |

抓包过程中连接会一直记在内存里，**超过上限后旧连接会被顶掉**（界面会提示丢弃了多少条）。想留更久的记录，就去设置里调 **Max logged connections（最大记录连接数）**。

## 二、一行连接里有什么

Connections 列表里每行代表一条出站连接，字段从左到右：

- **应用图标** —— 解析不出归属应用时显示问号（unknown），这很常见，见[常见问题与排查.md](常见问题与排查.md)；
- **应用名**；
- **协议 + 端口 + IP 版本** —— 协议是分析抓到的数据包得出的，识别不出来时这一栏会是空的或标为未知；
- **SNI 或 DNS 查询名** —— 有就显示域名，没有就只剩远端 IP 地址；
- **状态** —— `Open`（还开着）/ `Closed`（正常关闭）/ `Error`（出错）/ `Unreachable`（连不上）；
- **最后出现时间** —— 这条连接最近一个包的时间；
- **流量总计** —— 这条连接收发了多少。

点开任意一行进详情页：IP 地址、状态、统计这些**总是有**；域名只在协议能解析出来时才有（HTTP、TLS 这类）；**完整 URL 只有明文 HTTP 连接才有**——现在绝大多数网站走 HTTPS，看不到 URL 是正常的，要看得解密，见[HTTPS加密流量怎么解密.md](HTTPS加密流量怎么解密.md)。

详情页里的 IP 有时还会附带归属国家与 ASN（离线库查的，不联网）。

## 三、把无关流量滤掉（最重要的一节）

一次抓包动辄几百上千行，真正有用的就几条。四种过滤手段：

1. **搜索栏** —— 按 IP、域名、协议、应用名或 UID 搜。最省事的用法：**长按一条连接 → 从弹出菜单里直接选过滤条件**，等于「只看这一类」。
2. **Edit Filter 对话框**（列表右上角漏斗图标）——可选的固定过滤项：
   - *Not hidden*：只显示没被隐藏规则命中的（规则在 *Edit List* 里改）；
   - *Plaintext connections*：只显示明文连接；
   - *Status*：只按状态筛（如只看 Open）；
   - *Malicious connections*：只看判定为恶意的（要先开恶意检测，见[防火墙与恶意拦截怎么用.md](防火墙与恶意拦截怎么用.md)）。
3. **长按 → 隐藏** —— 把某条连接加进 **Hidden Connections** 名单。用法是先把「天天连、又不关心」的后台心跳、常用应用统统隐藏，剩下的就是你真正想看的那几条。这份名单是**持久保存**的，下次抓包还在。反过来：如果你把规则建歪了，所有连接都不显示了，也是来这里改。
4. **Apps 视图点应用** —— 在 Apps 标签里点某个应用，等于把它设为过滤条件，列表立刻只剩它的流量。

生效的过滤条件会以小标签（chip）的形式排在列表上方，点小标签即可撤掉对应条件——**「怎么全没了」先看这里**。

抓包**开始前**还能在 Status 标签设 **App Filter**：设定后只有这个应用的流量被送进来，其他应用根本不进抓包流程。做 TLS 解密时尤其该设（见[HTTPS加密流量怎么解密.md](HTTPS加密流量怎么解密.md)），能把解密范围锁死在目标应用上。

## 四、HTTP 请求视图与 HAR 导出

1.9.0 起，`Connections` 标签标题旁多了一个 **⇄ 图标**，点它切到 **HTTP 请求视图**——这是看「应用到底向服务器发了什么」最直接的地方：

- 每行一条请求：**Host**、**方法 + 路径**（如 `POST /api/login`）、**响应码**（`200 OK`）、**响应 Content-Type**、**响应体大小**；
- 顶部过滤栏可按方法、Content-Type、状态码、大小筛；
- 点一行看完整请求与响应；标题栏的左右箭头在请求之间翻页；
- 标题栏可把选中的请求**导出为文本或 HAR**——HAR 是标准格式，能丢进浏览器开发者工具或 Google 的 HAR Analyzer 里看。

**两个前提**：

1. 必须在设置里打开 **Full payload（完整载荷）**，否则 ⇄ 图标根本不出现——找不到这个图标时先检查这一项；
2. 请求来自 HTTPS 的话，先得解密，否则视图里只有连接外壳没有内容，做法在[HTTPS加密流量怎么解密.md](HTTPS加密流量怎么解密.md)。

明文 HTTP 的请求不用解密就能直接看（长按连接也能复制明文数据），但这类连接现在很少了。想把数据拿出来在电脑上细看，走[导出PCAP并用Wireshark分析.md](导出PCAP并用Wireshark分析.md)。

## 五、从单条连接跳到整体（Apps 与 Stats）

单条连接看得差不多了，换两个视图把口径放大：

- **Apps 标签** —— 按应用排的流量汇总，收发字节数一目了然。点某个应用进详情页，能看到**安装日期、版本号、权限**这三项元数据；页面上两个按钮各司其职：**Settings** 直接跳到该应用的系统设置页（要去改它的联网权限就从这儿走），**Connections** 相当于把它设成过滤条件、只看它的连接。
- **Stats 标签** —— 整体流量汇总，另外会显示**当前实际使用的那台 IPv4 DNS 服务器**（探测成功时是设备自己在用的，探测失败会回退到公共 DNS，对照这里就能看出来）。

一条常用路径：Apps 里找出流量异常的那个应用 → 点 Connections 转到它的连接列表 → 长按某条把它加进隐藏或过滤名单，把噪声逐层滤掉，剩下的就是值得看的那几条。
