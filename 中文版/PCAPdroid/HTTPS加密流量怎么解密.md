## 一、先想清楚要不要解密

不解密时，HTTPS 连接在列表里只显示域名（SNI）和 IP，**看不到里面传了什么**。解密能看到明文，典型用途是：查某个应用有没有把敏感信息明文发出去、抓它的接口地址、在不改协议的前提下排协议问题。

三件事先知道：

1. **这是个有门槛的功能**——需要装附加组件、装证书、配规则，失败是常态，官方文档原话说在安卓上解密「不是一件容易的事」；
2. **动手前先看目标应用的服务条款是否允许**；
3. **解密只对配了规则的连接生效**，不会全局解——这是设计如此，不是你配漏了。

## 二、解密向导（第一次开）

1. 右上角齿轮进设置，在 **Traffic inspection（流量检查）** 分组里打开 **TLS decryption** 开关；
2. 首次打开会进一个**安装向导**，做两件事：
   - 下载并安装 **PCAPdroid-mitm 附加组件**——真正干解密活的是它（内部是 mitmproxy）；
   - 安装 **PCAPdroid 的 CA 证书**。这个 CA 是运行时临时生成的，装进证书库后它才能解开数据；
3. 装完证书，部分手机还会再弹一次系统的「安装 CA 证书」确认框，按提示确认一次；
4. 国产系统若开了**自启动限制 / 后台冻结**，把 mitm 附加组件加进白名单——否则解密服务会被系统掐掉，表现为「开关开着却从来不解密」。

## 三、加规则：不解哪条由你定

打开开关只是具备能力，**真正开始解密靠规则**。两种加法：

- 左侧抽屉 → **Decryption rules（解密规则）**，按应用或按域名加；
- 列表里**长按某条连接 → 从菜单直接选解密条件**（最常用的入口）。

规则生效前还有个开关别忘：设置里打开 **Full payload（完整载荷）**——不打开，解出来的数据不会被完整载入，HTTP 视图也出不来（同一个开关也控制着[抓包结果怎么看.md](抓包结果怎么看.md) 里的 ⇄ 图标）。

只想解某个应用的流量，除了规则，还可以在 Status 标签设 **App Filter**：流量只从目标应用进，解密范围被锁死在它身上，其他应用完全不参与。

## 四、拿 Google Chrome 先试一次

第一次别拿目标应用试，先用最容易解的 Google Chrome 验证链路通不通：

1. 开解密、目标应用选 Chrome、点开始；
2. 在 Chrome 里**新开一个标签页、访问一个 HTTPS 网站**（或清一下浏览器缓存）；
3. 回到 PCAPdroid，应该开始出现**绿色开锁图标**的连接。

绿色出现 = 证书、附加组件、规则全都对了，接下来换目标应用才有意义。**一上来就绿不起来，问题多半在链路，不在目标应用。**

## 五、锁图标颜色对照

列表里的锁直接告诉你这次解密的状态：

| 图标 | 含义 |
| --- | --- |
| 绿色开锁 | 解密成功，点开能看到明文与 HTTP 内容 |
| 红色 | 解密失败——点这条连接，错误信息里写了原因 |
| 橙色 | 这个协议/应用不支持解密（如 QUIC，见下） |
| 灰色开锁 | 连接本来就没加密（比如明文 DNS） |
| 灰色闭锁 | 还没轮到解：没配规则，或还在等应用发数据 |

漏斗图标（Edit Filter）里可以只看「已解密」或「解密失败」的连接，逐条排查省事很多。

## 六、最常见的失败原因

红色里最典型的一条是 **"client does not trust proxy's certificate"（客户端不信任代理证书）**，按这个顺序查：

1. **安卓 7 起，targetSdk 24 以上的应用默认不信任「用户安装的证书」**，只认系统预装的。你装的是用户证书，所以目标应用不认它——这是平台行为，不是你装错了；
2. **应用自带证书库**——少数应用（多为浏览器）不走系统证书库，用自己的信任列表。查它有没有相关开关（Firefox 就能在 `about:config` 里关）；
3. **应用做了证书锁定（certificate pinning）**——只认写死在应用里的那张证书，装什么都不认。

第 1、3 条在**有 root 的机器上最好办**：把 mitm 的证书装进**系统证书库**（Magisk 用户可以用 `MagiskTrustUserCerts` 这类模块自动完成，或直接挂载系统分区写入），应用就认了。**没有 root** 时官方给的另一条路是**用一台 root 过的安卓模拟器**做同样的事（自 2.0.0 起模拟器需 x86_64 或 AArch64 镜像）。证书锁定的顽固情况，官方 caveats 章节还列了几类进阶做法——照 [官方 TLS 解密文档](https://emanuele-f.github.io/PCAPdroid/tls_decryption) 走，那里更新最及时。

其他几种失败：

- **只对 QUIC 橙色** —— QUIC 目前解不了。解法是**在设置里屏蔽 QUIC**，应用会回退到 TLS，就能解了（做 JS 注入时也要求先屏蔽 QUIC）；
- **STARTTLS 不支持** —— 官方标注为暂不支持；
- **浏览器报证书透明度（Certificate Transparency）错误** —— 自定义系统 CA 在部分浏览器里会被拒，需按浏览器各自的设置处理（详见官方文档同章节）；
- **要排除个别域名/端口** —— 比如不想解 1234 端口：设置里的 "Additional mitmproxy options" 填 `--ignore-hosts .*:1234`。

## 七、解出来的数据怎么用

- **应用内看**：点绿色锁连接 → 载荷与 HTTP 标签里是明文；⇄ 那个 HTTP 请求视图可以按方法/状态/大小筛并**导出 HAR**（前提都是开了 Full payload）；
- **拿到电脑上看**：开 PCAP 文件导出，停止时会生成同名 `.keylog`；Wireshark 里先配 TLS keylog 路径再开 pcap。若买了 **Pcapng 格式**，密钥直接嵌在 `.pcapng` 里，打开即见明文——细节在[导出PCAP并用Wireshark分析.md](导出PCAP并用Wireshark分析.md)。

**一个反直觉的点**：**root 抓包模式下反而解不了密**——解密走的 SOCKS5 代理在 root 模式里不可用。要解密就用默认的 VPN 模式抓。

进阶需求（接外部 mitmproxy、自定义 mitmproxy 插件、JS 注入）都在官方文档的 TLS Decryption 与 Advanced Features 章节里，等你把上面的流程跑通了再去看。
