## 一、先看硬边界（命中就别再试了）

| 情况 | 结论 |
| --- | --- |
| 想抓**别的设备**的流量（别人连你热点、局域网内其他机器） | 不支持，它只抓运行它的这台安卓设备 |
| 想抓**别人连进你手机**的连接（电脑 ping 手机） | 非 root 模式抓不到——只捕获手机自己发起的出站连接 |
| 想抓**热点/共享网络**上过路的流量 | 通常无 root 抓不到；只过 HTTP/S 的话有代理变通法（见第五节） |
| 想在**另一个 VPN 应用运行时**同时抓包 | 需要 root（改用 root 抓包模式） |
| **QUIC / STARTTLS** 流量想解密 | 暂不支持；QUIC 可通过屏蔽它让应用回退到 TLS（见解密篇） |
| **root 抓包模式下想解密** | 不行——该模式没有 SOCKS5 代理，解密不可用 |
| 系统版本太老 | 网盘这份 1.9.1 标注需安卓 5.2 以上；官方 2.0.0（2026-08-19）起要求 Android 6.0（API 23）及以上 |

对照命中任意一条，出现对应现象就是预期结果，不用继续找设置开关。

## 二、症状：一启动就问「要创建 VPN 连接」

**正常，不用慌。** 不 root 就要抓到全机流量，只能走安卓的 `VpnService` 接口把流量引进应用本地处理——所以那个弹窗是系统在要权限，**不是它要连到外部 VPN 服务器，数据也不会离开这台手机**。点确定才能开始；点拒绝则什么都抓不到。

顺带说明：抓包期间状态栏那把**钥匙图标**就是这个 VPN 在运行的标志，不同系统图标样式略有差别。

## 三、症状：列表里一堆 unknown / 看着奇怪的 IP

- **应用显示问号 + unknown** —— 系统级连接（netd 之类）解析不到归属应用，官方明确说这是正常现象，不影响其余行的可读性。
- **满屏 `10.215.173.1` / `10.215.173.2`** —— `10.215.173.1` 是 PCAPdroid 自己建的虚拟网卡地址（它相当于代理，所有连接的源地址都是它）；`.2` 是它用来接收 DNS 流量的虚拟地址。**不是你的局域网 IP，也不用去路由器上找这台机器**。
- **看不到完整 URL，只有一个域名** —— 明文 HTTP 才有 URL，HTTPS 要解密才有，做法在[HTTPS加密流量怎么解密.md](HTTPS加密流量怎么解密.md)。如果这个应用有网页版，用电脑浏览器开它再看开发者工具，比解密省事得多。
- **列表怎么变少了 / 没有了** —— 大概率是过滤条件还挂着：看列表上方的过滤小标签，点掉即可；也可能是 Hidden Connections 规则建歪了，去 Edit Filter 的 Edit List 里改（见[抓包结果怎么看.md](抓包结果怎么看.md)）。

## 四、症状：抓着抓着记录变短了 / 状态不对

- **旧连接莫名消失** —— 连接记录存在内存里，到上限会顶掉旧的，界面会提示丢弃了多少条。想留更久去设置调 **Max logged connections**。
- **IPv6 连接全是 Unreachable** —— IPv6 默认是关的，只有你在 VPN 设置里手动打开才监控；开着它但当前网络（Wi-Fi / 流量卡）本身不通 IPv6，就会这样。不需要盯 IPv6 服务就关着。
- **状态一直显示 Open** —— 意思是这条连接还开着，不是「正在高速传输」；要看有没有数据在动，看「最后出现时间」和流量计数。
- **后台跑着跑着停了** —— 多半是系统杀后台。按这个顺序给权限：
  1. 系统设置 → 应用 → PCAPdroid → **电池**，把它改成「不优化 / 无限制」（各厂名字不同，找「省电策略」「电池优化」那一项）；
  2. 同一层里再看有没有 **后台限制 / 后台活动** 被打开，有的话关掉；
  3. 厂商自带的「省电管家」「应用冻结」类功能把 PCAPdroid 排除掉；
  4. 开着 TLS 解密时，**mitm 附加组件也要一并加进自启动白名单**，否则解密会先罢工（官方明确提示过 Autostart 类限制要放行）。
- **电量统计里它排前面** —— 抓包期间所有流量都从它这儿过，系统的耗电统计会把这些流量的耗电**记到它头上**，这与它实际多耗的电不是一回事。官方 Play 页面的描述是「低耗电，可全天连续抓包」（以官方页面当时显示为准）；真嫌耗电就抓完立刻停，别让它一直挂着。

## 五、症状：抓不到热点、抓不到别人发来的连接

这两条都源于同一个限制：**非 root 只捕获这台设备主动发出的连接**。

- **别人连你手机热点上网的流量**：取决于系统实现，通常无 root 抓不到（官方给了一个 issue 链接专门讨论：`github.com/emanuele-f/PCAPdroid/issues/20`）。可行的变通是**在手机上装一个 HTTP 代理，让连热点的设备走这个代理**——只能覆盖 HTTP/S 流量。
- **外部设备连进来的连接**：局域网外本来就被 NAT/防火墙挡着，实际能进来的只有同一局域网的设备；这类入站连接在非 root 模式下不会被送进 VPN，列表里自然没有。

要覆盖这两类，只能看 root 抓包模式——它直接从网络接口抓包，不受 VPN 模式「只收出站」的框框限制（具体边界以[官方文档](https://emanuele-f.github.io/PCAPdroid/advanced_features#44-root-capture) 为准）；代价是解密不可用、以太网层不显示，取舍写在[导出PCAP并用Wireshark分析.md](导出PCAP并用Wireshark分析.md)。

## 六、症状：解密开不了 / 一直红

按[HTTPS加密流量怎么解密.md](HTTPS加密流量怎么解密.md) 的顺序查，最快的分诊是：

1. **先拿 Google Chrome 试**——它绿了说明链路没问题，红了说明问题在证书、附加组件或规则；
2. 红色带 "client does not trust proxy's certificate" → 目标应用不认用户证书（安卓 7+ 的默认行为）或做了证书锁定，处理办法见解密篇第六节；
3. 橙色且是 QUIC → 屏蔽 QUIC 再试；
4. **开关开着但从来不出锁图标** → 检查 mitm 附加组件是否被系统冻结、Full payload 是否打开、规则是否真加上了。

以上都试过仍对不上的情况，官方用户手册（`emanuele-f.github.io/PCAPdroid`）的 FAQ 与各功能章节是最新的说法；项目代码与 issue 在 `github.com/emanuele-f/PCAPdroid`，热点抓包、UID 解析这类边界问题在 issue 里有更细的讨论。
