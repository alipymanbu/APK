# 服务器告警怎么到手机

> 服务器出状况时，1Panel App 是你「收到通知后去处置」的入口，但通知本身不靠 App 推送——本篇讲清告警从面板到手机的完整链路与各渠道的版本门槛。

## 一、先纠正一个常见误解

装了 1Panel App 不等于服务器异常时手机会收到推送。App 的角色是**处置端**：打开概览、停掉异常容器、改出问题的应用配置。而「有事第一时间告诉你」这件事，由服务器端 1Panel 面板的**告警通知**负责——你在面板里配置告警任务，面板把通知发到你选的渠道，手机上的企业微信、钉钉、短信或自建接收端收到消息，再打开 App 处理。

所以「告警到手机」要配两样东西：**面板侧的告警任务 + 一个能落到你手机的接收渠道**。

## 二、接收渠道与版本门槛

按官方版本对比与帮助文档（截至 2026 年 9 月，以官方文档为准）：

| 渠道 | 版本要求 | 说明 |
| --- | --- | --- |
| 邮箱告警 | 社区版即可 | 面板设置里配好发件邮箱，告警发到你的邮箱 |
| Bark 告警 | 社区版即可 | Bark 是 iOS 端推送工具，iPhone 用户最轻量的选择 |
| 企业微信 / 钉钉 / 飞书 | 专业版 / 企业版 | 消息进 IM 群或应用号，安卓用户的主要选择 |
| 短信告警 | 专业版 / 企业版 | 发到许可证对应凌霞账号绑定的手机号；有额度与每日条数限制 |
| 自定义 Webhook | 面板 v2.3.0 起 | 把告警 POST 到你自己的接口，官方预设含通用 JSON、Slack、Discord、Teams 等格式 |

选法很简单：**iPhone 先试 Bark，安卓用企业微信 / 钉钉 / 飞书之一**；社区版用户前两个渠道就够用，不花钱也能第一时间知道出事。

## 三、能配哪些告警任务

官方文档列出的告警类型覆盖日常运维最常见的「出事点」：

- 网站证书（SSL）到期、网站到期；
- 面板密码到期、面板新版本提醒；
- 服务器 CPU / 内存 / 负载 / 磁盘占用过高。

每类任务可以设阈值与触发条件（例如 CPU 连续高于某百分比、证书剩余天数少于某值），持续异常有防打扰机制（如 30 分钟内同一条告警只发一次）。具体可配项随面板版本增加，配置时以面板内界面为准。

## 四、通知到手后，怎么用 App 处置

1. 从通知里知道「哪台服务器、什么事」；
2. 打开 App，首页概览确认整体状态（多台服务器时先切到出事的那台）；
3. 按问题类型处理：容器异常去容器管理、应用出错去应用管理、站点异常去网站管理——各项操作见[手机端功能与日常操作](手机端功能与日常操作.md)；
4. 处理不了的（比如要改防火墙规则、动系统配置），回电脑网页版，或按[连接服务器教程](连接服务器教程.md)先确认服务器状态。

## 五、两个容易踩的坑

- **只装 App、不配告警**：App 首页只有你打开时才看得到状态，服务器半夜出事你不会知道。先把面板的告警任务配起来，App 才有「用武之地」；
- **告警任务配了、渠道没打通**：比如配了短信但额度用完、配了邮箱但进了垃圾箱。配完后人为触发一次小阈值（如把磁盘告警阈值临时调低），确认通知真的能落到手机，再改回正常值。
