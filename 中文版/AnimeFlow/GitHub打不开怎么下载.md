## 一、按这个顺序试

1. **直接用网盘收录的版本**：如果目标只是「装一个能用的」，这份 **[AnimeFlow 安装文件资源（夸克网盘）](https://pan.quark.cn/s/54264c09c1f3)** 最省事，转存后下载即可，版本与包参数见 [下载与安装教程.md](下载与安装教程.md)；
2. **官方 Gitee 镜像**：开发者在国内代码托管平台 Gitee 上维护着同步镜像 `https://gitee.com/anime-flow/AnimeFlow`，GitHub 抽风时源码、README 与版本说明可以从这里看；
3. **换时段再试 GitHub Releases**：`https://github.com/openAnimeFlow/AnimeFlow/releases` 的可访问性随网络环境波动明显，隔一会儿再试常常就通了。

## 二、Gitee 镜像能干什么、不能干什么

- **能**：看代码、看 README、看提交记录，仓库内容与 GitHub 侧保持同步更新；
- **不能全指望**：镜像仓库的 Issues 区是空的，遇到问题要反馈还是得去 GitHub 的 Issues；安装包是否随版本发布到镜像页，以镜像页面当时显示为准，别默认它一定有。

## 三、选包先选 arm64

官方开发者在 Issue 里明确说过，自己**只保证 iOS、安卓 arm64（v8）、Windows x86 三类包正常可用**，v7a 与安卓 x86 包没有对应的物理设备可以调试测试。这也意味着：

- 手机党无脑选 `arm64` 后缀的包；
- 电视盒子用户要留意：有晶晨 S905L3AB 芯片盒子的用户反馈过 v7a 包在 2.3.0 上闪退，官方当时建议完全卸载后重装旧版本排查。盒子翻车了别死磕 v7a 新版，回退旧版更稳。

## 四、国内网络的两个已知坑

这两条都来自官方 Issues 里的真实反馈，写在这里让你知道「不是我一个人这样」：

- **数据源更新后丢失**：有用户反馈国内网络下数据源无法更新，开代理能更新但重进应用后又回到更新前——官方确认过这是已知问题，在 1.9.3 版本修复。网盘收录的 1.7.6 早于该版本，碰到的话先换网络环境，根治要升级新版；
- **封面图加载失败**：有用户反馈不挂代理时封面图抓取失败（该问题在后续版本已关闭），表现为列表能出来但海报全是灰块，属网络路径问题而非安装问题。
