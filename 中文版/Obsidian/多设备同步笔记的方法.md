## 一、前提：先把仓库放在「设备存储」

安卓上想用任何**外部**同步工具（Syncthing、云盘目录、Git 客户端），仓库必须建在**设备存储**——应用存储是 Obsidian 的私有沙箱，别的应用根本看不到它。官方帮助页对这一点写得很明确。如果你当初选了应用存储，又想走外部同步，先把笔记文件导出/复制到共享位置再重建仓库（详见 [下载与安装教程.md](下载与安装教程.md) 第四节）。

## 二、四类做法对照

| 方案 | 费用 | 安卓侧支持 | 要点 |
| --- | --- | --- | --- |
| **Obsidian Sync**（官方） | 订阅付费 | 直接支持 | 官方第一方方案，覆盖 Windows / macOS / Linux / iOS / Android |
| **云盘目录**（iCloud / OneDrive / Google Drive） | 各自的云盘套餐 | 看云盘 App | 把仓库文件夹放进云盘目录，多端共享同一份文件 |
| **Syncthing** | 免费开源 | 需设备存储 | 设备之间点对点直传，不经过云 |
| **Git** | 免费 | 需装客户端 | 版本可回溯，iOS 上常用 Working Copy，安卓上也有各类 Git 客户端 |

社区插件目录里还有一整类同步插件（官方 sync-notes 页直接给了入口），本质都是「把文件夹搬到某个地方」，选型逻辑与上表相同。

## 三、官方方案 Obsidian Sync 的几条关键口径

以下来自官方帮助与同步 FAQ（截至 2026-09，以 [obsidian.md](https://obsidian.md) 页面为准）：

- **只在 Obsidian 运行时同步**——不会在后台常驻同步，手机上把应用划掉后它就停了。
- 默认同步笔记、图片和配置文件夹，PDF / 音频 / 视频等附件要在设置里逐类打开。
- **不要把 Obsidian Sync 和第三方云盘同时开**：两套同步打同一份文件，可能产生重复或损坏的文件。
- 用 OneDrive / Dropbox 时要关掉它们的「按需下载 / 仅联机文件」功能——这类功能会把本地文件移走，同步会把它们当成「已删除」。

## 四、用云盘做同步的坑

- **OneDrive / Dropbox 的按需文件**：上一条同样适用于纯云盘方案，必须把仓库文件夹设为「始终保留在此设备上」。
- **iCloud 主要面向 macOS / iOS**：官方明确说 Windows 上的 iCloud Drive 可能导致文件重复或损坏，不建议在 Windows 用它同步。
- **安卓上的云盘表现参差**：官方 sync-notes 页把 OneDrive 在 Android 上标为「功能受限」。云盘能否及时把新文件落到本地，取决于该云盘 App 在你机器上的后台行为——拿它当主方案前，先在两台设备上各写一篇、确认对面真能收到。

## 五、冲突是怎么产生的

两台设备在**同步之前**改了同一个文件，就冲突了。离线时间越长越容易撞上。Obsidian Sync 的处理（官方口径）：

- **Markdown 文件**：自动合并两处改动；
- **其他文件**（含 Canvas）：后改的覆盖先改的（last write wins）；
- 1.9.7 起可以改设成「生成冲突副本文件，自己手动合并」，文件名形如 `xxx.sync-conflict-20241128-143022.md`。

冲突文件出现后的处理步骤见 [常见问题与解决办法.md](常见问题与解决办法.md)。

## 六、怎么选

- **只在安卓上用**：笔记不多的话，设备存储 + 定期手动备份文件夹就够，不必急着上同步。
- **手机 + 电脑都要用**：图省心用 Obsidian Sync；想免费、设备都在身边，用 Syncthing；已有云盘会员，按第四节的坑配好再用。
- 同步方案定了就别频繁换：每次换方案都是一次全量搬迁，中途断了比不同步更麻烦。

同步后如果感觉启动变慢，见 [打开加载很慢怎么解决.md](打开加载很慢怎么解决.md)。
