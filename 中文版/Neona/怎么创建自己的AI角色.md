## 一、什么时候该自建

角色库里翻了一圈没有对味的，或者你脑子里已经有一个具体的人物，自建就比反复试现成角色省时间。自建角色的入口与应用内的角色创建功能都在客户端里，不需要额外的账号或工具。

建好的角色属于你自己的账号，可以像预设角色一样直接开聊，也可以长期只跟它聊。

## 二、要填的字段与它们的作用

创建流程基本是「生成形象 → 填设定 → 保存开聊」。设定项按下面的顺序理解最省事：

| 字段 | 填什么 | 影响什么 |
| --- | --- | --- |
| 名字 | 角色的称呼 | 对话中自称与互称都会用到，中文、外文名都可以 |
| 年龄 | 角色的年龄设定 | 影响说话成熟度与关系设定 |
| 性格 | 用短句描述，如「占有欲强但嘴硬」 | 最主要的一项，决定反应方式 |
| 说话方式 | 用敬语还是随意口吻、句子长短 | 决定回复的语气，是「端着」还是「没大没小」 |
| 初次相遇的场景 | 你们在哪、怎么认识的 | 决定故事从哪一刻开始 |
| 两人的关系 | 同学、同事、恋人、陌生人等 | 决定称呼与互动的边界 |
| 世界观 | 现实校园、奇幻大陆等 | 决定场景里能出现什么元素 |

这些项不是装饰性的——官方对自建角色的说明就是「一切都能按你的意愿自定义」，包括从名字年龄到性格、说话习惯、初次相遇场景，以及两人的关系。填得越具体，开聊后越不容易跑偏。

## 三、形象怎么来

不用自己画图。写一段外貌描述（比如发型、服装、场景、气质），让应用按描述生成角色的形象图片即可。同一段描述多生成几次会得到不同的方案，选一张满意的保存。

形象生成是整个创建流程的第一步：先有图，再在此基础上补简介和设定。

## 四、角色简介怎么来

角色的详细简介会由应用根据你的设定自动整理成一份带排版的介绍，不需要自己写 HTML 或排版。生成后如果不满意，能改的项可以直接改。

省事的做法是：先把性格、关系、场景这几项写具体，再让应用生成那份简介——简介的质量基本取决于你前面几项写得细不细。

## 五、写设定时的几个要点

**把「怎么说」写进性格里**。只写「温柔」太空，写成「说话慢、总先问你今天怎么样、不主动提要求」才有约束力。

**关系设定要明确**。写「关系很好」不如写「同班同学，认识三年，你叫它小名」。称呼是角色对话里最容易露馅的地方。

**世界观别贪多**。现实题材就把地点、时间线交代清楚；奇幻题材说明有没有超能力、社会规则如何。设定项越多，内部互相矛盾的概率越高。

**一次建一个**。想把两三个性格揉进一个角色，往往会得到一个哪边都不像的结果；需要多种感觉，就建多个角色。

## 六、建好之后

保存角色后就能直接进入对话。因为设定是你自己写的，这个角色在做 [角色记忆怎么保持长期连贯.md](角色记忆怎么保持长期连贯.md) 里提到的那类「设定约束」时效果最好——关键设定本来就在角色的定义里，不容易随对话漂移。

对话过程中的操作方式与预设角色完全一致，见 [怎么找角色和开始聊天.md](怎么找角色和开始聊天.md)。

自建角色同样跟着账号保存，换设备登录同一账号后会一起回来；这一点与 [注册登录与账号设置.md](注册登录与账号设置.md) 里的说明一致。
