## 一、限制的根源：用的是系统 WebView

Hermit 页面渲染用的是安卓系统的 WebView，不带 Chrome 或 Firefox 那种自研引擎。绝大多数日常站点没有区别（定位、文件上传、DRM 视频、全屏播放这些都支持），但少数依赖引擎深度能力的高级页面会跑不了。官方对这类问题的态度是明说的：受影响的流程建议直接换独立浏览器，不值得硬等修复。

判断方法很简单：**某个页面在 Chrome 里正常、在 Hermit 里反复异常**，先查下表，对不上号再走 [常见问题与使用注意.md](常见问题与使用注意.md) 的 WebView 更新排查。

## 二、跑不了或受限的网页功能

| 功能 | 现状 |
| --- | --- |
| 跨域隔离类页面（依赖 SharedArrayBuffer 的高级网页应用） | WebView 不支持跨域隔离，此类页面无法运行，官方标注无解 |
| 网页剪贴板 API | 你自己长按复制粘贴不受影响；网页上一键「复制到剪贴板」的按钮可能无效 |
| 下拉刷新 | 与少数站点的滚动逻辑冲突，导致页面行为异常；受影响时可改用页面内的刷新按钮，或关闭该 Lite App 的下拉刷新（入口以应用内实际设置为准） |

## 三、密码保存：支持但依赖系统 AutoFill

Hermit 自己不存密码，走系统的自动填充服务。想让登录时弹出「保存密码」：

1. 在**手机系统设置**（不是 Hermit 里）打开「设置」；
2. 进「系统」→「语言和输入法」；
3. 展开「高级设置」；
4. 点「自动填充服务」；
5. 选「Google 自动填充」。

配好一次后，Hermit 里首次登录某站点就会询问是否保存，其他应用和浏览器也能共用这套填充。两点预期要放好：

- 官方自己承认不少用户反馈这套填充**时灵时不灵**，原因不明，属于已知不稳定项；
- 第三方密码管理器兼容不一，官方点名 Bitwarden 的支持请求至今未被响应——依赖密码管理器的用户要有心理准备。

## 四、为什么不能生成 APK、进不了应用抽屉

两个常见诉求官方都给不了：

- **把某个网站直接打包成独立 APK**——Google Play 政策不允许应用在设备上生成 APK，所以 Hermit 只能以「桌面快捷方式」形态工作；
- **把 Lite App 图标放进应用抽屉**（和普通应用混排的列表里）——同样受此限制，图标只能放在桌面上。

想要进应用抽屉的图标，只能靠支持自定义的第三方启动器变通，或接受「桌面图标」这一形态。

## 五、与拦截和脚本的交叉影响

个别站点因为页面安全策略与 WebView 的实现差异，用户脚本可能不生效；拦截规则误伤页面的处理则是独立的一套，两件事的排查分别见 [广告拦截与用户脚本.md](广告拦截与用户脚本.md) 的第四节和第三节。
