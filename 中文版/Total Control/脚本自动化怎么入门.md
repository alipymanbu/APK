## 一、先想清楚你要自动化什么

这套脚本能力适合两类事：一是**每天重复几十遍的手动操作**（打开某页、点某按钮、填一段字）；二是**多台设备跑同一套流程**（批量检查、批量设置）。如果只是偶尔点几下，鼠标直接点比写脚本快，不用入门。

写脚本前记住一个核心差异：**别用坐标，用「找元素」**。坐标 `click(100, 200)` 换一台分辨率不同的手机就点偏了；而 `click("OK")` 是「找到文字是 OK 的按钮再点」，同一段脚本能跑在所有机型上 —— 这也是它能在多台设备间同步操作的基础。

## 二、三个入口，按这个顺序走

全部在 PC 端主面板的 **Script（脚本）** 菜单里：

| 工具 | 干什么 | 什么时候用 |
| --- | --- | --- |
| UI Explorer | 列出当前屏幕上每个 UI 元素的属性（文本、类名、资源 ID、边界、是否可点） | 第一步：看你想点的东西叫什么 |
| Terminal | 交互式执行命令，三个窗口可同时开 | 第二步：当场试查询灵不灵 |
| Runner | 跑写好的脚本，结果记录在 Task 里 | 第三步：把验证过的流程存成脚本反复跑 |

配套还有一个练习用应用 **SigmaTestApp**（包名 `com.sigma_rt.sigmatestapp`）：设备连上后从 UI Explorer 里能直接安装，专门用来试查询语法和 `sendAai()`，不用拿你自己的常用 App 冒险。

## 三、AAIS：十几条命令的入门脚本语言

AAIS 是官方为「简单测试、一次性脚本」设计的小语言，语法就是一句句中文/英文命令。几个示例（照官方手册的写法）：

```
启动 "com.raider.skype"
等待 "Favorites"

寻找 "John"
点击

文本 "hello world"
```

能用的命令覆盖了日常主干：`点击 / 长按`、`启动 / 重启`、`等待`（默认等 5000 毫秒，可指定超时）、`文本`（输入）、`寻找`（滚动到目标再操作）等。特性要先知道，不然会写出跑不动的脚本：

- **没有条件、循环、变量**（只有 JS 变量），复杂逻辑请换 JavaScript；
- **任何一步失败脚本就停**，这在批量跑时意味着第一台出错后面全不执行；
- 脚本保存为 `.tst` 文本文件，也能用**录制回放**生成 —— 录制要求先切到**对象模式**；
- JS 代码块用 `{}` 包起来可直接嵌进 AAIS，`//` 是注释；
- 多设备运行时，选中的每台设备各起一个线程跑同一份脚本，1~50 台都行。

## 四、从试到跑的一条最短路径

1. 连上手机（见 [手机连接电脑的两种方式.md](手机连接电脑的两种方式.md)）；
2. Script → **UI Explorer**，点中你反复要操作的那个按钮，抄下它的 `T:`（文本）或 `R:`（资源 ID）查询；
3. Script → **Terminal**，用 `sendAai({query:"T:确认", action:"click"})` 这类写法当场验证；
4. 验证通过后，在 Runner 里组装成脚本存盘，勾选设备运行；
5. 要多机同步，去多控中心用对象模式发同一查询（专业版功能，见 [精简版和专业版的区别.md](精简版和专业版的区别.md)）。

## 五、这些场景它做不了（官方明说的限制）

写之前对一遍，省得调试半天才发现是硬限制：

- **只支持竖屏**，横屏节点取不到（官方手册注明后续版本才会支持）；
- **横向滚动、弹窗**可能取不到或取多节点；
- **WebView 与部分游戏**（Facebook、YouTube 这类）节点经常缺失 —— 先用 UI Explorer 看看到底识别了哪些节点，再决定这条路走不走得通；
- **不支持多线程**：多控中心对象模式、Terminal、UI Explorer 与 REST API 里用到 FindNode 的部分**互斥**，不能同时抢；
- 找图找色、OCR 这类能力有独立的命令体系，和节点查询不是一套，别混着指望。

日常手工操作的快捷键与窗口技巧在 [电脑上操作手机的日常用法.md](电脑上操作手机的日常用法.md)，脚本只是把那套动作变成可重放的文件。
