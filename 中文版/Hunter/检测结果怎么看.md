## 一、打开就出结果，先看那一句总判定

装好打开（安装步骤见 [下载与安装教程.md](下载与安装教程.md)），首页会直接给出本次检测的结论，不用先配置什么。读结果的顺序建议是：

1. **先看总判定**：通过 / 有风险项，决定了你后面要不要细看。
2. **再看它列出的具体风险项**：Hunter 给的不是「通过/不通过」两个字，报告里会带上具体的风险描述和可疑文件路径 —— 有路径就意味着你能顺着它去本机核对。
3. **最后对照行动**：提示的是 Root 残留，走 [隐藏Root后检测不通过怎么办.md](隐藏Root后检测不通过怎么办.md)；提示的是设备指纹、模拟器一类，走 [黑灰设备提示是什么原因.md](黑灰设备提示是什么原因.md)。

## 二、各检测项分别在查什么

下表是 Hunter 覆盖的检测项（按 6.65 版整理，版本更新后可能增减，以你装的那版界面为准）。你不需要每项都懂，但出红的那几项最好知道它指向什么：

| 检测项 | 它在查什么 | 你该关注的点 |
| --- | --- | --- |
| APK 签名 | 应用本身的签名信息 | 一般与你无关，用于识别被改过的包 |
| Magisk & Root | 设备上有没有 Root 工具及其残留 | 没做过 Root 却报这个，重点查 |
| 沙箱 / 沙盒检测 | 运行环境是不是被套了一层容器 | 多见于分身、多开类工具 |
| Frida & IDA 检测 | 有没有动态调试工具挂在进程上 | 你没在调试却报，说明有调试环境残留 |
| libc 内存检测 | 内存里的动态库是否被动过 | 与注入类改动有关 |
| Unidbg 检测 | 是否处于模拟执行环境 | 模拟器/云手机上常报 |
| 关键函数 inline hook & GOT 表检测 | 关键函数跳转是否被改道 | 系统被改过的旁证 |
| 反调试检测 | 进程是否处于被调试状态 | 同上，有则环境不干净 |
| ISO 强检测 | 系统镜像层面的完整性 | 刷过机后留意 |
| Magisk Hide 检测 | Root 隐藏功能本身是否被识别 | 恰恰是隐藏方案是否生效的观察窗口 |
| SOTER 与 IFAA 指纹检测（6.65 新增） | 指纹密钥体系的状态 | 涉及刷脸/指纹支付的设备留意 |
| 内存信息显示（6.65 新增） | 展示当前内存占用 | 只是信息展示，不是风险项 |

另外，首页偶尔还会弹出单条提示，比如「当前设备指纹可能被修改」「电池异常：充电功率过高」这类 —— 逐条含义见 [黑灰设备提示是什么原因.md](黑灰设备提示是什么原因.md)。

## 三、术语对照：报告里那些英文名

报告用词偏技术，这里给一份够用的对照，不需要背：

- **Root**：拿到系统的最高权限。做过 Root 的设备会留下各种痕迹。
- **Magisk**：目前最主流的 Root 方案，安装在系统之外，自带隐藏功能（旧版叫 Magisk Hide，新版由 Zygisk 承担）。
- **Xposed / LSPosed**：给系统挂功能模块的框架，装过会留痕。
- **Zygisk**：Magisk 在新版里用来向进程注入的机制，隐藏 Root 常靠它。
- **模拟器 / 云手机**：跑在电脑或服务器上的安卓环境，设备指纹与真机不同，容易被判异常。
- **Bootloader 解锁（BL 解锁）**：刷机的前提状态，解锁本身就会被检测到。
- **设备指纹**：Android ID、MAC 地址这类能标识设备的参数；被动过就会报指纹异常。

## 四、读结果时最容易踩的三个坑

1. **报了风险不等于手机中毒**。Root 残留、框架痕迹这些是「你或前任机主改过系统」的记录，不是恶意软件判定。先想这台机器刷没刷过机、装没装过框架。
2. **改过系统的机器会有误报空间**。不同品牌、不同安卓版本的分区结构有差异，个别项目在老机型上会误报 —— 单项存疑时，对照第二表格里它的指向，结合本机实际改动来判断，别只看一红就慌。
3. **换一版可能换一批结果**。检测项随版本增加，同一台手机用 6.65 和更早的 6.x 跑出不同项数是正常的。对比两台设备的结果时，先确认装的是同一版本（版本信息见 [下载与安装教程.md](下载与安装教程.md)）。
