# 隐藏Root后检测不通过怎么办

> 你用 Magisk 管理 Root、并开了隐藏之后，怎么用 Hunter 验证隐藏到底生效了，不通过时按什么顺序处理。

## 一、这篇解决什么问题

你给手机装了 Magisk 之类的 Root 方案，也开了它的隐藏功能（新版由 Zygisk 承担，旧版叫 Magisk Hide），但**隐藏配没配对，只有跑一次检测才知道**。Hunter 在这个场景里的作用就是「复检员」：它跑完告诉你残留还在不在、还在哪。

这篇讲的就是这条链路：开隐藏 → 复检 → 不通过时怎么逐条处理 → 什么时候该重新验证。全程只针对**你自己的设备和你自己配的 Root 环境**。

## 二、标准验证流程

1. 装好并打开 Hunter（安装见 [下载与安装教程.md](下载与安装教程.md)），跑一次完整检测。
2. 看总判定：
   - **通过** —— 当前配置下没查到残留，隐藏生效。
   - **不通过** —— 进入第 3 步。
3. 不通过时，报告会**列出干扰隐藏的进程与服务**（不是只给一句结论）。把这几项记下来。
4. 用你手机上的进程管理/启动项管理工具，把列出的那几项服务停掉。
5. 回到 Hunter 重新检测。通过即说明这几项确实是残留来源。
6. 复测通过后，重启手机**再跑一次** —— 重启后自启的项才是真实状态，只测一次会漏掉开机自启那部分。

## 三、复测还是不通过时的排查顺序

按「改完立刻能验证」到「改动最大」排序，从上往下试：

| 顺序 | 动作 | 说明 |
| --- | --- | --- |
| 1 | 确认 Hunter 与其它检测工具看到的是同一份环境 | 若你把 Hunter 本身加进了 DenyList，它就看不到残留，测出「通过」不代表其它应用也通过；验证时建议让 Hunter 保持能观察到真实环境 |
| 2 | 检查 Magisk 里隐藏相关的开关是否真的开着 | Zygisk 是否启用、DenyList 是否勾选了目标应用，改完必须重启才生效 |
| 3 | 清掉报告点名的残留项 | 按第二节第 4 步逐项处理，处理一项复测一次，避免一次改太多分不清是哪项起效 |
| 4 | 更新 Magisk 与相关模块到相互匹配的版本 | 版本错配是常见的失效原因；更新后**必须重新走一遍第二节的验证** |
| 5 | 换个检测工具交叉验证 | Hunter 查不到不等于没有，多装一个同类工具对照（术语含义见 [检测结果怎么看.md](检测结果怎么看.md)） |

**每改一项就复测一次**是这里最重要的操作纪律 —— 一次改五项、第五项才起效，前四项就永远不知道有没有副作用。

## 四、什么时候需要重新验证

配置不是一劳永逸的，以下动作之后都该重跑一遍第二节的流程：

- 更新了 Magisk 或任何 Xposed/LSPosed 模块；
- 升级了系统（OTA 会把系统分区改回官方状态，部分痕迹随之变化）；
- 升级了 Hunter 本身（新版本会加检测项，6.65 就新增了 SOTER 与 IFAA 指纹检测 —— 版本说明见 [下载与安装教程.md](下载与安装教程.md)）；
- 换了手机、恢复出厂设置后重新配置。

## 五、和「黑灰设备提示」的区别

两篇的分界线很清晰：

- 残留来自 **Root 方案与它的隐藏配置**（Magisk、框架、进程服务）→ 本篇；
- 提示来自**设备本身的条件**（不支持 Attestation、模拟器环境、ROM 被改、设备指纹异常）→ [黑灰设备提示是什么原因.md](黑灰设备提示是什么原因.md)。

实际跑起来两篇常会同时命中 —— 例如「查找 rwx 条目」既可能指向 Root 残留，也可能指向系统分区改动。先走本篇把 Root 相关项清干净，剩下的再按那一篇逐条对照，两边都清了才复测，结果才有参考价值。
