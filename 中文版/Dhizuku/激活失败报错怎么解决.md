# Dhizuku 激活失败报错怎么解决

## 一、报错「设备上已有账号」

**含义**：激活那一刻系统里存在至少一个账号，设备所有者不允许这样设置。

处理步骤：

1. 设置 → 账号，把列表里的账号全部退出；只删同步开关不算，要真的移除账号。
2. **「设置里看着空了」不代表真的空了** —— 有的账号退出后仍在系统底层残留。用 adb 验证：

```bash
adb shell dumpsys account
```

输出里只要还能看到账号条目，就说明没退干净。常见残留来源是装着账号类应用本身：把它们冻结或退出后再查，直到 `dumpsys account` 一条账号都没有。
3. 查干净后重新执行激活命令，见 [DeviceOwner激活教程.md](DeviceOwner激活教程.md)。

## 二、报错「设备上已有其他用户」

**含义**：应用分身、手机分身、访客、多用户里创建了 0 号主用户之外的用户。

处理步骤（二选一）：

- **推荐：在设置里删除其他用户**。入口各品牌不同，一般在「设置 → 多用户 / 手机分身 / 应用分身」。注意：被删除用户空间里安装的应用会被卸载。
- 删不掉时，用 adb 查出用户 ID 再删：

```bash
adb shell pm list users
adb shell pm remove-user 999
```

`999` 换成你要删的 ID，**只删 0 以外的**。输出 `Success` 才算删掉。

## 三、报错「设备所有者已存在」

**含义**：位置被冰箱、小黑屋、Island、Insular 之类应用占着（多半是以前用 adb 激活过又忘了）。

处理步骤：

1. 先强停 Dhizuku 再重进，看它是否其实已激活；
2. 若确实被别的应用占着：打开那个应用，在它的设置里找「移除设备所有者 / Remove Device Owner」移除；找不到入口时，该应用通常需要恢复出厂才能清掉身份 —— 这一步会清数据，先备份再考虑；
3. 位置空出来后重新激活。

## 四、报 `ProvisioningPreCondition 99`（OPPO / 一加等）

这些品牌只允许白名单内或测试签名的应用成为设备所有者，报错码 99 是签名校验没过。这不是你的操作顺序错了，官方讨论区给出了对应机型的处理思路，按 [github.com/iamr0s/Dhizuku](https://github.com/iamr0s/Dhizuku/discussions/19) 里的说明走即可。

## 五、激活方式里找不到 Shizuku 选项

说明 Dhizuku 没检测到可用的 Shizuku。先按 [shizuku.rikka.app](https://shizuku.rikka.app/) 的手册把 Shizuku 启动起来（root、无线调试、连电脑任选），确认 Shizuku 首页显示运行中，再重进 Dhizuku。

## 六、提示激活成功，首页却显示未激活

有的机型上命令返回成功、实际只授予了「设备管理员」而不是设备所有者，两者的接口相似但强度不同。排查顺序：

1. 强停 Dhizuku 后重进，看状态是否刷新；
2. 用 `adb shell dumpsys account` 再查一遍账号残留 —— 残留账号会让激活流程「表面成功、实际没生效」；
3. 重启手机后再看状态；
4. 都无效时，多半是该系统对设备所有者做了额外限制，到 [github.com/iamr0s/Dhizuku](https://github.com/iamr0s/Dhizuku/issues) 反馈机型信息。

## 七、冻结过账号应用，激活前记得解冻

为了藏住账号，有人会把带账号的应用冻结掉再去激活。官方明确提醒：**激活完成后或重启前要解冻**，一直冻着可能造成设备开不了机。冻结只是临时手段，最终以 `dumpsys account` 查不到账号为准。

## 八、adb 报错原文速查

命令行不会说中文，认准这几句原文就知道撞上哪一节：

| 报错原文 | 对应处理 |
| --- | --- |
| `Not allowed to set the device owner because there are already some accounts on the device` | 第一节：清账号 |
| `Not allowed to set the device owner because there are already some users on the device` | 第二节：删其他用户 |
| `Trying to set the device owner, but device owner is already set` | 第三节：位置被占（见 [怎么停用和卸载.md](怎么停用和卸载.md)） |
| `ProvisioningPreCondition 99` | 第四节：OPPO 系签名限制 |

以上四条来自官方讨论区整理的问题清单；命令输出是一段乱码、或只在 Dhizuku 里看到提示时，按第六节的顺序排查。
