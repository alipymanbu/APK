## 一、一句话概括

Shizuku 把 **ADB（shell）权限**分享给应用，Dhizuku 把 **设备所有者（Device Owner）权限**分享给应用。两者都是「让普通应用借到高权限」的中间件，但借出去的东西不同，因此激活门槛、重启后的表现、能配合的应用都不一样。

## 二、对照表

| | Dhizuku | Shizuku |
| --- | --- | --- |
| 分享的权限 | 设备所有者（Device Owner） | ADB shell 权限 |
| 激活方式 | 一条 adb 命令，或应用内走 Shizuku | 无线调试 / 连电脑 / root 启动 |
| 重启后 | **依然有效**，不用重新激活 | 服务要**重新启动**（root 开机自启除外） |
| 激活前提 | 设备无账号、无其他用户、所有者位置空着 | 无这些限制 |
| 典型能力 | 隐藏应用、暂停应用这类设备管理操作 | 更广泛的系统与应用管理接口 |
| 配套应用数量 | 较少（接入 Dhizuku 接口的应用） | 很多（生态成熟） |
| Root | 不需要 | 不需要 |

## 三、怎么选

- **你手机不能 Root，又不想每次重启都重新激活** → 先看你要用的应用支不支持 Dhizuku，支持就优先它。
- **你要用的应用只提供了 Shizuku 模式** → 用它，这类场景下 Shizuku 的激活门槛反而更低。
- **两者可以并存**：它们是相互独立的两套授权通道，同一个应用用哪个模式，就走哪条通道。

## 四、Dhizuku 的代价

设备所有者是 Android 里最高的管理身份，位置又只有一个，所以激活条件苛刻：**必须先清空所有账号与用户**，激活完成才能重新登录。此外支持它的应用比 Shizuku 少——应用得主动接入 Dhizuku 接口才能借到权限，不能像 Shizuku 那样「接上 shell 就能用」。

反过来说，这份身份是持久的：冻结类、隐藏类工具可以长期稳定工作，不用在每次重启后补一次授权。

## 五、和直接 Root 比呢

Root 能做到的事比设备所有者更多，两者不是一层级。社区里对这套方案的普遍看法（综合多个独立论坛的讨论，**非官方口径**）：

- **设备已 Root 时，Dhizuku 的意义不大** —— Root 本来就覆盖它的能力范围；
- Dhizuku 的价值在**不能 Root 的设备**：不改系统分区、不动 Bootloader、不引入 Root 带来的兼容性问题，却能拿到隐藏 / 暂停这类管理能力；
- 代价是身份绑定在这一个应用上，激活与撤销都比 Root 麻烦。

要不要折腾它，先看你的设备能不能 Root：能 Root 且你已用 Root 方案跑起来了，就不必换；不能 Root，它才是值得做的那条路。

## 六、与「直接 adb 激活」的关系

冰箱、小黑屋这类应用也支持把自己直接设成设备所有者，效果和「Dhizuku 占着位置、别人来借」是同一个位置、只能有一个。区别在于：直接激活时身份绑定在那个应用上，卸它之前得先移除身份；走 Dhizuku 则由 Dhizuku 一家占位，多个应用共用这一份权限。你的设备更适合哪种，取决于你打算配合几个应用用，参考 [能配合哪些应用使用.md](能配合哪些应用使用.md)。
