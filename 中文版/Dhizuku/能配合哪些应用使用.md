# 能配合 Dhizuku 使用的应用有哪些

> Dhizuku 自己不提供冻结、隐藏功能，真正干活的是接入了它的那些应用；这篇列清楚有哪些、怎么授权、各自能做什么。

## 一、Dhizuku 在这条链路里的位置

你需要先完成 [DeviceOwner激活教程.md](DeviceOwner激活教程.md)，让 Dhizuku 拿到设备所有者身份；然后在目标应用里把工作模式切成「Dhizuku」，它向 Dhizuku 申请权限，你在弹窗里点允许，之后这份权限就一直可用。**没激活就去切模式，应用会直接提示不可用**，先回头激活。

## 二、接入了 Dhizuku 的应用

以下是官方资料与各应用文档明确提到支持 Dhizuku 模式的开源工具：

| 应用 | 用途 | 走 Dhizuku 时能做什么 |
| --- | --- | --- |
| Hail（雹） | 冻结 / 隐藏应用 | 隐藏、暂停 |
| Amarok | 隐藏应用与文件 | 应用隐藏 |

**Hail 的能力边界值得单独说**：同一个应用在不同授权模式下能做的操作不一样 —— Root 与 Shizuku（root）模式能强停、停用、隐藏、暂停、重装系统应用；而 **Dhizuku 模式只支持「隐藏」和「暂停」**，不支持强停与停用。选模式之前先想清楚你要哪种冻结力度：

- **隐藏**：应用从桌面和已安装列表里消失，数据与包都还在，随时可恢复；
- **暂停**：图标变灰、通知被拦、点了会弹「应用已暂停」，但后台仍可能运行；
- **停用**：彻底停掉（Dhizuku 模式下拿不到）。

Amarok 那侧同理，它的文档把 Dhizuku 模式列为**未 Root 设备的推荐选择**，理由正是重启后不用重新激活。

## 三、授权的通用步骤

1. 确认 Dhizuku 首页显示已激活；
2. 打开目标应用 → 设置 → 工作模式，选带「Dhizuku」字样的选项；
3. 应用弹出 Dhizuku 授权请求，点允许；
4. 回到应用首页试一次实际操作（比如隐藏某个测试应用），能生效即授权成功。

**冻结类操作的通用注意**：用某个模式冻住的应用，要用**同一个模式**解冻。中途换模式（比如从 Dhizuku 换到 Shizuku），原来冻着的应用可能解不开，先在原模式下解冻再切。

## 四、应用列表之外的情况

Dhizuku 只能给**主动接入了 Dhizuku 接口**的应用发权限；市面上更多的工具只接了 Shizuku 或只支持直接 adb 激活，这类应用在 Dhizuku 这里借不到权限。挑工具前先看它的工作模式列表里有没有「Dhizuku」字样，没有就别指望它能配合使用 —— 你可以转而看 [和Shizuku的区别.md](和Shizuku的区别.md) 决定走哪条通道。

**有用户反馈的两类情况**（未见官方汇总，仅供参考）：

- 作者 iamr0s 自己开发的安装器 **InstallerX**、以及部分玩机工具箱会调用 Dhizuku 权限；
- **炼妖壶（Island / Insular）、冰箱**这类应用即使自身支持设备管理员模式，也**不会主动调用 Dhizuku** —— 它们走的是各自独立的身份通道，别把它们装上就切模式。

也就是说，能配合 Dhizuku 的应用数量目前仍偏少，装之前先确认模式列表，别为了它专门卸掉已有的授权方案。

## 五、给开发者

要让你的应用支持 Dhizuku，接入的是官方的 Dhizuku API 项目：[github.com/iamr0s/Dhizuku-API](https://github.com/iamr0s/Dhizuku-API)。应用接入后即可向 Dhizuku 申请设备所有者能力，用户侧的表现就是上面第三节那个授权弹窗。
