## 一、选项总览

界面上能勾的选项大致对应这几类能力，勾得越多、处理越重：

| 选项类别 | 管什么 | 勾了之后的直接效果 |
| --- | --- | --- |
| 字符串加密 | 藏起代码里的字符串常量 | 接口地址、密钥之类的明文搜不到了 |
| 类加密 | 把整个类加密挪离原位置 | 反编译工具开包后看不到对应类的内容 |
| 混淆 | 替换类名、方法名 | 代码面目全非，梳理逻辑的成本大幅上升 |
| 资源与资产加密 | 处理 res、assets 里的文件 | 图片、配置、内置网页等内容不能被直接抠走 |
| 隐藏敏感 API 调用 | 掩蔽对关键 API 的调用点 | 定位关键功能入口变难 |
| 完整性检查 | 注入签名校验、内容校验 | 包被改动后运行时会发现，防二次打包 |

两个常被问到的对照：

- **和 ProGuard 什么关系**：混淆这一类和安卓构建链里的 ProGuard 思路类似，区别是你不需要源码、不需要构建环境，直接处理现成的 APK 就行；
- **「增强型加密」是什么**：有教程提到这类选项会自动识别原程序里已有的类、把它们用到加密环节里；不开它也能完成基础保护，开不开看你对强度和速度的取舍。

## 二、第一遍怎么勾

第一次处理建议用最小组合，先保证"能出包、能启动"：

1. 只勾**混淆**和**字符串加密**；
2. 跑完装上，核心功能过一遍；
3. 没问题再逐类加（类加密、资源加密、完整性检查），每加一类就重验一次。

一次全勾是最常见的踩坑方式——出了问题分不清是哪一项导致的。

## 三、按场景取舍

| 你的情况 | 建议 |
| --- | --- |
| 给自己的应用上一层基础保护 | 混淆 + 字符串加密就够了 |
| 应用里有授权校验、内购、密钥逻辑 | 再加隐藏敏感 API 调用 + 完整性检查 |
| assets 里放了配置、网页、数据文件 | 加资源与资产加密 |
| 应用启动本来就偏慢 | 谨慎加类加密，加密项越多启动开销越大 |

字符串加密的取舍方向可以参考同名桌面版官方手册对同名机制的建议：集中在真正敏感的内容（密钥、接口地址、授权逻辑这类），开源库和无关键值不必全量勾——全量加密对启动速度不划算。

## 四、勾多了会怎样

- **启动变慢**：加密的类要在启动时还原，全量加密的包启动时间明显拉长；
- **偶发闪退**：个别机型、个别目标应用对某些选项敏感，减项重跑是最快的定位办法，排错步骤见 [加密后无法安装怎么办.md](加密后无法安装怎么办.md)；
- **排查变难**：混淆改了类名方法名，崩溃日志里的堆栈对不上源码，出问题自己都看不懂。

## 五、对保护强度要有数

这些选项提高的是逆向成本，不是绝对防线。要更高强度的方案（进构建流程、运行时防护、企业级能力），看 [与桌面版同名工具的区别.md](与桌面版同名工具的区别.md)，那里讲的是另一套同名桌面工具。
