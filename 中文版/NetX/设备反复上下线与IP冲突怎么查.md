## 一、本篇解决什么

和「一台设备死活扫不出来」不同，IP 冲突的表现是**它在列表里反复出现又消失**、两台设备抢同一个地址、或者某台设备能连上 Wi-Fi 却上不了网。这种情况扫得越勤越容易看出来，正好用 NetX 当观察窗口。两者的区分：

- 稳定地没有这台设备 → [扫描不到设备怎么排查.md](扫描不到设备怎么排查.md)
- 有，但时有时无、或者编号对不上 → 本篇

## 二、先在扫描结果里确认是冲突

连扫三次（手势见 [局域网设备扫描结果怎么看.md](局域网设备扫描结果怎么看.md) 第二节），对着列表核对这三条，命中任一条基本可以断定是 IP 冲突：

1. **同一个 IP 对应了两个不同的 MAC 地址** —— 地址被两台设备抢着用。
2. **同一个 MAC 反复换 IP**，或者同一台设备的 IP 每次扫描都在变。
3. **某台设备的厂商、名字一会上线一会空**，配合它自己报「网络受限」。

把有嫌疑的 IP 和 MAC 抄下来，接下来按成因找修法。

## 三、三种常见成因与对应修法

| 成因 | 你会看到什么 | 怎么修 |
| --- | --- | --- |
| 手动静态 IP 撞进 DHCP 自动分配范围 | 时好时坏，重启某台设备后又复发 | 把静态 IP 改到地址池之外，或干脆改回自动获取 |
| 静态 IP 填了路由器自己的地址 | 那台设备频繁掉线、网页打不开 | 改掉 —— 比如路由器管理地址是 `192.168.1.1`，设备就别用它 |
| 内网里有第二台路由器/设备也在发地址（DHCP） | 不同设备拿到互相矛盾的网段、网关 | 关掉小路由器的 DHCP，或把进线接到它的 LAN 口；实在不需要就拔掉 |

补充几点：

- **确认方法**：在电脑上用 `arp -a` 看同一个 IP 是不是挂着两个 MAC；Windows 上 `ipconfig /release` 后重新获取，看新地址是否仍与别人重复。
- **重启的顺序有讲究**：发现冲突后重启冲突的那台设备让它重新拿地址即可，**别同时重启路由器** —— 一起重启可能什么都没解决（厂商支持文档里的明确提醒）。
- **地址池规划**：让静态地址统一落在 DHCP 发放范围之外，比如池子设成 `192.168.1.50` 到 `192.168.1.200`，静态设备用 2~49，从此不再撞车。
- **别用 MAC 过滤当解法**：它挡不住地址重复，也管不住换了网卡的设备。

## 四、确认修好了没有

回到 NetX，下拉重扫两到三次：

1. 每个 IP 只对应一个 MAC；
2. 常用设备的 IP 不再来回跳；
3. 之前「掉线」的那台设备自己报网络正常。

三条都满足就算收工。仍有设备时有时无，但 IP 已经稳定不重复 —— 那就不是冲突，改走 [扫描不到设备怎么排查.md](扫描不到设备怎么排查.md) 第二、三节查可见性。

## 五、和网速问题分开

地址被两台设备抢着用，整个局域网都会跟着变卡。但**「网页开得慢、视频卡」不等于冲突**：

- 只是慢、设备列表一直稳定 → 看 [WiFi信号与信道拥堵怎么看.md](WiFi信号与信道拥堵怎么看.md) 的信道图与上下行速率。
- 慢 + 设备编号乱跳、时有时无 → 先按本篇处理冲突。

修完网络还想留一份设备台账，可以把列表导出，见 [局域网设备扫描结果怎么看.md](局域网设备扫描结果怎么看.md) 第八节。
