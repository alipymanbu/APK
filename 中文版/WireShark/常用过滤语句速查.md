## 一、先看清输入位置

两种过滤器语法不同、输入位置也不同——把一种语法抄到另一个位置，要么报错要么抓不到东西。区分方法见[过滤器使用指南.md](过滤器使用指南.md)，这里只放语句。以下写法来自 Wireshark 系工具的通用规则，具体可用字段以应用内的过滤输入为准。

| 你想做的事 | 用哪种 |
| --- | --- |
| 抓包之前就只要某类流量 | 捕获过滤 |
| 抓完之后再挑着看 | 显示过滤 |

## 二、显示过滤速查（抓完后筛）

| 想看什么 | 写法 |
| --- | --- |
| 某台设备的所有往来 | `ip.addr == 192.168.1.100` |
| 只要发出的 | `ip.src == 192.168.1.100` |
| 只要收到的 | `ip.dst == 192.168.1.100` |
| 某个网段 | `ip.addr == 192.168.1.0/24` |
| 某个 TCP 端口 | `tcp.port == 443` |
| DNS 流量 | `dns` |
| HTTP 流量 | `http` |
| 其中 HTTP 的请求包 | `http.request` |
| 排除 ARP 噪声 | `not arp` |
| 组合条件 | `ip.addr == 192.168.1.100 and tcp.port == 443` |
| 满足其一即可 | `http or dns` |
| 包长超过某值 | `frame.len > 500` |

逻辑词 `and` / `or` / `not` 与符号写法 `&&` / `||` / `!` 等价，可混用；加括号能改变组合顺序。

## 三、捕获过滤速查（开始前限定）

| 想抓什么 | 写法 |
| --- | --- |
| 只抓某台设备的 | `host 192.168.1.100` |
| 只抓某网段 | `net 192.168.1.0/24` |
| 只抓 DNS（53 端口） | `port 53` |
| 只抓 TCP 某端口 | `tcp port 443` |
| 某设备的 HTTPS | `host 192.168.1.100 and tcp port 443` |
| 排除某台设备 | `not host 192.168.1.100` |
| 去掉广播噪声 | `not broadcast and not multicast` |

注意两套语法的差别：同样是「443 端口的 TCP」，显示过滤写 `tcp.port == 443`（带点、有等号），捕获过滤写 `tcp port 443`（空格分隔、无等号）。混着写是新手最常见的报错原因。

## 四、几个实用组合场景

- **排查「App 连不上服务器」**：捕获过滤留空全抓，抓完先输入 `dns` 看域名解析出了什么地址，再按那个地址过滤，顺藤摸瓜；
- **只关心一台设备**：捕获阶段就写 `host 设备IP`，记录量能小很多，手机存储和翻页压力都小；
- **列表被广播包刷屏**：显示过滤输 `not arp` 立刻清爽；确认不需要 ARP 信息的话，下次捕获时就写 `not arp`。

语句抄了还是抓不到、筛不出，去[常见问题排查.md](常见问题排查.md)按清单过一遍。
