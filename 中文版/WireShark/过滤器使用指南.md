## 一、先分清两种过滤器

一句话区分：**捕获过滤器在抓包前生效，只记录符合条件的流量；显示过滤器在抓包后生效，从已记录的包里筛出你要看的**。手机上抓包最容易踩的坑就是把两种概念混用——在错误的位置输入了条件，结果要么一个包都没抓到，要么抓了一堆但筛不出来。

| | 捕获过滤器 | 显示过滤器 |
| --- | --- | --- |
| 生效时机 | 开始捕获之前 | 捕获之后，随时可改 |
| 作用 | 减少记录量 | 从记录里挑着看 |
| 改了之后 | 需要重新开始抓包 | 立即生效，不动数据 |
| 适合场景 | 明确只看某类流量 | 抓了一大堆再慢慢筛 |

建议的用法：不确定要抓什么时，捕获阶段先不加过滤、全部记下来，回头用显示过滤器筛。多抓只是文件大一点，漏抓却没法补救。

## 二、显示过滤器怎么写

显示过滤的思路是「按字段给条件」。Wireshark 系工具常见的写法形如：

```text
ip.addr == 192.168.1.100
ip.addr == 192.168.1.0/24
tcp.port == 443
http
http.request
dns
```

第一行只看与某台设备的往来，第二行换成整个网段，第三行只看某个端口，后三行直接按协议名筛（`http.request` 比 `http` 更进一步，只留请求包）。多个条件可以用 `and` / `or` 组合，比如「某台设备的 HTTPS 流量」就是地址条件与端口条件的交集。

具体到 WireShark 安卓版，可用的字段与语法以应用内的过滤输入为准；条件写错时过滤不会生效，核对写法再试即可。想直接抄语句，翻[常用过滤语句速查.md](常用过滤语句速查.md)，那里把显示过滤与捕获过滤的常用写法各整理成了一张表。

## 三、用颜色规则快速分拣

你可以给不同类型的流量设置着色规则：同一类协议或同一类事件在列表里显示同一个颜色，扫一眼就能把 DNS、TCP、HTTP 之类的流量分开。抓包时间一长，颜色分拣比逐行读协议名快得多。规则可以自己按协议、地址等条件来定义，顺序上把最常看的放前面。

## 四、统计视图：不逐包看，直接看汇总

逐包看细节之前，先看统计汇总往往更快。会话统计告诉你谁和谁通信最多，端点统计列出参与通信的所有地址，协议层级统计给出各类流量占比。排查「手机到底在和哪些服务器通信」这类问题时，先看协议层级与会话两三下就能锁定大头，再针对大头设显示过滤深入看。

## 五、一次典型排查的完整链路

1. 抓包（流程见[抓包教程.md](抓包教程.md)）；
2. 打开协议层级统计，看流量由什么构成；
3. 用显示过滤把无关协议筛掉；
4. 还嫌乱就再叠加一条地址或端口条件；
5. 定位到可疑的包，进详情树逐层看。

筛不出来、列表异常之类的问题，多半能在[常见问题排查.md](常见问题排查.md)里找到对应条目。
