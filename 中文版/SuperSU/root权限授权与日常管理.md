## 一、授权弹窗：每次 root 请求都由你拍板

任何应用想动用 root，屏幕上都会先弹出 SuperSU 的请求框：写着应用名和请求来源，下面是「允许（Grant）」和「拒绝（Deny）」两个按钮。

操作要点：

- **弹窗有倒计时**，你一直不点，倒计时结束默认按"拒绝"处理，不会自动放行——这个设计对没盯着屏幕的你来说是安全的。
- 弹窗里可以**记住选择**：勾上之后同一应用下次不再询问，直接按你这次的决定走。常用的、信得过的工具才建议勾。
- 判断原则很简单：**叫不上名字的应用先拒绝**。拒绝不会破坏任何东西，真需要权限的应用会再弹，或者你在日志里看到后回头给它开。

## 二、日志：谁在什么时候要过 root

主界面的「日志」页记录每一次 root 请求：应用名、时间、被执行的命令、你是允许还是拒绝。

它有两个实际用途：

1. **排查"这个应用为什么没权限"**——它到底有没有发起请求、被谁拒了，日志一眼可见。
2. **发现不该出现的请求**——某个你从没授权过的应用出现在日志里，就该警惕了。

日志保留量有限，重要问题尽早翻。

## 三、通知与弹窗行为

设置里可以控制请求怎么"提醒"你：

- **按应用配置通知**：给指定应用单独开关通知。重要工具的请求开提醒，其余靠弹窗就够。
- **来请求时点亮屏幕（Wake on prompt）**：锁屏状态下有应用要 root，屏幕自动亮起，避免请求在黑屏里干等超时。
- 深夜被弹窗打扰，就检查这两处配置。

## 四、默认访问策略

设置里的「默认访问」决定没经过你拍板的请求怎么处理，三档：

| 档位 | 行为 | 适合 |
| --- | --- | --- |
| 询问 | 每次都弹窗等你决定 | 默认值，大多数人停在这档就够 |
| 允许 | 不问直接放行 | 几乎不建议，root 机器上等于不设防 |
| 拒绝 | 不问直接拒绝 | 保守玩法：新应用一律先拒，要用再单独开 |

已授权过的应用随时可以反悔：在「应用」页里点进具体应用，改它的授权或删掉记录即可。

## 五、临时取消 root（Temporary unroot）

银行、支付这类应用一旦检测到 root 就拒绝运行。Temporary unroot 就是给这种场景准备的临时开关：

- 开启后，**所有 root 请求都拿不到权限**，包括之前已授权的应用；
- 到时间（或你手动恢复、或重启）之后，root 自动回来；
- 送修手机之前也建议临时关一次，免得维修人员拿到一台处于 root 状态的机器。

注意两点：一是它只挡"请求"，不抹掉 root 痕迹，对检测较严的应用不保证有效；二是恢复方式记住一种就够——设置里再点一次即可。

## 六、图标、主题与隐形入口

- 图标有 5 种可选，其中一种是"隐形"——桌面上看不到 SuperSU；
- 隐身后从**拨号盘**进：输入 `*#*#1234#*#*` 或 `*#*#7873778#*#*`（后者即 `*#*#SUPERSU#*#*` 的字母版）。部分机型对双 `*#*#` 不认，改用单个 `*#` 开头的写法试；
- 主题有 4 种配色，纯观感问题，随喜好选。

## 七、Pro 版多出来的功能

SuperSU 的付费授权（Pro）在免费版之上加了几项，列出来供对号入座：

| 功能 | 说明 |
| --- | --- |
| OTA 存活模式 | 系统更新时尽量保住 root（官方注明不保证） |
| 全色命令日志 | 日志按输入/输出/错误分色，看得更细 |
| 按应用日志配置 | 指定某应用记多细 |
| 按应用用户覆盖 | 对单个应用覆盖全局策略 |
| 限时授权 | 给某应用 N 分钟 root，到点自动收回 |
| PIN 保护 / 按应用 PIN | 进 SuperSU 或对指定应用授权前要输 PIN |
| 自动拒绝倒计时调整 | 弹窗倒计时长短可调 |

两点背景：应用内购买项目按官方描述只是捐赠性质、不解锁任何功能；Pro 是独立授权文件，需要与主应用搭配使用。要不要买自己权衡——日常授权管理，免费版已经够用。
