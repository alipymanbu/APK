# SuperSU 常见问题与报错处理

> 本篇汇总 SuperSU 用起来最常撞上的几类问题：SU 二进制相关报错、授权弹窗不出现、卡开机、OTA 更新失败，以及银行类应用检测 root 的应对。

## 一、"SU 二进制需要更新"（SU binary needs to be updated）

**这不是报错，是正常流程。** SuperSU 要把它配套的 su 二进制装进系统才能干活：

1. 弹窗时点「继续（Continue）」；
2. 方式选 **Normal（常规）**；
3. 等它跑完，按提示重启。

卡在更新不动、反复提示更新失败 → 系统层写入没成功，多半是设备其实没 root 成功，回卡刷 ZIP 那条路重刷（见 [下载与安装教程.md](下载与安装教程.md) 第四节）。

## 二、"没有安装 SU 二进制"（There is no SU binary installed）

这个提示含义很直接：**系统里根本没有 su**，也就是设备并没有 root 成功。常见两种来由：

- 只装了 APK、从来没刷过 ZIP → APK 只是管理界面，root 本体得靠卡刷 ZIP。重刷一遍即可，流程见 [下载与安装教程.md](下载与安装教程.md) 第四节；
- 之前 root 过、后来被系统更新冲掉了 → 重新刷 ZIP，或考虑换方案（见第八节）。

Android 模拟器场景另说：官方模拟器镜像自带 root 通道（`adb root` 即可），在这类环境装 SuperSU 前要先把环境备好，完整步骤见 [安卓模拟器root配置指南.md](安卓模拟器root配置指南.md)。

## 三、"SU 二进制被占用"（SU binary occupied）

系统里已经有一套别的 su（之前装过其他管理器），SuperSU 接管不了：

1. 先把原有的 root 管理器处理干净：在它里面执行"完整取消/卸载"，或走 SuperSU 的卸载流程（见 [完整卸载与取消root方法.md](完整卸载与取消root方法.md)）；
2. 重启后再装 SuperSU，按提示更新二进制。

从 KingRoot 这类一键工具迁移过来的场景（设备 root 是 KingUser 给的），有专门的接管流程，见 [替换KingRoot一键root.md](替换KingRoot一键root.md)。

## 四、授权弹窗一直不出现

应用明明需要 root，SuperSU 却没动静，按这个顺序查：

1. **看 SuperSU 的日志页**——有记录 = 请求发生过，只是你没看到弹窗（锁屏着、或者误勾了记住拒绝）；没记录 = 应用压根没发成功；
2. **通知权限**——弹窗被系统通知权限拦掉的情况存在，检查 SuperSU 的通知权限；
3. **应用本身**——部分应用 root 失败时会静默降级，什么都不弹。换一个已知会弹窗的工具（比如终端模拟器里执行 `su`）来测最直观。

## 五、刷完卡在开机第一屏

- 第一次开机明显变慢是**正常现象**，等三五分钟很常见，别急着强制重启；
- 超过 10 分钟还卡着：回 TWRP，用你刷机前做的备份还原——这就是为什么刷前要做 Nandroid 备份；
- 三星 Nougat 时期部分机型有加密分区的坑，卡开机可能与加密状态有关，先查你这个机型的专门教程再重试。

## 六、系统更新（OTA）失败，提示"系统已被修改"

root 动过系统层，官方 OTA 校验不过属于预期行为。可选的路：

- 放弃 root → 完成更新 → 再重刷一遍（重复安装流程）；
- 付费版 Pro 的 OTA 存活模式可以试，但官方明确写"不保证"；
- 需要长期 OTA 与 root 并存的，这正是 Magisk 方案的强项，见 [与Magisk的区别及怎么选.md](与Magisk的区别及怎么选.md)。

## 七、银行、支付类应用检测到 root

- 急用：开**临时取消 root**（Temporary unroot）再用，用完恢复。开关在设置里，用法见 [root权限授权与日常管理.md](root权限授权与日常管理.md)；
- 长期：部分应用连"曾经 root"都能检测出来，临时方案不保证全过；这类需求的主流解法是 Magisk 的隐藏能力。

## 八、Android 10 及以上还能用吗

不建议。SuperSU 的官方版本线停在 2.82（2017 年，SR 修补版到 SR5 为止），新系统引入的分区与验证机制它没跟上；社区口径是大约可用到 Android 9。更新的设备直接走 Magisk；老机型、老 ROM 上，它依然是顺手的那个选择。

## 九、TWRP 刷 ZIP 报 Error 1（updater process ended with ERROR: 1）

刷入中断、日志里出现 "Error: 1"，社区案例里最常见的三类成因，按顺序排查：

1. **ZIP 文件本身损坏**——下载不完整、拷贝中改坏了。重新取一份干净的，比对文件大小是否与来源标注一致；
2. **boot 镜像与当前固件不匹配**——部分机型（华为等品牌案例较集中）的刷入脚本要处理 boot 分区，固件版本对不上就报 Error 1。处理办法按机型教程来，通常是重刷与当前固件对应的原版 boot 再试；
3. **recovery 版本太旧**——老版 TWRP 对新固件的分区结构支持不全，换新版 TWRP 再试。

三条都试过仍报错，说明这套 ZIP 对该机型支持不佳，换 Magisk 路线通常能绕开（见 [与Magisk的区别及怎么选.md](与Magisk的区别及怎么选.md)）。
