# Anikku 换源迁移指南

> 某个源挂了、更新慢了、想换到更好的源——换源迁移（Migration）让你把番搬到另一个源而不丢进度。本篇讲两个迁移入口怎么用、哪些数据会跟着走、以及迁移最容易踩的「下载残留」坑。

## 一、先分清两种「迁移」

用 Anikku 时「迁移」这个词出现在两个完全不同的场景，别混：

| 场景 | 干什么 | 用什么 |
| --- | --- | --- |
| **应用间搬家** | 从 Aniyomi 等旧应用把书架搬进 Anikku，或换手机 | 备份文件（`.tachibk`），见 [备份与数据迁移](备份与数据迁移.md) |
| **应用内换源** | 同一部番从 A 源挪到 B 源 | 本篇的换源迁移功能 |

换源迁移的典型触发时机：原源关闭或失效、另一个源更新更快、原源画质/字幕差。官方在迁移指南开头就给了一条警告：**迁移前先做一次备份**，以防迁移结果不符合预期。

## 二、迁移的两个入口

### 从单部番迁移（最常用）

1. 在书架里点进这部番；
2. 右上菜单（Overflow）→ **Migrate**；
3. Anikku 会对所有已安装并启用的源做一次全局搜索，找到候选后，选你要迁去的源；
4. 确认后在右上角选 done 完成。

搜索结果里没有这部番、或匹配到的不是它：点 Overflow → **Search manually** 手动搜。

### 从整个源迁移（源要挂了时批量搬）

1. 底部导航进 **Browse**；
2. 顶部切到 **Migrate** 标签（在 Extensions 旁边）；
3. 选要迁出的源，勾选要搬的番；
4. Anikku 全局搜索后，点候选番的缩略图选目标源；
5. 勾选要带过去的数据（进度、分类等），确认完成。

新版还提供迁移配置页：可以挑选并优先排序目标源，批量迁移时匹配更省心（该能力随版本更新引入，你的版本里有没有以应用内界面为准）。

## 三、什么会跟着走、什么不会

迁移时应用会让你勾选要转移的数据；但有一条官方标了 DANGER 的硬限制：

> **已下载的剧集不会跟着迁移走。**

迁移只是把「番的记录」从 A 源改挂到 B 源，已经下载到你手机的剧集文件是按 A 源的结构存的，迁移后它们可能被留在原地成为残留。官方的处置办法：迁移完成后用文件管理器到下载目录里**手动删除这些残留文件**。

所以批量弃用某个源之前，先想清楚哪些番的已下载内容还想保留——想保留的就别迁移，直接让它们留在旧源上看本地下载（旧源挂了不影响已下载部分，见 [追番与播放设置](追番与播放设置.md) 的离线下载一节）。

## 四、迁移后的核对

迁移完成不等于结束，花一分钟核对：

- [ ] 番还在书架原分类里、进度没有回退；
- [ ] 追踪服务上的记录还是同一条（迁移不该产生重复条目）；
- [ ] 新源能正常打开这一话（打不开的排查见 [常见问题排查](常见问题排查.md)）；
- [ ] 下载目录里没有残留的旧源文件夹；
- [ ] 批量迁移的话，检查有没有漏网之鱼（搜索没匹配到的番还挂在旧源名下）。

迁移没找到想要的目标源？那不是迁移的问题，是目标源的扩展还没装——先去 [扩展与内容源配置](扩展与内容源配置.md) 把源配齐再回来。
