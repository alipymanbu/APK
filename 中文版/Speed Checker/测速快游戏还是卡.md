## 一、两个「ping」测的不是同一条路

Speed Checker 报告的 ping，是你到**测速服务器**的往返时间——这类服务器通常就在运营商网络里、离你近、线路好，所以数字往往很漂亮。而游戏里显示的延迟，是你到**游戏服务器**的往返时间：它可能在另一个地区，中间要绕更多的节点，服务器本身还可能有负载。

两个数字差两三倍是正常现象，不代表你的网络有问题。**判断游戏体验，以游戏内显示的延迟为准**；测速 ping 只能说明「你的线路本身响应快」，不能说明「到这个游戏快」。

| 情况 | 更可能的原因 |
| --- | --- |
| 测速 ping 低，游戏延迟也低 | 线路正常，没有可优化的 |
| 测速 ping 低，游戏延迟高 | 到该游戏服务器的路由远或绕路，与你的宽带无关 |
| 测速 ping 高，游戏延迟也高 | 线路本身响应慢，回到 [测速不准怎么办.md](测速不准怎么办.md) 排查 |

## 二、空载很快、一用就卡：队列膨胀

有一类问题测速永远查不出来：**bufferbloat（缓冲区膨胀）**。路由器和光猫里有一段排队用的缓冲区，平时队列是空的，所以空闲时 ping 很低；一旦有大流量把线路占满——别人开始看 4K 视频、电脑在系统更新、云相册在备份——你的游戏数据包就得排在这批大流量后面慢慢等。

典型症状：

- 一个人用时一切正常，家里人一开始看视频或下载，游戏立刻卡；
- ping 平时 20ms，大下载一开就冲到 200ms 甚至更高；
- 语音开黑时，一上传文件队友就听不清你说话；
- 下载还在全速跑，但网页点开要等两三秒。

**自查方法**：先在空闲时测一次 ping 记下来；再让另一台设备跑一个大文件下载（或自己开一个），同时再测一次。满载后延迟只涨几十毫秒属于健康；涨几百毫秒就是队列膨胀。

**缓解办法**（按有效程度排）：

1. 进路由器管理后台找 **SQM / 智能队列 / 智能 QoS**（有些品牌叫 Smart Queue Management，底层多是 Cake 或 fq_codel 算法），开启后它会把队列控制在很短；
2. 路由器没有智能队列的话，用普通 QoS 把上下行限速到**实测速率的 90%~95%**——让路由器先于线路饱和接管排队，效果差一些但同样能把延迟压平；
3. 把大下载、备份安排在没人打游戏的时间段。

注意：**升级更大带宽的套餐对这个问题的帮助很有限**——队列还是在，只是填满得更快。这是设备侧的排队问题，不是带宽不够。

## 三、平均延迟低但忽高忽低：抖动

比平均延迟更伤游戏的是**抖动（jitter）**——延迟在两次测量之间的波动。平均 20ms 但每隔几秒冲到 120ms 的线路，体验明显差于稳定 60ms 的线路：前者会让你的操作时而正常时而「瞬移」（rubber-banding）、射击判定时准时不准。

Speed Checker 多测几次、把每次的 ping 记下来对比，就能看出波动幅度。波动大的时候优先怀疑 Wi-Fi 链路（见下一节）或线路上有间歇性的大流量。

## 四、各类游戏对延迟的容忍度

不同游戏对延迟的敏感度差异很大，可以作为参考目标（数值为进入游戏后显示的延迟）：

| 游戏类型 | 可接受 | 竞技级 |
| --- | --- | --- |
| 竞技射击（CS、无畏契约类） | 50ms 以内 | 20ms 以内 |
| 大逃杀类 | 80ms 以内 | 40ms 以内 |
| MOBA / 竞技场 | 100ms 以内 | 50ms 以内 |
| MMO / RPG | 150ms 以内 | 80ms 以内 |
| 回合制 / 策略 | 250ms 以上也能玩 | 不敏感 |

## 五、怎么用 Speed Checker 定位原因

按这个顺序做，基本能把「卡」归因到具体环节：

1. **看波动**：连测 3~5 次，ping 稳定 → 排除抖动问题；忽高忽低 → 大概率是 Wi-Fi 链路或线路被间歇性占用；
2. **交叉对比**：Wi-Fi 和移动数据各测一轮。移动数据下游戏正常、Wi-Fi 下卡 → 问题在你家无线链路，按 [Wi-Fi 测速与排查.md](Wi-Fi 测速与排查.md) 处理；两边都卡 → 看第二节做满载测试；
3. **有条件就上有线**：Wi-Fi 通常比有线多出 2~10ms 延迟，还更容易抖动和丢包——竞技类游戏尽量用网线，手机的话至少贴着路由器玩；
4. **换服务器测方向**：换不同地区的测速服务器各测一次（方法见 [测速不准怎么办.md](测速不准怎么办.md)），如果只有某个方向延迟特别高，那是路由问题，找运营商报障时把这个证据带上。
