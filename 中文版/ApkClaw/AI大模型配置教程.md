## 一、为什么必须先配模型

ApkClaw 本身不带大脑：你发的每条指令，都要靠一个大模型看屏幕、想步骤、决定下一步点哪。所以「设置里没填 Key」是最常见的「发消息没反应」原因 —— 权限和通道都对，但模型调用失败，任务根本起不来。配之前先确认[权限已开完](下载与安装教程.md)。

## 二、去哪儿填

打开 ApkClaw 的**设置 → LLM Config（模型配置）**，要填的就四项：

| 配置项 | 填什么 | 说明 |
| --- | --- | --- |
| API Key | 你在模型服务商处申请的密钥 | 配错会直接失败，且不会自动重试（见第四节） |
| Base URL | 模型接口地址 | 默认 `https://api.openai.com/v1`，用别家就换成别家的 |
| 模型名 | 如 `gpt-4o`、`claude-sonnet-4-20250514` | 按服务商文档里的模型标识填 |
| 提供商 | `OPENAI` 或 `ANTHROPIC` | 走 Anthropic 官方接口时选 `ANTHROPIC`，其余选 `OPENAI` |

要点：

- **Base URL 是「接口地址」不是官网地址**。用 OpenAI 兼容服务（含各家自建中转）时，把服务商给的接口根地址整段填进去，末尾一般带 `/v1`。
- **提供商选的是协议**：OpenAI 兼容协议的第三方服务（无论哪家）都选 `OPENAI`；只有直连 Anthropic 官方接口才选 `ANTHROPIC`。
- 手机上的键盘填长 Key 容易错，可以改用电脑填（见[局域网配置方法](局域网配置方法.md)）。

## 三、模型怎么选

ApkClaw 走的是「工具调用」式交互，模型要支持 function calling 才能把指令拆成一步步的屏幕操作。官方页面列出的可选模型包括 MiniMax M2.5、GLM-4.7、Kimi K2.5、DeepSeek-V3.2、Qwen3-Max、GPT-4o、Claude 3.5、Gemini Pro、Llama 3、Mixtral 等（截至 2026 年 9 月，以 [apkclaw.ai](http://apkclaw.ai) 页面为准）。

选型建议（按你实际能拿到的 Key 来）：

- 手边只有国内服务商的 Key → 选一家 OpenAI 兼容的，把 Base URL 换成它的接口地址即可；
- 想要更稳的多步操作 → 用旗舰档模型，长链路任务（连续十几步点击）更少中途跑偏；
- 换模型后不用重装，改完模型名保存即可，下一条指令就走新模型。

## 四、配错时是什么表现

| 现象 | 多半是哪儿错 |
| --- | --- |
| 发消息始终无回复，日志里 401 / 403 | API Key 无效或过期 —— 这类鉴权错误不会自动重试，直接改 Key |
| 发消息无回复，日志里连接超时 | Base URL 填错，或手机当前网络访问不了该接口 |
| 任务总在起不来，日志里报工具调用不受支持 | 该模型不支持 function calling，换一个支持的模型名 |
| 偶发无回复后又自己好了 | 网络抖动 —— 它会自动重试最多 3 次（间隔 1s → 2s → 4s） |

调用失败的排查顺序见[常见问题排查](常见问题排查.md)。

## 五、用电脑填更省事

API Key 往往一大串，在手机上逐字敲很容易错。ApkClaw 自带一个局域网配置页，手机电脑连同一个 WiFi，浏览器打开就能在键盘上填 —— 方法见[局域网配置方法](局域网配置方法.md)。
