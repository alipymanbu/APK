## 一、先设定期望，再谈优化

Limbo Plus 模拟 x86 硬件靠的是指令翻译，没有真机的虚拟化加速可用。这意味着：轻量系统（FreeDOS、KolibriOS、小型 Linux）基本秒级开机、操作跟手；Windows 类桌面系统能装能跑，但开机与操作都明显慢，属于「能用来办特定的事」，不是日常主力机的替代。判断优化是否有效，拿同一台虚拟机开机的等待时长做前后对比最直观。

## 二、内存与核心数怎么给

| 配置项 | 建议口径 | 原因 |
| --- | --- | --- |
| 内存（RAM） | 不超过手机运行内存的 1/3；Windows 7 参考 1024~2048 MB | 给大了安卓会拒绝分配（报错或闪退），虚拟机暂停/恢复也会变慢 |
| CPU 核心数 | 与手机实际核心数接近，一般 4~8 | 超过物理核心数没有收益，反而增加调度负担 |
| 指令集优化（多线程） | 先按默认；卡顿或不稳就关掉、核心数降到 1 | 多线程优化能让多个虚拟核心用上多个物理核心，但并非所有设备/系统组合都稳定，社区经验是不稳就退回单核 |

两处联动要记住：核心数改了，「额外 QEMU 参数」里如果写过 `-smp 4,cores=4` 这类参数，两个数字必须跟着改，不一致会卡顿、闪退甚至蓝屏（处理见[常见问题与报错处理.md](常见问题与报错处理.md)第五节）。

## 三、网卡、显卡与音频

- **网卡**：`virtio` 性能最好，但极少数环境下会不通网；遇到「系统里明明联网了配置也对、就是打不开网页」，先换成 `rtl8139` 再试。用 Windows XP 这类老系统选 `rtl8139` 驱动更好找。模拟 e1000 的组合在社区教程里也常用，可以作为第三选项。
- **显卡**：`std` 是通用选择，cirrus 兼容老系统。不用纠结，异常再换。
- **音频**：声音输出依赖用户界面模式，很多配置组合下本来就无声，这不是故障。进 Windows 后也不建议专门装声卡驱动——驱动安装与解码都会吃掉本就紧张的性能，社区经验是保持无声换取流畅度。
- **用户界面（SDL / VNC）**：这项同时决定速度与后台行为——SDL 有声音、画面响应好，但应用切后台或息屏时虚拟机跟着暂停；VNC 没有声音，但更轻，虚拟机能真正在后台继续跑。要挂机选 VNC，要声音选 SDL，切换后要重启虚拟机才生效。
- **刷新率**：设置里分默认与空闲两档，长时间挂机把空闲档调低，画面静止时能省下可观的渲染开销。

## 四、装好 Windows 后的系统内减负

进系统后再做这几件事，桌面响应会明显好转：

1. **关掉索引服务**：开始菜单 → 运行 → 输入 `services.msc` → 找到 Windows Search → 停止并把启动类型设为「已禁用」；
2. **换轻量浏览器**：K-Meleon、Midori 这类轻量浏览器比现代浏览器在虚拟机里可用得多；
3. **不装多余软件**：杀毒、全家桶、桌面美化都别装，虚拟机里每一点性能都值得省；
4. **经典主题**：装 Classic Shell 之类的轻量外壳把桌面切回经典样式，渲染负担更小；
5. **Windows Update** 装完必要补丁就别开着自动更新空跑。

## 五、镜像存放位置

- 镜像文件放**手机内置存储**：速度快、文件选择器好找；路径别太深；
- 外置 SD 卡读写慢，挂载大镜像会拖长开机等待，能不放就不放；
- 镜像体积要与剩余空间匹配：qcow2 虚拟磁盘会随写入增长，留出余量，避免运行中途撑满存储。

## 六、温控与后台

手机降频对模拟速度影响很大：跑一段时间后明显变慢、放下凉一会又变快，多半是温控在起作用，这不是软件故障。长时间跑虚拟机前，把手机壳摘掉、别边充电边跑；系统设置里把 Limbo Plus 加入电池白名单/允许后台运行，避免切出去几分钟虚拟机就被杀掉（被杀的症状与恢复见[常见问题与报错处理.md](常见问题与报错处理.md)）。

配置层面的取舍原则就一条：**先稳定、再提速**。每改一项配置只验证一件事，别一次改一堆，否则出问题定位不了是哪项引起的。挂机场景另有一条要留意：SDL 界面下切到后台虚拟机是主动暂停、不是被杀；想真正息屏继续跑，用户界面要换成 VNC（见第三节）。
