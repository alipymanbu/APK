## 先查当前版本

三种方法，从快到全：

**方法一：设置里搜。** 打开「设置」，在顶部搜索框输入 WebView，点进 Android System WebView（部分机型显示为「系统 WebView」），详情页直接显示版本号。

**方法二：应用列表里翻。** 「设置 → 应用」，右上角菜单勾选「显示系统应用」，找到 Android System WebView，版本号和应用大小都在详情页里。

**方法三：开发者选项看「谁来干这个活」。** 「设置 → 关于手机」里连点「版本号」7 次解锁开发者选项，回到「设置 → 系统 → 开发者选项」，找到「**WebView 实现**」（或 WebView Implementation）——这里显示的才是当前真正在渲染网页内容的那个包。你更新了 WebView 但这里显示的是 Chrome，说明你的设备正由 Chrome 承担这个角色。

版本号的构成有规律可循：它跟随 Chromium 的版本节奏，比如本文收录的 127.0.6533.64 就属于 127 系列。新版本推得勤，你查到的具体数字随时会变，以手机当时显示的为准。

## 更新渠道

| 你的设备情况 | 更新路径 |
| --- | --- |
| 有 Google Play 商店 | Play 商店直接搜 Android System WebView，点「更新」；同时把 Chrome 也更到最新 |
| 无 Play 商店的国行 / 鸿蒙设备 | 走品牌应用商店搜 WebView，或「设置 → 系统更新」随系统升级 |
| 商店里搜不到 | 先试系统更新；WebView 作为系统组件会随厂商固件一起推 |

常见品牌的注意点（截至本文整理时，以各品牌官方说明为准）：

- **小米 / Redmi**：自带应用商店搜 Android System WebView；
- **OPPO / 一加 / realme**：自带软件商店搜 Android System WebView，系统更新入口在「设置 → 关于本机」；
- **华为 / 荣耀**：以华为 / 荣耀应用市场里的浏览器组件与系统更新为主，部分支持 GMS 的机型可单独搜 WebView；
- **三星**：Galaxy Store 或 Play 商店，随系统更新兜底。

更新装完后回到上文方法三确认当前实现已经换到新版本号。更新卡住、一直「等待中」或反复失败的，排查路径单独整理在[更新失败怎么解决](更新失败怎么解决.md)里；更新后反而出问题的处理顺序见[应用闪退怎么修复](应用闪退怎么修复.md)。

## 「WebView 实现」这个开关是干什么的

开发者选项里的「WebView 实现」允许你在设备上可用的实现之间切换（比如 Android System WebView 和 Chrome）。它的用途很明确：网页内容渲染异常时，换一个实现来隔离问题——如果切到另一个实现问题消失，那就锁定问题在原来那个实现上。

用的时候注意三条：

1. 列表里只显示**当前可用**的实现，只有一项就说明没得切，别去装来路不明的 WebView 安装包凑数；
2. 切换后要**重启**才完全生效；
3. 普通使用保持默认即可，这个开关是排查工具，不是优化手段。

## 进阶：预览渠道与 DevTools

给开发者和排障者准备的，普通用户可以不看：

- WebView 有 Beta / Dev / Canary 三个预览渠道（对应包名 `com.google.android.webview.beta` / `.dev` / `.canary`），新功能先在这些渠道走，稳定后再进正式版；
- 装了预览渠道后，用设备上的 WebView DevTools 的「Change Provider」切换实现；Android 16 及以上可从「开发者选项 → WebView DevTools」进入，它同时提供崩溃记录、开发者标志和网络日志三块排查工具。

## 为什么应用商店迟迟不给你推新版

WebView 的更新是分阶段推送的：新版本先放给一小部分设备，观察没有问题再逐步扩大范围，所以同一时刻不同手机的最新版本号可能不一样。你等几天通常就能收到；如果急着用某个新版本才能解决的问题，APK 侧载是另一条路，步骤与注意事项见[下载与安装教程](下载与安装教程.md)。
