# Amarok 隐藏文件的恢复与数据安全

> 用 Amarok 最怕的不是藏不了，而是藏了之后出不来：卸载前忘了取消隐藏、文件打得开打不开心里没底。本篇把「正常恢复」「卸载了怎么救」「手动恢复」三层都写清楚，建议在第一次大范围隐藏之前读完。

## 一、一条铁律：卸载或换机前，先取消隐藏

Amarok 隐藏文件时不加密、不复制、不挪地方，它直接在你原来的文件上改文件名和文件头签名——所以隐藏态的文件用别的应用打开就是「损坏」的样子。这意味着：**Amarok 在，随时一键还原；Amarok 不在了，系统里没有任何东西能认出这些文件**。

因此养成两个习惯：

- 不用 Amarok 了、要恢复出厂、要换机——先在主界面按「取消隐藏」，确认文件全部回来，再动手。
- 想升级或重装 Amarok 本身，先取消隐藏再卸载，装好后重新勾选、重新隐藏。

## 二、正常恢复

主界面一个按钮：按「取消隐藏」，之前藏的文件和应用整体恢复。恢复文件比隐藏稍慢一点，几秒到几十秒，等它跑完再退出应用。

**不要在隐藏或恢复过程中杀 Amarok 的后台。** 官方 issue 里就有真实案例：用户在隐藏几百张照片的过程中把应用从后台划掉，结果只有一部分文件被处理，第二次恢复时一部分照片没能回来。开发者后来给流程加了保护，但别去试探这个底线。

## 三、已经卸载了，怎么救回来

文件还在原位置，只是没人帮你改回来。官方文档给的恢复流程是四步：

1. **重新安装 Amarok**。手头有当初的安装包就直接装；0.9.2 可以从 [Amarok 安装文件资源（夸克网盘）](https://pan.quark.cn/s/3fe5276d0e12)取回，想用最新版则去官方 [GitHub Releases](https://github.com/deltazefiro/Amarok-Hider/releases)。
2. 把应用隐藏模式和文件隐藏模式**设置成与隐藏时完全相同**（比如当时用的混淆方式，现在还得是混淆）。
3. 在「设置隐藏文件」「设置隐藏应用」里**把当初隐藏的文件夹和应用原样加回来**——所以平时记一下自己藏了哪些路径，关键时刻就靠这份清单。
4. 进「更多设置 → 其他 → 强制取消隐藏」，执行。

顺利的话，文件和应用就都回来了。这也是为什么「模式」和「隐藏清单」两样东西要记牢：恢复靠的就是用同样的配置重演一遍隐藏。

## 四、强制取消隐藏也不行时：手动恢复

官方文档给了手动方案，需要一台装了 [ADB](https://www.xda-developers.com/install-adb-windows-macos-linux/) 的电脑，且应用类的命令需要 Root 权限。

**找回被隐藏的应用**（先列出所有被停用的包，再逐个恢复）：

```bash
# 列出所有被隐藏的包
fgrep -v -f <(adb shell pm list packages | sort) <(adb shell pm list packages -u | sort)
# 逐个恢复（包名换成上面列出的）
adb shell su -c "pm unhide 包名 & pm enable 包名"
```

**找回被隐藏的文件**：

- 当时用的是 Root 下的 chmod 方式，直接把权限改回去：

```bash
adb shell su -c "chmod 755 /path/to/hidden/file"
```

- 当时用的是混淆方式：文件的前 8 个字节被按位取反了一遍，再取反一次就还原。用十六进制编辑器打开文件，把前 8 字节逐个按十六进制反码改回（`1` 与 `F` 互换、`2` 与 `E` 互换，以此类推）。这是逐文件的手工活，只适合抢救个别重要文件；文件多就用第三节的强制取消隐藏流程。

## 五、让以后不用翻这一篇

- 隐藏清单（藏了哪些文件夹、哪些应用）单独记一份，纸上或备忘录里都行。
- 模式选择一旦定了就别换来换去，恢复时要对得上。
- 隐藏、恢复、升级前，都先看一眼 Amarok 是不是还在跑，跑完再切走。
- 官方免责声明写得很直白：使用隐藏类工具造成的数据损失由使用者自负，重要数据先备份。把这份提醒当成操作的一部分，而不是读完就忘的脚注。
