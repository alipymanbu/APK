# 和 Kazumi、Animeko 有什么不一样

> Animius 是一款只提供安卓版的看番工具，源内置、功能随版本更新。挑同类工具时真正决定合不合用的只有几件事：有没有你设备的版本、内容源谁来维护、能不能多设备接着看。本篇把它和常被拿来比较的 Kazumi、Animeko 放在一张表里。

## 一、先排除「设备对不上」这一条

这一类工具最硬的差别不是功能，而是**有没有你能装的版本**。Animius 官方只提供安卓 APK：

| 你的设备 | Animius 能不能用 |
| --- | --- |
| 安卓手机 / 安卓平板 | 可以，正常安装 |
| Android TV / 电视盒子 | 可以用，但要换 v1.2.1 那一版，见[下载与安装教程.md](下载与安装教程.md)第五节 |
| iPhone / iPad | 不行，项目没有 iOS 版 |
| Windows / macOS / Linux | 不行，项目没有电脑版 |
| 鸿蒙（HarmonyOS） | 不行，没有鸿蒙版 |

这一条是硬门槛，先过这一关再谈功能。官方仓库里长期有人问「后续考虑出 PC 端吗」「有没有鸿蒙版」，也就是说截至写作时这两个方向都还没有。

## 二、和 Kazumi、Animeko 的差别集中在四处

下表按各自官方页面与仓库说明整理，**截至 2026-09**。这几个项目都在持续更新，具体能力请以各自官方页面当时显示为准。

| 对比项 | Animius | Kazumi | Animeko |
| --- | --- | --- | --- |
| 支持的平台 | 仅安卓 | 安卓、iOS、Windows、macOS、Linux | 多平台（官方 Wiki 有 Windows、macOS、Linux、iOS 的安装说明） |
| 内容源怎么来 | 内置若干条，由作者随版本维护，**用户不能自己加** | 自定义规则，可导入、可自己写 | 在线多数据源聚合 + BT 源 |
| 弹幕 | 取自弹弹play 的开放接口 | 有 | 有自己的弹幕服务器，同时从弹弹play 取关联弹幕 |
| 多设备进度同步 | 没有账号体系，不同步 | 播放记录可用 WebDAV 同步 | 与 Bangumi 的收藏同步 |
| 开源许可 | GPL-3.0 | GPL-3.0 | AGPL-3.0 |

另外还有一条常见的路线是 **Aniyomi** 那类：应用本身不带源，需要你自己添加第三方的扩展仓库才有内容。它和 Animius 的思路正好相反 —— 一个内置、一个全靠自己配。

## 三、这四处差别会怎么影响你

**源失效的时候你手里有没有牌。** 这是最实际的一条。Animius 的源是内置的，官方更新记录里最常见的条目就是「增加某动漫源」「修复某动漫源」—— 源失效后你**只能等作者在下一个版本里换掉**，自己能做的就是换内置的另一个源，处理步骤见[动漫源切换与播放打不开怎么排查.md](动漫源切换与播放打不开怎么排查.md)第二节。Kazumi 和 Aniyomi 那两条路线则是用户自己换规则、换扩展就能处理。

**换设备时进度跟不跟你走。** Animius 没有账号，收藏和观看历史留在当前这台设备上，换手机不会带过去 —— 这也是为什么官方功能列表里看不到备份与导入这类功能，详情见[收藏追番与观看历史怎么用.md](收藏追番与观看历史怎么用.md)第六节。Kazumi 走 WebDAV、Animeko 走 Bangumi，都能把进度带到别的设备上。

**想投到电视上看。** 官方功能列表里没有投屏这一类功能，仓库里一直有人提「DLNA 投屏」的需求 —— 截至写作时应用本身不带投屏。想在大屏上看，就得走电视端安装那条路（也就是上面表格里的 Android TV 一行）。

**源数量够不够用。** 内置源的数量由作者维护、随版本浮动，没有一个固定值可写。有用户在公开论坛里反馈过「内置十来条源、失效后依赖作者更新」这样的使用感受 —— 这属于用户反馈，不是你应当当成承诺的数字，用起来以你当前版本里实际列出的源为准。

## 四、什么情况下 Animius 就够用

把上面的差别反过来读，就是它适合的场景：

- 只在**安卓手机或平板**上看，没有电脑、没有 iPhone；
- 不想研究规则、扩展这类配置，希望装完就能搜番看番；
- 能接受「源由作者维护、失效了等更新」这件事，不指望自己动手修；
- 不需要多设备同步进度，也不需要投屏。

四条都符合，它就是合你用的那一类；只要有一条不接受（比如你主力是电脑、或者必须投屏），那就要另找一条路线的工具，不必在这上面耗时间。
