# 常见问题与兼容设置

> 息屏后状态判断不准、实时功率通知不显示、记录老是断 —— 这类毛病多数能在设置页的「服务」分组里解决，本篇给排查顺序。

## 一、先走一遍通用排查顺序

遇到异常按这个顺序过，能省不少冤枉功夫：

1. **服务还活着吗？** 首页有没有「当前记录」。没有 → 见 [启动服务与开始记录.md](启动服务与开始记录.md)；用 App 启动方式的尤其常见（它不易保活，考虑换 ADB/nohup 或 Root 方式）。
2. **口径对吗？** 功率 0.00W、状态总是「未知 / 未充电」、总是没有记录文件 → 走校准，见 [功率显示校准方法.md](功率显示校准方法.md)。
3. **还是不对 → 进兼容设置**（下节）。
4. **要看日志** → 设置 → 「日志」分组，调日志级别与保留天数。

## 二、息屏状态 / 前台 App 判断异常 → 开轮询

**症状**：息屏状态判断不准、前台应用识别错，导致记录分段不对。

**解法**（官方文档原路径）：进设置页 → **「服务」分组** → 进入**「兼容设置」** → 把对应的**轮询选项**打开。这是系统 API 在部分机型上取不到实时状态时的兜底手段。

## 三、「实时功率通知」开了却看不到

通知类功能走的是 Shell 通道，系统可能把它自动禁用了。检查路径：

1. 设置页 → **「服务」分组** → 点**「管理 Shell 通知」**；
2. 看通知是不是被系统自动禁用了，在里面重新放行；
3. 顺带确认没开省电策略把这条通道拦掉（不同厂商叫法不同，找「通知」与「后台运行」相关的开关）。

## 四、服务跑着跑着断了

按启动方式对号处理：

| 你的启动方式 | 常见断法 | 对策 |
| --- | --- | --- |
| App 启动 | 系统回收后台，无障碍被停 | 官方已说明它「不易保活」；长期记录建议换 ADB（nohup 版本）或 Root 方式 |
| ADB 启动（nohup 版本） | 关终端窗口或断连导致退出 | 确认用的是 nohup 版本；手机与电脑断开后服务按 nohup 方式续跑 |
| Root 启动 | 理论上最稳，运行在特权进程 | 若仍异常，用「日志」分组调高日志级别后再复现，拿日志去官方仓库提 Issue |

另外，采样、写入、分段的节奏都在设置页**「服务」分组**里调 —— 记录太碎或太粗先想到这里，不用怀疑 App 本身。

## 五、其他已知情况

- **充电时首页没有续航预测卡片**：正常，放电状态才显示，见 [续航预测数据不足怎么解决.md](续航预测数据不足怎么解决.md)。
- **首次使用各种数值都不对**：先校准再判断，见 [功率显示校准方法.md](功率显示校准方法.md)。
- **权限被拒绝**：查询应用列表（预测排除高负载要用）与通知权限被关掉后，对应功能会静默失效，去系统设置里对 `yangfentuozi.batteryrecorder` 重新放行。
- **想反馈 Bug**：官方推荐走 GitHub Issues（[github.com/Itosang/BatteryRecorder/issues](https://github.com/Itosang/BatteryRecorder/issues)），QQ 群入口在仓库 README；提之前先搜搜有没有同款。
- **网上搜到的介绍和你手里的对不上**：功能文案、平台描述、版本号在搜索结果里五花八门，别按下载站的介绍判断功能与新旧，见 [同名软件与版本怎么分辨.md](同名软件与版本怎么分辨.md)。
