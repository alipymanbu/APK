## 一、为什么必须先启动服务

BatteryRecorder 的数据采集跑在一个**独立的服务进程**里，App 界面本身只是查看器。服务没起来，你打开软件看到的一切都是空的 —— 没有当前记录、没有充放电总结、没有续航预测。所以第一次用，第一件事就是按首页提示把服务跑起来。

## 二、三种启动方式怎么选

首页未连接服务时，会给出三种启动方式。官方文档给的选择原则很明确：**优先 Root 或 ADB，App 启动是兜底**。

| 方式 | 原理 | 优点 | 代价 |
| --- | --- | --- | --- |
| Root 启动 | 直接访问底层 API | 开销低，运行在特权进程，不需要保后台 | 需要手机已 Root |
| ADB 启动（推荐用 nohup 版本） | 同上，通过电脑 adb 下发 | 与 Root 同级的低开销、免保活 | 需要电脑 + 开发者选项 |
| App 启动 | 走系统 API，依赖无障碍 | 不用 Root、不用电脑，兼容性强 | 开销较大、不易保活 |

- **手机已 Root** → 直接选 Root 启动，最省事。
- **没有 Root，但手边有电脑** → 选 ADB 启动，官方文档特别标注「推荐使用 nohup 版本」（让命令在后台持续运行，关掉终端窗口服务也不停）。
- **既没 Root 也没电脑** → 才用 App 启动。官方的原话是「请仅在 Root/ADB 服务无法访问底层 API 时考虑 App 启动」—— 因为它靠无障碍撑着，系统一回收后台就容易断，断了就停止记录。

ADB 启动的大致流程（命令细节以官方使用文档 [battrec.itosang.com](https://battrec.itosang.com/) 的快速开始页为准）：

1. 手机开启开发者选项与 USB 调试，用数据线连电脑；
2. 在电脑终端执行 `adb` 相关启动命令（选 nohup 版本，防止关窗口后服务退出）；
3. 回到手机打开 BatteryRecorder，首页显示已连接即可拔线。

## 三、首页怎么确认「真的在记录」

服务起来后，首页会出现三样东西，缺一样都说明状态不对：

- **当前记录**：正在写入的这条记录，能看到它在走就说明采集正常；
- **充电总结 / 放电总结**：历史记录的两个入口，见 [历史记录导出与图表操作.md](历史记录导出与图表操作.md)；
- **续航预测卡片**：注意**充电状态下这张卡片不显示**，别误判成坏了 —— 放电后才会出现，见 [续航预测数据不足怎么解决.md](续航预测数据不足怎么解决.md)。

如果首页迟迟不出现「当前记录」，或者记录状态总显示「未知 / 未充电」，这不是启动问题，多半是校准问题，按 [功率显示校准方法.md](功率显示校准方法.md) 处理。

## 四、起来之后先做两件事

官方快速开始把这两件列为「必须的操作」，直接决定后面数据能不能用：

1. **校准**（设置 → 常规）：决定功率显示是否正常。首次使用、功率显示 0.00W、状态异常，都要在这里处理，详见 [功率显示校准方法.md](功率显示校准方法.md)。
2. **排除高负载 App**（设置 → 预测）：保证续航预测贴合你的日常场景，而不是被一局游戏带偏，详见 [续航预测数据不足怎么解决.md](续航预测数据不足怎么解决.md)。

之后按需再去设置页其他分组：**「服务」**调采样、写入、分段与兼容选项（息屏/前台判断异常在这里开轮询，见 [常见问题与兼容设置.md](常见问题与兼容设置.md)）；**「日志」**调保留天数与日志级别；**「预测」**是续航预测相关配置的集中地。
