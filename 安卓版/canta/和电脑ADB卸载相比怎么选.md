# 清理预装应用：用 Canta 还是连电脑敲 ADB

> 同一件事的两条主流路线对照：手机上的 Canta + Shizuku，和电脑上的 adb 命令 / 图形工具。差别不在效果，在你的设备条件和动手程度。

## 一、先说结论：效果是同一种

无论用哪条路，不 root 的清理做的都是同一件事 —— **把预装应用从当前用户（user 0）上卸载**：应用不再出现在桌面、不再运行、它的数据与缓存被清掉，但原始 APK 还留在只读的系统分区里。官方功能页对 Canta 的描述也是这个机制（直接调用系统 API，等同 adb 的做法）。

所以选路线只看两个约束：

- **设备系统版本**：Android 11 及以上才能在手机上免电脑完成（无线调试是 Android 11 才有的）；**Android 10 及以下的免 root 设备，只能连电脑用 adb 启动 Shizuku 或直接敲命令**。
- **你想不想碰命令行**。

## 二、三条路线对照

| | 设置里「停用」 | 电脑 adb（命令 / UAD 类图形工具） | 手机上 Canta + Shizuku |
| --- | --- | --- | --- |
| 要不要电脑 | 不要 | 要 | 不要 |
| 要不要 root | 不要 | 不要 | 不要 |
| 适用系统 | 全版本 | 全版本 | Android 11 及以上免电脑（更老版本配合电脑启动 Shizuku） |
| 能不能删系统应用 | 多数只能停用 | 能 | 能 |
| 安全分级参考 | 无 | 图形工具有社区清单；裸命令全靠自己查 | 有颜色徽章与描述 |
| 删错了怎么还原 | 重新启用即可 | 命令装回或 `install-existing` | 第二个标签页直接重装 |
| 每次重启后 | 无需处理 | 无需处理（每次用再连即可） | 要重新点一次 Shizuku「启动」 |

「UAD 类图形工具」指跑在 Windows / macOS / Linux 上的通用卸载工具：连上手机后列出全部包、按社区整理的清单给出「建议删除 / 有风险」分类，点按钮执行，不用手敲命令。有使用者反馈它比裸命令更稳的地方在于**有整理好的清单，有时会选择「禁用」而不是删除**——更保守。

## 三、什么情况选 Canta

- 手机是 Android 11 以上，手边没有电脑，或者懒得每次插线；
- 想在手机上边看徽章边删，删完还能从列表里一键还原；
- 要给多台同型号设备批量清（配合预设清单，见 [预设导入导出与批量卸载.md](预设导入导出与批量卸载.md)）。

代价是多一个 Shizuku 依赖：配对一次、每次重启后点一次启动，配对环节的坑集中在 [Shizuku配对失败的常见原因.md](Shizuku配对失败的常见原因.md)。

## 四、什么情况走电脑

- 系统是 **Android 10 或更低**，免 root 场景下无线调试不可用，电脑是唯一选项；
- 你要做批量脚本、要精确控制「删还是禁用」，或者正在用图形工具维护一份自己的清单；
- Shizuku 在你的机型上反复起不来（见 [Shizuku连接失败怎么解决.md](Shizuku连接失败怎么解决.md)），需要绕开它。

命令行侧的基本形态是 `pm uninstall -k --user 0 包名`（删除）与 `cmd package install-existing 包名`（装回当前用户），具体命令以你所用工具的文档为准，本文不展开成教程。

## 五、选完都别忘了这几条

三条路共用同一套风险边界：

- **收益预期**：系统应用住在和你的数据不同的分区，删完主要拿回的是数据、缓存与更新包那部分空间，别期待清出系统分区；真正明显的变化是通知、后台与重复图标变少了（实测数据见 [卸载系统应用与恢复误删.md](卸载系统应用与恢复误删.md) 第三节）。
- **删前留清单**：不管哪条路，导出一份「删了哪些包名」再动手，恢复出厂或系统更新后都用得上。
- **重启验证**：删完一轮重启一次，确认电话、网络、解锁正常，再动下一批。
