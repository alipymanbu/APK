## 一、先分清「连不上」发生在哪一段

手机上的 SSH 连接要走四段：手机网络 → 服务器防火墙 → sshd 服务 → 认证。报错信息基本能告诉你是哪一段断了，先对着下表定位：

| 现象 | 大概率原因 | 先做什么 |
| --- | --- | --- |
| Connection timed out | 端口不通：防火墙/安全组没放行，或 IP 写错 | 换个网络试；检查安全组 22 端口 |
| Connection refused | 网络通，但那个端口上没有 sshd 在听 | 核对端口号；上控制台看 sshd 状态 |
| Permission denied | 认证没过：密码错、密钥没部署对 | 见下面第三、四节 |
| Host key changed 警告 | 服务器指纹和上次记录对不上 | 见下面第五节 |
| 连上几分钟自己断 | 后台被杀或网络切换 | 见下面第六节 |

## 二、超时（timed out）：先排除网络和防火墙

1. 手机切到另一个网络（Wi-Fi 换流量）再连。有些公司/校园网封了 22 端口，流量下能连就是这种情况；
2. 云服务器去控制台查**安全组/防火墙规则**，确认入方向放行了你的 SSH 端口；
3. 地址和端口都核对一遍——IP 抄错一位、商家改过 SSH 端口，现象都是超时；
4. 还不行就去服务商控制台的 VNC / 网页终端登服务器，`systemctl status sshd` 看服务活没活。

连的是群晖、树莓派这类家用设备的话，还有第五种可能：**设备端 SSH 服务根本没开**（多数出厂默认关闭），开启方法见[连接群晖NAS与树莓派](连接群晖NAS与树莓派.md)。

## 三、密码认证被拒（Permission denied）

- **先确认输对了**：手机键盘的大小写、多拼的字符是大头。在 Termius 主机设置里重新填一遍密码再试；
- **服务器侧禁止了密码登录**：`/etc/ssh/sshd_config` 里 `PasswordAuthentication no` 时，只能走密钥。有控制台终端的话改回来或改用密钥；
- **root 被限制**：不少发行版默认 `PermitRootLogin prohibit-password`，root 账号只能密钥登录，密码怎么输都是 denied。

## 四、密钥认证被拒（Permission denied (publickey)）

密钥这条最容易踩坑，按顺序核对：

1. **公钥部署到位没有**：服务器 `~/.ssh/authorized_keys` 里是否真有你这把公钥，一行一条、没被折行截断；
2. **主机绑定对没有**：Termius 主机编辑页里认证方式是否选了 Key、选的是不是这一把；
3. **权限问题**（服务器端）：`~/.ssh` 要 `700`、`authorized_keys` 要 `600`，家目录不能对所有人可写，否则 sshd 会拒用。终端连上（用密码或控制台）执行：
   ```bash
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys
   ```
4. **导入的私钥是完整的吗**：粘贴导入时丢了 `-----BEGIN ... -----` 首尾行、或中途多了换行都会失效，对照原文重粘；
5. **手头有电脑**：用电脑 `ssh -v root@服务器` 连一次，verbose 日志会明说「offer 了哪些密钥、服务器拒了哪个」，比手机上猜快得多。

## 五、指纹变更警告（host key changed）

连一台服务器时弹「WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED」并拒绝连接，意思是：这台服务器的身份凭证和你上次连时记录的不一样了。

- **最常见且无辜的原因**：服务器重装了系统、换了实例（云主机重建后 host key 必然变）。确认过是这种情况，在 Termius 的已知主机（Known Hosts）里删掉旧记录，重连并确认新指纹即可；
- **需要警惕的情况**：没重装、没换机器却报这个——网络路径被劫持的可能性存在。此时别急着删记录，先用服务商控制台的网页终端核对服务器上的指纹（`ssh-keygen -l -f /etc/ssh/ssh_host_ed25519_key.pub`），对上了再更新。

## 六、连上后频繁掉线 / 切个应用就断

两个互相独立的原因，都要处理：

- **系统把 Termius 后台杀了**：Android 的电池优化会在你切走应用后冻结它，SSH 会话、SFTP 传输、端口转发随之断掉。到系统设置 → 应用 → Termius，关闭电池优化、允许后台无限制运行；
- **网络切换本身会断 SSH**：Wi-Fi 和流量互切、进电梯，TCP 连接当场死亡。这个治不断，只能绕：
  - 服务器装 **mosh**，Termius 主机详情里启用，会话跟着网络漂移自动续；
  - 长任务套在 **tmux / screen** 里跑，断线只是「看不见」，任务照跑，重连 `tmux attach` 原样恢复；配合主机设置里的启动命令，一连上就自动 attach。

掉线不影响服务器上正在跑的东西（前提是用了 tmux），这是手机远程办公能成立的基础，别省这一步。

## 七、都排查过还是不行

- 换一台设备（电脑）连同一个主机，能连说明是手机侧问题，不能连说明是服务器侧问题，范围立刻缩小一半；
- 看服务器日志定位认证失败的具体原因：`sudo journalctl -u ssh -n 50` 或 `/var/log/auth.log`，里面会写清是哪个用户、哪种方式被拒；
- 主机设置改乱了，删掉重建一个干净的往往比重逐项排查快，信息就四样：地址、端口、用户名、认证方式（参照[怎么连接服务器](怎么连接服务器.md)）。
