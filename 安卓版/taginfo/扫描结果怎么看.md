## 一、结果页长什么样

你把卡贴到手机背后，TagInfo 识别成功后会进入结果页。整页信息大致分四层：卡片/标签标识、芯片信息、存储布局、NDEF 内容。每层回答一个不同的问题，下面逐个说。

如果你还不知道怎么扫出这一页，先看 [下载与安装教程.md](下载与安装教程.md) 第四节。

## 二、逐区块解读

### 1. 卡片标识区

这一块告诉你**贴上来的是什么类型的对象**：是 NFC Forum 标签（Type 1~5 中的哪一类）、还是 MIFARE / NTAG / ICODE 系列的芯片，以及它走的通信技术（ISO/IEC 14443 还是 15693）。

- 对普通用户，最实用的是「这是哪种标签」——判断手里的标签能不能被别的应用（写标签工具、自动化 App）正常操作。
- 技术标准看不懂可以直接跳过，不影响后面几步。

### 2. 芯片信息区

这里列出**IC 厂商与 IC 型号**。比如你会看到 `NXP` + `NTAG213`，或 `NXP` + `MIFARE DESFire EV3`。

- **厂商**：芯片制造商。常见是 NXP，但 TagInfo 也能识别不少别家的芯片（官方明确说支持范围不限于 NXP 自家产品）。
- **型号**：决定这张卡的容量、功能和安全等级。比如 NTAG213 只有 144 字节用户区，DESFire 则带加密应用区。
- 部分卡还会显示**卡操作系统（Card OS）**、IC 存储大小、IC 配置等字段，有就看、没有就是该卡没暴露这项信息。

### 3. 存储布局区

这一块把芯片的**内存按扇区/页逐块列出**，每块后面跟着十六进制原始数据。两类人关心它：

- 开发者用它确认卡片配置有没有写错（比如格式化后该有的区块是空的）；
- 普通用户一般只看两点——**总容量多大**、**哪些区是锁定的**（锁定区通常意味着写保护已开）。

### 4. NDEF 内容区

NDEF 是标签里存的标准化数据。如果标签里写了内容，这一块会把它解析成人能读的形式：

| 内容类型 | 解析结果举例 |
| --- | --- |
| URL | 直接显示完整网址 |
| 文本 | 显示文字（含语言标记） |
| 联系人 vCard | 姓名、电话、邮箱 |
| Wi-Fi 配置 | SSID 与加密类型 |
| 应用启动记录 | 指向某个 App 的启动指令 |

Scan&Launch 模式下（应用设置里可切换），扫到带动作的 NDEF 会**直接执行**：打开网址、拨号、连 Wi-Fi、导入联系人等；Scan&Show 模式则只展示不执行，另有简单视图与专家视图两档，专家视图会把 NDEF 的原始记录结构也摊开。前提当然是标签里得先有内容——TagInfo 本身不提供写入，写自己标签的方法见 [可以写卡吗.md](可以写卡吗.md)。

## 三、什么读不出来（预期管理）

带安全机制的应用——银行卡、身份证、大部分加密门禁卡——**不会向 TagInfo 开放实际存储的数据**。你仍然能看到芯片型号、厂商这类卡片本身的元信息，但应用区内容是拿不到的，这是卡片自己加密的结果，不是应用坏了。判断「是加密了还是没读到」的技巧见 [读不到卡怎么办.md](读不到卡怎么办.md)。

另外要说明：交通卡余额、支付卡这类「能识别出应用名但读不了内容」的情况很常见，具体哪些卡能识别出应用、哪些能查余额，见 [支持哪些NFC标签和交通卡.md](支持哪些NFC标签和交通卡.md)。

## 四、把结果分享出去

结果页支持**创建并共享分析报告**——把自己的扫描结果导出发给别人，排查问题时最有用。注意报告里只有卡片的公开信息，不含你手机上的任何个人数据。

## 五、扫描历史

应用会记录你扫过的卡：界面里有 History（历史）入口，点开可以回看之前某次扫描的结果，不用把卡再找出来重扫一遍。官方更新日志里 History 视图修过多次缺陷（如 vCard 特殊字符显示、扫描历史里展示卡片），说明这是条被持续维护的正式功能，不是摆设。具体入口位置与条数上限随版本变化，以你装的这版界面为准。

批量核对卡片（比如一盒标签挨个扫）时，历史记录配合导出的报告，就是最省事的留档方式。
