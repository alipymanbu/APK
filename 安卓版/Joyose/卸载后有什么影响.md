# Joyose 卸载后有什么影响

## 一、先看这笔交易的两面

Joyose 管的是性能调度与温度（详见 [是干什么的.md](是干什么的.md)），把它停掉，等于让手机在「高性能」和「温度/功耗」之间少一个管理者。社区里大量的卸载反馈基本收敛成同一张对照表：

| 你可能换来的 | 你可能付出的 |
| --- | --- |
| 游戏不再被压帧，帧率上限放开 | 高负载时机身温度上升更快 |
| 没有调度介入，游戏过程中帧率更「平」 | 持续高性能时耗电明显加快 |
| 少一个后台组件在跑 | 游戏加速 / 游戏空间相关功能可能异常 |
| — | 耗电统计、部分系统调度行为可能变化 |

**两边的说法都有人对上号**：同一个小米社区帖子里，楼主发帖「禁用之后续航变好了」，高赞回复则说「它管的就是性能和温度，禁了之后高负载时更热、更费电，要自己压住散热」。这两种体验并不矛盾 —— **日常轻负载的人多半觉得更省电，天天打游戏的人多半觉得更热更费电**。你属于哪种，只有自己的使用习惯能回答。

## 二、卸载之后具体可能碰到什么

按社区反馈的频率排序：

1. **游戏加速相关功能失灵或行为异常** —— Joyose 是游戏加速链路的一环，停掉它之后游戏空间的部分功能可能不按预期工作。
2. **发热节奏变化** —— 没有调度压着，重负载上来得快、下去得也慢；机身烫时系统仍会触发底层温控降频，所以不是「永久满血」，是「更早烫、烫了更狠」。
3. **耗电与统计口径变化** —— 有用户反馈待机或游戏时掉电变快；也有人反馈续航变好（见上一节的两边说法）。
4. **极端个例** —— 有零星反馈称对系统组件动手后出现过启动异常；这类是单一来源的转述，无法复现核实，但结论很朴素：**按 [禁用与卸载方法.md](禁用与卸载方法.md) 里「先禁用、后卸载、带 `-k` 保留数据」的可逆顺序做，出任何问题都能一步恢复**。

没写进来的：关于卸载能「永久解决某机型的某个通病」之类具体承诺，公开材料里没有可交叉验证的结论，**查不到就不写** —— 别把某个帖子的个例当成你这台机器的预期结果。

## 三、出了问题怎么恢复

最常用的两条（完整命令与区别见 [禁用与卸载方法.md](禁用与卸载方法.md) 第三、四节）：

```bash
# 用 adb 禁用过的，重新启用
adb shell pm enable com.xiaomi.joyose

# 用 adb 卸载过的，按原样装回来（数据当时留了 -k 就还在）
adb shell pm install-existing com.xiaomi.joyose
```

恢复后进设置核对版本号（方法见 [下载与安装教程.md](下载与安装教程.md) 第五节）；如果状态乱了，直接「删除更新」回出厂版本，或手动覆盖装一份包，两篇的入口都在 [常见问题与解决办法.md](常见问题与解决办法.md) 第一节的判断顺序里。

**还有一个自动兜底**：系统 OTA 更新大概率会把组件恢复成官方版本（见 [禁用与卸载方法.md](禁用与卸载方法.md) 第六节）—— 你改坏了，等一次系统更新也能回到官方状态。

## 四、会不会影响保修

分两层说，两边口径都摆出来，不替你选边：

- **官方有明文的部分**：小米官方支持页面明确写了会导致官方保修失效的操作是 **解锁 Bootloader**（以及与之相关的 root、刷机这类改动系统底层的行为）。
- **官方没有明文的部分**：通过 adb 执行的 `pm disable-user` / `pm uninstall --user 0` 属于**用户层面**的操作，不动系统分区里的文件、不涉及 root 与解锁；针对这类操作是否影响保修，公开的官方条款里**没有明文规定**。
- **第三方的说法**：一些技术站点认为用户级卸载不触及保修限制条款 —— 但这不是官方承诺。

拿不准就两条路选一条：要么不动它（见 [禁用与卸载方法.md](禁用与卸载方法.md) 第二节，「删除更新」零风险）；要么动手前先问小米官方客服，**以官方答复为准**。

## 五、什么样的人不该卸

- 手机日常够用、没被调度问题困扰的 —— 它不碍你事，卸了只有风险没有收益；
- 散热条件一般、怕烫的 —— 高负载没人压温度，先想清楚；
- 不熟悉 adb、没耐心记恢复命令的 —— 用「清除数据 / 删除更新」这类可逆手段排查就够了（路径见 [常见问题与解决办法.md](常见问题与解决办法.md) 第一节）。

确定要动，回到 [禁用与卸载方法.md](禁用与卸载方法.md) 按「清数据 → 删除更新 → 禁用 → 卸载」的顺序来。
