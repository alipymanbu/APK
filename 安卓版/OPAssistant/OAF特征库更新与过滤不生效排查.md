# OAF 特征库更新与过滤不生效排查

> 本篇讲 OpenAppFilter（OAF）的特征库怎么选、怎么更新，以及「应用识别不出来、过滤不生效」时的排查顺序。

## 一、为什么过滤不生效，先查特征库

OAF 靠特征库认出「这是抖音、那是王者荣耀」。特征库太旧时，新应用认不出来、改过协议的老应用也会失效——表现在手机上就是：OPAssistant 的应用记录里某应用不出现，或过滤规则配了却拦不住。所以「过滤不生效」的第一步永远是**升级特征库**，而不是反复改规则。

## 二、下载哪个版本的特征库

免费特征库在官网下载页提供（[openappfilter.com/download.html](https://www.openappfilter.com/download.html)）。选版本前先弄清自己插件代码的新旧，官方页面上有两代格式：

| 特征库格式 | 适用插件 | 说明 |
| --- | --- | --- |
| feature2.0 开头 | 2022.12 之后编译的插件 | 较老的固件插件用这一代 |
| feature3.0 开头 | 2025 年 2 月之后的插件代码 | 新格式，配合新版本插件 |

下载到的是 zip 压缩包，**解压后取里面的 .bin 文件**去上传，别直接传 zip。上传入口在 LuCI 的「App Filter」→「应用特征库」页面。

你的插件代码是哪个年代，看不了编译日期的话，最稳的做法是把 OAF 三件套（`kmod-oaf`、`appfilter`、`luci-app-oaf`）先升到 GitHub Releases 的最新版，再配 feature3.0 特征库。安装方式见 [OAF上网行为管理配置.md](OAF上网行为管理配置.md)。

## 三、上传后没生效怎么办

官网特征库页面给过两条处理办法：

1. **重启路由器**再试；
2. 还不行就**手动替换特征库文件**：把解压出的特征文件传到路由器的 `/etc/appfilter/` 目录，替换同名文件（文件名为 `feature.cfg` 或 `feature_cn.cfg`），然后重启设备。

替换后回到 App 里看应用记录是否有新应用被识别出来，以此确认特征库已经用上。

## 四、升级了也拦不住的固有情况

有一类「拦不住」是应用之间的流量冲突，升级特征库也解决不了。官方在特征库页面说明过典型例子：**微信「视频号」**这类与正常聊天共用通道的功能，想完全过滤只能把微信整个屏蔽——要看你能不能接受这个代价。抖音、斗鱼、王者荣耀、B 站这类独立应用则不存在这种纠缠，属于可以正常管的对象。

遇到「某个应用怎么配都拦不住」，先想想它是不是和别的应用共用流量，再考虑换策略，别死磕规则。

## 五、iStoreOS 用户的额外注意

iStoreOS 集成的 OAF 与原版有差异（iStoreOS 官方文档口径）：

- 菜单位置在「**服务**」下，不在「网络」里；
- **默认未启用**：要在插件页面的「高级设置」里勾选「自动加载 oaf 驱动」并保存，功能才会生效——装了 OAF 却完全没有过滤效果，先查这一项；
- iStoreOS 版支持**切断已建立的连接**：对正在用的应用下禁止规则，连接会立即断开，不用等它重连。

其他第三方固件的集成方式各有差异，菜单找不到「App Filter」时，先看固件自己的文档。

## 六、验证特征库是否生效

一条可以照做的验证路径：

1. 升级特征库并按上面的办法处理后，重启路由器；
2. 用一台手机打开一个你配置了「禁止」的应用；
3. 回到 OPAssistant 的应用记录页看这台设备——新特征库正常时，应用能被认出来、规则也拦得住；
4. 认不出来就回到第二节检查特征库格式与插件版本是否匹配。
