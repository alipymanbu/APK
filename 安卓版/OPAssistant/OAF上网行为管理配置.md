## 一、OAF 是什么、和 OPAssistant 什么关系

OpenAppFilter（简称 OAF）是运行在 OpenWrt 上的开源上网行为管理插件，做的是应用过滤、上网控制、上网记录这三类事（项目官网 [openappfilter.com](https://www.openappfilter.com/)，源码 [destan19/OpenAppFilter](https://github.com/destan19/OpenAppFilter)）。OPAssistant 是同一个团队出的手机端：App 里的客户端列表、应用记录、过滤配置这些功能，都要路由器上装了 OAF 才有数据。

## 二、前提：路由器上先装好 OAF

App 里「客户端」「应用记录」这类页面是空的、或者根本没有这些入口，最常见的原因就是路由器上没装 OAF。两条路：

- **自己装插件**：在 OpenWrt 官方发布的固件上，从 OAF 项目的 GitHub Releases 下载 `kmod-oaf`、`appfilter`、`luci-app-oaf` 三个包按顺序安装，官方安装指南在 [openappfilter.com/install.html](https://www.openappfilter.com/install.html)，有逐步截图；
- **用预装固件**：官方推荐 FanchmWrt 固件，默认集成了 OAF 并做过优化，装好固件就有。

自己装要注意两点（按官方安装指南的口径）：

1. 固件要用 **OpenWrt 官方发布的版本**——自行编译的固件与插件可能因内核差异装不上；支持的版本范围以安装指南页面当时的说明为准；
2. 装完在 LuCI 的「App Filter」页面里**更新应用特征库**（版本选择与上传不生效的处理见 [OAF特征库更新与过滤不生效排查.md](OAF特征库更新与过滤不生效排查.md)），默认特征库覆盖的应用可能不含你要管的那几个。

用的是 iStoreOS 固件的话另有差异：OAF 菜单在「服务」下，且默认未启用，要在插件「高级设置」里勾选「自动加载 oaf 驱动」并保存才会生效——装了却完全没效果，先查这一项。

## 三、手机上能配什么

装好 OAF、App 连上之后，对应板块就有内容了：

| 功能 | 能做的事 |
| --- | --- |
| 客户端列表 | 看当前有哪些设备连在路由器上 |
| 应用使用记录 | 查看各客户端的应用使用时长记录 |
| 应用网络控制 | 对某个客户端放行或禁止特定类型的应用（游戏、视频、聊天、下载等） |
| 应用过滤规则 | 配置 OAF 的应用过滤规则 |
| 时间规则 | 配置策略生效的时间段，比如「周日至周四晚 22 点后不玩游戏」 |
| 用户规则 | 按用户分组配置不同策略 |

具体规则（拦哪些应用、对谁、什么时段）在 App 里配和在路由器 LuCI 的「App Filter」页面里配是一套数据，两边改都生效，选你顺手的那边。

## 四、两端版本要匹配

官网「重要提示」里列过一次匹配问题：OAF 发布 v6.1.7 时，对应的 iOS 版还在审核，所以当时的 iOS 应用只能管理 v6.1.6 及更早的 OAF。这说明一个通用规律：**手机端版本与路由器端 OAF 版本差得远时，部分功能可能不显示、不受控**。

遇到「明明装了 OAF 但手机上看不到数据/控不住」的情况，核对顺序是：先在路由器 LuCI 里看 OAF 版本，再看 App 版本，对照官网页面上的说明；单升级一头不一定解决问题。

## 五、应用记录从什么时候开始有

应用记录由路由器上的 OAF 统计。装 OAF 之前的日子不会有记录；想看某一天的记录，前提是那一天 OAF 已经在路由器上正常运行。另外应用识别依赖特征库，特征库太旧时部分应用可能识别不出来，记录里就是空的——识别不准先升级特征库，再怀疑别的。
