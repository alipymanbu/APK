## 一、先判断你适不适合自己写

写规则不需要会 JavaScript，但你要能接受这几件事：会用浏览器开发者工具（F12）、看得懂一点 HTML 结构、有耐心对照页面调选择器。如果只是想「多几个能看的源」，直接导入现成规则更省事，看 [规则导入与视频源管理.md](规则导入与视频源管理.md) 就够了。

适合动手写规则的情况：某个你喜欢的站点没人收录，或者收录的规则坏了而你等不及社区更新。

## 二、准备工作与编辑器入口

1. 在电脑上操作（Windows / macOS / Linux 皆可），用最新版 Edge、Chrome 或其他 Chromium 系浏览器——要用开发者工具；
2. 装最新版 Kazumi，进入 `我的` → `规则管理` → 右上角 `+` → `新建规则`；
3. 先在目标网站上搜一部番，确认它**不登录、不验证码就能直接出结果**——搜索前要登录或过人机验证的站点，基础规则接不进来（那需要额外配 Cookie，超出本篇范围）。

## 三、每个字段填什么

新建规则后按字段顺序填：

| 字段 | 填什么 |
| --- | --- |
| `Name` | 规则名，用于在列表里识别来源，填站点名或域名 |
| `Version` | 自用随意；要提交规则仓库就从 `1.0` 起，每次改动递增 |
| `BaseURL` | 站点能正常访问的根地址，直接从浏览器地址栏复制 |
| `SearchURL` | 在该站搜一次番，把搜索结果页的完整地址贴进来，再把关键词那部分换成 `@keyword` |
| `SearchList` | 选中搜索结果里「每一个作品条目」的 XPath |
| `SearchName` | 从条目里取番名的 XPath |
| `SearchResult` | 从条目里取详情页链接的 XPath |
| `ChapterRoads` | 定位播放线路列表的 XPath |
| `ChapterResult` | 定位各集剧集链接的 XPath |

`SearchURL` 举例：浏览器里搜完显示

```
https://www.example.com/search/-------------?wd=紫罗兰永恒花园
```

不管关键词显示为原文还是 URL 编码，都把关键词对应的部分替换成 `@keyword`：

```
https://www.example.com/search/-------------?wd=@keyword
```

Kazumi 执行搜索时会替你编码并填入。如果该站是 POST 表单提交关键词，用编辑器里的「POST 搜索」高级选项，官方教程有专门一节。

## 四、用开发者工具取 XPath（SearchList 起步）

这是写规则最花时间的一步，套路固定：

1. 在目标站执行一次搜索，让结果列表出现在页面上；
2. 按 `F12` 打开开发者工具，切到「元素」面板，点左上角的元素选择器图标；
3. 在页面上点任意作品名，工具会定位到对应 HTML 元素；
4. 逐级向上移动鼠标观察高亮范围——**当高亮刚好覆盖单个搜索结果（含名称和图片）时，折叠这个父元素**；折叠后通常是一排结构相同的 `<li>`，这一层就是 `SearchList` 要的选择器；
5. 同样的方法取 `SearchName`（番名）与 `SearchResult`（链接）。

取到的选择器**必须以 `//` 开头**——Kazumi 对 XPath 的支持不完整，只认这种写法（如 `//ul[@class="list"]/li`），写成 `/html/body/...` 这种从根开始的路径会失效。

## 五、写完怎么调试

按官方文档的两条经验走：

1. **检索不出来** → 先查选择器是不是 `//` 开头，再对照页面实际结构核对 `SearchList`（站点改版后这里最先坏）；
2. **能检索、播放不了** → 关掉这条规则的「使用内置播放器」选项，让 Kazumi 改用 webview 播放，兼容性会提高；内置播放器能用时建议开着，弹幕和流畅度更好。

调试时一条字段一条字段验：先让搜索出结果，再验详情页，最后验线路与剧集——链路从前往后通，比一次填完再猜哪里错了快得多。

## 六、分享与贡献

写好的规则可以提交到官方规则托管仓库 [github.com/Predidit/KazumiRules](https://github.com/Predidit/KazumiRules)（仓库说明写明欢迎贡献），提交前把 `Version` 按 `1.0` 起递增的规矩填好，是否在规则里留你的 ID 由你决定。不想提交也没关系，用「从剪贴板添加」或「从 JSON 文件添加」自用即可。官方的字段详解与完整示例在 [kazumi.app 的规则开发文档](https://kazumi.app/docs/rules/develop-rules)，遇到本篇没覆盖的场景（POST 搜索、站点禁开开发者工具等）去那里查。
