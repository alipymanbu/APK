## 一、启动与停止

首页右下角的启动按钮就是抓包总开关：

1. 首次点启动时系统弹「连接请求」（VPN 权限），选确定 —— 不给这个权限一条流量都抓不到；
2. 按钮进入运行状态后，手机里各应用发出的 HTTP/HTTPS 请求会实时出现在列表里；
3. 再点一次即停止。退出应用前建议先停掉抓包，避免 VPN 服务留在后台。

想直接看 HTTPS 明文，先把证书装好（见 [HTTPS抓包证书配置.md](HTTPS抓包证书配置.md)），否则列表里的 HTTPS 请求只有域名没有内容。

## 二、看懂请求列表

每行一个请求，重点看这几列：

- **域名与路径**：请求发给了谁；
- **状态码**：200 正常 / 3xx 跳转 / 4xx、5xx 出问题；
- **耗时**：排查「哪个请求慢」的依据；
- **方法与大小**：GET/POST 一眼可辨，响应大小帮你在长列表里定位「真在传数据」的那条。

点开单条请求，能看到请求头、请求体、响应头、响应体的完整内容；1.3.0 起请求详情带 JSON / XML 查看器（自动解析与格式化），密密麻麻的接口返回可以直接展开看，长文本的编辑器也带语法高亮。列表按时间滚动，目标请求一闪而过时用下面两节说的过滤与搜索。

## 三、域名过滤：只抓你要的

ProxyPin 支持按域名过滤（可用正则），比如只看某个接口就填 `api\.example\.com` 这类规则，命中之外的请求不进列表。手机上系统服务与各家 SDK 的心跳、上报请求非常多，不过滤的话列表几分钟就刷满 —— 先过滤、再抓包，是省时间的第一步。

## 四、按条件搜索

列表页支持按关键词、响应类型等多种条件搜索，1.3.0 起还支持正则表达式（具体条件项以你手上的版本界面为准）。典型用法：

- 搜 `login` / `token` 定位登录相关接口；
- 按状态码 `500`、`404` 找出错的请求；
- 按内容类型只看 JSON。

## 五、收藏、历史与 HAR

- **收藏**：重要请求手动收起来，下次直接回看；
- **历史记录**：抓过的请求自动保存，重启应用后仍能翻到；清空记录前应用会先弹确认；
- **HAR 导入导出**：导出菜单支持导出请求、响应、请求+响应与 HAR，把 HAR 文件发给别人，或把别人给的 HAR 导进来分析。HAR 是通用的 HTTP 存档格式，浏览器开发者工具也认，跨设备传「现场」全靠它。
