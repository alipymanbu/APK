## 一、排查前先确认装的是哪一份

你手上这份是 **1.0.0-debug**（包名 `com.aniwavestream.app.debug`，2026-09-23 采集）。排查的第一原则是先排除「装的不是同一份」—— 网上同名安装包很多，来源错了，后面所有排查都白做。核对方法见 [下载与安装教程.md](下载与安装教程.md) 第三节的 MD5 校验。

## 二、故障速查表

| 现象 | 先试 | 再试 |
| --- | --- | --- |
| 打开就闪退 | 重启手机后再开一次 | 卸载重装（重装前核对 MD5） |
| 搜索没结果 | 换关键词写法（英文 / 罗马音 / 全称简称各试一次） | 确认网络可用，换个时段重试 |
| 列表加载不出 | 下拉刷新；Wi-Fi 与流量各试一次 | 稍后再来，源端可能正在变动 |
| 播放转圈不出画面 | 把清晰度调到最低一档 | 退出播放页重进，或换一集测试 |
| 播放中途频繁缓冲 | 降清晰度；关掉后台的大流量应用 | 换个网络环境对比，定位是网络还是源的问题 |
| 播放器报「视频无法播放」类提示 | 降清晰度后重进播放页 | 换一集对比，排除单个条目的源问题 |
| 某部片突然找不到 | 确认片名写法没打错 | 过一两天再搜，内容库更新时条目会变动 |

## 三、几类故障的判断逻辑

### 1. 是网络问题还是源的问题

用同一网络打开另一个视频应用或网站做对照：

- 别的也慢、也打不开 → 是你的网络问题，换网络或等恢复；
- 只有 Aniwave 异常 → 大概率是源端波动，换时段重试最省事。

另外注意时段：晚间高峰期源端拥塞造成的缓冲会明显变多 —— 多个第三方资料都把「高峰拥塞」列为同类在线播放服务卡顿的首要原因，错开时段重试往往比反复刷新有效。

### 2. 是包的问题还是版本太旧

`-debug` 版属于早期构建，如果源端接口随后续迭代发生了变化，旧包可能出现「能打开但加载不出」的情况。判断路径：

1. 先把第二节的网络、清晰度这类常规项排除掉；
2. 仍然不行，接受「这份包在当前时点可能已不适配」的可能 —— 它是 2026-09-23 采集的版本，在线播放类应用的适配窗口本来就不长；
3. 需要另找包时，仍然以 MD5 核对为前提，风险边界写在 [来源与安全注意事项.md](来源与安全注意事项.md)。

### 3. 安装环节的报错

「解析包错误」「安装未完成」基本都是文件不完整或系统拦截：先删掉重下（转存与重下的操作见 [夸克网盘转存与下载步骤.md](夸克网盘转存与下载步骤.md)），重下后核对 MD5，再按安装教程里「未知来源放行」那一节处理，完整步骤在 [下载与安装教程.md](下载与安装教程.md) 第四、五节。

### 4. 设备侧还能做的三件事

1. 清 App 缓存：系统设置 → 应用管理 → Aniwave → 存储 → 清除缓存（只清缓存不动数据，观看设置不受影响）；
2. 对带宽有个数：有第三方资料给出在线视频流畅播放的参考值约为 5 Mbps，实际带宽低于这个水平时，先解决网络再看清晰度；
3. Wi-Fi 与流量互换测试一次，把问题固定到「网络」或「源」其中一边，避免两头瞎试。

## 四、什么情况不用再折腾

- 反复重装、换网络、换时段结果都一样，且 MD5 核对一致 → 停止尝试，这份包在该时段可能就是不可用状态，过几天再看；
- 不要为了「修好它」去装来路不明的「修复补丁」「加速器配置」「解码器」—— 这是第三方分发里最常见的坑，详见 [来源与安全注意事项.md](来源与安全注意事项.md) 第三节。
