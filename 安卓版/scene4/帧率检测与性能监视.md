## 一、先给悬浮窗权限

监视器、帧率记录都靠悬浮窗显示，第一次用会弹「需要授予悬浮窗权限」的提示。手动开启的位置：系统设置 → 应用管理 → Scene4 → 权限 → 允许「显示在其他应用上层」（悬浮窗）。不给这个权限，悬浮球和悬浮窗都出不来，表现就是「点了没反应」；权限开成功但悬浮窗仍然不见，走 [帧率显示为零与悬浮窗排查.md](帧率显示为零与悬浮窗排查.md)。

部分系统还会把 Scene4 的后台杀掉导致悬浮窗消失，到电池 / 自启动管理里给它「无限制」或允许后台运行。

## 二、用帧率记录器测游戏帧数

帧率记录在基础模式下不可用，需要先激活 ADB 模式（见 [ADB模式激活方法.md](ADB模式激活方法.md)）。以测一局游戏为例：

1. 打开 Scene4，点顶部的柱状图图标进入监视器功能。
2. 只勾选「帧率记录器」，屏幕上会出现一个半透明圆形悬浮按钮。
3. 打开游戏，等过完加载、进入可操作画面后再点悬浮球——变红代表开始记录。
4. 打完一局（或想结束时）再点一次红色悬浮球，变灰即停止记录。
5. 通过多任务切回 Scene4，到「功能 → 帧率记录」里查看这次录到的帧率曲线。

正常录完的报告里能看到的东西不少：最大 / 最小 / 平均帧率、帧率波动曲线、CPU 占用率曲线，以及这局里的最高温度与平均温度（具体字段以应用内实际显示为准）。看报告的要点：

- 平均帧只是整体印象，**掉帧看最低帧**：最低帧出现的时点对应卡顿瞬间；
- 帧率曲线如果呈阶梯状下坠（刚进图高、几分钟后掉一截），大概率是机身过热降频，而不是性能不够；
- 对照 CPU 占用曲线：占用没满但帧率掉，瓶颈多半不在 CPU，别急着改调度。

要注意游戏刚开场的加载阶段帧数波动很大，不能代表实际体验，所以第三步强调「进入画面后再开始」。如果悬浮球根本没出现、或帧数恒为 0，别对着重试，直接按 [帧率显示为零与悬浮窗排查.md](帧率显示为零与悬浮窗排查.md) 处理。

## 三、性能监视器：悬浮窗常驻看数据

监视器里除了帧率，还能勾选 CPU 负载、CPU 温度、内存、电池温度等项目，以悬浮窗形式常驻屏幕角落。不同工作模式能读到的数据不一样：

| 数据 | 基础模式 | ADB / ROOT 模式 |
| --- | --- | --- |
| 运存 / 闪存负载、电池温度、充电速度 | 可看 | 可看 |
| CPU 实时负载与温度 | 不完整 | 完整 |
| GPU 负载 | 不可 | 仅 ROOT 模式 |

游戏时嫌悬浮窗挡视线，可以把窗口调小或只保留一项；部分版本还提供缩小悬浮窗尺寸的优化选项，在设置里找。

## 四、充电统计与耗电统计

这两个入口在「功能」里：

- **充电统计**：插电后开始记录，能看充电速度曲线，用来判断充电器、数据线是不是拖了后腿。
- **耗电统计**：按应用看耗电情况，配合场景模式的规则，能定位「到底是哪个应用在后台吃电」。

统计类功能依赖应用保持后台运行，如果发现记录断断续续，八成又是后台被杀，处理方法同第一节。
