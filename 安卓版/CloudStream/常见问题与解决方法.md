## 一、仓库加载失败 / Add Repository 没反应

这是出现频率最高的问题。仓库清单几乎都托管在 GitHub 上，你的网络到 GitHub 的连通性直接决定成败。按官方故障排查页给的顺序排查：

1. **先测连通性**：在浏览器里打开官方的网关检查页 [public-gateway-checker](https://recloudstream.github.io/public-gateway-checker/)，看列表里的网关是否打叉；
2. **浏览器也打不开** → 说明当前网络整体到不了 GitHub。官方给的两条路：换网络通道（VPN 等）再试；或者用应用设置里的「站点克隆（cloning site）」功能，把可用的镜像克隆下来——入口在 `Settings` 的站点克隆一节；
3. **浏览器能打开、应用里还是失败** → 按官方说法到 Discord 的 `reports` 频道发一份报告（频道入口见本篇第五节）。

补充两条实操经验：改用 Wi-Fi 或流量切换网络再试一次；仓库地址粘贴时确认没把空格或换行一起粘进去。

## 二、搜索有结果、播放转圈或直接失败

按可能性从高到低：

| 现象 | 先做什么 | 说明 |
| --- | --- | --- |
| 播放器黑屏/转圈后报错 | 换外部播放器（VLC）重试 | 内置播放器（ExoPlayer）处理不了的流，外部播放器往往能播，官方排查页反复给这条处方 |
| 列表加载特别慢 | 等几秒后跳过加载 | 个别扩展收录的站点很多，逐个加载本来就慢，官方建议 3~5 秒后直接跳过 |
| 某个源始终失败，其他源正常 | 换一条网络通道再试 | 部分源有地区访问限制，换网后大多能恢复 |
| 列表里显示有片、点进去没源 | 正常现象 | 目录数据与实际站点是两回事，站点没收录就是没源，换个扩展再搜 |

播放器与字幕层面的设置（自动字幕、编码、缓存）见 [字幕与播放器设置.md](字幕与播放器设置.md)。

## 三、下载失败 / 存储报错

- **改下载位置**：`Settings → 下载路径（download path）`，选一个空间充足、你有权限写入的目录——官方排查页给的第一个动作就是换位置；
- **缓存占满存储**：把 `Settings → Player → Video cache on disk` 调低，再清一次应用缓存；
- **清缓存后重启应用**：这是官方给出的通用处方，解决一批说不清原因的异常。

## 四、备份与恢复

应用设置里提供备份导出（书签、观看进度等本地数据）。官方排查页里有一条恢复时的坑：**导入备份失败时，把备份文件的扩展名从 `.json` 改成 `.txt` 再导入**，多数能过。换机迁移的路径就是：旧机导出 → 传到新机 → 新机导入。

## 五、还解决不了：官方求助渠道

- **Discord 社区**：官方 README 挂的入口是 [discord.gg/5Hus6fM](https://discord.gg/5Hus6fM)，排查页提到的 `reports` 频道就在里面；
- **GitHub Issues**：[github.com/recloudstream/cloudstream/issues](https://github.com/recloudstream/cloudstream/issues) 提交时要选模板（bug 报告需写明应用版本、设备、复现步骤）。

提问题前先确认你用的是哪个版本（本文对应 4.7.0；4.x 各版本设置项位置偶有挪动），以及问题能否稳定复现——官方明确说了不能复现的 bug 基本不会被处理。

安装与扩展环节的问题不在本篇范围，分别见 [下载与安装教程.md](下载与安装教程.md) 与 [扩展与仓库添加方法.md](扩展与仓库添加方法.md)；电脑端（模拟器 / WSA）的安装与运行问题见 [电脑上运行方法.md](电脑上运行方法.md)。
