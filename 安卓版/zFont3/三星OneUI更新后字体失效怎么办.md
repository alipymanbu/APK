## 一、先对照现象

2026 年 3 月安全补丁与 One UI 8.5 发布后，多名 Galaxy 用户反馈同一组症状：

- 之前通过第三方应用加进来的字体，在系统字体列表里选择时弹提示「此字体不受支持。请联系字体提供商。要卸载此字体吗？」
- 默认字体的设备装不上新字体；已在用第三方字体的设备，一旦切到系统自带或 Galaxy Store 字体，就**无法再切回去**。
- 多个独立来源（Reddit 用户反馈、XDA 测试、媒体报道）与开发者的官方声明互相印证：免 root 通道在打过这批补丁的机型上不再可用。

影响范围：

| 机型状态 | 是否受影响 |
| --- | --- |
| 已装 One UI 8.5 测试版的 Galaxy S25 系列 | 受影响 |
| 已收到 2026 年 3 月安全补丁的 Galaxy 机型 | 受影响 |
| Android 16 / One UI 8.0 机型（如 Z Fold7） | 更早前已有部分兼容问题 |
| 补丁更早的旧系统机型 | 不受影响，可正常使用 |

查自己的补丁级别：设置 → 软件信息 → Android 安全补丁级别。

## 二、原因一句话

这批补丁给字体安装路径加了签名校验：只有三星自家与其签约字体商（Monotype）签名的字体包能通过，第三方应用打包的字体过不了这道校验。开发者已在官方社区确认这一点；截至 2026-09 没有恢复公告，后续以官方渠道消息为准。

## 三、现在还能怎么做

按你的处境对号入座：

1. **第三方字体还在正常显示**：什么都别动，尤其**不要切换到其他字体**——切走就回不来，这是当前形势下最要紧的一条。
2. **必须换新字体**：Galaxy Store 的字体区是当前唯一免 root 出口（官方签约字体，部分免费、多数收费）。
3. **设备已 root**：走 Magisk / KernelSU / APatch 模块路线，不受这道校验影响，模块做法见[自定义字体导入教程](自定义字体导入教程.md)第五节。
4. **不想 root 也不愿付费**：停在系统自带字体，等官方渠道的后续消息，不要反复重试触发改动。

## 四、跟 zFont 3 版本号有关系吗

关系不大。3.9.2.2 的更新说明里提到「修复新版 One UI 8/8.5 上 Exclusive Fonts 的兼容性」，那是应用内一项字体功能的修复；而本篇讲的是系统级签名校验拦下了整条免 root 写入通道——功能修复不等于通道恢复，两者是两回事。你的新机型实际能不能用，以装机实测为准；机型与系统版本的总体支持情况见[免root机型兼容清单](免root机型兼容清单.md)。
