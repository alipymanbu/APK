## 一、先分清四种工具的层次

同样是「一个应用变多个」，四类工具的原理层次完全不同，选错层次是大多数「怎么用都不对劲」的根源：

| 类型 | 代表 | 运行层次 | 是否 Root |
| --- | --- | --- | --- |
| 应用级容器 | BlackBox、VirtualXposed | 应用内沙盒，不碰系统 | 否 |
| 厂商系统分身 | 小米/华为等的「应用分身」 | 系统原生功能 | 否 |
| 真虚拟机 | VMOS 等 | 手机里跑一整个安卓系统 | 视产品而定 |
| 云手机 | 各类云端方案 | 远程真机，本机只是画面 | 否 |

BlackBox 与 VirtualXposed 同属应用级容器，也都源自 VirtualApp 系技术路线，相似度最高，下面单独展开。

## 二、BlackBox 对比 VirtualXposed

| 对比项 | BlackBox | VirtualXposed |
| --- | --- | --- |
| 支持系统 | 安卓 5.0 ～ 12.0（官方 README） | 安卓 5.0 ～ 10.0（官方仓库） |
| Xposed 框架 | 内置，可开关、可隐藏 | 内置 Xposed Installer |
| 模块限制 | 作用于系统层面的模块无效 | 不能修改系统；资源钩子不支持，主题美化类模块基本不可用 |
| 重启方式 | 重启 BlackBox 本身 | 重启容器即可，无需重启手机 |
| 架构分包 | 32 位与 64 位两个独立 app | 不分 |
| 维护状态 | 更新已停多年，停在 2.x | 同样长期未更新 |

两边共同点要认清：**作用于系统的模块（改状态栏、全局主题之类）在谁那里都不可用**，容器里只有装进去的那几个应用。VirtualXposed 官方 README 把这条列为仅有的两大限制之一。

选法不复杂：系统是安卓 11/12 → 只能选 BlackBox 这类支持到 12.0 的；要用的模块恰好依赖资源钩子 → 两边都不行，得考虑真虚拟机；其他场景两者均可，哪个在你机型上跑得稳用哪个。

## 三、和系统分身、云手机比，各差在哪

- **系统分身**（厂商自带）：稳定性和兼容性最好，不引入第三方容器；但一般只支持社交等少数应用、限制数量，且完全没有模块机制。只是想开两个微信，用它就够了，别装容器。
- **云手机 / VMOS 一类**：等于多了一台完整设备，应用兼容性接近真机，能装任何东西；代价是资源占用（真虚拟机）或持续付费（云手机），而且多了一层账号与隐私边界要自己掂量。BlackBox 这类容器的优势是轻：几 MB 的安装包、随装随删，劣势也是这个 —— 容器内的应用环境与真机差异更大。
- **容器共同的行为特征**：应用在容器里运行时，读到的系统环境与真机有可感知的差异，部分应用的完整性检查会因此拒绝工作。这是层次决定的，换哪个容器品牌都一样。

## 四、按需求对号入座

| 你的目的 | 建议 |
| --- | --- |
| 双开微信/QQ | 系统分身优先，不行再上容器 |
| 免 Root 跑单个应用的 Xposed 模块 | BlackBox 或 VirtualXposed |
| 安卓 11/12 上跑模块 | BlackBox 这类支持新系统的容器 |
| 完整的第二系统、随便装东西 | VMOS 或云手机 |
| 只是同时登两个游戏小号 | 先看 [多开与账号安全注意事项.md](多开与账号安全注意事项.md) 再决定 |

选定 BlackBox 的话，从 [下载与安装教程.md](下载与安装教程.md) 开始；模块相关直接看 [Xposed模块使用方法.md](Xposed模块使用方法.md)。
