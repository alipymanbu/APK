## 一、已安装列表里找不到我要的应用

这是新手撞到的第一个坎，原因几乎只有一个：**架构不匹配**。BlackBox 分 32 位与 64 位两个独立的 app，你的 BlackBox 是 64 位版，目标应用如果是纯 32 位库，就出现在列表里也装不上。

处理：换 32 位版 BlackBox 再添加（两个版本的应用与数据互不相通，要分别添加；架构区别见 [下载与安装教程.md](下载与安装教程.md) 第四节）。找不到 APK 的话也可以走「从文件安装」的路子，见 [添加应用与多开步骤.md](添加应用与多开步骤.md) 第二节。

## 二、启动应用就闪退

按命中率从高到低排查：

1. **系统版本超出支持范围**。官方只保证安卓 5.0 ～ 12.0，明确不支持 4.x；安卓 13 及以上未在官方支持列表里，闪退先对一下你的系统版本。
2. **应用本身较新、targetSdkVersion 高**。官方给开发者的建议是把目标应用的 targetSdkVersion 降到 28 及以下兼容性更好 —— 普通用户改不了这个，但可以从这个角度理解：越是新的大版本应用，在容器里翻车的概率越高。
3. **开启了 Xposed 框架或模块**。先关掉框架重启 BlackBox，再单独开回来，二分定位是框架问题还是应用本身的问题，参考 [Xposed模块使用方法.md](Xposed模块使用方法.md)。
4. **旧数据残留**。把该应用从黑盒里移除后重新添加一次。

## 三、官方自己列出的已知缺陷

以下是官方仓库「Known Issues」一节原文提到的，都是已知问题、不是你的操作错了：

| 现象 | 说明 |
| --- | --- |
| 应用被系统杀死后重启出现重复进程/页面，无法正常交互 | 官方给的临时办法：手动杀掉相关进程，再重启该应用 |
| 火狐浏览器在输入网址时崩溃 | 已知崩溃点，换别的浏览器用 |
| 调用 content provider 的 getType 时崩溃 | 应用内涉及此调用的功能会触发 |
| 静态广播收不到 | 依赖静态广播的功能（部分自启动、推送）在黑盒内可能失效 |
| 多进程应用卡顿 | 官方怀疑与新进程启动后 pid 未更新有关；卡顿源于初始化新进程 |

火狐那条官方后续版本修过部分问题，但你手里这份 2.2.0 不保证全部修复，遇到就绕开。

## 四、卡顿明显

黑盒给每个虚拟应用拉起独立进程，资源开销天然比直接开应用高。低配机上：少在黑盒里同时挂多个应用；后台不需要的从最近任务清掉；机身存储紧张时也会放大卡顿。个别应用是多进程架构的，卡顿属于上表最后一行的已知缺陷，等不了修复就换 32 位版或别的容器方案对比。

## 五、游戏里弹出「多开」警告或登录被拦

用黑盒开某个游戏时直接报错、提示关闭多开客户端，这不是 BlackBox 的故障 —— 平台方把「容器内运行」「客户端多开」列为拦截场景（腾讯游戏安全中心的官方页面就有对应的错误码与「请关闭多开的客户端」提示）。关掉另一个实例再试；反复被拦就别在这款应用上坚持容器方案了。多开与账号安全的完整边界说明见 [多开与账号安全注意事项.md](多开与账号安全注意事项.md)。

## 六、其他两个高频疑问

- **卸载 BlackBox 会怎样？** 黑盒内的应用和数据一起删除。游戏、聊天类应用先在应用内做绑定/备份，见 [添加应用与多开步骤.md](添加应用与多开步骤.md) 第五节。
- **想反馈问题去哪？** 官方源码仓库在 [https://github.com/BlackBoxing/BlackBox](https://github.com/BlackBoxing/BlackBox)，交流群是 Telegram 频道 [https://t.me/blackboxing](https://t.me/blackboxing)。提问时带上手机型号、系统版本、BlackBox 是 32 还是 64 位版，能少一轮来回。

官方多次强调稳定性未经大量测试、仅供学习交流。重要账号、唯一设备上的关键应用，别全押在黑盒里。
