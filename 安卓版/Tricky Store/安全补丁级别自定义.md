# Tricky Store 安全补丁级别自定义（security_patch.txt）

> 从 1.2.1 版起，Tricky Store 支持用 `security_patch.txt` 自定义密钥证明结果里报告的安全补丁级别。本篇讲简易与高级两种写法，以及它「只改证明结果、不改系统属性」的边界。
> **相关文档**：[target.txt配置详解.md](target.txt配置详解.md) · [keybox.xml配置指南.md](keybox.xml配置指南.md) · [常见问题与排查.md](常见问题与排查.md)

## 一、什么情况下会用到它

设备的实际安全补丁级别比较旧、而验证方在密钥证明结果里核对这一项时，两边对不上就会有麻烦。这个功能让你在**密钥证明结果**里报告一个自定义的补丁级别。

两个前提先对齐：

- 这是 1.2.1 版新增的功能，你从网盘拿到的这份是 1.3.0，已经包含；
- 它**只改密钥证明返回的结果**，不会去重置系统属性——系统属性里显示的补丁级别该是啥还是啥，官方文档专门强调了这一点，需要改属性得自己另用 `resetprop` 之类的工具处理。

## 二、简易写法

新建 `/data/adb/tricky_store/security_patch.txt`，里面写一行日期即可：

```text
# 修改 os/vendor/boot 的安全补丁级别
20241101
```

一行 `20241101` 的意思是：system、vendor、boot 三部分的补丁级别都按这个日期报告。日期格式用 `YYYYMMDD` 紧凑写法。

## 三、高级写法

想对每一部分分别控制，用 `键=值` 的格式，一行一条：

```text
# os 安全补丁级别为 202411
system=202411
# 不要修改 boot 安全补丁级别
boot=no
# vendor 安全补丁级别 20241101（使用了另一种格式）
vendor=2024-11-01
# 默认值
# all=20241101
# system 安全补丁级别与系统属性一致
# system=prop
```

键与值的取值范围：

| 键 | 管哪部分 | 可写的值 |
| --- | --- | --- |
| `all` | 全部 | 日期（两种格式都行） |
| `system` | 系统分区 | 日期，或 `prop`（跟随系统属性） |
| `vendor` | 厂商分区 | 日期 |
| `boot` | boot 分区 | 日期，或 `no`（不修改） |

日期两种写法等价：`202411` 与 `2024-11-01` 是同一个月。`#` 开头仍是注释。

## 四、改完之后

和另外两个配置文件一样，**保存立即生效**，不用重启。验证方式见 [常见问题与排查.md](常见问题与排查.md)——用 KeyAttestation 这类应用看证书链里的补丁级别字段有没有变成你写的值。

写错了也不至于出大事：把 `security_patch.txt` 删掉或清空，就回到默认行为（按设备真实值报告）。
