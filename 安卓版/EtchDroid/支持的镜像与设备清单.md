## 一、镜像类型：哪些能写、哪些不行

| 镜像 | 能否写入 | 说明 |
| --- | --- | --- |
| 现代 GNU/Linux 发行版 ISO / IMG | 可以 | Ubuntu、Debian、Fedora、Arch Linux、Linux Mint、pop!_OS、FreeBSD、BlissOS 等都在列 |
| 树莓派 SD 卡镜像 | 可以，先解压 | 官方镜像多为 `.img.xz` 压缩包，要先解出 `.img` 再写 |
| 微软官方 Windows ISO | 不行 | 从 microsoft.com 下载的官方 ISO 无法直接写入，原因见下文第三节 |
| 社区重制的 Windows 镜像 | 自行判断 | 官方提示这类镜像可能夹带病毒，来源不明就不要用 |
| Apple DMG 镜像 | 分版本 | 官方 2.0 起已移除 DMG 支持；1.5.1 是官方标注的最后一个支持 DMG 的版本（网盘备的就是这份，获取见 [下载与安装教程.md](下载与安装教程.md)） |
| 2010 年以前的旧 Linux 镜像 | 不保证 | Damn Small Linux、Puppy Linux 这类老镜像官方列为不可靠 |

## 二、设备：哪些能用、哪些不行

| 设备 | 可用性 | 说明 |
| --- | --- | --- |
| U 盘 | 可以 | 最常用、最稳的设备 |
| USB 读卡器 + SD 卡 | 可以 | 给树莓派写系统卡就是这个组合 |
| USB 移动硬盘 / SSD | 看情况 | 官方标注「部分可能可用」，供电是主要变数 |
| USB 扩展坞 / 集线器 | 看情况 | 经 U 盘设备过多或供电不足会失败，直插更稳 |
| 手机内部 SD 卡槽 | 不行 | 安卓系统不允许应用这样写入内部卡槽，官方也明确不靠 root 绕过 |
| 光驱 / 软驱 | 不行 | — |
| 仅支持 Thunderbolt 的设备 | 不行 | — |

一句话总结：**走 USB 口的「简单直插」设备基本都能用，越复杂的转接链路越容易出问题。**

供电是「看情况」那几类的最大变数：手机 USB 口输出的电流有限，U 盘和读卡器一般够用，但机械移动硬盘、接了多设备的扩展坞经常插上就掉盘——这不是应用或手机出了故障，是设备需要的电手机给不起。条件允许的话用带独立供电的 USB 集线器再接。

## 三、为什么微软官方 Windows ISO 写不进去

官方 FAQ 给过解释：现代 Linux 发行版的镜像采用的是「U 盘和光盘通吃」的分区与文件系统设计，而 Windows 官方 ISO 用的是 UDF 文件系统，多数电脑的 BIOS 不支持从 U 盘读取 UDF，所以直接刻进去也启动不了。要让 Windows ISO 能从 U 盘启动，得先把它转换成别的文件系统布局，官方 FAQ 里对此有专门说明。

所以如果你要装的是 Windows，思路只有两条：找一台能用的电脑用常规刻录工具处理，或者放弃 U 盘方案。EtchDroid 的定位就是 Linux 系统盘与树莓派镜像的应急写入工具。

## 四、容量与格式上的几个硬约束

- 镜像多大，U 盘就得多大以上，写入是整盘覆盖，不存在「装一半」。
- 写完的 U 盘在手机、电脑上通常都读不出来，这是镜像文件系统的特性，不是写坏了；想恢复日常使用，格式化一遍即可，四个平台的恢复步骤见 [写完的U盘怎么恢复.md](写完的U盘怎么恢复.md)。
- 老镜像（2010 年前）与 DMG（2.0 起）属于明确不保证的行列，别浪费时间反复试。
