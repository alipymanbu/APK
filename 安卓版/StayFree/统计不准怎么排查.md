# StayFree 统计不准怎么排查

> 时长榜单对不上实际使用、某几天数据整段缺失、浏览器只算成一条记录——这几类问题基本都能按固定顺序定位。本篇按「权限 → 后台 → 统计口径 → 设备关系」四层依次查，逐层排除比来回改设置省事。

## 一、按这个顺序查

1. **使用情况访问权限还在不在。** 系统升级、第三方清理工具、权限一键回收之后，这一项最容易掉。路径见 [首次打开要开的权限.md](首次打开要开的权限.md)。
2. **StayFree 有没有被后台清理。** 看断档的时间点是不是刚好在长时间息屏之后——是的话就是被系统杀掉了，去加自启动与电池白名单。
3. **是不是「某些使用没算进去」。** 息屏但后台放着的音频、视频，计不计入取决于你这版里的开关；部分版本在设置里提供了「是否统计后台播放音视频的标签页」这类选项（浏览器扩展端官方说明里就有这一项）。
4. **浏览器口径。** 手机系统本身只把浏览器算成一个应用，所以不装扩展，你只能看到「浏览器」这一条总时长；要看具体网站得装扩展，见 [网页与短视频怎么单独屏蔽.md](网页与短视频怎么单独屏蔽.md)。
5. **设备关系。** 多台设备关联在一起时，首页的总时长是合并值；只看单台设备，数字会小一截。断开或新增设备之后，统计口径会跟着变。
6. **系统环境。** 在分身 / 平行空间 / 多用户模式下装入的应用，统计往往覆盖不到；模拟器和部分深度定制系统也有同类情况。

## 二、几种常见现象的判断

| 现象 | 大概率原因 |
| --- | --- |
| 所有应用时长都是 0 | 使用情况访问权限没给 |
| 白天的数据有，晚上和早上缺 | 后台被杀（省电策略、自启动没放行） |
| 用过的应用没出现在榜单里 | 它在忽略名单里，或被当作系统类应用过滤掉了 |
| 只看到「浏览器」一条 | 没装浏览器扩展，网站粒度统计在扩展端 |
| 两台设备的数字对不上 | 设备没真正关联上，或者只连了一台 |
| 当天数字在某个固定时刻突然归零 | 到了每日重置时间 |
| 换过系统主题 / 字体后界面错乱 | 与统计无关，重开一次应用或回默认主题 |

## 三、和系统自带的数字健康对不上

手机自带的「数字健康与家长控制」也能看每日各应用时长，两边数字经常不一样，这属于正常现象，常见原因就这几类：

| 差异来源 | 说明 |
| --- | --- |
| 统计范围 | 系统自带只统计当前这台设备；关联了多台设备后，StayFree 首页给的是合并值 |
| 网站粒度 | 系统自带把浏览器算成一条；装了扩展之后才能拆到具体网站 |
| 保留周期 | 系统自带的逐日明细保留时间有限，多份第三方教程提到只按周滚动；两边的可追溯长度本来就不一样 |
| 受省电策略影响 | 系统的数字健康是系统组件，不受后台清理影响；第三方应用会，所以它断档更常见 |

差个几分钟不用管；差出一大截时，先把权限与后台白名单查一遍（见 [首次打开要开的权限.md](首次打开要开的权限.md)），再对照上面这张表确认是不是口径不同。两边各自能做什么、系统自带那套什么时候够用，见 [和手机自带的数字健康有什么区别.md](和手机自带的数字健康有什么区别.md)。

## 四、榜单里的小应用要不要较真

判断趋势时，注意两件事：一是长周期视图的取样更粗，排在很后面的小应用数字波动大，不必逐条核对；二是系统自带服务、桌面、输入法这类条目本来就会占掉一部分时长，别把它们当成「偷跑的应用」。

## 五、改设置之前先导出一份

排查过程中如果打算删历史、重置设置或重装，先把现有记录导出去——这几步都不可撤销。导出方式与卸载前要做的准备见 [使用记录导出与卸载前的准备.md](使用记录导出与卸载前的准备.md)。
