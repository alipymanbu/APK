## 一、先弄懂：番剧是从哪来的

用 Baka 之前要把一件事掰清楚：**Baka 本身不提供任何番剧内容**。官方对它的定位是通用的媒体播放与解析工具——它内置了一套规则系统，规则负责到各个第三方番剧站点上执行搜索、读取详情、解析出真正的播放地址。你在 Baka 里看到的每一部番，实际内容都来自规则背后对应的站点。

这带来两个直接后果：

- **能不能搜到一部番，取决于你在用的源收没收录它**，与应用本身无关。
- **某个源挂了，播放就失败**；第三方站点的接口和页面随时可能变，源失效是这类应用的常态，不是故障。

官方在项目文档里写明的合规口径也在这里一并转述：客户端不提供内容授权，你访问哪些站点、是否符合你所在地的法规和服务条款，需要你自己确认。

## 二、三层来源：内置源、社区规则、自定义站点

| 层级 | 是什么 | 适合谁 |
| --- | --- | --- |
| 内置源 | 随应用打包、装好就能用的源 | 所有人，开箱即播 |
| 社区规则 | 项目维护的规则库（AniBakaRule），通过应用内的规则中心获取 | 想要更多源的普通用户 |
| 自定义站点 | 自己填名称和域名新建的源 | 想接入自己常用站点的进阶用户 |

规则的更新走 GitHub 加速节点拉取，连不上时会自动依次回退到 jsDelivr 和 GitHub 直连——所以规则拉不下来时，先怀疑自己的网络对这三个地址通不通，而不是应用坏了。

规则库本身也在换代：官方在 5.0.0 新建了 AniBaka 规则库并收录 25 个规则源，同时停止兼容 Animeko、Kazumi 两类规则。也就是说，4.4.0 里的内置源名单和今天的社区规则不是同一批，逐版变化见[更新了什么与要不要升级](更新了什么与要不要升级.md)。

## 三、添加自定义站点的步骤

第三方教程里给出的添加路径如下（这一份 4.4.0 与新版对该页面的叫法略有出入，入口名称以你屏幕上实际显示的为准）：

1. 打开「我的」页面，点右上角的设置入口（齿轮图标）。
2. 进「内置源管理」（新版叫源管理）一类的条目，进入站点配置页。
3. 点页面下方的新建源按钮，打开填写页。
4. 依次填**源名称**（随你起，自己认得出即可）、**基础域名**（该站点的网址）、**描述**（可选）。
5. 打开启用开关，保存。

保存后回到搜索或首页，新源就参与聚合了。反过来说，如果某个源你不想用，也在同一个管理页里处理——官方在 4.5.2 的更新说明里才提到支持关闭内置源，4.4.0 里能直接管理的主要是自定义源这一层。

## 四、播放时换线路：卡了就换一条

同一部番常常有多条线路可用。播放页里提供线路入口，切换后接着看。什么时候该换：

- 当前线路加载慢、频繁缓冲 → 换一条线路试试；
- 播放页直接报错、黑屏 → 多半是这条线路对这一集的解析失效了，换一条最省事；
- 搜到的版本画质不满意 → 从搜索里用别的源重开这部番，找更高清的版本。

要注意的是：播放页里直接「换源」（不退出播放就切到另一个源）是 5.0.0 起新版才有的按钮；4.4.0 想换源，回搜索换一个源重新打开，收藏与观看记录都还在。线路和画质的具体操作在[弹幕与播放器设置](弹幕与播放器设置.md)里展开。

## 五、源失效了怎么办

按这个顺序排查，多数源问题都能解决：

1. **确认是源的问题**：换一个源搜同一个番，能搜到就是原源失效，不是应用坏。
2. **更新规则**：进规则中心检查有没有待更新的规则，社区规则会跟着站点变化修。
3. **检查网络**：规则更新依赖对 GitHub 加速节点、jsDelivr 的访问，播放依赖对源站点的访问；用移动数据和 Wi-Fi 各试一次，能定位是哪一段不通。
4. **都不行**：放弃这个源，换社区规则里的替代源。不要为失效的源反复重试，那是站点侧的问题，你这边重试多少次都一样。

更系统的排错流程（包括首页整个刷不出来、安装后首次联网失败等情况）见[常见问题与排查](常见问题与排查.md)；如果是刚装好就遇到，也可以先回[下载与安装教程](下载与安装教程.md)核对版本与权限。
