## 一、先说关系：Hamibot 基于 Auto.js 二次开发

Hamibot 的安卓客户端是在开源项目 Auto.js 的基础上二次开发的，脚本语法一脉相承 —— 社区里有用户把它形容成「Auto.js 的在线版」。由此带来三个直接后果：

- 学过 Auto.js 的人写 Hamibot 脚本几乎零成本；
- 网上 Auto.js 的教程、选择器写法大多能直接搬到 Hamibot 上用；
- 反过来读 Hamibot 的官方文档（[docs.hamibot.com](https://docs.hamibot.com/)）也能反哺你理解这套体系。

## 二、Auto.js 这几年发生了什么

查资料时容易混淆的部分，按公开资料理一条时间线（细节以各项目仓库为准）：

| 时间 | 事件 |
| --- | --- |
| 2020-03 | Auto.js 开源免费版停止更新，4.1.x 是免费版的最后版本 |
| 其后 | 出现两个主要分支：AutoX.js（基于 4.1.1 fork、开源）与 Auto.js Pro（原作者的付费闭源版） |
| 2020-11 | Hamibot 项目在 GitHub 创建，走「客户端 + 云端控制台 + 脚本市场」的路线 |

另据社区资料，Auto.js 后期版本对部分主流应用（淘宝、微信等）做了操作限制，AutoX.js 没有这类限制；这些限制随版本变化，以实际使用为准。

## 三、用起来的实际差别

| 维度 | Hamibot | Auto.js / AutoX.js |
| --- | --- | --- |
| 使用方式 | 需注册账号，脚本云端管理，网页控制台远程下发 | 本机 App 自带编辑器，独立运行 |
| 脚本来源 | 自带脚本市场，现成脚本装了就用 | 自己写，或从论坛找脚本手动导入 |
| 更新同步 | 脚本作者发布更新后，用户端实时生效 | 脚本文件自己分发、自己更新 |
| 多设备管理 | 控制台集中管理多台设备 | 各设备各自为战 |
| 付费点 | 免费额度之外按额度订阅；市场付费脚本单独收费 | AutoX.js 开源免费；Auto.js Pro 付费 |

取舍就在这组差异里：要云端管理和现成脚本，Hamibot 的形态更对口；要纯本机、不注册账号，AutoX.js 这类分支更直接。

## 四、从 Auto.js 迁移过来要注意什么

- **语法层面**：基本无缝，个别 API 差异以 [docs.hamibot.com](https://docs.hamibot.com/) 的文档为准；
- **形态层面**：脚本改放到云端账号里管理，注册与配对流程见 [注册配对与权限设置.md](注册配对与权限设置.md)；
- **发布层面**：自己写的脚本可以发布到脚本市场供人安装（有审核流程，有用户反馈等待时间不短），环境搭建见 [自己写脚本与开发工具.md](自己写脚本与开发工具.md)。
