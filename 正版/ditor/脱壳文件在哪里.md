# DITOR 脱壳文件在哪里找

> 脱壳跑完却找不到文件，是新手最常卡住的一步。本篇讲输出文件的路径在哪确认、文件长什么样，以及用什么工具打开这些 dex 文件。

## 一、路径在哪看

脱壳完成后，**输出路径会显示在结果里**（界面或悬浮窗），这是最权威的位置来源——不要凭印象去猜目录，每次跑完当场记下路径，或者直接复制。

如果当时没记，两个补救办法：

1. 用 DITOR 自带的**日志记录**翻最近一次操作，里面会带输出位置；
2. 用文件管理器按修改时间排序，找脱壳时间点前后新生成的 `.dex` 文件。

## 二、文件长什么样

- 输出的都是 **dex 文件**（安卓应用的字节码），文件名有时是目标的内部标识，需要你按应用名或日期**重命名**来区分。
- 一个应用可能一次导出**多个** dex（代码量大的应用本身就有多个 dex），都属于同一批结果。
- 个别情况下导出的文件需要先修复才能被查看工具正常打开，遇到「打开报错 / 内容错乱」先怀疑文件没修好，而不是工具不会用。

## 三、用什么工具查看

| 需求 | 可选工具 | 说明 |
| --- | --- | --- |
| 在手机上直接翻看 dex | MT管理器 这类文件管理器 | 自带 dex 查看能力，手机端最省事 |
| 在电脑上读代码、看整体结构 | jadx 之类的反编译查看工具 | 把 dex 拷到电脑上打开，能浏览可读的源码视图 |
| 只想确认文件是否完整 | 文件管理器看大小 | 大小为 0 或明显异常，说明这次脱壳没成功 |

把 dex 拷到电脑，数据线、局域网传输或云盘都行，按你顺手的方式即可。

## 四、文件管理建议

- 每个目标的输出单独建一个文件夹归档，避免多轮操作的 dex 混在一起对不上号。
- 文件名里带上目标应用名与日期，隔一段时间回来看还能对上。
- 确认没用的结果及时清掉，dex 文件积累起来并不小。

操作环节有疑问时回到 [使用教程.md](使用教程.md) 对照流程；根本跑不出文件的排查见 [常见问题解答.md](常见问题解答.md)。
