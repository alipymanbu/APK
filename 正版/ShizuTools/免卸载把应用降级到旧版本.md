# 免卸载把应用降级到旧版本教程

> 更新把应用改难用了？LookBack 菜单能直接装回旧版，数据留着不丢。

## 一、它适合什么情况

你遇到的是这三类问题之一：应用更新后变卡了、某个常用功能被更新删掉了、新版本界面/改版你不习惯。常规做法是先卸新版再装旧版 —— 卸载会把应用数据一并清掉。LookBack 走的是另一条路：直接把旧版本的安装包装上去，**不经过卸载这一步，登录状态和本地数据都还在**。

你手头需要先有**目标应用旧版本的 APK 文件**；ShizuTools 只负责装，不负责帮你找包（见 [Shizuku配对与启动教程.md](Shizuku配对与启动教程.md) 把服务先跑起来）。

## 二、操作步骤

1. 打开 ShizuTools，确认 Shizuku 授权已通过。
2. 进入 **LookBack** 标签页。
3. 点 **Start**，系统文件选择器会打开，只筛出 `.apk` 文件（界面提示原文是「Select an apk file to be installed as a downgrade」）。
4. 选中你准备好的旧版本 APK，等安装完成。
5. 回到桌面打开该应用确认：版本号变旧了、数据还在。

命令层面它做的是「重装 + 允许版本回退」（`pm install` 的 `-r -d` 组合），`-r` 保住数据，`-d` 打开降级开关 —— 这也是为什么不用先卸载。

## 三、什么时候会失败

官方 README 直接写着 **does not work on all devices**（并非所有设备可用），所以失败不等于你操作错了。已知的失败原因：

| 情况 | 说明 |
| --- | --- |
| 提示降级不被允许（Downgrade not allowed） | 部分系统保护应用、或旧包的版本目标高于当前系统支持范围时，`-d` 开关也压不住限制 |
| 设备/ROM 不支持 | 官方明确标注并非所有设备可用，换个包试也一样 |
| 选错了包 | 装的必须是**同一个应用**的旧版本；不同应用、不同包名的 APK 会被直接拒绝 |

试了两三个不同的包都失败，就别再耗了 —— 放弃降级、继续用现版本，比硬试安全。

## 四、两条边界

- **只动你自己的应用**。降级常被用在「更新把功能删了」这类场景，把它当成回退手段，不要拿去折腾来路不明的安装包。
- **降级不解决账号侧的限制**。应用如果在服务端校验版本（比如只允许新版登录），装回去也一样连不上，这不是 LookBack 能碰的范围。

删错了系统应用想找回，走的是另一条路，见 [卸载系统预装软件教程.md](卸载系统预装软件教程.md) 第四节；报错对照集中在 [常见问题与报错排查.md](常见问题与报错排查.md)。
