# NoActive 常见问题与故障排查

> 装完没效果、切回前台重载、消息延迟、和厂商机制打架……NoActive 用起来最常撞上的问题按现象归到本篇，先查现象再动设置。

## 一、装完完全不生效

按顺序查：

1. LSPosed 里模块已启用、作用域勾了「系统框架」，并且重启过手机（勾完不重启等于没勾）。
2. 打开 NoActive 的「运行列表」，确认是不是真的没有任何应用显示「已冻结」。
3. 到右上角设置换冻结方式，按内核对号入座的选法见 [冻结方式怎么选.md](冻结方式怎么选.md)。
4. 部分机型的系统框架没有权限读写 Freezer 目录——官方仓库提到这种情况可以开启提权模式再试。
5. 还不行：官方 Gitee 仓库的兜底方案是切 Kill -19 并每次开机执行一条 SELinux 策略命令，完整命令见 [冻结方式怎么选.md](冻结方式怎么选.md) 第五节。

## 二、怎么确认应用真的被冻结了

- 看运行列表：应用退后台后状态变成「已冻结」，这是最直接的判据。
- 用第三方工具看 CPU：有用户总结的经验是——应用退后台约 3 秒后 CPU 占用降到 0% 就是冻结成功；一直挂着 2–4% 说明没冻住（用户社区口径，个别应用后台本来就有常驻计算，自己多做几次对比）。
- 明明没冻结？先对照 [白名单与冻结规则设置.md](白名单与冻结规则设置.md) 第二节的自动豁免表——通话、定位、录音、VPN 这些状态下应用本来就不会被冻结，不是模块失灵。

## 三、应用切回来要重载 / 卡一下

- 用 KILL 方式时的已知现象：进程还在但回到前台可能重载，官方仓库原话是「进程还在依然重载」。换 V2 或 API 通常能改善。
- 重载也可能是应用被系统正常杀掉，而不是冻结失效——回看运行列表里它当时是否「已冻结」，再下结论。
- 还有两个高频反馈的现象：「闪弹」指点开应用动画刚出来就闪退、要再点一次才进得去；「掉卡片」指进程还在、最近任务的卡片却被清了。两者都多与冻结方式有关，换 V2 / API 后观察。
- 设置里的「定时解冻」就是给这类问题准备的：隔一段时间把冻结的应用解冻一下，防止应用因长期冻结在后台出毛病；个别应用冻结后行为异常时可以开它试试。

## 四、冻结中的应用无响应（ANR）

- 模块本身会屏蔽冻结应用的 ANR（官方作用域说明里有这一条），正常使用不应出现。
- 若某个应用频繁出现：先把它加白名单止血，再到日志（见第八节）里找 error 级别记录定位原因。

## 五、微信等应用消息延迟

- 把 IM 应用加入白名单；官方仓库说明：白名单推送进程时要把主进程一起加白，否则仍可能被后台限制。
- 国产 ROM 的推送通道与后台限制同样影响送达，模块只管冻结这一层。先加白验证延迟是不是冻结引起的，别一上来就怪模块。
- 社区进阶文档提到部分较新的 Pro 构建加入过 FCM 解冻（谷歌推送到达时临时解冻应用）；你手上的版本有没有这个能力，以设置里有没有对应开关为准，找不到就不用管。

## 六、和厂商自带的后台机制冲突

- MIUI / HyperOS / ColorOS 自带墓碑类机制（如「暂停执行已缓存」、ColorOS 的 hans），社区教程建议关闭或刷入对应的禁用模块，避免两套机制同时管理、互相打架。
- 小米的「电量和性能」清理：2.x 时代模块会处理它，3.0 起取消了这个处理（社区教程口径）。MIUI 用户若遇到锁屏后被清理，要自己处理电量与性能里的清理行为。
- 建议的环境是官方系统包加官方内核；移植包、第三方内核出问题不好定位（社区教程反复强调的一点）。

## 七、升级、版本分支与附加模块

- 从 2.9 及更早版本升到 3.x：先删旧配置目录 `/data/system/Noactive` 再装新版（社区教程提醒，否则重启可能异常）。
- 3.x 有正式版 / Pro / Alpha 几条分支的说法来自社区教程（Pro 为内测稳定版），以官方发布页为准；网盘里这份是 3.3-Pro。
- 要不要额外刷内核级「附加模块」（如 Re-Kernel）：社区说法不一致——有教程称部分系统的内核需要刷它的 lkm / kpm 版才能配合好；也有进阶文档把 KPM 版归为 APatch 玩家的选项；还有新人文档称任何有 LSPosed 的系统都能直接用。这里两边并列：先裸装实测，冻不住再考虑补。
- 官方渠道：开发者主页 [www.myflv.cn](https://www.myflv.cn/)、官方站点 [app.myflv.cn](https://app.myflv.cn/)（[使用手册](https://app.myflv.cn/guide/app.html)）、[LSPosed 模块仓库页](https://modules.lsposed.org/module/cn.myflv.noactive/)。

## 八、日志去哪看

| 位置 | 说明 |
| --- | --- |
| LSPosed 日志 | 模块作用域是系统框架，框架层的日志在 LSPosed 里看 |
| 文件日志 | `/data/system/NoActive_8位随机字符/log` |
| 级别 | 调试（反馈问题或分析时开）、信息（日常推荐）、警告、错误 |

排查顺序建议：先看「运行列表」确认现象，再看日志找原因，最后才是改白名单或换冻结方式。加白名单最省事，但它等于放弃这个应用的冻结收益，能用其他开关解决就别直接加白。
