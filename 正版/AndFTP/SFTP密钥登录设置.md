## 一、什么情况下需要密钥登录

两种典型场景：

- 服务器端关闭了密码登录（比如 VPS 上把 `PasswordAuthentication` 设为 no，只收密钥），密码填得再对也登不进去；
- 你不想把服务器密码长期存在手机里，密钥是更好的凭据形式。

密钥登录只对 SFTP/SCP 有意义——它们跑在 SSH 上；FTP/FTPS 用的是账号密码体系，没有密钥这一说。

## 二、AndFTP 里的配置步骤

官方 FAQ 给出的做法就五步：

1. 在站点设置里把「类型」选成 **SFTP**；
2. 填用户名，**密码留空**；
3. 切到「高级」标签，选择 OpenSSH 私钥（OpenSSH private key）；
4. 浏览选中放在手机存储里的私钥文件；
5. 如果私钥本身设了口令（passphrase），在 key password 一栏填上（没设就留空），保存后连接。

最容易踩的坑是第 2 步：很多人密钥都选好了，但密码栏里还留着旧密码，服务器端两个认证方式互相打架，结果登录被拒。**用密钥时密码栏就留空。**

## 三、私钥从哪来

电脑上用 OpenSSH 的 `ssh-keygen` 生成一对密钥，私钥（无后缀的那个文件）传到手机存储，公钥（`.pub`）追加到服务器的 `~/.ssh/authorized_keys`：

```bash
ssh-keygen -t ed25519
```

把 `id_ed25519.pub` 的内容追加进服务器端 `authorized_keys` 后，手机端的 AndFTP 才有得配。私钥文件通过数据线或局域网传到手机即可，AndFTP 在「高级」里浏览选择它。

服务器商如果直接发给你一对现成密钥（常见于云主机控制台），跳过生成这一步，直接部署公钥、传私钥到手机。

## 四、v5.6 支持的密钥类型

| 密钥类型 | v5.6 支持情况 |
| --- | --- |
| RSA / DSA | 长期支持 |
| ECDSA | v5.6 有所改进 |
| ED25519 | v5.6 新增 |

所以这份 v5.6 生成密钥时直接选 `ed25519` 就行（更短、更快，也是目前服务器端的主流默认）。如果你的服务器还挂着很老的 RSA 密钥，v5.6 同样能认。

两点版本相关的事实，供以后升级参考（以官方版本记录为准）：

- 从 v6.1 起，官方默认启用了 secure SSH 并收紧了策略；
- v5.6 相对更「兼容」，连一些只认传统算法的老服务器反而更顺——如果你的服务器很老、新版客户端连不上，留在 v5.6 是合理选择。

## 五、known_hosts 主机指纹校验

v5.6 加入了 SSH known hosts 主机密钥校验：首次连接 SFTP 服务器时会确认一次服务器指纹，之后每次连接都对照。它的实际意义在于——

- 服务器**重装系统**或换了 SSH 主机密钥后，App 会提示指纹变化。这时先确认「服务器确实重装过 / 服务商确实换过密钥」再更新记录，不要无脑接受；
- 连的根本不是你以为的那台服务器（DNS 劫持、连错内网机器）时，这个校验会替你拦一下。

## 六、密钥登录被拒时的检查顺序

1. 密码栏是不是没清空（见第二节第 2 步）；
2. 公钥有没有真的追加进服务器 `authorized_keys`（权限要求：`.ssh` 目录 700、`authorized_keys` 600）；
3. 私钥文件是不是 OpenSSH 格式——PuTTY 的 `.ppk` 不是，需要先转换；
4. 服务器端 `sshd_config` 是否允许你这个账号用密钥登录；
5. 还不行就把报错现象对着[连接失败常见问题排查.md](连接失败常见问题排查.md)过一遍；如果是第一次配置连接，先确认基础流程走通了——见[连接服务器配置步骤.md](连接服务器配置步骤.md)。
