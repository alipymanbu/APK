## 一、完全连不上（超时 / 拒绝连接）

按顺序核对：

1. **地址和端口**：SFTP/SCP 用 22，FTP/FTPS 常用 21，但不少服务商改过端口——以服务商面板里写的为准，不要按「常见端口」猜；
2. **网络路径**：手机流量和 Wi-Fi 是两条不同的出口，很多服务器端防火墙只对特定 IP 放行；家里 Wi-Fi 连得上、流量连不上（或反过来）多半是防火墙规则，不是 App 的问题；
3. **服务器是否在线**：用电脑上的 FTP 客户端连同一地址试一次，能快速区分「服务器挂了」还是「手机端配置问题」；
4. **账号并发限制**：部分虚拟主机限制同一账号的同时在线数，之前的连接没断开会挤掉新的，等一两分钟再连。

## 二、能连上但看不到文件 / 无法切换目录

- **远程目录没写对**：站点设置里的远程目录必须以 `/` 开头。填 `myremotefolder` 会失败，改成 `/myremotefolder` 就正常——这是官方 FAQ 里明确列出的坑；
- **账号权限不够**：服务器端该目录对你的账号没有读权限，联系管理员或换登录后落在有权限的目录；
- **目录是空的**：先确认服务器端确实有文件，有些 FTP 账号默认落在空的家目录，真正的站点文件在 `/www`、`/public_html` 之类的路径下；
- **中文文件名乱码**：客户端与服务器的编码不一致所致——Windows 平台的 FTP 服务器常用 GBK 系编码，而客户端默认按 UTF-8 解读。处理顺序：先到站点设置的「高级」里把编码方式改成 UTF-8 试一次（这是最常见的修法，两处独立的用户资料都指向这一步）；仍乱码说明服务器端不是 UTF-8，把客户端编码改成与服务器一致（入口同在高级设置里，具体选项名称以你手头版本为准）。文件名一旦以错误编码传上服务器，光改客户端设置不会纠正已传上去的名字，需要重传。

## 三、密码没错但登录被拒

按命中概率排序：

1. **协议类型选错**：拿 SFTP 去连 21 端口、或拿 FTP 去连 22 端口，都是「能连上但登录失败」的表象。回头核对服务商给的协议名称，见[连接服务器配置步骤.md](连接服务器配置步骤.md)第三节的对照表；
2. **服务器禁用密码登录**：不少 VPS 默认只收 SSH 密钥，这时要按[SFTP密钥登录设置.md](SFTP密钥登录设置.md)配密钥，而不是反复试密码；
3. **账号被锁定 / 密码含特殊字符**：密码里有引号、空格时个别服务器解析出问题，先在电脑端登录验证密码本身是否正确。

## 四、FTPS 特有的问题

- **证书校验失败**：服务器证书过期、自签名或域名不匹配时，握手会失败。v5.6 在 FTPS 上有数据通道安全选项（官方版本记录里列明），相关开关在站点设置里，具体名称以你手头版本的设置页为准；
- **能登录、列目录超时**：典型的被动模式端口段被防火墙挡住——控制连接通了、数据连接不通。让服务器管理员把被动模式的端口范围加进防火墙放行列表，或在客户端换成主动模式试试（见[连接服务器配置步骤.md](连接服务器配置步骤.md)第五节）。

## 五、传输中断 / 速度慢

- **中途断了**：重新传输同一文件即可，AndFTP 带断点续传，会从断点接着传（见[文件上传下载与权限管理.md](文件上传下载与权限管理.md)第三节）；
- **手机休眠导致传输停**：设置里开启 Wake lock 后再传大文件；
- **整体速度慢**：FTP/FTPS 每个文件都要额外建立数据连接，一次传几百个小文件会明显慢于一个大文件——先把整个文件夹打包成一个压缩包再传，是老练用户的常规做法；
- **移动网络下频繁断**：蜂窝网络抖动对长连接不友好，大传输尽量放在 Wi-Fi 环境。

## 六、主机密钥变化的警告（SFTP）

连 SFTP 时提示主机密钥变化，先别急着点接受。这个警告的两种常见来源：

- **正常情况**：服务器重装了系统、或服务商更换了 SSH 主机密钥——确认过再更新；
- **异常情况**：你的连接被引到了别的机器上（DNS 问题、内网连错机器）——核对服务器 IP 与预期一致再继续。

## 七、换手机时的配置迁移

重装 App 或换新机后，逐条重填服务器配置很折磨。两个省事的路径：

- AndFTP 自带**设置导出/导入**，换机前在旧机上导出配置文件，新机导入；
- 服务器配置原来记在电脑版 FileZilla 里的话，可以直接导入 FileZilla 的站点配置（官方功能清单里列明支持）。

导出入口在站点管理界面，具体位置以你手头版本为准。
