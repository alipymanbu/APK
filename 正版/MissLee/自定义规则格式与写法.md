## 一、两类规则：开屏与弹窗

规则都是一段 JSON，按处理对象分两类：

**开屏广告规则**——控制点掉开屏页上的「跳过 / 关闭」按钮：

```json
{"keywords":["关闭广告"]}
```

方括号里的值可以是按钮上的**文字**（如 `关闭广告`），也可以是控件的 **id**（如 `tv_close_button`）或**坐标 bounds**（如 `900,160,1170,250`）。注意 `keywords` 会**覆盖**默认开屏规则，只想追加时用 `keywords_append`。

**弹窗规则**——关闭应用内的各类弹窗（更新提示、青少年模式、开通知引导等）：

```json
{"popup_rules":[{"id":"检测到更新","action":"以后再"}]}
```

含义是：屏幕上出现含「检测到更新」的元素时，就自动点「以后再」。一条规则是一对 `id` / `action`，多条用逗号排在数组里。

## 二、匹配方式：默认模糊，符号收紧

规则里的文字**默认模糊匹配**——`以后再`、`以后`、`再说` 都能匹配到「以后再说」按钮。要精确控制时加前缀符号：

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `+文字` | 匹配以它**开头**的文字 | `+检测到` |
| `-文字` | 匹配以它**结尾**的文字 | `-用户体验` |
| `=文字` | 只匹配**完全相等**的文字 | `=以后再说` |
| `&` | 连接多个条件（且） | `+检测到&-用户体验` |

组合示例：`{"popup_rules":[{"id":"+检测到&-用户体验","action":"=以后再说"}]}`——开头是「检测到」、结尾是「用户体验」才触发，避免误伤其他弹窗。

## 三、点不到按钮时的三种替代写法

`action` 不一定填按钮文字。遇到只有叉号没有文字的弹窗，按可用性选：

1. **弹窗能被返回键关掉**：填固定值 `GLOBAL_ACTION_BACK`，等价于按一次返回：

   ```json
   {"popup_rules":[{"id":"=天天神券","action":"GLOBAL_ACTION_BACK"}]}
   ```

2. **叉号有控件 id**：直接填 id，如 `tv_close_button`。
3. **只有坐标**：填 bounds 四个数字，如 `500,900,620,1020`。

控件 id 与坐标要借助界面节点查看工具获得（开发者选项或专用查看工具）；拿不到时优先退回文字匹配，维护成本最低。

## 四、可调参数

写在对应层级的可选参数，按需使用：

| 参数 | 作用 |
| --- | --- |
| `delay` / `delay_popup` | 延迟点击（毫秒），广告还没渲染完就点空时加它 |
| `times` | 点击次数；`0` 表示只识别不点击，同一弹窗要点两次时设 `2` |
| `click_way_popup: 1` | 强制点击方式，规则正确却点不动时试 |
| `search_times_popup` | 每轮界面搜索次数，复杂页面找不到目标时加大 |
| `unite_popup_rules: true` | 联合规则，用于「倒计时结束才能关」这类需要多个步骤配合的持续任务 |

## 五、写完怎么验证

1. 按[规则导入与自定义.md](规则导入与自定义.md)的步骤导入保存。
2. 打开目标应用，看广告或弹窗是否被处理；弹窗一闪即过即生效。
3. 不生效时依次查：匹配符号是否过严（把 `=` 改回模糊试）、是否属于要界面刷新才触发的类型（切后台再切回，见[常见问题与失效处理.md](常见问题与失效处理.md)第三节）、是否需要加 `delay`。

## 六、来源与备份

- 不想从零写，先用社区现成合集：[snoopy1866 的 LiTiaotiao-Custom-Rules](https://snoopy1866.github.io/LiTiaotiao-Custom-Rules/)，里面的规则正是本篇这套格式，读懂格式后可以按需删改。
- 自己攒的规则记得定期导出存档（「更多」页里有导入 / 导出入口），换机或重装后直接导回，不用重写。
