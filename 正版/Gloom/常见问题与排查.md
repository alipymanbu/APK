这一篇不讲操作流程，只回答用起来之后最常冒出来的那几个问题：为什么点 GitHub 链接会跳进它、装不上是哪种原因、版本号和包名怎么认、它跟 GitHub 官方 App 到底差在哪。对着现象找答案即可，需要完整步骤的地方会指到对应那篇。

## 一、点 GitHub 链接被它接管了

装上 Gloom 之后，你在微信、浏览器或别处点开一个 `github.com` 的链接，系统可能会问「用哪个应用打开」，或者干脆直接跳进 Gloom。这是 Gloom 注册了 GitHub 链接的处理能力，不是 bug —— 反过来用它很方便：网页上看到一半的仓库，直接扔进 Gloom 读。

想改回来：

1. 让某个链接固定用浏览器打开：在系统「设置 → 应用 → 默认应用」里清除 Gloom 在这类链接上的默认状态；
2. 或者单次处理：点链接时弹出的选择框里选浏览器，并勾选「始终」，之后系统就记住你的选择；
3. 各家系统把这项设置放在「打开支持的链接」「默认打开方式」等不同位置，找不到就在设置里搜「默认应用」。

## 二、和官方 GitHub App 有什么区别

两个都叫「GitHub 客户端」，定位完全不同，装在同一台手机上互不冲突：

| 对比项 | Gloom | GitHub 官方 App |
| --- | --- | --- |
| 谁做的 | MateriiApps，第三方开源项目 | GitHub 官方 |
| 界面风格 | Material You，跟着你的壁纸取色 | 官方自己的设计语言 |
| 通知中心 | 没有 | 有，会推送 issue、PR、构建状态等 |
| 能做的写操作 | star、关注、表情回应三类 | 覆盖 issue 评论、PR 审核、合并等协作操作 |
| 代码浏览 | 有，含目录树与语言高亮 | 有，但以协作流程为主 |
| 联网要求 | 必须能访问 `github.com`，否则登录都走不完 | 同样需要 |

一句话选法：**要收通知、要处理协作事务，用官方那个；只是想舒舒服服读代码、翻项目、收藏仓库，Gloom 更合适。** 两者可以同时装着。

## 三、装不上、装完打不开

| 现象 | 多半是什么原因 | 怎么办 |
| --- | --- | --- |
| 点安装包提示「解析包错误」 | 安装包下载不完整或传输中损坏 | 回到 [Gloom 安装文件资源（夸克网盘）](https://pan.quark.cn/s/1b5cf0fe0273) 重新取一次，并按下载篇的第四节校验 MD5 |
| 提示「应用未安装」 | 同包名的应用签名不一致，或系统禁止安装 | 先看手机上已有 Gloom 的包名是否和这份一致；一致就先卸载旧的再装 |
| 系统直接拦下不让装 | 没给来源应用开安装权限 | 按下载篇第五节放开「未知来源」 |
| 装完点图标没反应 | 系统版本过低，或安装过程被打断 | 确认系统在安卓 5.0 以上；实在不行卸载清一次，重新装 |
| 装完是英文界面 | 系统语言不是中文，或该版本中文翻译未覆盖 | 见 [动态取色和图标怎么换.md](动态取色和图标怎么换.md) 第五节 |

## 四、版本号、包名怎么认

这是这份客户端最容易让人误会的地方，四条记住就够：

- **包名以 `com.materiiapps.gloom.debug` 为准**。网盘里这份就是这个包名。末尾的 `.debug` 说明它是调试构建，与官方正式包**不是同一个应用**，两者可以同时装着，各自的登录和设置互不影响。
- **版本号 1.0.0 不代表它比别的新或旧**。官方在不同阶段用过不同的编号口径，直接拿数字比大小会看错。判断是不是新版本，看官方构建产物页面上的时间，而不是编号。
- **判断两份包是不是同一个，看包名而不是看名字**。名字都叫 Gloom、图标也像，包名不同就是两个应用；包名相同但签名不同，会互相装不上。
- **网上的图文教程可能和你屏幕上的不一样**。Gloom 经过一次大改版，包名从 `com.materiiapps.gloom` 换成了 `dev.materii.gloom`，界面也重做过；网盘里这份属于改版前的线，按它对着旧教程看基本吻合，拿官方仓库现在的截图来对就会对不上。教程里的菜单名找不到时，以你手机上实际显示的为准。

## 五、更新这件事要有预期

Gloom 官方没有正式的发行版页面，正式的获取途径是官方仓库里 GitHub Actions 构建出来的产物，或者自行编译源码。也就是说：

- 手机上**不会自动提示更新**，得自己隔一段时间去官方渠道看一眼；
- **别收藏某个具体的构建产物链接**：那类产物有保留期（GitHub 上的构建产物默认保留 90 天，过期后打开就是 404，官方仓库里就有用户反馈过这个报错），要看新版就去官方仓库的入口现取，具体期限以 GitHub 与官方仓库当时显示为准；
- 网盘那条分享链接是长期有效的，换版本换的是里面的文件，链接不变；
- 这份 `.debug` 包换新版本，**做法是装新的、卸旧的**，不能像商店应用那样原地升级（包名不同）。

## 六、登录和首页的老问题

这两类问题出现频率最高，集中回答：

| 现象 | 结论 |
| --- | --- |
| 登录跳浏览器之后转不回应用 | 重走一次，跳转完成前别手动关浏览器；仍不行就换网络 |
| 一直登录不上 | 手机到不了 `github.com`，这个应用侧解决不了 |
| 用一阵子开始反复加载失败、过会儿又好了 | 请求次数被 GitHub 限了，等窗口过去即可，分辨方法见 [加载失败和请求次数限制怎么排.md](加载失败和请求次数限制怎么排.md) |
| 登录成功但首页是空的 | 新账号既没关注人也没 star 过东西，首页本来就空，先 star 几个仓库 |
| 首页只有仓库没有人的动态 | 去关注几个作者或组织 |
| 想要通知提醒 | 这份客户端没有通知中心，回 GitHub 网页端开通知 |

更细的步骤在 [登录与授权怎么弄.md](登录与授权怎么弄.md) 与 [首页动态和探索怎么用.md](首页动态和探索怎么用.md)。

## 七、卸载、换机与账号安全

- **卸载应用**：清理的是本地的登录状态和设置，**不会**删除你 GitHub 上的任何东西，star 和关注都还在账号里。
- **想彻底断开授权**：要去 `github.com` 的 Settings → Applications → Authorized OAuth Apps 里把对应条目移除。卸载不等于撤销授权。
- **换手机**：新机器上重新装、重新授权一次即可，star 与关注跟着账号走，不用手动搬。
- **密码始终没经过这个应用**：登录是在 GitHub 自己的页面上完成的，应用拿到的是授权凭证，不是你的密码。

## 八、存储与流量

- 安装包 25.64M，装完占用的空间与包体大致相当。
- 它没有常驻后台的同步和推送，**不打开就不会自己跑流量**；数据是你打开应用、翻到哪一页才去取的。
- 流量消耗主要看你在上面看什么：翻文字列表很省，反复打开大文件和大仓库会明显一些。
