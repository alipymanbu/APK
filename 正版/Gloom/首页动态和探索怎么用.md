## 一、首页那条流是怎么来的

Gloom 的首页不是推荐算法，也不给你做兴趣画像。它按你在 GitHub 上的关系往外铺，能出现的条目大致这几种：

| 条目类型 | 什么情况下会出现 |
| --- | --- |
| 你关注的人的动作 | 你 follow 了某个作者，他 star、新建仓库、发版时会出现在流里 |
| 你 star 过的仓库的动静 | 仓库有新的发行版，或者有 Pull Request 被合并 |
| 你可能感兴趣的仓库与人 | 与你的关注关系相近、或近期活跃的仓库和账号 |
| 组织相关条目 | 你加入或关注的组织有新动态 |

一句话概括：**首页的上限取决于你的关注列表**。一个刚注册、既没关注谁也没 star 过东西的账号，首页天然是空的，这不是应用坏了。

## 二、不知道看什么的时候去探索页

首页解决「我关心的东西有什么新动静」，探索页解决「GitHub 上现在有什么值得看的」。那里看的是平台上热度较高的项目，方向偏「逛」：翻一翻最近被讨论得多的仓库，看到有意思的点进去，再看作者还有没有别的仓库。

探索页的价值在于**不用先知道仓库名字**。如果你已经明确要找一个具体项目，更快的方式是直接在浏览器里搜到它的 `github.com` 地址，然后把链接交给 Gloom 打开 —— 装好 Gloom 之后，GitHub 的链接可以交给它处理，这个开关在哪里、怎么改回来，写在 [常见问题与排查.md](常见问题与排查.md)。

## 三、顺着一条线找下去

从首页或探索页点进一个仓库之后，常见的三条往下走的路：

1. **看作者**：从仓库跳到作者主页，看他 star 过什么、还维护哪些项目 —— 找同类工具最有效的一步。
2. **看 star 列表**：一个人的 star 列表通常比搜索结果更贴他的口味，尤其是小型项目。
3. **看 Releases 与提交**：判断这个项目还在不在维护，看最近一次发版和提交的时间，比看 star 数管用。

这三步具体怎么在仓库页里操作，见 [仓库页面能看什么.md](仓库页面能看什么.md)。

## 四、刷不出内容时按这个顺序查

| 现象 | 先查什么 |
| --- | --- |
| 整个首页空白 | 是否登录成功（看能不能看到自己的头像）；未登录时首页本来就是空 |
| 有内容但停在几天前 | 手动下拉刷新一次；再确认网络能不能连通 GitHub |
| 只有 star 的仓库，没有人的动态 | 你 star 过仓库但没关注任何账号，补几个关注就会有 |
| 探索页也打不开 | 基本可以判定是网络到不了 GitHub，与账号无关 |
| 反复提示加载失败 | 先换网络试；网络没问题却时好时坏，多半是请求次数被限了，见 [加载失败和请求次数限制怎么排.md](加载失败和请求次数限制怎么排.md) |

首页内容**不会推送通知**：Gloom 没有通知中心，需要盯着某个仓库的动静时，你的办法是回来手动刷，或者用 GitHub 网页端的通知功能。这也是它和官方客户端的最大差别之一，对比写在 [常见问题与排查.md](常见问题与排查.md)。

## 五、让它更好用的两个习惯

- **star 当收藏夹用**：想到什么就 star 一下，Gloom 里的 star 列表会跟着 GitHub 账号走，换设备也在。找同类项目时，翻自己的 star 列表往往比再搜一遍快。
- **关注人而不是仓库**：关注作者能持续收到他的新动作；只 star 仓库的话，只有这个仓库自己的动静会进来。

还有一点心理预期要放平：这是**浏览型客户端**，不是开发工具。想看代码、追进度、收藏项目它够用；想写代码、提 issue、开 PR，回电脑或网页端更顺手，别在手机上硬磕。
