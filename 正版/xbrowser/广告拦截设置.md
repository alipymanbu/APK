## 一、拦截功能在哪

X浏览器的广告拦截是**内置功能**，不需要像桌面浏览器那样先装一个拦截扩展。在浏览器设置里找到广告拦截入口打开总开关即可。

但要注意：**只开总开关效果有限**。官方的推荐做法是再订阅现成的拦截规则，订阅后才能拦住网页广告、视频广告和弹窗。

## 二、订阅拦截规则（推荐做法）

X浏览器支持订阅主流拦截规则，比如 EasyList、AdGuard 等。官方文档原话是：你只需要订阅第三方的一些拦截规则，即可达到很好的拦截效果。

操作思路：

1. 进入设置里的广告拦截（广告过滤）页面；
2. 找到规则订阅列表，添加你想用的规则源；
3. 保存后规则会随订阅更新，不需要手动维护。

常用的规则源（截至 2026-09，以各规则官网为准）：

| 规则 | 语言/范围 | 备注 |
| --- | --- | --- |
| EasyList | 英文站点为主 | 最老牌的通用规则 |
| EasyList China | 中文站点 | 配合 EasyList 使用 |
| AdGuard 规则 | 多语言 | AdGuard 维护的通用规则 |

## 三、两类拦截规则的区别

官方文档把拦截规则分成两大类，工作方式不同：

| 维度 | URL 拦截规则 | 隐藏元素规则 |
| --- | --- | --- |
| 生效时机 | 资源请求发出**前** | 页面渲染**后** |
| 是否省流量 | 通常更省流量 | 一般不省（资源已加载） |
| 典型目标 | 广告用的 JS/CSS/图片等资源 URL | 直接嵌在页面里的广告模块 |
| 可能的现象 | 误杀时页面功能异常 | 广告闪一下再消失 |
| 适用场景 | 广告以资源形式加载 | 广告混在页面结构里 |

URL 拦截规则匹配的是加载广告资源的网址，形如：

```text
||example-ad.com^
/haojio/js/scoll_bg.js
/heituad/*
```

隐藏元素规则通过选择器找出页面里的广告元素再移除，形如：

```text
example.com##.topbanner
drugs.com##.topbanner-wrap
```

## 四、自己写规则

如果你要针对某个站点自己写规则：X浏览器兼容 90% 以上的 ABP（Adblock Plus）规则语法，并在此基础上做了简化和少量自有扩展。上面两类规则的写法、例外规则、强力拦截模式，官方文档各有专文：

- [广告拦截简介](https://www.xbext.com/docs/ad-block-overview.html)
- [URL 拦截规则写法](https://www.xbext.com/docs/how-to-write-url-block-rule.html)
- [隐藏元素规则写法](https://www.xbext.com/docs/how-to-write-hide-element-rule.html)
- [例外规则写法](https://www.xbext.com/docs/how-to-write-exception-rule.html)
- [强力拦截模式和规则](https://www.xbext.com/docs/about-strong-adblock.html)

性能方面，官方文档称导入大量 ABP 规则（数十万条量级）仍能保持页面渲染性能，这条以官方说明为准。

## 五、常见现象与误杀处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面广告先闪一下再消失 | 隐藏元素规则是渲染后才移除元素 | 正常现象，不用处理 |
| 个别广告怎么都拦不掉 | 广告不是独立资源加载，或与正常业务混在一起 | 针对该站补隐藏元素规则 |
| 某网页按钮点不动、排版错乱 | 拦截规则误杀了页面元素 | 先关掉拦截对照确认；确认后给该站加例外规则 |

拦截导致的页面异常只是原因之一，完整的排查步骤（包括禁用脚本、检查 JS 开关等）见[常见问题与故障排查](常见问题与故障排查.md)。
