# App Ops 与系统自带权限管理的区别

> 系统设置里的权限开关和 App Ops 看起来都在管"权限"，实际管的东西、拒绝的方式、能改的范围都不一样。本篇用一张对照表说清两边差别，再告诉你什么场景用哪个。

## 一、两者管的不是同一层东西

系统权限面板管的是"运行时权限"（相机、麦克风、定位这类），档位就是允许 / 拒绝，以及安卓 10 以后的"仅在使用期间允许"等。

App Ops 管的是系统里另一套"应用操作"设置：其中一部分与运行时权限对应，另一部分是系统面板里根本没有开关的操作 —— 比如读取剪贴板、后台行为。你能看到的操作清单以你手机的系统为准，在 App Ops 的 设置 - 行为 - 全部权限 里能看全。

## 二、对照表

| | 系统权限面板 | App Ops |
| --- | --- | --- |
| 可管范围 | 运行时权限 | 运行时权限对应的操作 + 系统面板没有的操作（剪贴板、后台行为、传感器等） |
| 拒绝后的表现 | 应用调用时收到错误 | 应用不报错，只拿到空白数据 |
| 应用能否察觉 | 能，拒绝是明确的 | 多数察觉不到；主动检查的应用仍能发现 |
| 批量与模板 | 无 | 可按操作查看全部应用；模板、备份恢复、批量操作 |
| 设置的持久性 | 系统自己维护 | 安卓 11 及以上会在个别时点被系统重置 |
| 使用门槛 | 系统自带，打开就能用 | 需要先接上工作模式（Shizuku / root 启动） |

## 三、什么场景用哪个

- **只想关掉某个应用的定位、麦克风**：系统面板就够，不用折腾 adb。
- **想禁止应用读剪贴板、管住后台行为，或者想知道"谁在偷偷干这事"**：系统面板没有这些开关，用 App Ops 的"按操作看"视角。
- **想管加速度计这类传感器的使用**（安卓 10 以上支持）：传感器不需要权限，系统面板连入口都没有，App Ops 里可以控制。
- **不想让应用知道"我被拒了"**：系统面板一拒，应用调用就报错；App Ops 的拒绝是静默的，应用只拿到空数据。
- **换机或刷机后想快速恢复一整套权限配置**：App Ops 的备份导出再恢复，比逐个应用重设省事。

两处细节要记住：

1. App Ops 不能直接改"权限"本身（官方用语声明），彻底开/关一个运行时权限仍以系统面板为准；
2. 两边对同一权限的设置会互相影响 —— 系统写入的是高优先级设置，会压过 App Ops 的修改，纠结时两边设成一致。具体的冲突表现与排查见 [常见问题与解决方法.md](常见问题与解决方法.md)。
