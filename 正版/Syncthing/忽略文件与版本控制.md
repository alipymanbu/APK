## 一、排除不想同步的文件：`.stignore`

每个同步文件夹的根下可以放一个名为 `.stignore` 的文本文件，里面一行一条模式，命中的文件**不参与同步**。注意：排除只在本机生效，各台设备的 `.stignore` 相互独立、不会互相同步。

编辑入口：App 里点开文件夹 →「编辑」→「忽略模式」；电脑端在 Web GUI 该文件夹的「编辑」→「忽略模式」标签页。

常用写法：

```text
// 双斜线开头是注释
Thumbs.db            // 精确匹配这个文件名，各层子目录里的同名文件也命中
*.tmp                // 星号：匹配文件名里的任意字符，不跨目录层级
**/raw               // 双星号：可跨目录层级
photo?.jpg           // 问号：单个任意字符
!important.log       // 感叹号：例外，前面规则排除掉的它要保留
(?i)readme           // 不区分大小写地匹配
(?d)cache            // 允许随父目录一起删除（适合缓存类文件）
/temp                // 开头带斜线：只匹配文件夹根下的 temp
```

三条规则要点：

- 从上往下**第一条命中的生效**，所以例外（`!`）要写在宽泛规则的前面；
- `!` 例外规则会让 Syncthing 检查整棵目录树，目录很大时会明显加重扫描负担；
- 排除规则不会把**已经同步过的文件**从对方设备上删掉，只会让它以后不再跟着变。

一个绕不开的场景：笔记类应用（Obsidian、Joplin 等）会频繁改写自己的工作区状态文件，两台设备一用就产生冲突副本，社区通行做法是把这类文件加进 `.stignore`。相册备份场景要排除的 `.thumbnails` 缩略图缓存和 `.trashed-` 回收站文件，见[手机照片自动备份到电脑](手机照片自动备份到电脑.md)。

## 二、`.stfolder`：删了会报错的管理标记

每个同步文件夹根下都有一个 `.stfolder` 目录，它是「这个文件夹归 Syncthing 管」的标记。它一旦丢失，App 会停止该文件夹并报 **folder marker missing**。处理办法：手动在文件夹根下新建一个名为 `.stfolder` 的空目录，回到 App 点该文件夹的「重新扫描」即可恢复。

## 三、文件版本控制：给误删留后路

默认情况下，你在 A 设备删一个文件，同步之后 B 设备上的它也会被删掉。版本控制的作用是：**收到「删除 / 覆盖」的同步改动时，不直接删，先把旧文件挪进归档目录 `.stversions`**。设置入口在文件夹编辑页的「文件版本控制」，默认是关闭的。

四种策略对比：

| 策略 | 行为 | 适合 |
| --- | --- | --- |
| 无文件版本控制 | 默认；删除即删除，不留旧版 | 一次性中转、不在乎误删 |
| 回收站式 | 被删/被覆盖的旧文件都进 `.stversions`，可设自动清理天数 | 大多数人的稳妥选择 |
| 简单版本控制 | 同上，再限制每份文件最多保留几个历史版本 | 反复改的文档 |
| 阶梯式版本控制 | 按时间梯度淘汰：1 小时内每 30 秒留一版、1 天内每小时留一版、30 天内每天留一版、此后每周留一版，直到最长保留期 | 相册、长期项目，兼顾容量 |

注意两点：

- 版本控制只对**从其他设备同步来的改动**生效——你在本机自己删的文件，本机不会归档它；
- 找回文件：打开文件夹里的 `.stversions`，把要的那份复制回原位即可。

## 四、怎么选

- 相册备份：手机端「仅发送」+ 电脑端「回收站式」版本控制，误删的手机端文件在电脑端有档；
- 双向编辑的资料夹：「发送和接收」+「简单版本控制」；
- 大体积、一次性中转：不加版本控制，控制磁盘占用。

冲突副本的产生与清理是另一套机制，见[冲突文件处理](冲突文件处理.md)。
