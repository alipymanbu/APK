# Syncthing 中继连接慢的解决方法

> 设备详情里连接类型带「中继 / Relay」，说明两端没能直连、速度被兜底通道限制。本篇讲怎么确认、怎么切回直连。

## 一、先确认你是不是走了中继

- 电脑端 Web GUI：右侧设备列表展开对应设备，「连接类型 / 地址」以「中继 / Relay」开头即为中继；
- 手机端：设备页展开对应设备，同样能看到连接信息。手机端也有完整的 Web GUI（左上角菜单 →「Web GUI」，浏览器地址 `http://127.0.0.1:8384`），界面与电脑端一致，下面要改的设置两边都能调。

## 二、为什么会走中继

两端都在路由器（NAT）后面、直连握手失败时，流量改走官方的公共中继服务器转发。数据本身全程加密，但速度受中继负载限制，通常远低于直连。

## 三、切回直连的四个办法（按优先级试）

1. **给一台设备做端口转发**：进路由器管理页，把 `22000/TCP` 和 `22000/UDP` 转发到那台设备的内网 IP。两端里有一台做了转发，通常就能建立直连，另一端不用动。路由器支持 UPnP/NAT-PMP 的话，也可以在 Syncthing 的连接设置里开启 NAT 遍历，让它自动映射端口；
2. **放行本机防火墙**：电脑的本机防火墙放行入站 `22000/TCP`、`22000/UDP`，以及 `21027/UDP`（局域网设备发现用的广播端口）；
3. **手动指定对方地址**：同一家庭网络但本地发现失效（路由器隔离了广播、访客网络等）时，打开对方设备的编辑页，把「地址」从 `dynamic` 改成 `tcp://对方内网IP:22000`。给那台设备配静态 IP（或在路由器里绑定 IP）更稳；
4. **虚拟组网兜底**：两端都不方便动路由器时，社区常见做法是用 Tailscale 这类虚拟组网工具让设备互相可达，Syncthing 会经由虚拟网络直连（非官方方案，是否使用你自己取舍）。

## 四、改完怎么验证

回到设备详情看连接类型：不再以「中继 / Relay」开头，显示 `tcp://…` 或 `quic://…` 开头的地址即为直连成功。

## 五、直连了还是慢

- 初次同步大文件夹时，瓶颈常在两端的处理器校验速度，尤其是低配置手机和 NAS；
- 隔着互联网同步时，上限是两边的上行带宽，和下载带宽无关；
- 如果问题是「根本不动」而不是「动得慢」，先看[后台同步条件设置](后台同步条件设置.md)——大概率是运行条件或电池优化把后台停了。
