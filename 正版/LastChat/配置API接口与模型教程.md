## 一、先明白它的计费模型

LastChat 是自带 key（BYOK）的客户端：应用本身不收订阅费，也不内置任何额度，你调用哪家模型、就用哪家发的 API key，费用按你那边的用量算。key 只保存在设备本地，请求直连你填的服务商。

所以装完第一步不是聊天，而是配提供商 —— 这也是 [下载与安装教程.md](下载与安装教程.md) 里「第一次打开」卡住大多数人的地方。

## 二、接入一个提供商

LastChat 的上游是 RikkaHub，菜单结构基本沿用，各家版本的措辞略有差异，以你装的界面为准。通用流程：

1. 打开侧边栏 → **设置** → **提供商**（有的版本叫「提供商设置」）。
2. 列表里已经预置了常见服务商卡片（OpenAI、Anthropic Claude、Google Gemini、DeepSeek、OpenRouter 等），有对应 key 就直接点进去填；列表里没有的，点右上角新建。
3. 新建时选接口格式 —— 这是最容易选错的一步：

| 接口格式 | 什么时候选 |
| --- | --- |
| OpenAI（Chat Completions） | 默认选择。绝大多数中转、聚合站、开源模型服务都用它 |
| OpenAI 的 Response API | 用 OpenAI 官方 API 或只支持新接口的中转时切到这个模式 |
| Claude 原生格式 | Anthropic 官方 key |
| Gemini 原生格式 | Google Gemini 官方 key |

4. 填 **Base URL** 与 **API key** 后保存。用预置卡片时 Base URL 已经填好，只需贴 key；用自定义中转时 Base URL 要改成服务商给的那个（形如 `https://某中转域名/v1`）。
5. 本地/自建服务（如 Ollama、LM Studio）不需要真 key，填任意非空字符串即可。

部分服务要额外的请求头（比如 OpenRouter 要求 `HTTP-Referer`），在提供商详情的 **Custom Headers** / 自定义请求头 里加键值对；`Authorization: Bearer` 那一行应用会自动加，不用自己写。

## 三、加模型并选默认

提供商保存后，回到它的详情页底部的**模型**栏：

- 点展开**模型列表**，从列表里勾选要用的（多数支持列模型的服务商会直接列出来）；聚合服务要填完整模型 ID，如 `openai/gpt-4o`、`anthropic/claude-opus-4-5`。
- 列表拉不到就手输模型 ID 添加；加错了侧滑删除。
- 1.4.3 起改用内置的 **LastChat catalog** 提供商/模型目录，能直接从目录里挑模型，省去手填 ID；1.4.1 起提供商设置里还有 **Probe API capabilities**（探测 API 能力）按钮，跑一次请求自动识别该模型支持哪些能力，不用自己猜。

配完回设置里的**默认模型与提示词**，把对话、标题生成、翻译这些功能各自用的模型定下来。通常对话用主力模型，标题生成这类辅助任务挑个小而快的。之后在聊天界面的模型选择器里可随时切换，切换只影响新消息。

## 四、接完发不出消息，先查这四样

1. **key 是否有效**：同一份 key 在服务商后台能不能查到余额/调用记录；部分服务（OpenRouter、DeepSeek、SiliconFlow 等）在提供商设置里有余额检查项可直接配，你的版本没有这项就去服务商后台查。
2. **Base URL 是否带了 `/v1` 且与服务商文档一致** —— 少一段路径是最常见的连不上的原因。
3. **模型 ID 是否真实存在于该服务商**，拼写、大小写、前缀都要对。
4. **接口格式是否选对**（表格那一列）。

四样都对还在报错，就按状态码走 —— 401/404/429/413 各有各的动法，见 [API报错与连接失败怎么排查.md](API报错与连接失败怎么排查.md)；不是报错而是「没有任何反应、一直转圈」的，同一篇第四节排查链路。仍不行时把该提供商删掉重建一次，或换一个服务商卡片对照测试，能快速定位是 key 的问题还是填法的问题。

## 五、key 与配置的安全边界

- key 只存本地，但**导出/分享提供商配置会把 key 一起带出去**：应用支持把提供商配置生成二维码或文本串分享，那串内容里含明文 key，只发给你信得过的人。
- 助手配置另有导入/导出功能，用于换机迁移，见 [助手设定与角色卡怎么用.md](助手设定与角色卡怎么用.md)。
- 别把填好 key 的截图发到公开场合。
