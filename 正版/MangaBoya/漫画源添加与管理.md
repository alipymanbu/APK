## 一、先理解它的内容模型

MangaBoya 与内置版权库的漫画应用不同：它的内容来自一个个「订阅源」（仓库式的站点集合）。你添加了哪些源，决定了能搜到什么、能看到什么。所以装好后第一件事是添加源，之后阅读体验的好坏也很大程度取决于源的质量。

## 二、添加源的步骤

以 1.8.x 版本界面为例（新版本入口名称可能略有不同）：

1. 打开 MangaBoya，点界面右上角的「+」图标；
2. 进入订阅源页面后，能看到一份已有的仓库列表，从中勾选想用的源；
3. 列表里没有的，走**手动添加**：在订阅站点页选「手动添加」，把仓库地址填进表单，点「保存」即可导入一个新源；
4. 也支持添加第三方维护的仓库——添加前先确认来源可信，来路不明的仓库不要加。

添加完成后回到首页，点「最近更新」可以切换分类浏览；搜索框则会在你已添加的源里检索。各版本之间这部分的菜单措辞有过调整（2.x 与 1.8.x 的入口不完全一样，差异对照见 [版本更新与新旧版差异.md](版本更新与新旧版差异.md)），认准「订阅站点 / 手动添加」这类字样即可。

## 三、第三方源通常托管在 GitHub 上

1.8.x 时代的社区源大多以 GitHub 仓库形式发布。这里有两个实际会碰到的坑：

- **访问 GitHub 失败**：部分网络环境直连 GitHub 不稳定，添加或刷新源会一直转圈。这种情况下可能需要你自行解决网络可达性，或换个时段再试。
- **页面出现 "Whoa there" 字样**：这是 GitHub 的限流提示，代表当前 IP 被临时限制。处理办法是更换网络节点（切换 IP）或避开高峰时段再试，无须反复刷新。

## 四、源加载失败的判断与处理

| 现象 | 多半是 | 先做什么 |
| --- | --- | --- |
| 搜索页一片空白 | 内置源没加载成功 | 完全退出应用重新打开；每次启动时都会重新尝试加载源 |
| Wi-Fi 下加载不出 | 当前网络访问源站受限 | 切到移动流量试试；反过来也一样 |
| 能搜到但图片不显示 | 源站图片服务器波动 | 过段时间再刷新章节 |
| 某个源所有内容都打不开 | 该源本身失效 | 先移除再重新添加；仍不行就换源 |

官方更新记录也能佐证「源会失效、官方会修」这件事：2.0.x 到 2.2.x 的多次更新说明里都写着修复某个源（如 "Fixed the WC source"、"Fixed: broken images on the MP source"），2.1.0 还专门加了针对失效源的切换功能。你手上的 1.8.4 没有自动切换功能，遇到失效源只能手动增删。

## 五、源管理的日常建议

- **少而精**：源加太多，首页刷新和搜索都会变慢，留下三五个稳定好用的就够；
- **坏了先重启**：多数「源挂了」其实是本轮加载失败，重启应用再试一次再下结论；
- **搜不到书先换源**：同一个名字在不同源里的收录差异很大，换关键词、换源都比反复刷新有效——更多排查思路见 [常见问题排查.md](常见问题排查.md)。

内容解决了，接下来通常是两个方向：把自己下载的漫画文件导入进来（[本地漫画导入与离线阅读.md](本地漫画导入与离线阅读.md)），或者把阅读方式调到顺手（[阅读设置与界面个性化.md](阅读设置与界面个性化.md)）。
