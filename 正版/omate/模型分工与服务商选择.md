## 一、六类模型各管什么

OMate 的功能不止「聊天」一种，不同功能默认吃不同的模型。官方手册的分工如下：

| 模型类型 | 管什么 | 能否用对话模型顶替 |
| --- | --- | --- |
| 对话模型 | 与 AI 角色聊天 | ——（这就是主力） |
| 总结模型 | 自动回复、长期记忆提取、聊天历史的自动标题；不填则由对话模型兼任 | 可顶替（填了更省） |
| 嵌入模型 | 向量化知识库 | **不能** |
| 语音模型 | 语音播放与语音通话的合成 | **不能** |
| 生图模型 | 创建角色时生成头像和背景 | **不能** |
| 语音识别模型 | 语音通话时把你说的话转文字 | **不能** |

结论先记住两条：**只用文字聊天，配一个对话模型就够了**；**想用知识库、语音、生图，就必须在对应位置再填专门的模型** —— 拿对话模型的名字填进嵌入模型位置是不工作的。

## 二、服务商怎么选：一张官方支持矩阵

官方手册给过一张矩阵，说明同一个服务商能覆盖几类模型（截至本篇整理时，模型名以官方手册与服务商文档为准）：

| 服务商 | 对话 | 总结 | 嵌入 | 语音 | 生图 | 语音识别 |
| --- | --- | --- | --- | --- | --- | --- |
| 硅基流动 | DeepSeek-V3 / R1 | DeepSeek-V3 | BAAI/bge-m3 | CosyVoice2-0.5B | Kwai-Kolors/Kolors | 当时下线 |
| DeepSeek 官方 | deepseek-chat / reasoner | deepseek-chat | 不支持 | 不支持 | 不支持 | 不支持 |

读这张表的判据：

- **只想低成本先跑起来**：DeepSeek 官方一类「只有对话」的服务商就够，其余功能暂时放弃；
- **想把语音、生图、知识库一次配齐**：选覆盖面广的聚合服务商（如硅基流动），一个 key 配齐六类，不用到处注册；
- **要效果上限**：对话模型可以选 Claude、Gemini 等规范（应用 1.0.13 起支持 Claude 规范，仅聊天和总结模型），其余功能另配。

兼容性口径沿用官方提醒：理论上 OpenAI / Claude / Gemini 规范的接口都能接，但各家支持程度不同，个别服务商下会无法正常工作。

## 三、以硅基流动为例：从一个 key 到配齐

官方手册的推荐路径，三步拿到密钥：

1. 打开 [siliconflow.cn](https://siliconflow.cn) 注册账号（有试用 token 送，够先跑通）；
2. 进 [API 管理页](https://cloud.siliconflow.cn/account/ak) 新建一个 API 密钥；
3. 复制密钥，回 OMate 的 [API设置与密钥配置.md](API设置与密钥配置.md) 里填进去。

然后把各类模型名按第一节的分工分别填到设置里对应的位置。服务商用 DeepSeek / Qwen 等开源模型，价格比自己挤官方 API 便宜，模型名与价格以 [服务商文档](https://docs.siliconflow.cn) 当前显示为准。

## 四、钱花在哪：成本口径

这个应用的成本结构在装之前就该算清：

- **应用本身不收月费**：官方更新日志里有「支持免费永久激活 Pro 功能」的条目，设置页里的 OMate Pro 区块按提示激活即可（以应用内提示与[官方更新日志](https://help.omate.org/changelog/)为准）；
- **真正持续花钱的是模型调用量**：角色扮演聊天来回频繁、上下文又长，token 消耗比普通问答类应用高；长期记忆的载入条数调得越大越耗；
- **想零成本**：接本地模型（见 [API设置与密钥配置.md](API设置与密钥配置.md) 的本地模型一节），电费之外不产生调用费；但嵌入、语音、生图这些专用模型，本地未必有对应服务，缺哪类哪类功能就不可用。

## 五、配好之后怎么验证

- 文字聊天：发一条消息有流式回复即通；
- 知识库：挂一份资料做向量化，不报错即嵌入模型生效；
- 语音与通话：见 [语音播放与语音通话设置.md](语音播放与语音通话设置.md) 的逐项检查；
- 哪类功能报错，回 [常见问题与故障排除.md](常见问题与故障排除.md) 对照排查。
