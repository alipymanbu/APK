# Sefirah 和 KDE Connect 这类工具的区别

> 本篇把三套常见的「手机连电脑」方案放在一起对照：Sefirah、KDE Connect、微软 Phone Link，只看平台覆盖、账号与数据路径、功能边界，不替你做选择。

搜 Sefirah 的人多半手上已经有别的方案，或者装完想知道「这和 KDE Connect 有什么区别」。三套工具的定位确实重叠，但卡点不一样：有的是平台不对、有的是必须绑账号、有的是功能按机型给。

## 一、一句话区分

| 工具 | 是什么 | 谁维护 |
| --- | --- | --- |
| Sefirah | 开源（GPL-3.0）；安卓端 + Windows / Linux 桌面端，局域网直连 | 开发者 shrimqy，代码在官方 GitHub 仓库 |
| KDE Connect | 开源（GPL v2+）；覆盖 Linux / Windows / macOS / Android / iOS | KDE 社区 |
| Phone Link | Windows 自带的官方方案 | 微软 |

## 二、装之前先看四项

| 要看什么 | Sefirah | KDE Connect | Phone Link |
| --- | --- | --- | --- |
| 需要注册账号吗 | 不需要 | 不需要 | 需要微软账号 |
| 数据走不走云端 | 两端在局域网直连，不经过云端 | 两端在局域网直连，不经过云端 | 走微软账号体系 |
| 桌面端支持哪些系统 | Windows、Linux（官方说明 Linux 支持有限） | Linux、Windows、macOS | Windows |
| 手机端支持哪些系统 | Android | Android、iOS | Android、iPhone（功能随机型不同） |

电脑是 Mac、或者手机是 iPhone，这两项直接就把选择范围定下来了。所以这一步先看平台，不用看功能表。

## 三、功能边界上的差别

三套都覆盖剪贴板同步、文件互传、通知镜像、短信、媒体控制，差别在具体实现和附加能力：

- **Sefirah** 的手机存储集成，是把手机存储挂进 Windows 资源管理器（要求 Android 11 及以上）；屏幕镜像由另一个开源工具 scrcpy 完成，scrcpy 要自己另外装、并在设置里指向它的位置。
- **KDE Connect** 的附加能力偏向「把手机当输入设备」：虚拟触摸板、手机当键盘、演示翻页笔、找手机。它的官方功能列表里**没有屏幕镜像**，要镜像得另找工具。它的官方文档写明使用 1714 到 1764 这一段端口，和 Sefirah 用的 5149 到 5169 不重叠。
- **Phone Link** 与 Windows 的集成度最高，但功能按手机品牌给：有文章提到它的剪贴板同步长期只在部分合作机型上完整可用，具体以你自己机器的实测为准。

## 四、两套开源方案可以并存

端口段不重叠，配对记录也各自独立，同一台电脑上同时装 Sefirah 和 KDE Connect 不会互相把对方踢下线。实际用起来常见的做法是：日常用一套，另一套当备用——某个功能在这套上不好使、在另一套上是现成的，换一套试往往比排查它快。

## 五、选哪套的判断顺序

1. 先看平台对不对得上（第二节那四项）。
2. 再看你非要不可的那个功能在哪一套里是内置的。要屏幕镜像就得额外准备 scrcpy，要虚拟触摸板那是 KDE Connect 的现成功能。
3. 最后才轮到界面顺不顺手。
