## 一、目标应用一开就闪退

部分设备上实时注入脚本会让目标应用当场崩溃。官方给的处理节奏：

1. 先把该应用的 hook 服务关掉，正常启动目标应用，让它先跑几秒。
2. 再开启 hook 服务，让注入发生在应用运行途中。
3. 排查前先把所有脚本取消勾选 —— 先用空脚本确认注入本身没问题，再逐个加回脚本，定位是不是某个脚本写坏了。

## 二、「增强渲染」是什么，为什么开了会掉激活

增强渲染是 JsHook 绘制悬浮界面的模式：默认开启，直接走底层 API 绘制、不经过安卓系统，官方说明这种模式性能开销更低，且画出来的内容**不会被录屏或截屏捕获**；关掉则退回系统 API 绘制，会损失一些性能，且内容能被录屏截屏拍下来。

问题在于部分机型不支持这种绘制方式，表现为**一开启增强渲染，激活状态就掉**。官方的恢复办法：

1. 清除 JsHook 的应用数据；
2. 在已激活状态下，进设置把增强渲染关掉再重开一次试试；
3. 还不行就放弃增强渲染（关掉），代价是悬浮内容可能被录屏截屏。

想让你的机型获得支持：用 MT 管理器之类的终端以 root 执行下面两行，然后开启增强渲染，把终端输出发给开发者：

```shell
su
logcat|grep ImGui
```

## 三、在线服务一直「Server request failed」

JsHook 的内置在线服务（仓库、更新检查这类）部分依赖 GitHub，网络到不了 GitHub 就会报这个错。解决办法是让网络能访问 GitHub，再重试。这也解释了为什么有的功能今天好好的、换个网络环境就报错。

## 四、大版本升级后 JsHook 打不开 / 一直崩

跨大版本升级（比如 1.0.x 直接跳 1.1.x 及以上）改动大，官方文档明确说可能崩到打不开。恢复步骤：

1. **先备份脚本与订阅** —— 这一步放最前面，后面会清掉它们。
2. 清除 JsHook 的应用数据。
3. 删除 `/data/system/jshook` 与 `/data/adb/jshook` 两个目录。
4. 重新走一遍激活（见[激活教程.md](激活教程.md)）。

日常升级尽量小步走，别跨大版本直接覆盖。

## 五、加密脚本跑不了

加密脚本目前只有 `fridamod` 框架能跑。脚本不生效先检查你给目标应用选的框架是不是 `fridamod`，框架选择见[脚本管理.md](脚本管理.md)第三节。

## 六、手机没有 root，是不是就没法用

不是没有路，只是路窄一些：官方文档只写了 root 激活，但社区实践里有经 LSPatch 的免 root 用法 —— 修补目标应用、免 root 模式、后台常驻跑脚本。它的限制（加固强的应用可能失败、双应用常驻更耗电、目标应用更新要重新修补）与完整流程，见[免root与LSPatch路线.md](免root与LSPatch路线.md)。

另外模拟器与虚拟机（VMOS、光速虚拟机等）也算一种「不动机身」的选择：在虚拟环境里 root 再激活，见[激活教程.md](激活教程.md)第三节。
