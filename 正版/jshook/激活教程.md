# JsHook 激活教程

> 激活是 JsHook 能不能用的分水岭：装完没激活，应用列表与 hook 服务都是灰的。本篇讲官方的激活步骤、各条环境路线，以及激活失败时的排查顺序。

## 一、激活前先想清楚设备环境

JsHook 的激活对设备环境有要求，不同环境的可行路线不一样。先把你的设备归到下面某一类：

| 设备环境 | 路线 |
| --- | --- |
| 已 root 的真机（Magisk / KernelSU / APatch 任一） | 官方文档的推荐路线，应用内一键激活 |
| 未 root 的真机 | 经 LSPatch 的免 root 用法，见[免root与LSPatch路线.md](免root与LSPatch路线.md)；早期版本资料还提到过「免 root 模式扩展」，是否仍可用以应用内为准 |
| 虚拟机（VMOS、光速虚拟机等） | 在虚拟机里走 root 激活，流程与真机一致 |
| 模拟器 | 先给模拟器 root，再走应用内激活 |

需要说明的是：官方现行文档只写了 root 一条路线；「LSPosed 勾选系统、免 root 扩展」这些说法来自早期版本的第三方资料，与官方现行口径并不完全一致，你手上这个版本有没有这些选项，**以应用内的实际界面为准**。

## 二、root 环境激活（官方步骤）

前提：设备已 root，root 方案是 [Magisk](https://github.com/topjohnwu/Magisk)、[KernelSU](https://github.com/tiann/KernelSU)、[APatch](https://github.com/bmax121/APatch) 三者之一。

1. 安装 JsHook（见[下载与安装教程.md](下载与安装教程.md)）。
2. 打开 JsHook，在首页点「激活」按钮。
3. 系统弹出 root 授权请求时允许。
4. 等待激活完成 —— 应用会自动部署运行时文件、启动后台守护服务并修正文件权限。
5. 激活完成的标志：首页显示「Activated（已激活）」状态，并附带守护进程信息。

激活过程中应用自动做的事，官方文档的描述是：把运行时文件部署到 `/data/adb/jshook/`、按当前内核版本释放对应模块、启动后台守护进程、修正文件权限。这几件事都由应用自动完成，你不需要手动干预，但排查问题时要知道 `/data/adb/jshook/` 这个目录的存在。

**root 框架的前置组件（旧版本资料的口径）**：早期版本（1.2.x 时代）的第三方资料提到，当时的模块依赖 zygisk 或 riru 之一，需要在 root 管理器里先装好，并推荐 zygisk（riru 已停止维护）；流程是打开 JsHook，点「安装 Magisk/KernelSU 模块」，选对应的 zygisk/riru 版模块，装完重启手机完成激活。这与官方现行文档「点激活按钮后自动部署」的描述是两代流程 —— 你的版本走的是哪套，看应用内有没有手动安装模块的入口即可。

## 三、虚拟机与模拟器路线

- **虚拟机**：官方文档点名了 VMOS（vmos）与光速虚拟机（LightSpeed VM）等同类产品，激活流程与真机 root 环境完全一样 —— 在虚拟机内部完成激活，而不是在外部真机上。
- **模拟器**：官方的说明是先让模拟器取得 root，然后按第二节同样的步骤操作。模拟器方案众多、root 方式各异 —— 第三方资料里常见的是给模拟器装 MagiskDelta 这类带 Magisk 能力的方案拿到 root，之后仍走应用内激活；具体参考你所用的模拟器文档更靠谱。

## 四、激活失败的排查顺序

按出现频率从高到低排：

1. **root 授权没给**：root 管理器（Magisk / KernelSU / APatch）里检查 JsHook 是否被拒绝过授权，改成允许后重试激活。
2. **开启「增强渲染」后掉激活**：部分机型不支持增强渲染，一开就掉。处理办法：清除 JsHook 的应用数据，在已激活状态下进设置把增强渲染关掉再重新激活。这个选项是什么、为什么影响激活，见[常见问题解答.md](常见问题解答.md)。
3. **在线服务请求失败**：JsHook 的内置在线服务依赖 GitHub，网络到不了 GitHub 时会报「Server request failed」。需要能访问 GitHub 的网络环境，再重试。
4. **跨大版本升级后崩掉激活**：清应用数据并删除 `/data/system/jshook` 与 `/data/adb/jshook` 两个目录后重新激活，**动手前先备份脚本与订阅**，具体步骤见[常见问题解答.md](常见问题解答.md)。

激活彻底成功后，下一步就是挑框架、配脚本：见[脚本管理.md](脚本管理.md)。写脚本过程中想在电脑上编辑，见[连接电脑调试.md](连接电脑调试.md)。

## 五、一条使用边界

JsHook 的能力对象应当是你自己的设备、自己的应用与自己的账号 —— 用它调试自己开发的应用、分析自己设备上的程序行为，是它设计出来的用途。对别人的应用与别人的账号做注入，既违反目标应用的用户协议，也可能触碰当地法律的红线，这部分不在本套文档讨论范围内。
