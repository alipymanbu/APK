## 一、先说结论

- **官方现行文档只认 root 激活**（Magisk / KernelSU / APatch 任一），见[激活教程.md](激活教程.md)。
- **没有 root 也有路**：多个第三方资料相互印证了经由 LSPatch 的免 root 用法，本篇照此整理。这是社区实践，不是官方文档给的支持路线，你手上版本里有没有「免ROOT模式」入口，以应用内实际界面为准。

## 二、免 root 路线需要什么

这条路除了 JsHook，还需要一个叫 LSPatch 的工具（免 root 的模块修补方案：它把模块打包进目标应用的副本里，目标应用以修补后的形态运行，模块随之生效，全程不动系统）。

前置清单：

1. JsHook 本体（安装见[下载与安装教程.md](下载与安装教程.md)）。
2. LSPatch。
3. 要分析的目标应用的安装包（修补会生成一个新安装包，不是在原应用上直接改）。

## 三、操作流程（第三方资料整理）

以下步骤整理自 2024 年前后的公开资料，对应当时的应用界面；版本更新后入口名称可能变化，以你屏幕上实际显示的为准：

1. 用 LSPatch 修补目标应用的安装包，修补完成按提示安装生成的新包（安装包一般可在 Download 类目录里找到）。
2. 在 LSPatch 的模块作用域设置里勾选 JsHook。
3. 打开 JsHook，切换为「免ROOT模式」，进「框架管理」下载 `FridaMod(Gumjs)` 并设为全局默认。
4. 进「脚本管理」导入你准备好的脚本（脚本来源见[脚本管理.md](脚本管理.md)）。
5. 进「应用」页找到目标软件，启用 Hook 服务，注入框架选 `FridaMod(Gumjs)`，脚本选刚导入的。
6. 打开目标应用验证脚本是否按预期运行。

## 四、已知限制与代价

- **后台常驻**：目标应用运行期间，JsHook 与 LSPatch 都要留在后台，被系统清后台就失效 —— 免 root 路线最常被抱怨的就是耗电。
- **不是所有应用都能过**：有用户反馈，加固强、签名校验严的应用，修补后可能直接跑不起来，这条路走不通，只能回 root 环境或放弃。
- **目标应用更新后要重来**：修补针对的是具体的安装包，目标应用升级后需要重新修补再安装。
- **生效时机**：脚本改动后重启目标应用才生效，与 root 路线一致。

## 五、root 路线还是免 root 路线

| 对比项 | root 路线 | 免 root（LSPatch）路线 |
| --- | --- | --- |
| 是否官方支持 | 是（官方文档唯一路线） | 否（社区实践） |
| 设备要求 | 已 root | 无需 root |
| 后台 | JsHook 需在后台 | JsHook 与 LSPatch 都需在后台，更耗电 |
| 适用范围 | 基本不受限 | 加固/签名校验强的应用可能失败 |
| 目标应用升级 | 无额外操作 | 需重新修补 |

能 root 就走 root；设备不方便 root（比如主力机、保修顾虑）时，免 root 路线可以先用小成本试通流程，但它解决不了所有应用。

最后是使用边界：无论哪条路线，对象都应该是**你自己的设备、自己的应用、自己的账号**。
