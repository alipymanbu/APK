## 一、脚本从哪来

激活之后，JsHook 里真正干活的是脚本（`.js` 文件）。来源有三种：

1. **内置仓库订阅**：应用内置了脚本仓库，可以直接浏览与下载，别人公开分享的脚本仓库也能订阅进来（订阅自定义仓库见第五节）。
2. **手动导入**：把本地写好的 `.js` 文件导入脚本管理。
3. **自己写，电脑上编辑**：官方提供了 VS Code 插件，在电脑上编辑、一键推送到手机，见[连接电脑调试.md](连接电脑调试.md)。

拿别人的脚本时留个心眼：脚本能读写文件、发网络请求，执行前最好看一眼内容，确认它做的事与你预期一致。

## 二、给目标应用启用 hook 服务

官方文档给出的上手流程是五步，顺序不要乱：

1. 在应用列表里选中目标应用。
2. 选一个 hook 框架（三种框架的差别见下一节）。
3. 勾选要执行的脚本。
4. 开启该应用的 hook 服务。
5. 打开目标应用 —— 脚本会自动随目标应用运行。

设备没 root、走 LSPatch 路线时，框架与脚本配置的顺序略有不同（`FridaMod(Gumjs)` 要设为全局默认），完整流程见[免root与LSPatch路线.md](免root与LSPatch路线.md)第三节。

两个容易漏掉的点：

- **每次改动脚本内容后，要重启被 hook 的目标应用**，新内容才会生效（这一条来自早期版本的第三方资料，与当前版本行为一致的话会省掉很多「改了没反应」的困惑）。
- 目标应用运行期间，JsHook 需要留在后台。如果你在后台清理里把它划掉了，脚本自然就停了。

## 三、三种注入框架怎么选

启用 hook 服务时框架要选一个，官方文档给的对照如下：

| 框架 | 说明 | 适用情况 |
| --- | --- | --- |
| `fridamod` | 官方推荐。内置完整 jscore API 支持，支持内核模式、ImGui 渲染与加密脚本 | 不确定就选它；要用加密脚本只能选它 |
| `fridainject` | 通过 frida-server 注入，支持 jscore API | 需要电脑端 frida 直连时配合使用 |
| `fridagadget` | 通过 frida-gadget 配置注入，支持 jscore API | 目标应用对注入方式有特殊要求时 |

脚本仓库里的脚本分 `rhino` 与 `frida` 两种类型（仓库 JSON 的 `type` 字段），下载前看清类型，rhino 类型脚本与 frida 框架不通用。如果你接触过 Xposed 的 hook 写法，rhino 类脚本的概念会更熟悉；frida 类脚本则对应上表三种 frida 系框架。

## 四、脚本不生效的排查

按顺序过一遍：

1. **先排除脚本本身的问题**：把所有脚本全部取消勾选，只留一个最简单的脚本试。全部勾选时不生效，可能是其中某个脚本报错拖累了整体。
2. **目标应用的 hook 服务开了没有**：应用列表里逐项确认，脚本对应的应用没开 hook 服务等于白配。
3. **脚本内容改过没重启**：改脚本后重启目标应用再测（见第二节）。
4. **注入方式与目标应用冲突**：有的应用实时注入会当场闪退，换成「先启动应用、等几秒再开 hook 服务」的节奏能绕过，详见[常见问题解答.md](常见问题解答.md)。
5. **检查激活状态**：首页不再显示已激活（比如开了增强渲染掉激活），后面的脚本配置全是空转，回[激活教程.md](激活教程.md)。

## 五、订阅自定义脚本仓库

脚本仓库本质上是一个约定格式的 JSON 文件，提供 URL 即可订阅：在仓库页面的右上角菜单里配置 URL。

最简形式是一个数组，每项代表一个脚本：

```json
[
  {
    "author": "作者名",
    "title": "脚本名",
    "type": "frida",
    "version": "1.0.0",
    "url": "脚本的下载地址",
    "desc": "一句话简介（30 字以内）"
  }
]
```

字段含义，不用的字段可以留空或省略：

| 字段 | 含义 |
| --- | --- |
| `author` | 脚本作者 |
| `title` | 脚本名 |
| `type` | 脚本类型，`rhino` 或 `frida` |
| `version` | 版本号 |
| `url` | 脚本下载地址 |
| `desc` | 简短描述，详细说明放在 `markdown` 字段指向的页面 |
| `markdown` | 详细文档（markdown）的 URL |
| `ctime` | 创建日期，格式 `YYYY-MM-DD` |
| `source` | 脚本来源页（如 GitHub 仓库地址），不是下载地址 |

完整格式外层是一个对象，可以附带仓库名、图标、QQ 群、Telegram 群与推送配置等，适合想自建仓库长期维护脚本的人；网页里放一个 `jshook://store?url=仓库地址` 的链接，就能让读者一键添加订阅。这部分字段细节直接看官方文档即可：[https://doc.jshook.org/](https://doc.jshook.org/) 的「Custom Repository」一节。

仓库里若有推送通知，只有你在 JsHook 设置里允许了通知才会收到，而且不是实时推 —— 打开 JsHook 或打开被注入的应用时才拉取。
