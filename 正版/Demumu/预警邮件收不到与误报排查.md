# Demumu 预警邮件收不到与误报排查

> 这篇站在「收件人」的角度写：作为紧急联系人，说好的预警邮件没到怎么办；或者收到了，但人好好的（误报）怎么处理。邮件是这个应用唯一的预警通道，收不到和误报是实际用起来最常被讨论的两个问题。

## 一、先对齐时间预期：邮件最快要隔两天到

触发链条是「连续 48 小时无签到 → 次日发邮件」。也就是说，从用户最后一次签到算起：

| 时间点 | 状态 |
| --- | --- |
| 第 0 天（最后一次签到） | 计时开始 |
| 第 2 天结束 | 连续 48 小时未签到的条件才成立 |
| 第 3 天 | 系统发预警邮件 |

有用户评价这个节奏「更像事后通知，而不是实时预警」——它本来就是为「人已失联一两天」的场景设计的，不是跌倒秒级报警。如果你需要的是即时响应，这套机制不覆盖，见文末的替代手段。

## 二、邮件没到：按这个顺序排查

作为联系人，如果你知道对方两天没签到、却没等到邮件：

1. **翻垃圾箱**：预警邮件由系统批量发出，被收件方判进垃圾邮件是媒体和用户都提到过的实际情况——这类邮件在国内邮箱的触达率本身就被评论认为不及短信和微信；
2. **搜邮箱**：在邮箱里搜应用名或对方的名字，有些邮箱把可疑邮件归进「订阅邮件」「其他」分类，未必在垃圾箱；
3. **核对邮箱地址**：找对方确认当时填的是不是你这个邮箱——写错一个字母就发到别处去了；
4. **确认对方真的触发预警**：如果对方中途补签过一次，48 小时计时会重置，邮件根本不会发。

排查出原因后，把正确的邮箱地址告诉对方回应用里改，并按 [紧急联系人设置指南.md](紧急联系人设置指南.md) 第四节的办法减少再次漏收的可能。

## 三、收到了邮件，但人好好的：这就是误报

误报的常见原因，几乎都落在「手机与人的连接断了」上：

| 原因 | 典型场景 |
| --- | --- |
| 纯粹忘了 | 忙起来、节假日作息乱、出差途中 |
| 手机不在身边 | 关机充电、住院没带、手机丢失损坏 |
| 应用被系统清理 | 部分安卓手机的后台清理策略把应用进程杀掉（对签到的影响见 [每日签到与预警机制.md](每日签到与预警机制.md)） |
| 停用/卸载了 | 没提前告知联系人 |

有不少用户调侃自己「隔三差五死一次」——对一个靠自觉手动签到的机制来说，误报是常态而非故障。收到邮件的正确动作：**先打电话**，打不通再按事先约定处理（联系对方身边人、上门）。唯独不要做的是「不当回事直接删邮件」：万一这次是真的，你就是这个机制里唯一会行动的人。

## 四、把误报率压下来的三个做法

这是双方配合的事：

1. **固定签到时间**：把「点一下」挂在一个每天必然发生的动作后面（起床、午饭、睡前），比「想起来再签」可靠得多；
2. **提前说好的分级响应**：联系人收到邮件先电话、电话不通多久后升级到什么动作，事先约定好，免得到时候犹豫；
3. **状态变化主动报备**：要出差、住院、换手机、停用应用，提前跟所有联系人说一声，比事后解释省心。

## 五、如果这套邮件机制始终不合用

它不满足需求时，通常的替代方向有两类：一是时效更高的工具（智能穿戴设备的跌倒检测、心率异常提醒这类**被动监测**，出事当下就能通知家人）；二是约定俗成的低技术做法（每天在家人群里发一句报平安，媒体采访里就有独居者跟父母用「晚安表情」互相确认）。两条路各有利弊，按家里人的实际作息选，或者跟这个应用的签到机制叠加使用。
