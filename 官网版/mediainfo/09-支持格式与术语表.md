## 二、支持的编码格式

### 视频编码

MPEG-1 / MPEG-2 Video、H.263、MPEG-4 Visual（含 **DivX**、**XviD**）、**H.264 / AVC**、**H.265 / HEVC**、FFV1

### 音频编码

MPEG Audio（含 **MP3**）、**AAC**、**AC-3**、**DTS**、Dolby E、AES3、**FLAC**

### 字幕 / 文本

| 类型 | 格式 |
| --- | --- |
| 图文电视 / 广播字幕 | CEA-608、CEA-708、DTVCC、SCTE-20、SCTE-128、ATSC/53、CDP、DVB Subtitle、Teletext |
| 外挂字幕 | SRT、SSA、ASS、SAMI |

### 标签（Tags）

ID3v1、ID3v2、Vorbis comments、APE tags 等。

## 三、各类容器能读到什么（摘要）

官方对「能读到哪些字段」做了逐格式的覆盖度说明。整体规律：

| 字段类别 | 覆盖情况 |
| --- | --- |
| **常规 / 时长 / 码率** | 主流容器（MKV、MP4、AVI、MPEG、WAV…）覆盖良好 |
| **视频信息**（编码、码率、宽高比、帧率） | MPEG 系列、QuickTime、Matroska、RIFF、WM 等基本完整 |
| **音频信息**（编码、码率、声道、采样率） | **覆盖最广**，几乎所有支持的容器都可读 |
| **语言信息** | Matroska、Ogg、DVD-Video（IFO）等支持较好；部分容器不携带语言标记 |
| **章节** | Ogg、Matroska 等支持；MP4 / AVI 等通常无章节信息 |
| **标签（标题 / 作者 / 专辑等）** | 音频容器与非音频容器差异较大，`mp3`、`mp4`、Ogg、FLAC 较好 |

> 结论：**音频相关字段最可靠，章节与部分标签字段依赖容器是否原生支持**。读不到某个字段时，先确认该容器是否本来就不携带这类信息，再怀疑解析问题（参见 [08-常见问题与故障排查](08-常见问题与故障排查.md#q6读不到时长--码率或字段大面积缺失)）。

想自己动手核对某个文件？先取 [MediaInfo 安装文件资源（夸克网盘）](https://pan.quark.cn/s/7475c96060cb)，装好后按 [06-命令行使用指南](06-命令行使用指南.md) 的方法查看。

## 四、术语表

### 容器与流

| 术语 | 英文 | 说明 |
| --- | --- | --- |
| **容器 / 封装** | Container / Format | 把视频、音频、字幕、章节等打包在一起的「盒子」。MKV、MP4 是容器 |
| **轨道 / 流** | Track / Stream | 容器里的一条独立数据流。一个文件常见 1 条视频轨 + 多条音频轨 + 多条字幕轨 |
| **裸流** | Elementary Stream | 未经容器封装的单一编码数据，如 `.h264`、`.aac` |
| **混流 / 复用** | Muxing | 把多条流合并进一个容器 |
| **分离** | Demuxing | 从容器中拆出各条流 |

### 视频参数

| 术语 | 英文 | 说明 |
| --- | --- | --- |
| **编码 / 编解码器** | Codec / Format | 视频、音频的压缩算法，如 H.264、H.265/HEVC、AAC |
| **码率** | Bit rate | 单位时间的数据量，通常以 bps / kbps / Mbps 计。越高画质潜力越好、文件越大 |
| **总码率** | Overall bit rate | 整个文件（含所有轨道）的平均码率 |
| **帧率** | Frame rate | 每秒画面帧数，如 23.976、25、30、60 fps |
| **宽高比** | Aspect ratio | 画面宽与高之比，如 16:9、4:3 |
| **分辨率** | Resolution / Width × Height | 画面像素尺寸，如 1920×1080 |
| **色彩空间** | Color space | 颜色表示方式，如 YUV、RGB |
| **色度抽样** | Chroma subsampling | 色彩信息的采样方式，如 4:2:0、4:2:2、4:4:4 |
| **位深** | Bit depth | 每个颜色通道的位数，如 8 bit、10 bit。位深越高渐变越平滑 |
| **扫描方式** | Scan type | **逐行（Progressive）** 或 **隔行（Interlaced）** |
| **扫描顺序** | Scan order | 隔行视频中先扫上场还是下半场（TFF / BFF） |
| **档次 / 配置** | Profile | 编码器遵循的规格档次，如 H.264 的 High@L4.1 |

### 音频参数

| 术语 | 英文 | 说明 |
| --- | --- | --- |
| **采样率** | Sampling rate | 每秒采样点数，常见 44100 Hz、48000 Hz |
| **声道数** | Channels | 声道数量，如 1（单声道）、2（立体声）、6（5.1） |
| **声道布局** | Channel layout | 声道排布方式，如 `L R C LFE Ls Rs` |
| **语言** | Language | 该轨道的语言标记；缺失时说明容器未写入 |
| **音频位深** | Bit depth | PCM 类音频的量化位数，如 16 bit、24 bit |

### 其他

| 术语 | 英文 | 说明 |
| --- | --- | --- |
| **标签** | Tag / Metadata | 写入文件的描述性信息：标题、作者、专辑、封面等 |
| **章节** | Chapter / Menu | 文件内预设的时间点分段（常见于 MKV、DVD） |
| **写入程序** | Writing application / library | 生成该文件的软件及其版本 |
| **MXF** | Material Exchange Format | 广播 / 影视后期常用的专业封装格式 |
| **EBUCore** | — | 欧洲广播联盟（EBU）定义的元数据标准，MediaInfo 可直接输出该格式 |
| **PBCore** | — | 公共广播元数据标准，MediaInfo 支持 PBCore / PBCore2 输出 |
| **QC** | Quality Control | 质量检查，指核对媒体文件是否符合交付规范 |

> `--Inform` 模板与 JSON 字段名对应的就是上述英文标识（如 `Width`、`FrameRate`、`OverallBitRate`），完整字段名可用 `mediainfo --Info-Parameters` 列出，见 [06-命令行使用指南](06-命令行使用指南.md)。
