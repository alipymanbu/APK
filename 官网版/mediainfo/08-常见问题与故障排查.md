## 一、安装与命令相关

### Q1：命令提示 `mediainfo: command not found` / 「无法将 mediainfo 项识别为...」

**原因**：命令所在目录不在系统 `PATH` 里，或只装了图形界面版没装命令行版。

**排查与解决**：

| 平台 | 处理 |
| --- | --- |
| Windows | 确认安装时勾选了 PATH 选项；或手动把安装目录加入 PATH，**改完必须重开终端** → [03-Windows安装教程](03-Windows安装教程.md#六把-mediainfo-加入-path) |
| macOS | 若装的是 cask（GUI），补装 CLI：`brew install media-info` → [04-macOS安装教程](04-macOS安装教程.md) |
| Linux | 补装 CLI 包：`sudo apt install mediainfo`（只装 `mediainfo-gui` 是不够的）→ [05-Linux安装教程](05-Linux安装教程.md) |

### Q2：改了 PATH 还是不生效

终端窗口是**启动时读取一次** PATH 的。**关掉当前终端（包括 Trae / VS Code 内置终端）重新打开**，或重启 IDE。

### Q3：Windows 上解压官方包失败

`.7z` 格式 Windows 自带解压不支持，需安装 [7-Zip](https://www.7-zip.org/)。或改下 `.zip` 结尾的包。

### Q4：提示「Windows 已保护你的电脑」

新发布的安装包触发 SmartScreen 提示，属正常现象。请先按 [02-下载渠道与版本选择](02-下载渠道与版本选择.md#六下载后的校验可选但推荐) 确认为官网来源，再点「更多信息 → 仍要运行」。

### Q5：macOS 提示「无法打开，因为无法验证开发者」

Gatekeeper 拦截。到「系统设置 → 隐私与安全性」点「仍要打开」；或对应用右键 → 打开 → 确认。详见 [04-macOS安装教程](04-macOS安装教程.md#首次打开被拦截怎么办)。

## 二、输出内容相关

### Q6：读不到时长 / 码率，或字段大面积缺失

**先怀疑文件本身**，而不是软件：

1. 文件是否**下载完整**？被截断的文件常在末尾丢失索引信息；
2. 该文件能否正常播放？播放器也打不开说明文件损坏；
3. 是否为**特殊或罕见格式**？先升级到最新版 MediaInfo 再试；
4. 换一个同类型文件对比——如果别的文件正常，问题在源文件。

**进一步排查**：用 `--Full` 输出全部内部字段，看是否有更底层的线索：

```bash
mediainfo --Full problem_file.mkv
```

### Q7：文件能播放，但播放器里没有声音

MediaInfo 可以帮你判断是**没有音轨**还是**音轨编码不被支持**：

```bash
mediainfo --Language=raw --Inform="Audio;%Format% %Channels%ch %Language%" movie.mkv
```

- **完全没有 Audio 段落** → 文件本身没有音轨；
- **有音轨但没有输出** → 更可能是播放器 / 解码器不支持该音频编码（常见于 AC3、DTS、TrueHD 等），需换播放器或加解码器。

> 注意：MediaInfo 只告诉你轨道信息，不做播放能力判断，最终结论要结合播放器测试。

### Q8：中文文件名或输出乱码

| 平台 | 处理 |
| --- | --- |
| Windows CMD | 先执行 `chcp 65001` 切到 UTF-8，或改用 Windows Terminal / PowerShell |
| Linux | 确认 `LANG` / `LC_ALL` 为 UTF-8（如 `zh_CN.UTF-8`、`C.UTF-8`） |
| 脚本解析 | 加 `--Language=raw`，避免字段名被翻译 |

### Q9：输出里的字段名是中文，脚本解析失败了

字段名被界面语言翻译了。**所有脚本调用都应加 `--Language=raw`**：

```bash
mediainfo --Language=raw --Output=JSON video.mkv
```

### Q10：两个工具读出来的分辨率 / 时长不一致

MediaInfo 与 ffprobe、播放器等对同一文件读数**偶有差异**，常见原因：

- **解析策略不同**：有的工具只读文件头，有的会做更深解析，遇到文件元数据不自洽时结论不同；
- **字段定义不同**：例如「时长」可能指容器声明时长或实际流时长；
- **帧率**：存在「标称帧率 / 实际帧率 / 平均帧率」多种口径；
- **异常文件**：文件本身索引损坏时，工具会各自猜测。

**实践建议**：确定一个工具作为标准口径（做 QC 就用同一个工具同一版本），不要混用不同工具的读数做判定。

### Q11：同一批文件昨天和今天跑出来结果不一样

大概率是**升级了 MediaInfo 版本**。新版可能新增字段、修正解析逻辑。生产环境建议**固定版本**，升级前先在测试样本上回归（见 [06-命令行使用指南](06-命令行使用指南.md#六解析结果的稳定化建议)）。

## 三、性能相关

### Q12：处理超大文件很慢

- MediaInfo 需要读取文件相关区块，文件越大、存储越慢耗时越久；
- 可用 `--ParseSpeed` 调整解析深度：调低更快但字段更少，调高更完整但更慢；
- 批量任务在机械硬盘上建议**串行处理**，并发读盘反而降低总吞吐。

## 四、版本相关

### Q13：发行版仓库里的版本太旧

Linux 发行版仓库通常滞后。解决方式：

- 添加 MediaArea 官方仓库 → <https://mediaarea.net/en/Repos>
- 或使用官方 AppImage / tar.xz 版
- 或直接从夸克网盘取 **MediaInfo 安装文件资源**：[https://pan.quark.cn/s/7475c96060cb](https://pan.quark.cn/s/7475c96060cb)

详见 [05-Linux安装教程](05-Linux安装教程.md#三要更新版本使用-mediaarea-官方仓库)。

### Q14：Windows XP 上装不上

新版已不支持 XP，官网对 XP 只提供 21.03 及更早版本。见 [03-Windows安装教程](03-Windows安装教程.md#一系统要求)。

### Q15：想确认自己装的是哪个版本

```bash
mediainfo --Version
```

会输出命令行与库的版本号。GUI 版可在「帮助 → 关于」中查看。

## 五、还想做这些事？

| 需求 | 为什么不行 / 该用什么 |
| --- | --- |
| **修改文件里的元数据** | MediaInfo 只读不写。用 ExifTool 或 FFmpeg 处理 |
| **转码 / 压缩文件** | MediaInfo 不做转换。用 FFmpeg、HandBrake 等 |
| **修复损坏的视频文件** | MediaInfo 只诊断不修复。可先用它确认损坏点，再借助专业修复工具 |
| **播放文件** | MediaInfo 不是播放器 |

## 六、如何反馈问题

如果确认是 MediaInfo 自身的缺陷（而非文件问题）：

1. 先升级到**最新版本**复现一次；
2. 准备可复现的**样本文件信息**（可用 `--Full` 输出作为附件，注意样本可能含隐私信息，必要时只提供文件结构说明）；
3. 通过官方渠道反馈：
   - 官网联系页：<https://mediaarea.net/Contact>
   - 源码仓库 issue：<https://github.com/MediaArea/MediaInfo>
