## 一、提醒是怎么设计的

官方对提醒的描述是「早上和晚上提醒你要坚持的习惯」：给项目设好提醒时间后，应用会在对应时段弹出通知，提示你今天还有哪些项目没打卡。习惯打卡类应用的提醒依赖两个系统层面的东西，缺一个都不响：

1. **通知权限**——应用要有资格在手机上发通知。
2. **精确闹钟调度**——通知要在你设定的时间点弹出，而不是被系统合并、延迟。

这两项对应的权限（发布通知、精确闹钟 SCHEDULE_EXACT_ALARM）在安装环节就有说明，见 [下载与安装教程.md](下载与安装教程.md) 第五节。

## 二、把提醒设好

1. 打开应用，进入需要提醒的那条项目（或应用内的提醒设置区），设定提醒时间。官方设计是早晚各提醒一次，具体时间自己定。
2. Android 13 及以上的手机，首次触发通知时系统会单独弹窗问「是否允许发送通知」，选允许。如果当时点了拒绝，后面要在系统设置里手动补开。
3. 部分手机会在设置里单独管理「精确闹钟 / 闹钟和提醒」权限，装完后建议顺手检查一次。

## 三、收不到提醒的排查清单

按出现概率从高到低逐项过：

| 检查点 | 在哪里看 | 常见坑 |
| --- | --- | --- |
| 系统通知总开关 | 系统设置 → 应用 → iBetter → 通知 | Android 13+ 默认关闭，必须手动允许 |
| 分类通知 | 同上的通知分类（提醒 / 推广） | 有的系统会按类别单独关，提醒类要保持开启 |
| 精确闹钟 | 系统设置 → 应用 → iBetter → 闹钟和提醒 | 被关掉后提醒会延迟到系统批量处理时段 |
| 电池优化 | 系统设置 → 电池 → 应用耗电管理 | 国产 ROM（小米 / 华为 / OPPO / vivo 等）默认会冻结后台应用，把 iBetter 设为「无限制 / 允许后台运行」 |
| 自启动 | 系统设置 → 应用 → 自启动管理 | 关掉自启动的应用重启手机后调度会失效 |
| 免打扰 / 专注模式 | 系统设置 → 声音 | 免打扰时段正好盖住提醒时间的话，通知会静默 |
| 应用内提醒开关 | iBetter 项目详情 / 设置 | 项目本身没设提醒时间，自然不会响 |

过完一遍还不行的，做一个最小验证：把提醒时间设到两分钟后，锁屏等它弹不弹。弹了说明链路通，问题出在时段设置；不弹就回到上面表格从头再查。

## 四、提醒之外的建议

- 提醒只是兜底，打卡动作本身靠 [打卡项目创建与管理.md](打卡项目创建与管理.md) 里的项目设计——名字具体、数量少，比把提醒调得多更重要。
- 排查过程中如果发现是版本问题（比如升级系统后通知行为变了），先确认你的版本号，再看 [常见问题排查.md](常见问题排查.md) 里的版本口径说明。
