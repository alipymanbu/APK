## 一、先分清是哪一种「用不了」

三种现象的原因完全不同，先对号入座再动手：

| 现象 | 大致方向 |
| --- | --- |
| `busybox: command not found` | 程序本身没装上，或装的位置不在 PATH 里 |
| `vi: not found`，但 `busybox` 能敲 | 程序在，命令链接没建全 |
| `permission denied` | root 没给，或权限位不对 |
| 命令能跑，结果/选项和教程不一样 | 调用到了另一份实现 |

## 二、`busybox` 自己都找不到

1. **安装没走完**：回到应用看安装进度是不是真的成功，重新点一次 INSTALL。
2. **root 没授权**：打开 root 管理器看授权记录里有没有这个应用；没有就重新触发一次授权并允许。
3. **路径不在 PATH 里**：先用绝对路径试：

   ```sh
   /system/xbin/busybox
   ```

   （路径换成你在安装时选的那个。）绝对路径能跑、简写不能跑，就是 PATH 的问题 —— 你安装时选的目录没进终端的搜索路径，换个常用目录重装一次最省事。

## 三、`busybox` 在，但 `vi`、`wget` 这些找不到

多半是安装时**只勾选了一部分命令**，或者链接压根没建。两步处理：

1. 打开应用，确认 applets 勾选里你要的那几条是勾上的，重新 INSTALL 一次；
2. 或者在终端里手动补链接（同样需要 root）：

   ```sh
   busybox --install -s /system/xbin
   ```

   装完再 `ls -l /system/xbin/vi` 看链接在不在。

## 四、`permission denied`

- 终端里先 `su` 拿到 root 再敲；不进 root，很多命令只对 `/sdcard` 下的文件有效。
- 程序本身的执行位丢了时补一次：

  ```sh
  chmod 755 /system/xbin/busybox
  ```

## 五、报 `Read-only file system`

这说明你选的安装路径在**只读分区**上。较新的安卓把 `/system` 作为只读分区管理，老教程里那种「重新挂载为可写」的做法在这些机器上不一定成立，别照着改分区。更稳的做法是：**在应用里换一个可写的安装路径**重装；或者干脆不装进系统，需要时直接用 `busybox 命令` 这种带前缀的敲法（见 [常用命令速查.md](常用命令速查.md)）。

## 六、系统更新（OTA）之后又失效了

系统更新会把 `/system` 还原，之前建的链接随之消失，现象通常回到第二节或第三节。重新打开应用装一次即可；每次大版本更新后都这样，属正常情况，不是装错了。

## 七、和 root 方案自带的工具箱撞车

Magisk、KernelSU 这类 root 方案本身也内置了一份 BusyBox，用于跑它自己的模块脚本（Magisk 那份的固定位置是 `/data/adb/magisk/busybox`，见 Magisk 官方文档），不走你装的这份。两份并存一般互不影响，但如果你的异常只出现在**某个模块的脚本里**，那要改的是那份内置的配置，你装的这份管不到它 —— 脚本侧怎么指明用哪一份，见 [shell脚本里怎么调用它.md](shell脚本里怎么调用它.md)。

## 八、`sh: can't access tty; job control turned off`

进 shell 或跑脚本时看到这一行，**不是装坏了**：它的意思是这个 shell 拿不到控制终端，于是关掉了作业控制（`fg`/`bg` 切换、`Ctrl-C` 发中断这类能力）。命令本身照常执行，[busybox.net 官方 FAQ](https://www.busybox.net/FAQ.html) 对这条的解释也是如此 —— shell 被起在了一个不提供控制终端的设备上。

什么时候需要管它：

- 只是看着碍眼、命令都能跑 → 忽略即可；
- `Ctrl-C` 停不下来某个命令 → 换成在应用内的终端里跑，或给命令加超时（`timeout 10 命令`，若你的版本带 `timeout` 这个 applet）；
- 它出现在**你自己写的脚本**里且后面行为不对 → 问题在脚本怎么被启动的，回到 [shell脚本里怎么调用它.md](shell脚本里怎么调用它.md) 检查调用方式。

判断标准很简单：这行字后面命令还正常出结果，就不是故障；真正装坏了的表现是 `command not found`，回到第二节。
