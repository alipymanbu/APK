# AdGuard 省电与后台被杀怎么处理

> 拦截突然失效、通知栏那条通知不见了，多数是被系统省电机制清掉了。本篇给通用三步与主流定制系统的具体路径。

这是 AdGuard 在安卓上最容易被忽略的一类问题：装上当天一切正常，过几天广告悄悄回来了。原因往往是系统省电机制把 AdGuard 的后台进程清掉了 —— 它不是在报错，而是根本没在运行。本篇的症状判断、通用设置和各家定制系统的路径都列出来，一次设完可以长期稳定。

## 一、先确认是不是被系统杀掉了

按这几条对：

| 现象 | 说明 |
| --- | --- |
| 通知栏那条 AdGuard 通知不见了 | 基本确定进程已被清理 |
| 系统「设置 → 网络与互联网 → VPN」里看不到 AdGuard，或不在活动状态 | 本地 VPN 已断开，拦截停止 |
| 打开 AdGuard 应用图标后，拦截立刻又恢复 | 进程被拉起后重建了本地 VPN，典型的「被杀后没恢复」 |
| 「统计」页某个时段完全没有记录 | 那段时间它没在运行 |

注意别和 VPN 冲突混淆：如果是被别的 VPN 顶掉，VPN 列表里会出现另一个活动连接，处理方式见 [和别的VPN冲突怎么办.md](和别的VPN冲突怎么办.md)。

## 二、通用三步，先做完这三件

不管什么品牌，这三件都要做：

1. **电池优化设为不优化**：系统「设置 → 应用 → AdGuard → 电池」，把优化模式改成「不优化 / 无限制 / 允许后台活动」。
2. **允许自启动**：在应用权限里把 AdGuard 的「自启动」「后台自动启动」「关联启动」这类开关打开。
3. **在最近任务里锁定**：从最近任务里上滑清理时，AdGuard 常常被一起清掉。在最近任务卡片上长按或下拉，找到锁定图标把它锁上，之后一键清理就不会扫到它。

## 三、各家定制系统的具体路径

国内厂商对后台的限制差别很大，按你的机型对照。以下路径来自官方知识库，系统更新后菜单名称可能微调，找意思相同的项即可。

| 系统 | 关键动作 |
| --- | --- |
| 小米 MIUI 13+ / HyperOS | 「设置 → 应用 → 权限 → 后台自动启动」允许 AdGuard；「应用管理 → AdGuard」里关掉「在未使用时暂停应用」；省电模式选「无限制」。部分版本可直接在「应用管理 → AdGuard」里打开「自动启动」并设省电模式为「无限制」 |
| 小米 MIUI 10 到 12 | 「设置 → 应用设置 → 应用管理 → AdGuard」里：自启动设为开、其他权限全部设为开、省电模式设为「无限制」；再在最近任务里锁定 |
| 华为 EMUI | 「设置 → 电池 → 应用启动」里关掉「全部自动管理」，改为手动管理并允许 AdGuard 自启动、允许后台活动 |
| 三星 One UI（Android 11+） | 「设置 → 应用 → AdGuard → 电池 → 优化电池使用」把 AdGuard 设为「不优化」；再关掉「自适应电池」，并在「后台使用限制」里禁用「让未使用的应用进入休眠」 |
| 三星（旧版本） | 「设置 → 设备维护 → 电池 → 三点菜单 → 设置」，取消「让未使用的应用进入休眠」和「自动禁用未使用的应用」 |
| 华硕 | 「Mobile Manager → Power Master → 设置（或省电选项）」，取消「暂停清理」与「自动拒绝应用自启动」 |

三星机型有一个额外注意点：连续几天没被打开的应用会无法从后台启动，所以除了电池设置，**自动优化相关的开关也要一并关闭**；并且系统更新后这些设置经常恢复默认，更新完要再检查一遍。

## 四、AdGuard 自己的兜底：Watchdog

除了系统侧的设置，AdGuard 内置了一个把被关掉的自己拉起来的机制。

- **路径**：「设置 → 常规 → 高级 → Watchdog」。
- **填什么**：两次检查之间相隔的秒数，值越小拉回越快、也越耗电。
- **怎么理解**：它是「被你清掉后能自己回来」的补丁，不能替代上面那三步系统设置。系统级白名单是让它尽量不被清，Watchdog 是被清之后尽快恢复，两者要一起用。
- **别关掉那条常驻通知**：通知被清理或被系统禁掉后，判断它是否在运行的直观信号就没了；Assistant 的入口也在那条通知上。

## 五、先分清「看起来耗电」和「真的耗电」

设完保活之后，很多人下一句就是「它在耗电列表里排很前」。这两个数字要分开看：

- **系统设置的电池页显示的耗电量偏高，是正常现象**。官方解释了原因：所有被过滤应用的流量都被系统记到 AdGuard 头上，所以系统里看到的 AdGuard 消耗比它实际用掉的多。
- **要看实际值，用 AdGuard 自己的统计**：「统计 → 电池使用情况」，这里给的是过去 24 小时内 AdGuard 实际用掉的设备资源。
- **两处的数字不一致是预期行为**，不是统计出错；对比趋势看自己那份就够了。
- **想同时省电和保留拦截**：把「设置 → 常规 → 高级 → Watchdog」的间隔调大一些，能少几次自检唤醒；代价是被系统清掉后回到工作状态慢一点。两者只能取平衡，没有既最快恢复又最省电的配置。

## 六、想少被清，还有一个办法：降低误杀概率

- **不要让系统「一键加速 / 深度清理」自动处理 AdGuard**：这类工具的清理名单里默认包含「不常用后台应用」，设置里能找到把 AdGuard 排除的选项。
- **别把「保护」整个关掉当临时方案**：关掉再打开会重新建 VPN，短暂窗口期内的请求不受过滤；只是短暂不用某个应用时，用 [网站打不开或功能异常怎么放行.md](网站打不开或功能异常怎么放行.md) 里的按应用排除更稳。
- **观察几天**：设完之后看「统计」页是否连续有数据。如果隔一两小时就有断档，说明还有一处没放行，回到第三节按机型再核一遍。
