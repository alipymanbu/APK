# AdGuard DNS 保护怎么用

> DNS 保护是在域名解析这一层拦广告，独立于请求层过滤。本篇讲服务器怎么选、加密 DNS 怎么配、以及和系统私人 DNS 的关系。

AdGuard 里其实有两条独立的拦截路径：一条是检查请求本身（「保护 → 广告拦截」），一条是检查域名解析（「保护 → DNS 保护」）。DNS 保护是免费版就能用的能力，配置得当能补上请求层拦不到的一部分，也能顺手把 DNS 查询加密。本篇只讲 DNS 这一层。

## 一、DNS 保护能做什么、不能做什么

**能**：

- 拦截已知的广告与跟踪服务器地址 —— 域名在被解析时就被拉黑，请求根本发不出去；
- 加密本机的 DNS 查询，让运营商或本地网络看不到你在解析哪些域名；
- 统一管理一批「按域名拦截」的名单。

**不能**：

- 拦不到与正文同域的资源（同一个域名既提供内容又插广告时，拦域名等于把内容也拦了）；
- 拦不到应用内已经写死 IP 或用自己协议栈绕过系统解析的请求。

所以它不是请求层过滤的替代品，两条都开着拦截率最高。

## 二、先把服务器选对

路径：「保护 → DNS 保护 → DNS 服务器」。常见几类：

| 选项 | 适用情况 | 代价 |
| --- | --- | --- |
| 系统 DNS | 只想用 DNS 保护里的过滤器做拦截 | 查询不加密，运营商可见 |
| AdGuard DNS（默认） | 想同时拿到广告与跟踪域名拦截 | 拦截发生在对方服务器上，本机放行设置对它无效 |
| AdGuard DNS 家庭保护 | 需要额外挡成人内容 | 同上，可能误拦正常站点 |
| 无过滤（Non-filtering） | 被过滤 DNS 误拦、需要干净解析 | 放弃 DNS 层的广告拦截 |
| 自定义 | 有自己的 DoH / DoT / DoQ 地址 | 需要自己填地址，见下一节 |

**重要区别**：用「带过滤的公共 DNS」时，拦截是在解析服务器上做的。你在 AdGuard 应用里把域名加进允许清单，对这类拦截无效 —— 因为请求压根没到本机过滤器。要放行只能换到不带过滤的 DNS，或去 DNS 服务那边加允许规则，参考 [网站打不开或功能异常怎么放行.md](网站打不开或功能异常怎么放行.md) 第六节。

## 三、把 DNS 查询加密起来

在同一个 DNS 服务器页面里选「自定义」，把加密地址一行一个填进去。三种协议写法：

```text
https://dns.example.org/dns-query      # DoH
tls://dns.example.org                  # DoT
quic://dns.example.org                 # DoQ
```

- **多个地址可以同时填**：填多行时按顺序尝试，靠前的优先生效。
- **加密地址要配 Bootstrap DNS**：DoH / DoT / DoQ 的服务器主机名本身也要被解析出来，这一步不能用加密通道，所以需要一组普通的 bootstrap 解析服务器。默认用「自动 DNS」，一般不用改；自定义解析服务器不通时，这里是排查点之一。
- **填的是域名不是 IP**：加密 DNS 一般给的是域名，用 IP 直接填会失效。

## 四、DNS 过滤器与拦截行为

- **DNS 过滤器**：「保护 → DNS 保护 → DNS 过滤器」里能开一批按域名拦截的名单。这里开的是域名级规则，和「设置 → 过滤 → 过滤器」里那批请求级规则不是同一套，两边可以各开各的。
- **DNS 允许清单 / 阻止清单**：把单个域名加白或加黑。加白后本机不再拦该域名。
- **拦截后的响应方式**：可以选返回 `REFUSED`、返回 `NXDOMAIN`，或返回一个自定义 IP。默认值对多数场景都够用，不确定就别改。
- **几个默认值值得知道**：DNS 请求超时默认 5000 毫秒，被拦域名的应答 TTL 默认 3600 秒，DNS 缓存默认 1000 条。这三个在低级设置里，日常不用改。

## 五、和系统「私人 DNS」的关系

Android 9 及以上在系统里自带「私人 DNS」（走 DoT）。它会和 AdGuard 的 DNS 保护重叠，可能出现「明明设了却看不到 DNS 记录」的情况。

- 系统的私人 DNS 指向别处时，浏览器的解析可能绕开 AdGuard 的 DNS 保护。
- AdGuard 在低级设置里提供了 **「过滤安全 DNS」**（「设置 → 常规 → 高级 → 低级设置」），打开后除了普通 DNS，加密 DNS 请求也会被纳入过滤，有两种模式：直接把查询改道到本地 DNS 代理，或只在过滤域名的场景下介入。
- 更省事的做法是二选一：要么关掉系统私人 DNS、由 AdGuard 统一管；要么把系统私人 DNS 指向你在 AdGuard 里配置的那个加密地址。两边都随手配一套，反而容易出现解析行为不一致。

## 六、想验证 DNS 保护有没有生效

1. 在「保护 → DNS 保护」里确认总开关是开的，并且选的是一个带过滤的服务器或开了 DNS 过滤器。
2. 打开「统计」，看被拦请求里有没有出现 DNS 类型的记录；被拦的域名列表也会列出来。
3. 找一个已知的广告域名，用任意支持自定义 DNS 的工具查一次；如果被拦，查不到正常结果，或被指到拦截 IP 上。

DNS 过滤记录在本地，排查完可以清掉。若某天开始「很多网站都解析不了」，第一件事是回到本节第 2 步换个不带过滤的 DNS 试一次 —— 判断是解析服务器侧的问题还是本机配置问题，比逐条加放行快得多。
