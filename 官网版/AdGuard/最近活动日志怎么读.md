# AdGuard 最近活动日志怎么读

> 「最近活动」记录了最近一万条请求，能直接看出某个页面是谁拦的、被哪条规则拦的，也能一键加例外。

前面几篇讲的是「凭现象猜原因」。最近活动不一样，它是**直接看证据**：某个网页空白、某个按钮点不动、某个应用突然连不上，都能在这里找到对应那一条请求，看到它被拦了还是被改了、被哪条规则处理过。这个面板以前叫「过滤日志」，官方在 4.x 里改成了现在的名字。

## 一、在哪、记录了多少

- **路径**：「统计 → 请求 → 最近活动」。
- **容量**：保留最近处理的 **10000 条**请求，超出后最早的会被顶掉。它不是全量日志，够用但别指望靠它回溯很久以前的事。
- **按数据类型分开看**：可以在移动数据、Wi-Fi、全部之间切换，只看某一种网络下的记录。
- **来自 Assistant 的快捷入口**：从通知栏展开 AdGuard 通知、点 Assistant，在「Apps」或「Websites」里选一个应用或网站，点「最近活动」，就直接跳到**已经过滤好**的日志页 —— 排查单个应用时这一步能省掉手动筛。

## 二、每条记录怎么看

点开一条请求，能看到它的详细信息，最有用的是两块：

1. **处理结果**：这条请求是被拦了、被改了、还是被放行。
2. **它为什么被这样处理**：如果是被规则拦的，这里会指出是哪条规则、来自哪个过滤器。

面板右上角的三点菜单里有「自定义」，用来筛选：

| 筛选项 | 可选值 | 什么时候用 |
| --- | --- | --- |
| 状态 | 常规 / 已拦截 / 已修改 / 已加入白名单 | 想看「到底拦了些什么」选「已拦截」；想知道「哪些被豁免了」选「已加入白名单」 |
| 来源 | 第一方 / 第三方 | 只关心第三方广告与跟踪请求时选「第三方」；怀疑正文资源被误拦时选「第一方」 |

## 三、用它定位「是哪条规则拦错了」

这是这个面板最实用的地方，按顺序做：

1. 让问题复现一次（打开那个页面、点那个按钮）。
2. 进「统计 → 最近活动」，把状态筛到**「已拦截」**，来源先筛**「第一方」**—— 误拦正文资源通常是第一方请求。
3. 从最上面（最新）往下看，找请求地址与出问题的页面同域的那一条。
4. 点开它，看是哪条规则、属于哪个过滤器。
5. 判断处理方式：

| 判断 | 处理 |
| --- | --- |
| 规则的写法太宽（例如把一个域名整个拦了） | 在规则所在的那个过滤器里关掉它，或按 [网站打不开或功能异常怎么放行.md](网站打不开或功能异常怎么放行.md) 加一条精确的例外 |
| 只是这一个页面要放行 | 在最近活动里直接对该请求**一键解除拦截规则**，比手写规则快 |
| 页面是空白且找不到第一方请求被拦 | 可能是 HTML 元素被移除了，看下一节 |
| 找了一圈没有拦截记录 | 问题不在这里，回到 [广告拦不住怎么排查.md](广告拦不住怎么排查.md) 从总开关那一环重查 |

## 四、元素被移除的情况：先打开一项设置

有些「拦」发生在页面元素这一层，例如某块区域整个消失、某个按钮不见了，这在日志里默认**看不到**。

- **路径**：「设置 → 常规 → 高级 → 低级设置」，找到「记录已删除的 HTML 事件」这一项，打开。
- **效果**：打开后，被拦掉的 HTML 元素也会写进「统计 → 最近活动」，排查完记得关掉 —— 它会明显增加日志量。

低级设置改动有风险，官方也在页头给了警告。只改这一项、排查完改回去即可，别顺手动别的。

## 五、日常维护建议

- **排查完清一次**：日志只保留最近 10000 条，长期不清也不会撑爆存储，但混着旧记录会干扰判断。排查完在日志页清空一次，下次再查就是干净的。
- **别把它当隐私审计工具**：这里记录的是本机请求列表，能看出各个应用连了哪些域名。「统计 → 应用」里按应用看域名列表更直观，需要时再看。
- **不要靠它反推规则写法**：想自己写规则，先看官方「自己创建过滤规则」一篇的语法说明；最近活动只负责告诉你「这条被谁拦了」，不负责教你怎么写。
