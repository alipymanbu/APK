# Azahar 需要的系统文件与密钥怎么准备

> 本篇讲 Azahar 数据目录里 `sysdata` 下两个文件的来历：`aes_keys.txt` 与 `seeddb.bin`，以及怎么从你自己的 3DS 把它们导出来。

## 一、为什么有的游戏打不开

先记住一条版本线：**Azahar 2120 起（含本文这份 2122-alpha1）不再支持加密的游戏转储**，官方为这次改动专门发过说明（[azahar-emu.org/blog/game-loading-changes](https://azahar-emu.org/blog/game-loading-changes)）。所以在 Azahar 上：

- **没解密的游戏转储跑不了**——扫不出来、点进去黑屏或报解密错误，都不是文件损坏，也**不是放了密钥文件就能解决**；
- 解密要在导出环节完成：用 GodMode9 从你自己的卡带导出时选解密导出，得到的就是 Azahar 能直接用的文件（见第三节）；
- 密钥与系统文件仍然有用途：系统内容、eShop 相关功能需要它们（见第二节）。

旧 Citra 时代「放个 `aes_keys.txt` 就能跑加密转储」的经验，在 Azahar 上不再成立——别再往这个方向排查。

## 二、密钥与系统文件怎么来

| 文件 | 现在的用途 | 放置位置 |
| --- | --- | --- |
| `aes_keys.txt` | 解密所需的主密钥表：系统内容、eShop 相关功能要用 | Azahar 数据目录下的 `sysdata/` 文件夹 |
| `seeddb.bin` | 部分内容需要的种子数据库 | 同上，`sysdata/` 文件夹 |

两个文件的获取路径都是官方给的，都指向你自己的 3DS：

- **DumpKeys 脚本**：官方仓库 [dist/dumpkeys 目录](https://github.com/azahar-emu/azahar/tree/master/dist/dumpkeys) 里的 GodMode9 脚本，在你的 3DS 上跑一次，导出上面两个文件（流程见第三节）。
- **Artic Setup Tool**：官方 2120 起指定的系统文件获取工具（[github.com/azahar-emu/ArticSetupTool](https://github.com/azahar-emu/ArticSetupTool)），同样从你自己的 3DS 提取；装好系统文件后，还能在模拟器里的 eShop 应用直接下载你自己账号拥有的游戏。

## 三、从你自己的 3DS 导出（GodMode9 流程概览）

前提只有一条：**密钥、系统文件、游戏转储都只能来自你自己拥有的 3DS 主机**。本篇只覆盖这一条路径，不涉及任何其他获取方式。

这一趟导出通常做两件事，一次搞定：

- **解密导出游戏转储**：GodMode9 里对卡带选解密导出（dump decrypted），出来的才是 Azahar 能直接用的游戏文件；
- **跑 DumpKeys 脚本**：把密钥表和种子库导出来，供系统内容与 eShop 功能使用。

流程概览（具体细节随机型和系统版本而异，按你的机型搜对应的 GodMode9 教程）：

1. 在你的 3DS 上装好 GodMode9（一个运行在自制环境下的文件管理工具；让 3DS 进入自制环境的方法因机型和固件差异很大，这一步照你机型的教程做）。
2. 把上面说的官方 `DumpKeys.gm9` 脚本复制到 SD 卡的 `gm9/scripts/` 目录。
3. 按住 START 键开机进入 GodMode9，按 HOME 键打开菜单，选 **Scripts**，再选 **DumpKeys** 执行，等它跑完回到主菜单。
4. 关机，把 SD 卡插回电脑（或用读卡器），取走两个产物：
   - `gm9/aes_keys.txt`
   - `gm9/seeddb.bin`
5. 把这两个文件复制到手机上 Azahar 数据目录的 `sysdata/` 文件夹里，重启 Azahar。

一句话记住：**脚本放 SD 卡 → 真机跑一次 → 取走两个文件 → 丢进 sysdata**。

## 四、放好之后怎么验证

1. 重启 Azahar（最好连后台一起划掉再开）。
2. 验证标准看用途：密钥服务的是**系统内容与 eShop 相关功能**，这两摊恢复正常即为生效。至于黑屏的游戏，那多半是转储本身没解密（见第一节），放密钥救不了它，按第三节重新导出。
3. 还不行的，按这个顺序排查：
   - 文件名对不对（`aes_keys.txt` 一个字符都不能差，别带 `.txt.txt` 这类双重后缀）；
   - 位置对不对（必须在数据目录的 `sysdata/` 下，不是游戏目录）；
   - 游戏转储本身是不是 Azahar 要的形态——已解密、扩展名没踩 `.3ds` 的坑（见 [游戏文件格式与添加方法.md](游戏文件格式与添加方法.md)）；
   - 游戏本身在不在官方兼容性列表的「能跑」范围里（见 [游戏文件格式与添加方法.md](游戏文件格式与添加方法.md) 第四节）。
4. 密钥与转储都排除了还崩溃的，转 [常见问题与报错处理.md](常见问题与报错处理.md)。
