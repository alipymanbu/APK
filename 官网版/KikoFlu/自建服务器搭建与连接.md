# KikoFlu 自建服务器搭建与连接

> 不想依赖在线服务、想用自己的音声库，就把 KikoFlu 连到自建的 Kikoeru 后端。本篇讲后端要改哪两处设置、客户端怎么连、哪些功能连了也没有。

## 一、先分清：客户端归 KikoFlu，后端归 Kikoeru

KikoFlu 只是播放端。自建方案里，内容与账号都由开源后端 **kikoeru-express**（`https://github.com/Number178/kikoeru-express`）提供。官方 wiki 明确了两条适配前提：

- **用最新版的 kikoeru-express**，其他分支版本不做适配；
- 部署方式（本机 / NAS / 云主机）属于后端项目自己的事，按 kikoeru-express 仓库的说明部署即可，本篇不展开。

后端跑起来之后，先别急着开客户端——下面两处设置不改，客户端连上也会出问题。

## 二、后端必改的两处设置

这是官方 wiki 给出的配置步骤，部署完成后进后端的管理设置：

1. **打开用户验证**：高级设置 → Web 服务器相关设置 → 打开「用户验证」→ 下拉保存；
2. **设置一个你能记住的账号**：用户管理 → 新添加一个账户，或把默认 admin 账户的密码改成自己的。

跳过第 1 步直接连，是「客户端一直提示异常」的常见原因——客户端按带验证的方式登录，后端却没开验证，对不上。

## 三、回 KikoFlu 里连接

1. 打开 KikoFlu 的设置，添加自定义服务器地址（后端部署后的访问地址，注意带上 `http://` 或 `https://` 协议头和正确端口）；
2. 先对这条地址**测连接延迟**，通了再往下走；
3. 用第二节设置的账户登录。

服务器地址的管理方式（多地址、多账户）在 [服务器连接与账号注册.md](服务器连接与账号注册.md) 第三节。

## 四、连上之后：哪些功能预期就不可用

自建后端与 asmr.one 的功能面**不一样**，官方 wiki 点名的几项在自建后端下不可用或受限：

| 功能 | 自建后端下的状态 |
| --- | --- |
| 播放列表 | 不支持 |
| 部分高级搜索 | 不支持 |
| 标签添加 | 不支持 |
| 点赞 | 不支持 |

官方明确说明：这不属于客户端缺陷，要向后端作者请求支持。也就是说，你在这几项上反复折腾客户端设置是白费的——先确认是不是后端能力边界。播放、字幕、缓存下载等核心能力不受影响，见 [播放与字幕功能使用.md](播放与字幕功能使用.md) 与 [缓存下载与离线收听.md](缓存下载与离线收听.md)。

连不上、登录报错这类通用问题，先过一遍 [常见问题排查.md](常见问题排查.md) 的检查顺序。
