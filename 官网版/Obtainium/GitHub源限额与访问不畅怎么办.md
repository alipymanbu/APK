# Obtainium 的 GitHub 源限额与访问不畅怎么办

> 跟踪的 GitHub 应用一多就报「速率限制」，或者检查更新总是转圈失败 —— 本篇讲官方 Wiki 给出的两套解法：个人访问令牌与代理前缀。

## 一、为什么偏偏 GitHub 会限额

Obtainium 抓 GitHub 应用的版本信息走的是 GitHub 的接口，而 GitHub 对接口请求数设了上限 —— 未认证的请求额度很低，跟踪的应用到了几十个以上，一轮后台检查就可能把额度用完，于是报「速率限制」。这是用 GitHub 源最常撞到的一堵墙，报错字样一般直接带着 rate limit 字样。

## 二、第一步：配一个个人访问令牌

令牌（Token）相当于给请求报上身份，额度立刻从「按匿名访客算」提到「按你的账号算」。官方 Wiki 给的步骤：

1. 登录 [GitHub](https://github.com/)；
2. 进设置里的开发者选项，找到 [Fine-grained tokens](https://github.com/settings/personal-access-tokens) 页面；
3. 点 **Generate new token**；
4. 给令牌起个名字、设个有效期；
5. 拉到底部点 **Generate token**；
6. 复制生成的令牌，粘进 Obtainium 的设置页 —— 令牌只显示这一次，关掉页面就再也看不到了，务必当场复制。

令牌不设任何仓库权限也能起到提额的作用，不用被权限选项吓住。

## 三、第二步：连不上时配代理前缀

令牌解决「额度」，解决不了「连不上」—— 有些网络环境下 GitHub 接口本身就访问不稳，表现为检查更新长期转圈、换 Wi-Fi 也不见好。这时可以在源设置里配 **GitHub 代理前缀**（例如 `gh-proxy.com` 这类公共加速代理）：配好后所有 GitHub 接口请求都改走这个前缀中转。

两点注意：公共代理的速度与可用性由代理方决定，坏了就换一个或清空还原；这只是网络层的替换，应用列表、令牌都不受影响。

## 四、顺手省额度的两个小动作

- **关掉「验证最新标签」**：这个开关每查一个应用要多花一次接口调用，应用多时它就是额度刺客，除非你要对付预发布版排序问题，否则关着；
- **能换源的换源**：同一个项目如果也发布在 GitLab、Codeberg 或 F-Droid 上，跟踪那边就不占 GitHub 的额度，各源找法见[支持的应用源有哪些.md](支持的应用源有哪些.md)。

## 五、配完还是不行

按这个顺序过一遍：确认令牌粘的时候没带空格 → 手动下拉刷新看报错是否变化 → 还不行就去[官方仓库的 issues 页](https://github.com/ImranR98/Obtainium/issues)搜关键词，确认是不是当前版本引入的问题。其它症状的对症处理见[更新失败与常见问题排查.md](更新失败与常见问题排查.md)。
