## 二、哪些链接必须手动指定来源

第三方 F-Droid 仓库、Jenkins、SourceHut 这类地址，Obtainium 不会自动认出，添加时要从「覆盖来源」下拉框手动选 —— 否则会被当成 HTML 源处理，抓回来的东西不对。

第三方 F-Droid 仓库还要多填一步：一个仓库里应用很多，得在「应用 ID 或名称」里写清你要哪一个；版本选择上可以在「跟随仓库建议版本」与「取最高版本代码」之间选，仓库标记混乱时用后者。

直链与 HTML 源的区别：直链就是地址本身是一个 APK 文件；HTML 源给的是一个网页，Obtainium 去页面里把 APK 链接找出来、排序、挑一个 —— 页面结构复杂的（下载按钮藏好几层）可以配「中间链接」先跳一层再找。

## 三、几个源的特殊行为（踩坑前先看）

- **GitHub**：对 API 请求数有限额，跟踪的仓库多了会撞「速率限制」报错 —— 在设置里填一个个人访问令牌即可解决；部分网络环境下还可以在源设置里配 GitHub 代理前缀。令牌申请步骤与代理的用法单独写了一篇：[GitHub源限额与访问不畅怎么办.md](GitHub源限额与访问不畅怎么办.md)。GitHub 源另有排序方式、验证最新标签、检查仓库重命名等选项，用来对付预发布版与多个旧版本并存的情况；
- **APKMirror / RockMods**：只能跟踪提醒，不能下载安装 —— 不是出了故障，是对方不允许；
- **F-Droid 与其它渠道签名不同**：从 F-Droid 装的应用，换 GitHub 之类的源去更新会因签名不一致被系统拒绝 —— 同一个应用从头到尾认准一个渠道。Obtainium 自己分两个包名版本也是这个原因，见[F-Droid版与官方版有什么区别.md](F-Droid版与官方版有什么区别.md)；
- **腾讯应用宝**：部分包只有 32 位版本，较新的机器可能装不上；
- **APKPure**：有些应用给的是 XAPK，Obtainium 对 XAPK 的支持不完整，可能装不了；
- **HTML 源**：灵活度最高、也最容易要调试的源 —— 支持自定义请求头、APK 链接过滤正则、版本提取正则；抓不到版本号时它用链接哈希当「伪版本」，对方改版后伪版本一变就可能误报更新，重新进该应用的选项里调一下。

## 四、多包应用怎么固定选哪一个

一个版本同时挂 universal、arm64、armv7 多个包时，每次都要你手动挑、后台静默更新也会停摆 —— 用「通过正则表达式筛选 APK」把它固定成唯一目标，比如只要 arm64 就把其余筛掉。各选项的具体说明见[添加应用与更新设置.md](添加应用与更新设置.md)。
