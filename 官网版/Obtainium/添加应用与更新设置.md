## 一、添加一个应用的最小流程

1. 点应用列表右下角的「+」，粘贴应用发布页链接 —— GitHub 仓库页、GitLab 项目页、F-Droid 应用页、某个官网的下载页都可以；
2. Obtainium 会自动识别来源；识别不出来时会让你从「覆盖来源」下拉框里手动指定。哪些链接必须手动指定，见[支持的应用源有哪些.md](支持的应用源有哪些.md)；
3. 确认后应用进入列表，Obtainium 随即查一次版本，之后按设置页的频率定期检查；
4. 不想自己配的懒办法：官方维护了一个众包配置库 [apps.obtainium.imranr.dev](https://apps.obtainium.imranr.dev/)，搜应用名能直接拿到别人配好的链接与选项，应用内的「添加应用」页面也有入口；
5. 懒得找链接的另一个路子：GitHub、GitLab、Codeberg 这几个源支持在添加页里直接搜应用名（GitHub 还能按最低星标数筛掉同名小项目），搜到即加。

## 二、每个应用可以单独调的选项

点开列表里的应用进入编辑页，常用选项如下：

| 选项 | 作用 | 什么时候用得上 |
| --- | --- | --- |
| 仅跟踪 | 只收更新通知，不下载不安装 | 应用在只许看的源上（如 APKMirror），或暂时不想装新版本 |
| 通过正则表达式筛选 APK | 从一个版本的多个安装包里筛出唯一目标 | 同时提供 universal / arm64 / armv7 多个包的应用；不筛的话每次都要你手动挑，后台静默更新也会停摆 |
| 尽可能按 CPU 架构筛选 APK | 按你设备的架构自动排除不兼容的包 | 一般直接开着；它按文件名猜，不一定准，不能全指望 |
| 应用名称 | 改列表里显示的名字 | 源里抓到的名字乱码或太长时 |
| 禁用后台更新 / 跳过更新通知 | 单独关掉这个应用的后台动作或提醒 | 个别应用不想让它自动动 |

## 三、更新检查怎么配

设置页里管全局：

- **检查频率**：后台检查的间隔自己定；
- **附加条件**：仅 Wi-Fi、仅充电时、启动时检查、查看应用详情时检查 —— 四个都能单独开关；
- **后台机制二选一**：标准后台调度（省电，但可能被厂商的电池策略往后推）或前台服务（更准时，代价是通知栏常驻一条，且要求 Android 11 及以上）；
- **并行下载**：批量更新时同时下载多个包，快但占带宽，网络一般就别开。

## 四、静默安装（后台自动装）的条件

后台检查发现新版后，能不能不弹窗直接装好，要看这几个条件同时满足：

1. 系统是 Android 12 或更高；
2. 被更新的应用本身要求较新的系统版本（旧应用系统会强制要求人工确认）；
3. 手机上当前这个版本当初就是 Obtainium 装的 —— 你以前手动装的版本它接不上手；
4. 全局后台更新与该应用的后台更新都没被关掉；
5. 更新包能被筛成唯一一个（多包应用靠上面的正则筛选）。

差任何一条就退化为「下好了、弹通知、你点一下确认」。想让通过率更高还可以配 Shizuku（怎么配、有什么维护成本，单独写了一篇：[Shizuku静默安装怎么配.md](Shizuku静默安装怎么配.md)），另有「伪装成 Google Play」的开关改善个别应用的兼容性 —— 这两项属于可选折腾，不配也完全能用。

## 五、版本显示对不上时

Obtainium 的比对逻辑：拿系统里装的版本号和源上写的版本号做文本比对，两边格式一致才比，比不了就对这个应用停用版本检测 —— 这是「明明出了新版却不提示」的常见原因之一。两个每应用开关可以救急：「使用版本代码作为操作系统版本」和「使用发布日期作为版本」。完整排查清单见[更新失败与常见问题排查.md](更新失败与常见问题排查.md)。
