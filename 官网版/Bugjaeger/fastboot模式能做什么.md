# Bugjaeger fastboot 模式能做什么

> 本篇讲 fastboot 通道用得上什么场景、命令支持范围由谁决定、哪些机型根本不支持，以及刷写失败时的排查顺序与风险。

ADB 是设备开机进系统之后的通道，fastboot 则工作在引导加载程序这一层，用来读写分区、查看机型与安全状态这类底层信息。Bugjaeger 两种协议都支持，也就是说你在电脑上要装 platform-tools 才能做的事，插一根 OTG 线也能在手机上做。代价是风险等级更高：fastboot 里敲错命令的后果比 ADB 严重得多。

## 一、先分清两套通道

| 对比项 | ADB（日常用） | fastboot |
| --- | --- | --- |
| 目标机状态 | 正常开机进系统 | 处于 fastboot / bootloader 模式 |
| 连接方式 | USB 线或 Wi-Fi 都行 | 只能 USB 线直连 |
| 典型用途 | 装卸载应用、传文件、看日志、截图 | 读引导加载程序变量、查看安全状态、分区相关操作 |
| 出错代价 | 通常可恢复 | 可能清数据、进不了系统 |

## 二、怎么进入 fastboot 环境

1. 用 USB 线把主机与目标机连好（这一步不能靠无线）。
2. 让目标机重启进 bootloader。Bugjaeger 的 **Commands** 标签里有对应的重启命令，也可以手动按目标机的组合键进入。
3. 切到 Bugjaeger 的 **Fastboot** 标签，点右下角的 **<>** 悬浮按钮打开 fastboot shell，之后的命令都在这个 shell 里执行。

## 三、命令支持范围由机型决定

进 shell 后第一条命令建议先跑：

```bash
fastboot --help
```

它列出的只是**"理论上可用"的命令集合**，不代表你这台设备都能用。真实可用的命令取决于两件事：

- **目标机（含运营商定制版）自己的实现**。同一品牌不同型号、甚至同型号不同运营商版本，支持的命令都可能不同；
- **命令是否依赖额外工具**。有的命令需要配套的外部程序才能完成，例如 `fastboot -w` 需要类似 `mke2fs` 的格式化工具来生成稀疏格式；按官方 FAQ 的说明，这类工具没有随应用一起提供，所以这一类命令不会生效，不是操作姿势不对。

结论很直接：**没有放之四海皆准的 fastboot 命令清单**。要刷某台设备，得先去看该机型官方的说明，而不是照抄别人的教程。

## 四、三星机型不支持 fastboot

官方 FAQ 里写得明确：三星设备不支持 fastboot，用的是自家那一套，第三方工具没有稳定的官方协议可依。所以：

- 三星设备进 bootloader 后，在 Bugjaeger 里会显示为空或没有任何设备；
- 官方也说明了，**不会为三星机型做刷写支持**。

如果你手上是三星的设备，这一节就可以直接跳过了，用别的渠道处理。

## 五、报「Write to device failed」怎么办

这个报错不是一句话能解释的，按下面顺序逐条排除：

1. 确认要写入的镜像文件本身**完整、且与目标机匹配**（半截文件、别的机型的镜像都会失败）；
2. **换一根更短的 USB 线**；
3. 全程**不要经过 USB Hub**，直连；
4. 两台设备的 **USB 标准尽量一致**（都用 2.0 或都用 3.0）；
5. 执行命令时**别移动设备、别碰线**，放稳在桌面上；
6. 检查是不是这台目标机本身不支持这条命令——应用内置的 fastboot 版本相对较新，遇到很旧的设备或做过深度定制的系统可能有兼容问题，换一条常见命令试试，能通则问题在这条命令上。

## 六、动手前的三条提醒

- **刷写会清空数据，也可能让设备无法开机**。执行前先确认数据有备份，并且清楚每一步在做什么。
- **解锁引导加载程序是另一件独立的事**，各家有各自的官方流程与后果（丢失保修、部分应用拒绝运行等），这个应用不负责也不能替你绕过；它只能在你已经获得相应权限的前提下执行引导加载程序允许的操作。
- 官方明确表示**不提供具体机型的具体操作指导**。所以查资料时以你机型的官方文档为准，别按别人的机型照抄。

日常想做的多数事情（装应用、传文件、看日志、改设置）都在 ADB 通道里，不需要进 fastboot，遇到问题先看 [连不上设备怎么排查.md](连不上设备怎么排查.md)。
