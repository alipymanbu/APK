# Bugjaeger 免 root 能做什么不能做什么

> 本篇讲清楚这个工具的能力边界：不 root 的情况下哪些操作真的能生效、哪些一定会失败，以及为什么。

Bugjaeger 走的是 Android 官方开放的 ADB 调试通道，不 root 也能完成装卸载应用、传文件、看日志、截图录屏、查看与结束普通进程这类日常操作，但也有明确的边界。本篇把两边逐项列清，并说明为什么有些命令执行了却没有效果。

## 一、不 root 也能做的事

| 类别 | 具体能做什么 |
| --- | --- |
| 应用 | 安装、卸载普通应用；启动、强制停止、禁用已安装的应用；查看已安装应用的详细信息；从目标机把已安装的 APK 拉出来 |
| 文件 | 在目标机文件系统里浏览、推送与拉取文件；在可写目录里放文件并改权限 |
| 日志 | 读取、按条件过滤、导出 logcat |
| 画面 | 截图；完整版还能把实时画面录成视频文件；屏幕镜像并用手势远程点击操作 |
| 进程与信息 | 查看运行中的进程与附加信息、结束普通进程；查看 Android 版本、SDK、内核、CPU、ABI、显示参数；查看电池温度、健康状态、技术类型、电压等 |
| 控制 | 重启设备、重启进 bootloader、旋转屏幕、切换设备 |
| 命令 | 在交互式 shell 里执行任意 shell 命令；把常用命令存成自定义命令一键执行 |
| Fastboot | 目标机进入 fastboot 后读取引导加载程序变量、执行 fastboot 命令 |

上表里的动作，在电脑上要用命令行逐条敲，在 Bugjaeger 里多数是标签页里点一下按钮，或者存成自定义命令下次直接调用。

## 二、不 root 就做不到的事

| 做不到 | 原因 |
| --- | --- |
| 真正删除系统应用 | `/system` 分区在正常启动下是只读的，ADB shell 改不动；多数机型上卸载系统应用不可逆 |
| 结束系统进程 | 系统进程受权限保护，执行会被拒绝 |
| 改系统分区里的文件、刷入第三方系统镜像 | 同上，需要先解锁引导加载程序等更重的操作 |
| 拿到 root 权限、给别的应用提权 | ADB shell 的身份是 shell 用户，不是 root |
| 绕过应用自身的权限、登录、付费等限制 | 这不在 ADB 的能力范围内 |

遇到「命令执行了但没有任何效果」时，先对照这张表：很可能不是命令写错，而是这件事本来就需要更高权限。

## 三、和「root 工具」不是一回事

- Bugjaeger 不是一键 root 工具，也不利用系统漏洞；它使用的还是设备官方开放的那条调试通道，需要你在目标机上手动授权。
- 它不会绕过 Android 的安全机制。也就是说，在未 root 的设备上，它同样做不了系统级的特权操作。
- 想让设备获得 root，是另一条独立的、与 Bugjaeger 无关的路径；那一步的风险（变砖、失去保修、部分应用拒绝运行）由你自己承担，本篇不涉及。

## 四、动手前的两条自保

1. **能禁用就先别卸载**。对预装应用，用禁用（disable）代替卸载：多数机型上禁用可以随时恢复，而卸载通常不可逆。
2. **对系统组件谨慎下命令**。在系统应用上执行强制停止、禁用一类操作前，先确认它是不是桌面、系统界面、输入法这类关键组件——弄错会导致设备行为异常，严重时只能恢复出厂设置。Android 的重要组件在崩溃后大多会自己重启，但这不是可以依赖的保险。

## 五、和电脑上执行 adb 命令的取舍

两者用的是同一套协议、同一套授权，能力没有本质差别。区别在场景：

- 电脑上有完整键盘，批量敲命令、看长篇日志更舒服；
- 手机随身，设备在别处、或者你只想临时改一下设置时更快。

所以常见的用法是两者配合：在家用电脑做重活，在外面临时处理用 Bugjaeger。无线连接时能做的事和插线时一样（受带宽影响，镜像、录屏这类看画面的操作会更卡），连接方式见 [手机连手机怎么连上设备.md](手机连手机怎么连上设备.md)。
