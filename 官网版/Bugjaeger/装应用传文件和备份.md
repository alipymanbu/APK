连上目标机之后，最常用的两类操作就是「给目标机装东西」和「在目标机与主机之间搬文件」。Bugjaeger 把这两件事放在 Packages 与 Files 两个标签页里，也允许你直接写 shell 命令。本篇把四条路径、各自的前提和常见失败原因讲清楚。

## 一、装应用（含拆分包）

装 APK 有两条路：

- **图形入口**：切到 **Packages** 标签，用安装按钮选中主机上的 APK 文件，推送给目标机安装。适合装一两个包。
- **命令行入口**：在交互式 shell 里用 `pm install` 加上目标机上的 APK 路径。适合批量、或者要带参数的情况。

一个容易踩的坑是**拆分包（split APK）**：像 VR 一体机上的大型应用常被拆成 base 加若干配置包，只装其中一个会失败。Bugjaeger 支持侧载这类拆分包，操作时把同一个应用的所有分片都选中一起装，别只挑一个。装完如果列表里看不到，先确认分片是不是装全了。

## 二、应用管理：启动、强停、禁用、卸载、导出

| 想做的事 | 在应用里怎么点 | shell 等价命令 |
| --- | --- | --- |
| 启动某应用 | Packages 标签里点该项旁边的运行按钮 | `monkey -p app.package.name -c android.intent.category.LAUNCHER 1` |
| 强制停止 | Processes 标签里点该项旁边的叉 | `am force-stop app.package.name` |
| 禁用 / 启用 | Packages 标签里的相应操作 | 用 `pm` 系列命令 |
| 卸载 | Packages 标签里的卸载 | 用 `pm` 系列命令 |
| 查看应用详情 | Packages 标签内展开该项 | `dumpsys package` 一类 |

两条路效果一样，图形入口胜在不用记参数，命令行胜在能一次处理一批。

**把目标机上已装的应用导出**（俗称拉 APK）也在 Packages 标签里：选中目标应用，把它拉取到主机存储，得到的 APK 可以直接装到另一台设备上。想省事的话，主机上装同一份 Bugjaeger，两台设备各连一次，用 Files 在中间转一次也能达到同样效果。

## 三、传文件

文件操作集中在 **Files** 标签：

1. 顶部输入框里填目标机上的路径，用来定位当前目录，例如：

```text
/data/local/tmp
```

2. 用工具栏的 **push** 把主机上的文件推到当前目录，用对应的 **pull** 把目标机上的文件拉到主机。
3. 目标机的文件系统里，普通应用看不到的目录（比如 `/data/data` 下别的应用数据）访问会失败，这不是传输出错，而是权限边界。

跨设备搬文件优先选 `/sdcard` 下的公共目录或 `/data/local/tmp`，这两处通常可写，也不容易被系统清理。

要搬的是大文件（几百兆以上）时优先插线：无线传大文件占满带宽，录像、镜像这类操作会跟着卡；USB 直连也更快、更不容易中途断。

## 四、在目标机上运行可执行文件

ADB shell 能运行目标机架构的可执行文件，这在只带手机出门时很实用。基本流程：

1. 把编译好的可执行文件推到目标机的可写目录，惯例是 `/data/local/tmp`；
2. 给它加上可执行权限（改文件权限的功能在完整版里提供）；
3. 在自定义命令或交互式 shell 里执行它。

三个现实限制，动手前先知道：

- **架构必须对得上**。Android 设备绝大多数是 ARM，x86 上编出来的二进制跑不起来，需要交叉编译；
- 依赖的系统库要对得上，用到 Android 不提供的接口或带图形界面的程序一般跑不起来，实际能用的多是基础命令行工具；
- 不是随便哪个目录都允许执行文件，放到 `/data/local/tmp` 这类可写且允许执行的位置最稳。

## 五、备份与备份内容查看

Bugjaeger 支持创建 ADB 备份、检查备份文件内容、把其中一部分提取出来。有两点要提前知道：

- 备份**是否包含某个应用的数据，取决于系统版本与那个应用自身的设置**，不是所有应用都会被完整备份；
- 备份文件是打包格式，直接改名解压往往拿不到有效内容，用应用自带的查看 / 提取功能更可靠。

还有一条会随系统版本变的信息：按 Android 官方在 Android 12 行为变更里的说明，**以 Android 12（API 级别 31）或更高版本为目标平台的应用，其应用数据不会包含在 `adb backup` 导出的内容里**。也就是说，同一台设备升级后，备份里能取回的应用数据可能比升级前更少。具体能拿到什么，以你手上设备与系统版本的实际表现、以及官方页面当时说明为准。

所以备份更适合当作「能取回一部分数据」的兜底手段，重要数据仍然建议另外用云同步或导出功能留一份。

## 六、写命令的两个要点

- **交互式 shell 里已经处在 `adb shell` 环境**，直接敲命令本身即可，不要再加 `adb` 或 `adb shell` 前缀，加了通常只会报找不到命令。
- 常用命令存成**自定义命令**，下次一键执行；免费版对自定义命令数量有限额，完整版不限（见 [高级版和免费版有什么区别.md](高级版和免费版有什么区别.md)）。

## 七、操作失败时的对照

| 现象 | 常见原因 |
| --- | --- |
| 安装失败 | 拆分包只装了其中一片；目标机存储不足；目标机上已装同应用的新版本，装旧版通常会被拒 |
| 装完没出现 | 应用被系统限制安装非商店来源，需要先在目标机上放行 |
| 推文件失败 | 目标目录只读或不存在，换 `/sdcard`、`/data/local/tmp` 再试 |
| 命令报「找不到」 | shell 里多写了 `adb` 前缀，或者该命令在这台设备上不存在 |
| 命令执行了没反应 | 这件事本身需要更高权限，对照 [免root能做什么不能做什么.md](免root能做什么不能做什么.md) |
