「插上线，设备列表里什么都没有」是这类工具最常见的第一步故障。多数情况不是应用坏了，而是授权没走完、线材或 USB 角色不对。本篇按从便宜到费事的顺序排，建议逐条做完再往下走，不要跳步。

## 一、先确认三件最基本的事

| 检查项 | 怎么确认 |
| --- | --- |
| 目标机开了开发者选项和 USB 调试吗 | 设置 → 关于手机连点版本号进入开发者选项，再确认「USB 调试」是开的 |
| 两次授权都过了吗 | 主机上要同意「访问 USB 设备」，目标机上还要同意一次「USB 调试」授权弹窗 |
| 线插对了吗 | OTG 线的主机端必须插在能当 USB 主机的那一侧 |

很多人卡在这里：只点了主机上的 USB 授权，漏掉了目标机上的调试授权弹窗，或者手滑点了「拒绝」。目标机上如果一直不出弹窗，可以进开发者选项里的「撤销 USB 调试授权」，再重新插线触发一次。

## 二、按顺序往下排

1. **换一根线**。这是最高频的解法，劣质线只供电不传数据，外观看不出来。
2. **不要经过 USB Hub**，直连两台设备，中间任何转接都可能让 ADB 握手失败。线越短越稳。
3. **确认主机开了 OTG**。部分机型（例如一些 Realme 设备）在系统设置里单列了一个「OTG 连接」开关，在主机上找到并打开它，OTG 才对外供电。
4. **USB-C 对 USB-C 直连时检查端口角色**。两台都是 Type-C 时，系统需要决定谁是主机、谁是从机，去设置的「USB 偏好设置 / 由谁控制」里确认方向正确，别让两台都想当主机。
5. **目标机是 Android 10 及以上时，把 USB 模式设成 PTP**。有些机型在 MTP 模式下不会正常挂出调试接口。
6. **让两台设备的 USB 标准对齐**，尽量都用 USB 2.0 或都用 USB 3.0，高低配混接在部分机型上会握手失败。
7. **目标机上的授权弹窗确认勾了「一律允许」**。只同意一次的话，下次插线还得再点一遍；如果你误删过授权，重新走一遍第一节的撤销授权流程。
8. **部分华为机型：先把 USB 共享打开，再开 USB 调试**。这一条来自第三方教程、官方 FAQ 里没有收录，属于有用户反馈有效；前面几条都试过无效时可以一试。

## 三、无线连接单独查

无线连不上和 USB 完全不是一类问题，按下面顺序：

| 现象 | 先查什么 |
| --- | --- |
| 填了 IP 连不上 | 两台设备是否在同一个 Wi-Fi 网段；路由器是否开了 AP 隔离 / 访客网络隔离 |
| 之前连过，现在连不上 | 目标机是否重启过——多数机型重启后会丢掉 `tcpip` 监听，需要重新插线执行 Connect through WiFi |
| 一直在「正在连接」 | 端口填错：标准方式的端口是 5555；Android 11+ 配对时显示的配对端口不能用来连接 |
| 连接时断时续 | 无线信号本身的问题，换到信号更好的位置或改用 USB |

执行 Connect through WiFi 之后，应用会尝试自动连接一次，这一步官方明确说明**不一定成功**，失败就手动用 **+plug** 对话框填 IP 加端口重连。

手表、电视这类目标设备的调试开关位置和手机不一样，单独整理在 [连手表和电视这类设备.md](连手表和电视这类设备.md) 里。

## 四、更新 Bugjaeger 之后突然连不上

这种情况有固定的处理顺序，从最轻的动作开始试，别一上来就清数据：

1. 进 Android 的「应用信息」页面，找到 Bugjaeger 的**默认打开（Open by default）**并重置；
2. 还不行，再**清除存储 / 数据**——注意这会删掉你建的自定义命令和已保存的截图；
3. 最后才重装。

## 五、设备本身能力不足的表现

低端设备可能出现「连上了但命令不可靠、过一会儿就掉线」，并且日志里能看到这样的报错：

```text
ERROR: n = -1, errno = 12 (Out of memory)
```

这属于主机内存吃紧，不是命令写错。可选的应对是改用无线连接（USB 那套流程更吃内存），或者换性能更好的主机。老设备上 USB 连接还要靠 OTG 供电，反过来也会加重这一项。

## 六、判断问题出在哪一边

想确认是设备 / 线的问题，还是 Bugjaeger 的问题，用一台电脑做隔离测试最有效：

1. 在电脑上装好 ADB，用数据线连目标机，执行 `adb devices`。
2. 如果能正常识别，再执行：

```bash
adb tcpip 5555
```

3. 然后在主机上的 Bugjaeger 里用 **+plug** 手动填目标机 IP 和 5555 端口连接。

- 电脑能连、Bugjaeger 走 Wi-Fi 也能连 → 问题在 USB 那一环（线、OTG、端口角色）；
- 电脑都连不上 → 问题在目标机或线材，跟应用无关，先去解决目标机的调试开关与授权。

## 七、确认是应用的问题时怎么反馈

真要反馈问题时，官方要的信息比想象中多，一次给全能省一轮往返：你做了什么操作（要能复现）、Android 版本和具体机型、能看清问题的截图、完整报错信息；有条件再附上 Logcat 日志。Bugjaeger 自带日志读取与导出功能，路径见 [看日志截图和录屏怎么用.md](看日志截图和录屏怎么用.md)。反馈渠道是开发者的邮箱 `roman@sisik.eu`，注意那里是他的通用邮箱，写信时说明是 Bugjaeger 的问题。
