## 一、一条规则 = 条件 + 动作

规则用大白话就能描述：**「当我收到某条通知（条件），就执行某件事（动作）」**。例如：

- 来自 WhatsApp、内容包含 `urgent` 的通知 → 报警提醒
- 来自购物应用、内容不含「已发货」的通知 → 直接移除
- 睡觉时间段的全部通知 → 暂存，早上打包推给你

条件能用的维度包括：**哪个应用**、**通知文字**（关键词/短语）、**发送者**（通知标题里的人名）、**时间**、**屏幕是否亮着**、**手机是否在某个位置**等，动作则从静音、报警到自动回复有几十种，全部清单见 [通知动作一览.md](通知动作一览.md)。

## 二、筛选组：条件是怎么组合的

条件部分由**筛选组（group）**构成。一个筛选组里装着若干短语和子组，再用一种「组合方式」把它们串起来。组合方式一共四种：

| 组合方式 | 什么时候匹配 |
| --- | --- |
| Contains all of（全部包含） | 短语**全部**出现在通知里，如同时含 `John` 和 `Jane` |
| Contains any of（任一包含） | 短语**至少一个**出现，如含 `John` 或含 `Jane` |
| Doesn't contain all of（非全含） | **不是全部**出现就算命中（缺任意一个就中） |
| Doesn't contain any of（全不包含） | 一个都不出现才算命中 |

注意中间两种的区别：`Doesn't contain all of` 只要**缺一个**就命中，`Doesn't contain any of` 要**全都没有**才命中。短语只有一个时，这两种写法效果相同。

筛选组里还可以嵌套**子组**，子组先算出「中/不中」，再当成一个短语参与父组的判断。

## 三、两个套用实例

### 实例 1：群消息里只要某个人说话才提醒

场景：篮球群（WhatsApp 群聊名「Basketball Group」）太吵，只要朋友 John 之外的人发言就静音。写法：

```text
Contains all of
├── "Basketball Group"
└── Doesn't contain any of
    └── "John"
```

外层要求「是篮球群」，子组负责「不含 John」，两个都中才触发。

### 实例 2：特定的人发紧急词才报警

场景：收到包含 `emergency` 或 `help`、且来自妻子或父亲的消息时报警。写法：

```text
Contains all of
├── Contains any of
│   ├── "Emergency"
│   └── "Help"
└── Contains any of
    ├── "Wife"
    └── "Dad"
```

两个子组各管一个维度（关键词、发送人），外层用「全部包含」把两个维度都锁死。

## 四、规则打架了怎么办

一条通知可能同时匹配多条规则，而有些动作天生互斥（比如「静音」和「自定义响铃」不可能同时成立）。BuzzKill 的处理方式：

1. **默认自动裁决，通常不用你管**：更具体的那条赢。比如一条规则针对「Messages 里来自 John Smith 的通知」，另一条针对「所有应用」，那么 John Smith 的通知只触发前者——应用能看出前者的范围窄得多。
2. **手动指定优先级**：在规则列表里点该规则左上角的三点菜单，选 **Set priority**，设为 **High**，冲突时它必赢。
3. **改写规则绕开冲突**：给不想让它赢的那条加排除短语，或加应用/关键词筛选把范围收窄。

常见互斥组合（节选）：

| 一边 | 另一边 |
| --- | --- |
| Alarm（报警） | Mute / Cooldown / Dismiss |
| Batch（暂存打包） | Mute / Dismiss / Sticky / Summarize / Custom alert / Flashlight 等 |
| Mute（静音） | Custom alert / Remind me / Flashlight |
| Dismiss（移除） | Secret / Sticky / Add snooze button |
| Unsilence（破静音） | Mute / Cooldown |
| Reply（自动回复） | Batch |
| Press button（自动按按钮） | Batch / Open notification / Remind me |

有一条细节要注意：**Dismiss 若设置为「延迟几秒再移除」**，它与 Custom alert、Flashlight、Remind me 就不再冲突（立即移除才冲突）。

**Multi-tool（多工具）规则**是在一条规则里挂多个动作的写法：组内动作按**排列顺序**定先后（排在前面的赢）；这条规则整体对外冲突时，仍按它的优先级参与裁决。

## 五、调不动的排查思路

规则建好却没反应，先按这个顺序查：

1. 去规则列表确认规则**开关是开的**，条件里的短语和通知原文**逐字对得上**（大小写、空格都会影响匹配）。
2. 怀疑是规则冲突的，按第四节的三招处理。
3. 通知历史里**根本没出现**这条通知的，多半是后台被厂商电池管理杀掉了，按 [常见问题排查.md](常见问题排查.md) 第一节处理各品牌的开关。
4. 调好的规则记得导出备份，方法见 [设置备份与换机迁移.md](设置备份与换机迁移.md)。
