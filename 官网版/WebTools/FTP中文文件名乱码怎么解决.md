# Web Tools 连 FTP 时中文文件名乱码怎么解决

> 本篇讲用 Web Tools 连 FTP/SFTP 传中文文件名出现乱码的原因与处理办法：先分清乱的是哪一层，再按服务端、文件、协议三条路处理。

## 一、先分清：乱的是「文件名」还是「内容」

两种乱码原因完全不同，处理方向也不同：

| 你看到的现象 | 问题所在 | 去哪一节 |
| --- | --- | --- |
| 目录列表里文件名变成问号、方块或乱字符 | 双方文件名编码不一致 | 二、三、五 |
| 文件名正常，打开后里面的文字是乱码 | 文件内容的字符集与打开方式不匹配 | 四 |

在 Google Play 评论区有用户反馈过第一种情况（用另一台设备开 FTP 服务端，Web Tools 连上后中文字符显示乱码）。这类问题的根源在协议：FTP 不约定文件名用什么字符集，老服务端常用 GBK 一类编码存文件名，新客户端一般按 UTF-8 解读，两边对不上就乱。

## 二、在服务端把编码统一成 UTF-8

FTP 客户端这边通常没有编码开关可调，能动的关键是服务端：

1. 打开你 FTP 服务端的管理界面（NAS 的文件服务设置、Windows 的 IIS、面板软件等，入口名称各不相同）；
2. 找「字符集 / 编码 / 语言 / UTF-8」相关的设置项；
3. 统一设置成 UTF-8 后重启 FTP 服务，重新连接验证。

如果你连的是另一台手机、路由器这类设备上开的轻量 FTP 服务端，它们往往只有开关没有编码选项——这种情况直接走第三节的临时办法或第五节的根治办法。

## 三、改不了服务端时的临时办法

把要传的文件先改成英文或拼音文件名再传，传完在服务端上改回中文名。改之前先传一个测试文件验证：如果英文文件名显示正常，就确认了问题只出在文件名编码上，与传输本身无关。

## 四、内容乱码是另一回事

文件名正常但打开后内容是乱码，与传输过程无关——是文件内容本身的字符集和你打开它时用的编码不匹配。处理思路：

1. 用支持选择字符集的编辑器打开，按文件的实际编码（常见 GBK、UTF-8 各试一次）读；
2. 确认内容正常后，把文件另存为 UTF-8，以后就不会再乱；
3. 网页源码类文件顺手在 `<head>` 里带上 `<meta charset="utf-8">`，浏览器端也能少一类乱码。

## 五、要彻底没有这个问题：换 SFTP

SFTP 在设计上把文件名当作 UTF-8 字符串交换，两端不需要各自猜编码，基本不会出现 FTP 那种文件名乱码。你的服务器只要能 SSH 登录就支持 SFTP：在 Web Tools 里把连接类型从 FTP 换成 SFTP，端口用 22，主机与账号信息不变，连接步骤见[FTP与SSH连接服务器教程.md](FTP与SSH连接服务器教程.md)。

换 SFTP 之外的问题（连不上、掉线、监控）汇总在[常见问题与故障排查.md](常见问题与故障排查.md)。
