## 一、速度测试：测的是当前网络

速度测试测的是手机当前网络（Wi-Fi 或流量）的上传与下载速率。两个用处：

- **换环境对比**：在家里测一次、在公司测一次，数字差异大说明是网络环境的问题；
- **排除法的第一步**：访问网站慢之前先测速，确认「底子」正常，再去怀疑服务器。

## 二、HTTP 测试：看网址到底返回了什么

HTTP 测试是本应用里最常用的工具：你填一个网址发请求，能看到状态码、响应头和返回内容，用来测网站和后端（比如 REST API）的表现。

拿到结果后这么读：

| 你看到的现象 | 大概率说明 |
| --- | --- |
| `200`，响应时间几百 ms | 正常 |
| `301` / `302` | 网址跳转了，跟随跳转或改测新地址 |
| `401` | 没带或带错了登录凭证，检查认证信息 |
| `403` | 服务器拒绝访问：权限不足、IP 被拦或触发了防护规则 |
| `404` | 路径错了，或页面被删了 |
| `429` | 请求太频繁被限流，隔一会儿再试 |
| `500` | 服务器端代码报错，去看服务日志 |
| `502` / `504` | 后端没起来或超时，先用 SSH 登服务器查服务状态 |
| 状态码有但响应时间突然变长 | 服务器负载或线路波动，过会儿再测对比 |

## 三、REST API 调试：JSON 与 XML

如果你在调接口，REST API 工具让你直接发请求看返回的 JSON / XML 内容，不用开电脑开抓包工具。典型用法：

1. 填接口地址，选择请求方式；
2. 需要的参数与请求头按接口文档填上——最常碰到的两个请求头：`Content-Type: application/json` 告诉服务端你发的是 JSON；`Authorization` 用来带登录凭证，没带它通常就会收到 `401`；
3. 发送后直接看返回体：数据结构对不对、字段是不是你要的。

配合响应时间一起看，能判断接口是「慢但能用」还是「彻底挂了」。

## 四、可达性检查：IP 通不通

可达性检查通过 IP 地址检测目标设备的网络连通性。它回答一个二选一的问题：**这个地址能不能到达**。测不出具体多快，但在「服务器疑似挂了」时是最快的第一手确认。

## 五、组合排障：三步定位问题在哪边

网站访问异常时，在手机上按这个顺序走一遍：

1. **测速**——确认手机当前网络正常；
2. **可达性检查**——确认服务器 IP 能通；不通基本是服务器宕机或被防火墙拦了；
3. **HTTP 测试**——IP 通但网站打不开，看状态码：`50x` 去服务器查服务，`404` 查路径与配置。

三步走完，「我这边的问题」「服务器挂了」「服务配置错了」三种情况就能分清。需要登录服务器处理的话，操作步骤见[FTP与SSH连接服务器教程.md](FTP与SSH连接服务器教程.md)。

## 六、站点监控：让手机替你盯

上面是手动测；如果某个站点你长期关心，在应用里对它开启监控（做法见[使用教程.md](使用教程.md)第四节），让检查按周期自动跑，出问题你先于用户知道。
