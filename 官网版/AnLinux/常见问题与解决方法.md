## 一、安装阶段

**粘贴命令后 Termux 报错或没反应**

- 确认复制的是完整命令：AnLinux 里点 COPY 后整条复制，命令很长，粘贴后回车前扫一眼结尾是否完整
- 确认是在 Termux 里执行，不是别的终端应用；AnLinux 生成的脚本只能在 Termux 里跑
- Termux 首次启动还在初始化时，等提示符稳定再粘贴

**报 `wget: command not found`**

- 新装的 Termux 没有预装脚本依赖：先执行 `pkg update && pkg upgrade`，再 `pkg install wget proot`，然后重新粘贴安装命令（完整初始化步骤见[Termux环境准备与报错处理.md](Termux环境准备与报错处理.md)第二节）

**下载镜像很慢或失败**

- 镜像走 GitHub 一类地址（官方说明明确提到需要连接 `raw.github.com` 等网址），网络不通畅是这一步最常见的故障点
- 失败后重跑同一条安装命令即可，脚本会重新下载；中断的半成品脚本会自行处理

**想知道文件下到哪了**

- 都在 Termux 主目录里，`ls ~` 能看到；发行版目录形如 `ubuntu-fs`，旁边是启动脚本

## 二、启动阶段

**`./start-ubuntu.sh` 提示 no such file or directory**

- 说明基础系统没装完或装失败了，回上一节重跑安装命令
- 确认脚本名与所选发行版一致：不同发行版生成的脚本名不同（Kali 是 `start-kali.sh`），`ls ~` 看实际名字

**报 `proot error: '/usr/bin/env' not found`**

- 多为 Termux 或 proot 版本过旧：在 Termux 里执行 `pkg update && pkg upgrade` 更新后，删掉发行版目录重跑安装命令

**Termux 弹 `[Process completed (signal 9) - press Enter]`，任务中断**

- 这是 Android 12 及以上系统的「幽灵进程」清理机制干的（子进程超 32 个或后台占 CPU 过高就杀），不是 Termux 或 AnLinux 的 bug
- 处理办法按系统版本不同，逐版本的操作见[Termux环境准备与报错处理.md](Termux环境准备与报错处理.md)第三节

**进入系统后提示命令不存在**

- 基础镜像做了精简，常用工具要自己装：Ubuntu/Debian 先 `apt update` 再 `apt install 软件名`

## 三、图形界面阶段

**VNC 连接失败 / 拒绝连接**

- 先确认在系统里执行过 `vncserver-start`，再打开 VNC Viewer
- 地址必须是 `127.0.0.1:1`（冒号后是显示号；也可以写 `127.0.0.1:5901`，两种写法等价）
- 前一次没正常关掉可能占着端口，先执行 `vncserver-stop` 再重新 `vncserver-start`

**连上后黑屏**

- 多为桌面环境没装完，或没随 VNC 启动；回 Termux 看 `vncserver-start` 的输出里有没有报错
- KDE 起不来时换 Xfce4 或 LXQt 重试，轻量桌面成功率高得多

**桌面卡顿**

- 优先换轻量桌面（Xfce4 / LXQt / LXDE），关特效
- 设备内存只有 2~3GB 时，KDE 会明显吃力

## 四、环境限制类（不是故障，别白折腾）

装好之后有些「用不了」是 PRoot 方案本身的边界，重装多少遍都一样：

| 现象 | 原因 | 能怎么办 |
| --- | --- | --- |
| `systemctl start xxx` 报 `System has not been booted with systemd as init system` | PRoot 环境没有 systemd | 服务类软件改用手动启动或发行版自带脚本 |
| 桌面里播视频没声音 | 音频支持在官方「未来目标」清单里，截至 6.x 未实现 | 见[桌面环境与图形界面.md](桌面环境与图形界面.md)第四节的说明 |
| 部分工具报错或功能异常（如需要内核模块的） | 不是双系统，改不了内核 | 换不依赖内核特性的同类工具 |
| 长任务跑着被杀（signal 9） | 系统杀后台机制 | 见[Termux环境准备与报错处理.md](Termux环境准备与报错处理.md)第三节 |

## 五、卸载与重装

- **卸载单个发行版**：AnLinux 里的卸载入口可生成卸载命令，粘到 Termux 执行；或手动删对应目录与启动脚本（见[安装Linux系统教程.md](安装Linux系统教程.md)第五节）
- **彻底清理**：卸载 Termux 与 AnLinux 两个应用即可，Termux 的数据随卸载一起清掉
- **重装**：同名目录重新安装会重建，不与残留冲突；装不干净就先手动删目录
