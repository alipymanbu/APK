## 一、决定「能不能玩」的是什么

Flash 内容的交互逻辑用 ActionScript 写成，运行在两代虚拟机上：

- **AVM 1**（ActionScript 1 / 2）：2006 年中之前的内容几乎都是它，此后仍被使用到 2013 年前后；
- **AVM 2**（ActionScript 3）：2006 年中随 Flash Player 9 引入，2013 年之后的新内容基本都是它。

你的文件属于哪一代，基本就决定了它在 Ruffle 里的成功率。

## 二、官方兼容度（截至本文检索时）

官方在 [ruffle.rs/compatibility](https://ruffle.rs/compatibility/) 上跟踪两代虚拟机的实现进度，数字会随版本更新变化，以官方页面为准：

| 虚拟机 | 语言 | API |
| --- | --- | --- |
| AVM 1（AS 1/2） | 99% | 82% |
| AVM 2（AS 3） | 90% | 82% |

按官方的说法：大多数 AVM 1 内容可以运行，可能有零星画面瑕疵；AVM 2 内容「大多数游戏足够好玩」，但仍在快速改进中。

官方在 GitHub 项目说明里给的口径也是同一句话的意思：ActionScript 1、2、3 的支持「都已经不错，但远没有完工」（见 [github.com/ruffle-rs/ruffle](https://github.com/ruffle-rs/ruffle)）。所以这张表里的百分比会一直变，今天跑不动的内容，隔几个月再试是常规操作。

## 三、快速判断手里的文件

- **按年代猜**：2006 年之前的老小游戏、早期动画，成功率最高；2010 年之后的大型 AS3 游戏，成功率低一截；
- **直接试**：这是最快的判断方式。加载一个文件只要几秒，能不能跑马上见分晓；
- **看表现**：画面正常但点按钮没反应，多半是内容用到的 API 还没实现，不是你操作错了。

## 四、玩不了时的典型表现

- 黑屏或白屏，加载条不动；
- 画面出来了，但按钮点了没反应、动画不动；
- 弹出报错（内容自带的报错或模拟器的报错）。

遇到这些表现，先按 [黑屏白屏打不开怎么排查.md](黑屏白屏打不开怎么排查.md) 排除文件损坏之类的基础问题；确认是兼容性问题就只能等新版本——项目更新很快，可以过几个月再拿同一个文件试。

## 五、安卓版与桌面版的差异

两端跑的是同一套 Ruffle 引擎，兼容性结论可以互相参考。但界面与设置不是一个量级：有用户反馈安卓版的设置项明显更少。如果你在电脑上也装了桌面版（官网 [ruffle.rs](https://ruffle.rs/) 可下载），同一个文件两端表现不一致时，以能跑通的那端为准。
