# YTDLnis 提示需要登录或验证怎么办

> 下载卡在「需要确认你不是机器人」「403 禁止访问」这类提示上时，按从便宜到贵的顺序处理：更新 yt-dlp、补齐 JS 运行时、带上自己的登录会话、放慢请求节奏，最后才怀疑内容本身。

这类提示不是应用坏了。源站在决定要不要把内容交给你之前，会给这次请求打一个信任分，分不够就回一句「请登录确认」或者直接拒绝。信任分由几个因素凑出来，下面就按「改动成本从低到高」排一遍，逐条试，命中即停。

## 一、先认清你遇到的是哪一条

| 你看到的说法 | 大致含义 |
| --- | --- |
| 需要确认你不是机器人 / Sign in to confirm you're not a bot | 拒绝的是**取信息**这一步，源站要一个更像真人的会话 |
| HTTP 403 Forbidden | 拒绝的是**取文件**这一步，通常是同一批原因的后半段 |
| 请求的格式不存在 | 源站换过编码或格式已经下架，你选的这条已经不在了 |
| 提示需要登录 / 会员 | 属于权限问题，处理方式见 [登录才能看的内容怎么下载.md](登录才能看的内容怎么下载.md) |

前两条同源，后面的办法通用；第三条要在下载卡片里重新挑一条实际存在的格式。

## 二、按这个顺序处理，命中了就停

**第 1 步：更新 yt-dlp，并确认版本真的变了。**

这是最省事也最常命中的一条。源站改规则的频率远高于应用发版的频率，而这类修复基本都随 yt-dlp 新版一起发布。进「更多 → 设置 → 更新」更到最新，然后回来重试。

关键动作是**确认版本号变了**。更新没生效就继续重试，是最容易白花时间的做法 —— 你以为换过了，其实跑的仍是旧的那份。

**第 2 步：更新或补齐 JS 运行时组件。**

信任分里有一项与 JavaScript 运行环境有关，源站的挑战需要它才能算出来。在同一个「更新」区里，检查 Deno、NodeJS 这类组件是否装了、是不是最新版 —— Deno 是多数资料推荐的首选，NodeJS 也可用。装好之后重启应用再试。

**第 3 步：带上你自己的登录会话（Cookie）。**

匿名请求在源站看来和脚本没区别，带上一个真实登录会话能明显抬高分。做法见 [登录才能看的内容怎么下载.md](登录才能看的内容怎么下载.md)。

有两条实践提醒（来自公开的排查经验，非官方说明）：

- **别用你的主要账号去给自动化请求供会话**。多个来源都提到，被判定为自动化后反复用同一账号，可能让这个账号被限流。要长期挂着下载，建议单独准备一个次要账号。
- **Cookie 会过期**。表现为「昨天还能下、今天又要登录」，这不是配置错了，重新生成一条即可。

**第 4 步：把请求节奏放慢。**

短时间内的密集请求，尤其是把同一条链接反复重试，会把信任分越拖越低。具体做法：

- 别同时并行开一堆任务对着同一个站下；
- 失败后不要立刻连点重下，隔一段时间再试；
- 长列表（播放列表、频道）分批跑，比一口气拉完稳。

**第 5 步：换一条网络出口验证。**

机房线路、共享代理、公共 VPN 出口的信任分普遍低于家庭宽带，同一台设备「在家能下、在别处不能下」是常见现象。拿手机流量和 Wi-Fi 各试一次，就能判断是不是出口 IP 的问题。

**第 6 步：确认是不是只有这一条内容不行。**

拿同一个站的另一条公开内容试一次：

- 别的能下、只有它不行 → 问题在这条内容本身（已被删除、地区受限、年龄限制、需要登录），换内容或按权限处理；
- 全都下不了 → 回到第 1 步，逐条往下走。

## 三、别做的事

- **不要对着同一条链接连续重试**。信任分是动态算的，密集重试只会让它更低，越试越下不了。
- **不要在应用之外装第三方浏览器扩展去导出 Cookie**。公开的排查记录里出现过这类扩展窃取全部会话的案例；应用自身就能生成和导入 Cookie，不需要外部工具。
- **不要为了突破限制去改包或找第三方修改版**。这不是配置问题，改动过的包还会破坏签名，后续更新和核对都会失灵。

## 四、什么情况下属于正常

下面这些情况提示得再准也没用，因为限制来自内容或网络位置本身，不是应用的设置问题：

- 内容已被删除或设为私有；
- 内容有地区限制，而你所在的网络位置不在允许范围内；
- 内容有年龄门槛，且你的会话没有通过验证；
- 内容来自带数字版权保护的平台 —— 这类平台不支持，处理口径见 [常见问题与排查.md](常见问题与排查.md)。

判断自己是哪一类，最快的办法还是第二节第 6 步：换一条同站内容对照一次。
