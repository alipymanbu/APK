## 先说结论

没有 root 的设备靠免 root 框架把模块「装进」Via 里，做法是拿框架对 Via 的安装包做一次修补，让 Via 自己带上加载模块的能力，再装修补出来的包。整个过程四步：装框架、修补 Via、装修补包、启用模块勾作用域。麻烦点不在步骤，而在修补会改掉 Via 的签名，后续更新和卸载都得顺着这个前提来。本篇把这些讲清楚。

## 需要准备什么

| 东西 | 说明 |
| --- | --- |
| 免 root 框架 | LSPatch 或它的衍生版本。原版 LSPatch 由 LSPosed 团队推出，现已停止维护；公开社区里有在其基础上继续维护的衍生版本（截至 2026 年）。用哪个不影响 BetterVia，能正常加载模块就行 |
| Shizuku（部分框架需要） | 修补或安装过程中可能提示需要 Shizuku 服务，按框架提示装上并启动即可 |
| Via 的官方安装包 | 修补的对象是 Via 本体。注意：如果手机上已经有修补过的 Via，先备好一份官方包再动手 |
| BetterVia 安装包 | 见[下载与安装教程.md](下载与安装教程.md) 的核对方法 |

## 四步走

1. 装好免 root 框架，按提示给它必要的权限。
2. 打开框架，在应用列表里选中 Via，选一种修补模式，开始修补。
3. 修补完成后安装修补包。多数框架能直接引导安装；如果提示需要 Shizuku 服务或安装失败，就卸载原来那份 Via，再到框架指定的输出目录里手动点安装。
4. 回到框架的模块页，启用 BetterVia，并勾上作用域——也就是修补后的那个 Via。

勾完作用域后重启一次 Via，进它的设置页看模块入口是否出现。

## 本地模式和便携模式怎么选

框架里的叫法可能是「本地修补」和「集成修补」，含义一致：

| 对比项 | 本地模式 | 便携模式（集成模式） |
| --- | --- | --- |
| 作用域能否随时改 | 能，改完重启应用即可 | 不能，要重新修补一遍 |
| 框架要不要常驻后台 | 要，框架被杀掉后修补版 Via 可能启动失败 | 不用 |
| 只更新模块时 | 直接升级模块，重启一次 Via | 要重新走一遍修补 |
| 只更新 Via 时 | 要重新修补 | 要重新修补 |
| 修补成品能否直接分享给别的设备 | 一般不能，依赖你本机的框架 | 可以，对方装上就能用 |

自己一台机器长期用，选本地模式更省事，改配置灵活；只有要把成品装到没有框架的设备上时，才需要便携模式。

## 修补带来的三个副作用

1. **签名变了**：修补包的签名与原版 Via 不一致，所以不能从应用商店更新 Via，也不能直接覆盖安装官方包。每次更新都要重新修补。
2. **部分机型上模块会失效甚至闪退**：作者在官方说明里提到过，某些机型上免 root 框架的修补补丁可能与模块或作用域应用的运行环境冲突，表现就是功能失效或闪退。
3. **本地模式依赖框架后台存活**：把框架加进系统的后台白名单、关掉针对它的电池优化，能明显减少「隔一段时间打开 Via 就打不开」的情况。

## 更新与还原怎么做

- **只更新 BetterVia**：本地模式直接装新版模块，重启一次 Via；便携模式要重新修补。
- **只更新 Via**：下载新版官方包，在框架里对新包再修补一次，卸载旧修补包，装新修补包。
- **想彻底还原**：卸载修补版 Via，从官方渠道装回原版 Via，再卸载框架与模块。
- **还原前**：先在 Via 里把书签、历史、Cookie 这类数据导出或备份一份，卸载会一并清掉；Cookie 相关的处理见[Cookie管理和隐私防护怎么用.md](Cookie管理和隐私防护怎么用.md)。

## 卡住了先看这几条

- 提示 Shizuku 服务未连接：装上并启动 Shizuku 后重试，或者到框架的输出目录里手动安装修补包。
- 修补完直接闪退、进不去：作者给过的答复是给框架和 Via 放行自启动、后台运行这类权限，然后多修补几次；也可以回到框架里把该应用的修补状态重置，重新修补一次。
- 修补后 Via 打不开：换一种修补模式重新修补；还不行就换一个框架版本。
- 框架里找不到 BetterVia：先确认模块装上了，再刷新框架的模块列表。
- 模块入口有了、设置却不生效：这一般不是修补的问题，按[装完不生效或闪退怎么排查.md](装完不生效或闪退怎么排查.md) 的顺序查一遍。
