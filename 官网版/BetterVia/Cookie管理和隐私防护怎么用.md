## 这篇解决什么问题

浏览时碰到的怪毛病，有不少最后都落在 Cookie 上：某个站点登录状态反复掉、页面还显示着旧内容、想把浏览器临时借给别人用一下。这些场景的共同点是「要动数据，但不想全清」。模块里的 Cookie 管理器就是干这个的，同一片区域还有几个隐私相关的开关。本篇讲它们各管什么、什么情况下值得用、以及动手前的注意点。

## Cookie 管理器

- **看**：按站点列出当前保存的 Cookie，点进单条是它的详情，详情里是这条 Cookie 自身的字段（名称、值、所属域名一类），以页面显示为准。
- **找**：站点多的时候按域名定位，比在浏览器设置里一层层翻要快。
- **清**：可以删单条，也可以整批处理；较新版本里加了全选，方便一次清一组。
- **改**：按作者的说法，这批 Cookie 不只能删，还可以批量管理并做一定修改。

典型用法是把某个站点的登录态清掉，效果等于在该站点退出登录，其它站点不受影响。

有一点要提前知道：这个管理器页面是作者自己实现的，他自己说明过不一定适配所有机型。如果在你的机器上显示不全、删不掉或改不动，退回用 Via 自带的数据清理功能即可。

## 什么时候值得开它

| 你遇到的情况 | 先做什么 |
| --- | --- |
| 某个站点一直提示登录失效 | 清掉该站点的 Cookie，再重新登录 |
| 页面显示的还是旧内容 | 清掉该站点 Cookie，再强制刷新一次 |
| 要把浏览器临时给别人用 | 先把涉及账号的站点 Cookie 清掉 |
| 装了个脚本之后页面异常 | 先停用脚本（见[脚本大全和广告规则怎么用.md](脚本大全和广告规则怎么用.md)），不要急着清 Cookie |

## 动手前要清楚的两件事

1. **Cookie 里带着登录凭证**。清掉就要重新登录，个别站点还会因此触发新设备验证一类的风控流程，属于正常反应。
2. **先确认影响范围**。删之前想清楚是「只清这一个站点」还是「全部清掉」，两者的后果差很远。

还有一条：Cookie 不要随手导出或发给别人，那等于把账号交出去。

## 隐私类开关有哪些

| 开关 | 大致作用 |
| --- | --- |
| 隐私锁 | 给进入加一道验证 |
| 超级隐身 | 隐身相关的一组设置 |
| 截屏防护 | 针对截屏、录屏的防护项 |

这三个开关的具体行为在不同版本里可能调整过，锁的对象、验证方式、防护范围都以模块内那一页的说明为准，用之前先看一眼。

## 想彻底清干净

- 只清一个站点：用 Cookie 管理器删该站点。
- 清全部数据：用 Via 自带的清除数据功能，注意它会连书签、历史一起清掉，先确认有没有需要备份的。
- 准备卸载修补版 Via：卸载会一并清空数据，动手前先把要留的导出来（见[下载与安装教程.md](下载与安装教程.md) 的还原部分）。
