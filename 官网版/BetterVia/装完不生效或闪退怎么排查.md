## 排查思路

模块不生效，多数情况不是「模块坏了」，而是没启用、作用域没勾对、或者作用域应用没重启。本篇按从易到难给你一个固定顺序，并把作者在官方说明里公开讲过的几个具体现象——完整性校验提示、自检失败与错误代码、免 root 机型失效、安卓版本不适配——分别对应到处理办法。按顺序走，能省掉大部分瞎试。

## 第一步：三个开关先确认

1. 框架里，BetterVia 是否处于启用状态。
2. 作用域是否勾了 Via。国内版包名 `mark.via`，谷歌版 `mark.via.gp`，改过包名的勾对应的那一个。
3. 勾完之后是否重启过作用域应用。框架通常会提示；不确定就整机重启一次。

这三条里任意一条没做到，表现都是「开关拨了但没反应」。

## 第二步：看 Via 里的模块入口在不在

- 进 Via 的设置页找模块入口，模块自身也能独立打开。
- **入口在、但设置不生效**：大概率是作用域没勾对，回第一步。
- **入口根本不在**：模块没被加载，同样回第一步，并确认框架本身在正常工作。

## 第三步：弹了「安全检测异常」或提示「模块不合法」

这是触发了模块的完整性校验。作者在官方说明里给的处理办法：

1. 清空模块的全部存储，再打开一次试试。有些情况下这样就能恢复。
2. 较新版本提供了「安全修复」：先给模块授予 Root 或文件读取权限，再到模块主页菜单里找到「安全修复」，点一下解除限制。

常见诱因是安装包被修改过，或者更新过程出了岔子。如果你手上的包是从非正规渠道拿的，先换成官方渠道或本文档页头那份再排查，别在二改包上浪费时间。

## 第四步：自检失败或出现错误代码

- 新系统对权限管得紧，模块读不到某些信息就会自检失败。较新版本修过这个问题，并加入了错误代码，方便定位。
- 看到错误代码先记下来，它本身就是线索；对照作者的更新页看有没有对应的修复说明。
- 还找不到原因，就开开发者模式取日志。作者说明日志输出在 `Android/data/` 下以 `BetterVia` 命名的目录里，按时间命名，路径形如 `/storage/emulated/0/Android/data/<作用域应用的包名>/files/BetterVia/`。

注意：开发者模式与日志入口是较新版本才加的，模块版本太旧就没有这一项。

Via 自己那边也有一份调试日志：进 Via 的设置 - 关于，点一下它的 logo 就能看到；较新版本的 Via 还支持把这份日志直接分享出去。

## 第五步：免 root 机型上功能失效甚至闪退

作者在官方说明中提到，某些机型上免 root 框架的修补补丁可能与 BetterVia 或作用域应用的运行环境冲突，表现就是模块失效、甚至应用闪退。处理办法是换一种修补模式重新修补，或者换一个框架再试，具体操作见[没有root怎么用LSPatch修补.md](没有root怎么用LSPatch修补.md)。

## 第六步：整个模块用不了

作者在官方说明中写明：模块在 Android 10 到 16 的系统上测试通过，安卓版本过低或过高都可能不行；也可能还没适配你的设备或 CPU 架构。这种情况不用反复折腾，关注官方更新页等下一个版本即可。

## 第七步：更新之后反而不能用了

- 作者在更新记录里提到过一次发布事故，原因是类名缺失，表现是更新完模块直接失效。处理办法是重新下载该版本最新的包。
- 所以遇到「刚更新完就出问题」，先确认你装的是当前版本的最新安装包，再往下排查。

## 顺带：网页本身出问题时，先按 Via 官方的顺序过一遍

如果问题表现是「某个网页打不开、白屏、图文排版错乱」，通常不是模块的问题，而是这个页面与浏览器设置较劲。Via 官方给出的排查顺序是：

1. 关闭广告拦截：可能有规则错误拦掉了页面需要的资源。
2. 禁用用户脚本：脚本可能破坏了网页本身的功能。主页都打不开时，先怀疑脚本，并重启一次浏览器。
3. 把浏览器标识改回默认（见[浏览器标识和电脑模式怎么调.md](浏览器标识和电脑模式怎么调.md)）。
4. 确认允许网页运行 JavaScript。
5. 关掉这个站点的网站设定（地址栏左侧那个盾牌按钮里）。
6. 清一次缓存。
7. 以上都不行，再考虑重置浏览器——这一条会清数据，务必先导出备份。

其中前三步正好都是模块里能直接改的开关，排查起来会比在原生 Via 里快。

## 其他已知情况

| 现象 | 说明 |
| --- | --- |
| 一加机型上模块失效 | 作者在更新记录里提到过这个机型的问题，并做过针对性调整；遇到时先确认模块是最新版 |
| 用了二改包 | 除了触发完整性校验，还可能被判定为「模块不合法」，排查前先换回原包 |
| 官方渠道版本更高 | 网盘里那份是 1.1.0，已修复的 bug 通常只体现在更高版本上（见[下载与安装教程.md](下载与安装教程.md) 的核对部分） |
| 设置被锁定、弹窗点了没反应 | 关掉 Via 自带的实验模式。它是给开发者测试用的，会锁住一部分设置（例如电脑模式改不动），作者在更新记录里专门说明过这一点 |

## 反馈问题时带齐这几样

模块版本、Via 版本与包名、安卓版本与机型、错误代码、日志文件。前四项自己就能看，后两项按第四步取。信息齐了，作者定位起来会快很多。
