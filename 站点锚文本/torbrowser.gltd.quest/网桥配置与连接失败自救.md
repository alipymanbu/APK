# 网桥配置与连接失败自救：进度条卡住后的完整顺序

> 首次点「连接」后进度条长时间不动、反复报错，是这类浏览器最常见的坎。本篇按从易到难的顺序整理自救路径：看日志、换网络、配网桥、索取私有网桥。
> **相关文档**：[手机匿名浏览的实现原理.md](手机匿名浏览的实现原理.md) · [安全级别怎么选.md](安全级别怎么选.md)

## 一、先判断是哪种失败

点开 设置 → 连接 → Tor 日志（或连接页的「配置连接」），把日志翻到底，几类高频记录对应不同问题：

| 日志特征 | 含义 | 对策 |
| --- | --- | --- |
| 连不上第一跳（hop 0） | 所在网络拦了公开入口 | 配网桥，见下文第三节 |
| TLS 握手反复失败 | 加密握手被干扰 | 同上，配网桥 |
| 时钟偏差（clock skew） | 手机时间不准 | 开自动确定日期与时间后重连 |
| SOCKS 代理失败 | 代理设置填错 | 不用代理就删掉，用就核对地址端口 |

## 二、成本最低的两步先做

1. **换网络**：Wi-Fi 与手机流量走不同出口，一个被拦另一个未必；公司网与校园网常有额外限制。
2. **确认应用在内置存储**：移到 SD 卡是安卓版的已知故障源，装回内置存储就能恢复。

## 三、配网桥：三种内置传输

网桥是不列入公开目录的中继，配合可插拔传输使用，让拦截方不易认出流量。开启路径：设置 → 连接 → 配置网桥 → 打开「使用网桥」。

| 传输 | 流量看起来像 | 建议 |
| --- | --- | --- |
| obfs4 | 随机数据 | 第一选择 |
| meek-azure | 在访问微软网站 | 封锁较深时用，较慢 |
| snowflake | 在进行视频通话 | 临时应急，速度波动大 |

一个不行就换下一个，逐个切换是最直接的办法。

## 四、内置的不够用时：索取私有网桥

1. 应用内直接请求：配置网桥页点「请求网桥」，过一道验证码；
2. 邮件索取：用 Gmail 或 Riseup 邮箱给 bridges@torproject.org 发邮件，回信就是网桥行；
3. Telegram 机器人：联系 @GetBridgesBot 发送 /bridges。

拿到网桥行后回到「配置网桥」→「输入已知网桥」，整行粘贴，返回重连。填好后界面会显示一串表情符号，用来人工核对是不是同一个网桥——它只是标识，连接仍要完整地址。旧网桥可能下线，连不上就重新索取一批。

## 五、都试过了还是不行

- 核对版本：过旧版本可能因节点目录变更而连不上，更新到当前版本再试；
- 换设备时间与时区校准；
- 带上日志与版本号到 Tor 的支持论坛提问，别人才能帮你定位。

连上之后也别急着关掉这篇：遇到某个网站反复要验证码时，先用菜单里的「新线路」换出口重试——这是日常使用里最常见的另一类「连不上」。安装环节卡住的话，从[TorBrowser 介绍站的安装页](https://torbrowser.gltd.quest/)重新走一遍流程即可，安装与连接是两条不同的故障线。
