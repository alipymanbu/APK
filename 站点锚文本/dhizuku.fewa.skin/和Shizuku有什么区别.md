# Dhizuku 和 Shizuku 有什么区别

> 两个名字相近的权限工具到底差在哪：借出的身份、重启后的表现、激活门槛与配套生态，一张表讲清，再给怎么选的建议。
> **相关文章**：[设备所有者权限怎么激活](设备所有者权限怎么激活.md) · [免Root隐藏应用怎么实现](免Root隐藏应用怎么实现.md)

## 一、一句话概括

两者都是「让普通应用借到高权限」的中间件，设计思路一脉相承，但借出去的东西不同：**Shizuku 借的是 ADB（shell）权限，Dhizuku 借的是设备所有者（Device Owner）权限**。身份不同，激活门槛、重启后的表现、能配合的应用自然都不同。

## 二、对照表

| | Dhizuku | Shizuku |
| --- | --- | --- |
| 借出的身份 | 设备所有者（Device Owner） | ADB shell 权限 |
| 激活方式 | 一条 adb 命令，或应用内走 Shizuku | 无线调试 / 连电脑 / root 启动 |
| 重启之后 | 依然有效，不用重新激活 | 服务要重新启动（root 自启除外） |
| 激活前提 | 无账号、无第二用户、位置空闲 | 无这些限制 |
| 典型能力 | 隐藏、暂停应用这类设备管理操作 | 更广泛的系统与应用管理接口 |
| 配套应用数量 | 较少（需主动接入接口） | 很多（生态成熟） |
| 是否需要 Root | 不需要 | 不需要 |

## 三、怎么选

- **手机不能 Root，又不想每次重启都重新激活** → 先看要用的应用支不支持 Dhizuku 模式，支持就优先它；
- **要用的应用只提供 Shizuku 模式** → 直接用 Shizuku，这类场景下它的激活门槛反而更低；
- **两者可以并存**——它们是相互独立的两条授权通道，同一个应用用哪个模式就走哪条管道，互不干扰。

## 四、Dhizuku 的代价

设备所有者是 Android 里最高的管理身份，位置又只有一个，所以激活条件苛刻：必须先清空所有账号与第二用户，激活完成才能加回来（流程见[设备所有者权限怎么激活](设备所有者权限怎么激活.md)）。另外它的配套应用比 Shizuku 少——应用得主动接入 Dhizuku 接口才能借到权限，不是「接上 shell 就能用」的逻辑。

反过来说，这份身份是持久的：冻结类、隐藏类工具可以长期稳定工作，不必每次重启后补一遍授权。对「不想 Root、又想要一份长期不掉线的管理权限」的设备，这笔交换通常划算。

## 五、和直接 Root 比呢

Root 能做的事比设备所有者更多，两者不在同一层级。社区讨论里比较一致的看法是：设备已 Root 时它意义不大；它的价值在**不能 Root 的设备**——不改系统分区、不动 Bootloader，却能拿到隐藏、暂停这类管理能力。代价是身份绑定在这一个应用上，激活与撤销都比普通应用麻烦。
