# KernelSU LKM 与 GKI 安装模式怎么选

> 从 0.9.0 起，GKI 设备有两种运行模式：LKM 不替换原内核、GKI 整体替换。这篇按「手机优先」的思路讲两种模式的取舍、安装前必做的两件事和大致流程。
> **相关文档**：[设备支持与内核版本判断.md](设备支持与内核版本判断.md) · [与Magisk的区别和共存问题.md](与Magisk的区别和共存问题.md)

---

## 一、两种模式差在哪

装之前先想好用哪种，这决定日后的升级与 OTA 体验。核心区别一句话：LKM 是把 KernelSU 作为可加载模块挂进原内核，原内核不动；GKI 是用通用内核镜像把原内核整体换掉。

| | LKM 模式 | GKI 模式 |
| --- | --- | --- |
| 原内核 | 保留 | 完全替换 |
| 升级 | 多数操作在管理器内完成 | 每次都要重新刷 boot |
| OTA 后 | 装到另一槽位即可恢复 | 需重新刷入内核 |
| 临时退出 | 可卸载模块，部分场景无需重启 | 只能刷回原厂镜像 |
| 典型场景 | 手机日常使用 | 模拟器、WSA、Waydroid 等环境 |

手机用户没有特殊理由时，优先考虑 LKM：升级省事、退出干脆，第三方内核也能与它共存。有一个容易忽略的细节——LKM 修补的是 ramdisk，所以出厂 Android 13 及以上的设备，动的是 `init_boot` 分区而不是 `boot`。

## 二、动手前必做的两件事

安装绕不开刷写分区，这两件不是可选项：

1. **解锁 Bootloader**。没解锁就无法刷写 boot 分区，各品牌的解锁方式差异很大：有的要在专页申请并等待，有的只需在开发者选项里打开开关。
2. **备份原厂 boot.img（或 init_boot.img）**。这是整个流程里最重要的保险：刷错压缩格式、刷错版本导致无法开机时，只有刷回原厂镜像能救回来。备份来源通常是对应机型的原厂固件包，卡刷包可用 payload-dumper-go 之类的工具提取。

另外记住一条通用原则：刷机有变砖风险，动手前先做整机数据备份。

## 三、LKM 的大致流程

支持 `fastboot boot` 的设备走的是最短路径：

```sh
adb reboot bootloader
fastboot boot boot.img
```

临时启动不写入分区、重启即失效，成功后设备已有临时 root。此时打开管理器选「直接安装」，它会自动修补当前固件并刷入，同时把原厂镜像备份到 `/data/adb/ksu/` 目录，日后想退出就从卸载入口还原。重启后状态牌显示「工作中 <LKM>」即为成功。

不支持 `fastboot boot` 的设备，则需要先提取原厂镜像，交给管理器的「选择并修补一个文件」处理，再把修补产物用 `fastboot flash` 刷回对应分区。机型特殊、拿不准时，先走一次临时启动验证——失败不伤系统。

## 四、GKI 的大致流程

GKI 模式要先下载与设备 KMI、安全补丁级别、压缩格式都一致的通用内核镜像，然后：

```sh
adb reboot bootloader
fastboot flash boot boot.img
fastboot reboot
```

Pixel 这类 `lz4_legacy` 压缩的机型，直接刷通用镜像多半点不亮，需要用 magiskboot 手动解包、替换内核文件再打包；有第三方 Recovery 的设备也可以走 AnyKernel3 包刷入。成功后状态牌显示「工作中 <GKI>」。

无论哪种模式，开不了机时先别慌：音量键组合的安全模式能挡掉大多数模块类故障，实在不行刷回第二节备份的原厂镜像。模式选择的背景知识也可以先到 [KernelSU 安装与模式选择](https://kernelsu.bpfl.quest/) 过一遍再动手。装完想装模块、接 Zygisk，路径整理在 [与Magisk的区别和共存问题](与Magisk的区别和共存问题.md)。
