# KernelSU 设备支持与内核版本判断

> 判断一部手机能不能用 KernelSU，看的是 Linux 内核版本而不是 Android 版本——这篇讲清怎么看、怎么对，以及管理器三种状态各代表什么。
> **相关文档**：[LKM与GKI安装模式怎么选.md](LKM与GKI安装模式怎么选.md) · [与Magisk的区别和共存问题.md](与Magisk的区别和共存问题.md)

---

## 一、先看内核版本，别看 Android 版本

很多人打开「设置 → 关于手机」看到系统是 Android 13，就默认能装，结果管理器一开显示「不支持」。原因在于：内核版本一般跟设备**出厂时**的系统走，之后系统怎么 OTA，内核大版本通常不变。所以判断顺序永远是：先查内核版本，再谈支持与否。

查内核版本有两个顺手的位置：

- 「设置 → 关于手机」，部分系统直接列出内核版本；
- 装上管理器后，首页状态牌下方也会读出当前内核信息。

内核版本长这样：`5.10.101-android12-9-g30979850fc20`。从左往右读：`5.10.101` 是 Linux 内核版本，`android12` 是对应的 Android 代际，`9` 是 KMI 代数。凡是 `5.10` 及以上、走通用内核镜像（GKI）的设备，大概率开箱即用；`4.14` 及更旧的内核没有现成镜像，需要自行编译集成。

## 二、三种状态各代表什么

装好管理器打开，首页只会出现三种状态之一，每种对应完全不同的下一步：

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| 工作中 | 内核已生效，root 通道可用 | 看标注的运行模式，决定日后升级方式 |
| 未安装 | 设备在支持范围内，还没刷入 | 先解锁 Bootloader、备份原厂镜像，再走安装流程 |
| 不支持 | 没有现成可刷的内核 | 停下来，按下面的路径另找适配，别反复重试 |

「不支持」不是多试几次能改变的：管理器只对有现成镜像的设备报「未安装」。碰到「不支持」，常见出路按成本从低到高：查社区维护的非官方支持设备清单、自行编译内核并集成、或换更宽泛的社区分支版本。

首页状态牌下方还有几行常被引用的系统信息：内核版本、设备架构（如 aarch64）、ABI 支持列表、安全补丁级别与 SELinux 状态。发帖求助或核对适配时，先截图这几行。想看这套状态牌长什么样，可以到 [KernelSU 设备支持介绍](https://kernelsu.bpfl.quest/) 一览。

## 三、KMI 对版本的三条规则

确认要下载内核镜像时，按这三条对版本：

1. **KMI 必须一致**：`5.10-android12-9` 这样一组标识要逐字对上；SubLevel（`5.10.101` 与 `5.10.137`）不算在 KMI 里，可以互刷。
2. **安全补丁级别不能倒退**：不少新设备有防回滚机制，刷入补丁级别更老的镜像可能直接点不亮。KMI 一致的前提下，优先选补丁级别相同或更新的。
3. **压缩格式要对**：同一 KMI 下常有 lz4、gz、不压缩几种格式，选错无法开机。不确定就用 magiskboot 查原厂 boot 的压缩格式，或参考同机型用户的成功记录。

三条都对上了，再回到安装环节。模式怎么选（不替换内核的 LKM，还是整体替换的 GKI）、装之前要备份什么，见 [LKM与GKI安装模式怎么选](LKM与GKI安装模式怎么选.md)。

## 四、与既有 root 方案的关系

设备上已经有一套方案时，别急着叠加：KernelSU 与 Magisk 的 su 可以共存，但两者的模块挂载体系互斥，日常只能选一套跑模块。具体边界与常见误区整理在 [与Magisk的区别和共存问题](与Magisk的区别和共存问题.md)。
