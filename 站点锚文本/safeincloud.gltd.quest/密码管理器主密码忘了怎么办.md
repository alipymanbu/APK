# 密码管理器主密码忘了怎么办：以 SafeInCloud 为例的抢救思路

> 主密码是密码库的唯一钥匙。不少密码管理器（包括 SafeInCloud）不为主密码提供任何找回渠道——这是安全设计的直接后果。本篇按「还能不能进应用」梳理几条抢救路径，以及下次怎么避免走到这一步。

---

## 一、先接受一个前提

主密码不存在任何备份：设备上没有，开发者的服务器上也没有。忘记就是忘记，找客服也恢复不了。所以所有办法的目标都不是「找回密码」，而是「在彻底忘记之前抢救回数据」。

动手前先花几分钟把常用密码和变体都试一遍：大小写差异、多打的空格、旧密码、不同键盘布局。这是成本最低的一步，不少人卡在这里就解开了。

另外有一类「假忘记」：如果建过附加数据库（多库功能），它的密码通常会自动存成主库里的一张卡片——打开主库搜附加库的名字就能找到。丢主库密码的才是真麻烦，继续往下看。

## 二、还能用指纹 / 面部进应用 → 直接改密码

这是最省事的路径，前提是至少有一台设备还开着生物解锁：

1. 在锁屏界面故意输错主密码几次，应用会放行生物识别登录。
2. 进去后到设置里修改主密码。
3. 立刻触发一次云同步，让云端换成新密码版本。

其余设备还锁在旧密码上：逐台卸载 → 重装 → 首次启动选「从云恢复数据库」→ 用新密码进入，数据一点不丢。

## 三、刚改过密码、还记得旧的 → 用云的版本历史回滚

「忘了新密码、记得旧密码」时，可以把云端的数据库文件回滚到还用旧密码的版本：

1. 在浏览器打开你的云盘，找到密码库的数据库文件（SafeInCloud 的固定名字是 `SafeInCloud.db`）。
2. 右键该文件 → 版本历史记录 → 下载一个改密码**之前**的版本。
3. 重装应用，随便用个临时密码新建空库，再用恢复功能选中刚下载的文件。
4. 用旧密码登录；不行就再换更早的版本。

两个大坑先看再动手：iCloud 和 Google Drive 的应用专属文件夹通常不提供文件版本历史，存在这两处的走不了这条路；回滚前先把当前云端数据留着别删，失败还能退回来。

## 四、什么都不行 → 只能推倒重来

最后一步会永久清掉所有已存密码，确认前几条都走不通再做：删掉云端数据库文件 → 卸载重装 → 新建库设新密码 → 密码条目手动重录或从浏览器重新导入一次。

## 五、下次别再走到这一步

- **把主密码写在纸上**，放家里固定的地方。纸质备份不联网、不进云端。
- **至少在一台设备上开生物解锁**——它是唯一不依赖记忆的入口。
- **保持云同步开启**。数据只在本地的话，忘了主密码连「删掉重来保住数据」的机会都没有。
