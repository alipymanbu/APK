## 手机上测接口，实际是在测什么

后端联调和排障里，最常发的请求就两类：确认「接口活着没」和确认「返回对不对」。
手机上的测试工具把请求拆成几块可配置的部分，填完发出去，看状态码、响应时间和
返回内容。电脑上用调试软件做的事，在手机上是同一套逻辑。

## 一个请求拆开看，对应哪些配置

以一个常见的调试请求为例，各部分在 WebTools 的 HTTP 测试界面里都有对应位置：

| 请求的组成部分 | 界面里的位置 | 填什么 |
| --- | --- | --- |
| 目标主机 | 主机名或 IP 地址输入框 | 域名或 IP，不用自己拼协议头 |
| 方法 | 请求类型下拉 | 调试常用 GET，POST 也可选 |
| 跳转处理 | 跟随重定向开关 | 排查 CDN 和 301 场景时留意它的状态 |
| 鉴权 | 授权项 | 需要登录态的接口在这里补 |
| 自定义头 | HTTP 头字段 | 加 `Content-Type` 之类的附加说明 |

这个配置清单来自它的实际界面：请求类型、重定向、授权、头字段都是独立可调的，
不是「填个网址点一下」的简化版。

## 手机测试顺手在哪儿

- **快**：接口异常时，掏出手机几十秒就能确认是后端问题还是网络问题；
- **网络视角**：手机走的是蜂窝或另一路 Wi-Fi，和电脑的有线网络环境不同，
  「电脑上正常手机上不行」这类问题只有换端才能暴露；
- **和排障流程衔接**：测完接口发现要改配置，同一部手机里连上服务器就能动手。

这套衔接正是 WebTools 的组织思路——HTTP 测试、可达性、测速、SSH、FTP、
源码编辑器收进一个应用，从发现问题到处理问题一条线走完；介绍站里按真实
排障顺序把这条线讲了一遍，装之前可以先过一遍。
