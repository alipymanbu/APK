# 在手机上跑服务端项目的打包思路

把服务端项目装进手机，听起来像是要在设备上折腾终端环境。实际上 WebToApp 把这条路做成了可点的类型选项：Node.js、PHP、Python、Go 四种运行时以原生二进制的形式随应用存储分发，构建时直接 fork+exec 起真实进程，在本地端口提供服务。这和「网址转 App」是两类东西——它装出来的是能跑后端代码的应用。

## 三类项目各自的打包方式

**前端构建产物（React / Vue / Vite）**：选「前端」类型，把构建产物作为项目导入，应用会把它发布成 localhost 服务再呈现，等于给静态产物套上独立 App 的外壳。

**服务端运行时（Node.js / PHP / Python / Go）**：选对应语言类型导入项目。运行时二进制直接从应用存储执行，端口冲突由内置的端口管理处理（含冲突策略与真实停止处理器），并有 DNS 桥接让本地服务可被访问。

**便携 WordPress**：PHP 与 SQLite 都运行在设备上，整站随 APK 分发，适合做演示站、离线站点这类场景。

这些类型默认藏在类型网格之外，需要在应用「关于」页面打开「高级功能」开关后才出现——找不到入口时先检查这个开关。

## 配套的基础设施

- **Linux 环境**：Termux 风格的设备端环境，带构建和运行项目所需的工具链，适合在打包前先在手机上把项目调通。
- **加固网络栈**：DNS-over-HTTPS、TLS 指纹处理、加密客户端 Hello（ECH）、按应用代理，以及针对受限 SPA 的 CORS 处理，均内置于网络层。
- **应用修改器**：可以克隆已安装的 APK 并重打包、批量导入应用定义、导出模板，适合在多个项目间复用配置。

## 从打包到上架
