# 降低手机分辨率的利弊与恢复办法

> 本篇讲给安卓手机降分辨率、改 DPI 之前值得想清楚的收益与代价，以及改坏之后的完整恢复路线。
> **相关文档**：[安卓分辨率与DPI修改方法.md](安卓分辨率与DPI修改方法.md) · [Shizuku无线调试配对与授权.md](Shizuku无线调试配对与授权.md)

---

## 一、降分辨率能换来什么

渲染像素少了，GPU 与内存带宽的负担跟着轻：

- **流畅度**：游戏、滚动列表这类重渲染场景帧率更稳，老设备改善尤其明显；
- **续航**：屏幕点亮时的渲染功耗下降，重度使用场景下能多撑一段；
- **兼容性调试**：把整块屏幕临时切到某个特定数值，验证应用在低配设备或异形屏上的排版表现——这是开发者高频用法。

## 二、代价同样明摆着

- **清晰度**：像素密度低于原生后，字体和图标会发糊；降得越狠越明显；
- **比例失衡**：只降分辨率不动 DPI，界面元素会显得过大或过小，所以两者要按比例联动；
- **个别应用排错版**：极少数应用按硬编码尺寸布局，参数变了就错位，重启该应用通常能恢复；
- **全局生效**：改的是整块屏幕，桌面、状态栏、所有应用都受影响，验证完记得切回来。

一个通行参考：想省电或提帧率，把分辨率往原值的 70%~85% 方向调、DPI 跟着同比例降；宽度压到 400 以下时部分机型桌面会直接崩溃，别一步降到位。

## 三、第一道保险：10 秒自动撤销

用 [Screener](https://screener.fedq.ren/) 这类工具改参数时，应用之后 10 秒内没有任何操作，修改会自动退回应用前的状态。这是刻意设计的保命机制——应用了一个黑屏、花屏、没法再操作的数值时，把手拿开等 10 秒，多数情况屏幕自己就回来了。

反过来，屏幕显示正常的话，随手点一下屏幕就把这次修改固定下来。正确的节奏：**应用 → 看一眼 → 正常就确认，异常就等回退**。

## 四、救不回来时：ADB 两条命令

等了 10 秒没恢复、或者已经误点确认，用电脑 ADB 强制恢复（需要一台电脑 + 数据线）：

```bash
adb shell wm size reset
adb shell wm density reset
```

操作前提：

1. 电脑装好 ADB 工具（Google 提供的 platform-tools 就够用）；
2. 手机打开「USB 调试」并连接电脑，弹出授权提示时允许；
3. 在电脑终端依次执行上面两条命令；
4. 执行完屏幕参数即恢复系统默认值。

如果当初记下了原始分辨率，也可以用 `adb shell wm size 宽x高` 直接指回原值；没记也不要紧——执行 `adb shell wm size` 能读出硬件原始值（`Physical size` 那一行）。

## 五、两个事后注意事项

- **重启前先恢复默认**：带着覆盖值重启，部分设备可能出现布局错乱、触控错位、应用闪退（因设备而定）；建议养成「用完恢复、再重启」的习惯；
- **个别应用残留错版**：恢复分辨率后仍显示异常的应用，重启那个应用或重启设备即可。

参数层面的修改完全可逆，它不写系统文件、不动分区，不存在「变砖」一说——怕的只是屏幕异常时手忙脚乱反复叠加新参数。先等撤销、再上 ADB，两条路足够兜底。
