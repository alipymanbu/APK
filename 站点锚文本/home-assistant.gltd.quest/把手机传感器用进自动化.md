# 把手机传感器用进自动化

> 手机登录中枢后能上报哪些实体、哪些默认就有、哪些要手动开，以及两条能直接抄的自动化。**相关文档**：[手机端连接中枢的完整流程.md](手机端连接中枢的完整流程.md) · [通知与位置不生效的排查思路.md](通知与位置不生效的排查思路.md) · [桌面小部件与快捷磁贴怎么用.md](桌面小部件与快捷磁贴怎么用.md)

---

## 一、手机在这里是个随身传感器

除了当遥控器，安卓端还会把自身状态上报成中枢里的实体，自动化就能拿「人」的信号当触发条件。前提是连接与权限先就位（见[手机端连接中枢的完整流程.md](手机端连接中枢的完整流程.md)），否则大部分实体不会更新。

## 二、默认就有 vs 要手动开

登录并授权后，默认上报的是电量类：电量百分比、充电状态、充电方式，以及配对时点过「允许」的那些权限对应的传感器。

其余默认关闭，去 Settings → Companion App → Manage Sensors 逐个打开。常用的几类：

| 实体（示例 ID） | 内容 | 典型用途 |
| --- | --- | --- |
| `sensor.ssid` | 当前 Wi-Fi 名 | 判定人在哪个网络，代替不准的 GPS |
| `sensor.geocoded_location` | 由坐标反查的地址 | 展示与粗粒度判定 |
| `sensor.last_update_trigger` | 最近一次上报由什么触发 | 排查位置问题的入口 |
| `sensor.connection_type` | 蜂窝还是 Wi-Fi | 省流量自动化 |
| 步数 / 活动类 | 计步与活动状态 | 「走够一万步触发场景」类 |

数据只在你自己的中枢里存，分享哪些由你在手机上勾选，随时可关。上报节奏也有总控：Sensor Update Frequency 三档（Normal / 充电时加快 / 每分钟一次），档位越高越耗电，只开用得上的传感器才是好习惯。

## 三、权限给到什么程度，决定能玩什么

- 位置权限只给「仅使用期间」：前台还能定位，后台一概不报，设备跟踪实体基本躺平；
- 给「始终允许」（安卓 12 及以上还要精确定位）：后台位置、地理围栏、到家离家自动化才可用；
- 拒绝位置权限：位置与依赖位置的实体全部失效，电量、Wi-Fi 等其余传感器照常。只想要传感器、不要位置实体的，去中枢的实体注册表里禁用 `device_tracker` 就行，不用拒权限。

## 四、两条能直接抄的自动化

天黑回到家，玄关灯自己亮：

```yaml
trigger:
  - platform: state
    entity_id: device_tracker.你的设备名
    to: "home"
condition:
  - condition: sun
    after: sunset
action:
  - service: light.turn_on
    target:
      entity_id: light.玄关灯
```

手机插上充电器，全屋进夜间模式：

```yaml
trigger:
  - platform: state
    entity_id: sensor.你的设备名_battery_state
    to: "Charging"
action:
  - service: scene.turn_on
    target:
      entity_id: scene.夜间
```

实体 ID 里的设备名以配对时起的名字为准，可在中枢的集成面板 → Mobile App 里查看和改名（保留 `sensor.` / `device_tracker.` 前缀）。

## 五、几条边界，先知道能省事

- 多台手机连同一个中枢时，传感器名字很像，配对时就起能区分的名字；
- 每多开一个传感器，后台上报就多一路，只开用得上的；
- 手机换机或重装后，清掉旧设备条目再配对，否则 person 实体会挂着一台永远不动的设备。
