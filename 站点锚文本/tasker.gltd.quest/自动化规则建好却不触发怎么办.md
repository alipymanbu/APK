# 自动化规则建好却不触发怎么办

> 规则界面看起来一切正常，条件成立了却没动静——按「开关 → 条件 → 权限 → 后台」四层从外到内查，比逐项乱改设置快得多。
> **相关文档**：[安卓自动化怎么入门.md](安卓自动化怎么入门.md) · [到家自动静音这类场景怎么搭.md](到家自动静音这类场景怎么搭.md)

「没反应」是自动化工具最笼统的抱怨，底下可能是完全不同的几种原因。别急着改设置——先按本文的固定顺序逐层确认，每一层都能用眼睛直接验证。

## 一、第一层：开关真的开了吗

两个开关都要看：工具本体处于启用状态（主界面和常驻通知都能确认它活着），以及**这一条**规则没有被禁用——被禁用的规则在列表里看起来和正常规则一模一样，只差名字前面的一个小勾。

## 二、第二层：条件此刻成立吗

手动把场景造出来：该连 Wifi 的连上、该到的时间段调进去，看规则名字有没有变成激活状态。没变绿说明条件根本没被感知到——这一层还能揪出一类常见笔误：Wifi 名称大小写写错、时间区间跨零点写反、位置半径画得太小导致人在边界上反复进出。

顺带分清两种「看起来没反应」的正常现象：带「事件」类条件的规则是瞬发即执行的，没有「保持激活」的状态可言；「靠近 Wifi」判定离开本来就慢，等几分钟不算故障。

## 三、第三层：权限给全了吗

这是头号原因。界面都能点、规则也写了，但对应的权限没授权，动作自然执行不了。重点核对这几项：

| 权限 | 缺了它坏什么 |
| --- | --- |
| 无障碍服务 | 应用类条件失灵、界面交互类操作报错 |
| 通知访问 | 通知相关动作直接报权限错误 |
| 位置（含后台） | 位置类规则不触发 |
| 附近的 Wifi 设备 | Wifi 类条件失效 |

无障碍和通知访问最容易被系统在更新后「自己关掉」，用了一阵子突然全不灵时，先回来重开这两项。

## 四、第四层：后台被清了吗

亮屏一切正常、锁屏就不跑，基本锁定在这一层。三步处理：把工具加入电池优化白名单（原生安卓在「设置 → 应用 → 电池优化」里改）；在自启动管理里放行；卸载或停用「省电 / 冻结 / 自动清理」类第三方工具——它们会把自动化工具一起清掉。

验证方式很直接：锁屏放两分钟，再触发一次同样的条件。能过这一关，日常使用就稳了；定时任务「总是晚几分钟」单独记一条——检查应用内「可靠闹钟」的设置，选「从不」会被系统合并延后，这是开发者文档里明确指出的最常见原因。

## 五、还不行就看运行日志

以上四层都过了还找不到原因，就让工具自己说话：打开运行日志复现一次，看有没有触发记录（没有 = 卡在条件或后台）、哪条操作标红（直接定位问题动作）、触发时间戳和预期差多少（判断定时是否被延后）。日志定位到具体动作后再回权限层核对，通常一轮就能收口。

排查工具的选择与基本概念，见 [安卓自动化怎么入门.md](安卓自动化怎么入门.md)；规则还没搭起来的，[到家自动静音这类场景怎么搭.md](到家自动静音这类场景怎么搭.md) 里有四个可以直接照抄的结构。本文以 [Tasker](https://tasker.gltd.quest/) 的排查口径为例整理，同类规则引擎工具思路通用。
