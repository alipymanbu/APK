# 安卓端 Godot 引擎版本怎么选

> 3.x 还是 4.x、正式版还是带宽限制下的旧版、GDScript 还是 C#——手机上选引擎版本的三个判断依据。

应用里的引擎列表动辄十几个版本，第一次选容易犯选择困难。其实判断依据就三条：工程适配、脚本语言、设备性能。

## 一、老工程跟着原版本走

接手的工程原本用什么版本，就切到什么版本打开。Godot 3.x 与 4.x 的工程格式互不兼容，硬用高版本打开低版本工程会触发大量资源重导与脚本报错。安卓端的管理应用（如 GodotHub）支持多版本并存，给工程配对的引擎版本在项目详情里切换即可，互不干扰。

## 二、新项目选 4.x 最新稳定版

新开项目直接选 4.x 的最新稳定版，理由很直接：

- 插件、模板、教程这些社区资源的新产出一律优先适配 4.x；
- 3.x 已进入维护节奏，新特性不再加；
- 手机上从 3.x 迁移到 4.x 的成本比桌面端更高（触屏改配置不方便）。

## 三、GDScript 还是 C#

安卓编辑器**不含 C# 支持**，这是上游明说的限制。手机上写 GDScript 没有问题；工程用 C# / .NET 开发的，回桌面端处理，安卓端只当预览与轻量修改的工具。

## 四、正式版之间的差一代怎么挑

列表里相邻正式版（比如 4.6.3 与 4.6.2）差的是缺陷修复与小功能，跟教程学的版本差一代以内都不影响跟做；真正要避开的是带 beta / dev 字样的开发版——除非刻意要试新特性，日常开发不碰。

## 五、装错了怎么撤

多版本并存意味着装错不用卸整个应用：引擎页里把不用的版本卸载、顺手清缓存，再下目标版本就行。磁盘紧张时优先删旧的大体积版本。

选好版本装上，就可以建工程开工了；从装应用到装引擎的完整顺序，见[手机上做Godot游戏要装哪些东西](手机上做Godot游戏要装哪些东西.md)。工程的实操层面，这篇[手机开发工作台介绍](https://godothub.qjxz.skin/)里也有整理。
