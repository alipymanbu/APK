# 网页打包成安卓应用要装什么环境

> 打包网页成安卓应用，最劝退的从来不是代码量，是环境。本篇把"要装什么"这笔账摊开算：传统本地编译要装哪几样、每样占多少空间，以及把编译挪走之后，事情可以简化到什么程度。

## 一、传统路线的环境清单

自己从源码编译一个安卓客户端，通常要在电脑上备齐这几样：

| 要装的东西 | 用途 | 体积感受 |
| --- | --- | --- |
| JDK + Android Studio | 编译安卓工程、跑模拟器 | 十几 GB 起步 |
| Node.js + npm | 构建前端工程、跑打包脚手架 | 数 GB（含全局缓存） |
| Rust 工具链 | 编译基于 Tauri 的壳工程 | 数 GB，版本敏感 |

清单里的每一项单看都不难装，麻烦的是版本组合：Node 版本旧了脚手架起不来，Rust 工具链更新后编译参数变了，Android Studio 的 SDK 路径配错一项就卡半天。换一台电脑，这些坑大概率要重踩一遍。

## 二、把编译挪到云端：只要一个 Token

基于 Tauri2 的开源打包工具 PakePlus 走的是另一条路：本机只负责填配置，编译交给云端的持续集成去做。你需要的全部东西是一枚 GitHub Token，登录后提交配置，云端开始编译，完成后取回各平台安装包。

这种做法的几点实际意义：

- **硬盘账**：几十 GB 的开发环境变成零；打包工具本身也只有 10M 左右。
- **多平台**：一次配置，Windows、macOS、Linux、Android、iOS 的安装包可以同时开做，不用逐个平台伺候环境。
- **安全边界**：Token 只存在本机，项目放在你自己的仓库里，不经过第三方服务器。

环境之外的产物账也顺带说一句：按项目公开文档的口径，打出的安装包小于 5M，比 Electron 包小约 20 倍。你可以在 [PakePlus 打包工具介绍](https://pakeplus.yoan.quest/) 里看到这些数字的完整出处与两条路线的展开。

## 三、连 Token 都不想碰：本地直出

如果只是想快点拿到一个 APK，还有一条更短的本地路线：不登录任何账号、不装任何依赖，把网址或 dist 目录丢进去，本机直接完成打包，参考用时约 30 秒，对文件数量和大小没有限制。

两条路线怎么分工，本套文档里另有一篇专门对比：[云端打包和本地打包怎么选.md](云端打包和本地打包怎么选.md)。

## 四、一个容易忽略的前提

环境可以省，预期不能错：这类打包工具不做软件签名，产物按项目说明仅限自己使用。也就是说，它适合"给自己或特定的人装一个能用的客户端"，不适合当作上架分发渠道来规划。
