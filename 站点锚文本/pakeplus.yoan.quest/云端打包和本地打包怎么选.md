# 云端打包和本地打包怎么选

> 以 PakePlus 为例讲打包路线的取舍：云端一条（Token + 云端编译，一次出多平台安装包）、本地一条（免账号免依赖，约 30 秒直出）。本篇把两条路线逐项摆在一起，帮你按手头的情况选。
> **相关文档**：[不写代码把网站变成手机应用的方法.md](不写代码把网站变成手机应用的方法.md) · [网页打包成安卓应用要装什么环境.md](网页打包成安卓应用要装什么环境.md)

---

## 一、两条路线逐项对比

| 对比项 | 云端打包 | 本地打包 |
| --- | --- | --- |
| 前置条件 | 登录 GitHub 或填入 Token | 不需要任何账号 |
| 本机依赖 | 不装复杂依赖环境 | 不装任何依赖 |
| 编译发生地 | 云端持续集成 | 本机直接完成 |
| 参考用时 | 几分钟（视平台数） | 约 30 秒 |
| 一次能出什么 | 多平台安装包同时编译 | 先拿到手头这一份 |
| 文件数量与大小 | 随仓库走 | 不限制 |
| 适合谁 | 想一次覆盖桌面 + 手机多端 | 只想快点拿到一个 APK |

## 二、什么时候选云端

- 你要的不是一个平台：Windows、macOS、Linux 桌面安装包与安卓、iOS 移动端想一次开做，云端一次配置全部覆盖。
- 你想把配置沉淀在仓库里：项目放在你自己的 GitHub 仓库中，Token 只存本机，下次打包接着用。
- 你不在乎等几分钟编译：配置提交之后人就可以走开，包好了去取即可。

## 三、什么时候选本地

- 你只有一个立刻要验证的念头：填个网址，约 30 秒出包，先装上手机看看效果。
- 你不想碰任何账号：没有 Token 也能走完整个流程，这对"就打一个自己用的包"的场景足够了。
- 你要打包的东西很多：本地路线对文件数量和大小没有限制，批量场景不受约束。

## 四、两条路线不是单选题

先本地打一个包验证想法，等确定要发多平台了再配 Token 走云端——这是很常见的推进方式，两条路线随时可以换着用，配置是同一套。工具本身的定位、体积数据与两条路线的出处，在 [PakePlus 介绍站](https://pakeplus.yoan.quest/) 有更完整的整理。

## 五、选之前最后看一眼的注意事项

无论走哪条路线，有两点是共同的：其一，工具不做软件签名，打包结果按项目说明仅限自己使用；其二，桌面版与安卓版是两套独立安装包，版本号各自独立，别拿一端的包去另一端装。
