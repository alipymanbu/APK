# 手机照片自动备份到自己的服务器

手机用得越久，相册越庞大，而"备份"这件事大多数人只做到一半：开了某个云相册的自动上传，就以为万事大吉。真到换手机、清理存储空间、想找三年前某张照片的时候，问题才一个个冒出来——云端压缩了原图、免费空间满了、或者干脆记不清当时传到了哪。

这篇文章介绍另一种思路：用 **Immich** 把照片自动备份到一台属于自己的服务器上。

## 为什么"放到自己手里"值得多花一步

把照片交给公有云相册，方便是真方便，代价也真实存在：

- 原图常常被压缩，几十年后想回看原始画质已经不可能；
- 存储空间按月付费，照片越多支出越高；
- 照片是最私人的数据之一，存在哪、被谁分析，自己说了不算。

自托管方案把这三件事都翻转过来：原图按原样存放、没有按张计费的空间焦虑、数据物理上就在自己家的 NAS 或自己的云主机里。代价是前期要花一次部署功夫，并且手机端要配一次服务器地址。

## Immich 的备份链路长什么样

Immich 是一个开源的照片与视频自托管管理方案，在 GitHub 上的星标数长期位居同类项目前列。它的核心链路可以概括成一句话：**手机自动上传 → 自己的服务器保存 → 手机和电脑随时浏览、检索**。

落到手机端，日常使用就是这样的体验：

1. 部署好服务器端之后，手机上装客户端、填服务器链接地址、登录；
2. 进入「备份」设置，勾选希望备份的相册；
3. 之后拍了新照片，后台会自动把它们送回服务器，不需要任何手动操作。

## 几个让备份更省心的细节

Immich 的备份设置把很多"别人家不给你选"的事情摊开了：

- **网络要求分开控制**：照片和视频可以分别决定要不要用流量上传，默认只在 Wi-Fi 环境下工作；
- **充电时才执行**：后台任务可以设定为只在设备充电时运行，还能设置延迟，兼顾省电和及时性；
- **内容校验去重**：上传前会逐个文件计算校验值，和服务器上已有的内容比对，重复内容直接跳过——换手机、重装应用都不会把整个库重传一遍；
- **相册结构镜像**：开启相册同步后，手机里的相册组织会在服务器上原样复现，找起来和手机上一样顺手。

## 一个必须说在前面的前提

Immich 手机端是一个客户端，它不能独立工作——首次打开要求填写「服务器链接地址」。也就是说，先要有一套跑起来的 Immich 服务器端（家里的 NAS、一台闲置电脑或一台云主机都可以），手机端的备份功能才有用武之地。如果还没有服务器，建议先从服务器端的部署文档读起。

另外，项目自身也明确提醒：备份进 Immich 不等于完整的容灾方案，重要照片建议同时遵守「三份副本、两种介质、一份异地」的 3-2-1 原则。
