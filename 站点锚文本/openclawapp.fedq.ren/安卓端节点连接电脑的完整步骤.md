# 安卓端节点连接电脑的完整步骤

> 本篇讲 openclawapp 怎么连上电脑端的 Gateway：连接前的三件事、三种连接方式怎么选、设备批准与后台保活，以及连不上时的排查顺序。
> **相关文档**：[手机端功能与权限授权详解.md](手机端功能与权限授权详解.md)

## 先弄清一个前提

openclawapp 是「伴生节点」：它本身不运行助手，真正的助手跑在电脑的 Gateway 里。所以连接的前提是电脑端已经就绪——`openclaw gateway status` 显示监听 18789 端口，才算有东西可连。还没部署电脑端的，先去 [openclawapp 介绍站](https://openclawapp.fedq.ren/) 看功能总览与资源入口，把电脑端装好再回来。

## 连接前确认三件事

1. 电脑端 Gateway 正在运行，端口 18789 在监听；
2. 手机与电脑网络互通：同一局域网，或用 Tailscale 这类组网工具打通；
3. 手机上已装好 app（安装包入口见上方介绍站，文件 openclawapp_v10.0.apk，约 6.7 MB）。

## 三种连接方式，按场景选

| 方式 | 适用场景 | 怎么做 |
|---|---|---|
| 自动发现 | 手机和电脑同一局域网 | Settings 的 Discovered Gateways 里选中网关直接连 |
| Setup Code / 二维码 | 组网后跨网段，最省事 | 电脑端 `openclaw qr` 生成，app 里扫码或粘贴 |
| 手动填写 | 自动发现被路由器 AP 隔离挡住 | Advanced controls 里填主机 + 端口（默认 18789） |

私有网段地址用 `ws://` 协议填；跨网络远程访问建议走 Tailscale Serve 这类提供 `wss://` 加密的路线，不要把 18789 端口直接暴露到公网。

## 在电脑端批准这台设备

首次连接会在 Gateway 侧生成一条设备配对请求，批准了才生效：

```bash
openclaw devices list
openclaw devices approve <requestId>
openclaw nodes status    # 确认手机节点已连上
```

批准之后，app 以后启动会自动重连上次的 Gateway（手动填过端点的优先用手动端点），不用每次重新配。

## 连接保持与离线行为

app 靠一条前台服务维持连接，通知栏的常驻通知就是它的保活方式。离开前台后部分安卓系统会暂停次要连接，回到 app 自动恢复。断网时发出的消息按 Gateway 分开排队，重连后按顺序送达，不会丢。各家安卓的后台策略不同，频繁掉线就把 app 加进电池白名单、允许自启动。

## 连不上时的排查顺序

自动发现失败 → 先确认两端同一网段（访客网络、AP 隔离都会挡）→ 改手动填电脑 IP + 18789 → 跨网络就让两端进同一 Tailscale 网络再连。扫了 Setup Code 没反应的，多半是配对请求还没在电脑端批准——回到上一节把最新那条请求批掉。手机端各功能与权限的取舍原则，见 [手机端功能与权限授权详解.md](手机端功能与权限授权详解.md)。
