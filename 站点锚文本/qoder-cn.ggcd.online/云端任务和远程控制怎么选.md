# 云端任务和远程控制怎么选

> Qoder CN 手机端管 AI 编程任务有两条路：把任务丢到云端环境跑，或者远程控制自己电脑上的会话。两条路各有适用场景，这篇讲清楚怎么选、以及各自的边界。
> **相关文档**：[手机上审批AI编程任务的工作流.md](手机上审批AI编程任务的工作流.md) · [通义灵码手机版现在叫什么.md](通义灵码手机版现在叫什么.md)

## 一、先看两条路的本质区别

**远程控制**：任务还是跑在你自己的电脑上，手机只是「远程方向盘」。电脑端会话持续运行、状态实时同步到手机，你看进度、做审批、补指令，最终产物全部落在本地机器。

**云端任务**：任务被委派到云端环境执行，连接 GitHub 仓库或你的工作区之后，**关掉电脑任务照样推进**，代码不落在本地设备，完成后在手机上直接验收产物和代码 Diff。

一句话概括：远程控制是「人走了，电脑替你守着」；云端任务是「电脑也可以关了」。

## 二、什么情况选云端

- 任务要跑很久，而你的笔记本没法一直开机挂在那里；
- 出差、通勤途中想派活，身边根本没有开发机；
- 代码放在 GitHub 仓库或团队工作区里，本机不留副本反而更干净；
- 担心本地环境被长任务占满——编译、跑测试都在云端完成。

## 三、什么情况选远程控制

- 代码和环境强绑定在本地（没推到远端仓库、依赖本地数据库或特殊硬件）；
- 需要持续盯本地会话的实时输出，随时插话调整方向；
- 安全或合规上要求产物只存在于本地机器。

用 Qoder CN CLI 的开发者还有个中间形态：**守护模式**。在项目目录跑 `qoderclicn remote-control`，让 CLI 挂成后台守护进程，不开会话也能随时从手机派新任务过去；已有会话想在离开后继续盯，则在会话里输入 `/remote-control` 开启远程监听。注意无论哪种，电脑本身都得保持开机——这是它与云端任务最根本的差别。

## 四、两者混用也很自然

实际用起来不必二选一：手头赶工的任务留在本地开远程控制，人盯着心里踏实；背景里的重构、批量改造这类不急的活，丢到云端慢慢跑。任务列表里两者会带不同的来源标签，一眼能分清哪个在本地电脑、哪个在云端沙箱。
