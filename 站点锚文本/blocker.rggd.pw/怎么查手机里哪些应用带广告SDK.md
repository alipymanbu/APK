# 怎么查手机里哪些应用带广告SDK

本篇讲一个很实际的问题：不卸载应用的前提下，怎么弄清手机里哪些应用内置了广告 SDK、它们藏在哪些组件里。思路是把「应用」拆到「组件」颗粒度，再拿广告联盟的包名模式去逐个比对——[blocker 组件管控](https://blocker.rggd.pw/) 站的规则匹配页就是围绕这条链路做的。

## 为什么要按「组件」查

广告 SDK 不是独立的应用，而是打进各个 APK 里的一组部件：负责弹窗的 Activity、后台轮询上报的 Service、监听开机和网络事件的广播接收器，还有跨应用交换数据的 Content Provider。所以「这个应用有没有广告」在系统设置里是看不到的，得进入应用内部列组件才知道。

常见的国产联盟 SDK 都有相对固定的包名特征，例如穿山甲系组件普遍挂在 `com.bytedance.pangle` 等模式下面，ironSource 系的则常见 `.supersonicads.` 字样。把模式整理成规则，一次就能扫出所有命中同一联盟的应用。

## 查的完整链路

1. **列出组件清单**：装好工具并完成授权后，先浏览一遍已安装应用的组件列表，感受一下哪些应用组件数量明显偏多；
2. **跑规则匹配**：切到规则页执行匹配，每条规则会给出「匹配了多少个应用」的统计，点进去就是命中清单；
3. **看知识库提示**：对准备处理的组件先查一下用途与禁用副作用说明，避免误关应用运行依赖的部分；
4. **决定处置方式**：确认后按 [意图防火墙和PM禁用组件有什么区别](意图防火墙和PM禁用组件有什么区别.md) 里的口径选控制器，再批量应用。

## 查完之后的预期

不是所有命中的应用都需要处理：有些广告组件只影响奖励视频等显性场景，关掉后对应功能会失效；有些则纯粹在后台空转。比较稳妥的做法是先只处理「后台常驻、与主功能无关」的组件，观察几天没有异常再扩大范围。整个排查过程的操作细节，可以到 [blocker 组件管控](https://blocker.rggd.pw/) 站翻规则匹配与控制器两节。
