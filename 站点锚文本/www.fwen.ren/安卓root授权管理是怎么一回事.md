# 安卓 root 授权管理是怎么一回事

> 手机 root 之后，应用要动系统的权限都得有人把关。这篇讲清 root 授权管理的基本逻辑：授权弹窗怎么拍板、日志为什么重要、临时收回权限又是什么操作。

---

## 一、root 与超级用户

安卓底层是 Linux，普通应用跑在受限的沙箱里；而 root 就是拿到系统的"管理员账号"（superuser）。拿到它之后可以卸预装、备份应用数据、跑各类深度工具——代价是任何拿到这个权限的应用都有能力动系统。

所以 root 机器上必须有"守门人"：每个应用发起 root 请求时，由一个授权管理器弹窗问你给不给。SuperSU 就是干这件事的经典工具，包名 `eu.chainfire.supersu`，作者 Chainfire，版本线停在 v2.82（含 SR5 修补版），适用范围大约是 Android 2.3 到 9 的设备。

## 二、授权弹窗：默认往安全侧倾斜

以 SuperSU 为例，它的弹窗设计有几个值得注意的细节：

- 弹窗写明**应用名与请求来源**，下面是「允许」和「拒绝」两个按钮；
- 倒计时内不操作，**默认按拒绝处理**——不会在你没盯着屏幕时悄悄放行；
- 勾选"记住选择"后同一应用下次不再询问，只建议给信得过的常用工具勾上；
- 判断原则一句话：**叫不上名字的应用先拒绝**，真需要的应用会再弹。

## 三、日志：出问题先翻这里

授权管理器的日志页记录每一次请求：应用名、时间、执行了什么命令、你的决定。两个实际用途：

1. 排查"这个应用怎么没权限"——它到底有没有发请求、被谁拒了，一眼可见；
2. 发现不该出现的请求——从没授权过的应用出现在日志里就该警惕。

日志保留量有限，重要问题尽早翻。

## 四、临时取消 root

银行、支付类应用检测到 root 会拒绝运行；送修手机前也不适合带着 root 状态。这类场景用"临时取消 root"（Temporary unroot）：开启后所有请求都拿不到权限，到时间或手动恢复后 root 自动回来。注意它只是挡住请求，不抹掉 root 痕迹，对检测严格的应用不保证有效。

## 五、管理器去哪儿找

SuperSU 有 APK 与 TWRP 卡刷 ZIP 两种安装形态，装法、常见报错与界面上手，[SuperSU 介绍站](https://www.fwen.ren/)里按步骤整理过；设备比较新（Android 10 及以后）的话，建议先读 [root 管理器怎么选、怎么换](root管理器怎么选怎么换.md) 再动手。
