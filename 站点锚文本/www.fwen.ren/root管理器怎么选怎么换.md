# root 管理器怎么选、怎么换

> SuperSU 与 Magisk 不是竞品，更像前后两个时代的接力。这篇把两代方案摆在一起对比，给出选择依据，以及从旧换新的正确顺序。

---

## 一句话结论

**老设备、老 ROM、跟着老教程走 → SuperSU 依然好用；Android 8/10 以后的新设备、要 OTA、要模块 → 直接 Magisk。**

## 差异速览

| 维度 | SuperSU | Magisk |
| --- | --- | --- |
| 开发状态 | 2017 年停更（v2.82 / SR5 为最后版本），2018 年从 Google Play 下架 | 持续活跃维护 |
| 开源情况 | 闭源 | 开源 |
| 作者 | Chainfire（后转手 CCMT） | topjohnwu |
| 安装方式 | TWRP 卡刷 ZIP，或已 root 设备直接装 APK | 应用内修补 boot 镜像，再 fastboot 刷入 |
| 对系统的改动 | 系统层植入 su（新版支持 systemless 模式） | systemless：不动系统分区，只改 boot |
| OTA 系统更新 | 多数情况要先取消 root 再更新 | 可保留（更新前还原、更新后再注入） |
| 模块生态 | 无 | 有，大量功能靠模块扩展 |
| 适合的系统版本 | 约 Android 2.3 ~ 9 | 约 Android 6.0 起新老通吃 |

## 什么情况 SuperSU 仍是合理选择

- **老机型、老 ROM**：系统停在 Android 7/8 的设备，TWRP + ZIP 的流程成熟、教程遍地；
- **照着老教程做**：不少机型论坛的刷机教程就是按它写的，照做最不容易出岔子；
- **对 root 需求很轻**：只是偶尔卸个预装、备份应用数据，用不上模块生态。

它的两种安装形态与获取入口，见 [SuperSU 介绍站](https://www.fwen.ren/)；授权弹窗、日志、临时取消这些日常操作，整理在 [安卓 root 授权管理是怎么一回事](安卓root授权管理是怎么一回事.md)。

## 什么情况直接上 Magisk

- **Android 10 及以后**的设备，SuperSU 基本没有支持保障；
- **银行、支付类应用**是刚需——root 检测的应对是 Magisk 的强项；
- **要正常跟 OTA 更新**，不想每次更新都重刷一遍；
- **需要模块**（去广告、音效、字体这类系统级改造）。

## 从旧换新的正确顺序

两套方案不共存——su 二进制和 Magisk 互相打架会出现中间态，务必先清旧的、再装新的：

1. 在 SuperSU 里执行 **Full unroot**，重启确认 root 已清干净；
2. 装好 Magisk 应用，按它的流程修补当前系统的 boot 镜像并刷入；
3. 重启后在 Magisk 里确认"已安装"，之前管理的 root 应用重新走一遍授权。

顺序颠倒的典型症状：一边残留失效的 su，一边 Magisk 报安装异常，最后往往要重刷系统收场。
