# 双向同步和单向备份怎么选

> 本篇只讲清楚一件事：GoodSync 里的 Backup（单向备份）和 Synchronize（双向同步）到底差在哪、删除动作怎么处理、什么场景该用哪个。具体场景的实操，见[手机照片备份到电脑的完整流程](手机照片备份到电脑的完整流程.md)；装好之后的首次配置，见[安卓版安装与电脑配对方法](安卓版安装与电脑配对方法.md)。

---

## 一句话分清

- **单向备份（Backup）**：文件只从一侧流向另一侧，目标端永远朝源端对齐。用途是「留后路」。
- **双向同步（Synchronize）**：两侧互相补齐，哪边变了都跟到另一边。用途是「两台设备用同一份工作目录」。

建任务时选哪个，取决于数据的「唯一权威副本」在哪。照片、工程文件这类只在手机上产生的内容，权威副本在手机，备份到电脑用单向就够了；两台电脑都在写的工作文档，两边都是权威，才需要双向。

## 删除是关键差异

两种模式对「删除」的处理，比复制方向更值得关心：

1. **单向备份**：源端删了，目标端默认也删——这样目标端才和源端一致，但误删会一起丢。重要的内容把「传播删除」关掉，代价是目标端会积累已删除的冗余文件。
2. **双向同步**：删除默认在两侧都生效，因为这是「保持两边一样」的语义。同样可以关闭，但关掉之后，一边删掉的文件会在下次同步时从另一边被补回来——这是双向同步的正常行为，不是出错。

GoodSync 在执行前会先分析出逐文件清单：新增、修改、删除分开列出，方向一目了然。拿不准删除策略时，先跑一次分析看清单再决定，比装完就全自动跑要稳妥。

## 两种模式对应的典型场景

| 场景 | 建议 |
| --- | --- |
| 手机相册 → 电脑 / NAS 归档 | 单向备份，关「传播删除」 |
| 电脑工作目录 ↔ 笔记本 | 双向同步，保留删除传播 |
| 手机文档 ↔ 电脑文档（两边都改） | 双向同步 |
| 大文件冷备份到移动硬盘 | 单向备份 + 接入即动（On Connect） |
| 项目目录实时跟到另一台机器 | 双向同步 + 文件变化即动（On File Change） |

## 别把同步当备份

反向的坑也存在：把「唯一一份」数据放在双向同步链里当备份用，一旦误删且删除传播开着，两边一起丢。稳妥的做法是链式组合——两台设备之间双向同步，再从其中一台单向备份到外部硬盘或网盘，两层各司其职。
