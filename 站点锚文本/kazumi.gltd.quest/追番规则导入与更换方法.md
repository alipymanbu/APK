# 追番规则导入与更换方法

> 这篇讲开源追番应用 Kazumi 最核心的机制——「规则」：第一次用怎么导入、搜不到东西时怎么换、想自己写从哪起步。
> **相关文章**：[番剧时间表与追番管理](番剧时间表与追番管理.md) · [弹幕超分与播放设置](弹幕超分与播放设置.md)

## 规则是什么，为什么刚装好是空的

Kazumi 本身不提供任何视频内容，它是一个播放容器：你搜到的每一部番、每一条线路，都来自「规则」对接的外部资源站。所以刚装完打开，首页空空荡荡不是故障——还没有规则，链路就不通。

一条规则负责两件事：按关键词返回作品列表，再按你选中的作品返回播放线路和剧集。某个资源站改版导致看不了时，换一条规则就能恢复，不需要等应用更新——这是规则机制最大的好处。

## 怎么导入一条规则

入口在应用里：`我的` → `规则管理`（部分版本叫规则设置）。点右上角的添加按钮，常见有四种方式：

| 方式 | 适用场景 |
| --- | --- |
| 从规则仓库添加 | 最省事。列表里挑一条，点安装即可，客户端自动拉取 |
| 从剪贴板添加 | 别人发来一段规则文本，复制后直接粘贴导入 |
| 从 JSON 文件添加 | 手上有 `.json` 规则文件时 |
| 新建规则 | 自己动手写，见下文 |

导入完成后，在列表里启用它，回到首页搜索番名验证：能出结果，说明链路通了。

## 搜不到、播不了怎么办

按成本从低到高排查：

1. **先换线路**：能搜到但这一条线路播不了，在播放页切换其他线路，一条规则往往对应多条线路；
2. **再换规则**：多备几条覆盖同类站点的规则，哪条活着用哪条，规则可以并存也可以随时停用；
3. **更新规则**：从规则仓库重新拉一次同名规则，覆盖旧版；
4. 以上都无效，再怀疑网络或软件本身。

日常建议：不要只留一条规则。资源站改版是常态，手里有备用规则，出问题就是一次点击的事。

## 想自己写规则的话

规则分两种类型，搜索和选集可以各自独立选型：XPath 规则请求网页用选择器定位，适合服务端直接输出 HTML 的站点；API 规则直接请求 JSON 接口，适合前端靠接口加载的站点。新手起步记三条硬约束：

- XPath 选择器目前只支持以 `//` 开头的写法，其他开头写法不生效；
- 搜索地址里把关键词位置写成 `@keyword`，应用搜索时会自动编码填入；
- 照着规则仓库里的示例规则抄一遍，比看文档快得多。

写完发现能搜到但播不了，试着关掉那条规则的「使用内置播放器」选项，改用 webview 播放能提高兼容性。
