# 应用冻结与批量卸载怎么做

> 本篇讲清冻结与卸载的实际差别、批量动作各自的后果与回退方式，以及批量执行时稳妥的顺序安排。
> **相关文档**：[安卓预装应用怎么清理](安卓预装应用怎么清理.md) · [Shizuku授权后应用管理器怎么用](Shizuku授权后应用管理器怎么用.md)

---

手机里装了几百个应用之后，逐个点进系统设置做操作并不现实。应用管理工具的价值就在于：先把范围筛出来，再对勾选的一批应用统一执行同一个动作。但批量意味着影响面大，动手前值得把每个动作的后果过一遍。

## 一、冻结与卸载，差在退路上

| 对比项 | 冻结 | 卸载（系统应用） |
| --- | --- | --- |
| 应用能否运行 | 不能，进程起不来 | 不能，从当前用户消失 |
| 桌面图标 | 多数启动器不再显示 | 消失 |
| 应用数据 | 保留 | 通常一并清除 |
| 恢复方式 | 解冻，一步还原 | 看机型与权限模式，不一定有现成入口 |

一句话判断：**拿不准就先冻结**。冻结能得到近似「应用消失」的效果，但随时退得回去；卸载更彻底，退路却更窄。系统应用尤其如此——先冻结观察几天，没问题再考虑卸载。

## 二、批量动作各自动什么

常见的批量动作按可逆程度排个序：

1. **搜索、排序、勾选**：只改显示，最安全，放心试；
2. **冻结 / 解冻、挂起 / 取消挂起**：可逆，状态记在系统里；
3. **结束进程**：临时效果，应用之后还会被系统重新拉起；
4. **重新安装**：改动安装记录，常用于修复异常状态；
5. **卸载、清除数据**：不可逆或难回退，尤其是清除数据——清掉就没了。

批量执行时，把不可逆的动作单独拎出来做；同一批只做同一件事，不要又冻结又卸载混在一起，出了异常分不清是哪一个引起的。

## 三、稳妥的执行顺序

1. 先筛后选：按类型、来源或状态把范围缩小，避免在大清单里大海捞针；
2. 单个试手：挑一个最无关紧要的应用，先单独执行一次目标动作，确认效果符合预期；
3. 再整批执行：勾选确认无误后统一执行；
4. 留观察期：批量冻结之后用一两天，再决定要不要升级成卸载；
5. 清数据放最后：它不可逆，且往往在前几步都确认对了之后才需要。

批量动作依赖权限引擎，遇到「部分成功、部分失败」先别重复点——权限中途失效是最常见的原因，处理方式见 [Shizuku授权后应用管理器怎么用](Shizuku授权后应用管理器怎么用.md)。

## 四、工具与入口

这些动作在开源管理器 [Thor](https://thor.fedq.quest/) 里都有对应入口：清单按来源、类型、状态筛选后勾选执行，冻结过的应用在状态筛选里一眼能对上。清理预装应用的完整路线（含哪些应用不能碰）整理在 [安卓预装应用怎么清理](安卓预装应用怎么清理.md)，建议先读那篇再动手。
