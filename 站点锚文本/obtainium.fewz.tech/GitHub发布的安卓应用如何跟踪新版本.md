# GitHub 发布的安卓应用如何跟踪新版本

> 不少安卓工具只在 GitHub Releases 里发 APK：装的时候手动下载，更新的时候同样没人提醒。本篇围绕「GitHub 源应用的版本追踪」讲两个话题：用什么工具盯发布页、盯上了之后怎么把检查做稳。
> **相关文档**：[商店外安装的安卓应用怎么自动更新.md](商店外安装的安卓应用怎么自动更新.md) · [README.md](README.md)

## 一、GitHub 源应用的特殊性

GitHub 仓库的 Releases 页面本身就是一份现成的「更新源」：每次发版带版本号、更新说明和 APK 附件，结构规整、非常适合程序化读取。缺的只是一个替你定时去看的东西 —— 手动刷新 Releases 页这件事，在跟踪三五个仓库时还撑得住，到了十几个就该自动化了。

## 二、把仓库交给更新追踪工具

以开源的 Obtainium 为例：添加应用时直接粘仓库链接（或在它的添加页里按名字搜 GitHub 仓库，还能按最低星标数过滤同名小项目），它读取 Releases 判断新版本，出新版就提醒，条件满足时后台静默安装。同一个应用如果同时发在 GitLab、Codeberg 或 F-Droid，跟踪那边也不占 GitHub 的额度。

安装包通过网盘获取，入口与装机步骤见 [Obtainium 安装说明与资源页](https://obtainium.fewz.tech/)。

## 三、跟踪 GitHub 仓库的三个实用要点

1. **速率限制要提前想到**：GitHub 对匿名接口请求的额度很低，跟踪的仓库一多就会报「速率限制」。解法是在工具设置里填一个 GitHub 个人访问令牌（Fine-grained token 即可，不需要配任何仓库权限），额度立刻按账号计算；
2. **预发布版与多包发布**：有的仓库每个版本同时挂 universal、arm64、armv7 好几个包，不筛选的话每次都要人工挑，后台更新也会停摆 —— 用「正则筛选 APK」把目标固定成唯一一个；在意稳定性还可以关掉「包含预发行版」；
3. **网络不畅的备用路**：部分网络环境下 GitHub 接口访问不稳，可以给源配置代理前缀，让接口请求走中转。公共代理的可用性由代理方决定，失效就换一个。

## 四、从添加到静默安装的完整链路

仓库添加完成后，检查频率、网络条件（仅 Wi-Fi / 仅充电）、后台机制（标准调度或前台服务）都在设置页统一定。Android 12 及以上的机器满足全部条件时，更新会在后台直接装好；差条件的场合退化为「下好弹通知、点一下确认」，接上 Shizuku 还能进一步提高静默安装的成功率。每个症状对应的排查条目，资源页里按场景列得比较全。
