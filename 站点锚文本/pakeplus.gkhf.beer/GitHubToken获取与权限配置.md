# GitHubToken获取与权限配置

云端打包依托 GitHub 平台运行：模板仓库的复制、编译任务的触发、产物的回传，都要靠一个访问令牌（Token）来授权。本篇按实际界面把生成与勾权过程写清楚，配合 [网页打包成安卓应用的完整步骤](网页打包成安卓应用的完整步骤.md) 使用。

---

## 为什么必须给它授权

打包不是在本机凭空完成的——工具要在你的 GitHub 账号下复制一个模板仓库、往里写入配置、触发编译流程，这些动作都需要令牌具备对应权限。令牌只保存在你自己的设备上，不会上传到别处。

## 生成入口

登录 GitHub 后，进入 `Settings → Developer Settings`，两种令牌任选其一：

- **beta 版（细粒度）**：生成时选择 All repositories，并勾选 Actions、Administration、Contents、Issues、Workflows 等权限，读取与写入都要勾上；
- **classic 版（经典）**：只需要勾选 `repo` 和 `workflow` 两项。

有效期建议选不过期，省得打包中途令牌失效。生成后复制令牌，填进打包工具的设置里，显示可用即配置成功。

## 权限没给够会怎样

最常见的表现是卡在发布环节：项目能建、预览能开，一点发布就报错或一直等待。这时候回到令牌设置逐项核对——尤其是 Administration（仓库的复制与文件管理）和 Workflows（编译任务的运行）这两项，缺一个都会导致云端流程走不通。

## 安全上的两点说明

- 令牌等同于账号的部分操作权，不要发给别人，也不要贴进公开场合；
- 觉得令牌可能泄露时，回到同一页面删除重建一个即可，旧令牌立即失效。
