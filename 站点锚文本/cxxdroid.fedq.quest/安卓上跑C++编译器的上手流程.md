# 安卓上跑 C++ 编译器的上手流程

> 在手机上把一段 C++ 代码从新建文件跑到出结果，到底要经过哪些动作？这篇以安卓端的 Clang 编译 IDE 为例，把环境准备、首次运行、日常写码三段流程串起来，照着走一遍就能上手。

## 一、环境准备：装之前核对口三件事

手机编译和电脑编译的原理一样，都是本地跑真实工具链，所以对设备有几个硬要求。装之前先核对：

1. **系统版本**：安卓 5.1 及以上，这个门槛近年的设备基本都满足；
2. **CPU 架构**：主流发行包面向 64 位 ARM（arm64-v8a）。用 CPU-Z 这类应用查 ABI 一栏，出现 `arm64-v8a` 就能装；老款 32 位设备会直接提示未安装；
3. **存储空间**：工具链本身约 48MB，但应用要求至少 150MB 空闲内部存储，打算装 Boost 这类大库的按 200MB 以上准备。

另外提醒一点：新版安卓设备改用了 16KB 内存页规格，未适配的旧版应用在新机型上会闪退。挑选安装包时认准带这项适配的版本（例如 5.6 版的更新说明里写的就是"16KB support"），可以少走弯路。

安装包的获取渠道可以参考 [Cxxdroid 介绍站](https://cxxdroid.fedq.quest/)，下载页里把转存、安装授权这些步骤单独列了出来。

## 二、第一次运行：从 Hello World 开始

装好后第一次打开，建议按这条线走一遍，把整条编译链路验通：

1. **新建文件**：主界面点文件夹图标，菜单里选 `New`；
2. **写代码**：输入一段最简单的程序，比如 `cout << "hello" << endl;`。键盘上方的扩展符号栏里，`{}`、`<>`、`::`、`#` 都在，不用翻符号页；
3. **保存**：再点文件夹图标选 `Save as`，起名时**后缀别省**——`.c` 按 C 编译、`.cpp` 按 C++ 编译，后缀错了编译器就用错了语言规则；
4. **运行**：点屏幕下方的圆形播放按钮，编译和运行一气呵成，结果出现在运行窗口；
5. **交互**：程序里有 `cin` 或 `scanf` 时，直接用键盘输入、回车继续。

看到输出那一刻，环境就算全部打通了。之后写任何程序都是这五步的重复。

## 三、几个一上手就会用到的功能

跑通第一段代码后，这几个功能很快会进入日常：

- **内置示例**：应用自带一批示例程序，第一次接触某个语法点时，打开示例改着跑比从零写快；
- **REPL 解释器模式**：基于 CERN Cling，逐行输入表达式立刻出结果。试一段指针运算、验证一个函数行为，不用先建文件再编译；
- **终端模拟器**：编译出的程序在完整终端里运行，支持历史命令与字体缩放，ncurses 这类终端库的演示也能跑；
- **标签页与行号跳转**：多文件同时开着切换，代码长了按行号直达；
- **字符编码切换**：utf-8、utf-16、shift_jis 都支持，打开别人的文件出现乱码时先查这里。

## 四、想装库了怎么办

写到某个阶段就会碰到 `#include <boost/...>` 这类需求。这款 IDE 的做法是内置包管理器加自带仓库：Boost、SQLite、ncurses、libcurl、SDL2 都是预构建包，在列表里点安装、等下载完成，回到代码里直接 include 就能用——装库这一步需要联网，编译运行本身仍然不用。

报 `file not found` 或 `undefined reference` 时，先确认三件事：库装完了没有、头文件名拼写对不对、文件后缀是不是被编译器认成了另一种语言。这三条覆盖了绝大多数库相关报错。

## 五、边界在哪：提前知道不吃亏

最后把能力边界说在前面，避免期望错位：

- **没有断点调试**：调试器在开发者的路线图上还标注为"开发中"，排查靠打印输出加 REPL 逐段验证；
- **大工程不合适**：它是为学习与小项目设计的工具，几十个源文件的工程在手机上编译和操作都会难受，这类活儿回电脑；
- **各商店版本不同步**：不同应用商店收录的版本号经常不一致，认准包名 `ru.iiec.cxxdroid` 与 arm64 架构后缀即可。
