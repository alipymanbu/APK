# 学生用手机交 C 语言作业的完整路径

> 老师周五布置作业、下周一要交，手边只有一台安卓手机——这套装备到底能不能按时交出能跑的代码？这篇按真实作业的时间线走一遍：环境、写码、验证、交付，每个环节给可执行的做法。

## 一、为什么手机真能搞定作业

先说结论的依据：手机上的编译 IDE 跑的是真实 Clang 工具链，和电脑上交作业用的编译器同源。也就是说，**在手机上编译通过的代码，交上去大概率也能过**——这不是"手机版简化语法"的玩具环境。

对学 C/C++ 的学生来说，作业代码普遍在几十到几百行，正好落在手机 IDE 的舒适区。排队、通勤、课间的碎片时间都能用来敲代码，这是比"能用"更实际的优点。

工具准备一条：装好 Cxxdroid 这类编译 IDE，预留 150MB 以上存储空间。安装包与功能说明可以看这个 [Cxxdroid 整理页](https://cxxdroid.fedq.quest/)，不重复展开。第一次运行请先把 Hello World 跑通，完整流程见 [安卓上跑C++编译器的上手流程.md](安卓上跑C++编译器的上手流程.md) 第二节。

## 二、接到题目：先拆要求再动手

拿到题目别急着敲，先花五分钟拆三件事：

1. **输入输出格式**：样例输入长什么样、输出按什么顺序打印，决定了 main 函数的骨架；
2. **数据范围**：范围决定类型——`int` 还是 `long long`，要不要用浮点，这些在手机小屏上改起来比电脑烦，动手前定好；
3. **提交物**：只要 `.c`/`.cpp` 源文件，还是要有运行截图？截图需求的话，运行窗口的结果要提前留好。

拆完在注释里写好思路骨架，再开始填代码——小屏上返工的成本比电脑高，动手前的两分钟思考最划算。

## 三、写码与验证：用好两件利器

作业代码的写法没有特殊之处，但两个功能能让手机上的效率明显上一个台阶：

- **REPL 先验证再拼装**：拿不准的语法点（比如结构体传参、指针运算），先在解释器模式里单独敲一段跑通，再拼回作业程序。整段调试在小屏上很折磨，化整为零最舒服；
- **打印输出当调试器**：这类 IDE 暂时没有断点调试，在可疑位置插 `printf` 看变量变化是最实在的排查手段。程序崩溃不会带崩编辑器，关掉运行窗口接着改就行。

编译报错时先读第一行：`file not found` 多半是头文件拼写、`undefined reference` 是库没链上、语法错误会给出行号，对应改即可。

## 四、代码搬运：从手机到提交入口

写完的代码怎么交，按老师的提交方式对号处理：

| 提交要求 | 做法 |
| --- | --- |
| 交源码文件 | 应用内文件菜单里找到 `.c`/`.cpp` 文件，用系统分享发到微信/QQ/邮箱 |
| 交纯文本代码 | 打开文件全选复制，粘进提交框；确认编码 utf-8，中文注释不变乱码 |
| 要运行结果截图 | 运行窗口出结果后系统截屏即可；终端里跑的程序提前调好字号 |
| 要在机房电脑复跑 | 用分享功能把文件传到云盘或邮箱，机房下载后用本地编译器重编译一次确认 |

其中最后一栏值得单独说：文件从手机传到电脑后，**在电脑上重新编译运行一遍再交**，顺便统一一下缩进风格——五分钟的事，能避免"手机上好好的、交上去跑不了"的尴尬。

## 五、交完之后：把这次作业变成积累

作业交了不等于结束，手机练习真正的价值在复用：

1. **整理代码片段库**：把作业里写过的通用函数（排序、查找、输入校验）存成单独文件，下次作业直接改用；
2. **错题本电子化**：这次编译报过什么错、怎么修的，记在文件里，比第二天就忘的印象深得多；
3. **逐步加码**：课堂作业顺手了，试着把课后习题也过一遍，或者去在线题库找同类型题刷——工具已经就位，剩下的只是练的量。

工具从来不是学 C 的瓶颈，"随时能写"才是坚持的关键。还在挑工具的可以回头翻 [手机写C语言代码的软件怎么选.md](手机写C语言代码的软件怎么选.md)；环境还没装好的，先走一遍 [安卓上跑C++编译器的上手流程.md](安卓上跑C++编译器的上手流程.md)。
