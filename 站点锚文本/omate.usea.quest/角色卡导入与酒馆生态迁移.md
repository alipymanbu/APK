# 角色卡导入与酒馆生态迁移

> 本篇讲从 SillyTavern（酒馆）搬进 OMate 时，各类数据分别怎么走、到那边变成什么，以及哪些东西带不过去。
> **相关文档**：[API密钥配置与模型分工](API密钥配置与模型分工.md) · [安卓安装与首次上手](安卓安装与首次上手.md)

---

## 一、搬家思路：转化式兼容

OMate 对酒馆生态做的是「转化式兼容」——角色卡、世界书、预设、聊天记录导入时自动转成它的原生机制，不需要先理解两边的术语差异。批量导入时多选一次丢进「角色」页右上角的「+」即可，系统会自动识别类型，并附一份转化报告。

## 二、各类数据的对照

| 你在酒馆里的东西 | 搬过去之后 | 支持情况 |
| --- | --- | --- |
| 角色卡 PNG / JSON / charx（V1 / V2 / V3） | 全字段映射；charx 内嵌资源自动取 icon 作头像 | 完整支持 |
| 世界书 / World Info（独立 JSON 与卡内嵌） | 原生世界书引擎：四种触发逻辑、正则关键词、插入位置与深度、order 排序、概率、常驻、递归、sticky / cooldown / delay 时效、token 预算 | 完整支持 |
| 预设 Preset JSON | 转为预设对象 + 提示词分组，可挂在全局 / 角色 / 对话 / 故事 / 朋友圈五处，按优先级叠加 | 完整支持 |
| 聊天记录 jsonl | 自动建对话，同名角色自动关联，完整 swipes 保留 | 完整支持 |
| 宏 Macros（{{char}}、{{random}}、{{roll}}、时间宏、条件块等） | 全面支持 | 完整支持 |
| 深度提示词 depth_prompt | 自动转为深度注入，随角色生效 | 完整支持 |
| 卡内正则脚本 regex_scripts | 性能考虑暂不启用，已随原卡完整存档 | 暂缓 |
| STscript / Quick Reply | 酒馆私有脚本语言 | 不适用 |

两个实用细节：

- **导出回酒馆**：改过的角色能以原卡为底稿双 chunk（V2 / V3）写回，分享回社区不丢数据；
- **图片浏览器暗门**：下载到本地的角色卡文件，用它的图片浏览器点开就会被自动识别，也是一条导入入口。

## 三、搬完之后从哪开始

导入只是把「人」接过来了，让角色开口还需要配好模型密钥——OMate 不内置模型服务，回复全部走自己填的 API，配置步骤见 [API密钥配置与模型分工](API密钥配置与模型分工.md)。还没安装的，先看 [安卓安装与首次上手](安卓安装与首次上手.md)。

功能全景、界面截图与获取入口都整理在 [omate 角色扮演应用速览站](https://omate.usea.quest/)，搬家前先扫一眼会更有底。
