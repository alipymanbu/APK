# GitHub开源应用新版提醒设置思路

> 追开源应用的新版本，一大半场景是追 GitHub 上的发版。本篇把"有新版怎么第一时间知道"拆成几条路：站内自带的关注机制、通用的更新追踪工具，以及跟踪数量多了之后绕不开的接口额度问题。
> **相关文档**：[商店外安卓应用更新怎么追](商店外安卓应用更新怎么追.md)

---

## 一、最轻量的路子：仓库自带的关注

在 GitHub 仓库页点 "Watch" 的 Releases 选项，有新发布时站内通知会提醒你。零配置、零成本，适合只追一两个项目的情况。它的短板也很明显：提醒停在网页里，看到之后还要自己拿手机下载安装包、自己安装，整条链路在"通知"这一环就断了。

## 二、把提醒接到手机上：更新追踪工具

想在手机上一步到位，可以交给 Obtainium 这类更新追踪工具：把仓库链接添加进去，它替你查发版、推通知，点开通知就能下载安装；条件满足时（Android 12 及以上、应用当初就是它装起来的）后台直接静默装好，连确认框都省了。

除 GitHub 之外，它同样认 GitLab、Codeberg、F-Droid 等发布渠道，一个工具把散在各处的发版收进一张列表。功能与安装入口见 [Obtainium 介绍与安卓版获取](https://obtainium.fewa.skin/)。

## 三、跟踪一多，接口额度会先挡路

追的仓库到了几十个，很多人会撞上一堵墙：检查更新时报 rate limit（速率限制）。原因是工具抓发版信息走的是平台接口，而接口对未认证请求的额度卡得很低。

通行解法是配一个个人访问令牌（Fine-grained token 即可，不用给任何仓库权限）：额度立刻从匿名档提到账号档，一次配置全局生效。另一个常见动作是关掉"验证最新标签"这类每次检查都要多花一次接口调用的选项——不处理预发布版排序问题时它纯属额度刺客。

同一个项目如果同时发布在 F-Droid 或其它托管平台，把跟踪源换过去，也能给 GitHub 的额度腾地方。

## 四、别让签名问题白忙一场

最后提醒一个高频坑：同一个应用从不同渠道拿到的安装包，签名可能不一致。从 F-Droid 装的应用拿 GitHub 渠道的包去覆盖更新，系统会直接拒绝。追更新之前先固定一个渠道，从头到尾认它，能省掉绝大多数"装不上"的排查时间。

一句话总结：追一两个项目用站内关注就够；追得多就让工具接管提醒和安装；追得特别多，再把令牌配上。
