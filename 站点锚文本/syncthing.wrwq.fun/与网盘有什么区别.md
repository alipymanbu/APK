# 与网盘有什么区别

> 「手机和电脑之间传文件，网盘不也能做吗？」能，但两者的路线完全不同：网盘是「文件存在厂商服务器上，各设备从服务器存取」，Syncthing 是「文件只留在你自己的设备上，设备之间直接互传」。这篇把差别和各自的适用场景摊开说。

## 差别在哪

| | 网盘 | Syncthing |
| --- | --- | --- |
| 文件存放位置 | 厂商服务器 + 你的设备 | 只在你的设备 |
| 大容量成本 | 通常要会员 | 无此项支出 |
| 设备不同时在线 | 不影响，服务器中转 | 不同步，要同时在线 |
| 第三方可见性 | 厂商侧可处理 | 传输加密，无中间存储 |
| 分享给别人 | 天然擅长 | 不擅长，它的目标是自己的几台设备 |

一句话概括：Syncthing 更像「自己的几台设备组成的小局域云」，而不是随时随地上传的云端硬盘。

## 什么时候选它

- **相册自动进电脑**：手机设「仅发送」、电脑设「仅接收」，在家连 Wi-Fi 就自动备份，不占手机云空间那 5 GB；
- **多台设备的资料夹保持一致**：文档、代码、照片素材在手机、电脑、NAS 之间双向同步，任何一端改动都会传到其它端；
- **电脑给手机推文件**：电子书、安装包设「仅接收」，从电脑推过去就行，不用数据线；
- **在意文件经过谁的手**：传输全程 TLS 加密、没有中间存储，文件夹内容自始至终只在自己的硬盘上。

## 什么时候它不合适

- 设备很少同时在线（比如只有一台手机）——没有另一头，同步无从谈起；
- 要把文件分享给朋友——它的配对机制是为自己设备组网设计的；
- 想要「随手传、随时取」的云端中转——这正是网盘的主场。

## 两个常见疑问

**设备 ID 要保密吗？** 不用刻意保密。仅凭设备 ID 找不到文件、也建立不了连接——配对必须两边都手动添加对方，ID 只是让设备互相找到彼此。

**同步速度慢是什么原因？** 先看是否走了中继：电脑端 Web GUI 的设备详情里，连接类型以「中继 / Relay」开头说明没连上直连，检查路由器是否放行 22000 端口（TCP 和 UDP）；其次，低性能设备做哈希校验慢、两边上行带宽的天然上限，都是常见瓶颈。
