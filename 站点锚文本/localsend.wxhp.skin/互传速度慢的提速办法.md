# 互传速度慢的提速办法

> LocalSend 的传输速度上限取决于网络本身，能跑满 Wi-Fi 就已经是它的满速。这篇按命中率从高到低列四个提速检查项，再解释为什么大量小文件要先打包，最后给两种极端情况的兜底。

## 一、按顺序查这四项

| 检查项 | 动作 |
| --- | --- |
| 频段 | 2.4GHz 换 5GHz Wi-Fi，近距离下差距明显 |
| 距离 | 设备靠近路由器，信号弱时反复重传会拖慢整体 |
| 有线 | 电脑插千兆网线最稳，无线掉速时的备选 |
| 带宽占用 | 传输期间停掉网盘同步、视频下载这类抢带宽的任务 |

传输中还要注意：别切换网络（从 5GHz 跳到热点、从 Wi-Fi 换流量这类动作都会直接断开重连）。

## 二、大量小文件：先打包再传

几百张照片逐个发，每个文件都要走一遍确认与建连，总时间大半耗在流程上；打成一个压缩包只走一次流程，总耗时通常明显缩短。这是对「传一大夹子照片很慢」最立竿见影的办法。

## 三、两种极端情况的兜底

- **速度始终只有几百 KB/s**：先换一台设备对传测一下。换设备后正常，说明问题在原来那台的网络（频段、省电策略限制后台联网）；两台都慢，多半是路由器或频段本身。
- **大文件传到一半断**：把发送端的省电策略设为「无限制」、允许后台联网，传输期间别锁屏、别让电脑睡眠，然后原地重试一次。

排查的前提是两端确实在同一个网络里、权限也给全了——这些基础项没过的话，表现往往不是慢而是直接搜不到。工具本身的安装与界面参考，可以看 [LocalSend 介绍站](https://localsend.wxhp.skin/)的整理。
