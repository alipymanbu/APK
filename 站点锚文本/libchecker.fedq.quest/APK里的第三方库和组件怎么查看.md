# APK 里的第三方库和组件怎么查看

> 一个安装包里塞了哪些第三方 SDK、注册了多少服务与广播接收器、权限都要了哪些——本篇讲怎么把一个 APK 的「内在成分」逐条翻出来看。
> **相关文档**：[安卓应用是32位还是64位怎么看.md](安卓应用是32位还是64位怎么看.md)

## 为什么要拆开看安装包

应用的行为背后是它的成分：后台常驻、开机自启、消息推送，都对应着具体的组件和 SDK。把这两样翻出来看，就能对「这个应用为什么耗电」「它到底集成了哪些服务」这类问题给出实据，而不是靠猜。

## 用 LibChecker 逐项查看

[LibChecker](https://libchecker.fedq.quest/) 是一款开源的安卓应用分析工具（Apache-2.0 许可），装上后点开任意应用，详情页按标签分组陈列：

- **原生库**：应用里每个 `.so` 文件及其所属架构，知名库会带名字标记；
- **服务 / 活动 / 广播接收器 / 内容提供器**：应用注册的四大组件，逐条列出；
- **权限 / 元数据 / 签名 / 安装来源**：包信息类条目。

知名库标记来自项目维护的规则仓库，覆盖面不止 SDK 名字——原生库、四大组件、权限、元数据、包名、签名都在规则范围内；识别不到的条目就不带标签。

## 不装进手机也能拆

除了查看已装应用，它还能直接分析本地的安装包文件：在设置里找到 APK 分析入口，选中文件就能出同样的详情页，Split APKs（`.apks` 之类的分包格式）同样支持。下载完先拆开看一眼成分，再决定装不装，是很顺手的用法。

## 统计全机与对比变化

- **库引用排行**：统计页把全机应用汇总成图表，能看到哪些第三方库在你手机上的应用里出现得最多，适合看某个 SDK 的覆盖面。
- **快照对比**：升级前存一份快照，应用更新后再对比，新增与移除的组件、原生库会分开列出；系统预装应用版本号长期不变，可加进追踪列表强制触发。

## 常见疑问速答

- **需要 root 吗？** 不需要，普通权限即可完成查看；个别进阶信息（安装请求方、DEX 优化状态）可选择性搭配 Shizuku。
- **「无原生库」是什么意思？** 说明该应用是纯 Java/Kotlin 实现，不含 `.so` 文件，任何架构的设备都能安装运行。
- **数据会上传吗？** 查看与统计都在本地完成；联网部分只有知名库规则仓库的更新，可在设置里关闭。

工具的获取方式与完整功能速览，见 [LibChecker 应用分析工具](https://libchecker.fedq.quest/)介绍页；想先弄懂架构标签的含义，回看 [安卓应用是32位还是64位怎么看.md](安卓应用是32位还是64位怎么看.md)。
