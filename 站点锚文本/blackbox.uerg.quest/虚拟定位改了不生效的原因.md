# 虚拟定位改了不生效的原因

> 在容器里给应用设好了位置，打开一看还在原地——十有八九不是设置错了，而是那个应用根本不读 GPS 这一层。这篇把手机定位的三个来源拆开讲，帮你判断应用在听谁的、哪一层是容器管得了的。

---

## 一、手机的定位其实有三个来源

应用想拿到你的位置，可以从三条路读：

| 定位方式 | 谁说了算 | 容器能否干预 |
| --- | --- | --- |
| GPS 卫星定位 | 系统定位服务 | 能，改成设置的位置 |
| 基站定位（LBS） | 运营商网络 | 通常被直接禁用 |
| Wi-Fi 定位（WPS） | 周边热点数据库 | 通常被直接禁用 |
| 按 IP 的网络定位 | 服务端按上网 IP 反推 | **管不了** |

以 Blackbox 为例，它的做法是禁用基站与 Wi-Fi 定位、只提供修改过的 GPS 位置——所以读 GPS 的应用会被"骗"过去，而走 IP 定位的应用纹丝不动。

## 二、为什么 IP 那层管不了

IP 定位发生在服务端：应用把你的上网出口 IP 报给自己的服务器，服务器按 IP 数据库反推出大致位置。容器是手机上的客户端，既决定不了你的出口 IP，也改不了对方服务器的反推逻辑——这层天然在它的管辖之外。

Wi-Fi 环境下 IP 定位很准（能到街道级），移动网络则通常只能到城市级。这也解释了为什么同一个设置，有人在 Wi-Fi 下"怎么改都没用"，插上流量卡反而近似生效。

## 三、判断应用在听谁的三步法

1. 先查自己当前出口 IP 被定位到哪（网上搜「IP 定位查询」类工具即可）；
2. 对比应用内显示的位置：与 IP 定位结果一致 → 应用走 IP 那层，容器的虚拟定位对它无效；
3. 与设置的位置接近 → GPS 层已生效，剩下的偏差是定位精度问题。

## 四、想连 IP 层一起动，思路只有换 IP

- 关 Wi-Fi 改用移动数据，让 IP 定位精度降到城市级；
- 或通过 VPN 改变出口 IP，让服务端按节点位置反推。

这两条都在容器之外操作，容器只负责把 GPS 那层稳稳接住。
