# 手机写的程序怎么打包成安装包

> 在手机上写好的安卓程序，怎么从一堆代码变成能装能发的 APK 文件。

用 AIDE 这类手机端开发环境写程序，最后一步永远是同一个问题：代码怎么变成安装包。好消息是这一步已经被大幅简化——不需要命令行，不需要另装打包工具，一个运行按钮就能完成。这篇把从编译到拿到 APK 文件的整个过程拆开讲清楚。

## 一、编译这一步在做什么

点下运行按钮后，工具在后台完成了一串动作：

1. **检查代码**：全程实时报错已经在写的时候把关过一遍，编译前再做整体检查；
2. **编译**：Java 代码连同 XML 布局、图片等资源一起，按安卓 SDK 的规范编译打包；
3. **签名**：用调试用的密钥给包签名——安卓系统只装有签名的包，这一步自动完成；
4. **安装**：编译好的 APK 自动推给系统安装，装完可以直接启动。

增量编译是手机端开发能流畅运转的关键：只重新处理改动的部分，二次构建比首次快得多，改一行代码马上就能看到效果。

## 二、拿到 APK 文件本身

运行按钮给你的是「装到这台手机上」的结果；如果想把安装包文件发给别人，就要找到它存在哪：

- AIDE 编译出的 APK 默认存在工程目录下的 `bin` 子目录里，用手机文件管理器进去就能看到；
- 长按文件可以重命名，改成一个好认的名字再分享；
- 通过内置的文件管理器也能直接查看、复制这个文件，或者借助内置 Git / Dropbox 同步到别的设备。

拿到 APK 文件后，别人把它传到手机上点开就能装（同样需要允许「来自此来源的应用」）。这个流程细节，[AIDE 介绍站](https://aide.fewz.tech/)的下载安装页有按步骤展开的说明，第一次操作时可以对照着做。

## 三、装到别人手机上的几种方式

有了 APK 文件，常见的分发路径：

1. **直接传文件**：微信、网盘、蓝牙都行，对方收到后点开安装；
2. **走应用市场**：正式发布要注册开发者账号、按市场规范签名上架，那是另一个话题，初学阶段不着急；
3. **给自己多台设备用**：把 APK 放进网盘，平板、备用机随装随取。

注意一点：自签名的包不会被应用市场接受，那只影响「上架」，不影响朋友之间互传安装。

## 四、包出问题时的排查顺序

编译或安装环节常见的几类故障，按这个顺序排查效率最高：

| 现象 | 多半是 | 怎么处理 |
| --- | --- | --- |
| 编译报错，红字标在代码里 | 语法写错 | 长按报错处看修复建议，或对照课程示例改 |
| 编译通过但装不上 | 存储空间不足或旧版本冲突 | 清一点空间，卸掉旧版再装 |
| 装上就闪退 | 逻辑错误（如空指针） | 用 LogCat 看崩溃日志定位到行号 |

LogCat（日志查看器）是内置的，闪退时打开它，红色那几行就是崩溃原因，把报错信息原文拿去搜索，基本都能找到答案。

## 五、往前一步和往后一步

- **还没开始装工具**：先看 [零基础学安卓开发用什么工具](零基础学安卓开发用什么工具.md)，把设备和软件准备好；
- **刚装好还没跑通第一个工程**：看 [手机上开发安卓应用怎么入门](手机上开发安卓应用怎么入门.md)，十几分钟就能见到第一个运行结果。

打包这件事，初学阶段理解到「一个按钮 + 一个 bin 目录」就够了；等真的要发布作品，再去研究正式签名和应用市场上架，那些规则的细节多、但都不难，难的部分你已经在手机上写完代码时解决了。
