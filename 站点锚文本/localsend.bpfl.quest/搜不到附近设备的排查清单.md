# 搜不到附近设备的排查清单

> 「附近的设备」列表一直空着？九成出在网络没对齐、权限没给全或防火墙拦了。本篇按命中率从高到低给一份排查清单，末尾是两条一定能连上的兜底办法。
> **相关文档**：[手机电脑互传文件为什么选局域网.md](手机电脑互传文件为什么选局域网.md)

---

局域网互传的前提是「互相看得见」，看不见就什么都谈不上。别急着重装应用，照下面的顺序过一遍，绝大多数情况在第一、二步就解决了。

## 一、先核网络：是不是真的在同一个网里

- 手机和电脑的 Wi-Fi 名字要一样。特别注意路由器的**访客网络**——访客网和主网默认互相隔离，连访客网的设备永远发现不了主网设备；
- 路由器若开着「AP 隔离 / 客户端隔离」，同一 Wi-Fi 下的设备之间也不转发流量，两台都联网正常、唯独互相看不见，要去路由器管理页把隔离关掉；
- 两端应用都要**开着**：从后台划掉就不再广播了，两端都重新打开一次。

## 二、再核权限：少一项就「单头瞎」

权限问题的典型特征是一头能看到另一头、反方向不行：

- **安卓**：系统「设置 → 应用 → LocalSend → 权限」里，「附近设备」（部分机型叫位置权限）要允许，通知权限也一并给了，否则收到了没弹窗；
- **iPhone**：在系统「设置」里找到 LocalSend，打开「本地网络」开关——这是 iOS 独有的一项，没开就什么都搜不到。

## 三、电脑防火墙：放行 53317

默认端口是 53317，入站方向的 TCP 与 UDP 都要放行。Windows 上：开始菜单搜「通过 Windows 防火墙允许应用」，找到 LocalSend 把「专用网络」「公用网络」两列都勾上；列表里没有就点「允许其他应用」，选中安装目录里的 localsend.exe 再勾。

用 VPN 的先把 VPN 断开试一次——VPN 会改写本机路由，局域网发现经常直接失效；Docker、安卓模拟器装出来的虚拟网卡偶尔也捣乱，排查时先禁用。

## 四、兜底一：手动填 IP 直连

自动发现失效时，在对方设备的设置页能看到它的局域网 IP（形如 192.168.1.23），在自己这端的「发送」页用「输入地址」填入即可跳过发现直接连。这一步还有诊断价值：**手动能连、自动搜不到，问题一定出在发现环节**，回头重查第一、二步；手动也连不上，多半是第三节的防火墙。

## 五、兜底二：换热点自建网络

公司网、咖啡厅这类网络普遍开着客户端隔离，而你没有路由器管理权限去关它。随便一台手机开个热点、另一台连上，等于自建一个只有你们两台设备的网络，隔离规则够不着——没有外网也照样传，链路本身不消耗流量。

排查通了两端还是连不上时，把两端应用都完全退出重开、再各重启一次系统服务；仍无解的话，先到 [LocalSend 中文介绍站](https://localsend.bpfl.quest/) 核对一遍使用前提，再考虑换网络环境。
