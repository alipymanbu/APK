# LSPosed 框架下的小米系统增强模块

经常有人问：这个模块和普通应用有什么区别，为什么装完「没反应」？答案藏在它的运行方式里——它不是独立工作的应用，而是挂在 LSPosed 框架下的增强模块。理解了这条链路，很多问题自然就通了。

- 相关文章：[小米 HyperOS 深度个性化指南](小米HyperOS深度个性化指南.md) · [HyperOS 状态栏与锁屏定制玩法](HyperOS状态栏与锁屏定制玩法.md)

## 一条链路看懂运行原理

hyperceiler 的工作路径是：Root 环境 → LSPosed 框架 → 模块接管系统应用 → 改动生效。四环缺一不可：

1. **Root 环境**：解锁 Bootloader 后刷入 Magisk 或 KernelSU，这是地基；
2. **LSPosed 框架**：在 Root 管理器的模块功能里刷入 LSPosed，重启后入口出现在通知栏，状态显示「已激活」才算就绪；
3. **启用模块并勾作用域**：在 LSPosed 的模块页打开开关，进入详情页勾选作用域——作用域决定模块接管哪些系统应用，想改状态栏、锁屏就勾「系统界面」，想改系统设置就勾「设置」；
4. **重启加载**：勾完作用域重启手机，框架开始接管，之后再在模块应用里打开具体功能开关。

「装了没效果」的排查九成落在这条链路上：框架没激活、模块没启用、作用域漏勾、改完没重启，按顺序对一遍即可。

## 版本分支与系统对应关系

项目按系统大版本拆分支发布：OS2、OS3 分支分别面向 HyperOS 2 与 HyperOS 3；老设备用的 2.5.x 系列是 Android 13 时期 MIUI 与 HyperOS 1.0 的最后版本线；更老的 Android 11~12 MIUI 用户，社区姊妹项目 Cemiuiler 在延续维护。

装错分支是「开了没反应」的另一大来源，动笔前先在系统设置里核对自己的版本号。各分支支持范围以项目发布页的更新日志为准。
