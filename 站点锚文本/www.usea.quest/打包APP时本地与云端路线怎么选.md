# 打包APP时本地与云端路线怎么选

> 用 PakePlus 打包时有两条编译路线：本地打包和云端打包。两条路的入口在同一个配置界面里，差别集中在账号、耗时和文件限制三件事上。这篇按使用场景把选择讲清楚。

## 一、两条路线各是什么

- **本地打包**：编译在设备本机完成，参考耗时约三十秒，全程不要求任何账号或令牌；
- **云端打包**：项目文件放到自己的 GitHub 仓库，编译由 GitHub 执行，客户端负责提交和取结果，需要 GitHub 账号与令牌（classic 令牌要勾 repo、workflow、user 三项权限）。

两条路线打出来的东西是同一种 APK / IPA，差别不在产物质量，在过程。

## 二、逐项对照

| 对比项 | 本地打包 | 云端打包 |
| --- | --- | --- |
| 账号要求 | 无 | GitHub 账号 + 令牌 |
| 参考耗时 | 约三十秒 | 几分钟（含排队） |
| 文件限制 | 不限数量与大小 | 单文件建议不超过 10M（GitHub 限制） |
| 多平台同时出包 | 以客户端选项为准 | 支持，一键同时编译 |
| 产物留存 | 在客户端里 | 挂在 GitHub 发布页，换设备也能取 |

## 三、按场景选

- **手机上现打现用**：走本地，省掉整个令牌配置环节；
- **要同时出安卓、iOS、桌面多份安装包**：走云端，多平台一次编译；
- **项目里有超过 10M 的大文件**（本地视频、大图）：云端会被单文件限制卡住，走本地，或把大文件改成外链引用；
- **想换设备也能拿到产物**：走云端，产物挂在发布页随时下载。

还没装客户端的话，先解决工具本身：安装包获取入口在 [PakePlus 介绍站](https://www.usea.quest/)的下载页。

## 四、两条路线共同的边界

- 工具只负责打包，不做软件签名；
- 产物仅限自己使用；
- 打出来的应用是原网页的独立窗口，内容仍然联网加载——原网站的状态直接决定应用的状态。
