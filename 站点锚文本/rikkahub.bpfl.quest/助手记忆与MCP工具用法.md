# RikkaHub 的助手、记忆与 MCP 工具怎么用

> 聊天只是 RikkaHub 的基本盘：把常用场景固化成助手、让 AI 跨对话记住偏好、给它挂上 MCP 工具与联网搜索，才是它作为聚合客户端的价值所在。本篇逐个讲。
> **相关文档**：[怎么配置API密钥和服务商.md](怎么配置API密钥和服务商.md) · [安卓APK安装步骤与常见问题.md](安卓APK安装步骤与常见问题.md)

## 一、把常用场景做成助手

助手（Assistant）是 RikkaHub 里最值得花几分钟配置的东西：每个助手可以配**自己的系统提示词、默认模型与人格**，聊天页里一键切换；不同助手之间的对话互相隔离，工作与生活分成两个助手，记录互不掺和。

几个实际用法：

- 翻译助手：系统提示词写明「中译英 / 英译中，只输出译文」；
- 周报助手：固定输出格式与语气；
- 代码审查助手：绑定一个擅长代码的模型，提示词里写清审查重点。

系统提示词还支持变量（当前模型名、当前时间等），写模板时能自动填充。

## 二、消息分支：同一个问题试两种问法

对某条回复创建分支，对话就从那个节点岔出另一条走向，原对话保持不动。适合两类场景：

- 同一个问题想试两种问法，看哪种得到的答案好；
- 在同一个上下文里对比两个模型的回复——这也是聚合客户端最大的好处，模型切换零成本。

## 三、跨对话记忆

RikkaHub 有类似主流聊天产品的记忆功能：AI 会记住你的偏好，跨对话生效。入口在**助手配置里**：打开某个助手，进「记忆」页签，可以开关记忆、查看、手动编辑或添加它记住的内容。两点要知道：

- 记忆是模型主动记录的，**要求所用模型支持工具调用**——换了不支持的模型，记忆可能不工作；
- 不想被记住的隐私内容，聊完进这个页签手动清。

## 四、MCP：给 AI 挂外部工具

MCP（Model Context Protocol）是让 AI 调用外部工具与数据源的通用接口。接上之后，AI 能按需查数据、调接口、跑流程，而不只是聊天：

1. 在设置里添加 MCP 服务器，配置地址与请求头等信息；
2. 聊天时由模型决定何时调用哪个工具，界面上能看到调用过程与结果；
3. 连不上时先核对服务器地址、请求头拼写，旧版本有「请求头名称为空导致连接失败」这类已知修复，升到新版本再试。

## 五、联网搜索：给 AI 接搜索引擎

开了联网搜索后，AI 回答前会先查实时网页再作答，适合问「今天 / 最近」开头的问题：

- 支持的搜索服务包括 Exa、Tavily、Brave、智谱、LinkUp、Perplexity 等，大多要到对应服务单独注册拿 key（与模型密钥是两回事）；
- 在设置的「搜索服务」里填入密钥并开启；
- 搜索按次向搜索服务计费（或耗其免费额度），不走模型服务商的账。

部分聚合 API 平台还提供内置联网能力的模型变体（模型名常带 search 后缀），联网走模型账单，不用单独配搜索 key。

## 六、输入与渲染

- 输入栏可以附带图片、文本文件、PDF、Docx 一起提问；
- 回复按 Markdown 渲染：代码高亮、LaTeX 公式、表格、Mermaid 流程图都正常；
- 支持 SillyTavern 角色卡导入，玩角色扮演可以把现成角色卡直接带进来；
- 应用自带 AI 翻译功能，配合一个翻译模型就能日常取词。
