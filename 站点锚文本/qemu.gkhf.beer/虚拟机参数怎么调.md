# 手机虚拟机参数怎么调才跑得动

> 本篇只讲参数：CPU 架构、型号、核数、虚拟运存、联网模式，每一条给结论也说原因。还没了解过手机虚拟机的读者可以先看 [手机上运行电脑系统](手机上运行电脑系统.md)，镜像准备见 [qcow镜像与磁盘管理](qcow镜像与磁盘管理.md)。

---

以基于开源 QEMU 的安卓端启动器为例，一份空白配置能不能点亮，基本就取决于下面这几项。

## CPU 架构：先想清楚要跑什么系统

- 跑 **32 位** 系统（如 32 位的 Windows 7、老发行版）→ 选 **i386**；
- 跑 **64 位** 系统 → 选 **x86_64**。

以 Windows 7 32 位为例，i386 与 x86_64 两条路都通，多篇教程更推荐 x86_64 一侧。ARM、MIPS 等架构同样在列表里，用于跑对应体系的系统。

## CPU 型号：跟着教程的共识选

**IvyBridge** 是教程里出现频率最高的推荐，**core2duo** 也稳妥。列表里都是现成的型号，没有特殊需求就照着选，不要留"默认"碰运气。

## 核心数：保持 1 个，别堆

这是被问得最多的一项。指令级模拟**没有真正的多线程**，多开的每个"核心"都在跟真实 CPU 抢算力——教程的实测结论一致：**多开核心反而变慢**。1 核就是最优解。

## 虚拟运存：手机内存的 1/4

运存给得越大，被安卓系统当成异常占用、杀后台的概率越高，虚拟机直接崩溃或冻结。**四分之一**是公认的安全线；小内存机型（3G/4G）再往下让一点，跑轻量系统反而更稳。

## 联网模式：一定选 user

联网模式选 **user** 才能正常联网，这是教程里被点名最多的一处遗漏——忘了选它，虚拟机里处处断网，还以为镜像坏了。

## 画面：VNC 与端口

图形界面选择 **VNC**，端口填 **0**（自动分配），启动成功后用 **127.0.0.1:0** 连接本机画面；新版本启动成功后也可以直接选择关联图形端打开。

## 一份能直接抄的组合

| 项目 | 推荐值 |
| --- | --- |
| CPU 架构 | x86_64（64 位系统）/ i386（32 位系统） |
| CPU 型号 | IvyBridge（或 core2duo） |
| CPU 核数 | 1 |
| 虚拟运存 | 手机内存的 1/4 |
| 联网模式 | user |
| 图形界面 | VNC，端口 0 |

按这张表配好，接下来就是镜像的事了，见 [qcow镜像与磁盘管理](qcow镜像与磁盘管理.md)。完整的面板截图与分步说明，可以到 [qemu 启动器介绍站](https://qemu.gkhf.beer/) 对照着看。
