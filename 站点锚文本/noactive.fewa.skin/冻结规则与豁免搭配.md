# 冻结规则与豁免搭配

> NoActive 的冻结是默认行为，「谁不被冻结、什么时候不冻结」由两层规则决定：模块自动识别的豁免状态，加上每个应用的手动开关。本篇按应用类型给出搭配建议，避免「要么全冻、要么全白名单」的两个极端。
> **相关文档**：[墓碑机制与后台冻结原理.md](墓碑机制与后台冻结原理.md) · [装完不生效排查思路.md](装完不生效排查思路.md)

---

## 一、先分清两层规则

**第一层是模块自动豁免**，不用设置：有可见窗口、通话中、播放铃声、正在定位/录音/使用相机、已连接 VPN、正在备份、开启了无障碍的应用，都不会被冻结；系统应用、输入法、Root 管理器、Xposed 模块本身默认在白名单里。

所以「列表里怎么找不到某个应用」多半不是 bug——列表只显示用户应用，看不到的按系统应用处理，默认不冻。

**第二层是每个应用的手动开关**，一共五个，作用各不相同。

## 二、五个开关各自管什么

| 开关 | 冻结时机 | 适合谁 |
| --- | --- | --- |
| 应用白名单 | 完全不冻 | 消息必须实时送达的 IM 类 |
| 后台播放 | 暂停约 10 秒后才冻 | 音乐、播客 |
| 常驻通知 | 通知被移除约 3 秒后冻 | 确实需要常驻通知的应用 |
| 禁止意图 | 挂起意图被拦 | 主要留给 Android 12 的设备 |
| 网速识别 | 传输停止后约 3 秒冻 | 下载、相册同步类 |

几个容易踩的点：

- **白名单要连推送进程一起加**：只加主进程，推送进程仍可能被后台限制，消息照样延迟。
- **后台播放的判据是「有声即为播放」**：有的应用切到后台并不主动停止发声，给这种应用开它，等于变相白名单。
- **常驻通知开关慎给网盘类**：常年挂常驻通知的应用开了它，效果约等于白名单，要自己权衡。

## 三、按应用类型的搭配建议

| 应用类型 | 建议 |
| --- | --- |
| 微信 / QQ 等 IM | 白名单（连推送进程一起加白） |
| 音乐 / 播客 | 后台播放 |
| 下载 / 同步 | 网速识别 |
| 挂常驻通知的网盘类 | 二选一：接受它被冻，或直接加白 |
| 闹钟等小工具 | 先用默认，真出问题再加白 |

内存不足时的处理顺序由「后台优化」档位决定：想保住的应用设高一档，系统杀后台时会最后才轮到它。

## 四、游戏场景的特殊处理

打游戏怕被后台应用解冻打扰，可以开「极致模式」：冻结的应用在游戏期间不放出来，还能添加成状态栏磁贴随手切换。开黑语音、直播的场景不用额外操作——正在录音、通话中的应用本来就在自动豁免名单里。

## 五、给新手的起点

从默认设置开始用几天，观察「运行列表」里哪些应用的状态符合预期、哪些总在冻结和解冻之间反复，再按上面的表逐个调整。想看这套机制本身的原理（为什么冻结不重载、CPU 为什么归零），先读 [墓碑机制与后台冻结原理](墓碑机制与后台冻结原理.md)；开关都调过了还是全都没冻住，那是环境问题，去 [装完不生效排查思路](装完不生效排查思路.md) 按顺序查。模块的功能总览与各设置的界面截图，见 [NoActive 介绍站](https://noactive.fewa.skin/)。
