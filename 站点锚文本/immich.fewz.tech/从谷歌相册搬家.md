# 从谷歌相册搬到自己的服务器

> 存了几年的照片视频想从谷歌相册迁到自己的 Immich 服务器，最大的坑不在「传」，而在元数据：直接上传会让整批照片的时间错乱。这篇讲正确的搬家顺序。

## 一、为什么不能直接拖进去

用谷歌相册自带的导出（Google Takeout）拿到的压缩包里，每张照片旁边都躺着一个同名 JSON 文件——拍摄时间、地点这些信息被从照片里抽出来放进了 JSON。把这些照片原样上传，服务器读不到正确的时间，几万张照片会全部显示成「今天上传」，时间线直接废掉。

社区工具 **immich-go** 就是为这个准备的：它直接读 Takeout 的 zip（不用手动解压），把 JSON 里的元数据拼回照片，再按原始的相册结构、正确的时间上传到服务器。

## 二、第一步：Takeout 导出

1. 打开 takeout.google.com 并登录谷歌账号；
2. 点「全部取消选择」，只勾选 **Google 相册**；
3. 交付方式选「通过电子邮件发送下载链接」，文件类型选 zip，分卷大小选 50GB（分卷越大、文件数越少）；
4. 提交后等导出生成——图库大的话要几小时到几天。

把所有分卷 zip 都下载到电脑上，**不要解压**，immich-go 直接吃 zip。另外每个下载链接有下载次数限制，用完了要重新生成导出。

## 三、第二步：immich-go 上传

immich-go 从它的项目发布页下载对应系统的版本，放在 zip 同一目录，然后：

1. 在 Immich 网页端生成 API 密钥（Account Settings → API Keys，权限给全，密钥只显示一次）；
2. 先加 `--dry-run` 空跑一遍，验证连接与权限没问题；
3. 去掉 `--dry-run` 正式上传。

上传时服务器按内容自动去重，与手机备份共用同一套校验和机制，两批数据不会互相重复。

## 四、迁移期间与迁移之后

- **给磁盘留余量**：缩略图与转码视频会让图库再涨 10%~20%，导入前建议预留约 1.5 倍源数据的空间；
- **先别开手机备份**：迁移期间两批数据一起灌会把服务器压得很慢，等后台的缩略图、人脸识别、搜索索引任务全部跑完（几万张以天计是正常的），再去开手机端；
- **完成后核对三样**：抽查几个时间段的照片拍摄日期对不对、原相册结构建出来没有、老视频能否正常播放。

搬完家只是换了个地方放照片，日常的自动备份与多设备同步，按[安卓客户端安装与连接](安卓客户端安装与连接.md)里的步骤开启即可；还不熟悉这套方案整体的，先看[自建照片备份方案](自建照片备份方案.md)。安卓客户端的获取入口与功能一览在 [immich.fewz.tech](https://immich.fewz.tech/)。
