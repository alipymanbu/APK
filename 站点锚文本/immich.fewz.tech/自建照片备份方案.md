# 自建照片备份方案：为什么选 Immich 这类自托管路线

> 手机相册是大多数人最舍不得丢的数据。把它的副本交给哪家服务，越来越多人开始重新考虑——这篇文章聊一条不同的路线：把相册搬回自己的服务器。

## 一、云相册的隐忧

云相册用起来省心，但有几件事一直悬着：容量到期就得续费，一续就是几十年；照片的整理方式、压缩策略、推荐算法都由平台说了算；哪天想整体迁走，导出的数据往往缺元数据、缺结构。对把照片当资产的人来说，这些都不是小事。

自托管路线把决定权拿回来：照片放在自己够得着的硬盘上，格式是通用文件，存储成本就是一块硬盘的成本，走哪条技术路线也由自己选。

## 二、Immich 是什么

Immich 是一套开源的照片视频管理方案，走的是「服务器 + 客户端」结构：

- **服务器端**跑在属于自己的机器上（NAS、家里的小主机、云服务器都行），用 Docker 部署，照片、数据库、缩略图全在这台机器上；
- **手机端**是一个操作入口，负责浏览时间线和自动备份，安卓与 iOS 都有客户端，界面支持中文。

它补齐的正是自托管方案过去最缺的「体验层」：人脸识别聚类、按内容描述搜图（比如搜「海边日落」）、按日期滚动的记忆时间线、多人账号与共享相册——这些曾经只在云服务上才有的能力，现在由服务器在本地推理完成，不需要把照片交给第三方。

## 三、日常用起来的样子

- 手机连上家里 Wi-Fi，新拍的照片视频自动传到服务器，多台设备之间按内容去重，不会传重；
- 手机空间吃紧时，用「释放空间」批量清掉已备份的本机副本，收藏和指定相册可以强制保留；
- 全家人各开各的账号，互相看不见；想共享就建共享相册，或者给没有账号的长辈生成一个带密码的公开链接；
- 网页端同样能用，电脑上整理相册不必掏手机。

## 四、动手前要准备什么

一台能常年开机的机器（2 核 CPU、6GB 内存是舒服的下限），装好 Docker，留一块容量够大的盘放照片。剩下的就是装客户端、填服务器地址、勾选相册三件事。

想先看界面长什么样、功能全不全，可以逛逛这份 [Immich 中文介绍资料](https://immich.fewz.tech/)，里面有安卓客户端的实拍截图与功能清单；具体安装与连接步骤写在[下一篇](安卓客户端安装与连接.md)里。老照片还躺在谷歌相册的，搬家路径见[从谷歌相册搬家](从谷歌相册搬家.md)。
