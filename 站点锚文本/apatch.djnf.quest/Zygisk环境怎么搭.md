# Zygisk环境怎么搭

> APatch 默认不带 Zygisk：想装依赖它的模块（包括 LSPosed），得先补一层环境。这篇讲清加载路径与先后顺序。
> **相关文档**：[内核级Root方案怎么选.md](内核级Root方案怎么选.md) · [超级密钥设置与保管.md](超级密钥设置与保管.md)

---

## 一、先说默认状态

APatch 与 KernelSU 保持一致，**默认不附带 Zygisk 支持**。刷完就去找 Zygisk 模块来装，是装不上的——那些模块启动时找不到环境，直接失效。

判断方法很简单：模块说明里写了「需要 Zygisk / Magisk」的，在 APatch 上都得先走下面这一步；没写依赖的 APM 模块一般直接装，装不上再按报错排查。

## 二、补环境：装一个提供 Zygisk 的 APM

社区里常见的实现有这么几个（状态随版本演进，装之前以各项目页面当时的说明为准）：

- **ZygiskNext**：最早为 KernelSU 补 Zygisk 环境的实现，对 Zygisk API 做完整实现，明确适配 APatch；留意它的许可证在某个版本节点后从自由软件转成了专有。
- **ReZygisk / NeoZygisk**：前者的自由实现方向的后续项目，部分特性覆盖不全，但保持了自由软件路线。
- **Zygisk_mod**：早期的过渡方案，适配完成后已停止更新，别再选。

装好环境后重启设备，用依赖 Zygisk 的模块自己验证：能加载、模块页状态正常、重启后仍然在，就算成了。这些第三方实现的稳定性由各自维护方负责，出问题先找对应项目，别去找 APatch 本体。

## 三、LSPosed 的正确装法

LSPosed 依赖 Riru 或 Zygisk，而这两样 APatch 默认都没有，所以**不能直接装**。可行路径只有一条：

1. 先按上一节装好一个 Zygisk 环境并重启；
2. 再走 LSPosed 的常规安装流程。

曾经还有一条「无 Zygisk 单独加载」的旁路（某个 loader 的专版），但那个项目早已停止更新，也不再被推荐，现在直接按上面两步走最稳。

## 四、常见的连锁坑

- **先装模块后补环境**：顺序反了模块装不上，补完环境后要把这些模块重新启用一次。
- **误判成 root 没刷上**：Zygisk 模块失效不代表 APatch 本身没工作——先在管理器确认密钥验证通过，再看模块环境，两件事分开排查。
- **环境类模块与系统升级**：系统大版本更新后补丁需要重做，Zygisk 环境同样要重新过一遍，别以为一次性配好就永久生效。

方案的选型背景与刷入链路，可以配合 [内核级Root方案怎么选.md](内核级Root方案怎么选.md) 一起看；完整操作流程整理在 [APatch 介绍与刷入指引](https://apatch.djnf.quest/) 里。
