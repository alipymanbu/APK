# Xposed 模块注入后不生效排查思路

> 这篇按「装不上 → 打开闪退 → 功能没反应」的顺序，把免 Root 打包方案最常见的三类故障逐条对号。
> **相关文章**：[免Root加载Xposed模块教程.md](免Root加载Xposed模块教程.md) · [安卓高版本Xposed框架替代方案.md](安卓高版本Xposed框架替代方案.md)

## 一、装不上：签名不一致 / 应用冲突

**原因**：打包后的 APK 换了签名，系统不允许用它覆盖安装原应用。

**处理**：卸载原应用 → 再装打包后的版本。没有绕开的办法，看到冲突提示直接卸载，别反复点安装。卸载会清掉该应用的本地数据，先备份再动手。

## 二、一打开就闪退

按出现频率对号：

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 打开目标应用立刻闪退 | 该应用签名校验较完善，挡住了注入 | 换校验弱的应用试，这个应用本身没有通用解法 |
| 应用检测到签名变化就拒绝工作 | 它主动拒绝运行修改后的包 | 同上，属该校验的正常反应 |
| 银行、支付类应用装上就用不了 | 这类应用校验最严 | 别拿它们做实验 |
| 闪退且模块加载不出来 | 模块与加载器版本不匹配 | 两边版本各换一轮凑对 |
| 部分功能异常后崩溃 | 唤起支付、登录、分享这类依赖原签名 | 正常现象，用不了就绕开 |

## 三、装上了但模块没反应

逐条对照，别跳步：

1. **作用域带「系统框架」**：免 Root 方案碰不到系统进程，这类模块必然不生效——这条占了「不生效」的大头，先把它排掉；
2. **作用域服务没起来**：动态加载靠 Shizuku 提供作用域，手机重启后服务会停，先打开 Shizuku 确认状态；
3. **模块版本不匹配**：模块与加载器版本凑不上是最常见的兼容问题；
4. **一次挂了多个模块**：只留一个重打，跑稳了再加下一个；
5. **加载顺序与依赖问题**：换「自定义打包签名」手动组包，往往就绕开了。

## 四、排查原则

每换一个变量就完整跑一遍流程，**别一次改三样**——否则好了也不知道是哪个改动起的作用。某个应用无论怎么换都闪退，通常是它的加固强度超出了免 Root 方案的处理范围，换个目标比死磕划算。
