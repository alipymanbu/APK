# 安卓高版本 Xposed 框架替代方案

> 这篇讲安卓 12 / 15 以上机型上，老 Xposed 方案纷纷失灵之后还有哪些路可走，以及怎么按机型挑。
> **相关文章**：[免Root加载Xposed模块教程.md](免Root加载Xposed模块教程.md) · [Xposed模块注入后不生效排查思路.md](Xposed模块注入后不生效排查思路.md)

## 一、为什么老框架在高版本上跑不动

Xposed 系的方案都依赖对应用进程的 hook，而安卓每个大版本都在收紧这方面的口子：隐藏 API 越封越多、系统完整性校验越来越严、部分机型干脆强化了对进程注入的拦截。结果就是：同一个框架，安卓 9 上好好的，升到安卓 12 之后要么装不上、要么挂了模块没反应、要么直接闪退。

## 二、现在还能走的三条路

| 路线 | 前提 | 特点 |
| --- | --- | --- |
| 刷机装 LSPosed | 已解锁 + Root | 兼容面最广，但高版本机型解锁越来越难 |
| LSPatch 打包 | 免 Root | 老牌免 Root 方案，但开发者已停更，新系统上问题渐多 |
| 新一代免 Root 加载器 | 免 Root | 为高版本机型而生，主打「老框架失效」的场景 |

第三条路里的代表是 FPA：FunBox 作者开发的独立项目，底层基于 LSPlant 与 Pine，社区实测口径从安卓 10 起步，主打的正是安卓 12 / 15 以上旧框架跑不动的机型。它的[介绍站](https://fpa.uerg.quest/)上有完整的界面截图与两种加载方式的步骤拆解，动手前可以先看一遍。

## 三、按机型怎么挑

- **安卓 9 ～ 11、模块兼容性要求高**：LSPosed 成熟度仍占优，能解锁就优先它；
- **安卓 12 以上、LSPatch 装上就跑不动**：先试 FPA 这类新方案，它的设计目标就是这个场景；
- **两头都不行**：多半是目标应用自身的签名校验太强，跟选哪个框架无关，换个目标应用试。

两个免 Root 方案可以同时装着，按应用逐个试；但**同一个应用一次只用一个方案打包**，别套娃。

## 四、无论选哪条都成立的两条

1. 作用域里带「系统框架」的模块，免 Root 路线一律加载不了——这类需求只能上刷机方案；
2. 打包 = 换签名 = 卸载原包重装，数据该备份先备份。

装完不生效的排查顺序，见 [Xposed模块注入后不生效排查思路.md](Xposed模块注入后不生效排查思路.md)；第一次上手免 Root 路线的，从 [免Root加载Xposed模块教程.md](免Root加载Xposed模块教程.md) 读起。
