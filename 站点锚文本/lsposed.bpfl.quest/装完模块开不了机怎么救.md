# 装完模块开不了机怎么救

> 本篇给卡开机动画时的三条救援路径，按「手上还剩什么入口」来选，先让系统能开机、再回头定位元凶。
> **相关文档**：[已Root手机装Xposed框架的完整步骤.md](已Root手机装Xposed框架的完整步骤.md) · [Xposed模块在安卓14上还能用吗.md](Xposed模块在安卓14上还能用吗.md)

装了模块重启后一直停在开机动画，是这类框架最典型的翻车方式——它基本是软件层面的问题：某个模块在系统进程里挂了不该挂的东西，不是手机坏了。别反复重启试探，每多一次开机循环都是白耗时间。

## 一、先花十秒判断手上有什么

| 设备状态 | 可走的路 |
| --- | --- |
| 能被电脑识别到 ADB | 路径一，优先试，不用刷任何东西 |
| 能进安全模式 | 路径二 |
| 装了 TWRP / OrangeFox 这类第三方 Recovery | 路径三 |

## 二、路径一：ADB 一条命令移除全部模块

电脑连上设备后执行：

```bash
adb wait-for-device shell magisk --remove-modules
```

它给 Magisk 留一个标记，让本次启动移除所有模块，设备接下来那次启动就能正常进系统。两个代价提前知道：移除的是**全部** Magisk 模块，不只是出问题的那个；命令需要设备能被 ADB 识别，始终连不上就换路径二或三。

## 三、路径二：安全模式

多数机型是开机时按住音量减，以机型说明为准。进安全模式后第三方应用停用；从安全模式再重启回正常模式，**Magisk 的模块仍保持停用状态**——这正是要的效果。进系统后按「一次只启用一个模块、每次重启」的节奏逐个加回来，加到哪个复现，元凶就是它。

用 KernelSU 的还有一个更省事的入口：开机第一个画面之后，**连续按三次音量减**（按下—抬起算一次，不是按住不放），进入它自带的安全模式，效果相同。

## 四、路径三：Recovery 里删模块目录

有第三方 Recovery 时最直接：挂载 data 分区后删掉框架的模块目录。

```bash
mount /data
rm -rf /data/adb/modules/lsposed
```

动手前确认路径：`/data/adb/modules/` 下每个子目录对应一个模块，只删出问题的那个，别对整层下手。画面仍不对时，再把框架自己的数据目录 `/data/adb/lspd` 一并清掉。

## 五、救回来之后

- **把元凶找出来**：按路径二的节奏复现一次，分清是框架本身与系统不兼容，还是某个具体模块的问题；
- **记下当前配置**：启用了哪些模块、各勾了哪些作用域，重装后照着恢复；
- **下次预防**：改动系统环境的操作前备份 boot 镜像；系统大版本更新后不要一次性把模块全开；给「系统框架」勾作用域前先想好退路——它是最坏结果会开不了机的那个位置。

装机流程与前提自查见 [已Root手机装Xposed框架的完整步骤.md](已Root手机装Xposed框架的完整步骤.md)；框架的注入原理与作用域机制，整理在 [LSPosed 说明站](https://lsposed.bpfl.quest/)。
