# 无障碍服务与权限设置：自动化脚本的第一道门槛

> 装好 Auto.js 后，脚本不是立刻就能跑的：无障碍、悬浮窗、存储三个权限缺一个都会被系统卡住。
> 这篇按真实顺序讲清每一项在哪里开、开了怎么验证、掉了怎么救。

## 一、为什么必须开无障碍服务

Auto.js 不需要 Root，它操作手机的方式是借用系统提供给视障用户的「无障碍」能力：脚本里的
`click()`、`text()` 这些函数，背后都是无障碍服务在读取屏幕控件、代为执行点击。服务不开，
脚本不是报错就是干等——这是新手第一个卡住的地方。

开启路径一般是：设置 → 更多设置（或辅助功能）→ 无障碍 → 已下载的应用 → Auto.js → 开启。
更省事的办法是在应用内侧边栏点「无障碍服务」，会直接跳到系统设置页。

## 二、Android 13 起的「受限设置」

从 Android 13 开始，对非应用商店渠道安装的应用，系统默认禁止打开无障碍这类敏感权限——开关
是灰色的，旁边写着「受限设置」。这不是安装包坏了，处理办法固定：

1. 进入「设置 → 应用 → Auto.js」（或长按图标 → 应用信息）；
2. 点右上角三个点，选「允许受限设置」，按提示验证；
3. 回到无障碍列表，此时开关可以正常打开。

不解除这个限制，无论怎么点开关都开不起来。很多「auto.js 开不了无障碍」的提问，实际就卡在这一步。

## 三、开启后 30 秒验证

服务开好后别急着写正式脚本，先确认它在工作：回到应用，点侧边栏「布局分析」→「布局范围分析」，
屏幕上会浮出一层控件信息；点任意有文字的控件，能看到文本、ID 等属性，说明服务确实在读屏幕。
之后写脚本用的 `text()` / `id()`，找的就是这里看到的属性。

## 四、服务被杀、自动关闭怎么办

无障碍用着用着变「关闭」，原因基本是系统把应用从后台杀了。按这张表逐项处理能明显减少复发：

| 措施 | 操作位置 |
| --- | --- |
| 允许自启动 | 应用信息 → 自启动管理（小米、OPPO、vivo 默认禁止） |
| 电池策略改「无限制」 | 应用信息 → 省电策略 |
| 锁定后台任务 | 最近任务卡片下拉（或长按）→ 锁定 |
| 关闭系统管家对它的深度清理 | 系统管家类应用设置 |

另外两点系统行为要知道：部分系统（如小米）每次重启后会自动重置无障碍开关，重启后记得复查；
一些系统把无障碍做成定时「体检」项，检测到风险会自动关闭，只能去安全设置里关掉该项检测。

## 五、剩下两个权限

- **悬浮窗**：运行 / 停止按钮、布局分析浮层都是悬浮窗形式，不开就没有「停止脚本」按钮可用；
  在「应用信息 → 显示在其他应用上层」里打开。
- **存储**：脚本、日志、截图都落在本地文件，不给的话编辑器读写会报错。

三项开齐后，就可以从 [手机自动化脚本入门](手机自动化脚本入门.md) 的三步跑通第一段脚本；
工具本身的能力清单与安装入口，见 [auto.js 专题介绍站](https://auto-js.gerw.hair/)；
脚本写顺之后的打包与电脑联调，见 [脚本进阶：打包与电脑联调](脚本进阶打包与电脑联调.md)。
