# 服务器告警通知到手机怎么配

> 本篇讲清 1Panel 面板的告警从配置到落到手机的完整链路、各接收渠道的版本门槛，以及手机客户端在这条链路里扮演的角色。
> **相关文档**：[面板手机客户端怎么连接服务器](面板手机客户端怎么连接服务器.md) · [手机端服务器运维客户端怎么选](手机端服务器运维客户端怎么选.md)

## 一、先纠正一个常见误解

装了 1panel 手机客户端，不等于服务器异常时手机会收到推送。客户端的角色是**处置端**：打开概览、停掉异常容器、改出问题的应用配置。而「有事第一时间告诉你」由服务器端面板的**告警通知**负责——面板把通知发到你选的渠道，手机上的邮箱、企业微信、短信或自建接收端收到消息，再打开客户端处理。

所以「告警到手机」要配两样东西：**面板侧的告警任务 + 一个能落到你手机的接收渠道**。

## 二、接收渠道与版本门槛

按面板帮助文档整理（随版本更新可能有变化，以面板内界面为准）：

| 渠道 | 版本要求 | 适合谁 |
| --- | --- | --- |
| 邮箱告警 | 社区版即可 | 最通用的兜底，配好发件邮箱就能用 |
| Bark 告警 | 社区版即可 | iPhone 用户最轻量的推送方案 |
| 企业微信 / 钉钉 / 飞书 | 专业版 / 企业版 | 消息进 IM 群或应用号，安卓用户的主力选择 |
| 短信告警 | 专业版 / 企业版 | 直发手机号，有额度与每日条数限制 |
| 自定义 Webhook | 面板 v2.3.0 起 | POST 到自己的接口，可对接值班系统 |

选法很简单：社区版用户把邮箱或 Bark 配上就够用，不花钱也能第一时间知道出事；用专业版的优先走 IM 渠道，消息不容易被折叠。

## 三、能配哪些告警任务

面板列出的告警类型覆盖日常运维最常见的「出事点」：

- 网站证书（SSL）到期、网站到期；
- 面板密码到期、面板新版本提醒；
- 服务器 CPU / 内存 / 负载 / 磁盘占用过高。

每类任务可设阈值与触发条件（比如 CPU 连续高于某百分比、证书剩余天数少于某值），持续异常有防打扰机制，避免同一条告警连环轰炸。

## 四、通知到手后，用客户端处置

1. 从通知里知道「哪台服务器、出了什么事」；
2. 打开客户端，首页概览确认整体状态，多台服务器时先切到出事的那台；
3. 按类型处理：容器异常进容器管理、应用出错进应用管理、站点异常进网站管理；
4. 处置不了的（改防火墙规则、动系统配置这类）回电脑网页版。

客户端的功能分区与获取方式，见 [1panel 手机客户端介绍站](https://1panel.qhah.skin/)的整理。

## 五、两个容易踩的坑

- **只装客户端、不配告警**：概览只有你打开时才看得到，服务器半夜出事你不会知道。先把告警任务配起来，客户端才有用武之地；
- **告警配了、渠道没打通**：配了短信但额度用完、配了邮箱但进了垃圾箱，都是常见翻车点。配完人为触发一次小阈值（比如把磁盘告警阈值临时调低），确认通知真的落到手机再改回来。
