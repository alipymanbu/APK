# 装第三方闹钟前，怎么把权限逐条核对清楚

> 安卓上装一个来路不明的时钟应用，最怕的就是它顺手要了一堆用不上的权限。这篇讲一套不用懂代码也能操作的核对方法，并以开源项目 Chronos 为例走一遍完整流程。
> **相关文档**：[手机闹钟不响排查步骤.md](手机闹钟不响排查步骤.md) · [README.md](README.md)

---

## 一、先看应用商店或系统设置里的权限声明

装之前，商店页面的"权限"一栏值得逐行读完；已经装了的，到系统设置 → 应用 → 该应用 → 权限，能看到系统实际授了哪些。两个入口对照着看：声明多但实际要求少的，通常是按需申请；声明里出现和功能明显无关的条目（比如一个闹钟要通讯录、要位置），才是该警惕的信号。

一个可参照的底线：闹钟类应用的合理权限大致就是闹钟设定、震动、唤醒屏幕、发通知这几项，再加上自定义铃声/背景时的媒体读取。超出这个范围越多，越要问一句为什么。

## 二、开源应用多一步：去源码仓库核对声明

开源应用多一个别人没有的核对渠道 —— 源码仓库里的说明文件。以 Chronos 为例（`github.com/meenbeese/Chronos`，Apache-2.0 许可证），项目说明里有一节专门列权限，每条后面写着用途：

| 权限 | 用途 |
| --- | --- |
| SET_ALARM / VIBRATE / WAKE_LOCK | 设闹钟、响铃时震动、到点唤醒屏幕 |
| POST_NOTIFICATIONS | Android 13+ 发送闹钟与计时器通知 |
| RECEIVE_BOOT_COMPLETED | 重启后自动重排已设闹钟 |
| READ_MEDIA_AUDIO / READ_MEDIA_IMAGES | 仅在自定义铃声 / 背景图时读取媒体 |
| FOREGROUND_SERVICE | 支撑"睡眠提醒"的就寝通知 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 申请电池白名单，防止后台被清 |
| SCHEDULE_EXACT_ALARM / USE_EXACT_ALARM | 到点准点响，而非"大致时间" |

核对时看三点：声明是否和实际功能对得上（比如要媒体权限是不是真为了自定义铃声）、有没有解释不了的条目、说明是否随版本更新。这份清单里没有通讯录、位置、短信任何一项，对一个闹钟来说，这本身就是信息。

想再进一步，可以在仓库里全局搜索权限字符串，直接看每条权限在代码里的使用位置。这一步不做也不影响判断，前两条已经能筛掉绝大多数问题应用。

## 三、渠道也是核对的一部分

从哪里拿安装文件，和权限声明同样重要。同一个应用，不同渠道拿到的文件可能是不同版本、甚至被改过的包。可行的做法：

- 有源码仓库的，优先走仓库的 Releases 页面，看清版本号与签名说明；
- 用 IzzyOnDroid 这类经过审核的第三方仓库，更新由客户端自动跟；
- 用 Obtainium 的话，它直接盯仓库发布，装的就是仓库里那份原包。

Chronos 没有上架 Google Play，走的就是上面三类渠道。如果你更习惯"先看介绍再拿文件"的顺序，[Chronos 闹钟](https://chronos.hfdk.space/)这个介绍站把权限清单、界面实拍和版本信息整理在同一页，比在仓库里翻说明更快。

## 四、装完之后还有一次"事后核对"

装完别急着用，做两件事：一是再进系统设置看一遍实际授予的权限，把你不认可的关掉（比如不允许读取媒体，自定义铃声就用不了，属于可放弃项）；二是注意首次打开后的权限弹窗，Android 13+ 的通知权限、部分机型的"闹钟与提醒"开关，都是装完才出现的。权限被关带来的"闹钟不响"是这类应用最常见的反馈，处理办法见[手机闹钟不响排查步骤.md](手机闹钟不响排查步骤.md)。
