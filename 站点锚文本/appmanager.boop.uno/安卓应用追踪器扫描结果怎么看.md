# 安卓应用追踪器扫描结果怎么看

> 给已装应用做一次本地扫描，把追踪类与第三方库的名单读出个所以然：哪些条目值得多看一眼、看到之后有哪些处置选项、扫描结果本身的边界在哪里。
> **相关文档**：[不root怎么冻结安卓后台应用.md](不root怎么冻结安卓后台应用.md) · [查安卓应用包名与签名的方法.md](查安卓应用包名与签名的方法.md)

---

## 一、扫描扫的是什么

扫描对象是设备上已安装应用的安装包内容。所谓"追踪器"，指开发时被一起打包进应用的、与广告或数据回传相关的代码类；第三方库则包含统计、崩溃上报、推送等常见组件。开源工具 App Manager（GPLv3+，一款安卓应用管理器）把这类扫描做进了应用详情页：打开某个应用，选"追踪器"条目，等进度走完就得到名单，扫描在设备本地完成，结果不经过服务器。

## 二、名单怎么读

拿到结果后，条目大致可以按这几类看：

| 类别 | 常见样子 | 多半意味着 |
| --- | --- | --- |
| 广告类 | 包名里带 `ads` / `advertising` | 应用内嵌了广告 SDK，即使平时不展示也可能常驻 |
| 统计类 | 包名里带 `analytics` / `stats` | 会收集使用行为做统计分析 |
| 崩溃上报类 | 包名里带 `crash` / `fabric` / `sentry` | 记录崩溃日志，风险相对低 |
| 推送/云服务类 | 各厂商推送 SDK 名 | 可能拉起后台进程保持连接 |

一个应用里有统计或崩溃上报类属于常见现象，不必见一个杀一个；真正值得注意的是广告类条目多、且出现在按理用不到广告的场景里。

## 三、看到之后有哪些处置选项

- **只做知情**：不改任何东西，把名单当作评估"要不要继续用这个应用"的参考。
- **想动手拦**：拦截活动、服务这类组件属于"改系统"的操作，需要 ADB 或 root 权限档；三档各解锁什么，[App Manager 中文介绍站](https://appmanager.boop.uno/)有一张按能力逐项对照的表，先看表再动手能少走弯路。
- **用不上就卸**：扫描结果只是信息，卸载仍然是最干净的处置。

## 四、扫描结果的边界

这类扫描看的是打包进安装包的代码类，属于静态信息：类被扫出来不等于它一定回传了数据，反过来，经过加固处理的应用也可能扫不全。把结果当作线索而不是判决，结合应用的实际行为判断，才不会被名单带偏。

排查到具体某个组件想拦又不确定影响时，先看[不root怎么冻结安卓后台应用.md](不root怎么冻结安卓后台应用.md)里"冻结前想清楚的事"那一节。
