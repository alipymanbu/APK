# 手机上运行Lua脚本的实用姿势

> 本篇整理在安卓手机上把 Lua 跑起来的几种常见姿势：单文件脚本、带界面的工程、以及运行出错时先看哪里。

## 一、先分清：跑一段代码，还是跑一个工程

手机上「运行 Lua」其实有两种粒度。小粒度是一段独立脚本：写几行、点运行、看输出，验证想法用；大粒度是一个完整工程：有入口文件、有界面布局、有配置，改完整体跑。工具支持到哪一层，决定了你能玩到哪一层。

## 二、单文件脚本的跑法

最朴素的流程：打开编辑器 → 新建文件 → 写代码 → 点运行。以 Shield 为例，它的编辑器自带行号和语法高亮，屏幕底部还有一条符号快捷栏，`( ) [ ] { }` 和引号这些编程符号一键输入，顶栏三角按钮就是运行。改错了用顶栏的撤销箭头退回来，整个过程不需要离开应用。

打印输出（`print`）是最直接的观察手段；报错信息通常带脚本名和行号，对着编辑器左边的行号列就能定位到出错那行。

## 三、带界面工程的跑法

AndroLua+ 风格的工程把界面和逻辑分开：`main.lua` 是入口，`layout.aly` 描述界面，`init.lua` 记着应用名与包名。这类工程拿到手机上后，从工具的工程入口打开文件树，改哪个文件都行，改完一样点运行。工程存放位置一般在内部存储的 `AndroLua/project/<项目名>/` 目录下，各文件的角色在 [AndroLua+工程在手机上打开与修改.md](AndroLua+工程在手机上打开与修改.md) 里逐个拆过。

顺带一提，Shield 的市场标签里按类型归档了不少在线文件，其中数量最多的 ALP 一类就是这种工程文件，看到感兴趣的拿到手就能直接编辑运行。

## 四、跑不起来时的排查顺序

1. **先看报错行号**：Lua 的报错大多直接指出文件与行，90% 的问题在这一步就解决了；
2. **查拼写与导入**：`require` / `import` 漏写、函数名拼错是高频错误；
3. **查文件是否完整**：工程文件没传全（比如少了 layout.aly）会报找不到文件，重新整包拿一次；
4. **查系统权限**：涉及读写存储的脚本，确认给应用授了存储权限。

这四步从上往下走，多数卡点都能解。工具本身怎么装到手机上，[Shield 介绍站](https://shield.djnf.quest/)的下载页有现成步骤。
