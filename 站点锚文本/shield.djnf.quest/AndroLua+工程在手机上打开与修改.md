# AndroLua+工程在手机上打开与修改

> 本篇拆开一个 AndroLua+ 风格的工程：目录里每个文件管什么、在手机上从哪里打开、改完怎么验证。
> **相关文档**：[安卓手机写Lua脚本用什么工具.md](安卓手机写Lua脚本用什么工具.md) · [手机上运行Lua脚本的实用姿势.md](手机上运行Lua脚本的实用姿势.md)

---

## 一、工程目录长什么样

一个典型的 AndroLua+ 工程放在手机内部存储的 `AndroLua/project/<项目名>/` 下，打开后通常能看到这几样：

```text
AndroLua/project/<项目名>/
├── java/
├── init.lua
├── layout.aly
└── main.lua
```

结构很扁平，文件不多，但每个文件都有明确分工。

## 二、每个文件的角色

| 文件 | 角色 |
| --- | --- |
| `main.lua` | 入口脚本，点运行时执行的就是它 |
| `layout.aly` | 界面布局描述，AndroLua+ 体系的布局文件，界面长什么样由它说了算 |
| `init.lua` | 工程的应用名、版本、包名都记在这里，打包成 APK 时靠它 |
| `java/` | 需要原生能力时放 Java 扩展的目录，普通脚本工程往往碰不到它 |

改界面的去动 `layout.aly`，改逻辑的去动 `main.lua`，想改应用身份信息就翻 `init.lua`——知道了分工，改起来就不用全文件乱翻了。

## 三、在手机上从哪里打开

工具侧的入口以 Shield 为例：它的编辑页左上角有工程抽屉，展开就是文件树，点谁就开谁；顶栏显示当前工程名，多个文件之间切来切去不会迷路。它对这套工程结构是原生兼容的，`main.lua`、`layout.aly`、`init.lua` 都按各自角色对待，改完顶栏三角按钮直接运行，报错了对着行号改。

## 四、改完怎么验证

推荐小步快跑：每改一处就点一次运行，别攒一大堆改动再验证。看到报错先读错误信息里的脚本名与行号，对照编辑器左侧行号列定位；改界面就重启一次运行看效果。更多排查思路（权限、文件不完整等）在 [手机上运行Lua脚本的实用姿势.md](手机上运行Lua脚本的实用姿势.md) 的最后一节。

## 五、从哪里能拿到现成工程练手

Shield 的市场标签里按类型归档了在线文件，其中 ALP（AndroLua+ 工程文件）一类数量最多，APK、CPP 等类型各占一格。挑一个名字和说明都看得懂的工程拿到手，用上面的流程打开、修改、运行，是最快的上手路径。这个工具本身的情况与获取方式，见 [Shield 介绍站](https://shield.djnf.quest/)。
