# NoActive 装完没效果？按这五步排查

> 本篇讲 NoActive 装完之后「看起来什么都没发生」的排查路径：从作用域、重启，到冻结方式与提权模式，按顺序走一遍，大部分「没效果」都能在其中一步解决。
> **相关文档**：[冻结方式怎么选.md](冻结方式怎么选.md) · [白名单与冻结开关设置.md](白名单与冻结开关设置.md)

---

## 一、先确认前提：它对环境是有硬要求的

NoActive 是一个以冻结为核心的后台优化 Xposed 模块，靠 Hook 系统框架把退到后台的应用置入冻结状态。这意味着它对环境有三条硬要求：手机已 Root（Magisk / KernelSU / APatch 任一）、装好 LSPosed 管理器、系统在 Android 12 及以上。

没 Root、没装 LSPosed 的机器，安装包本身能装上，但装完不会有任何效果——这是排查的第一站，也是最容易被跳过的一站。安装与启用的完整流程，可以看 [NoActive 介绍与安装说明站](https://noactive.bpfl.quest/) 整理的五步操作。

## 二、五步排查路径

### 第 1 步：LSPosed 里模块真的启用了吗

打开 LSPosed 的「模块」页，确认 NoActive 处于启用状态，并且作用域里勾选了「系统框架」。只装 apk、没在 LSPosed 里启用，等于没装。

### 第 2 步：勾完作用域重启了吗

作用域不重启不生效——勾选「系统框架」之后必须重启手机。很多人卡在这一步：模块是启用状态、作用域也勾了，就是没重启。顺手把「系统界面」也勾上（部分版本提供），重启后多一个从磁贴解冻的入口。

### 第 3 步：看运行列表，别凭感觉

打开 NoActive 的「用户应用」，切到「运行列表」。随便开一个应用再退回桌面，等几秒：列表里出现「已冻结」就是生效了。也可以用第三方工具看 CPU——应用退后台约 3 秒后占用降到 0%，就是冻结成功。

### 第 4 步：换冻结方式

运行列表全空、或者日志里报 error，最常见的原因就是冻结方式和内核不匹配。NoActive 提供 API、V2、V1、KILL 四种方式，选法一句话：内核 5.0 及以上选 V2 或 API；4.19 内核的小米系（MIUI / HyperOS）选 V1；其它 4.19 及以下用 KILL 兜底。具体机制差异与各自的坑，见 [冻结方式怎么选.md](冻结方式怎么选.md)。

### 第 5 步：开提权模式

部分机型的系统框架没有权限读写 Freezer 目录，模块本身冻不动任何进程——这种机器在设置里开启「提权模式」再试。还不行的话，社区里流传的最后手段是把冻结方式切到 Kill -19 并在每次开机后执行一条 SELinux 策略命令（`magiskpolicy --live "allow system_server * process {sigstop}"`），效果重启不保留，每次开机都要重新执行。

## 三、不是故障的三种「没效果」

排查之前先对照这三种情况，它们都不是模块失灵：

- **列表里找不到某个应用**：列表里看不到的应用按系统应用处理，系统应用有全局白名单、默认不冻结。
- **某个应用一直不被冻结**：先看它是不是正处在自动豁免状态——有可见窗口、通话中、定位、录音、用相机、连 VPN、正在备份、开着无障碍，这些状态下应用本来就不会被冻结。
- **切回应用时重新加载**：用 KILL 方式时的已知现象（进程还在但回前台可能重载），换 V2 或 API 通常能改善。

更多按应用类型的开关搭配建议，见 [白名单与冻结开关设置.md](白名单与冻结开关设置.md)。
