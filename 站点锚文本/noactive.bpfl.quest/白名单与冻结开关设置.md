# NoActive 白名单与冻结开关设置：按应用类型对号入座

> NoActive 的冻结是默认行为，「谁不被冻结、什么时候不冻结」由两层规则决定：模块自动识别的豁免状态，加上每个应用的手动开关。本篇把两层都讲清，并给出按应用类型的搭配建议。
> **相关文档**：[冻结方式怎么选.md](冻结方式怎么选.md) · [装完没效果怎么排查.md](装完没效果怎么排查.md)

## 一、模块自动豁免的情况（不用你设置）

下面这些状态下应用不会被冻结，都是模块自动识别的：

| 状态 | 行为 |
| --- | --- |
| 有可见窗口 | 免冻结 |
| 通话中 / 播放铃声 | 免冻结 |
| 正在定位 / 正在录音 / 正在使用相机 | 免冻结 |
| 已连接 VPN / 正在备份 / 开启了无障碍 | 免冻结 |
| 带系统签名的应用、Magisk、输入法、Xposed 模块 | 默认白名单 |

对照这张表能解释大部分「这个应用怎么一直不被冻结」——先看它是不是处在上述状态，再考虑改设置；「列表里找不到某个应用」通常也不是故障，列表里看不到的应用按系统应用处理、默认不冻结。

## 二、每个应用的手动开关

### 1. 白名单

开启后该应用完全不受冻结限制，推荐给消息必须实时送达的应用（微信这类）。有一条要注意的仓库说明：白名单推送进程时，需要把主进程一起加白，否则仍可能被后台限制。

### 2. 后台播放

播放期间不冻结，暂停后约 10 秒冻结。判定口径是「有声即为播放」——有的应用切到后台并不会主动停止发声，这种应用开了这个开关就永远不会被冻结。适合音乐、播客类；给会后台发声但不该发声的应用开它，等于变相白名单。

### 3. 常驻通知

通知常驻期间不冻结，通知被移除后约 3 秒冻结。网盘类应用会一直挂着常驻通知，开了这个开关效果等同于白名单，要自己权衡。

### 4. 禁止意图

管的是挂起意图一类：状态栏操作、桌面小组件，还包括发送广播、启动前台服务、启动 Activity。V3.2 起对 Android 13+ 已内置意图限制，这个开关主要留给 Android 12 的设备。

### 5. 网速识别

后台传输不冻结的判据：上传达到 100KB/s 或下载达到 300KB/s；回落到上传 10KB/s、下载 30KB/s 以下后约 3 秒冻结。下载大文件、同步相册这类场景开着它，防止传输被打断。

## 三、按应用类型怎么搭

| 应用类型 | 建议 |
| --- | --- |
| 微信 / QQ 等 IM | 白名单（推送进程要连主进程一起加白） |
| 音乐 / 播客 | 后台播放 |
| 下载 / 同步类 | 网速识别 |
| 挂常驻通知的网盘类 | 别开常驻通知开关；要么接受它被冻结，要么加白名单，二选一 |
| 闹钟等小工具 | 先用默认；真出现响铃不准再加白名单 |
| 游戏 | 开极致模式防解冻；可添加成状态栏磁贴随手切换 |

## 四、后台优先级与进阶玩法

**后台优化（原「重要程度」）**：给后台应用定优先级，内存不足时系统按 oom_adj 从大到小的顺序杀，分高 / 中 / 低三档。想保哪些应用，就把它们设高一档——先后台了 C（低）、B（低）、A（高）三个应用时，A 最后才轮到被杀。

**极致模式**：3.0 起加入的开关，作用是防止打游戏时被后台应用解冻打扰；开黑语音、直播的场景不用额外操作——正在录音、通话中的应用本来就免冻结。

**定时解冻**：隔一段时间把冻结的应用解冻一下，防止应用因长期冻结在后台出毛病；个别应用冻结后行为异常时可以开它试试。

**进阶配置文件**（社区文档口径，改动前先备份）：模块的配置目录是 `/data/system/NoActive_8位随机字符/`，其中 `config/MemConfig.json` 可以调内存保留值——`freeRAM`（物理内存保留）与 `freeSWAP`（交换分区保留），0 为自动、负整数关闭、正整数按 MB 指定。JSON 写错语法时模块会自动清掉错误配置还原默认，改坏了也不用慌。

这些开关都建立在模块正常工作的前提上：装完没动静，先按 [装完没效果怎么排查.md](装完没效果怎么排查.md) 走一遍；换冻结方式的依据见 [冻结方式怎么选.md](冻结方式怎么选.md)。模块的界面与功能全景，也可以在 [NoActive 说明站](https://noactive.bpfl.quest/) 里过一遍。
