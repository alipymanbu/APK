# 换机迁移歌单的两种做法

换新手机，最烦的不是装应用，而是把攒了几年的歌单、收藏和播放记录原样带过去。这篇把开源播放器 NeriPlayer 里两条迁移路线讲清楚，按你的使用习惯选一条或两条都用。

---

## 先分清：同步的是数据，不是音频

无论哪条路线，搬的都是**元数据**——歌单结构、收藏、最近播放、播放统计。已下载的音频文件本身不跟着走，要么在新手机上重新下载，要么用数据线把旧手机的下载目录整个拷过去。想明白这一点，迁移方案的选择就简单了：歌单结构走同步或文件，音频文件走拷贝或重下。

## 路线一：GitHub / WebDAV 同步

这条路线适合长期使用：在应用里配置一个 GitHub 令牌（勾上 repo 权限），歌单与播放数据会以文件形式自动提交进你的仓库；WebDAV 同理，支持这类协议的网盘或自建存储都能当同步目标。

换机操作很直接：新手机装好应用，进「设置 → 备份与恢复 → 配置 GitHub 同步」，填同一个令牌、选原来那个仓库、打开自动同步，数据就拉回来了。

两点提醒来自项目更新日志：一是同步的数据模型在大版本间不保证完全向下兼容，大更新前先手动导出一份本地备份；二是仓库建议建私有的——公开仓库等于把听歌记录晾给所有人看。

## 路线二：本地文件导出

不打算绑 GitHub 的话，「备份与恢复」里的导出功能就能当一次性搬家工具：

| 导出类型 | 内容 | 适用 |
| --- | --- | --- |
| 歌单 JSON | 本地歌单与收藏 | 只想保住听歌清单 |
| 完整配置 | 设置、平台授权、同步配置一起打包 | 换机整机迁移 |

用「完整配置」导出再导入，连平台授权都会带过去，新手机上几乎不用重配；只导歌单 JSON 则适合把清单分享给别人或做轻量备份。有用户反馈过外部导入的歌单偶有个别曲目匹配失败，缺的条目手动搜一下补上即可，歌单结构不会丢。

## 音频文件的搬运

已下载歌曲存放在应用的下载目录里（在「设置 → 下载管理」能看到全部内容），换机时整个目录拷到新手机对应位置，或在新手机上重新在线下载。本地音乐更简单——它们本来就在你自己的存储里，文件管理器搬完，媒体库重新扫一遍就认回来了。

两条路线不冲突，平时开着自动同步、大更新前再导一份完整配置，是最稳的组合。还没安装应用的话，[NeriPlayer 介绍站](https://neriplayer.yoan.quest/)有安装文件资源的获取入口与完整的功能介绍；想先了解这个应用是什么，读这篇：[音理音理是什么应用](音理音理是什么应用.md)。
