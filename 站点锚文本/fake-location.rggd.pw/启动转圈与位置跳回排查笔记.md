# 启动转圈与位置跳回排查笔记

用虚拟定位工具最常见的两类「翻车」现场：一是点下启动后按钮一直转圈，二是模拟明明成功了、过一会儿又自己跳回真实位置。这篇按现象拆原因，把授权之外的那些坑逐个过一遍。

相关文档：[模拟位置授权设置全流程](模拟位置授权设置全流程.md)、[单点路线与独立模拟怎么选](单点路线与独立模拟怎么选.md)

---

## 现象一：点启动后一直转圈

转圈不等于失败，它多数时候是在等某个授权。按顺序核对：

1. **模拟位置应用选对了没有**——免 ROOT 路线依赖开发者选项里的指定，选漏了或选成了别的应用，请求会一直悬着。
2. **root 管理工具放行了没有**——ROOT 模式下，首次启动模拟时会向 root 管理器申请授权；如果把它藏在隐藏名单里，授权弹窗永远出不来，转圈也就不会停。
3. **切到后台直接看位置**——有相当一部分转圈只是提示动画没刷新，后台的位置其实已经变了。先验证再下结论，能省掉一轮无意义的重试。

## 现象二：目标应用里位置纹丝不动

排除了系统授权问题之后，重点查这三处：

- **应用分身 / 双开**：双开环境有独立的定位配置，主系统里做的模拟位置授权对它无效。需要在分身里用虚拟定位的话，先把分身关掉验证主应用。
- **多个同类工具同时运行**：两个虚拟定位工具抢同一个系统接口，结果往往是互相覆盖或双双失效。只保留一个，重启手机后干净地重来。
- **目标应用读的是别的定位源**：有些应用不只看 GPS，还参考基站、WiFi。单改 GPS 坐标对这类应用可能不够，可尝试应用内的基站与 WiFi 环境伪装选项。

## 现象三：过一会儿跳回真实位置

这是典型的「后台服务被系统回收」，不是应用坏了：

1. 把 Fake Location 加入电池优化白名单（设置 → 应用 → 电池 → 不受限制 / 无限制，各机型叫法略有差异）。
2. 在最近任务里把应用锁定，防止一键清理误杀。
3. 内存特别紧张的设备，运行大型应用时后台服务也容易被回收——跳回后重开一次模拟即可。

## 一个容易忽略的边界

部分应用会主动识别并拒绝模拟位置，这类检测与工具设置无关——即便每一步都做对了，也可能仍然被识别。这属于正常现象，不必反复折腾设置。
