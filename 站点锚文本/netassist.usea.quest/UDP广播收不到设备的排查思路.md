# UDP 广播收不到设备？安卓端排查思路

用 UDP 广播在局域网里找设备（或让设备报地址）是联调里的常用手段：不用预先知道对方 IP，发一个广播包，在线设备应答即可。真到用的时候却常遇到"发出去了、没回音"，这篇按从粗到细的顺序给一套排查清单。

## 先确认手机端发的是真广播

最常见的原因是发送目标根本不是广播地址：

- **全网广播**用 `255.255.255.255`，能覆盖本地网段，但很多路由器默认不转发，只在本网段有效；
- **定向广播**如 `192.168.1.255`，要与手机当前网段一致——手机在 `192.168.0.x` 网段时发 `192.168.1.255` 是无效的；
- 端口要和设备监听的 UDP 端口一致，收发双方各绑各的本地端口。

手机端调试时，先在工具里核对当前手机的网络地址再填广播目标。用 NetAssist 这类调试助手时，UDP 模式可以同时填远程端口和本地端口，[手机版工具的界面与填法](https://netassist.usea.quest/)参考对应介绍站会更直观。

## 逐项排查清单

按命中率从高到低：

1. **不在同一网段**：手机连了访客网络或 5G 频段的独立子网，设备在主网段，广播跨不过去。把手机和设备连到同一路由器的同一网段再试。
2. **AP 隔离**：不少路由器（尤其公共 WiFi、酒店网络）默认开 AP 隔离，无线设备之间互相不可见，广播全被拦。进路由器后台关掉，或换热点试。
3. **手机用了流量/热点**：手机开移动数据时，广播发到的是蜂窝网络里的无效地址；开热点给设备连时方向反过来，确认设备真连上了这个热点。
4. **设备端口没对上**：设备固件监听的端口与发送目标端口不一致，或设备只应答特定内容格式的探测包。抓不到线索时，先用文本格式发一条设备文档里写的探测指令试试。
5. **路由器拦组播/广播**：部分路由器安全策略会过滤 UDP 广播，换个路由器或用手机热点做最小环境验证。

## 验证顺序建议

与其一遍遍改设备端固件，不如先在手机端搭一个最小环境：手机开热点 → 设备连热点 → 手机发广播。这个环境里没有路由器策略干扰，如果这样能收到应答，问题就锁定在路由器配置；如果收不到，再回头查设备固件的 UDP 监听是否真的启动。

广播能通之后，设备地址就拿到了，后续走 TCP 单播精确控制即可，做法见 [安卓手机上怎么做 TCP 调试](安卓手机上怎么做TCP调试.md)；物联网模块从配网到联调的完整链路整理在 [ESP8266 用手机配网联调的方法](ESP8266用手机配网联调的方法.md)。
