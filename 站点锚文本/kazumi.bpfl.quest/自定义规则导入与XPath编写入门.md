# 自定义规则导入与 XPath 编写入门

> 这篇讲 Kazumi 的"规则"从哪里来、怎么装进应用、失效了怎么换——这是它和一般播放器最不一样的地方。
> **相关文档**：[弹幕超分与播放设置调优.md](弹幕超分与播放设置调优.md) · [时间表追番与多端同步玩法.md](时间表追番与多端同步玩法.md)

---

## 一、规则在 Kazumi 里扮演什么角色

Kazumi 本身不带片库：你看到的番剧列表、每一集的播放地址，都来自一条条"规则"——规则用选择器描述某个资源站的页面结构，应用照着它去取数据。所以"换片源"在这套应用里，本质上就是换一条规则。

安装完成后，内置规则可以在「我的 → 规则管理」里直接看到。多数人要做的第一件事不是动手写，而是把现成规则导进来；想先看整体形态，[Kazumi 规则玩法与安装指引](https://kazumi.bpfl.quest/) 有图文版的整理。

## 二、导入规则：三个入口

在规则管理页点「添加规则」，有三个来源可选：

| 入口 | 适合场景 | 操作要点 |
| --- | --- | --- |
| 规则仓库 | 大多数人 | 仓库建在 GitHub 上（`github.com/Predidit/KazumiRules`），逐条浏览后直接导入 |
| 剪贴板 | 拿到了别人分享的规则文本 | 先复制规则 JSON，再选剪贴板导入 |
| JSON 文件 | 批量备份或换机迁移 | 选中本地规则文件，一次导入多条 |

导入后列表里立刻能看到新规则；同名的规则建议先删旧的再导新的，避免播放时用错。

## 三、想自己写：五行选择器就够

一条规则最多由五行基于 XPath 语法的选择器构成，大致对应这几类字段：

```text
SearchURL     搜索请求的地址模板
SearchList    搜索结果列表的容器路径
SearchName    条目标题的提取路径
ChapterList   分集列表的容器路径
ChapterRoads  播放线路的提取路径
```

动手前有两点先知道：

1. 目前只支持以 `//` 开头的选择器，语法支持并不完整——照着示例规则改，比从零写稳得多；
2. 页面路径用浏览器开发者工具定位元素后就能取到，改完在应用里立刻可以试搜一次。

每个字段的详细写法，项目文档站的规则开发页讲得最细：[kazumi.app/docs/rules/develop-rules](https://kazumi.app/docs/rules/develop-rules/)。

## 四、规则失效了怎么换

资源站改版后，原规则取不到数据是最常见的问题，对应解法也是现成的：

- **换规则**：回规则仓库找维护者更新的版本，删旧导新即可；
- **改规则**：只在个别字段失效时，进编辑器改对应那一行选择器。

两种做法都不需要等应用发新版本——这正是把片源逻辑做成规则的用意。写规则时踩坑的情况，多半和选择器语法有关，回第三节对照字段即可。

## 五、检索正常，就是放不出来

先试这个开关：把该规则的「使用内置播放器」关掉，应用会改用 webview 播放，兼容性更好。代价是 webview 下弹幕体验打折，所以内置播放器能放的番，还是建议开着它看。

播放相关的档位与参数（超分、弹幕样式、缓存），见 [弹幕超分与播放设置调优.md](弹幕超分与播放设置调优.md)。
