# 修补后的应用装不上的原因

> 修补跑完了，新包却装不上——签名不一致、点了没反应、找不到产物，是最常撞上的三件事。本篇按现象对号入座。
> **相关文档**：[免Root怎么用Xposed模块.md](免Root怎么用Xposed模块.md) · [便携模式和本地模式怎么选.md](便携模式和本地模式怎么选.md)

## 一、提示「签名不一致 / 应用未安装」

最常见的原因：手机上还留着同名的原版应用。修补产物经过重新签名，与原版签名不同，系统不允许两者共存。

处理顺序：

1. **先备份原应用的本地数据**（聊天记录、存档等，卸载后不可恢复）；
2. 卸载原版应用；
3. 再安装文件名带 `lspatched` 字样的修补产物。

同一批应用里，微信这类会被其他应用「拉起」的高频应用还要多想一步：修补版上「微信登录 / 分享 / 支付」等场景可能失效，替换前先权衡。

## 二、点「安装」没反应，或提示 Shizuku 未连接

修补完成后在管理器里直接点「安装」，这条路依赖 Shizuku 服务；没连接时它会提示失败——这不是修补坏了。

两条路任选：

- 部署并启动 Shizuku，回到管理器重试应用内安装；
- 直接放弃这条路：用文件管理器进入修补时设置的输出目录，手动点开产物 APK 安装。手动路不依赖任何服务，最稳。

## 三、找不到修补产物

产物落在你首次修补时选定的输出目录里。找不到时按顺序核对：

1. 输出目录是不是当时选的那个文件夹（文件名统一带 `lspatched` 字样，可全盘搜索确认）；
2. 当初没选过目录的，回管理器重新发起一次修补，第一步会重新让你选；
3. 修补中途报错（日志出现 `Failed to read zip file` 之类）的，多半是安装包本身被动过——换未经处理的原始安装包重修。

## 四、装上了但打不开、闪退

这已经不是「装不上」，而是兼容问题，常见解法按序尝试：

1. 换一种修补模式重修（便携 ↔ 本地）；
2. 换目标应用的旧版本安装包重修——个别新版本加了完整性校验或加壳，旧版成功率更高；
3. 反复换法仍不行，接受这个应用修不了：免 Root 方案的能力边界摆在那里。

模块装上却不生效的排查思路，在[免Root怎么用Xposed模块.md](免Root怎么用Xposed模块.md)；修补前的模式取舍见[便携模式和本地模式怎么选.md](便携模式和本地模式怎么选.md)。这两篇与更多图文整理，都收录在 LSPatch 说明站（[https://lspatch.yoan.quest/](https://lspatch.yoan.quest/)）。
