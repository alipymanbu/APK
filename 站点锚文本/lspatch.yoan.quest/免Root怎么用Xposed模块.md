# 免 Root 怎么用 Xposed 模块

> 想在安卓上用 Xposed 模块，最劝退的一关向来是 Root。本篇讲一条绕开 Root 与解锁 Bootloader 的路线：用 LSPatch 把模块直接「缝」进目标应用。
> **相关文档**：[便携模式和本地模式怎么选.md](便携模式和本地模式怎么选.md) · [修补后的应用装不上的原因.md](修补后的应用装不上的原因.md)

## 一、传统方案卡在哪

Xposed 框架的原理是在系统层面挂载钩子，让模块有机会改写应用的行为。这套机制在老方案里依赖 Root 权限：先解锁 Bootloader、刷入框架，才能让模块生效。门槛与风险都摆在那里——解锁丢保修、刷机有变砖概率、银行类应用还会检测环境直接拒绝运行。

## 二、免 Root 路线的思路

LSPatch（LSPosed 生态的衍生物）把方向反过来：**不动系统，只改单个应用**。它把框架组件与勾选的模块一起注入目标应用的 APK，重新打包签名后安装。修补后的应用自带运行环境，启动时在应用内部完成模块加载，全程不需要 Root，也不需要解锁 Bootloader，最低支持 Android 9。

换句话说，传统方案是「给整部手机开框架」，LSPatch 是「给某一个应用开框架」——粒度更细，代价也更可控：哪个应用修补失败，影响的也只是那一个应用。

## 三、适合谁用

- 手机不能解锁 Bootloader、或不想失去保修，但想用模块给某个应用加功能；
- 只有一两个应用需要模块，为它们刷整机的框架不划算；
- 想先把修补产物发到另一台设备上直接用（这要选便携模式，取舍见相关文档）。

也有一类需求不适合它：想给系统级组件（状态栏、系统动画等）加模块的，免 Root 路线覆盖不了，那些模块的作用域不在单个应用上。

## 四、从哪入手

整体动作链是：装管理器 → 选目标应用与模式 → 修补 → 卸原版装新包。每个环节的细节，LSPatch 说明站（[https://lspatch.yoan.quest/](https://lspatch.yoan.quest/)）按原理、模式、流程、排错分了区块，照着走一遍就能跑通第一条修补链。

修好装不上、装上闪退这类收尾问题，先看[修补后的应用装不上的原因.md](修补后的应用装不上的原因.md)；模式拿不定主意，看[便携模式和本地模式怎么选.md](便携模式和本地模式怎么选.md)。
