# FunBox 安装前提与免 Root 疑问

> 装 FunBox 之前先确认环境：它需要 Root + LSPosed 框架；不想 Root 的"内置版"路线差别在哪、风险在哪，这篇一次说清。
> **相关文档**：[模块用法与面板呼出.md](模块用法与面板呼出.md) · [表情包与语音包玩法.md](表情包与语音包玩法.md)

FunBox 的身份先摆正：它不是独立聊天软件，而是 LSPosed（Xposed）框架里的模块，前身叫 HaveFunPanel，4.0.0 起改名。第三方插件仓库的收录信息标注开发者为 Hicores，收录包名为 `have.fun`。功能全貌与界面截图见 [FunBox 模块介绍站](https://funbox.laze.skin/)。

## 一、常规路线需要什么

| 前提 | 说明 |
| --- | --- |
| 已 Root 的手机 | LSPosed 一般通过 Magisk / KernelSU 这类 Root 方案安装 |
| LSPosed 框架 | 模块在里面启用、勾作用域；框架太旧时先升级 |
| 微信 / QQ 本体能正常登录 | 模块只在你勾选的应用内生效，本体异常先解决本体 |

安装与激活动线：安装 apk → 给悬浮窗与存储权限 → LSPosed 启用模块 → 作用域勾微信 / QQ（用哪个勾哪个，作用域越小越稳）→ 强制停止聊天应用或重启手机。重启这步不能省：模块在聊天应用进程启动时注入，旧进程不重启，勾了也不生效。

装完在微信「我 → 设置」里找面板入口；入口出现后的日常用法见 [模块用法与面板呼出.md](模块用法与面板呼出.md)。

## 二、免 Root 的"内置版"是什么

社区流传把模块嵌进微信 / QQ 安装包的免 Root 路线：装的是被第三方重新打包、预装了模块的聊天软件本体，不是模块本身。它和常规路线的差别：

| | 常规路线（模块本体） | 内置版路线 |
| --- | --- | --- |
| 前提 | Root + LSPosed | 不需要 Root |
| 装的是什么 | 独立模块 + 原版微信 / QQ | 被第三方动过的聊天软件本体 |
| 更新 | 模块与聊天软件各自独立 | 想换版本要等重新打包的整包 |
| 信任成本 | 来源各自清晰 | 内容全凭打包者 |

分发渠道对内置版写明的注意事项包括：内置版微信不与原版共存（装前先卸载原版）、不支持从别的应用跳转微信、安装前务必备份聊天记录、使用期间不要自行升级微信版本。这四条每一条都在压缩正常使用的空间。

## 三、把风险压低的几件事

- 作用域只勾微信 / QQ，不勾「系统框架」和不相干的应用；
- 拿常用小号先试跑几天，真有风控损失可控；
- 不在模块生效的客户端里登录支付、银行类应用——这类应用会检测运行环境；
- 折腾降级、重装前先用微信自带的「聊天记录备份与迁移」备份；
- 开发者早在 v5.3.0 就移除了自动抢红包功能，这类自动化操作是风控重点，别找替代实现。

## 四、几个高频疑问

**Q：手机不想 Root，还有别的办法吗？**
只有上面说的内置版路线，约束与风险都在第二节，接受前先想清楚值不值。

**Q：聊天软件更新后模块失效怎么办？**
先停用模块确认本体正常，再等模块更新适配；不建议回退微信 / QQ 版本硬扛，回退丢数据的风险更大。

**Q：模块装在哪些应用里生效？**
作用域里勾谁就对谁生效，微信、QQ 都支持，收录信息里还提到 TIM；分身应用不一定自动出现在作用域列表，需要手动加包名。

装好之后怎么用，见 [模块用法与面板呼出.md](模块用法与面板呼出.md)；面板里存表情、录语音的具体玩法见 [表情包与语音包玩法.md](表情包与语音包玩法.md)。
