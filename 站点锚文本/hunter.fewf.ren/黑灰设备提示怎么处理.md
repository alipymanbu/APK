# 黑灰设备提示怎么处理

> 结论页给出「黑灰设备」一类判定时，这句话到底在说什么、逐条怎么对照、三种情况分别怎么处理。
> **相关文档**：[检测项逐条解读.md](检测项逐条解读.md) · [root隐藏后怎么验证过没过.md](root隐藏后怎么验证过没过.md)

## 一、这句话在说什么

「黑灰设备」是对「这台设备的环境存在异常特征」的汇总性判定，列的是机器上能查到的客观痕迹，不是对机主的定性。要看懂各检测项分别指向什么，先过一遍 [检测项逐条解读.md](检测项逐条解读.md) 的对照表。

## 二、常见触发原因对照

| 报告提示 | 通常指向 |
| --- | --- |
| 不支持 Attestation 或 AndroidKeyStore 被破坏 | 老机型或精简 ROM 上常见 |
| 可能是模拟器 / 云手机 | 参数与真机不符，多开分身也会造出这种环境 |
| 机型 ROM 可能被修改 | 刷过第三方 ROM、动过系统分区 |
| 查找 rwx 条目 | 存在可读写执行的挂载项，多与 Root 方案残留有关 |
| 设备指纹可能被修改 | Android ID、MAC 一类标识与预期不符 |

另外首页偶尔弹的「电池异常」这类单条提示，报的是状态而非痕迹，单独出现不构成环境判定，复测一次看是否复现即可。

## 三、分三种情况处理

**情况 A：确实改过系统（Root、刷机、装过框架）**
提示是如实记录。要回到干净状态，标准做法是重刷官方固件：解锁过的重新刷入官方镜像（先备份个人数据），刷完复测。

**情况 B：什么都没改，提示依旧**
按顺序排除：确认版本一致 → 换时间复测 → 查机型是否二手带改动 → 结合报告里的可疑路径到本机核对。

**情况 C：本来就在模拟器或云手机里跑**
前两条提示属于预期结果，不是故障；要测真机就把包装到实体手机上再扫。
