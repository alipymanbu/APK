# Qoder CN 远程控制与云端任务：两条链路怎么选

> 本篇讲 Qoder CN 手机端接入任务的两种方式——远程控制与云端任务：原理、前提、发起步骤与选择思路。
> **相关文档**：[手机端能做什么.md](手机端能做什么.md) · [下载安装与账号配置.md](下载安装与账号配置.md)

---

## 一、一句话区分

- **远程控制**：电脑干活、手机指挥——电脑必须开机且任务在跑，产物留在电脑里；
- **云端任务**：云端干活、电脑随意——任务跑在云端环境，产物推回 GitHub 仓库，电脑关机都不影响。

两条链路在手机列表里并排显示，看进度、审批、追问的操作完全一致；区别只在电脑要不要在线、代码落在哪。

## 二、远程控制：临时离开工位

**CLI 会话模式**（已开着 `qodercn` 会话、人要走开）：

1. 会话里输入 `/remote-control`，屏幕给出二维码与 URL；
2. 手机相机扫码（或把 URL 复制到手机浏览器打开）；
3. 同账号的手机端会话列表里出现这条连接，即可看进度、审批、下发新任务；
4. 回到电脑前，`/remote-control stop` 断开，`/remote-control status` 查状态。

**守护进程模式**（让电脑挂着待命、随时接单）：项目目录直接跑 `qodercn remote-control`，同样扫码连接；手机端点「+」连发多个任务，不用等上一个做完，CLI 会顺序或并行处理，产物都落在跑 CLI 的那台电脑上。

前提只有三条：电脑活着、两端同账号、网络都通。断连后手机会看到任务停在最后同步的状态——不是 App 坏了，电脑恢复后重扫一次即可。

## 三、云端任务：手边没电脑

1. 新建任务时把运行环境切到 `Cloud`；
2. 关联 GitHub 账号，挑这次要改的仓库与分支——选错分支改动会落到别的代码上；
3. 写清需求发送，任务在云端环境执行，进度与本地任务并排显示；
4. 跑完后改动以 Diff 形式给出，手机上先翻关键改动，确认后再回电脑走合并流程。

私有仓库列表里找不到目标仓库时，是授权范围问题：点 **Manage repository access**，去该仓库安装对应应用完成授权，回来重新选即可。

## 四、怎么选

| 场景 | 选哪条 |
|---|---|
| 任务已开着，临时开会 / 吃饭 | 远程控制 |
| 通勤、出差，手边只有手机 | 云端任务 |
| 产物要留本地电脑 | 远程控制 |
| 代码不落地、直接进仓库 | 云端任务 |

额度方面两条链路一致：手机上发的任务和电脑上跑的任务从账号同一份 Credits 里扣，个人版各端共享，不存在「手机再付一次钱」。

两条链路的前提都是手机端已装好、登录成功——还没装的从[下载安装与账号配置.md](下载安装与账号配置.md)开始；想先了解整体能力，读[手机端能做什么.md](手机端能做什么.md)。界面与操作入口的图文对照，见 [Qoder CN 手机端介绍站](https://qoder-cn.wrwq.fun/)。
