# Auto.js 停更之后怎么选？安卓自动化开源续作对比

> 本篇讲清 Auto.js 2020 年停更后的几条开源延续路线，以及各自主打什么、适合谁；想直接看某个续作的完整介绍与装机步骤，可跳到 [AutoJs6 介绍站](https://autojs6.ggcd.online/)。相关阅读：[安装包架构区别与选择](安装包架构区别与选择.md)、[手机脚本自动化场景与第一段代码](手机脚本自动化场景与第一段代码.md)。

## 先弄清楚：为什么会有"续作"

Auto.js 由 hyb1996 在 2017 年 1 月发布，是安卓平台上最早把「无障碍服务 + JavaScript」组合起来的自动化工具之一。2020 年 3 月，开源版本停在 4.1.1 alpha2 不再更新；作者转向的后续版本走付费、闭源路线，并对部分主流应用做了限制。

于是社区里长出了两条主要的开源延续路线：一条以 Auto.js 4.1.1 的原始代码为底子继续修；另一条同样从这份代码出发，但按自己的节奏重做与扩展。AutoJs6 属于后者：SuperMonster003 从 2021 年 12 月起在 4.1.1 开源版本基础上二次开发，采用 MPL-2.0 许可证，到今天仍在持续迭代。

## 两条路线的差别

**延续 4.1.1 手感的路线**（如 Autox.js）：版本号从 4.x 直接往上走，API 与老教程的兼容性好，网上大量旧脚本稍改就能跑；适合手里已经攒了一批旧脚本、只想换个还能维护的环境的人。

**重做扩展的路线**（如 AutoJs6）：一边保持对旧 API 的大体兼容，一边把引擎、模块体系、文档站重新梳理。6.x 系列陆续加入 OCR 文字识别、条码二维码、Shizuku 等模块，并把夜间模式、多语言这类体验层面的东西当成重点来打磨；适合愿意从头系统学一遍、想要文档齐全的人。

## 对比时值得看的四个维度

1. **开源许可与免费程度**：是否基于开源版本、许可证是否明确（MPL-2.0 / GPL 等），决定它会不会哪天突然加付费墙。
2. **维护活跃度**：更新日志是否持续滚动、文档站是否还在更新——自动化工具与系统版本强相关，停更就意味着新系统上随时失效。
3. **脚本兼容性**：旧脚本多就挑贴近 4.1.1 行为的；从零开始则不必背这个包袱。
4. **特色能力**：比如选择器手感（拾取选择器、控件罗盘）、OCR、打包 APK 的完整度，这些差异点决定写脚本的顺手程度。

## 一个简单的结论

手里有一堆旧脚本要救 → 优先试贴近 4.1.1 的延续版本；从零开始、想要文档与模块齐全 → AutoJs6 这条重做扩展的路线更省心。它的功能清单、实机截图与安装步骤，见 [AutoJs6 介绍站](https://autojs6.ggcd.online/)；装之前建议先弄清[安装包架构区别与选择](安装包架构区别与选择.md)。
