# webcat 把网页打包成安卓应用的过程

用 webcat 做好的网页，最后一步往往不是「存着」，而是变成一个能发给别人、能装进手机的应用——它自带打包功能，网页项目可以直接出安卓安装包，包名、图标、版本号都能自定义。这篇把这条路从头到尾说清楚；还没跑通页面的先看 [webcat怎么新建工程和运行预览](webcat怎么新建工程和运行预览.md)。

## 打包前：把页面在预览里跑通

打包出的应用行为和预览里基本一致，所以装到手机上才发现问题，多数在预览里也能看到。动手打包前过一遍：

- 页面在预览里能正常打开，交互（按钮、表单、动画）都响应；
- 引用的 CSS、JS、图片都在工程内部，路径正确；
- 如果页面依赖联网接口，想清楚装到别人手机上断网时的表现。

## 打包：自定义三项，一键出包

进入工程文件列表，点**打包**（5.21 的界面上与「新建文件」「导入文件」并列的那个入口）。打包时主要自定义三样：

| 自定义项 | 说明 |
| --- | --- |
| 包名 | 应用的唯一标识，如 `com.example.myapp`；别和手机上已装的应用重名，否则系统会当成覆盖安装而拒绝 |
| 图标 | 装到桌面后显示的图，选一张方图即可 |
| 版本号 | 后续更新时递增，方便区分新旧包 |

确认后应用在本地完成打包，产物就是一个安卓安装包。发给别人或传到自己其他手机上，按普通安装包的流程装（第一次安装同样要在来源授权里允许一下）。

## 装不上？三个高频原因

1. **来源授权没放行**：系统提示「禁止安装来自此来源的应用」时，进对应来源（文件管理器或浏览器）的设置里允许安装，返回重装；
2. **包名冲突**：打包时填的包名恰好和手机上某个已装应用相同，系统拒绝覆盖——换一个没被占用的包名重新打包；
3. **存储空间不足**：安装包加解压都需要空间，先清出几百 MB 再试。

## 打包之外的进阶玩法

- **想给应用加 AI 能力**：新的 WebCatX 版本线内置 AI 助手，可以直接让 AI 生成和改代码，打包功能同样具备——两条版本线的取舍写在 [webcat手机代码编辑器功能盘点](webcat手机代码编辑器功能盘点.md)；
- **想要更完整的原生调用**（相册、扫码、分享等）：新版线的原生能力桥更直接，按需求选版本线；
- **页面有更新**：改完重新打一个包、版本号递增，覆盖安装即可。

整个过程不需要电脑、不需要开发环境，一部手机从写页面到出安装包是闭环的。功能与界面实拍可到 [WebCat 介绍站](https://webcat.laze.skin/) 对照查看。
