# 用 OpenClaw 要花多少钱：费用构成与模型选型

> 关心账单之前先分清两笔钱：项目本身和模型用量。本篇把费用构成说清楚，再给一份按场景选模型的参考。
> **相关文章**：[部署网关与首次引导.md](部署网关与首次引导.md) · [安全风险与权限收紧.md](安全风险与权限收紧.md)

## 一、两笔账分开算

**项目本身**：OpenClaw 是 MIT 协议的开源项目，没有订阅、没有托管套餐，代码公开可查，装多少台机器都不收授权费。

**模型用量**：这是唯一持续的开销——助手的每次理解和回答都调你接的大模型 API，按 token 计费，由模型供应商收。项目常见问题给的量级参考：个人自用每月大约 5~20 美元（截至 2026 年，随任务量浮动）。

## 二、按场景选模型

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 先试试水 | 低档位模型 | 跑通流程最重要，账单压力最小 |
| 日常问答、提醒、摘要 | 中小档位 | 日常任务对推理深度要求不高 |
| 写代码、长文处理 | 高档位 | 复杂任务的质量差距明显，注意用量 |
| 完全不想接云 API | 本地部署模型 | 零按量账单，但对机器配置要求高，质量有折损 |

选型可以随时换：配置里改模型名就行，建议日常挂低档、干重活再切高档，这是最直接省钱的习惯。

## 三、钱都花哪儿了：隐形消耗排查

发现用量比预期高，按这个顺序查：

1. **心跳任务**：默认每 30 分钟自动跑一轮，哪怕你一整天没说话也在烧 token——不需要就把 `agents.defaults.heartbeat.every` 设为 `"0m"`；
2. **定时任务**：早报、巡检这类主动汇报都是模型调用，留真正有用的；
3. **大任务一锅炖**：一次塞几千封邮件，既烧 token，长对话触发自动压缩后还可能把规矩挤丢——分批做，两头都省；
4. **来回追问**：下指令前先想清楚要什么，一轮说清比五轮来回便宜。

控制台里有用量统计，定期看一眼，异常波动早发现。

## 四、一笔总账

以「日常挂中低档模型 + 关掉不必要心跳 + 每天几十轮对话」的典型用法估算，月支出大概率落在项目 FAQ 给的 5~20 美元区间内；把重活全丢给它跑的重度用法另算。想控制预算，从心跳和定时任务下手最快。

工具本身的获取方式与部署步骤，见[部署网关与首次引导.md](部署网关与首次引导.md)；安卓应用的下载入口整理在 [OpenClaw 介绍站](https://openclaw.fewf.ren/)。
