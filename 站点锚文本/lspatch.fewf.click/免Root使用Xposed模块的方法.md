# 免Root使用Xposed模块的方法

> 本篇讲在手机不 Root、不解锁 Bootloader 的前提下，怎么让 Xposed 模块真正跑起来：原理靠什么、需要准备什么、装好之后怎么确认生效。
> **相关文档**：[修补应用的完整步骤与模式选择.md](修补应用的完整步骤与模式选择.md) · [修补版应用的更新与数据备份.md](修补版应用的更新与数据备份.md)

## 一、为什么免 Root 也能玩模块

Xposed 模块的传统玩法依赖系统层框架：要么 Root 后装框架，要么解锁 Bootloader 刷进去，门槛和风险都不低。LSPatch 换了一条路——不动系统，而是对目标应用本身做「修补」：把框架加载器写进应用的 APK，应用启动时在自己内部把模块带起来。

也就是说，模块不再是全局生效，而是「哪个应用被修补过，模块就对哪个应用起作用」。对只是想给某一两个应用加功能的玩家来说，这个粒度反而更合适，代价也更小：大不了卸掉修补版重装原版，系统本身毫发无伤。

## 二、动手前的三样准备

| 准备 | 说明 |
| --- | --- |
| 管理器 | LSPatch 的手机端是一个独立应用，负责发起修补、管理产物 |
| 目标应用 | 想加功能的那一个应用：已装在手机上，或手里有它的 APK |
| 模块 | 也是一个 APK，先装到手机上待命（便携模式修补时从列表里勾选） |

系统要求是安卓 9 及以上；修补生成的应用也会以安卓 9 为最低支持线。具体的获取与安装步骤，整理在 [LSPatch 免 Root 修补工具介绍站](https://lspatch.fewf.click/) 的下载安装页，这里不展开。

## 三、生效的原理一句话

修补工具对目标 APK 做了三件事：改写应用清单让框架组件先行启动、把加载器（dex 与 so）注入包内、用新签名重新打包。应用一启动，加载器先跑起来，再把勾选的模块挂进应用进程——模块的钩子就这样在不碰系统的前提下生效。

也正因为签名变了，修补版与原版不能共存，这引出了几乎所有新手都会撞上的两件事：必须先卸载原版、商店更新会失效。这两件事的处理思路在 [修补版应用的更新与数据备份.md](修补版应用的更新与数据备份.md) 里有完整说明。

## 四、装好之后怎么确认模块在跑

- 打开修补后的应用，进它的设置页，多数模块会在这里出现自己的入口或「已激活」字样；
- 没有独立入口的，直接看功能面：模块该改的地方变了，就是生效了；
- 没生效的，按模式回查——便携模式看修补时是否真的勾了「嵌入模块」，本地模式看管理器里的作用域和管理器是否还在后台活着。

修补环节的完整操作链（含两种模式怎么选），见 [修补应用的完整步骤与模式选择.md](修补应用的完整步骤与模式选择.md)。
