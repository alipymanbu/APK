# JanitorAI 聊久了忘事：消息限制警告的真实含义与三个解法

> 本篇讲清 JanitorAI 长聊天里「消息限制」警告到底是什么、角色为什么开始忘事，以及不动钱包能做的三件事。
> **相关文档**：[角色卡创建与开场白写法.md](角色卡创建与开场白写法.md) · [中文对话设置方法.md](中文对话设置方法.md) · [安卓客户端安装步骤.md](安卓客户端安装步骤.md)

---

JanitorAI 的长聊天里会弹出一条像是「消息用完了」的提示，很多人以为被限流了。按多方核对的结果：**免费的内置模型没有每日或单聊条数上限**，这条提示说的是另一件事——你的聊天总长度超过了模型一次能读进的文本量（上下文窗口，约 8000~9000 token），最老的内容开始被挤出去。你还能继续发消息，只是角色「记得的事」在变少。

顺带两个数字：免费模型的上下文约 8k~9k token，高峰时段会被临时压小——所以「昨晚还好好的，今晚突然变笨」多半是这个原因；聊得太长开始忘事，也和这个窗口直接相关。背景与玩法不熟的，可以先翻整理了平台机制介绍的 [JanitorAI 介绍站](https://janitorai.fwen.ren/)。

## 为什么会忘：两类内容在抢同一块地方

每次发消息，系统会把这些打包给模型：角色的人格与场景、你的 Persona、**Chat Memory 框里的摘要**（以上是「永久内容」，每条消息都带）、加上最近的聊天记录。空间不够时，**最先被挤掉的永远是最老的聊天记录**——你们怎么认识的、第一幕发生了什么，最先消失。

| 症状 | 多半是因为 |
| --- | --- |
| 聊二三十条后开头的事开始模糊 | 正常淘汰，记录被挤出窗口 |
| 才聊几条就忘 | 角色卡太重，还没开聊就占掉大半空间 |
| 角色突然不按人设说话 | 永久内容堆得太高，模型读不全人设 |
| 明明聊过的事只记得大概 | Chat Memory 摘要写得太笼统 |

## 不花钱的三个解法

### 1. 给角色卡减负

把 Personality 里「其实模型每次都需要」的长篇背景砍成要点，判据很简单：删掉这段，角色说话会不会变个人？不会就删。字段取舍见[角色卡创建与开场白写法](角色卡创建与开场白写法.md)。

### 2. 用好 Chat Memory

聊天设置里的 **Chat Memory** 框，内容算永久项、每条消息都带着走——这是你能主动保住的「存档」。写法要领：只列事实不写场景、全篇统一时态、每条一短句。参考结构：

```text
Environment:          （当前在哪、什么氛围）
Relationship Dynamic: （你们现在什么关系）
Current Plot Points:  （正在推进的事）
Important Past Events:（影响后续的大事件）
```

写成小作文等于自己把窗口占满。

### 3. 主动让模型做小结

聊到一个章节结束，直接发一条场外指令让它交总结，拿到的摘要贴进 Chat Memory：

```text
[OOC: 暂停剧情，用几句话总结从酒馆冲突开始的全部关键事件与影响]
```

相当于章节存档：几十上百条的长篇，靠一次次小结把关键事实留在窗口里，比指望模型自己记住划算得多。

## 什么时候才值得换模型

上面三招做完，健忘仍是长篇连载的硬约束——窗口就那么大。真要根治只有两条路：平台付费档（宣称数倍上下文），或接中文与记忆都更强的外部模型。换之前先把三件事做完，不然再大的窗口也会被过重的角色卡吃掉。中文回复质量与模型选择的关系，另见[中文对话设置方法](中文对话设置方法.md)。
