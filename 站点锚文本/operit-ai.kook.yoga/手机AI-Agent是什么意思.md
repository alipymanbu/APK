# 手机AI-Agent是什么意思

本篇解释「AI Agent」这个词落到手机上到底指什么：它和普通 AI 聊天应用差在哪、为什么2025年之后安卓上突然冒出一批 Agent 应用、以及判断一个 Agent 是不是"真能干活"的几个硬指标。文末附一个完整落地的开源例子。

---

## 从「会聊」到「会做」

普通 AI 应用回答问题，靠的是把文字生成出来；AI Agent 则是把大模型接到一堆"工具"上——查资料、读写文件、执行命令、点按界面——模型决定调哪个工具、传什么参数，然后把结果交回来继续推理。所以同样的提问"帮我把这段录音转成文字"，聊天应用会给你一份操作教程，Agent 会直接调工具把活干完。

这个形态在电脑上已经跑通了好几年，手机上慢了一步，卡点不在模型，而在"手脚"：安卓对后台执行、系统权限、跨应用操作管得严，普通应用拿不到那么多执行通道。

## 手机 Agent 靠什么"动手"

目前安卓上真正能落地的执行通道大致三条：

- **无障碍服务**：读屏幕元素、模拟点击滑动，这是不刷机前提下最通用的自动化通道；
- **ADB / Shizuku**：借开发者调试能力拿到更高权限，能做装卸应用、冻结应用这类系统级操作；
- **Root**：权限最全，门槛和风险也最高，日常并不必需。

一个 Agent 应用支持哪几条通道、授权分级做得细不细，基本决定了它的能力上限。评测一个手机 Agent 时，比"接了多少个模型"更要紧的问题是：它能不能稳定地替你点屏幕、跑脚本、动文件。

## 本地推理：另一条分水岭

2025 年起 MNN、llama.cpp 等推理引擎在安卓上逐渐成熟，中高端手机跑 1.5B～7B 的量化模型已经可用。这意味着 Agent 的"大脑"可以搬进手机——离线可用、对话数据不出设备，代价是速度受硬件限制。能不能同时接云端 API 和本地模型，成了区分玩具和工具的又一条线。

## 一个完整的落地样本

安卓社区里常被拿来拆解的开源项目 Operit AI，就是把上面几件事压进了一个安装包：内置 Ubuntu 终端当执行环境，无障碍加 Shizuku 当操作通道，云端 Key 与本地 GGUF 双模接入，再用插件和工作流把能力串成任务。[Operit AI 介绍站](https://operit-ai.kook.yoga/)按它的真实上手顺序整理了五步路线与客观短板，想知道这类工具装到手机上到底能干什么，从那里看最直观。
