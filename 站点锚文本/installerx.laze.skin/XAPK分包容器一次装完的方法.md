# XAPK分包容器一次装完的方法

> 拿到的不是单个 .apk，而是 .xapk / .apks / 带 OBB 数据的容器，系统安装器直接不认；本篇讲这些格式各是什么、为什么必须一次事务装完、以及装完打不开时怎么补数据。
> **相关文档**：[免ROOT接管安卓装包的完整流程.md](免ROOT接管安卓装包的完整流程.md) · [Shizuku授权装包与锁定默认安装器.md](Shizuku授权装包与锁定默认安装器.md)

## 一、先分清拿到的是哪种包

现代应用越来越多以分包形式发布，先看后缀：

| 后缀 | 里面是什么 | 系统能否直接装 |
| --- | --- | --- |
| .apk | 单个完整安装包 | 能 |
| .apks | base.apk 加按架构 / 语言 / 分辨率拆分的分包集合 | 不能 |
| .xapk | ZIP 容器：分包 APK + OBB 数据 + 描述信息 | 不能，文件管理器会当压缩包打开 |
| .apkm | 分包的另一种容器格式 | 不能 |
| .obb | 单独的游戏数据文件，不独立安装 | 装完 APK 后要放到位 |

大体积游戏最容易以 XAPK 形态出现：APK 部分是应用本体，OBB 部分是素材数据，缺一个都跑不起来。

## 二、为什么"逐个装"必失败

系统要求**全部分包在同一次安装事务里提交**——手动把容器解开、先装 base 再补分包，后装的每一次都会被系统当成"对已装应用的新安装"而失败。这就是"用支持分包的安装器"存在的意义：解析容器、自动挑包、一次提交。

## 三、用 InstallerX 装分包容器

1. 在文件管理器里点开 .xapk / .apks 文件，打开方式选 InstallerX（未接管的机型可临时用"打开方式"手动指定）；
2. 它会解析容器内容，分包自动按设备的架构与语言挑选；
3. 确认安装，整包一次事务装完。

顺带两条：

- 内含 APK 的 ZIP 压缩包同样可以直接指给它，不用先解压；
- 报 `INSTALL_FAILED_MISSING_SPLIT` 之类错误，多半是手动拆开装过一半——先卸干净再整包重走一遍。

还没接管的，先按 [Shizuku授权装包与锁定默认安装器.md](Shizuku授权装包与锁定默认安装器.md) 把授权和锁定做完。

## 四、装完打不开或提示缺数据

包装成功但应用闪退、进游戏提示重新下载数据，常见原因两条：

- **OBB 没就位**：安装器一般会把容器里的 OBB 自动放到位；仍提示缺数据时，手动解包 XAPK，把 OBB 放进手机的 `Android/obb/<应用包名>/` 目录，目录名必须与包名逐字一致；
- **架构不匹配**：包里只有 64 位分包而设备是 32 位系统（或反过来），换对应架构的包重装。

## 五、签名冲突怎么办

报签名冲突 / `UPDATE_INCOMPATIBLE`，说明设备上已有同名应用但来自别的渠道签名不同：先卸载旧版再装，卸载会清数据，重要资料先备份。与分包无关的通用安装报错（授权失败、弹系统安装页、降级被拦等），见 [免ROOT接管安卓装包的完整流程.md](免ROOT接管安卓装包的完整流程.md)；InstallerX 的功能盘点与安装文件资源入口在 [InstallerX 介绍站](https://installerx.laze.skin/)。
