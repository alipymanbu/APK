# 手机脚本打包成独立应用

用 Autox.js 写好的脚本，只能在自己手机上跑？用它的打包功能把脚本变成一个独立 APK——对方不装 Autox.js 也能用。本文讲打包流程与常见坑；工具本身从 [Autox.js 指南站](https://autox-js.hfdk.space/) 的资源入口获取即可。

## 一、打包能解决什么问题

直接跑脚本的前提是对方手机上装着 Autox.js。打包之后，你的脚本、界面、图片资源都被装进一个普通 APK，接收方只需要装这一个文件、给它开权限就行——适合把小工具发给别人，或者把自己常用的脚本整理成独立入口。

## 二、基本流程

1. 把脚本整理成一个项目文件夹（main.js 入口 + 模块与资源；单文件也能直接打）。
2. 在脚本列表对该项目点开菜单，找「打包应用」入口。
3. 填应用名称、包名、图标、版本号，按需勾选权限与「开机自启动」。
4. 选择或创建签名，点打包。
5. 产物 APK 会生成在脚本目录附近，按普通 APK 的方式安装。

配置里如果有 ABI 架构选项，主流 64 位手机选 arm64-v8a。

## 三、签名是个大事

打包需要一个签名，内置默认签名什么都能打出来。但签名是 APK 的「身份」：签名一致、包名一致，新版本才能覆盖安装旧版本。打算长期维护自己的工具，就一开始创建一个自己的签名并保管好——签名文件丢了就无法对已发布应用做覆盖更新，只能换包名重发。

## 四、产物常见问题速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装器直接失败 | 签名 / 架构与机型不匹配 | 自建签名重打；确认选了 arm64-v8a |
| 装上但点了没反应 | 打包产物也要重新授权 | 无障碍、悬浮窗、存储一项不能少 |
| 被安全软件报毒 | 无障碍 + 自动点击的行为组合易被误判 | 确认来路可信后加白名单 |
| 脚本里的图片找不到 | 图片没随项目一起打包 | 图片放项目文件夹用相对路径引用，重新打包 |

打好的应用想让它在固定时间干活，定时与保活的做法见[安卓定时任务与后台保活](安卓定时任务与后台保活.md)；还没写过脚本的话，从[无Root自动化脚本入门](无Root自动化脚本入门.md)开始。
