# 动画 JSON 和 GIF 动图有什么区别

> 同样是让画面动起来，一份 Lottie 的 JSON 文件和一张 GIF 动图，在体积、清晰度、交互性上完全是两个量级的东西。本文把两者的差异摊开讲。

在网上刷到一段顺滑的小动画，想分清它是不是 GIF，得先从两种文件存的东西说起。

## GIF：把每一帧都拍成照片

GIF 是上世纪 80 年代的位图格式，原理是"逐帧拍照"：几秒钟的动画，每一帧都被完整存成一张像素图，再打包循环播放。这带来三个绕不开的问题：

- **体积大**：每帧都是完整像素，随便一段几秒的动效就以 MB 计；
- **放大就糊**：位图拉伸必出锯齿，高分屏上尤其明显；
- **只有 256 色**：渐变过渡容易出色带，颜色一多就脏。

而且 GIF 播放起来是死的——从头循环到尾，速度、颜色、进度都改不了。

## Lottie JSON：存的不是画面，是"怎么画"

Lottie 是 Airbnb 在 2017 年开源的动画方案。动画在 After Effects 里制作，经 Bodymovin 插件导出成一份 JSON 文本——里面写的是关键帧、缓动曲线、图层信息这些"绘制指令"，由手机或网页上的播放器实时把画面画出来。

因为存的是指令而不是像素，差距就很直观了：

- **体积小**：按 LottieFiles 公开页的对比，同样动画比 GIF 小约 6 倍，加载几乎无感；
- **无限清晰**：矢量绘制，从 200px 的图标放到全屏横幅都不会糊；
- **能交互**：播放速度、进度、颜色都能在运行时改，可以跟着手势和状态走。

## 怎么快速分辨

一个简单办法：把动画放大几倍看细节。糊成马赛克的是 GIF，边缘依旧锐利的多半是 Lottie；再或者试着让动画跟着操作变化——能响应的就是 Lottie。

想在手机上亲手播一份动画 JSON、亲眼对比这两种格式的效果，可以看 [Lottie JSON 动画入门](https://lottie.ggcd.store/)，从格式原理到手机播放器都有整理。
