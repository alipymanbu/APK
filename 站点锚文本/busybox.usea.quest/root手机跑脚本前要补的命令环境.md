# root 手机跑脚本前要补的命令环境

折腾 root 手机的人迟早会撞上这个场景：从论坛或模块仓库拿来的脚本，第一行就跑不下去，报 `xxx: not found`。脚本本身没毛病，毛病出在环境——脚本作者默认你的手机里装了 [BusyBox](https://busybox.usea.quest/) 这套命令，而安卓原生环境里恰恰没有。本文把脚本环境的来龙去脉捋一遍：脚本依赖什么、root 方案自带的那份算不算数、装完怎么确认。

## 脚本默认你会用这套命令

root 圈子里的脚本（备份、精简、自动化、刷入类）大量使用 sed、awk、dd、mount 这类 Unix 工具，其中不少是安卓 shell 里没有的。作者懒得为每台机器适配，普遍直接假设"有"。所以跑脚本前的准备工作，本质上就是把这套命令补进系统：装一次，脚本里 `#!/system/bin/sh` 加各种命令调用就能正常走通。

## root 方案自带的那份，和你装的不是一回事

Magisk、KernelSU 这类 root 方案内部也带了一份 BusyBox，位置在它们自己的数据目录里，专门用来跑它们的模块脚本。这份的存在容易让人误以为"已经有了，不用装"——它确实解决了模块作者的难题，但那份环境不对你的终端开放：你在终端模拟器里敲 `awk`，用的不是它。

两者并存互不干扰，也不冲突。想在自己的终端和脚本里随手用上这些命令，还是要装一份进系统分区；写脚本的人如果想明确指定用哪一份，写清楚路径即可。

## 装完之后的两步确认

1. 终端里敲 `busybox`，回显开头是版本号加一长串命令名，说明装好了；
2. 随便跑一条短名命令（比如 `awk 'BEGIN{print "ok"}'`），能出结果说明链接也建好了。

只过第一关不过第二关，通常是安装时只挑了部分命令或者链接没建全，回安装器里重新执行一遍安装即可。系统大版本更新（OTA）之后如果又出现 not found，也不用排查别的——OTA 会把系统分区还原，重装一次是标准操作。

至于安装文件从哪来、怎么装进 /system/xbin，配套的机制原理写在 [安卓终端缺命令怎么补](安卓终端缺命令怎么补.md)。
