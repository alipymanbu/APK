# 安卓 RSS 阅读器哪个好用

> 这篇从「要不要自己找源、要不要离线、听不用听得」三个维度聊安卓端 RSS 阅读器的挑选思路，并以 FeedMe 为例说明一个依赖服务账号的客户端实际用起来是什么样。
> **相关文章**：[RSS离线阅读与全文缓存.md](RSS离线阅读与全文缓存.md) · [自建RSS服务手机客户端.md](自建RSS服务手机客户端.md)

## 一、先分清两类阅读器

安卓上的 RSS 阅读器大致分两类：

- **自带源管理的一体化应用**：订阅、抓取、存储都在应用里完成，上手快，但换手机要导出导入，多设备之间已读状态也难同步；
- **依赖服务账号的客户端**：订阅、已读、加星都存在服务端（Feedly、Inoreader、Feedbin，或自建的 FreshRSS、Tiny Tiny RSS、Miniflux），应用只负责拉取和呈现。换手机、换设备，登录同一个账号状态就跟过来了。

重度订阅用户更建议第二类：数据在服务端，客户端坏了换一个就是，迁移成本几乎为零。

## 二、按使用习惯挑功能

挑阅读器时，真正拉开差距的是这几个点：

| 在意什么 | 该看什么 |
| --- | --- |
| 地铁飞机上没网也要读 | 全文与图片能否提前同步到本机 |
| 订阅里有播客 | 能不能把播客单集当文章管理、离线收听 |
| 外文源多 | 有没有标题翻译、正文总结类的能力 |
| 订阅量大 | 未读条数、同步范围能不能精细控制 |
| 阅读习惯 | 音量键翻页、单手模式、字体与排版调节 |

## 三、FeedMe 的答卷

FeedMe 属于第二类：它自己不生产内容，登录已有 RSS 服务账号即可开读，兼容范围覆盖托管服务与自建服务两条线（Fever API 与 Google Reader API 两个兼容层都有支持）。离线阅读、播客收听、TTS 朗读、按源开关的 AI 总结与标题翻译，上面表格里的几项它都给出了答案；四种同步方式加未读条数控制，对订阅量大的人比较友好。

它的功能盘点、各服务能力对照表与上手三步，整理在 [FeedMe 介绍站](https://feedme.hfdk.space/)，选型前值得过一眼。

## 四、一个提醒

换阅读器不等于换服务：只要 RSS 服务账号不变，换哪个客户端，订阅和已读状态都还在原处。所以真正值得慎重的是选服务，客户端可以随时换着用。
