# APK 签名不一致导致装不上的解决办法

> 点安装时系统只丢下一句「应用未安装」，或者明说签名不一致——这是折腾安装包时最常见的坎。本篇解释它为什么发生、怎么处理；签名本身的补法见[手机上给 APK 重新签名的方法](手机上给APK重新签名的方法.md)。

先说原理：安卓把签名当成应用的「作者身份」。同一个应用想覆盖升级，新包和手机里已装旧包的签名必须完全一致；只要对不上，系统一律拒绝安装，而且往往不给具体原因。

什么情况会触发签名不一致：

- 手机里已经装过同包名的另一个版本，两边不是同一张证书签的；
- 安装包被解包修改后重新打包，原签名被破坏，等于换了一个「作者」；
- 换了密钥库重签——哪怕是同一个人操作的，在系统看来也是两个来源。

对应的处理思路：

1. **确认手机里有没有同包名的旧版本**。有就先卸载（注意卸载会清掉该应用的数据，重要的先备份），再装新签的包；
2. **重签一遍再装**。如果包是改过的，用签名工具重新签名后通常就能正常安装——工具本身可以装在手机里现场处理，比如 [Apksigner 这款安卓端签名工具](https://apksigner.boop.uno/)，签名、验证两步都在手机上完成；
3. **装完后到验证页回查**，确认新包的签名信息符合预期，避免反复折腾。

还有一种容易误判的情况：下载不完整或文件损坏，安装器报「解析失败」，看起来和签名问题很像。区分的办法是重新下载一次——换了文件还报同样的错才是签名问题，一次就好八成是传输出了岔子。
