# 脚本不生效怎么排查

激活完成后，JsHook 里真正干活的就是脚本（`.js` 文件）。脚本来源有三种：内置仓库订阅、手动导入，或在电脑上用 VS Code 插件编辑后一键推送。装好了、也配了脚本，目标应用却毫无动静——这类「不生效」几乎都有固定的排查顺序。

## 先把两个前提钉死

**第一，脚本改动后必须重启目标应用。** 注入发生在目标应用启动时，改完脚本不重启，跑在里面的永远是旧内容——这是「改了没反应」的头号原因。

**第二，目标应用的 hook 服务开了没有。** 在「应用」页逐项确认：选中应用、选框架、勾脚本、开服务，四步缺一不可。JsHook 本体被后台清理划掉，脚本同样会停。

## 注入框架与脚本类型要配对

开启 hook 服务时要选一个注入框架，三者分工不同：

- `fridamod`：内置完整 jscore API，支持内核模式、ImGui 渲染与加密脚本，不确定就选它；
- `fridainject`：经 frida-server 注入，默认监听 `28042/28043` 端口，适合配合电脑端 frida 直连；
- `fridagadget`：经 frida-gadget 配置注入，应对目标应用的特殊注入要求。

容易忽略的一点：脚本仓库里的脚本分 `rhino` 与 `frida` 两种类型，**rhino 类脚本与 frida 系框架不通用**。接触过 Xposed 写法的人对 rhino 类会更眼熟；下载脚本前先看清类型标注。

## 五步排查顺序

1. **先怀疑脚本本身**：取消所有脚本勾选，只留一个最简单的试。全部勾着不生效，可能是某份脚本报错拖累了整体；
2. **核对 hook 服务**：回到「应用」页确认目标应用的 hook 服务确实开着；
3. **重启目标应用**：脚本改过就要重启（见前提第一条）；
4. **换注入节奏**：有的应用实时注入会当场闪退，改成「先启动应用、等几秒再开 hook 服务」的节奏能绕过；
5. **回头看激活状态**：首页不再显示已激活（比如开了「增强渲染」后掉激活），后面配置全是空转，回激活环节重新走一遍。

## 电脑端协作值得一试

手机上改脚本输错一个括号就要来回切应用。装上 VS Code 插件后，`Shift+Alt+D` 推送、`Shift+Alt+C` 拉回，前提是脚本名与相对路径和手机上一致、JsHook 设置里开了 server、电脑手机同一 Wi-Fi。习惯命令行的人也可以用电脑端 frida 直连 `28042` 端口，spawn / attach 都行。

工具与安装包的全貌介绍，见 [JsHook 使用教程介绍站](https://jshook.xnyx.quest/)；还没走到脚本这一步、卡在激活的，先看[免root激活路线怎么选](免root激活路线怎么选.md)。

照例提醒：脚本能读写文件、发网络请求，执行别人分享的脚本前先看一眼内容；注入对象限于自己的设备、自己的应用、自己的账号。
