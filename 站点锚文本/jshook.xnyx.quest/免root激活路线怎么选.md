# 免 root 激活路线怎么选

装过 JsHook 的人大多在同一个地方卡住：首页一条「未激活」横幅，应用列表和 hook 服务全是灰的——激活没完成之前，这份工具基本什么都不做。而激活路线怎么走，取决于你的设备环境。

## 先确认激活为什么是前提

JsHook 的本体只是一个管理器：真正干活的是注入运行时与脚本。激活过程会把运行时文件部署到 `/data/adb/jshook/`、按内核版本释放对应模块并启动后台守护服务——这些做完，hook 服务才可用。所以「装完没反应」多数不是装坏了，而是还没激活。

## 四类环境，四条走法

| 设备环境 | 走法 | 特点 |
| --- | --- | --- |
| 已 root 真机（Magisk / KernelSU / APatch） | 应用内点「激活」，允许 root 授权，等待自动部署 | 流程最短，推荐 |
| 虚拟机（VMOS、光速虚拟机等） | 在虚拟机内部完成 root 激活，与真机流程一致 | 不动机身 |
| 模拟器 | 先让模拟器取得 root，再按真机步骤激活 | 适合本就在模拟器里工作的人 |
| 未 root 真机 | 经 LSPatch 的免 root 用法（见下节） | 社区实践路线，限制最多 |

## 免 root：LSPatch 修补路线

没有 root 也有路走，但要先弄清这条路的性质：开发者文档只写了 root 激活一条线，免 root 用法来自社区实践的相互印证，属于「能用、但没人替你兜底」的路线。

前置准备三样：JsHook 本体、LSPatch 工具、要分析的目标应用安装包（修补会生成一个新包，不动原应用）。

流程概括：

1. 用 LSPatch 修补目标应用的安装包，按提示安装生成的新包；
2. 在 LSPatch 的模块作用域里勾选 JsHook；
3. 打开 JsHook 切到「免ROOT模式」，进「框架管理」下载 `FridaMod(Gumjs)` 并设为全局默认；
4. 进「脚本管理」导入脚本，再到「应用」页给目标应用启用 hook 服务；
5. 打开目标应用验证。

## 这条路的代价，想清楚再走

- **双应用常驻**：目标应用运行期间，JsHook 与 LSPatch 都得留在后台，被清后台就失效，耗电是被抱怨最多的一点；
- **不是所有应用都能过**：加固强、签名校验严的应用，修补后可能直接跑不起来；
- **目标应用更新要重来**：修补针对具体安装包，目标应用一升级就得重新修补再装。

结论很朴素：设备能 root 就走 root；不方便 root 的主力机，免 root 路线可以先低成本试通流程，但它解决不了所有应用。

想看这份工具的能力构成、界面实拍与安装包获取入口，见 [JsHook 免 root 与激活介绍站](https://jshook.xnyx.quest/)；脚本配好却没反应的情况，另见[脚本不生效怎么排查](脚本不生效怎么排查.md)。

最后照例一句：无论哪条路线，对象都应该是你自己的设备、自己的应用、自己的账号。
