# 手机审批与云端任务实操

> 编程智能体停下来等你拍板的时刻，人往往不在电脑前。这篇讲两件事：怎么在手机上处理审批与追问，以及手边没电脑时怎么把任务直接发到云端环境去跑。

## 一、审批为什么重要

智能体改文件、执行命令之前会先申请许可，方案动手前也支持先审 Plan。这个设计意味着：**任务推进的节奏由你的响应速度决定**。推送没送到手上，任务就一直在节点上等——所以装好 App 后第一件事是把通知权限开好，并把系统层面的省电限制、后台冻结解除掉。

审批的粒度自己选：单次放行、整个会话放行，还是拒绝重来。改动内容以 Diff 形式逐条列出，手机上翻完再决定。

## 二、云端任务：电脑不开机也能跑

远程控制要求电脑开着，云端任务反过来——**任务跑在云端环境，本机全程不参与**，手机 App 关掉、电脑关机都不影响它继续。适合通勤、出差、会议间隙直接交付的活儿。

四步发起：

1. App 的 New Task 页面，把运行环境切到 `Cloud`；
2. 关联 GitHub 账号，选定这次要改的**仓库和分支**——这步别跳，选错分支改动会落到别处；
3. 输入框里把需求写清楚（一句话需求也能跑，越具体越好）；
4. 回会话列表看进度，云端任务和本地任务并排显示。

跑完后改动以 Diff 形式给出：先核对改动范围是否只落在选定分支、有没有碰到不想动的文件，需要调整就在会话里补一句让它继续改，确认没问题再回电脑走合并流程。

## 三、仓库列表里找不到目标仓库

这是授权范围问题，不是仓库不存在。点列表下方的 **Manage repository access**，到目标仓库里安装 Qoder AI App，装完回到 App 重新选即可。公开仓库通常直接能选，私有仓库必须走这一步。

## 四、两条路怎么选

| | 云端任务 | 远程控制 |
|---|---|---|
| 电脑 | 不用开机 | 必须开机且任务在跑 |
| 代码在哪 | 云端环境，连接 GitHub | 你电脑本地 |
| 产物落地 | 推回 GitHub 仓库 | 存在电脑里 |
| 典型场景 | 通勤、出差路上直接交付 | 短暂离开工位，任务已经开了 |

两条链路的连接方法（扫码、守护模式、断线重连）在[手机端怎么连上电脑的编程任务](手机端怎么连上电脑的编程任务.md)里有逐步说明；产品线区分与账号讲究见[通义灵码更名后的手机端](通义灵码更名后的手机端.md)。

功能总览与界面截图，见 [Qoder CN 手机版介绍站](https://qoder-cn.xnyx.quest/)。
