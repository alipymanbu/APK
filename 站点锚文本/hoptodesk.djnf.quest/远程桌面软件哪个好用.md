## 一、先比费用：免费的边界画在哪

远程桌面工具的「免费」各有各的画法，差别比想象中大：

| 工具 | 免费范围 | 门槛从哪来 |
| --- | --- | --- |
| HopToDesk | 个人与商业使用均免费，无时长限制 | 只在仪表板管理大批设备时涉及付费 |
| TeamViewer | 个人使用免费 | 商用需授权，有使用检测争议 |
| AnyDesk | 个人使用免费 | 商用需授权 |
| RustDesk | 开源客户端免费 | 公共中继有限制，重度用要自建 |

TeamViewer 的「商业使用检测」是老话题：不少用户反馈个人会话被误判为商用而限制时长，申诉要人工处理。对偶尔帮朋友修电脑也算「工作」的人来说，这类不确定本身就是成本。HopToDesk 在费用这一项上给得最直接——客户端功能全部免费，且明确覆盖商业用途，源代码 AGPLv3 公开，收费层只出现在仪表板这种「管几十台设备」的场景。

## 二、再看加密：传输加密和端到端不是一回事

很多产品的安全声明写的是「加密传输」，这只保证数据在路上不被窃听，服务端理论上仍能看到画面。端到端加密则更进一步：会话内容在两端加密，中间方（包括厂商）无法窥看。

- **HopToDesk**：屏幕共享、聊天、文件传输的全部流量做端到端加密，会话内容不存储；
- **TeamViewer**：RSA 2048 加会话密钥交换、AES 256 做传输加密；
- **AnyDesk**：TLS 1.2 加 AES 256 的传输加密方案。

对远程网银、登录密码管理器这类画面敏感的操作，端到端口径是有实际意义的差异位。加上 HopToDesk 代码开源、可逐行审计，它的安全声明是「可验证」而非「可信任」。

## 三、部署自由度：链路能不能握在自己手里

这是经常被忽略、但对 IT 场景很关键的一条：

- **RustDesk** 是自托管路线的代表作，自建中继后全链路自主；
- **HopToDesk** 同样支持私有部署——信令服务（HopSignal）可以装在自己的 Linux / Windows 服务器上，或架在 Cloudflare Workers、AWS 上，客户端切换网络配置即可；
- **TeamViewer / AnyDesk** 走自家云，链路自主性基本不在选项里。

个人用户大概率用不到自托管，但它代表一个事实：开源方案不把你锁在别人的基础设施上。

## 四、按场景给结论

- **个人 / 家庭 / 小团队，不想碰订阅制**：HopToDesk 的「全功能免费 + 商用免费 + 免账号连接」组合是最省心的答案；
- **成熟企业已有 TeamViewer 生态**：迁移成本大于收益，留在原方案并按席位付费更现实；
- **对链路自主性要求高、愿意折腾**：RustDesk 或 HopToDesk 的自托管路线，把信令与中继收回自己手里；
- **对隐私口径最敏感**：优先端到端加密 + 开源可审计的组合，HopToDesk 在这两项上是同类里给得齐的。
