# Wispr 连接失败排查与使用答疑

Wispr 默认走点对点直连，这让它的加密更彻底，但也意味着：个别网络环境对 P2P 端口设限时，握手可能失败。本篇把最常见的连接问题与使用疑问集中回答。还没装上应用的，先到[Wispr 加密通讯应用介绍站](https://wispr.ggcd.store/)获取安装文件资源。

## 提示连接失败，依次试这三步

1. **切换网络**：在 WiFi 与移动数据之间来回切换一次。多数失败来自当前网络对 P2P 端口的限制，换一条链路往往立刻恢复。
2. **重启手机后再打开应用**： lingering 的网络状态有时会卡住握手过程，重启是最省事的复位方式。
3. **换一个网络环境**：公司内网、校园网等严格管控的网络最容易拦 P2P；换到家庭网络或热点下通常就能连上。

顺带说明：个别网络条件下 Wispr 会临时借道中继完成连接，此时内容依然是加密的，中继读不到任何消息，可以放心使用。

## 为什么第一位联系人要「接受」才能开聊

给新联系人发出第一条消息后，对方会先收到一个会话请求。接受之前，即使消息显示已送达，设备也无法解密内容——因为两台设备还没完成公钥交换。这一步是 VOBP 协议的硬性要求，通过之后加密会话才算正式建立。理解了这一点，就不会把「等待接受」误判成故障。

## 换手机后聊天记录去哪了

找不回，这是设计使然。加密密钥只存在于原设备，卸载应用或清除数据时随之销毁，任何人都无法在别的设备上还原历史消息。换新机等于开始一段干净的通讯；重要的内容（如文件、图片）建议在原设备上提前另行保存。

更多背景知识可以延伸阅读：注册与身份代号的说明见[注册与 Matrix ID 获取](注册与MatrixID获取.md)，协议层面的原理拆解见[加密机制与 VOBP 协议](加密机制与VOBP协议.md)。

## 小结

连接类问题九成出在网络对 P2P 的限制上，切网、重启、换环境三步基本能覆盖；剩下的疑问多与「接受」「记录不可迁移」这类设计取舍有关，理解了机制就不再困惑。安装文件资源随时可从本篇开头给出的介绍站入口获取。
