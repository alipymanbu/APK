# Wispr 加密机制解读：VOBP 协议到底特殊在哪

市面上标榜「加密」的通讯应用不少，Wispr 的差异在于它没有沿用常见的「服务器中转 + 加密传输」结构，而是用一套自研的 VOBP 协议重构了消息的传递路径。本篇把这套机制拆成四个可验证的事实，帮读者判断它是否值得信任。对应用本身还陌生的，可以先浏览[Wispr 加密通讯应用介绍站](https://wispr.ggcd.store/)再回来。

## 事实一：密钥只在你手里

VOBP 的加解密密钥由设备在安装使用时自动生成，只保存在本机，从不向任何服务器上传或存档。这意味着两件事：应用本身也无法解密你的消息；卸载应用或清除数据时，密钥随之销毁，历史消息在任何设备上都无法再被还原。

每次会话、每条消息还使用独立的密钥，会话结束即销毁——不是「一套密码用到底」，而是「一次一密」的思路。

## 事实二：点对点直连，服务器不在链路上

Wispr 默认在收发双方之间建立 P2P 直连：文本、语音、视频通话、群聊与文件都在设备之间直接传输，不经过中央服务器。即便在防火墙或复杂网络环境下临时借道中继，中继搬运的也只是密文，读不懂内容。

离线场景同样如此：消息在队列中加密等待送达（媒体文件最多保留两周），送达后服务器即删除，不留副本。

## 事实三：区块链用来校验身份，不是存聊天记录

VOBP 引入区块链作为信任层：会话建立、密钥交换这类事件会被登记校验，用于确认「和你通话的确实是那台设备」，拦截中间人冒充。链上记录的只有校验凭据，没有任何聊天内容——它解决的是「你是谁」的问题，而不是「你说了什么」。

## 事实四：AES-256 是加密的底座

消息、通话与文件全程采用 AES-256 端到端加密。这是目前全球范围内保护高敏感数据的主流标准，也是这套协议里最容易被验证的一环。

## 这套机制的实际代价

强加密带来两个使用上的取舍：换新设备意味着历史记录无法找回（密钥不可迁移）；首次联系需要对方「接受」请求以完成密钥交换，多了一步等待。这两点在[注册与 Matrix ID 获取](注册与MatrixID获取.md)里有对应说明。
