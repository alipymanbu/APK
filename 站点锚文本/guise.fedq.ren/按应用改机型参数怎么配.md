# 按应用改机型参数怎么配

> 本篇是 Guise 的参数配置实操：机型从哪选、字段怎么填、随机怎么用、模板怎么在多个应用间复用。前提是模块已在 LSPosed 里启用——环境还没搭的先看[是什么模块与root前提](是什么模块与root前提.md)。配完没反应的，直接翻[配置不生效的排查顺序](配置不生效的排查顺序.md)。

---

## 动手前：先把目标应用勾上

打开 Guise 的应用列表，勾选要伪装参数的目标应用——这个勾选就是启用开关，勾选状态会同步为 LSPosed 作用域。只填参数不勾选，模块对该应用不生效；把某个应用的配置清空保存，勾选也会跟着自动取消。

## 改机型的两条路

**从机型目录选**：内置目录按品牌分组，覆盖手机、平板等常见设备，选中后品牌、型号等字段自动填入。省心的地方在于目录把「界面显示名」和「实际写入 Build 的值」分开了——界面上看到的是"一加"，写进参数的是 `OnePlus`，不用自己去查代号。

**手动填**：品牌填实际 Build 值（`samsung`、`OnePlus` 这类），型号填具体代号（三星 `SM-G991B`、红米 `M2101K9G` 这种格式）。手填适合目录里没有的设备或自己构造的组合，但要注意字段之间的配套关系——下一节说。

无论哪条路，连系统版本一起伪装时，把 Android 版本、SDK、Fingerprint 设成与机型**配套**的值，别各填各的：品牌是 A 家、Fingerprint 格式却是 B 家的组合，目标应用一校验就露馅。

## 一键随机：不想挑就用它

字段旁的独立随机按钮适合只换个别项；整表不想动脑就用一键随机——它从同一组设备数据里生成一套互相配套的值（品牌、型号、Android 版本、SDK、Build ID、Fingerprint），新版本的随机值按常见平台形态生成：Android ID 是 16 位十六进制、IMEI 带校验位、MAC 用本地管理地址、坐标落在全球有效范围。生成的组合通常比手填更自洽，这也是排查参数校验问题时最常用的兜底手段。

## 模板：一次配置，多处套用

同一套参数要给几个应用用，别逐个抄：

- **保存**：把当前应用的配置存成模板，可选「通用模板」（任何应用都能套）或「应用专属模板」（只给指定应用用）；
- **套用**：在模板列表里批量选择目标应用套用，会覆盖已有配置时应用内会先确认；
- **导入导出**：模板能导出成 JSON 或二维码做备份，也能从 JSON 文件、HTTPS 链接、相机扫码或相册二维码导入——换机迁移时尤其省事。

## 保存之后：强停才算数

保存成功只是把配置写进去，目标应用是否读到新值要看进程重启：用系统「应用信息 → 强制停止」再重新打开（从最近任务划掉不算），参数替换才发生。应用没在运行时就不用管，下次打开自动带上新参数。

想先确认注入链路是通的，用作者配套的靶应用 Guise Test 走一遍：勾选它、配几个明显不同于真机的值、强停重开，对照它屏幕上各接口的返回值——配置过的项显示新值就是通了，再把同样的配置套到真正的目标应用。完整的生效流程与界面截图，[Guise 改机型模块介绍](https://guise.fedq.ren/)里按步骤配了实拍。
