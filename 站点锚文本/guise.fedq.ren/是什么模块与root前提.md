# 是什么模块与root前提

> 搜索 Guise 的人多半带着两个疑问：它到底是个什么软件、没有 root 能不能跑。本篇把这两件事一次说清，再看懂它"按应用伪装"的思路。配置怎么动手写，见[按应用改机型参数怎么配](按应用改机型参数怎么配.md)；保存后没反应，见[配置不生效的排查顺序](配置不生效的排查顺序.md)。

---

## 一句话定位

Guise 是一个运行在 LSPosed 框架下的安卓 Xposed 模块，做的事是在**单个应用进程内**替换设备参数的读取结果：品牌、型号、Android ID、IMEI、Wi-Fi 与基站信息、经纬度、语言时区、电池电量……都在可改之列。原项目由 Houvven 开发，2.0.0 起由 daxiaamu 以 Guise Reborn 的名义接手维护，包名一直是 `com.houvven.guise`。

它和常见的"一键改机"工具思路不同：**没有全局开关**。你在应用列表里勾选谁，谁读到的才是你配置的值；没勾的应用照常读真机参数。这个设计让伪装粒度落在"某个应用"上——社交应用的机型展示、单个游戏的环境适配、不想交出真实标识的应用，各配各的，互不影响。

## 四层依赖，缺一层都跑不起来

| 层级 | 你需要准备什么 |
| --- | --- |
| Root 与解锁 | 已解锁 Bootloader，Magisk 或 KernelSU 提供 Root |
| Zygisk | Magisk 设置里开启（KernelSU 路线可配 Zygisk Next），开完重启 |
| LSPosed 框架 | 以 Magisk 模块形式刷入，或用兼容 Modern Xposed API 的框架 |
| Guise 本体 | 一个 APK，装上等待框架加载 |

机型方面要求 arm64-v8a，系统要求 Android 10（API 29）及以上。想确认手里的环境能不能跑，把这张表从下往上对一遍即可。

## "免 root 版"的说法从哪来

部分下载站会给它挂上"免 root""无需 root"的标题。这与模块的工作原理直接冲突：Guise 自己不会注入任何进程，注入动作由框架完成，而框架必须运行在已 Root 的设备上——所谓免 root 版本要么装了没反应，要么根本是另一个东西。更实际的风险在于，这类工具处理的恰恰是设备标识与定位信息，用来路不明的安装包等于把这些数据交给陌生人。

## 能改的参数与改不到的地方

可配置项分六组：设备与系统（品牌/型号/Fingerprint 等 Build 字段）、唯一标识（Android ID、IMEI、手机号）、网络与 SIM（Wi-Fi SSID/BSSID/MAC、运营商、基站 LAC/CID）、定位（经纬度加随机偏移、隐藏 Wi-Fi 与基站定位信息）、运行环境（语言、时区、电量、允许强制截图）、空白通行证（联系人媒体查询返回空、应用列表可见性过滤）。

边界同样要心里有数：它只替换目标应用进程内 Java 层接口的返回值，IP 定位与厂商私有接口不在覆盖范围；不改系统全局设置，其他应用完全无感。想看六组参数的逐项拆解与界面实拍，[Guise 改机型模块介绍](https://guise.fedq.ren/)里整理成了一张参数档案表。

## 装好之后

环境就绪的话，剩下的就是安装 APK、在 LSPosed 里启用、勾选目标应用、配置保存、强停重开五步。具体操作细节在[按应用改机型参数怎么配](按应用改机型参数怎么配.md)里展开。
