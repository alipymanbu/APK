# 不用root真机开超级用户的方法：虚拟机内的Root是怎么回事

> 讲清虚拟机 Root 的边界、开启与验证步骤、授权失败的排查顺序，以及它和传统一键 Root 的本质区别。
> **相关文档**：[手机虚拟机多开小号怎么弄.md](手机虚拟机多开小号怎么弄.md) · [安卓12虚拟机起不来的处理办法.md](安卓12虚拟机起不来的处理办法.md)

---

## 一、先分清是哪一层的 Root

VMOS Pro 的 Root 是**虚拟机内部的超级用户**：打开的是虚拟系统里的权限，真机的 Bootloader 不解锁、系统分区不动、保修不受影响。权限的作用范围也只在虚拟机里——虚拟机内的应用拿得到 root，真机上的应用一切照旧。

这是它和传统一键 Root 工具的本质区别：练手、测试需要 root 的工具、在隔离环境里折腾，搞坏了删掉这台虚拟机重开即可，真机毫发无损。

## 二、开启步骤

1. 建好一台虚拟机并进入（安装与建台步骤见 [VMOS Pro 介绍站](https://vmos-pro.fewz.tech/)）；
2. 打开虚拟机内的「设置」（是 VMOS 的虚拟机设置项，不是安卓原生设置），找到「**超级用户**」开关，打开；
3. 回到虚拟机桌面，启动一个需要 Root 的应用——首次调用时弹超级用户授权窗，勾选允许即可。授权记录可在超级用户管理界面查看、撤销；
4. 验证是否生效：装一个 Root 检查类应用，或在终端里执行 `su`，能拿到 `#` 提示即为成功。

部分镜像（如内置 Root 环境的 ROM）开箱即带超级用户，装进去就能授权，无需手动开开关——以所选镜像的实际说明为准。

## 三、能拿来做什么

- 卸载或冻结虚拟机里预装的应用；
- 用需要 root 的系统工具改配置、调音效（蝰蛇音效类工具是常见用途）；
- 在虚拟机内挂载 Xposed 框架与模块；
- 测试 APK 的高危行为——中招也只污染虚拟机。

所有这些操作都发生在虚拟机内；想动真机的系统分区，这条路做不到，也不该那样用。

## 四、授权不生效，按命中率排查

1. **重启虚拟机**：社区经验是 superuser 守护进程没在运行时授权必失败，虚拟机关机再开机基本能解决，这也是最常见的一招；
2. **确认开关在正确的虚拟机上**：Root 开关按台生效，建了多台的话进错台就看不到授权；
3. **免费镜像可能限制 Root**：有第三方资料指出，部分版本的免费虚拟机不开放 Root 权益，表现为超级用户应用闪退或重启后丢授权，遇到这种表现先对照账号与版本状态；
4. **重装授权应用**：超级用户管理应用本身损坏时表现为一授权就闪退，重装可恢复。

## 五、收费口径：两边说法并列，如实记

这一条不同来源的说法不一致：

- 开发方 FAQ 对「VMOS 收费吗」的回答是「承诺对用户永久免费」，指的是基础虚拟机功能；
- 第三方资料则称 Root、Xposed 属于 Pro 版的会员付费功能，需开通会员（有月 / 季 / 年档位）后使用。

也就是说：基础的建台、多开、挂机免费，Root 相关权益是否要付费取决于版本与账号状态——以应用内实际提示为准，这里不给结论。

## 六、两个进阶限制，先知道再折腾

- **不支持 Magisk**：VMOS 没有 `boot.img` 与 recovery 模式，Magisk 无法在其中初始化，Root 走的是 Superuser 方案；想装 Magisk 模块的话这条路走不通；
- **Xposed 视镜像而定**：部分镜像自带 Xposed 环境，装好模块即用；没有的镜像需自行在虚拟机内装框架，框架版本要与镜像的安卓版本对应，装错版本会起不来。
