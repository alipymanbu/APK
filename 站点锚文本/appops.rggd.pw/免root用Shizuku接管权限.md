# 免root用Shizuku接管权限

本篇梳理没有 root 的手机如何让 AppOps 真正接管应用权限：为什么必须有一条「提权通道」、Sui 与 Shizuku 怎么选、无线调试与电脑 adb 两种启动方式的差别，以及 root 模式为什么从新版里消失了。权限状态本身怎么调更合适，见[拒绝权限后应用闪退怎么办](拒绝权限后应用闪退怎么办.md)。

---

## 为什么绕不开提权

appops 是 Android 系统里长期存在的一套控制框架，但普通应用没有权限去修改它的设定——这既是它的隐蔽性，也是使用门槛的来源。AppOps 想动手改设定，必须先借到一条比普通应用更高一级的通道，这就是「工作模式」选择页存在的原因。

新版本里真正可用的通道是 Shizuku：它通过 adb（shell）级别的特权启动一个系统进程，把修改 appops、运行时权限和权限标志这三层设定的能力交给应用。三层都能改，权限管理才能跟得上系统自身的行为逻辑。

## Sui 还是 Shizuku

工作模式页会提示先安装 Sui 或者 Shizuku，两者是一对拥有相同 API 设计的姐妹项目：

- **Sui**：Magisk 模块。设备已经刷入 Magisk 的话，装它最省事，随系统启动常驻。
- **Shizuku**：独立应用，不需要刷机。开机后服务不常驻，重启要用下面两种方式之一重新激活。

没有 root 的设备走 Shizuku 这条路即可。

## 两种启动方式

**无线调试（Android 11 及以上）**：在开发者选项里打开无线调试并完成配对，然后在 Shizuku 应用里选「通过无线调试启动」。全程不插线，激活后回到 AppOps 授权，首页就能列出全部应用与权限。

**电脑 adb（老系统）**：Android 11 以下的设备需要数据线连接电脑，开启 USB 调试，在命令行执行 Shizuku 提供的启动命令，手机上确认授权调试。装好 platform-tools 就能跑，一条命令的事。

两种方式殊途同归，启动成功后在 Shizuku 里能看到运行状态，再到 AppOps 的设置里确认工作模式已切换。

## root 模式去哪了

网上不少旧教程提到 AppOps 的「root 模式」，在新版本里找不到是正常的。纯 root 只提供一个 uid 0 的 shell，改不了「权限标志」这一层，也没法正确跟随系统的权限行为；Android 11 还会在安装应用等时机把全部 appops 设定重置回系统默认。能力残缺的模式留在新版里只会误导，v5.0.0 起它被移除了。同理，托管设备管理员模式自 6.0.0 起也不再支持，旧教程里那条路不必再折腾。

还有一个高频疑问：重启后权限又回去了。adb 通道不常驻，重启后重新执行一次启动命令即可；长期方案是开启应用内的「自动恢复」，让设定在被系统重置后自动导回。

通道跑通之后，剩下的就是对每个权限做取舍。这款工具的版本信息与安装文件资源入口，见 [AppOps 权限管理介绍站](https://appops.rggd.pw/)。
