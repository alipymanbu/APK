# 不写代码也能做游戏吗

> 「做游戏是不是必须先学编程」——答案是否定的。可视化游戏引擎把代码翻译成了看得懂的表格与参数，这篇讲清楚它到底怎么替掉代码，以及新手最容易踩的三个坑。相关阅读：[手机做游戏的无代码工具怎么选](手机做游戏的无代码工具怎么选.md) · [事件表做游戏逻辑入门](事件表做游戏逻辑入门.md)

## 一、代码在游戏里到底干了什么

拆开任何一个 2D 游戏，代码无非在干四件事：

1. 读输入：玩家按了跳跃键；
2. 改状态：角色纵坐标按重力加速度变化；
3. 判条件：角色和地面碰撞了吗；
4. 画画面：把角色画到新位置。

每一件都是固定套路。可视化引擎做的事，就是把套路做成「填空题」——你填数值和选项，引擎替你执行。

## 二、填空题长什么样：以 GDevelop 为例

GDevelop 把逻辑写成一行行「事件」：左边是条件、右边是动作。举两个例子：

- 条件「玩家碰到金币」→ 动作「删除金币、变量得分加 1」；
- 条件「变量生命 ≤ 0」→ 动作「切换到结束场景」。

再往上，连「重力」「跳跃」都不用写：给角色挂一个「平台跳跃角色」行为，移动速度、跳跃高度都是数值框，改数字就改手感。这就是无代码工具的核心——**逻辑没有变少，只是换成了选择题和填空题**。

## 三、新手最容易踩的三个坑

### 坑一：从白板新建项目

第一次就从空项目开始，面对空白场景不知道第一下点什么。正确姿势是从内置示例改起：平台跳跃类示例的关卡逻辑是完整的，换图、调速度、改布局，一小时就有成品感。

### 坑二：攒一大波改动再预览

改了二十处才点预览，出 bug 根本不知道哪步引入的。改一两处就预览一次，问题当场暴露。

### 坑三：一上来就想做大型游戏

开放世界、联网对战是团队级工程。第一个目标定成「一关的平台跳跃」或「躲障碍的小游戏」，做完整比做大重要。

## 四、在手机上做，现实吗

现实。现在的手机版编辑器已经把场景编辑、事件表、行为参数、即时预览全部装了进去，通勤路上改关卡、午休预览一局完全可行；平板屏幕大些，改事件表更舒服。

想看它在真机上长什么样、装一份自己试，[GDevelop 手机版介绍站](https://www.laze.skin/)整理了界面截图、功能拆解与安卓安装包入口。装好之后，配合[事件表做游戏逻辑入门](事件表做游戏逻辑入门.md)把第一张事件表写出来，就算正式入门了。

## 五、进阶也不遥远

无代码不等于永远不碰代码：等玩法复杂到一张表装不下，引擎还支持在事件里插入 JavaScript 片段——到时候你已经懂「条件、变量、循环」的游戏语义，学起来比纯新手快得多。这也是很多教程把可视化引擎当作编程启蒙的原因。
