# BT磁力下载与断点续传参数

> 集中回答搜索里最常见的两类问题：aria2 的多连接与并发参数怎么用，BT 磁力任务该抱什么预期。
> **相关文档**：[多协议下载引擎是什么.md](多协议下载引擎是什么.md) · [手机端下载与远程遥控用法.md](手机端下载与远程遥控用法.md)

---

aria2 的速度表现主要取决于参数与源的状况，本篇把常被问起的几组命令行参数列成对照，再说明 BT 与磁力任务的现实预期。手机端用户不敲命令也可以读第一节的逻辑——图形前端里那些「最大连接数」「分段数」对应的就是这些参数。

## 提速参数对照

| 参数 | 含义 | 默认值 |
| --- | --- | --- |
| `-x` | 单服务器最大连接数，上限 16 | 1 |
| `-s` | 单任务分段数 | 1 |
| `-j` | 并行任务数（队列同时下载几个） | 5 |
| `-k` | 分段最小尺寸 | 20M |

典型组合：

```bash
aria2c -x16 -s16 https://example.com/big-file.iso
aria2c -j5 -x8 file1.zip file2.zip file3.zip
```

`-x` 对付的是「服务器限速单连接」的源，连接数上去后往往立竿见影；`-s` 让文件被拆成多段同传；`-j` 解决的是「一批小文件逐个下太慢」的排队问题。但注意：**源本身只有一个慢速链路时，参数堆再高也没用**，多连接救的是被单连接限速的场景。

## 断点续传

- `-c`：从中断的字节位置继续，而不是从头开始；
- `--always-resume=true`：总是尝试续传，源不支持续传时直接中止而不是重下，避免白费流量；
- 任务列表会记录在控制文件里（`--save-session` 配合使用），进程重启后批量恢复。

断网、断电、杀进程之后接着传，是大文件场景里 aria2 被反复推荐的主要原因。

## BT 与磁力：能做什么，预期放多少

引擎原生支持 BitTorrent 与 Metalink，种子文件和磁力链接都能直接交给它。需要放平预期的地方：

- 速度取决于做种数量与连接质量，冷门资源慢是常态，与工具无关；
- 新任务需要时间连接 DHT 网络与 peer，起步慢、后段快很常见；
- 做种上传请在合法范围内分享。

参数逻辑在手机端同样适用：Aria2App 的任务设置里能改到同一批参数，只是换成了输入框。哪条路径在手机上跑、怎么配，见 [手机端下载与远程遥控用法](手机端下载与远程遥控用法.md)；更系统的参数整理与界面截图，可看 [aria2 参数速查与手机端用法](https://aria2.rggd.pw/)。
