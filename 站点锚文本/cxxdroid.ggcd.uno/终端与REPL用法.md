# 终端与 REPL 用法

除了"建文件、编译、运行"这条正路，Cxxdroid 还内置了两种更轻的代码执行方式：完整功能的交互终端，和基于 CERN Cling 的 C/C++ 解释模式（REPL）。本篇讲它们分别适合什么场景、怎么用。基础环境还没跑通的，先看[手机写 C++ 离线编译指南](手机写C++离线编译指南.md)。

---

## 交互终端：不只是摆设

Cxxdroid 自带的终端模拟器是完整功能的，支持 TAB 补全。它和编译器打通之后，能跑的东西比多数人预期的多——比如用 ncurses 写的终端程序，字符画、颜色、动画都能正常渲染，内置示例集里就有一个 ASCII 火焰动画的演示，跑起来像模像样。

终端适合的场景：

- 跑命令行风格的小工具，看完整输出；
- 观察带终端界面的库（ncurses 等）的实际效果；
- 配合 REPL 做一些交互式的验证。

## REPL：验证语法的最短路径

REPL（读取-求值-循环）来自 CERN 的 Cling 解释器，同一套技术也用在欧洲核子研究组织的科研场景里。它的价值是**省掉整个工程环节**：不用新建文件、不用写 main 函数骨架，敲一行看一行。

典型用法：

```text
[0] int a = 42;
(int) 42
[1] a * 2
(int) 84
```

刚学 C++ 时最容易被打断节奏的就是"想验证一个语法点，却要建文件、写框架、编译、运行"这一整套流程。REPL 把它压成了一问一答：运算符优先级拿不准、指针行为想确认、某个标准库函数的返回值好奇，敲进去当场出结果。

## 两者的分工

| 需求 | 用哪个 |
| --- | --- |
| 验证一行语法、试一个表达式 | REPL |
| 观察终端程序的实际渲染效果 | 交互终端 |
| 完整的作业、多文件工程 | 编辑器 + 编译运行 |

三条路互不冲突，同一个环境里随时切换。REPL 里验证过的代码，确认没问题再搬进正式文件，是效率比较高的一种写法。
