# Root授权步骤与排查

> DataBackup 拿不到 Root 就一步都走不动。三种 Root 方案各自的授权姿势、su 文件改名的处理，以及授权卡片一直不亮的排查顺序。

> **相关文档**：[应用数据备份与恢复流程.md](应用数据备份与恢复流程.md) · [换机迁移实操指南.md](换机迁移实操指南.md)

## 一、为什么必须 Root

它备份的对象是应用私有目录里的数据库、配置与登录态，Android 从系统层面隔离这些位置，普通应用连读都不被允许，所以备份应用数据绕不开 Root。这也是它与厂商自带备份的分工：厂商方案通常只搬应用本身，数据是否完整看厂商实现；它直接读私有目录，应用本体和数据一起打包。

## 二、三种方案的授权方式

第一次打开是欢迎向导，「需要」区有 Root 权限与验证 ABI 两张卡片，「可选」区是通知权限，底部「全部授予」可以一次走完。三种 Root 方案的授权姿势不同：

| Root 方案 | 授权方式 |
| --- | --- |
| Magisk | 点授权卡片，在弹窗里直接允许 |
| KernelSU | 先在 KernelSU 管理器里放行，然后重启 DataBackup |
| APatch | 先在 APatch 管理器里放行，然后重启 DataBackup |

注意 KernelSU 与 APatch 不走应用内弹窗：必须在各自管理器里先动手，放行之后**重启的是 DataBackup 这个应用**，不是重启手机。

## 三、su 文件不叫 su 的设备

少数 ROM 的 su 二进制改了名。入口在「Root 权限」卡片右侧的设置图标，点开「自定义 SU 文件」弹窗，把名称改成设备上的实际文件名（默认 `su`），弹窗会提示重启应用以生效——改完重启 DataBackup 再看卡片状态。

## 四、授权不成功的排查顺序

1. **卡片一直未授权**：先确认设备真的 Root 了——任意 Root 管理器能正常工作才算数。
2. **Magisk 弹窗一闪而过或没弹**：打开 Magisk 日志页看有没有对应请求记录，把 DataBackup 加入授权列表再重试。
3. **KernelSU / APatch 明明放行了还是不行**：核对放行的包名是不是 `com.xayah.databackup.foss`，然后重启应用再看卡片。
4. **怎么都拿不到授权**：确认安装的 ABI 变体与设备匹配，装错变体的应用可能连正常功能都起不来，换对应变体重装。

授权通过后就可以开始第一次备份，流程见 [应用数据备份与恢复流程.md](应用数据备份与恢复流程.md)；装机环节的问题可以在 [DataBackup 介绍站](https://databackup.wrwq.fun/) 的下载页找到对应排查。
