# 四种投屏协议分别怎么选

> 手机往电视投画面，列表里一会儿叫屏幕镜像、一会儿叫投送、一会儿叫投放到电视——它们背后是四条不同的协议。挑对路，一次连上；挑错路，折腾半天还以为是设备坏了。

相关条目：[旧电视盒子改造为投屏接收端](旧电视盒子改造为投屏接收端.md) · [投屏黑屏卡顿没有声音怎么办](投屏黑屏卡顿没有声音怎么办.md)

## 一、先看发送端是谁，再看投什么

四条协议的分野其实只有两个问题：**你用什么设备发**，以及**你想投整块屏幕还是只投一条内容**。

| 协议 | 谁在用 | 投的是什么 | 适合的场景 |
| --- | --- | --- | --- |
| AirPlay | iPhone / iPad / Mac | 整屏镜像，或单条内容 | 苹果设备投到没有 AirPlay 的电视 |
| Cast | 安卓应用、Chrome 浏览器 | 内容本身 | 视频应用右上角的投送图标 |
| DLNA | 各类本地播放器、老视频应用 | 内容本身 | 只有"投放到电视"入口的老应用 |
| Miracast | 安卓 / Windows | 整屏镜像 | 受系统版本限制，见第四节 |

接收端装好 [AirScreen 投屏接收端](https://www.bmww.store/)之后，四条路收在同一个应用里，来了什么信号就接什么信号，不用按协议分别装几套东西。

## 二、想投整屏：镜像路线

镜像投的是发送端的整块屏幕，切应用、弹通知都会跟着上屏，适合演示、网课、看没有投送按钮的内容。

- 苹果设备走 **AirPlay**：控制中心 → 屏幕镜像 → 选中接收端的设备名（形如 AS-xxxx），需要配对码时照着电视上显示的输入即可。
- 安卓与 Windows 理论上走 **Miracast**，但这条路有硬边界（见下），实际可用性要看接收端的系统版本。

镜像对网络的要求更高，路由器不给力时优先把发送端挪到离路由近的位置，或改用 5GHz 频段。

## 三、想投内容：投送路线

投送投的是内容本身——手机只负责"点播"，大屏自己拉流播放，手机锁屏、切出去聊天都不影响播放。

- **Cast**：YouTube、Chrome 等带投送按钮的应用都走这条路，点图标、选设备即可。
- **DLNA**：不少本地播放器里的"投放到电视"就是它，界面朴素但胜在通用，老设备也能对上。

看剧、听歌优先走投送路线：画质由接收端直接拉取，通常比镜像转拍一层的画质更稳，延迟感受也更从容。

## 四、Miracast 这条路要先看清边界

Miracast 功能自 Android 8.0（Oreo）起停用。接收端跑的是较新系统时，发送端的"无线显示"里搜不到它属于正常现象——不是装坏了，也不是设置错了。

遇到这种情况别在这条路上反复折腾，直接换 AirPlay、Cast 或 DLNA 中对应的那条即可。三条常用路覆盖了苹果全家、安卓主流应用与老播放器，绝大多数家庭场景够用。

## 五、一张速查表收尾

- iPhone 投屏 → AirPlay（镜像或单条内容都行）
- 安卓视频应用点播 → Cast 或 DLNA
- 老播放器只有"投放到电视" → DLNA
- Windows 投屏 → 优先 Chrome 标签页投送（Cast），Miracast 视接收端系统而定
- 玩游戏、要跟手 → 镜像路线优先，接收端打开硬件加速
