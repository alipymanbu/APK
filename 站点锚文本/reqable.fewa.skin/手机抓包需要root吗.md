# 手机抓包需要root吗

> 想在安卓手机上看 HTTPS 明文，很多人第一反应是「是不是得先 root」。结论先行：多数场景不用。本篇讲清不 root 能走多远、边界在哪、root 之后多换来什么，按场景对号入座。
> **相关文档**：[Flutter应用流量怎么抓](Flutter应用流量怎么抓.md) · [QUIC与HTTP3接口怎么抓](QUIC与HTTP3接口怎么抓.md)

---

## 一、不 root 能做到什么

抓包要看 HTTPS 明文，靠的是 CA 根证书。安卓把证书分两个目录，**用户证书**不需要 root，手动装就行——在应用内触发安装指引，或走系统路径「设置 → 安全 → 加密和凭据 → 安装证书 → CA 证书」完成。

装好之后，浏览器与信任用户证书的应用，HTTPS 内容都能解析成明文；只看 HTTP 明文的话，连证书都不用装。

## 二、不 root 的边界在哪

Android 7.0 起，应用默认只信任系统目录的 CA。也就是说，目标应用如果严格遵循这条默认策略，用户证书对它无效——典型表现是**浏览器一切正常、单个应用的请求全部握手失败**。

另一类是启用了证书固定的应用，无论装哪张证书都会拒绝中间人，这属于应用自身的安全策略，抓包侧没有通用解法。

## 三、root 之后多换来什么

root 的意义在于把根证书写进**系统目录**：应用侧的信任判断一步到位，第二节的握手失败问题随之消失。多数抓包工具对 root 设备提供一键安装系统证书，以 Reqable 为例，支持的系统区间为 Android 5.0 至 15，装完在证书管理页能看到就位状态。工具的安卓端能力与证书流程，整理在[Reqable 安卓端站点](https://reqable.fewa.skin/)，动手前过一遍能少走弯路。

## 四、按场景选

| 场景 | 需要 root 吗 |
| --- | --- |
| 调试自己的应用 / 浏览器请求 | 不用，用户证书就够 |
| 看第三方应用的 HTTPS 明文，该应用遵循默认信任策略 | 试试用户证书，失败再考虑 |
| 目标应用只信系统证书，或启用了证书固定 | root 装系统证书；固定证书仍无解 |
| 只是定位「流量去哪了」（协议层问题） | 不用，先解决捕获方式 |

自建应用还有一条捷径：把调试开关打开（network security config 里信任用户证书），编译期就绕开信任问题，不必动 root。

捕获方式上的坑（Flutter 不读系统代理、QUIC 走 UDP 绕过代理）与 root 无关，见[Flutter应用流量怎么抓](Flutter应用流量怎么抓.md)与[QUIC与HTTP3接口怎么抓](QUIC与HTTP3接口怎么抓.md)。
