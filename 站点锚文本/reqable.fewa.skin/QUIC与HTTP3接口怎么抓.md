# QUIC 与 HTTP3 接口怎么抓

> 越来越多服务默认走 HTTP/3，抓包列表里却看不到它们的身影——QUIC 跑在 UDP 上，传统代理式抓包很容易漏掉这一层。本篇讲清 HTTP/3 和前两代的差别、代理方案为什么容易失灵，以及抓包工具需要具备什么。
> **相关文档**：[Flutter应用流量怎么抓](Flutter应用流量怎么抓.md) · [手机抓包需要root吗](手机抓包需要root吗.md)

---

## 一、HTTP/3 差在哪

前两代 HTTP 建立在 TCP 之上，HTTP/3 则换了底座：跑在 QUIC 上，而 QUIC 直接用 UDP。握手更快、弱网下更稳，代价是整套传输逻辑和 TCP 完全不同——对抓包工具来说，等于要多支持一整套协议解析。

## 二、代理式抓包为什么容易漏掉它

经典抓包链路是 HTTP 代理：应用主动把请求交给代理，代理替它建立 TCP 连接。这套机制对 HTTP/1 和 HTTP/2 好用，但 QUIC 的 UDP 流量根本不会走进为 TCP 准备的代理通道——于是浏览器和服务器悄悄升级到 h3 通信，抓包列表里却一片安静，看起来就像「应用没发请求」。

还有个容易误判的细节：浏览器对支持 HTTP/3 的服务器会自动尝试升级，连不上 h3 时回落 h2。同一条请求可能这次是 h3、下次是 h2，列表里看到哪个取决于当时的回落结果。

## 三、工具需要具备什么

抓 HTTP/3 接口，工具至少要满足两条：

- **三代协议都支持**：HTTP/1.1、HTTP/2、HTTP/3(QUIC) 都能解析，列表里能区分协议版本；
- **流量接管方式跟得上**：依赖系统代理的方案对 QUIC 无能为力，VPN 式接管才能把 UDP 流量也收进来。

Reqable 在这点上给得比较全：全平台支持 HTTP/1、HTTP/2 与 HTTP/3(QUIC)，安卓端走 VPN 通道接管流量。协议支持与界面细节整理在[Reqable 安卓端整理页](https://reqable.fewa.skin/)，选工具前可以先对着真实截图核对一遍。

## 四、实操核对三件事

1. **确认请求真的走了 h3**：详情页的协议字段会显示，显示 h2 就说明当时回落了；
2. **别把「没抓到」当「没发生」**：先看工具的协议支持，再怀疑应用——很多「抓不到」是 QUIC 绕过了代理；
3. **对照测试**：让设备回落到 h2 再抓一次（比如确认工具接管了 UDP），两次对比能快速定位流量去向。

传输层原因导致的漏抓，和证书信任导致的握手失败是两回事，后者见[手机抓包需要root吗](手机抓包需要root吗.md)。
