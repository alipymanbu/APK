# 安卓手机怎么看哪个应用占 CPU

> 手机发烫、风扇声没有但就是烫、电量掉得快——先搞清楚是哪一个应用在吃 CPU，再谈怎么办。
> **相关文章**：[免root结束后台进程的方法](免root结束后台进程的方法.md) · [后台应用杀掉又自动启动怎么办](后台应用杀掉又自动启动怎么办.md)

## 一、先有个预期：进程多不等于有问题

安卓是 Linux 内核，后台常驻几百个进程是常态（整机 700 个以上很常见），绝大多数只是系统服务在待命。「占 CPU」要看的是**持续的高占用**，而不是某一次截图里的数字——瞬时跳高多半是同步、索引这类例行任务，过去就过去了。

## 二、系统自带的查看途径

不装任何东西也能看个大概：设置里连点版本号 7 次打开开发者选项，在「开发者选项 → 运行服务」（不同品牌叫法略有差异，可在设置里直接搜「运行服务」）里能看到当前运行的服务与各自内存。限制也明显：只有内存维度、没有 CPU 曲线，只适合瞄一眼，定位不了「谁在吃 CPU」。

## 三、用任务管理器类工具看曲线

要看 CPU 曲线、按占用排序、点进单个进程看明细，就得靠专门的工具。以开源的 TaskManager 为例（需配合 Shizuku 授权，见相关文章），路径是这样的：

1. 打开应用，先看 **CPU 标签的整机曲线**——确认是真高还是瞬时抖动；
2. 切到 **进程列表**，按占用排序，找出持续霸榜的那一个；
3. 点开这一行看 **详情**：PID、归属应用、内存、优先级、线程数都在，能对上包名再决定要不要处理。

卡顿排查的通用套路：开着监控**复现一次卡顿**，回头看曲线哪一段窜高、当时排在最前的是谁——能持续复现的才是元凶。

详细的资源曲线用法、GPU 与硬件信息页的说明，整理在 [TaskManager 介绍站](https://taskmanager.usea.quest/)，这里不重复展开。

## 四、找到元凶之后

- **认识的应用**：正常使用就该占这么多，属于合理消耗；
- **不认识的应用**：先查清来源再动手，别急着结束；
- **确定要处理的后台应用**：结束进程只是当场生效，想让它别再自己回来，要配合系统的后台限制开关（见[后台应用杀掉又自动启动怎么办](后台应用杀掉又自动启动怎么办.md)）。

## 五、两个提醒

- 进程列表里混着系统服务与厂商常驻组件，**只处理能说出包名归属的应用**，认不出的一律只看不碰；
- 监控类工具自身也会耗一点电，排查完可以退出后台，不必常开。
