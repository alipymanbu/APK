# Kazumi 规则导入与视频源配置

> 这篇讲 Kazumi 的核心机制「规则」：从哪里装、四种导入方式怎么选、失效了怎么换，以及写规则前的几条硬约束。
> **相关文档**：[时间表与追番管理](时间表与追番管理.md) · [播放设置与画质调优](播放设置与画质调优.md) · [WebDAV 同步与换机迁移](WebDAV同步与换机迁移.md)

## 一、先理解：规则为什么是一切的前提

Kazumi 本身不提供任何视频内容。你搜番、出列表、拿到播放线路，整条链路都由「规则」驱动：一条规则负责按关键词返回作品列表，再按你选中的作品返回线路和剧集，视频地址的提取由应用内部完成。

所以「搜不到」「播不了」这类问题，绝大多数不是软件坏了，而是规则缺位或失效。反过来，某个资源站改版导致看不了，换一条规则就能恢复，不用等软件更新——这是把内容源做成规则的意义。

## 二、四种导入方式

入口在 `我的` → `规则管理`，点右上角加号：

| 方式 | 适用场景 |
| --- | --- |
| 从规则仓库添加 | 最常用。规则仓库托管在 GitHub 上，客户端自动拉取列表，选中点安装即可 |
| 从剪贴板添加 | 别人发来一段规则文本，复制后直接粘贴导入 |
| 从 JSON 文件添加 | 手上有 `.json` 规则文件（网盘或论坛下到的） |
| 新建规则 | 自己动手写，见下文第四节 |

导入完成后规则出现在列表里，保持启用状态，搜索和播放才会用到它。

## 三、规则失效的排查顺序

规则对接的是外部站点，站点改版、换域名、加防护都会让规则失效，表现为搜索无结果、列表空白或播放解析失败。按成本从低到高排：

1. **换线路**：能搜到但这条线路播不了，先在详情页或播放页切换其他线路——一条规则往往带多条线路；
2. **换规则**：多备几条覆盖同类站点的规则，哪条活着用哪条，规则可并存、可随时停用；
3. **重拉规则**：从规则仓库重新安装同名规则，覆盖旧版；
4. 以上都无效，才轮到排查软件本身。

日常建议只有一条：别只留一条规则。手里有备用，出问题就是一次点击的事。

## 四、想自己写规则，先记住这几条

规则分 XPath 与 API 两类，搜索和选集可以各自独立选类型、同一条规则里可混用。新手起步的硬约束：

- XPath 选择器**只支持以 `//` 开头**的写法，从根路径开始的写法不认——自定义规则检索不出来，多半栽在这里；
- 搜索地址里把关键词位置替换成 `@keyword`，执行搜索时会自动编码填入；
- 字段就九个：`Name`、`Version`、`BaseURL`、`SearchURL`、`SearchList`、`SearchName`、`SearchResult`、`ChapterRoads`、`ChapterResult`，照着仓库里的示例规则抄一遍最快；
- 写完能搜不能播：关掉这条规则的「使用内置播放器」选项，改用 webview 播放提高兼容性；内置播放器能用时建议开着，弹幕和流畅度都更好。

动手前想先看看这款应用的界面与功能全貌，可以逛逛 [Kazumi 观测站](https://kazumi.bmww.store/)，首页把运行链路拆成了三步图解。
