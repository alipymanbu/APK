# Stellar 免 root 权限管理怎么选

本篇讲安卓免 root 工具的选型思路：哪些场景值得上一套特权框架、Stellar 在其中处在什么位置，以及它靠什么把权限管住。激活操作与授权细节分别见[无线调试激活步骤](无线调试激活步骤.md)与[shizuku兼容与应用授权](shizuku兼容与应用授权.md)。

---

## 什么情况下需要这类工具

不少玩机应用会卡在同一道墙前：真正干活的那几个系统 API，普通应用拿不到调用权限，功能要么残缺、要么绕弯实现得很慢。想让应用直接调这些 API，过去的路子基本三条：

- **刷机 Root**：一整套解锁、刷入、提权走完，保修作废，操作失手有变砖风险；
- **解锁 Bootloader**：解锁即清空数据，部分机型解锁通道干脆不存在；
- **shell 脚本变通**：用受限权限绕着实现，速度慢、能做的事有限。

如果只是想让几个工具用上高权限，为它们把整机 Root 掉显然不成比例——这正是免 root 特权框架存在的理由。

## Stellar 的解法：服务进程代为站位

Stellar（包名 roro.stellar.manager）的思路是：通过 ADB 无线调试在手机上拉起一个高权限服务进程，受权应用经由这个进程间接调用系统 API，调用速度与直调几乎无差。整个过程不改系统分区、不解锁引导，手机保持原样。

它在授权管理上做了三重把关：

1. **自动降权**——服务只保留必要权限，避免整段 Root 权限裸奔；
2. **分级授权**——核心 API 访问与服务伴随启动分属两个独立权限，按需发放；
3. **一次性授权**——对敏感工具可以只给一次会话的授权，用完即收。

## 挑这类工具时值得看的几点

- **生态兼容**：手里已有的工具能否直接接上，Stellar 提供兼容层放行存量应用；
- **授权粒度**：是否区分永久与一次性，撤销入口是否齐全；
- **驻留能力**：重启手机后服务能否自动恢复，有没有开机启动选项；
- **体积与占用**：这类框架常驻后台，太重反而拖累日常使用。

Stellar 的安装包在 4 MB 出头，设置页里开机启动（无线调试 / Root 两条通道）与兼容层开关都有独立入口。想直接上手装的，安装文件资源获取入口见 [Stellar 介绍站](https://stellar.boop.uno/)，激活流程见[无线调试激活步骤](无线调试激活步骤.md)。
