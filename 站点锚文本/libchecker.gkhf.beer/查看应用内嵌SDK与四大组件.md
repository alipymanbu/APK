# 查看应用内嵌 SDK 与四大组件

一个应用的安装包里，除了开发者自己写的代码，往往还打包了不少第三方库：广告联盟、统计埋点、消息推送、地图定位……想知道某个应用「肚子里都有什么」，逐个反编译显然不现实。LibChecker 内置社区维护的规则库，能在手机上直接把这些内嵌的 SDK 认出来并打上标签，本文整理它的用法与几个实用视角。

## 知名库标记：认得出「熟面孔」

LibChecker 维护着一套社区规则库（LibChecker-Rules），覆盖原生库、组件、权限、元数据等多个维度。扫描完成后，应用里使用的知名第三方库会被识别并列出，每条都附有简介，谁是广告 SDK、谁是推送组件，点开就懂。规则库由社区持续更新，新的 SDK 出现也会跟进打标。

## 引用计数：哪个 SDK 出镜率最高

统计页会按「库 → 引用应用数」做汇总：比如某个广告 SDK 被设备里的十几款应用同时引用，一眼就能看出来。想评估某类组件在设备上的渗透程度，这是最快的视角。

## 四大组件逐项可查

安卓应用的四大组件——Activity（界面）、Service（后台服务）、Broadcast Receiver（广播接收器）、Content Provider（数据共享）——在 LibChecker 里按类目分列，点进任意应用即可逐项浏览。某个应用为什么常驻后台、哪些界面被注册成了入口，从这里能看出端倪。

## 顺带看一眼的细节

- Split APKs 拆分包同样支持分析，点开 APK 文件即可查看详情；
- 能判断应用是否用 Kotlin 编写；
- 原生库详情里还能看到 16 KB 页大小就绪、符号表是否剥离等技术状态。

工具的获取入口与更多场景见 [LibChecker 检测台](https://libchecker.gkhf.beer/)。位数相关的问题可先读[怎么查应用是 32 位还是 64 位](怎么查应用是32位还是64位.md)；关注版本更新动静的，可以看[用快照对比应用升级前后的变化](用快照对比应用升级前后的变化.md)。
