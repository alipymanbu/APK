# 怎么查应用是 32 位还是 64 位

从应用列表上一般看不出一个应用是 32 位还是 64 位——但这件事直接影响兼容性：64 位设备跑 32 位应用会损失性能，部分新系统甚至不再支持纯 32 位包。本文介绍在手机上用 LibChecker 快速核对的方法，几分钟就能把自己设备里的「位数家底」摸清楚。

## 方法：看 ABI 徽章

ABI（Application Binary Interface）决定了应用的原生库按哪种指令集编译，日常口语里说的「32 位 / 64 位」指的就是它。安装并打开 LibChecker 后，应用列表里的每一项都会带上一枚架构徽章，比如 `64 BIT` 配 `arm64-v8a`，代表这是一款 64 位应用；只标 `32 BIT` 的就是还停留在旧架构的包。

具体步骤：

1. 打开 LibChecker，等首次扫描完成，应用列表逐个带出徽章；
2. 看任意应用名称下方的一行小字，`64 BIT` 即 64 位、`32 BIT` 即 32 位；
3. 点进单个应用，还能看到更细的架构划分（如 arm64-v8a、armeabi-v7a）。

## 全机统计：谁还没跟上 64 位

除了逐个看，统计页还能把全机应用的架构分布汇总成图表：64 位占多少、32 位还剩几个，一目了然。想清理旧应用时，这份名单就是依据。

## 常见疑问

**没有徽章的应用是怎么回事？** 部分应用不含原生库、纯 Java/Kotlin 实现，不存在位数问题，列表里可能不显示架构徽章。

**需要 Root 吗？** 不需要，LibChecker 的常规查看与分析功能用普通权限即可完成。

想先装上工具再动手，可以到 [LibChecker 检测台](https://libchecker.gkhf.beer/)获取安装文件资源；装好之后，还可以接着看[查看应用内嵌 SDK 与四大组件](查看应用内嵌SDK与四大组件.md)和[用快照对比应用升级前后的变化](用快照对比应用升级前后的变化.md)。
