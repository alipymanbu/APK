# 不写代码怎么做游戏

> 本篇聊「不会编程能不能做游戏」这个问题：把游戏逻辑拆成条件与动作之后，剩下来的事比想象中少得多；顺便讲清事件表思路下，一个新手前两个小时该干什么。

## 一、卡住新手的从来不是代码，是「不知道先做什么」

想做游戏的人大多卡在同一个地方：打开一个空白工程，盯着画布不知道第一下点哪。传统引擎要求你先理解脚本、坐标、物理体一堆概念，而无代码路线把这些问题换了一种问法——不问「怎么写」，只问「什么时候、发生什么」。

GDevelop 就是这条路线的代表：编辑器按 MIT 许可开源，核心逻辑全靠事件表表达。事件表长得很像表格，左半边写条件（玩家碰到了金币），右半边写动作（得分加一、播放音效）。游戏运行时引擎每一帧都来检查这张表，条件成立就执行动作——所有游戏，拆到底都是一堆这样的「当……就……」。

## 二、行为：不用写就能让角色「活」起来

比事件表更省事的是预置行为。让角色会走路会跳，不需要自己算重力和速度曲线——给它挂一个「平台跳跃角色」行为，跳跃高度、移动速度都是现成的数值框；让平台能托住角色，挂「平台」行为；敌人来回巡逻，挂「路径移动」行为。

上百种行为可以叠加在同一个对象上，参数随时改、改完立刻预览。新手在这一步的体感通常很强：原来「做游戏」的大部分时间，是在调数值而不是在写逻辑。

## 三、前两个小时的建议路线

1. **从示例开始，别开白板。** 内置两百多个完整可玩的示例，平台跳跃、射击、解谜都有，先试玩看懂再另存为自己的项目；
2. **改熟一件小事。** 换角色图片、把跳跃高度调高一格、给金币加个旋转——每次只改一两处，改完马上预览；
3. **再碰变量。** 生命值、得分显示都靠「变量记数值 + 文本对象显示数值」这一对组合，做过一次就通了。

手机上也能完整走完这条路线，界面实拍与入口整理在 [GDevelop 手机版介绍站](https://gdevelop.qjxz.skin/)。

## 四、无代码不是终点

事件表思路练熟之后，想往深处走也接得上：引擎支持在事件里直接写 JavaScript 表达式，导出端覆盖安卓、网页与桌面。换句话说，无代码是低门槛的入口，不是能力的天花板——先把第一个能玩的 demo 做出来，比纠结「学哪个引擎」有意义得多。
