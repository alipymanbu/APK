# 手机跑大模型卡顿怎么办

> 同一个模型，别人手机上对答如流，你的手机上半天蹦一个字——多半不是玄学，是模型与硬件不匹配。这篇按「从最常见到最少见」的顺序给排查办法。

---

## 先看卡在哪一段

| 现象 | 大概率原因 |
| --- | --- |
| 加载模型就失败，或直接闪退 | 运行内存不够，装不下这个模型 |
| 能聊，但每个字之间停顿明显 | 模型尺寸超出芯片算力，生成速度被拖慢 |
| 一开始快、几轮对话后越来越慢 | 长对话把上下文撑大，或手机发热降频 |
| 点发送后长时间无响应 | prompt 处理阶段太长，通常是上下文里塞了太多内容 |

## 五个可操作的排查办法

1. **换小一档的模型**。这是见效最快的一条：同一系列往往有不同参数规模的版本，先跑得动、再追求效果。
2. **换低一点的量化档位**。量化精度低一档，体积和内存占用都会明显下降，速度随之改善；效果损失对日常问答通常可以接受。
3. **清空或精简上下文**。长对话会让每次回复都带着全部历史重算，新开一个对话窗口往往立刻恢复速度。
4. **别让手机带着壳、在被子上跑**。推理是持续满载运算，发热降频是物理规律，散热条件直接决定能否维持速度。
5. **关掉不用的后台应用**。给推理腾出运行内存，尤其是相机、游戏这类常驻大户。

## 用实测数据挑手机

如果换模型、换设置都试过还是不满意，那可能真的是机器算力到顶了。判断一台手机跑本地模型的真实水平，可以看社区实测数据：PocketPal 应用内置了基准测试，量的是 prompt 处理速度与 token 生成速度两项硬指标，结果汇总在按 Glicko-2 评分排序的社区排行榜里，每 6 小时随新提交重算一次——换机前查一眼同款机型的实测表现，比看纸面参数靠谱。入口和界面说明见 [PocketPal 中文介绍站](https://pocketpal.fedq.quest/)。

## 卡顿之外的问题

模型下载不动、装完打开是空白页这类「跑不起来」的问题，与速度问题不是一回事：多数情况是模型还没下载或没加载，先照着[GGUF模型怎么在手机上打开](GGUF模型怎么在手机上打开.md)把模型装上再谈速度。
