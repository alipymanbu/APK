# 组件误关后的恢复顺序

用组件控制器的人都绕不开一次误关：应用闪退、通知消失、某个页面打不开，但记不清刚才关了哪个。别慌，绝大多数情况几分钟内就能恢复，最坏也有兜底手段。文中提到的开关操作都在 [Blocker 组件开关工具](https://blocker.uerg.quest/) 里有对应入口。

## 一、先按症状定位

| 症状 | 最可能的组件 |
| --- | --- |
| 应用一打开就闪退 | 核心 activity 或被依赖的 provider |
| 某个页面打不开，应用能开 | 对应 activity |
| 收不到通知、不自启了 | receiver（推送或开机广播） |
| 后台任务不跑、下载失效 | service |

判断不了就直接跳到下一步，先恢复再研究。

## 二、由轻到重恢复

1. **开回来**：回到该应用的组件页，把最近一次调整里关掉的组件逐个开回。开关即时生效，不用重启应用；开完应用还异常就彻底杀掉进程再开。
2. **对照规则文件**：调整前导出过规则文件的话，打开对照——里面记录的就是当时的完整开关清单，逐项核对哪些是后来误加的。
3. **卸载重装**：PackageManager 通道的禁用状态随卸载清除，重装等于彻底重置组件状态，代价是应用本地数据。动手前先在应用内备份；IFW 规则是系统级的，重装后记得验证拦截是否还在。

## 三、系统应用要格外小心

误关普通应用最坏就是重装；误关系统应用的关键组件（桌面、系统界面）可能卡在开机界面进不去系统。预防永远优于恢复：动系统应用前想清楚「关掉它还能不能进设置、还能不能打开工具本身」，一次只改一两个、改完立即验证。

真进不了系统时，剩下的手段是连电脑用 adb 执行 `pm enable 包名/组件名` 把组件开回（前提是此前开过 USB 调试）；连 adb 都不可用，就只剩恢复出厂。所以每一步谨慎都是在给自己留退路。

## 四、防复发

- 批量调整前先导出规则存底，一分钟的功夫，出事后省半小时；
- 每关一组验证一次，别一口气关十个再回头看；
- 被应用「复活」的组件换 Intent Firewall 通道再禁；
- 拿不准的组件跳过，只动看得懂说明的。
