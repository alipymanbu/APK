# 手机上读 GitHub，除了浏览器和自家 App 还有第三种方式

在手机上刷 GitHub 的痛点很具体：网页端信息密度低，列表挤成一团，看个 README 还得不停捏合缩放；而 GitHub 自家的移动应用是围绕协作流程设计的，通知、审阅、评论这些工作台能力是主角，纯粹「翻项目、读代码、追更新」的阅读体验反而不是它的重点。

于是第三方客户端有了一块明确的生存空间：**只把「读」这一件事做到顺手**。

## 一个阅读器该有的样子

以开源项目 Gloom 为例，它的做法是按 Material You 的路数把四个页面重画了一遍：

- **动态流**：按你关注的人和 star 过的仓库往外铺，不是推荐算法，上限取决于你的关注列表；
- **探索页**：看平台上热度较高的项目，不知道翻什么的时候去逛；
- **仓库页**：目录树、按语言着色的代码、渲染成排版的 Markdown、提交记录、Releases；
- **用户主页**：头像、简介、置顶仓库、README、关注数据同屏铺开。

写操作收敛到 star、关注、表情回应三类。这看起来是阉割，实际是把定位想清楚了：读是高频动作，评论区留到电脑上一次性处理，通勤路上读完全够用。想详细了解这套界面的实拍与分工，可以看 [Gloom 的介绍页](https://gloom.kook.yoga/)，里面有四张真实界面截图。

## 为什么授权登录是跳浏览器

这类客户端自己没有账号体系，第一次打开会停在登录页，走 GitHub 的 OAuth 授权：密码只输在 GitHub 自己的页面上，应用拿到的是授权凭证。想断开时，去 GitHub 网页端的 Settings → Applications → Authorized OAuth Apps 里移除对应条目即可，光卸载应用并不撤销授权。

## 怎么判断这类项目靠不靠谱

第三方客户端最怕弃坑，判断方法三步：

1. 看仓库最近一次提交或发版的时间，比 star 数管用；
2. 看 Issues 里有没有维护者回复；
3. 看许可协议（比如 GPL-3.0）是否允许你按需要的方式使用。

满足这三条的，就可以放心装来用一段时间了。
