# 用第三方 GitHub 客户端，授权安全这件事要说透

第三方 GitHub 客户端都绕不开一个问题：它凭什么能读我的仓库、我的关注列表？答案是把授权想明白——想明白之后，「安不安全」就不再是一个感觉问题。

## 它拿到的是什么

这类应用自己没有账号体系，登录走的是 GitHub 的 OAuth 授权：应用把你带到 GitHub 自己的登录页，你在那里输入账号密码——**密码从头到尾不经过第三方应用**。授权确认页会列出这个客户端能读、能做的范围，你同意之后，应用拿到的是一枚有权限边界的令牌，而不是你的密码。

所以评估一个第三方客户端，看两点就够：

1. **登录入口对不对**：正常流程一定是跳到 GitHub 的页面完成登录，任何在应用内直接要你输 GitHub 密码的都该警惕；
2. **权限范围对不对**：以阅读为主业的客户端（比如 Gloom 这类），拿到的权限应该以读取为主，写操作收敛到 star、关注、表情回应这类轻动作，看到「要动你的仓库内容」的授权就该多想一步。

## 令牌能做什么、不能做什么

OAuth 令牌的权限边界在授权页写得很清楚。一个定位为「阅读器」的客户端，能用它做的也就是读公开内容、按你的关系生成动态流、替你点个 star。它做不了建 issue、发评论、合并 PR 这类协作写操作——这类客户端通常也不打算做。

## 不想用了怎么断干净

分两步，缺一不可：

- **卸载应用**：清掉的是本地的登录状态和设置，GitHub 账号里的 star 和关注原样都在；
- **撤销授权**：到 `github.com` 的 Settings → Applications → Authorized OAuth Apps，找到对应条目移除。这一步不做的話，令牌在有效期内仍然存在。

换手机同理：新机器上重新装、重新授权一次即可，star 和关注跟着账号走。如果对某个客户端的界面和权限范围没把握，先看它的介绍页（比如 [Gloom 的介绍与获取指引](https://gloom.kook.yoga/)）核对授权环节的说明，再决定装不装。

一句话总结：OAuth 机制本身把密码隔在了应用外面，你要做的只是在授权页看清范围、不用了记得回去撤销。
