# OMate API配置与模型分工

本篇讲 OMate 的 API 怎么配、密钥存在哪、以及高级设置里那一排模型分别负责什么。这款应用走「自带 API」模式，先把这层配置想明白，后面的聊天体验才会顺。安装环节的问题见[安卓版下载与安装步骤](安卓版下载与安装步骤.md)。

---

## 先回答：要不要钱

OMate 本身不收对话服务费——它不提供 AI 服务，角色「活过来」靠的是你自己配置的服务商。对话消耗的是你自己的 API 额度，接本地模型则完全由自己的设备承担，私密且没有额度焦虑。内置助手「小M同学」也走你的配置，同样不产生额外费用。

## 配置步骤

1. 在任一 AI 服务平台申请一个 API 密钥。
2. 打开 OMate 的「设置 → API 设置」，点 + 新增配置，填入名称与密钥。
3. 右下角的悬浮按钮可以快速填入常用服务商的模板；填完保存，新配置会自动设为启用状态。

密钥只保存在设备本地，不上传到任何服务器；配置列表里密钥以打码形式展示，编辑时注意别截图外传。

## 理论上都能接，但要看兼容性

符合 OpenAI 规范的接口理论上都可用，不过不同服务商对规范的实现程度不一，个别服务商的接口可能出现兼容问题。实际表现以你接入的服务商为准。

## 高级设置里的模型分工

对话之外，OMate 还允许给不同任务指定不同的模型，在 API 配置页的「高级设置」里逐项添加：

- **嵌入模型**：长期记忆与知识库的向量检索靠它，大段资料「用多少取多少」全看这一项。
- **总结模型**：对话摘要与记忆整理，影响角色「记得住多少」。
- **语音模型**：语音交互里的语音合成。
- **生图模型**：图片生成相关的功能。
- **语音识别模型**：语音输入的转写。

对话模型与这些辅助模型可以各用各的，成本与质量可以分开权衡——比如对话用能力强的，总结用便宜的。

## 配好之后去哪验证

回到「发现」页随便点开一张角色卡发一条消息，能正常回复即代表配置生效。想把手里的酒馆资产搬进来，看[角色卡导入与酒馆迁移](角色卡导入与酒馆迁移.md)；更多界面与功能速览可以在 [OMate 介绍站](https://omate.gkhf.beer/)上翻一遍。
