# Magisk 模块网页界面打不开怎么办

> 刷了带网页界面的模块，在 Magisk 里却找不到入口。本篇讲清原因，以及从确认宿主到拉起界面的处理顺序。
> **相关文档**：[模块提示找不到界面宿主怎么办.md](模块提示找不到界面宿主怎么办.md) · [模块网页界面的工作原理.md](模块网页界面的工作原理.md)

---

## 一、先弄清为什么打不开

不少 Root 模块除了启动脚本，还配了一套网页界面，但能否打开取决于你用的 Root 环境：

| 环境 | 界面入口 | 说明 |
|---|---|---|
| KernelSU / APatch（较新管理器） | 模块卡片上的界面按钮 | 点按钮即可进入模块页面 |
| Magisk | 没有内置入口 | 模块只能靠自己的 action 脚本拉起外部宿主应用 |

所以问题通常不在模块本身，而是这台设备上缺少一个负责打开模块页面的宿主应用。

## 二、处理顺序

1. **看模块的说明，确认它要哪种宿主**。有的模块只认特定包名的应用，说明页里一般会写清楚。
2. **装一个独立的界面宿主**。比较常见的选择是 [KsuWebUI](https://ksuwebui.wrwq.fun/)，它只负责加载模块网页，安装包很小，Magisk、KernelSU、APatch 环境都能配合使用。
3. **回到 Magisk 管理器，点模块卡片上的 action 按钮**。脚本会检查设备上的宿主应用：以个别常见模块的实现为例，会先找 KsuWebUI，找不到再看其他宿主，都没有时才提示缺应用。
4. **首次拉起宿主时，在 Root 管理器弹窗里放行超级用户请求**。核对应用名与包名再允许，之后每次打开不再询问。

## 三、还是打不开时

- 确认 Root 权限本身正常：其他模块的脚本能否执行，能不能看到超级用户弹窗。
- 核对宿主包名与模块要求是否一致，个别模块写死了只认一个包名，装错应用不会生效。
- 模块界面加载后一直空白，可以重启一次宿主应用，或在模块说明里查有没有已知的兼容性说明。
