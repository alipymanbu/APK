# 模块网页界面的工作原理

> Root 模块自带的网页界面是怎么从模块目录变成手机上能点的界面？本篇按"模块页面 → 宿主加载 → 授权放行"三段讲清这条链路。
> **相关文档**：[Magisk模块网页界面打不开怎么办.md](Magisk模块网页界面打不开怎么办.md) · [模块提示找不到界面宿主怎么办.md](模块提示找不到界面宿主怎么办.md)

---

## 一、模块页面：装在模块目录里的网页

KernelSU 的模块规范允许模块带一个网页目录：模块作者用 HTML、CSS、JavaScript 写好页面，随模块一起安装到设备上。这类页面不是普通网页——页面里的脚本可以调用宿主提供的接口，执行命令、读取系统状态，所以模块作者常拿它做设置面板、开关列表这类交互界面。

## 二、宿主：负责把页面显示出来的应用

页面自己不会出现在屏幕上，需要一个宿主应用用 WebView 把它加载出来，并把"执行命令"这类能力接到页面上。宿主通常有三种来路：

1. **管理器内置**：较新的 KernelSU 与 APatch 管理器直接在模块卡片上提供界面按钮。
2. **独立宿主**：一个只做加载模块页面这一件事的应用，例如 [KsuWebUI](https://ksuwebui.wrwq.fun/)，装上后多数按包名搜索宿主的模块脚本都能找到它。
3. **模块脚本拉起**：Magisk 环境下没有内置入口，模块靠 action 脚本寻找并启动宿主。

## 三、授权：为什么第一次打开要放行

宿主要读取模块列表、渲染页面，页面里的操作又要以 Root 权限执行，所以第一次打开时 Root 管理器会弹"超级用户请求"。核对应用名与包名再放行即可；选"永久"可以避免之后每次询问。拒绝授权的话，宿主一般会停在"请授予 Root 权限"的提示上。

## 四、整条链路串起来

```
模块安装 → 模块目录里的网页文件
              ↓
     宿主应用加载页面（WebView）
              ↓
   Root 管理器放行超级用户请求
              ↓
  页面调用接口执行命令 → 你在屏幕上操作
```

链路里任何一环断了，表现都不一样：缺宿主会提示找不到应用（见[模块提示找不到界面宿主怎么办.md](模块提示找不到界面宿主怎么办.md)），Magisk 没有入口则另有处理顺序（见[Magisk模块网页界面打不开怎么办.md](Magisk模块网页界面打不开怎么办.md)）。
