# 手机上给 APK 签名的工具怎么用

> 本篇讲不连电脑、直接在安卓手机上给 APK 安装包签名的完整流程：什么时候需要它、操作顺序、以及签前签后各要注意什么。
> **相关文档**：[APK签名方案V1到V4的区别.md](APK签名方案V1到V4的区别.md) · [密钥库丢失的后果与预防.md](密钥库丢失的后果与预防.md)

---

## 一、什么时候需要在手机上签名

- 自己编译或改动过的 APK，安装时提示没有签名、签名无效——重签一份就能装。
- 手上的旧包只带了 V1 签名，在安卓 11 及以上的新系统上被直接拒装，想重签补上 V2。
- 把已安装在手机上的应用提取出来重签一份留档。

这三件事的共同点是包已经在你手里、量不大——为一两个包开电脑、配环境反而不划算，手机上点几步更快。

## 二、操作流程

图形界面工具把命令行那一套翻译成了四步：

1. **选中安装包**：包在手机存储里就直接选文件；应用已经装在手机上，也可以从应用列表里提取再签。
2. **选密钥库**：导入现成的 `.jks` / `.keystore` 文件，输入密码和别名（alias）。别名区分大小写，输错任何一个都会报错。
3. **勾签名方案**：拿不准就 V1 + V2 都勾，新老设备两头兼顾，依据见 [APK签名方案V1到V4的区别.md](APK签名方案V1到V4的区别.md)。
4. **开始签名**：进度走完，结果一般生成在输入文件所在目录的 done 文件夹里，找不到就在原文件同目录翻一下。

这类流程里，[Apksigner](https://apksigner.wrwq.fun/) 是一个有代表性的图形界面实现：签名、验证、密钥库管理按标签页分布，深色界面，免费版就能完成签名与验证。

## 三、签前记牢两条规矩

- **先改完，再签名**：签名对整个安装包做校验，签完之后改图标、替换资源、重新压缩，哪怕只是压一下，验证都会报「已修改」。
- **先对齐，后签名**：要做 zipalign 就放在签名前面，顺序反了签名会失效；带对齐选项的工具保持默认顺序即可。

## 四、签完先验证一次

签名完成后先在「验证」标签里过一遍，确认完整再安装或分发，能省掉大量「装到一半失败」的来回。验证报「已修改」说明包在签名后被动过或传输损坏；报「未签名」说明根本没签上。

密钥库是整个流程里唯一丢不起的东西——文件、密码、别名三样要一起备份，原因与做法见 [密钥库丢失的后果与预防.md](密钥库丢失的后果与预防.md)。
