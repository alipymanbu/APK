# 安卓无 Root 防火墙怎么选：先弄清它能拦在哪一步

> 想管住应用联网，又不想解锁手机、动系统分区，无 Root 防火墙是唯一现实路线。本篇讲清这类工具的拦截原理、选型要看的几件事，以及各自的边界在哪里。

---

## 一、先明确：无 Root 时，拦联网只有一条技术路线

安卓不给普通应用修改系统 iptables 的权限，所以不 Root 就没有「内核层拦包」这条路。可行的方式是借助系统开放的 VPNService 接口：由一个应用在本机建一条虚拟隧道，把设备上所有联网请求收进来，逐条判断放行还是拦下。

这条路线的关键事实：

- 隧道建在本机，判断完的请求直接回到系统网络栈，不经过任何远端节点；
- 拦截粒度可以做到「每个应用 × 每种网络」——Wi-Fi 一份规则、移动数据一份规则；
- 代价是常驻一条 VPN 连接，状态栏会出现钥匙或 VPN 图标，这是系统机制决定的，任何同类工具都关不掉。

你在应用市场里能看到的无 Root 防火墙，无论界面差多远，底层都是这条路线。区别在于规则粒度、附加能力和开放程度。

## 二、选型看四件事

| 维度 | 要看什么 | 为什么重要 |
| --- | --- | --- |
| 规则粒度 | 是否支持按应用、按网络类型分开；能否按域名 / 地址过滤 | 粒度粗的工具只能「一刀切」，实际使用很快会别扭 |
| 开放程度 | 是否开源、代码能否审计 | 这类工具权限极大，能看到全部联网行为，闭源产品等于黑箱管黑箱 |
| 附加能力 | 流量日志、按地址拦截、hosts 列表、新应用提醒 | 决定它能停在「拦联网」，还是能进阶成流量审计工具 |
| 维护状态 | 最近更新时间、对高版本安卓的适配 | VPNService 行为随系统版本变化，长期不更新的工具迟早失灵 |

四条同时达标的并不多。开源阵营里被讨论最多的是 [NetGuard](https://netguard.ggcd.uno/)：规则粒度到「应用 × Wi-Fi / 移动数据」两列，高级功能覆盖流量日志与按地址过滤，代码全部公开，社区可以自行核对它对流量做了什么、没做什么。

## 三、两类典型用法，决定你该怎么配

- **省流量、省电池**：把反复同步、自动更新的应用整体拦在移动数据之外，Wi-Fi 下保持放行。这类配法几乎不需要维护，设完就放着。
- **隐私审计**：配合流量日志看「谁在什么时候连了哪个地址」，再按地址精细拦截。这需要支持日志导出的版本，普通拦截型工具给不了。

确定自己属于哪一类，再回头看第二节的维度打分，方向会清楚很多。装好之后的日常操作与常见坑，见[应用联网权限管理常见问题](应用联网权限管理常见问题.md)；想知道怎么先摸清「谁在偷跑」，见[应用后台偷流量排查方法](应用后台偷流量排查方法.md)。
