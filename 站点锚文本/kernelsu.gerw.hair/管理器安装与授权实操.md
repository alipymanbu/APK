# 管理器安装与授权实操：从装上到用稳

> 一句话：装管理器、看状态、临时引导、写入内核，再到按应用授权——KernelSU 上手的完整动作清单。
> **相关文档**：[机型支持与内核版本自查.md](机型支持与内核版本自查.md) · [模块玩法与Zygisk开启路径.md](模块玩法与Zygisk开启路径.md)

---

## 一、先说清三件绕不开的前提

KernelSU 工作在 Linux 内核层，安装过程免不了刷写分区，所以下面这些不是可选项：

1. **解锁 bootloader**：没解锁就无法刷写 boot 分区，这一点没有变通办法。解锁会清空数据，保修一般也随之失效。
2. **备份原厂 boot 镜像**：整个流程里最值钱的一步。从对应机型的固件包里提取 boot.img（出厂 Android 13 及以上的机型多半是 init_boot），刷错了只有它能救回来。
3. **会用基本的 ADB 与 fastboot**：后文的命令都建立在这两个工具上。

任何刷机操作都有变砖风险，手机里有重要数据先做整机备份。

## 二、五步走完安装

1. **取回安装包**：管理器是一个 APK，从可获取的渠道取回（写作时的最新稳定版是 v3.3.0，2025-08-28 发布；版本随时间变化，以项目发布页为准）。
2. **装管理器、看状态**：首次安装系统会拦「未知来源」，在设置里对发起安装的应用放行即可。打开管理器，首页显示「未安装」说明设备在支持范围内，可以继续；显示「不支持」就停，回支持自查重新对号，反复刷没有意义。
3. **对内核版本**：KMI 三段、安全补丁级别、压缩格式逐项对上，方法见[机型支持与内核版本自查.md](机型支持与内核版本自查.md)。
4. **临时引导验证**：`adb reboot bootloader` 进 Bootloader 后执行 `fastboot boot boot.img`——不落盘、重启即失效。能正常开机、管理器认得出来，再谈写入；验证失败不伤系统，是最便宜的一次试错。
5. **直接安装**：临时启动后设备有了临时 root，在管理器里选「直接安装」，它会修补当前系统并写入，重启后首页变「工作中」即为成功。安装时它会自动把原厂镜像备份到 `/data/adb/ksu/`，日后想卸载，选「还原原厂镜像」就能回到刷机前。

两点模式上的补充：0.9.0 起有 LKM 与 GKI 两种模式，LKM 以可加载模块方式挂进原内核、不替换内核，升级与系统更新都更省心，手机上优先考虑；三星开了 KNOX 的机型 LKM 不生效，只能走 GKI。

## 三、授权：按应用单独发牌

装好之后，哪个应用要 root 就在管理器的超级用户页单独放行，没被授权的应用连 su 的存在都感知不到。想管得更细，可以在 App Profile 里规定提权之后的身份：

- 指定 UID/GID（比如降到 shell 级权限）；
- 裁掉能力组（比如去掉网络权限）；
- 限定 SELinux 域，并开启 NO_NEW_PRIVS 防止二次提权。

这些约束由内核强制执行，应用自己绕不开。日常最常见的两件事：列表里逐个开关授权，以及用右上角搜索定位某个应用。

## 四、出问题时的两条退路

- **装了模块开不了机**：开机第一屏之后连续按音量下键多次（按下松开的节奏，不是按住），KernelSU 会进安全模式、禁用全部模块，卸掉出问题的那个再重启。
- **刷了内核开不了机**：刷回第 1 条里备份的原厂 boot 镜像，系统就能起来，排查清楚原因再重来。

模块装好之后怎么玩、Zygisk 怎么开，见[模块玩法与Zygisk开启路径.md](模块玩法与Zygisk开启路径.md)。动手前想再过一遍完整流程，[KernelSU 安装指引](https://kernelsu.gerw.hair/)站把安装与自查两条线都串了起来。
