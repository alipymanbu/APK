## 先想清楚脚本的三段式结构

社区里大部分入门教程的第一段脚本都长一个样，因为签到这件事天然就是三步：

```javascript
// 1. 等待无障碍服务就绪
auto.waitFor();

// 2. 启动目标应用
app.launchApp("软件名");

// 3. 找到签到按钮并点击
let btn = text("签到").findOne(5000);
if (btn) {
    btn.click();
    toast("今日任务完成");
}
```

三行核心代码，分别对应「准备 → 进入 → 操作」。读懂这三步，再复杂的自动化流程也只是把它们组合、循环、加判断而已。

## 每一步背后的原理

**`auto.waitFor()`**：脚本运行前必须确认无障碍服务处于连接状态，否则后面所有的界面操作都会失败。这一行会阻塞等待，直到服务就绪。

**`app.launchApp("软件名")`**：通过应用名启动目标应用。也可以用包名启动（`app.launch("com.example.xxx")`），包名可以用悬浮窗里的「查看包名」功能直接查到。

**`text("签到").findOne(5000)`**：这是选择器 API 的典型用法——在当前界面上按文字查找控件，最多等 5 秒。界面上控件很多时，还可以按 `id()`、`desc()` 定位，或用 `findOne().parent()` 在控件树里游走。

**`btn.click()`**：由无障碍服务代为完成点击。某些控件不支持无障碍点击时，可以改用 `click(btn.bounds().centerX(), btn.bounds().centerY())` 按坐标点击。

## 不想写代码？先试试录制

Auto.js 的悬浮窗里有个「录制」功能：点开始，然后手动把操作做一遍——打开应用、点签到，操作序列会被记录下来，保存成脚本后就能回放。

录制生成的脚本不够精致（它只是忠实还原操作路径），但它是理解「脚本在干什么」最直观的方式，也是改脚本前的绝佳起点。

## 想让它每天自动跑

签到场景的精髓在于「定时」。常见做法有两种：

1. **脚本内等待**：`setInterval` 配合系统时间判断，脚本常驻后台到点执行——适合临时用；
2. **借助定时任务工具**：把脚本交给系统的定时器或第三方定时工具在每天固定时间拉起，脚本本身只负责「执行一次」——更省电、更稳。

无论哪种，都记得在系统设置里给应用开「自启动 / 后台运行」权限，否则休眠一夜后无障碍服务可能已被系统回收。

## 常见的第一次翻车

- **脚本没反应**：九成是无障碍服务没开或被系统关了，回侧边栏重新开启即可；
- **找不到控件**：界面上根本没有「签到」两个字，或者它在弹出层里——先用布局分析功能看看控件的真实属性，再换选择条件；
- **点击了没效果**：有的按钮是无障碍点击不动的自绘控件，改用坐标点击通常能解决。
