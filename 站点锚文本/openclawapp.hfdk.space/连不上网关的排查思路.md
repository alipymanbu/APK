# openclawapp 连不上网关的排查思路

> 本篇按"症状 → 处理"整理 openclawapp 连不上电脑端 Gateway 的三类高频情况：发现不了、批准不了、连上又掉。
> **相关文档**：[手机端配对与语音用法](手机端配对与语音用法.md) · [安卓版下载安装步骤](安卓版下载安装步骤.md)

## 先确认一个前提

app 是随行端，电脑端的 Gateway 必须先在跑：

```bash
openclaw gateway status   # 应看到监听 18789 端口
```

这一步不通的话，问题在电脑端不在手机——先去把 Gateway 跑起来再说。

## 症状一：发现列表里没有网关

多半是网络隔离：路由器开了 AP 隔离、手机连的是访客网络、或者手机在用流量。按这个顺序处理：

1. 确认手机和电脑连的是同一个路由器、同一网段；
2. 不行就改手动：Connect 页 Advanced controls 里填电脑 IP + 18789；
3. 跨网络（人在外面）就让两端进同一 Tailscale 这类虚拟网络再连，走 `wss://` 加密路线，别把端口裸露到公网。

## 症状二：扫了配对码一直没反应

配对请求要在电脑端批准才生效，缺了这一步手机端永远停在"等待"：

```bash
openclaw devices list      # 看待批准的请求
openclaw devices approve <requestId>
openclaw nodes status      # 确认节点已连上
```

一个容易忽略的点：认证信息变过之后，app 会重新生成一条新请求——批准编号最新的那条，旧的那条可以直接忽略。

## 症状三：连上了但频繁掉线

app 靠一条前台服务维持连接，通知栏那条常驻通知就是它的命脉。掉线九成是系统把后台杀了：

- 确认通知栏常驻通知还在不在；
- 把 app 加入电池优化白名单、允许自启动（各厂商路径不同，一般在 设置 → 电池 / 应用管理 里）；
- 断线期间发出的消息不会丢——它们按网关排队，重连后按顺序送达。

## 还是不行

把三类症状都排过仍连不上，就带着 `openclaw gateway --verbose` 的前台日志去看报错；安装环节的问题回 [安卓版下载安装步骤](安卓版下载安装步骤.md) 对一遍步骤。图文版排查指引也放在了 [openclawapp 安卓随行站](https://openclawapp.hfdk.space/) 的常见疑问区。
