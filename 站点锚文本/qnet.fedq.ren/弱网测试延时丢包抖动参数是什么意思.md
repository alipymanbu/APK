# 弱网测试延时丢包抖动参数是什么意思

> 本篇把弱网测试里最常见的六类参数逐条说清：它们各自模拟什么、组合时怎么下手、哪些现象是预期而不是缺陷。相关文档：[地铁电梯弱网场景怎么模拟出来](地铁电梯弱网场景怎么模拟出来.md)、[手机免root抓包导出pcap的方法](手机免root抓包导出pcap的方法.md)。

---

弱网模板里的参数名大多来自网络工程术语，第一次接触容易被单位绕晕。以[QNET 弱网测试工具](https://qnet.fedq.ren/)的模板编辑页为例，它把参数按上行、下行两组分开填，六个维度含义如下：

| 参数 | 模拟什么 | 典型用途 |
| --- | --- | --- |
| 延时（Delay） | 请求往返变慢 | 「信号只有一格」的基础卡顿感 |
| 延时抖动（Jitter） | 延迟忽大忽小 | 实时语音、对战类应用的敏感项 |
| 带宽（Bandwidth） | 限速到指定 kbps | 大图、视频、资源包的加载体验 |
| 随机丢包（Random Loss） | 按比例随机丢包 | 转圈加载、请求超时重试 |
| 连续丢包（Continuous Loss） | 连续丢一段再恢复 | 周期性断网，验证重连与重发逻辑 |
| 协议控制（Protocol） | 只对 TCP 或 UDP 下手 | 比如 UDP 100% 丢包，测运营商 UDP 劣化场景 |

## 组合参数的三条经验

**一次只动一个参数。** 延时、丢包、限速全开时出了问题，说不清是谁导致的。先把单一参数跑通，再逐档加码，定位才有意义。

**100% 丢包不等于拔网线。** 它是「包全丢但链路状态还在」，与系统级断网的行为不完全一样；要测真正的断网恢复，用连续丢包或周期弱网类模板更接近真实。

**温和起步。** 「上下行延时 100ms」这类温和模板先确认应用在普通弱网下能正常跑，再加到极端档位；一上来就 100% 丢包，应用连不上是预期行为，测不出新东西。

## 写进模板的数值为什么「不准」

有人会拿真实环境对照：设了 200ms 延时，实测却不止。原因是工具会动态探测当前网络到远端服务器的延迟，再适配设定的上下行延时——真实延迟 = 基础网络延迟 + 模板设定值，基础网络本身越差，叠加后偏离越大，这属于正常现象而不是工具失准。想核对参数实际效果，可以把弱网开着抓一轮包，对照方法见[手机免root抓包导出pcap的方法](手机免root抓包导出pcap的方法.md)。

另外注意参数的更新语义：正在跑的弱网不会自动加载刚编辑的模板，重新启动或走命令热更新时参数是全量更新——没带的字段会重置为默认值，别只改一个字段就指望其余保持原样。
