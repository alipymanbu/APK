# Dhizuku 和 Shizuku 该怎么选

这两个工具经常被放在一起讨论：名字相近、思路也相似，很多应用的说明里会同时提到两者。实际取舍并不难——它们拿到的是**不同层级**的安卓身份，适合的场景不同，甚至可以同时装、串联用。想看两者更完整的对比与激活整理，可以到 [Dhizuku 指引站](https://dhizuku.ggcd.uno/) 查阅。

## 先分清两份权限

- **Shizuku** 通过 ADB 或无线调试启动一个 shell 服务，应用借它以 shell 用户（UID 2000）的身份执行操作，覆盖的是常规系统与应用管理类需求。
- **Dhizuku** 则把 Device Owner（设备所有者）这个设备管理级的身份设在自己身上，应用通过它的 API 发起请求、由它代为执行，层级比 shell 更高，能覆盖冻结或隐藏应用这类普通方案做不到的操作。

## 按四件事比较

| 关注点 | Dhizuku | Shizuku |
| --- | --- | --- |
| 重启之后 | 权限仍在，无需重新激活 | 服务停止，重启后要重新启动 |
| 是否需要 root | 不需要 | 不需要 |
| 初始设置 | 需先移除全部账户与次要用户 | 无此要求 |
| 支持的应用数量 | 目前还不多 | 生态大得多 |

## 常见的组合用法

两者并不互斥。一个常见的串联路径是：先在手机上把 Shizuku 跑起来（Android 11 以上支持无线调试配对，不用连线），再借它执行 Dhizuku 的激活命令。等 Dhizuku 激活完成，Shizuku 就可以照常给其他应用服务——一个管常规操作，一个管设备管理级操作。

选择建议一句话概括：**应用只支持其一，就按应用的说明来；两者都支持、又需要设备管理级权限，优先把 Dhizuku 激活**，它激活一次就长期有效，代价只是初次设置时多清一遍账户。设置前的清理清单见[激活前要清空哪些账户](激活前要清空哪些账户.md)，没有电脑时的激活办法见[没有电脑怎么完成激活](没有电脑怎么完成激活.md)。
