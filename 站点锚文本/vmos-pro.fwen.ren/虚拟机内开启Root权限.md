# 虚拟机内开启Root权限

> 不动真机拿到超级用户：VMOS Pro 的 Root 边界、开启步骤与授权失败排查。
> **相关文档**：[虚拟机多开与账号分身.md](虚拟机多开与账号分身.md) · [安卓12激活虚拟机的方法.md](安卓12激活虚拟机的方法.md)

---

## 一、这里的 Root 是什么、不是什么

VMOS Pro 的 Root 是**虚拟机内部的超级用户权限**：开的是虚拟系统里的 root，真机的 Bootloader 不解锁、系统分区不动、保修不受影响，权限的作用范围也只在虚拟机内——里面的应用拿得到 root，真机上的应用一切照旧。

这正是它与传统一键 Root 工具的本质区别：可以放心拿它练手、测试需要 root 的工具，搞坏了删掉虚拟机重建即可，代价几乎为零。

## 二、开启步骤

1. 建好一台虚拟机并进入；
2. 打开虚拟机内的「设置」（虚拟系统的设置，不是真机的），找到「**超级用户**」开关，打开；
3. 启动一个需要 Root 的应用，首次调用会弹授权窗，勾选允许；
4. 验证：装一个 Root 检查类应用，或在终端执行 `su`，能拿到 `#` 提示即成功。

部分镜像内置 Root 环境，装进去就能授权，无需再开开关——以所选镜像的实际情况为准。

## 三、能拿来干什么

- 卸载或冻结虚拟机里用不到的预装应用；
- 跑需要 root 的系统工具（音效增强、备份类等）；
- 在虚拟机内挂 Xposed 类框架与模块（部分镜像自带环境，框架版本需与镜像的安卓版本对应）；
- 测试陌生 APK 的高危行为——中招也只污染这台虚拟机。

两个边界要提前知道：VMOS 不支持 Magisk（没有 boot.img 与 recovery，走的是 Superuser 方案）；Root 相关权益在部分版本中属于会员内容，是否可用以应用内实际提示为准。

## 四、开了开关却拿不到 root

按出现频率排查：

1. **重启虚拟机**——superuser 守护进程没在运行时授权必失败，关机再开机基本能解决；
2. **确认开关开在对的那台**——Root 按台生效，多开时进错台就看不到授权；
3. **对照版本与账号状态**——免费镜像可能限制 Root 权益，表现为超级用户应用闪退或重启后丢授权；
4. **重装授权应用**——授权就闪退时，重装超级用户管理应用可恢复。
