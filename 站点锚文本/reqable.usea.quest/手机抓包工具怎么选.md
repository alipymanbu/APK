# 手机抓包工具怎么选

> 桌面端的 Fiddler、Charles 用了很多年，手机上抓包该用什么？本篇按使用场景把常见工具形态摆在一起对比，说明什么样的组合值得装进手机。

## 一、按场景看工具形态

| 场景 | 顺手的形态 |
| --- | --- |
| 出门在外，临时确认一条请求 | 手机端独立抓包，装上即用 |
| 分析长报文、改请求做对比 | 手机抓 + 电脑大屏分析（协同） |
| 造请求验证接口 | REST 客户端，最好与抓包数据打通 |
| 联调时把请求发给同事复现 | 能一键导出 cURL / HAR 的工具 |

抓包与接口测试过去分属两类工具（抓包看 Fiddler / Charles，造请求看 Postman），在手机上还要再各装一份，来回切换很碎。

## 二、合并到一台手机上是什么体验

Reqable 走的是「抓包调试 + 接口测试一体」的路线：安卓端用本机 VPN 记录流量，抓到的请求可以直接存成接口测试案例，反过来也能从流量列表当场造请求；配合电脑端还能把流量转发过去做重调试动作。安装包只有 30 MB 上下，社区版免登录就能用，对个人开发者很轻。

它把两件事合成一件的思路，适合「一个人、一部手机、排查一个接口」这类高频小场景。功能清单、真机截图与安装入口整理在 [Reqable 安卓端介绍站](https://reqable.usea.quest/)，可以先看截图再决定装不装。

## 三、选择时别忽略的三件小事

- **证书链路是否顺**：HTTPS 解析靠证书，工具最好把「生成 → 同步 → 指引安装」做成一条链；
- **数据能否带走**：会话导出 HAR、请求导出 cURL，换设备或找人帮忙时都用得上；
- **免费档够不够用**：不少工具的免费档对个人足够，先跑一段时间再考虑付费档。
