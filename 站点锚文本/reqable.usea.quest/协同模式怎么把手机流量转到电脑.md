# 协同模式怎么把手机流量转到电脑

> 手机的屏幕太小，看长 JSON、做请求对比都费劲。协同模式的作用是把手机流量自动转发到电脑端处理。本篇讲它的配对步骤、比传统 Wi-Fi 代理省心的地方，以及连不上时先查什么。

## 一、比 Wi-Fi 代理省心的四点

早年的做法是在 Wi-Fi 设置里手动填代理，把手机流量指到电脑上的抓包工具。这条路有四个绕不开的麻烦：代理要手动配、调试完还要改回去；部分应用的网络库不读系统代理；根证书要自己想办法倒进手机；代理是全局的，没法只对某个应用生效。

Reqable 的协同模式正是冲着这四条来的：不用碰 Wi-Fi 设置，扫码即连；走 VPN 机制，拦截更全面；电脑端根证书自动同步到手机；安卓上还能拿到每条流量所属的应用信息。

## 二、配对三步

1. 电脑端打开二维码页面；
2. 手机端装好 Reqable 并启动，初始化时选协同模式，扫电脑端的二维码——同一局域网内还会自动发现可协同的设备，点一下就能添加；
3. 连接成功后，电脑端的根证书自动同步到手机（安装仍要在手机上完成），下次启动自动重连。

电脑的 IP 或端口变了，在手机端侧边栏点扫码图标重新扫一次即可。

## 三、连不上时先查这四项

| 现象 | 检查点 |
| --- | --- |
| 扫码连不上 | 手机和电脑是否在同一局域网 |
| 同一网络仍连不上 | 有些局域网禁止跨网段通信，确认同网段 |
| 始终握手失败 | 电脑防火墙是否放行了抓包工具的代理端口 |
| 换个网络就通了 | 让电脑连手机热点，再用扫码连接 |

## 四、分工与边界

协同之后，重活在大屏上做：断点、重写、脚本这些调试动作属于桌面端能力；手机端负责记录与接口测试。只想临时看一条请求时，切回独立模式更省事。

这套两端配合的形态长什么样，[Reqable 安卓端介绍站](https://reqable.usea.quest/)里整理了两种模式的对照与真机截图，配对前先看一眼，心里更有底。
