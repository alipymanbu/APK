# 应用双开与两个账号同时在线

本篇聊一个与设备无关的高频需求：同一部手机上，让工作号与生活号同时保持在线。适合正在物色双开方案、又担心数据混在一起或账号被挤下线的读者。

## 为什么双开需求这么多

社交与游戏类应用大多限制"一部设备一个账号"。两个号来回切换不仅麻烦，还常常把另一个号挤下线，消息收不到。把需求拆开看，无非三件事：两个账号并行在线、消息各收各的、切换时不丢数据。

## 双开的常见做法

### 系统自带分身

部分国产手机系统内置"应用分身"功能，对系统自带支持的少数应用（通常是几款主流聊天工具）够用。局限也明显：支持的应用列表固定，不在名单里的应用无能为力。

### 容器类工具的克隆能力

以 Gspace 为代表的空间类工具思路不同：在应用里开一个虚拟空间，把任意应用克隆一份放进空间里跑。空间内的实例与主系统里的原版互相独立，各自登录各自的账号。它的优势在于：

- 克隆对象不限于几个白名单应用，社交、游戏都可以导入；
- 空间与主系统数据隔离，卸载空间即整体清除克隆实例；
- 对没有谷歌服务的设备，它还兼任谷歌框架容器的角色，一份工具两用。

双开用法在[Gspace 的介绍页](https://gspace.boop.uno/)里有完整说明，包括导入克隆与创建快捷方式的操作。

### 双手机 / 双 SIM 方案

最"笨"也最稳的办法：一台设备一个号。没有兼容性顾虑，但要背两台手机、养两套电量和流量，多数人不会为两个账号多带一部手机。

## 几个值得提前知道的点

1. **通知依赖后台存活**：容器内的实例要靠容器活着才能收消息。把容器工具加入电池优化白名单、允许自启动，消息才不会漏。
2. **克隆占存储**：克隆一份应用相当于再装一遍，大应用会额外占用数百 MB 到数 GB。
3. **删原版会连坐**：容器内的克隆实例依赖本机原应用，卸载本机原版时，空间里克隆的那份也会被移除——清理应用前先想清楚。
4. **支付与账号安全**：涉及短信验证码登录的应用在容器内一般可正常收码；但涉及设备校验的支付类功能在容器里通常不可用。
