# 手机抓的包怎么导出 Wireshark 分析

> 在手机上初筛、在电脑上深挖，是流量分析最省力的组合。本篇讲怎么把安卓设备上抓到的流量完整交给 Wireshark：离线导出文件与实时推送两条路各走一遍。

## 两条路，按场景选

Wireshark 是桌面端的分析工具，它自己不去手机上收包——包得先由手机端应用抓好，再"递"过去。递的方式有两种：

| 方式 | 怎么工作 | 适合场景 |
| --- | --- | --- |
| 导出 PCAP 文件 | 捕获结束存成文件，传到电脑打开 | 事后分析、留档、发给别人看 |
| PCAP-over-IP 实时推送 | 抓到的包经 UDP 实时发到指定机器 | 边抓边看、现场排查 |

以 [PCAPdroid](https://pcapdroid.boop.uno/) 为例，两种方式的入口都在它的"流量转储"选项里（No dump / HTTP server / PCAP file / UDP exporter 四选一），下面分别走一遍。

## 路线一：导出 PCAP 文件

1. 把转储模式切到 **PCAP file**，然后开始捕获；
2. 正常用手机一段时间，或专门复现你要查的行为；
3. 点停止，抓取的流量落成本地文件，附带应用元数据——这点很关键，后面会用到；
4. 把文件传到电脑（数据线、云盘、局域网都行），用 Wireshark 直接打开。

打开后除了常规的包结构，还能看到每条连接归属哪个应用——元数据被写进了转储文件，在 Wireshark 里按应用过滤就不用靠猜端口和 IP 了。

## 路线二：PCAP-over-IP 实时推送

1. 转储模式切到 **UDP exporter**，填上接收机器的局域网 IP 与端口；
2. 电脑端 Wireshark 选对应网卡开始捕获，过滤器填 `udp port 5555`（端口按你填的来）；
3. 手机端开始捕获，Wireshark 里随即出现实时流。

适合排查"某个应用什么时候发包、发了多大"这类要盯现场的问题。注意两台设备要在同一局域网，手机用 Wi-Fi 时别开会隔断本地广播的访客网络。

## 一个预期管理

转储交过去的流量里，TLS 加密部分在 Wireshark 里同样是密文。主机名、IP、包长、时序这些信息足够定位"谁在什么时候连了谁、传了多少"；要看具体明文内容需要额外的解密条件（多数情况要 root 设备配合），别把"导出成功"当成"能看到全部明文"。
