# 脚本市场与多设备批量管理的玩法

> 一台手机跑脚本省的是一个人的手，多台手机跑脚本省的是一个团队的手。本篇讲 Hamibot 脚本市场的挑选逻辑、付费规则的注意点，以及多设备批量管理、定时排班与 API 对接的玩法。基础接入流程见 [hamibot 安卓自动化介绍站](https://hamibot.hfdk.space/) 与本目录其他文章。

## 一、脚本市场怎么挑

市场里的脚本由作者上架、持续更新，类型跨度很大：签到打卡、能量收取这类每日重复操作，飞书打卡这类考勤场景，设备定时开关机、多脚本依次启动、后台守护这类设备运维场景都有覆盖。挑脚本按三条核：

1. **权限要求**：脚本页会写清需要哪些权限，多数要求无障碍服务和后台弹出界面，缺什么先去手机设置里补；
2. **收费模式**：免费脚本直接装；付费脚本按「定价计划」订阅，常分单设备、多设备几档，是否支持离线运行也写在脚本页；
3. **试用期**：多数付费脚本带试用期，不合适在试用期内的脚本页直接点退款；过试用期的走「创建脚本工单」申请。

一个容易踩的坑：删除脚本后重装，付费脚本要选**与之前相同的定价计划**，否则会按新计划再计一次费。

## 二、多设备批量管理

同一个脚本可以同时下发到多台已配对设备上运行，这是 Hamibot 与单机自动化工具拉开差距的地方：

- **集中配对**：所有手机都配到同一个账号下，控制台的「设备」页统一看在线状态；
- **统一下发**：脚本更新后，用户端实时生效，不用挨台导文件；
- **批量执行**：控制台里勾选多台在线设备跑同一脚本，适合多账号签到、批量巡检这类横向复制的工作；
- **额度边界**：免费额度只有 1 台配对设备，多设备场景需要订阅扩容，档位价格以控制台当时显示为准。

设备多的团队还有一个杀手锏：脚本配置（延迟、次数等参数）可在控制台按设备改好再下发，同一套脚本跑出不同行为。

## 三、定时排班与离线运行

- **定时任务**：给脚本指定运行时间，夜里收能量、早上打卡都能排班；免费额度含 1 个，超量订阅；
- **离线运行**（公测功能）：把脚本「离线到设备」后存在手机本地，不依赖控制台实时下发，网络不稳的设备也能跑；前提是客户端装公测版，操作是脚本页【更多】→【离线到设备】→ 选设备，再到手机上点开运行；
- **保活**：设备要在线才能接指令，自启动、省电无限制、前台服务、悬浮窗几项开齐（细节见 [从配对到跑通第一个脚本的完整流程.md](从配对到跑通第一个脚本的完整流程.md)）。

## 四、往系统里接：REST API

Hamibot 提供 REST API（`https://api.hamibot.com/`），能从外部系统管理设备与脚本——比如由服务器在某个事件发生时触发某台设备执行脚本。认证用控制台生成的个人令牌（`hmp_` 开头），免费额度 100 次请求：

```shell
curl -H "Authorization: hmp_你的令牌" https://api.hamibot.com/
```

接口清单在开发文档的 REST API 一节。配合定时任务与多设备，可以把安卓侧的自动化嵌进更大的流程里。
