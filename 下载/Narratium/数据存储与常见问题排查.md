## 一、数据存在哪

Narratium 的设计是本地优先：你的配置、角色卡、对话记录都保存在你自己的设备上，不依赖一台上游服务器替你存档。具体位置按你用的形态而不同：

| 你用的是 | 数据位置 |
| --- | --- |
| 安卓端（本文这份 APK） | 这台手机的应用数据里 |
| 网页版 | 当前这个浏览器里（配置与角色在本地存储，对话历史在浏览器数据库中） |
| 桌面版 | 电脑本地目录（Windows 在 `%APPDATA%/Narratium/`，macOS 在 `~/Library/Application Support/Narratium/`，Linux 在 `~/.config/Narratium/`） |

推出新的桌面版本时官方不会自动更新，要去项目的 [GitHub Releases](https://github.com/Narratium/Narratium.ai/releases) 页面自己看新版本。

## 二、什么操作会丢数据

理解了「本地优先」，丢数据的路径也就清楚了：

- **安卓端**：卸载应用、或在系统设置里「清除数据」，本地角色卡和聊天记录就没了。
- **网页版**：换一个浏览器（甚至换一个隐私窗口）数据就不跟着走——不同浏览器之间互不相通；在浏览器设置里清掉该站点的缓存与站点数据，同样等于清空。
- **桌面版**：删掉上面表格里对应的本地目录即等于清空。

所以玩出感情的长篇剧情，别做「卸载重装试试」「清个缓存提速」这类操作之前没有心理准备。网页版推荐用 Chrome 这类主流浏览器；用哪个浏览器就固定用哪个，别今天 A 明天 B。

## 三、聊天没反应：排查表

| 现象 | 多半是 | 处理 |
| --- | --- | --- |
| 提示未配置模型 | 没建过配置，或配置没激活 | 按 [API配置与模型接入.md](API配置与模型接入.md) 走一遍配置五步 |
| 点角色完全没动静 | 同上，或配置里的 Key 已失效 | 检查配置是否激活，重新粘贴有效 Key |
| 聊到一半断开 | Key 额度用完、服务商限流、网络波动 | 去服务商后台看用量；换网络重试 |
| 换了模型就不回 | 该模型不可用或名称不对 | 「获取模型列表」里选得到的才靠谱 |
| 剧情树打不开 | 那场对话还没产生足够节点 | 先聊几轮再回来看 |
| 聊久了开始忘事、人设漂移 | 上下文被卡面与长对话占满 | 精简角色卡、把关键设定移进世界书，或换上下文更大的模型（见 [角色卡字段含义与写法.md](角色卡字段含义与写法.md)） |

## 四、角色列表与社区卡的问题

| 现象 | 多半是 | 处理 |
| --- | --- | --- |
| 社区卡拉取失败 | 网络问题或接口限流 | 点刷新重试，缓存的卡还能正常聊 |
| 卡封面图片不显示 | 图片缓存过期或加载中 | 等列表预载完，或刷新页面 |
| 找不到之前删掉的预设卡 | 首次自动下载只发生一次 | 去社区重新下载同名卡 |
| 导入 PNG 后没出现 | 不是带设定的标准卡格式 | 换 SillyTavern 标准格式的 PNG 重导 |

## 五、网页版的刷新小技巧

网页版更新频繁，而页面资源有缓存，偶尔会遇到「界面版本落后一两个版本」或「试用 API 不显示」的情况——官方给过的处理办法就是**多刷新**；试用类接口不出现时，可以删掉已保存的 API 配置再刷新，页面会重新加载官方接口（这条针对网页版，以实际页面表现为准，随时可能调整）。安卓端没有这套缓存机制，遇事重启应用即可。

## 六、最后一条底线建议

配置里的 API Key 只存在你本地，但它在聊天的每一轮都会用到——别把带 Key 的截图或配置导出发给别人。数据安全这件事在这个应用里没什么玄学：**它存哪，就守好哪**。装包环节有疑问回 [下载与安装教程.md](下载与安装教程.md)，玩法层面的疑问去 [剧情分支与世界书玩法.md](剧情分支与世界书玩法.md)。
