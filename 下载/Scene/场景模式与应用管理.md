# Scene 场景模式与应用管理用法

> 场景模式让指定应用启动时自动切到你预设的性能与显示状态；应用管理则负责卸载、冻结、隐藏。这两个功能覆盖了 Scene 日常用得最多的场景，本篇讲配置方法与各模式下的权限边界。

## 一、场景模式：让应用启动时自动切状态

思路很简单：你给某个应用（比如某款游戏）预设一套参数，之后每次打开它，Scene 自动把参数套上，退出后还原。常见的配置项包括：

- Soc 性能档位（省电 / 均衡 / 性能）；
- 独立屏幕亮度；
- 自动开关 GPS；
- 通知屏蔽（打游戏时的「勿扰」效果）；
- 按键屏蔽、状态栏 / 导航栏的显示与隐藏。

其中一部分配置项需要 ADB 或 ROOT 权限，基础模式下能配的项目少。各模式能解锁什么，见 [工作模式怎么选.md](工作模式怎么选.md) 的对照表。

**前提**：场景模式的自动触发要在系统**无障碍**服务里开启「Scene - 场景模式」，并在自启动管理里允许 Scene 自启与保持后台 —— 自动切换靠它在后台盯着应用切换，这两道权限关了它就成了摆设。后台进程被省电策略清掉是「规则设了却不触发」的头号原因，各品牌的放行入口见 [后台被杀与保活设置.md](后台被杀与保活设置.md)。

## 二、给单个应用配一套场景

1. 进入场景模式的应用场景列表，点「添加」；
2. 选中目标应用（游戏最常用）；
3. 勾选要自动化的项目并设值，比如「性能档位拉到最高 + 屏蔽通知 + 亮度锁定」；
4. 保存后打开该应用验证一次：亮度是否切换、通知是否被压住。

调试这类自动规则要留意的点：有的机型会在系统更新后重置无障碍授权，表现为「场景突然不生效」，去无障碍服务列表里看一眼 Scene 还在不在即可；规则设了但没触发，优先查 Scene 的后台保活，而不是反复改规则。

## 三、应用管理：卸载、冻结、隐藏

应用管理在「功能」页里，列表支持按系统应用 / 第三方应用筛选、按名称搜索。三种常用操作对应三种需求：

| 操作 | 什么用途 | 权限要求 |
| --- | --- | --- |
| 卸载 | 彻底删除不要的应用 | 基础模式即可卸第三方；卸系统应用要 ADB |
| 冻结 | 应用还在但停止运行、不出现在桌面，适合「偶尔要用但不想让它后台乱跑」的 app | ADB 或 ROOT |
| 隐藏图标 | 只从桌面藏起来，应用照常运行，适合接孩子的平板、借出去的手机 | 基础模式可做 |

冻结是 ADB 模式下最实用的能力：耗电统计里发现某个应用常驻后台，冻结它比卸载温和 —— 需要时解冻即可，数据不会丢。

**一条安全线**：ADB 模式解锁了系统应用的卸载，这是整个 Scene 里最容易造成严重后果的操作。列表里看不懂用途的系统组件（尤其是厂商服务、带 `com.android` 前缀的条目）不要动 —— 卸掉关键组件可能导致无法开机，只能恢复出厂设置。想清理预装，先搜清楚那个包名的用途再动手。

## 四、性能调校入口：CPU、SWAP、温控

这些属于进阶能力，集中在 ROOT 模式（部分在 ADB 模式可用）：

- **CPU 控制**：调频率与调度策略，追求省电或流畅两个方向；
- **SWAP / ZRAM 设置**：调压缩内存与虚拟内存，后台驻留能力小内存机型的改善点；
- **温控配置**：查看与切换温控策略；
- **备份还原**：刷入或备份 Boot、Recovery 镜像 —— 这一项建议只留给明确知道自己在做什么的人。

动手前先做一件事：**把当前默认值记下来**（截图最快）。调坏了知道默认值是什么，才退得回去。改动后如果出现发热异常、卡顿、耗电飙升，第一反应是恢复默认值，而不是继续往别的方向调。

## 五、用出问题时的顺序

先分清是「没生效」还是「搞坏了」：没生效（场景不触发、冻结的应用又活了）查授权与后台保活；搞坏了（改性能配置后异常）恢复记录下来的默认值；如果是误删了系统应用导致系统异常，那就只剩恢复出厂设置这条路 —— 这也是为什么第三节反复强调别动看不懂的系统组件。
