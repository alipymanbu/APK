## 一、先跑一键诊断

App 的 **连接诊断** 会检查版本、网关、网卡、防火墙和远程通道状态，生成一份脱敏报告。定位问题的顺序建议是：

1. 先看诊断报告里哪一项不是绿色；
2. 再对照下面的高频问题清单找处理办法；
3. 涉及防火墙的报告项目前只在 Windows 上给出具体检查，其他系统显示「不适用」，需要自己确认系统防火墙放行。

## 二、高频问题对照表

| 现象 | 原因与处理 |
| --- | --- |
| 浏览器打开局域网链接提示「证书不受信任」 | 局域网入口用插件自签的私有证书，属预期现象；确认地址是自己的电脑后按浏览器指引继续 |
| 远程入口也提示证书不受信任 | 不正常。公开远程证书应由系统验证，先检查通道与证书，不要忽略警告强进 |
| App 搜不到电脑 | 确认手机与电脑在同一网络；电脑端 **移动访问 → 局域网** 是否开启；跑诊断看网卡与防火墙项 |
| 换 Wi-Fi / 热点后连不上 | 插件记住的是配置时的网卡。若换了网卡（Wi-Fi 换网线等），在电脑端重新配置局域网或重跑 `dsh-mobile setup` |
| 连接提示认证失败（401） | 设备授权被撤销或本地记录失效，在 App 里对该设备重新配对 |
| cpolar 免费地址连不上 | 免费临时地址重启后可能变化，重新扫电脑端当前的远程配对二维码，不用清 App 数据 |
| 提示「第三方远程插件」 | 装了另一个远程访问插件（如 `dsh-remote-web-ui`），两套配对码不能交叉使用；先关闭那个插件的远程访问，再扫 DSH Mobile 的码 |
| 扫自己的域名二维码提示「无效二维码 / Invalid QR code」 | 入口选错了：自有域名（命名隧道、反向代理）的码必须从 App 的「远程」入口扫，在「局域网」流程里扫自有域名一律判无效；或把电脑端的完整配对链接复制到手机粘贴 |
| 源码方式装插件报 `ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED` 等构建错误 | GitHub 来源的插件首次安装要执行构建脚本，pnpm 默认拦截。按 dsh 提示把对应键加进该 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds` 下重跑；只对可信来源放行 |
| 某个第三方插件的 WebSocket 连不上 | 网关默认拦截非 DSH 内置的 WS 路径。在 **连接诊断 → 第三方 WebSocket 路径** 里按报告的精确路径点「允许」，不接受带查询串或模糊前缀的路径 |
| 手机页面白屏或报脚本错误 | 手机系统 WebView 内核过旧，先更新 Android System WebView / Chrome；应急可在浏览器地址后加 `?frontend=stock` 回到旧版桌面适配模式 |
| 远程加载特别慢 | 免费通道有带宽上限（如 cpolar 免费版约 1 Mbps、Tailscale Funnel 有不可调限额），先想到服务方限速，其次看 [远程访问通道选择与配置.md](远程访问通道选择与配置.md) 换通道 |

放行第三方 WebSocket 路径只代表该路径可以通过已认证的同源网关，不会开放任意端口、也不会绕过设备配对；已允许的路径随时可移除。

## 三、版本兼容对照

DSH 本体和插件都在快速迭代，连不上时先核对版本组合。下表来自项目仓库的兼容性章节（以官方页面最新版为准）：

| 插件 / App 版本 | 验证支持的 DeepSeek Harness 版本 |
| --- | --- |
| 0.5.0 | 0.1.7-alpha.2 / 0.1.7-rc.1 / 0.1.7-rc.2（官方 Desktop 0.1.7-rc.2） |
| 0.4.5 ~ 0.4.7 | 0.1.7-alpha.2 ~ 0.1.7-rc.2 各对应小版本 |
| 0.4.2 ~ 0.4.4 | 0.1.6-alpha.1 / 0.1.6-alpha.2 |
| 0.3.x 系列 | 0.1.2-alpha.x ~ 0.1.3-alpha.2 / 0.1.5-rc.x 各对应小版本 |
| 0.1.4 / 0.2.x | 0.1.1-rc.2 |

要点：

- 插件 0.3.6 起不会仅凭版本号拒绝启动；升级 DSH 后移动端出现异常，先更新插件再排查。
- 插件与 Android App 建议保持同版本升级，已有配对会保留。
- 网盘里这份 0.2.0 属于早期版本，验证组合是 DSH 0.1.1-rc.2；如果你的 DSH 已经升到更高版本，出现异常时优先把插件和 App 一起升级到当前版。

## 四、升级注意事项

- App 0.4.0 才有多设备列表、启动行为设置、电脑端撤销状态同步和任务通知；更早版本只能连已保存的单台设备。
- 0.2.0 及之后的正式版 APK 使用固定签名，可以从旧的正式版原位覆盖升级并保留配对；自己编译的 debug 包签名不同，不能直接覆盖正式版，切换前准备重新配对。
- App 0.1.3 及更早版本升级时需要卸载重装并重新配对。
- npm 安装的插件会在桌面界面加载时提示「更新插件」，装完重启 DSH 生效；Android App 不会自动检查更新，要自己到 [项目发布页](https://github.com/saya-ch/dsh-mobile/releases) 下载。

装回或升级后仍连不上，按第一节的顺序再跑一遍诊断；问题集中在局域网场景时回到 [局域网连接与配对方法.md](局域网连接与配对方法.md) 核对每一步，设备授权相关的问题见 [安全设置与设备管理.md](安全设置与设备管理.md)。
