## 一、一条原则先记住

配对设备可以操作电脑上的 DSH：看会话、发指令、跑任务。所以：

- 只给你自己的、锁屏有密码的手机配对；
- 手机丢失或转手前，第一时间在电脑端撤销该设备；
- 局域网访问只在可信网络开启；远程访问不用就关。

## 二、设备列表里能做什么

App 的「已配对设备」列表集中管理所有配对过的电脑，每条记录显示自定义名称、连接方式、地址、可达状态和最近连接时间。

- **编辑 / 重命名**：长按设备行或点右侧菜单，可改名、立即检测、重新配对或删除本地记录；删除有二次确认和短暂撤销。
- **启动行为**：单台设备默认直接连；多台时优先连上次用的。经常切换设备的话，在列表右上角设置里改成「显示设备列表」。
- **电脑端撤销后**：在线的 App 会立即断开并显示「电脑端已移除」；离线期被撤销的设备，下次检测时显示「配对已过期」。这两种情况都重新配对一次即可恢复。
- **多设备列表说明**：多设备管理是 App 0.4.0 起的功能；网盘里的 0.2.0 只支持单台设备（见 [下载与安装教程.md](下载与安装教程.md) 的版本说明）。

## 三、凭据与证书怎么管理

- 设备令牌和局域网证书凭据由 Android 系统的 Keystore 加密保存在手机上，不会出现在设备列表或配对二维码里。
- 局域网入口的证书是插件生成的私有证书，所以手机浏览器首次访问会提示不受信任；远程公开入口则用系统信任的证书，出现警告反而要警惕（排查见 [常见问题与连接诊断.md](常见问题与连接诊断.md)）。
- 电脑端撤销设备会永久删除其授权记录，旧令牌之后一律被拒绝，被撤销的设备无法凭旧凭据再连回来。

## 四、日常安全习惯清单

- 不要为了在外面方便访问而自行做端口转发，把电脑的 3080/3443 直接暴露到公网；要远程就走插件提供的远程通道，它们自带配对保护。
- 使用公共 Wi-Fi 时优先走远程通道而不是局域网入口。
- 装插件等于在你的电脑上以你的用户权限运行第三方代码（GitHub 源码安装还会执行构建脚本），只从 npm 源、官方发布页或插件市场安装，不要装来路不明的插件包。
- 自建 FRP、自有反向代理这类自建通道：后端端口留在可信私网，不映射公网；部署或清理 VPS 前核对主机指纹；共享令牌不要出现在截图或聊天记录里（部署细节见 [自建远程通道部署与排错.md](自建远程通道部署与排错.md)）。
- 通过 `/mobile` 生成的电脑端扩展以你的用户权限运行，只保留你能看懂的扩展，用不到的及时删掉（见 [手机界面定制与扩展.md](手机界面定制与扩展.md)）。
- 远程通道用完后，在 **移动访问 → 远程** 里关闭开关；关闭后 DSH 在电脑本机照常运行。

## 五、卸载与数据清理

电脑端按你的安装方式操作（桌面端在应用 **插件** 页卸载）：

只卸载插件、保留本机数据（证书、配对记录、自定义文件）：

```powershell
dsh plugin --profile web remove dsh-mobile
```

想连同数据一起清干净，**先执行 purge，再卸载插件**，顺序不要反：

```powershell
dsh plugin --profile web exec dsh-mobile purge --yes
dsh plugin --profile web remove dsh-mobile
```

`purge` 会删除整个 `mobile-access/` 目录（含证书、配对记录、自定义界面与扩展）以及插件创建的 Windows 防火墙规则；自建通道在 VPS 上的文件不归它管，要按自建指南单独清理。卸载后想再用，重新走一遍 [局域网连接与配对方法.md](局域网连接与配对方法.md) 或远程配对即可。
