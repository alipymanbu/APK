## 一、三种自建方式的前置条件

| 通道 | 你需要有什么 | 手机 App 版本要求 |
| --- | --- | --- |
| Cloudflare 命名隧道 | 已接入 Cloudflare 的域名 + Zero Trust | 当前版即可 |
| 自建 FRP | 一台 VPS（自动部署要求 Ubuntu/Debian + systemd） | 0.3.3+（接入既有 frps 的自签档需 0.4.6+） |
| 自有反向代理 | 已有的 Nginx / Caddy / Lucky 等公网 HTTPS 代理 | 0.4.0+ |

三者都是「公网入口 + 设备配对」的结构：公网地址只暴露 dsh-mobile 的认证网关，没配对的请求进不了 DSH。通道之间同一时刻只能运行一个，切换提供方时会先停掉前一个；局域网访问不受影响。

## 二、端口红线（三种通道通用）

| 端口 | 归属 | 能否挪用 |
| --- | --- | --- |
| 3080 | DSH Web 本体 | 反代后端与命名隧道都**拒绝**它 |
| 3443 | dsh-mobile 局域网 HTTPS 网关 | 不能占用；命名隧道填它会直接报「端口被保留」 |
| 3444 | 命名隧道默认转发端口 = 反代默认后端端口 | 可改成 3445 等空闲端口，但要两边同步改 |
| 1024 以下 | 需要系统特权 | 后端不接受 |

## 三、Cloudflare 命名隧道

1. 域名的 NS 先指向 Cloudflare（注册商处修改，几分钟到 24 小时生效；zone 未激活前解析不会生效）。
2. 在 **Zero Trust → Networks → Tunnels** 创建 Cloudflared 类型隧道，Public Hostname 页签添加一条：子域自定义，Service 填 **HTTP** → `127.0.0.1:3444`。
3. 复制连接器令牌（`eyJ` 开头的长串）——它等同于密码，只粘贴进 dsh-mobile 面板，不要发给别人或贴进截图。
4. 回到面板：**移动访问 → 远程 → cloudflared**，隧道类型切 **命名隧道**，填公网域名、本机转发端口 `3444`、令牌，保存并连接。已保存后令牌框留空表示不更改。

两个高频坑：

- **换了固定域名后必须重新配对**：设备凭据只发给当初保存的精确 Origin，换域名旧凭据一律作废，这是防钓鱼设计。重新扫电脑端新生成的远程二维码即可，设备记录会原位更新、保留自定义名称。
- **自有域名的二维码必须从 App 的「远程」入口扫**：在「局域网」流程里扫自有域名的码会提示「无效二维码 / Invalid QR code」，不是连不上，是入口选错了。不想扫码时，把面板显示的完整配对链接整条复制到手机粘贴也行。

## 四、自建 FRP

- **两种公开入口**：域名模式由 VPS 上的 Caddy 自动申请续期证书；公网 IPv4 模式用 Certbot 申请约 6 天有效的 IP 证书并装每日续期定时器（示例地址 `203.0.113.10` 和内网保留地址会被拒绝，必须填真实可路由的公网 IP）。
- **手动部署**：从面板复制受限模板，frps 部分存为 `/etc/dsh-mobile/frps.toml`，Caddy 片段存为 `/etc/caddy/dsh-mobile-dsh.caddy`，主 Caddyfile 里加一行 `import /etc/caddy/dsh-mobile-dsh.caddy`。你自己的 Caddyfile 内容不会被改写；已有非空配置时自动部署会停下来让你手动加这一行。
- **自动部署**：SSH 密钥登录（不支持密码），部署前面板会列出全部改动；**主机指纹核对每次必做**，与 VPS 控制台不一致就取消，插件不会静默接受未知主机。
- **安全底线**：frps 明文 vhost 只许监听 `127.0.0.1`，插件会拒绝公网可达的明文端口。
- **清理**：本机「彻底移除 FRP」只删电脑端 frpc 与配置；VPS 侧要用「复制卸载脚本」或一键清理，两者都只删 dsh-mobile 拥有的文件、服务与带标记的防火墙规则，你原有的内容不动。
- **运维排障**常用命令：

  ```bash
  sudo systemctl status dsh-mobile-frps.service caddy
  sudo journalctl -u dsh-mobile-frps.service -u caddy -n 200 --no-pager
  curl -v https://你的域名或IP/mobile-access/discovery
  ```

  本机日志在 `$DSH_HOME/mobile-access/logs/dsh-mobile.log`（自动脱敏）。Windows 杀毒软件可能隔离 frpc，如被拦截只为已校验的组件目录加最小范围例外。

## 五、自有反向代理

面板里填四项：公网 HTTPS 地址（可带非 443 端口，不带路径）、私有监听 IPv4（回环或 RFC1918，不能填 `0.0.0.0`）、后端端口（默认 3444，排除 3443/3080）、允许的代理来源 CIDR（填代理的**直接 TCP 来源**，优先单地址 `/32`，不认 `X-Forwarded-For`）。

代理侧五条要求，缺一条就会出现「页面能开但实时功能失败」这类现象：

1. 公网地址配可信证书并在代理上终止 TLS，不要让手机忽略证书错误；
2. 代理目标是面板给出的 HTTP 后端地址，不是手机用的 HTTPS 地址；
3. 保留外部 Host 且**含端口**（`Host: phone.example.com:8815`），不能改成内网地址、不能丢端口；
4. 透传 Origin、Cookie、认证头，不改写 Cookie 属性，不缓存配对响应；
5. 透传 WebSocket 升级与双向数据。

用 Lucky 的话：WebSocket 默认支持，Host 模式选 **「使用请求Host」**，别选「使用目标地址Host」。

验收按这个顺序：证书与域名正确 → 手机扫码配对登录成功 → 发起对话确认 WebSocket 持续工作 → 关掉后端后远程入口失效而局域网仍正常。面板显示「后端已监听」只代表本地监听成功，**不代表**公网可用，必须用手机从外网实测。

## 六、高频错误码对照

| 面板提示 | 处理 |
| --- | --- |
| 转发端口被保留 | 填了 3443，换成 3444/3445 并同步改代理或 Cloudflare Service |
| 本机转发端口不可用 | 端口被占用；命名隧道不能换端口转发规则，只能释放端口或换端口两边同步 |
| 公网域名无效 | 只接受本账号域名的真实主机名；不接受 IP、通配符、`trycloudflare.com` |
| 令牌无效 | 令牌里有空格或换行，从控制台完整重复制 |
| 等待隧道可用超时 | 电脑到 Cloudflare 边缘不通（DNS、UDP/QUIC、TCP），见下节代理问题 |
| 公网访问返回 1033 | Cloudflare 看不到健康的 connector，确认隧道 Healthy 且 ingress 端口一致 |
| 组件下载/校验失败 | 重新安装组件；反复失败说明中间链路在改包 |
| 反代返回 403 | 核对来源 CIDR、外部 Host（含端口）与 Origin；伪造转发头绕不过 |
| HTTP 能开但对话失败 | 代理没透传 WebSocket，检查升级头与超时 |

## 七、开着 TUN / 全局代理时隧道很慢

电脑上挂着 TUN/透明代理时，`cloudflared` 到 Cloudflare 的连接可能被兜底规则送进代理节点，表现为手机加载远程页面极慢（不等于配对失败）。处理：在代理客户端加直连规则并让 cloudflared 重连一次。Clash 系示例：

```yaml
prepend-rules:
  - PROCESS-NAME,cloudflared.exe,DIRECT
  - DOMAIN-SUFFIX,argotunnel.com,DIRECT
  - DOMAIN-SUFFIX,trycloudflare.com,DIRECT
```

对比判断：同一资源局域网快、远程慢 → 查电脑到 Cloudflare 的路径；电脑上也慢 → 先修电脑网络再排查手机。

自建通道把公网入口交给了你自己的设施，撤销设备、令牌保管这些安全项同样适用，见 [安全设置与设备管理.md](安全设置与设备管理.md)；局域网侧的 3443 端口说明见 [局域网连接与配对方法.md](局域网连接与配对方法.md)。
