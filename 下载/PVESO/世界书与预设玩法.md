## 一、世界书解决什么问题

你跟 AI 说「去宗门领任务」，模型大概率不知道「宗门」在你的故事里是什么——自创词都有这个通病。世界书就是提前把这些词条写好：聊天里出现对应**关键词**时，平台把相关设定自动发给模型，角色就「懂行」了。需要成体系世界观的剧情扮演、小说式创作都值得配一本；随口闲聊则不一定用得上。

## 二、创建世界书与条目

1. 找到**创建世界书**入口，填世界书名称与简介；
2. 在这本世界书下**添加条目**：世界观、历史、地理、规则、科技、事件、人物关系都可以各算一条，拆得越细后面越好维护；
3. **绑定角色**：创建或编辑角色卡时，把世界书绑到这张卡上，对话时设定才会生效。

写条目的两个通用惯例（SillyTavern 生态经验，PVESO 兼容该格式）：多个关键词指向同一条内容时，用**英文半角逗号**分隔；条目标题只是给自己看的备注，真正生效的是关键词与内容两栏。

导入 SillyTavern 角色卡时，卡里自带的完整世界书会一并进来（见 [角色创建与发布.md](角色创建与发布.md) 第五节），不用重新抄一遍。世界书内容会占用上下文，条目堆得太多太长，token 消耗会明显上升——按剧情真正需要的写，省法见 [token消耗太快怎么省.md](token消耗太快怎么省.md)。

## 三、预设：控制回复风格的系统级开关

第三方商店资料提到，PVESO 支持设置**系统提示词、历史指令、深度提示词**，这些内容会以系统级指令发给模型，用来约束回复的行为与风格。简单理解：

- **系统提示词**：告诉模型「按什么规矩回复」，比如文风、称呼、格式要求；
- **历史指令 / 深度提示词**：调整历史内容与指令进入上下文的方式（具体选项以应用内为准）。

预设属于进阶玩法，先用默认设置玩熟，觉得模型「不听话」再回来动这里；世界书管「世界是什么样」，预设管「AI 怎么说话」，两者别混着用。

## 四、渲染规则与安全边界

PVESO 的角色卡渲染兼容 **Markdown 与 HTML 混合解析**，遵循 GitHub Flavored Markdown 规范；出于安全考虑，平台**移除了 iframe 渲染与 JavaScript 脚本执行**。落到使用上就是两件事：

- 依赖 JS 的交互效果（点击按钮触发剧情、动态面板之类）在 PVESO 里不会生效；
- 需要点击交互的卡，官方文档的《html-指令》章节给了改造说明，按它调整即可。

Markdown 与 HTML 混排的三条高频坑（官方 FAQ 口径）：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 写的 HTML 被原样显示出来 | 三反引号代码块内的内容一律按纯文本处理 | 去掉代码围栏再写 HTML |
| HTML 标签里的 Markdown 不生效 | HTML 内部区域不解析 Markdown | HTML 标签内不要写 Markdown 语法 |
| 排版时而正常时而错乱 | 两种标记风格混排嵌套 | 一张卡只用一种风格：纯 Markdown，或分段合理的 HTML |
