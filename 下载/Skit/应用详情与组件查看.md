## 一、这一篇解决什么

系统自带的「应用信息」页只给占用、权限、强停几项，Skit 的详情页把一个应用拆得更细：什么时候装的、多久没用了、声明了哪些权限、内部有哪些组件、签名是谁的。本篇按页面讲这些字段在哪看、各自能回答什么问题——想把某个应用整个导出文件，做法在 [提取APK与批量导出.md](提取APK与批量导出.md)。

## 二、详情页：一个应用的基本盘

在列表里点开任意应用，详情页能看到（字段随应用与系统版本略有差异）：

| 字段 | 能回答什么问题 |
| --- | --- |
| 安装时间 | 这应用是什么时候装的——排查「我没装过这个」时最有用 |
| 最后更新时间 | 版本是不是停在老版本 |
| 最后使用时间 | 长期没碰过的应用，可考虑清理 |
| 应用体积 | 本机实测的占用大小 |
| 包名 / 版本号 | 覆盖安装、查更新时对包名用 |
| SDK 版本 | 最低/目标安卓版本，判断能不能装到旧手机 |

列表页本身也有增强：3.4 起可以给列表项加第三行显示体积、给系统应用加识别徽标，排序方式都支持倒序——在列表设置里开，逐个翻详情之前先靠列表快速筛。

## 三、组件页：这个应用内部都在干什么

详情页里的组件视图把 APK 的 AndroidManifest 拆开展示，你能看到四类组件与权限：

- **Activities（活动）**：应用的各个界面入口，你点的每个页面基本都对应一条；
- **Services（服务）**：后台干活的模块，比如同步、播放；
- **Receivers（广播接收器）**：监听系统或其他应用广播的模块，开机自启、网络变化这类响应常在这；
- **Providers（内容提供器）**：对外供数据的接口；
- **Permissions（权限）**：应用声明请求的权限清单。

用途是「对账」：装完一个应用发现它要的权限和它该干的事对不上、或想知道它有没有开机自启相关组件，到这页比在系统设置里翻更直观。Manifest 原文也有入口可整页查看。

## 四、证书页：这个包是谁签的

详情页可查看应用的签名证书信息。同一个包名的应用能不能互相覆盖安装，取决于签名是否一致——**签名不同，系统直接拒绝覆盖**。所以拿到一份新 APK 犹豫「能不能直接盖上去」时，对比两份包的签名是判断依据（包名差异导致的覆盖失败也见 [常见问题与排查.md](常见问题与排查.md)）。

另外，证书只是身份信息，不构成安全结论：证书能说明「两次安装是不是同一个签名方」，但不能证明应用本身无害，别把「签名看着正常」当成安全背书。

## 五、统计与使用情况

Skit 里还有按应用查看使用时长、流量消耗的统计视图，可以回答「哪个应用最耗时间/流量」这类问题。注意其中**详细的使用报告与完整统计属于 Premium 功能**，免费版能看到的范围以你实际界面为准；3.6 起统计里还并入了系统自带的应用分类维度（该版本之后的更新才有）。

## 六、几个字段读不准时

- 「最后使用时间」来自系统的使用情况统计，刚清过使用数据的机器可能不准；
- 体积是 Skit 实测计算的结果，3.6 对算法做过修正，不同版本间数字有出入属正常；
- 系统应用的详情大多能看，但涉及改动类操作（停用、卸载）通常需要 root，见 [常见问题与排查.md](常见问题与排查.md)。
