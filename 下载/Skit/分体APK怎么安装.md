## 一、这一篇解决什么

两个高频场景会撞上同一件事：你用 Skit 提取某个应用，导出的却是 `.apks` 而不是 `.apk`；或者你从别处拿到一个 `.apks` / `.apkm` / `.xapk` 文件，双击安装说「解析错误」。原因相同——它是**分体包**，系统自带安装器不认识。本篇讲清这格式从哪来、Skit 怎么把它装回去、装不上时怎么办。

## 二、分体包是怎么来的

2018 年起安卓引入 App Bundle：开发者不再发布一个大而全的 APK，而是上传一套「基础包 + 按屏幕密度、CPU 架构、语言拆开的分片」，商店在下载时按你的设备挑分片拼装。2021 年起，商店新应用与更新基本都走这套。

分片在本地拼好后被打包成单个文件分发，社区把它命名为 `.apks`；`.apkm`、`.xapk` 是类似的多分片打包格式。它们**不是损坏的 APK，也不是另一个应用**，只是「一袋 APK」。系统自带安装器只认单个 `.apk`，所以直接点开会报解析错误——这不是文件坏了。

## 三、用 Skit 安装分体包

Skit 3.0 起内置分体包安装器，3.3 起还能从其他应用直接调起安装 `.apks` / `.apkm` / `.xapk`。两种进法：

**方式 A：从文件管理器调起**

1. 手机文件管理器里找到分体包文件；
2. 点开 → 选择用 Skit 打开；
3. Skit 解析包内容后按提示确认安装。首次这样做，系统会要求你允许 Skit「安装未知应用」，按提示授权一次即可。

**方式 B：在 Skit 内部安装**

1. 打开 Skit，在工具入口里找到安装器；
2. 浏览到分体包所在目录（外部存储的下载目录都在列表里）；
3. 选中文件 → 确认安装。

安装过程会逐分片拉起系统安装会话，进度与结果跟着系统弹窗走。

## 四、常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 点开分体包提示「解析错误」 | 用上面的方式交给 Skit 装，别用系统安装器直接点 |
| 提示与已装应用签名不一致 | 两份包不是同一签名方，只能卸载旧的再装（会丢该应用数据，先确认） |
| 安装到一半失败 | 多半是存储空间不足或分片与本机架构不匹配——分体包通常按机型拆分，拿到别人机型的包本来就可能缺你这台的分片 |
| 一直转圈没反应 | 退出重试一次；仍卡住则按 [常见问题与排查.md](常见问题与排查.md) 排查 |

## 五、非要单个 .apk 也可以

Skit 设置里有强制选项，能把 App Bundle 应用也导出成单个 `.apk`。代价是：单包只能保留基础分片里的一套配置，**换到配置不匹配的设备上可能装不上或功能缺失**。所以优先用分体包原样搬运；只有目标设备确实只认单 APK 时才用这个选项，装不上再回来按上表排查。
