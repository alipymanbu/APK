# Root权限与系统目录访问

> 没 ROOT 也能用 MT管理器，但访问 /data 这类系统目录要 ROOT；这篇讲怎么开、怎么判断生效、哪些目录改不动。

## 一、ROOT 不是使用前提

默认设置下 MT管理器 启动时会**自动尝试获取 root 权限**，但这不代表用它必须有 root。没有 root 时，你照样能做日常那套：管理内部存储文件、双窗口复制移动、压缩解压、文本编辑（见 [双窗口操作上手指南.md](双窗口操作上手指南.md)）。

差别在于：没有 root，就**无法访问或修改大部分系统目录或文件**，典型的就是 `/data`。

另一个和系统版本有关的点：Android 11 起限制了对 `/sdcard/Android/data` 目录的访问。目前还有绕开的方式，但**官方明确说不保证这些方式在后续 Android 版本中依旧有效**，届时只能靠 root 访问。所以如果你的工作流依赖这个目录，root 迟早是刚需。

## 二、相关设置在哪

主设置里和 root 相关的有两项：

| 设置 | 作用 |
|---|---|
| 获取 root 权限 | 开启后 MT 启动时自动尝试获取 root。手机没有 root、或你总是拒绝授权的话，**关掉它能提高启动速度**。改动后要重启 MT 才生效 |
| 自定义 su 命令 | 获取 root 时调用的命令，默认就是 `su`，可自行改成你环境里的命令 |

## 三、怎么判断 root 真的生效了

最简单的判据：**访问 `/data` 目录，出来的不是空白文件列表，就说明已经拿到 root 权限了。**

反过来说，`/data` 是空白的，先去查 root 授权本身（比如授权弹窗被拒了、su 命令配置不对），而不是查 MT。

## 四、/system 改不动：是系统限制，不是没 root

拿到 root 后，你仍可能无法修改 `/system` 目录里的文件，会提示「挂载读写失败」——**这是系统限制导致的，并不代表没有 root 权限**，别在这上面反复查授权。

另外，早期版本有手动「挂载读写」按钮，现在已经删掉改成自动：修改只读目录中的文件时会自动尝试挂载读写，挂载失败就弹提示。

## 五、没有 root 又想看应用数据

官方用户手册给的替代路径是：在手机上装一个**虚拟机软件**，虚拟机一般自带 root 功能，在虚拟机里访问 `/data` 看应用数据，不折腾真机。

## 六、谨慎修改：官方原话级别的警告

改系统文件不是零风险的。官方手册的警告值得原样转达给你：**修改系统文件可能导致重要数据丢失、系统损坏甚至无法开机，不知道用途的文件不要随意修改或删除。** 想随便折腾，去虚拟机里面搞。

因此实操上有两条自我约束：

1. 动 `/data`、`/system` 下的东西之前先备份到另一个窗口（双窗口正好用来做这件事）；
2. 只改你明确知道用途、且改错了能恢复的文件；不确定就只读不写。

遇到 `/data/data` 只能看到两个文件夹这类 root 相关异常，属于版本与 su 的兼容问题，见 [常见问题与排查.md](常见问题与排查.md)。
