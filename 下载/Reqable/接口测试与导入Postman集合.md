## 一、接口测试和抓包调试是两件事

- **抓包调试**：看别人发出去的请求——你的 App、浏览器、局域网里别的设备，用来定位问题。
- **接口测试**：你自己造一个请求发出去，看服务端返回什么，用来验证接口。

两者在 Reqable 里是打通的：抓到的请求可以直接建成接口测试案例，URL、请求头、请求体原样带过去，不用手工再敲一遍。

## 二、发一个请求

1. 新建一个 REST 标签页。
2. 选请求方法，填 URL。URL 支持语法高亮和多行显示，很长的地址不至于糊成一行。
3. 依次编辑查询参数、请求头、请求体。请求头和参数都支持批量编辑，成批改动比逐行点省事。
4. 需要鉴权时在授权设置里选类型：API Key、Basic Auth、Bearer Token 等。
5. 点发送，在响应区看结果。响应可以用 JSON、XML、图片、HEX 等视图切换着看。

另外两项日常会用到：

- **自定义请求方法**：`PATCH`、`PROPFIND` 这类不常见的动词也能手填。
- **Cookie 管理**：自动保存收到的 Cookie，之后发请求时会自动带上关联的 Cookie。

## 三、支持的协议与数据格式

| 项目 | 支持情况 |
| --- | --- |
| 协议 | HTTP/1.1、HTTP2、HTTP3（QUIC） |
| 请求体格式 | JSON、Text、XML、urlencode、form-data（Multipart）、二进制文件 |
| 响应视图 | JSON、XML、图片、HEX、Multipart 等 |
| 辅助信息 | 请求各阶段耗时、请求跟踪、自动记录历史 |

## 四、把现成的请求搬进来

从别的工具迁过来时，这一节最省事：

- **Postman 集合**：直接导入。
- **Hoppscotch 集合**：支持导入。
- **ApiPost / ApiFox 集合**：支持导入。
- **cURL**：把命令粘进来就变成一个请求；反过来也能把 Reqable 里的请求导出成 cURL，发给同事复现。
- **HAR**：导入导出都支持，抓包结果可以直接带走。
- **从抓包项创建**：在调试列表里对某条请求选择创建接口测试，参数原样继承。

## 五、环境变量怎么配

同一套接口要在测试、预发、线上之间切换，差别往往只有域名和 Token。把这两样定义成环境变量，请求里用变量引用，切环境时改一处就够。

当前用的是哪个环境，显示在标签栏最右侧，点一下就能切换。

## 六、集合与历史记录

| 项目 | 社区版 |
| --- | --- |
| API 集合 | 无限制 |
| 环境变量 | 无限制 |
| 历史记录 | 保留 30 天 |
| 脚本模板 | 有数量限制 |

集合与环境变量在社区版都不设数量上限，这两项可以直接用。

## 七、只想用接口测试？切禅模式

不做抓包、只把 Reqable 当接口测试工具用时，可以切到**禅模式**，界面会收掉抓包相关的内容，只留下接口测试需要的部分。入口在底部栏。

## 八、哪些地方会碰到订阅版的边界

多设备云端同步、规则数量、历史保留时长这几项，社区版都有额度上限。具体数字和订阅版多出来的东西，见 [免费版与订阅版有什么区别.md](免费版与订阅版有什么区别.md)。
