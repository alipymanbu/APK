# Reqable 抓不到流量怎么排查

> Reqable 的调试开关打开后，正常情况下经过代理的请求都会出现在调试列表里。本篇讲一条都没有时怎么排查：先过五条开关，再按三种现象判定原因，协同模式下另有单独的顺序。

## 一、先把五条开关过一遍

官方给的前置清单，缺一条都可能什么都看不到，这几项都在调试相关的设置与筛选栏里：

| 检查项 | 该是什么状态 |
| --- | --- |
| 调试开关 | 已开启 |
| 记录模式 | VPN，不是代理 |
| 增强模式 | 已启用 |
| 筛选与搜索条件 | 全部关闭 |
| 指定应用 | 已全部移除 |

改完这五项，打开手机浏览器访问一个网页，再回头看调试列表。

记录模式与增强模式各管什么、分别覆盖到哪类流量，见 [常规模式与增强模式有什么区别.md](常规模式与增强模式有什么区别.md)。

## 二、按结果分三种情况

| 情况 | 现象 | 原因与处理 |
| --- | --- | --- |
| 一 | 网页打不开，列表里连 CONNECT 请求都没有 | 大概率是代理端口异常，比如被别的程序占用了 → 换个端口重试。换端口后还打不开，带上日志去官方反馈 |
| 二 | 网页能正常打开，列表里依然没有 CONNECT 请求 | 记录模式没在 VPN → 改成 VPN 再来一次。VPN 模式下还是这样，属于要反馈的问题 |
| 三 | 网页能打开，列表里也能看到浏览器的请求 | 说明目标应用禁止在 VPN 激活状态下工作 → 这不是 Reqable 的问题，需要联系该应用的开发者。先确认增强模式是开着的，否则也可能只是那个应用不走系统代理没被抓到，见 [常规模式与增强模式有什么区别.md](常规模式与增强模式有什么区别.md) |

**情况三最容易被误判成「Reqable 坏了」**：你抓某个 App 什么都抓不到，但浏览器一切正常，基本就是那个 App 自己不愿意在 VPN 环境里干活。换别的应用试试就能确认。

## 三、协同模式下抓不到

1. 先切回独立模式（侧边栏选「调试」Tab），按上面第一节和第二节的流程排查一遍。
2. 手机端把「增强模式」关掉再重新打开，然后重试。
3. 电脑端换一个端口，重新扫码连接。

## 四、只想抓某一个应用

默认状态是抓所有应用，这也是排错时官方要求「移除全部指定应用」的原因。反过来的用法是：只想看某一个 App 的流量，就把它加进指定应用列表，列表立刻干净很多，也不容易被别的后台请求淹没。

## 五、浏览器提示「不安全的网站」

这是证书信任的问题，不是抓包链路断了。Chrome 和 Firefox 的处理方式不一样，见 [证书安装与SSL握手失败排查.md](证书安装与SSL握手失败排查.md) 第五节的对照表。

## 六、排查前先更新到最新版

官方 FAQ 开篇第一句就是：先把 Reqable 更新到最新版本，然后再排错。旧版本里已经修掉的问题，在新版上不必再折腾一遍。

## 七、日志在哪看

侧边栏 → **长按顶部的 Logo** → 选择日志文件查看。反馈问题时把日志一起带上，定位会快很多。

## 八、还是不行

带上这几样去官方 GitHub 仓库的 Issues 反馈：Reqable 版本号、手机型号与系统版本、记录模式（VPN 还是代理）、日志文件。这几项齐了，对方基本能直接复现。
