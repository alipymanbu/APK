## 一、先接受一个事实：Android 端剪贴板只通文本

各平台客户端的重定向能力不一样，微软的功能对比表给出的支持是：

| 内容 | Android / Chrome OS | iOS / iPadOS | Windows 桌面客户端 |
|---|---|---|---|
| 文本 | 支持 | 支持 | 支持 |
| 图片 | 不支持 | 支持 | 支持 |
| 文件 | 不支持 | 不支持 | 支持 |

（支持范围以微软官方功能对比页当时显示为准。）

也就是说，你在手机上复制一段文字粘进远程电脑（或反向）是正常需求，**复制一张图、或直接粘一个文件过去，在 Android 端本来就做不了**——这不是坏了，是平台限制。图片和文件请走第三节的存储重定向。

## 二、文本也粘不过去时，按这个顺序查

剪贴板能不能用，由「客户端开关 + 被连端策略」两层决定，两边都得放行，且**限制更严的一方优先**：

1. **确认连接上的重定向开着**。编辑那条连接，检查剪贴板（以及本地存储）重定向是否启用；重定向项会随你连的对象（远程电脑 / 虚拟桌面）不同而不同。
2. **查被连端策略**。在远程电脑上按 `Win + R` 输入 `gpedit.msc` 回车，进「计算机配置 → 管理模板 → Windows 组件 → 远程桌面服务 → 远程桌面会话主机 → 设备和资源重定向」，看「不允许剪贴板重定向」是不是被设成了「已启用」——改成「已禁用」或「未配置」。公司域控下发的组策略同样能禁掉它，那要找管理员。
3. **重启剪贴板通道**。会话里卡住时，任务管理器找到 `rdpclip.exe` 结束它，再「文件 → 运行新任务」输入 `rdpclip.exe` 回车。这个进程负责两头的剪贴板搬运，重连后偶尔会静默失灵，重启它通常当场恢复。
4. **改完策略要重连**。断开当前会话、重新连一次，策略才会生效；光改不重连不会有任何变化。

三步都做了还不通，就是你的 Android 客户端版本与被连端的组合不支持，别再耗时间，改用下一段的办法。

## 三、传文件的两条正路

**路一：把手机存储挂进会话**。添加或编辑连接时把「Redirect local storage（重定向本地存储）」打开（默认关闭），连上后在远程电脑的文件资源管理器里就能看到手机存储，复制粘贴等于在本机挪文件。

**路二：用电脑端的驱动器重定向**。Windows 桌面客户端发起的连接会把本地磁盘映射进远程会话（在远程的文件资源管理器里显示为网络驱动器，形如 `\\tsclient\c`）。从手机 App 发起的连接没有这个映射入口，所以大文件更现实的做法是：手机 → 网盘 / 局域网共享 → 电脑，或反过来。

**别用剪贴板传大文件**。有用户反馈通过剪贴板复制超大文件（约 2GB 量级）会静默失败——文本、图片小内容才适合走剪贴板，文件一律走上面两条路。
