## 一、这是个什么功能

「一起听」让你和朋友**实时同步播放状态**：谁在放、放到哪一秒、切歌还是暂停，两边界面跟着走。你自己听、对方跟着，或者反过来，都行。

先说清楚状态：**这是官方标注的实验性功能，仍在测试中**（官方更新日志原话是「如有问题请及时反馈」）。能用，但遇到不稳定属预期内，别把它当日常主力功能依赖。

## 二、开一个房间 / 进一个房间

- **开房**：你创建房间，自己当房主，控制播放。
- **进房**：加入别人的房间，身份是听众。
- **邀请方式**：房间支持**邀请链接**与**深链**直接加入——把链接发给对方，点开就能进，不用手动输一串房间号。
- **房主离线检测**：房主下线了，房间里看得出来，听众不会一直等一个已经关掉的播放。

## 三、权限是怎么分的

房间里有**房主与听众**两种身份，权限不同：

| 身份 | 能做什么 |
| --- | --- |
| 房主 | 控制播放、切歌、调循环/随机模式；管理成员（允许谁操作） |
| 听众 | 跟随房主的进度与模式；被房主允许时才能操作 |

**循环与随机模式是跟着房间同步的**——你在自己这端切了模式，对方的播放行为也跟着变。同步的只是播放状态，两端各自的音量互不影响，各自想调多大声调多大声（见 [搜索音乐与在线播放.md](搜索音乐与在线播放.md) 第四节）。

## 四、服务端是哪来的

这个功能要一台**中转服务器**转发状态，两种拿法：

1. **用别人部署好的服务**：官方 README 里列了社区维护的服务端项目与现成服务地址（具体仓库名与地址以官方仓库 [github.com/cwuom/NeriPlayer](https://github.com/cwuom/NeriPlayer) 当时的说明为准）；
2. **自己部署**：官方仓库另有部署文档，适合对隐私要求高、愿意自己维护一台服务的用户。

**选服务等于把播放状态交给那台服务器**：用公共服务前想清楚这一点；同步的内容只有「在放什么、放到哪」，不涉及你的账号令牌（授权信息只存本机，见 [支持哪些音乐平台.md](支持哪些音乐平台.md) 第四节）。应用里也支持**自定义服务端地址**，填自己那台最稳妥。

## 五、出问题时怎么办

- **连不上 / 进不了房**：先确认你与房主双方的网络都能连到那台服务端；公共服务可能时好时坏，换一个或自部署是常见做法。
- **同步不准 / 房主操作没传过去**：官方把它标为实验功能，小毛病以反馈为主——用 [常见问题排查.md](常见问题排查.md) 第七节的办法取日志，去官方仓库提 Issue。
- **版本差异**：两端版本差太多时同步行为可能不对，先对齐到同一版本（升级注意事项见 [GitHub同步备份与换机迁移.md](GitHub同步备份与换机迁移.md) 第三节）。
