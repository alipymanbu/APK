# OpenLess 词典热词怎么设置

语音识别是按发音猜字的，遇到「不是常见词、但对你很常用」的名字就爱出错——同事的名字、公司内部系统的代号、某款产品的英文写法。OpenLess 的**词典**就是给这类词开的后门：加进去的词会在**识别和润色两个环节**都被照顾到，一次配置，长期受益。

## 一、词典在链路里的哪一段起作用

回想一下输入的两段链路（见 [语音识别与润色服务怎么配置.md](语音识别与润色服务怎么配置.md)），词典是**同时打在两端**的：

| 环节 | 词典起什么作用 |
| --- | --- |
| 语音识别 | 作为**热词**送进去，让识别优先往这个词上靠，减少同音误判 |
| 文本润色 | 作为**语义提示**交给模型，让它不要顺手把专有名词改错 |

两端都配的好处是：即使识别那一步没完全听对，润色这一步还有机会按词典把名字纠回来。只配一端也能用，但效果打折。

## 二、加词条要注意的两件事

- **写「正确写法」，不是写读音。** 词条填的是你希望它出现在文字里的样子，比如产品名按官方大小写写；不要填拼音或谐音提示。
- **一个词条一个词。** 别把一整串名词塞进一条，识别与润色都是按词匹配的，塞成一串反而命中不了。

加什么词最值：

1. **人名**——尤其是名字里有生僻字、或英文名拼写不常见的；
2. **产品名与项目代号**——官方大小写、连字符、数字后缀要写全；
3. **内部术语与缩写**——外面搜不到、模型没见过的词；
4. **爱被听错的英文技术词**——中英混说时最容易翻车的一类。

## 三、哪些识别服务真的吃热词

这是本篇最该记住的一节：**热词不是每家识别服务都支持，也不是都支持得一样**。项目说明里给出的现状大致是：

| 识别服务 | 热词的支持方式 |
| --- | --- |
| 火山引擎 | 请求级热词参数，词典直接生效 |
| 阶跃星辰 | 请求级热词参数 |
| OpenAI 兼容的批量转写（Whisper 系） | 通过提示字段带入，但有一类兼容服务不走提示字段，带不进去 |
| 阿里云百炼 | 走词表标识，需要在平台侧先建词表 |
| 讯飞实时语音转写标准版 | **没有请求级热词参数**，要到讯飞控制台配置个性化热词 |

所以同一个词典，换个识别供应商效果可能就不一样。你如果重度依赖专有名词，选识别端时把这一栏一起考虑——**先确认它支不支持你这种用法，再决定填哪家**。列表与参数名以官方说明为准，也会随版本更新。

词典里每个词条会累计**命中次数**，用久了能看出哪些词真的在起作用、哪些白加了。

## 四、让词典自己长：改一下就问你要不要记住

以前词典只认识你亲手敲进去的词。现在多了一条路径：**当你在润色结果里手动改掉某个词，OpenLess 会弹一张小卡片问你要不要记住**，点一下这个词就进词典了，下次不用再改。

用这条路径时记住两件事：

- **每一条都是你过目确认才会加**，不存在悄悄学走的情况；
- 改的时候改对——你改成的那个写法就是它要记的写法。改错了还确认，等于把错词教给了它。

配合这个机制，前几周用下来词典会自然攒成一份贴合你自己的词表，比一开始硬凑几十个词实在。

另外，桌面版在 macOS 上还有一项**光标上下文**开关，开启后润色模型能读到光标周围正在写的内容，对判断语境有帮助；这一项属于桌面端能力，安卓版没有，别在手机设置里找。

## 五、词条存在哪、会不会泄露

词典和音频、历史、配置一样，**都留在你自己的设备上**，不上传到项目方的服务器。真正会被发出去的，是**你说话时的音频**（去识别服务）和**转写出来的文字**（去润色服务）——这两段都是发给你自己配的那家供应商，与 OpenLess 无关。

所以敏感词条的边界要自己拿捏：加进词典的专有名词，会随识别请求或润色请求一并送到你配的服务商那里。**内部代号、未公开项目名这类东西，值不值得进词典，取决于你对那家云服务的信任程度**，这跟 OpenLess 是不是开源没关系。

词典改完不用重启应用，下一次按住说话就会带上新词。如果加完仍然被识别错，先回 [常见问题与排查.md](常见问题与排查.md) 看是不是识别端本身不吃热词。
