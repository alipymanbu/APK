# SukiSU-Ultra GKI内核判断与刷入方式选择

## 一、为什么刷法因机型而异

root 改动的是系统内核。你的内核从哪来（Google 通用内核还是厂商自己编译的），决定了有没有现成包可以直接刷 —— 这是选择路径前唯一必须搞清的事。

## 二、先查内核版本

两个入口任选：

- 手机上：设置 → 关于手机 → 内核版本，形如 `5.10.157-android13-...`，开头两段（`5.10`）就是关键信息；
- 电脑上：开启 USB 调试后执行 `adb shell uname -r`。

把版本号前两位记下来，后面要反复用到。

一个高频误解：**内核版本 ≠ 系统安卓版本**。系统升到 Android 13、内核还停在 `android12-5.10` 的设备很常见 —— 内核一般跟着**出厂**系统走，升级不动它。挑包、选修补目标时永远以内核版本为准，选错了会反复重启，细节见[boot镜像提取与修补.md](boot镜像提取与修补.md)。

架构方面，官方兼容性页给的口径是：arm64-v8a 完全支持，armeabi-v7a 基础支持，x86_64 部分支持（截至 2026 年，以官方页面为准）。老设备基本都是 arm64，不用操心；x86 平板想折腾就先做好失败预案。

## 三、GKI 2.0 设备（内核 5.10 起）

内核版本是 5.10、5.15、6.1、6.6 这类，且系统版本较新 —— 大概率是 GKI 2.0 设备，典型如小米、红米、三星的大部分机型。你的刷入成本最低：

- 社区维护的 GKI 构建仓库（官方文档「更多链接」页给出：[https://github.com/ShirkNeko/GKI_KernelSU_SUSFS](https://github.com/ShirkNeko/GKI_KernelSU_SUSFS)）里有按内核版本分好的现成包，直接下载带 `AnyKernel3` 后缀的 zip 刷入即可；
- 也可以走管理器修补 boot / init_boot 镜像的路径。

两条路径的完整步骤见[下载与安装教程.md](下载与安装教程.md)。

## 四、旧内核与非 GKI（4.x ~ 5.4）

内核在 4.x 到 5.4 之间、或机型明显不在 GKI 名单里 —— 没有现成包，需要把 SukiSU-Ultra 集成进内核源码自己编译：

- 官方提供了内核集成脚本，分主分支（LKM 方式）与内置（builtin）两种集成形态，从内核源码构建时一并带入；
- 要启用 KPM 内核模块，内核配置需加 `CONFIG_KPM=y`；非 GKI 设备还需要 `CONFIG_KALLSYMS=y` 与 `CONFIG_KALLSYMS_ALL=y`；
- 3.x 老内核只能靠反向移植支持（3.4 ~ 3.18），官方标注为实验性。

这条路对动手能力要求高，需要你会拉取并编译自己设备的内核源码；没有把握就先看第五节的厂商方案，或到社区确认有没有现成产物。

## 五、内核改动深的厂商机型

一加、真我、OPPO、魅族对内核的定制较深，**现成 GKI 包刷上去不生效甚至出问题**，官方文档明确把这类机型排除在通用刷法之外：

- **一加**：官方链接页提供了自动化构建仓库（[https://github.com/ShirkNeko/Action_OnePlus_MKSU_SUSFS](https://github.com/ShirkNeko/Action_OnePlus_MKSU_SUSFS)），填入内核版本前两位（如 `5.10`、`6.1`）、处理器代号（一般是不含数字的英文，从一加开源内核仓库可查到）以及分支与配置文件，生成专属内核包后照常刷入；
- **真我 / OPPO / 魅族**：官方文档没有给现成方案，通常只能走第四节的自行编译路线，或到社区（Telegram 群、GitHub Issues）找同机型的先例。

## 六、路径选择对照表

| 你的情况 | 建议路径 |
| --- | --- |
| 内核 5.10+，小米 / 红米 / 三星等 | 现成 GKI 包 TWRP 刷入，或管理器修补镜像刷回 |
| 内核 5.10+，但不想动 recovery | 管理器修补 boot / init_boot 镜像 + fastboot 刷回 |
| 一加机型 | 官方自动化构建仓库生成专属包再刷 |
| 内核 4.x ~ 5.4 的非 GKI 设备 | 内核源码自行集成编译（LKM 或 builtin） |
| 内核 3.x | 反向移植方案，实验性，先备份并做好失败预案 |
| 真我 / OPPO / 魅族 | 自行编译，或去社区找同机型产物 |

刷完之后系统一更新可能把 root 弄丢，提前看[OTA更新保持Root方法.md](OTA更新保持Root方法.md)；中途任何一步不对劲，见[常见问题与风险须知.md](常见问题与风险须知.md)。
