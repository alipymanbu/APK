## 一、点了下载却失败

按顺序排查：

1. **链接是否完整**：有些应用分享出来的是短链或中间页链接，先在浏览器里打开，确认能直达那条内容；
2. **平台是否受支持**：对照[支持平台清单与解析方式.md](支持平台清单与解析方式.md)，不在清单里的平台无解；
3. **网络是否可用**：文件要从解析服务取回来，断网或网络受限时必然失败（应用内没有代理设置，走代理才能上网的环境要留意这一点）；
4. **上游服务波动**：同一平台突然集体失败，多半是解析服务那边的问题，等一段时间再试，别反复重试。

几个有仓库记录可查的具体异常：

- **下出来是 0 字节文件**：解析服务没给出有效文件时的产物，删掉重下一次；还是 0 字节就先放弃这条链接；
- **下载的视频没有声音**：有用户反馈过 Facebook 视频下完无声（仓库有记录），重新下载或换一条链接再试；
- **YouTube / X / Instagram 怎么都下不动**：这是当前失败最集中的几类，原因与现状在[下载失败原因与现状.md](下载失败原因与现状.md)里展开讲。

以上都正常还是失败，换一条同类链接交叉验证一下，能定位是链接问题还是应用问题。

## 二、反复弹权限申请，或提示没有权限

1.4 版改为按需申请存储权限。如果你之前拒绝过、且勾选了"不再询问"，系统不会再弹窗，需要手动补：

1. 打开 **设置 → 应用 → FetchIt**；
2. 进入**权限**；
3. 把**存储**（部分机型叫"文件和媒体"）设为允许；
4. 通知权限在同一页面，建议一并打开。

## 三、下载完成但找不到文件

- 它的下载都归在应用内的「下载」页里：文件名是 `video_日期_时间.mp4` 的形式，选中后用底部**保存**动作导出，才落到你选的目录（详见[链接解析与下载步骤.md](链接解析与下载步骤.md)第四节）；
- 打开系统文件管理器，进入保存目录（默认常见的是 Download），按**最近修改**排序，最上面的就是刚导出的文件；
- 用第三方文件管理器时注意它的可见范围：部分管理器默认不显示 SD 卡目录，切换存储位置再看。

## 四、通知栏不显示进度

- 检查 FetchIt 的通知权限是否开启（路径见第二节）；
- 部分机型的省电策略会限制后台活动，可在 **设置 → 电池**（或"后台管理"）里允许 FetchIt 后台运行；
- 关掉通知权限不影响下载本身，只是进度要回到应用内看。

## 五、想只提取音频，或者批量下载

截至 1.4 版，这两个能力都没有：只提取音频有开放请求（作者答复计划在未来版本加入），批量下载也还没有。作者在仓库答复里推荐了两个同样开源的安卓应用来补足这类需求：[Seal](https://github.com/JunkFood02/Seal) 和 [YTDLnis](https://github.com/deniscerri/ytdlnis)，需要批量或音频功能可以去看这两个，功能状态以各自项目页面为准。

网盘里的 **FetchIt 安装文件资源（夸克网盘）**：[https://pan.quark.cn/s/3d4d720cb7b3](https://pan.quark.cn/s/3d4d720cb7b3) 对应 1.4 版；之后想换新版，从上面两个渠道取更新的安装包覆盖安装即可。若覆盖时提示签名冲突，说明两份包不是同一来源构建的，先卸载旧版再装（会清掉应用内的设置）。

另一个要知道的节奏：这是个人维护的项目，平台改版导致解析失效后，修复要等作者或上游服务跟进（作者 2026 年年中的公开回复也说明了维护一度放缓）。所以某平台突然全挂时，除了等更新没有更好的办法，动态看仓库就知道了。

## 七、其他问题去哪反馈

FetchIt 是开源项目，问题反馈走 GitHub Issues：[github.com/tharunbirla/FetchIt/issues](https://github.com/tharunbirla/FetchIt/issues)。发之前带上三样东西，回复会快很多：失效的链接、应用版本号、屏幕上的报错原文。

最后提醒一句使用边界：它与你下载内容所在平台没有从属关系，保存前确认内容版权与平台条款允许，只保存你有权保存的内容。
