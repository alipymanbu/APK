## 一、官方标注的支持清单（21 个平台）

按内容类型分组列在下表（分组是本文为了方便阅读做的，官方只是平铺列出）：

| 类型 | 平台 |
| --- | --- |
| 视频与直播 | YouTube、Vimeo、Dailymotion、Twitch、Rutube、Streamable、Loom、Bilibili |
| 社交与社区 | Facebook、Instagram、Twitter、TikTok、Reddit、Snapchat、Tumblr、VK、Bluesky、OK、Vine |
| 音频与图片 | SoundCloud、Pinterest |

几点说明：

- Vine 已经停止服务，列在清单里更多是历史兼容，别指望它能正常解析；
- 官方同时声明：开发者和上述平台之间没有任何从属或合作关系。

## 二、它的链接解析走的是第三方服务

FetchIt 本身不托管任何内容，你的链接是交给外部解析服务处理、再把文件传回手机的。开发者在仓库 issue 里的答复说明：YouTube 及多数平台走 cobalt 这类解析服务，Twitter 与 Instagram 用的是另外的服务（官方 README 致谢里点名了 twitsave.com 与 imginn.com），Facebook 具体用哪个服务没有公开点名。

| 目标平台 | 解析依托 |
| --- | --- |
| YouTube 及多数平台 | [cobalt.tools](https://cobalt.tools) |
| Twitter | `twitsave.com` |
| Instagram | `imginn.com` |
| Facebook | 未公开点名 |

这对你意味着三件事：

- 某个平台**今天能下、明天集体失败**，最常见的解释是上游解析服务在变动或被限制，跟你的操作没关系，换个时间段再试——失败时按[下载失败原因与现状.md](下载失败原因与现状.md)判断原因在哪一层；
- 下载能不能成功、下下来是什么画质，取决于上游服务当时能给什么，应用本身没有画质承诺，遇到模糊或只有部分格式的情况属正常；
- **x.com 域名的 Twitter 链接**：仓库里还挂着"支持 x.com 链接"的开放请求，说明这类链接目前可能识别不了；拿 x.com 链接失败时，可以试试把域名改成 `twitter.com` 的同一条链接，以实际结果为准。

## 三、什么样的链接能被识别

- **能**：指向具体内容页的公开链接，比如某条视频、某个帖子的分享链接或地址栏链接；
- **一般不能**：个人主页链接、搜索结果页链接、需要登录或订阅才能看的私密内容链接；
- 拿不准时，先在浏览器里打开这条链接，能直接看到内容本身（而不是中间页或登录墙），再丢给 FetchIt 试试。

## 四、清单会变，以官方页面为准

支持平台清单以 GitHub 仓库 README 当时列出的为准：[github.com/tharunbirla/FetchIt](https://github.com/tharunbirla/FetchIt)。平台改版、解析服务更替都可能让某个平台临时不可用，遇到解析失败按[常见问题与解决办法.md](常见问题与解决办法.md)排查。
