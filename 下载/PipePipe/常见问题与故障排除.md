## 一、先建立一个排查观念

PipePipe 这类客户端直接调用视频平台的接口，平台一改版，客户端就可能跟着出问题——这不是你操作错了，也通常不用卸载重装。官方的修复节奏比较快，**升级到新版本是大多数「突然用不了」的第一解法**。

所以遇到问题的固定顺序是：

1. 记下症状（哪个平台、什么操作、什么报错）；
2. 打开官方发布页 [github.com/InfinityLoop1308/PipePipe/releases](https://github.com/InfinityLoop1308/PipePipe/releases)，看最近版本的修复说明里有没有同类问题；
3. 有 → 升级；没有 → 按下面的症状清单继续排查。

## 二、按症状排查

| 症状 | 先查什么 | 再做什么 |
| --- | --- | --- |
| 播放一直转圈 | 网络是否能直连对应平台；画质是否过高 | 降一档画质再试；换网络环境对比 |
| 播放报错但别人正常 | 自己的版本是否落后 | 升级；登录用户遇到「内容不可用」类报错时优先升级（官方修过登录用户相关的播放问题） |
| B 站内容播不出 / SponsorBlock 不生效 | 版本是否落后 | 升级（官方修复说明里多次出现 B 站相关修复） |
| 搜索无结果 | 是否触发了平台风控（频繁请求后突然全空） | 隔一段时间再试；换网络环境 |
| 悬浮窗弹不出来 | 「显示在其他应用上层」权限 | 到系统设置里给应用补授权 |
| 后台播放被杀 | 电池优化白名单 | 把应用加入系统的后台保护名单 |
| 覆盖安装更新失败 | 是否换了下载渠道（签名可能不同） | 沿用原渠道更新；或先导出数据备份、卸载重装后再导入，见 [导入订阅与数据迁移.md](导入订阅与数据迁移.md) |
| 订阅刷新失败或列表报错 | 网络能否直连对应平台 | 稍后再刷；订阅数据本身可以先用备份保全，见 [导入订阅与数据迁移.md](导入订阅与数据迁移.md) |
| 安装时提示解析失败 | APK 是否下载完整、架构是否匹配 | 重新下载；按 [下载与安装教程.md](下载与安装教程.md) 的表格换对应架构的包 |

## 三、老系统的 WebView 问题

部分受保护的播放依赖系统 WebView 组件。在 Android 6、7、8 这类老系统且没有谷歌服务的设备上，WebView 长期不更新会直接影响播放——播放异常时，把系统 WebView 升到可用的最新版是一个常被忽略的检查点。老设备没有好的 WebView 更新渠道的话，这类问题只能靠换系统或换设备解决。

## 四、想第一时间拿到修复：CI 构建

官方仓库说明里写明：如果某个已知问题已经修好、但还没发正式版，可以去仓库的持续集成（CI）页面拿最新构建——打开 [github.com/InfinityLoop1308/PipePipe/actions/workflows/ci.yml](https://github.com/InfinityLoop1308/PipePipe/actions/workflows/ci.yml)，选最近一次成功的运行，下载其中的 debug APK。debug 构建未经完整发布流程，日常使用还是优先正式版，急着验证某个修复时再走这条路。

## 五、去哪反馈问题

问题排查不出、确认是新故障时，到官方 Issue 页 [github.com/InfinityLoop1308/PipePipe/issues](https://github.com/InfinityLoop1308/PipePipe/issues) 搜索关键词——你的问题大概率已经有人报过。提交新 Issue 前把版本号、平台、复现步骤写全。有一点要有预期：按仓库说明，作者欢迎 Issue 与 PR，但**不受理「服务请求」类诉求**（比如要求新增某个平台的接入），这类提议仓库不接。

## 六、其他高频小问题

- **应用商店里搜不到**：它不在 Google Play 上架，安装渠道见 [下载与安装教程.md](下载与安装教程.md)。
- **需要账号吗**：不需要，登录只在你需要看账号权限内容时才有用，见 [B站与YouTube登录设置.md](B站与YouTube登录设置.md)。
- **会收集我的数据吗**：官方口径是不收集、无广告、无跟踪；订阅与历史都在手机本地。
- **SponsorBlock 为什么跳不准**：它的片段标记来自社区数据库，没人标记过的片段自然不会跳，标记密度取决于视频热度。
- **还没拿到安装包**：本文开头的 PipePipe 安装文件资源（夸克网盘）转存后即可安装，流程见 [下载与安装教程.md](下载与安装教程.md)。
