# LSPosed 开机卡住进不去系统怎么救

> 本篇给出卡开机动画时的三条救援路径，以及把系统救回来之后怎么定位是哪个模块闯的祸。

装了模块之后重启，手机一直停在开机动画进不了桌面——这是这类框架最典型的翻车方式，也最容易被误判成「手机坏了」。它基本上是软件层面的问题：某个模块在系统进程里挂了不该挂的东西。本篇按「先让系统能开机、再回头查元凶」的顺序给出三条路。

## 一、先判断一件事：能不能进 Recovery

救援路径取决于你手上还有什么入口，先花十秒确认：

| 你的设备状态 | 可用的路径 |
| --- | --- |
| 能被电脑识别到 ADB | 路径一，优先试这条，不用刷任何东西 |
| 能进系统自带的安全模式 | 路径二 |
| 装了 TWRP / OrangeFox 这类第三方 Recovery | 路径三 |
| 以上都没有，但能进 fastboot | 先按机型官方方式刷回原厂 boot，再处理模块 |

判断完再动手，别在三条路之间反复试——每多一次开机循环，电池和时间的消耗都是白搭的。

## 二、路径一：用 ADB 移除全部模块

在设备开机、能被电脑识别到 ADB 的时候执行下面这条命令：

```bash
adb wait-for-device shell magisk --remove-modules
```

它的作用不是立刻改你手机里的东西，而是给 Magisk 留一个标记，让本次启动把所有模块都移除，所以设备接下来的那一次启动就能正常进系统。

两个代价要提前知道：

- **移除的是全部 Magisk 模块，不只是 LSPosed**，进系统之后要按需重新装回来；
- 这条命令需要设备能被 ADB 识别。如果开机过程中始终连不上，直接走路径二或路径三。

如果用的是 KernelSU 或 APatch，思路一样，换它自己的命令行工具：

```bash
adb shell su -c "ksud module list"
adb shell su -c "ksud module disable 模块目录名"
adb shell su -c "ksud module uninstall 模块目录名"
```

先列出模块，把出问题的那个停用或卸掉，再重启。KernelSU 还有一个比接电脑更省事的入口：**开机第一个画面之后，连续按三次音量减**（是按下—抬起、重复三次，不是一直按住），会进入它自带的安全模式，此时所有模块都被停用，进系统后在管理器里一个个启用回来就能定位元凶。安全模式管不到模块写在开机脚本里的内容，如果模块在那里面做了不合理的事，仍然开不了机，那就只能走路径三。

## 三、路径二：进安全模式

各家进入安全模式的手法不一样（多数机型是开机时按住音量减，部分定制系统要在 Recovery 里启用），以你自己机型的说明为准。进入之后会发生两件事：

1. 第三方应用被停用，Magisk 应用本身也打不开；
2. 从安全模式重启回正常模式后，第三方应用会恢复，**但 Magisk 的模块仍然保持停用状态**。

也就是说，安全模式的作用是「让模块集体静默一次」，让你有机会回到系统里。进系统之后按这个顺序处理：

1. 打开 Magisk，进模块页，先**只保留 Magisk 本身必需的那一两个**，其余先停用；
2. 重启，确认能正常进系统；
3. 之后再把模块一个一个启用回来，每启用一个就重启一次，直到复现问题，那个模块就是元凶。

## 四、路径三：在 Recovery 里删目录

有第三方 Recovery 时，这是最直接的做法。进 Recovery 后挂载 `data` 分区，然后删掉出问题的模块目录：

```bash
mount /data
rm -rf /data/adb/modules/lsposed
```

删的是 Magisk 加载模块时读取的那个目录，删掉之后框架就不会再被加载。如果画面或状态还是不对，可以再把 LSPosed 自己的数据目录一并清掉：

```bash
rm -rf /data/adb/lspd
```

动手前务必确认路径：`/data/adb/modules/` 下面每个子目录对应一个 Magisk 模块，只删出问题的那个（LSPosed 的目录名就是 `lsposed`），别对着 `/data` 或 `/data/adb` 整层下手。Recovery 里的文件管理器看不到目录名时可先列一次确认。

KernelSU 与 APatch 在 Recovery 下的做法不同：它们的模块加载依赖内核侧的启动脚本，把管理端程序文件删掉就能让模块整体不再加载。

```bash
mount /data
rm -f /data/adb/ksud
```

同样地，动手前先确认路径，别扩大删除范围；重启后进系统，再从管理器里处理模块。

## 五、把系统救回来之后

系统能进桌面只是第一步，不做下面这两件事，同一个坑还会再踩：

- **把元凶找出来**：按路径二第 3 步那种「一次只加一个模块」的方式复现一次，确认是 LSPosed 框架本身不兼容，还是某个具体模块的问题；
- **记下当前配置**：启用了哪些模块、各自勾了哪些作用域。重装之后照着恢复，比凭记忆快得多。

如果确认是 LSPosed 框架本身在你的系统上起不来（例如系统版本超出它声明的支持范围），那再怎么调模块也没用，要么升级到支持该系统版本的框架分支，要么就先不用它。

## 六、下次动手前的三条预防

1. **改动系统环境的操作前先备份 boot 镜像**——真出了状况，刷回原厂 boot 是绕开所有模块的最直接一条路；
2. **不要在系统大版本更新之后一次性把模块全开**，更新会改动的正是模块依赖的那些接口；
3. **给系统框架勾作用域之前先想好退路**：一个模块只挂普通应用，最坏结果是那个应用闪退；一旦挂到系统框架上，最坏结果是开不了机。

想彻底退回到没有框架的状态，按 [卸载与恢复原状.md](卸载与恢复原状.md) 走一遍，比在开机循环里反复试探安全得多。
