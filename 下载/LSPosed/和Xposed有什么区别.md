# LSPosed 和 Xposed 有什么区别

> 本篇把 LSPosed、原版 Xposed、EdXposed 三者的关系讲清楚，并给出「什么时候值得用它、什么时候别碰」的判断依据。

LSPosed 是安卓上的一套 Xposed 实现：模块能挂进应用进程、改变它们的行为，而不用改任何一个 APK。它和最早那个 Xposed 用的是同一套模块 API，但运行方式换了一代。本篇讲清它和原版 Xposed、EdXposed 到底差在哪，以及你的设备是否适合走这条路。

## 一、三者是传承关系，不是三个并行产品

| 名称 | 是什么 | 现在还能用吗 |
| --- | --- | --- |
| 原版 Xposed（Xposed Framework） | 最早的框架，需要直接改动系统文件来替换应用进程与 ART 运行时 | 在 Android 8.1 之后基本失效，原作者的项目早已停止更新 |
| EdXposed | 借助 Riru 把框架注入 Zygote 的实现，是 LSPosed 的**上游来源** | 项目已停更，模块生态基本迁走了 |
| LSPosed | EdXposed 的分支，用自研的挂钩库重写了注入与挂钩这一层 | 仍在维护，是现在这类模块的主流运行环境 |

三者的模块生态是同一套：给 Xposed 写的模块能在 LSPosed 上跑，给 LSPosed 写的模块也能在原版 Xposed 上跑——官方 README 明确写了两者 API 双向兼容。所以换框架不等于换模块，你收藏的那些模块基本都能带过来。

## 二、和原版 Xposed 的实际差别

最容易踩的误会，是把原版 Xposed 的安装印象搬过来——以为要先解锁、刷第三方 Recovery、再刷一个系统级的包。到 LSPosed 这一代，改的是运行方式：

- **不改系统分区**：改动都在内存里完成，系统文件保持原样。带来的直接好处是官方 OTA 更新时不用先卸载框架，出问题也好退——把模块停用、重启，系统就回到原样了（这一点是官方 README 写明的设计目标）。
- **安装前提换成了 Root 管理器**：框架以模块的形式装进系统，所以它的前置条件不再是「刷 Recovery」，而是「设备已 Root 并装好 Magisk 或 KernelSU 这类管理器」。具体版本要求见 [下载与安装教程.md](下载与安装教程.md) 第二节。
- **注入层从 Riru 转到 Zygisk**：Zygisk 是 Magisk 自带的能力，装起来少一层依赖，这也是现在推荐的路线。

## 三、和 EdXposed 的实际差别

两者都从 Riru/Zygote 这条思路出发，差别集中在挂钩库与维护状态：

| 对比项 | EdXposed | LSPosed |
| --- | --- | --- |
| 底层挂钩 | SandHook / YAHFA 等老一代方案 | 自研的 LSPlant，官方 README 中列为框架核心 |
| 维护状态 | 已停更 | 仍在更新，社区分支也在继续跟进 |
| 安装环境 | 依赖 Riru | Zygisk 或 Riru 都支持 |

对你的实际影响：EdXposed 停更之后，适配新系统这件事基本都转到 LSPosed 这一支上了；如果你的设备只支持老环境，沿用 Riru 路线仍然可以装它的 riru 版包。模块不用换——两边的模块生态本来就是同一套。

## 四、和「不用 Root」那一类方案怎么选

网上还有一类不需要 Root 的方案（例如 LSPatch 这种给单个 APK 打补丁的思路，以及各类虚拟空间容器）。区别不在好坏，而在作用范围：

| 方案 | 前提 | 生效范围 | 适合什么 |
| --- | --- | --- | --- |
| LSPosed | 设备已 Root（Magisk / KernelSU 等） | 你勾选作用域的应用，含系统进程 | 需要动系统框架、或要给多个应用统一挂模块 |
| 给单个 APK 打补丁 | 不需要 Root | 只有被重新打过包的那一个应用 | 只针对某一个应用，且不想动系统 |
| 虚拟空间容器 | 不需要 Root | 只在该容器内运行的副本 | 想把改动限制在一个沙盒里 |

选择依据很简单：只想改一个应用、又不想 Root，走打补丁那条路更省事；要改的是系统框架本身，或者有多个应用要挂同一批模块，就得 Root 上 LSPosed。

## 五、什么时候该用，什么时候别碰

值得上这条路的信号：

- 你已经在用 Magisk，Root 是现成的，只是想多一类能力；
- 你要的某个功能只有 Xposed 模块能做，应用商店里没有对应实现；
- 你能接受「改动都在内存里、重启即还原」这种可回退的工作方式。

先别急的情况：

- 设备还没 Root，且你有不能解锁的顾虑（这类框架绕不过 Root）；
- 手机上有你离不了的金融、支付类应用，且你没法接受它们因设备被改动而弹出异常提示；
- 你只是想让某个应用多几个小功能——先去官方模块仓库看看有没有现成模块，再决定要不要为它铺一套 Root 环境。

框架与模块能改动的东西很多，动作前有一点要记牢：模块一旦挂到系统框架这类进程上，出错的表现就是开不了机。真遇上了别慌，处理步骤在 [开机卡住进不去系统怎么救.md](开机卡住进不去系统怎么救.md)。
