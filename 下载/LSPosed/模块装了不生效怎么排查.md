# LSPosed 模块装了不生效怎么排查

> 本篇给一条从框架到模块的排查顺序，每步都有能看到的判据，避免在「到底哪一环没通」上瞎试。

「模块装了不生效」这句话底下其实藏着好几种不同的故障：框架没起来、模块没被加载、作用域没勾对、勾对了但目标应用没重新启动。它们的外观一模一样，处理方式却完全不同。本篇按从外到内的顺序排一条排查线，每步都给出可以自己确认的判据。

## 一、第一步：先确认框架还在线

打开管理器，看首页的状态区。这是最关键的一次分流：

- **显示已激活**：框架正常，问题在模块这一侧，跳到第三节；
- **显示未激活或读不到状态**：问题在框架这一侧，继续往下看。

框架侧的四个常见原因：

1. **Magisk 里的 Zygisk 被关掉了**。Magisk 的设置里 Zygisk 开关在某些机型上会随系统更新被重置，重新打开并重启即可；
2. **装的包与环境不匹配**。Zygisk 环境装了 riru 版、或者反过来，框架不会报错，只是不起作用——换成本环境对应的那个包；
3. **系统版本超出支持范围**。官方 README 给 1.9.x 写的范围是 Android 8.1 到 Android 14，范围外的机型起不来属于预期内的事，升级框架到支持该系统的分支才是解法；
4. **Zygisk 是刚打开的**。Zygisk 要在 Zygote 启动时注入，而打开它这件事本身也是靠一次重启生效的，所以第一次重启之后如果状态还是未激活，别急着改配置，直接再重启一次看看——这一条能省下不少白折腾。

如果用的是 KernelSU 或 APatch，还要先确认 Zygisk 环境提供者那一层装好了，顺序见 [不用Magisk的Root环境怎么装.md](不用Magisk的Root环境怎么装.md)。

## 二、第二步：确认模块有没有被加载

模块页里能看到它，只说明「手机里装着这个 APK」，不代表它已经被加载。两处要一起看：

- **模块的启用开关是不是打开的**（关着的模块不会加载）；
- **作用域里有没有勾上你要它生效的那个应用**（没勾 = 这个应用里不会加载这个模块）。

这两项都对了还不生效，再确认一次你有没有做「重启目标应用」这一步——不少人是在装完模块后直接打开目标应用看效果的，改动还没机会生效。

## 三、第三步：看日志怎么说

管理器自带日志页面，能看到模块在哪个进程被加载、挂钩有没有报错。看之前先做一件事：**在设置里把详细日志打开**。它在正式版里默认是关的，打开后立即生效、不用重启，代价是日志量会明显变大，问题查完记得关回去。

另外，管理器自己崩过之后会把一份诊断报告打包放到手机的「文档」目录下，文件名以 `LSPosed_crash_report` 开头加时间戳。要向模块作者反馈问题时，发这个包比截几张图有用得多——里面带着框架侧的完整日志。

看日志时按这个顺序找：

1. 有没有出现目标应用的进程名——没出现，说明框架压根没往这个应用里注入；
2. 出现了但后面跟着报错，把报错里的类名或方法名抄下来，去模块的发布页或说明里对一对，通常是模块与宿主应用版本对不上；
3. 日志里能看到模块名，但看不到任何挂钩记录——模块自己判断条件不满足主动跳过了（例如宿主版本低于它要求的版本）。

想把「框架没注入」和「注入了但模块自己跳过」分开，日志是最直接的依据，所以排查时先看它，比反复重启应用省事。

## 四、常见原因对照表

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 管理器里勾了作用域，目标应用毫无变化 | 目标应用没有重新启动 | 强制停止后重新打开；系统类应用则重启整机 |
| 只有「系统框架」相关的功能不生效 | 只勾了应用、没勾系统框架 | 按模块说明补勾，风险见 [模块怎么激活与作用域怎么设置.md](模块怎么激活与作用域怎么设置.md) 第三节 |
| 单个应用怎么都不生效，别的应用正常 | 该应用被 Magisk 的排除列表排除了 | 被排除的应用不会注入任何 Zygisk 模块，需要时把它从排除列表里移出去 |
| 应用分身 / 双开里的那份不生效 | 双开副本运行在独立进程与独立目录下 | 作用域里要把双开那份也勾上，部分机型仍可能拿不到 |
| 模块装完不久，应用开始闪退 | 模块与当前宿主版本不兼容 | 先停用该模块确认，再换版本或等模块更新 |
| 多个模块同时开后陆续出问题 | 模块之间互相挂钩同一个方法 | 一次只开一个，逐个加回来定位冲突方 |
| 应用能打开，但一进某界面就被杀掉 | 该应用检测到运行环境被改动，主动退出 | 这是应用自己的保护行为，见 [隐藏管理器图标怎么用.md](隐藏管理器图标怎么用.md) 里的说明 |
| 模块装了、作用域也勾了，日志里却连加载记录都没有 | 模块要求的接口代际比当前框架新（模块说明里通常会写它需要哪一代接口） | 看模块发布页写的要求：要么把框架升到对应代际，要么留在该模块的旧版本 |

## 五、什么时候该停手

下面这两种情况，别再继续加模块试探，先把环境退回可控状态：

- **重启过程中卡在开机动画**：这已经不是「不生效」而是「起不来」，按 [开机卡住进不去系统怎么救.md](开机卡住进不去系统怎么救.md) 处理，先让系统能开机，再回头查是哪个模块；
- **同一个模块连续多次把系统搞不稳定**：把这个模块停用，等它的下一个版本，不要用「再试一次说不定就好了」的方式反复开机。

排查完记得把结论落到具体动作上——是换了包、改了作用域，还是停了某个模块。只记住「重启了一下就好了」，下次同一个问题会再花一遍时间。
