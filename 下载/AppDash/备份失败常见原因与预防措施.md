# AppDash 备份失败常见原因与预防措施

## 一、第一步就把备份目录设对

第一次进备份功能时，AppDash 会要求先选一个目录作为备份的存放位置——这步不能跳过，选错了后面全是麻烦：

- 开发者在 XDA 官方帖里的建议是：**给 AppDash 单独新建一个目录**，不要和别的文件混放；
- 备份列表页支持搜索、排序、筛选和批量操作，目录干净时这些都好用；
- 实用做法是「本地一个 + 云端一个」：本地目录求快，Google Drive 或 SMB 再放一份求稳。

## 二、别一次勾选全部应用去备份

这是开发者本人明确劝阻过的用法：一次备份上百个应用意味着现场压缩、写入几个 GB 的数据，**非常容易中途失败**，而且部分手机品牌会以「耗电」为由限制这类后台行为。

可执行的替代做法：

- 只备份真正重要的那批（付费应用、不好找的老版本、装完要配半天的工具）；
- 想分批的话，按标签组批量勾选，一组一组来（多选入口见 [标签分组与批量管理技巧.md](标签分组与批量管理技巧.md)）；
- 无 root 设备备的只是 APK，占空间小，但失败重来的时间成本一样存在，照样别贪多。

## 三、root 数据备份恢复的特殊风险

root 设备能把应用数据、外部数据、OBB 一起备份恢复，但开发者自己加了免责提醒：**有些应用不喜欢被备份和恢复，恢复后可能出问题，风险自担**。实际操作里值得注意：

- 聊天、银行、带设备绑定的应用，出问题的概率高于普通工具类应用；
- 这类应用更稳的迁移方式是「重装 + 应用内自带的迁移/恢复功能」，而不是第三方数据恢复；
- 备份数据前留意应用体积——数据加 OBB 动辄几 GB，空间和耗时都要提前算。

## 四、自动备份没生效的两个检查点

| 检查点 | 怎么处理 |
| --- | --- |
| 系统把 AppDash 当耗电应用杀后台 | 到系统设置里把 AppDash 排除出电池优化，各品牌叫法不同（省电策略/自启动管理/后台运行权限），要挨个放行 |
| 把「定时备份」当成了主要手段 | 开发者说过定时备份主要对 root 的数据备份有意义；无 root 设备靠「应用更新后自动备份」就够了，不必依赖定时 |

自动备份的触发时机是「应用更新时」——也就是说它保的是更新后的新版本，想留住旧版 APK 还是得在更新前手动备一份。

## 五、备份做完要核对，别凭感觉

有用户在 XDA 帖里反馈过早期版本的进度提示不明显、备完数量对不上。稳妥的习惯是：备份任务跑完后进备份列表逐项核对（数量、大小、版本号），发现缺的当场补。备份列表本身支持搜索、排序和筛选，核对几十条用不了几分钟。
