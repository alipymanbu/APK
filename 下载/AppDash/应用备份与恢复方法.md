## 一、先弄清：不 root 和 root 能备的东西不一样

这是备份功能里最关键的一条边界，动手前先对号入座：

| 你的设备 | 能备份的内容 |
| --- | --- |
| 普通设备（无 root） | 应用的 APK 安装包 |
| 已 root 的设备 | APK + 应用数据 + 外部数据 + OBB 文件 |

也就是说，不 root 的备份等于「把安装包存一份」，恢复后应用回到初始状态，聊天记录、存档这类数据不在里面；root 设备才能把数据一起带走。如果只是想留一个能随时重装的副本、或把老版本 APK 存下来防升级，不 root 的 APK 备份就够用。

## 二、备份存到哪里

AppDash 支持三个备份位置，按需选：

- **本地存储**：最快，手机丢了就没了；
- **Google Drive**：适合跨设备、换机场景；
- **SMB 网络共享**：路由器挂载的硬盘、NAS 都能接，适合想自己管文件的人。

同一个应用可以保留多个版本号的备份（版本化备份），恢复时你能选回滚到哪个版本，而不是只能回到最新。

## 三、手动备份一个应用

1. 第一次做备份前先设好备份目录——AppDash 会强制你先选一个位置；开发者建议**单独新建一个目录**给它专用，别和别的文件混放，原因与目录方案见 [备份失败常见原因与预防措施.md](备份失败常见原因与预防措施.md)。
2. 在应用列表里找到目标应用，进入它的详情页。
3. 点「备份」，等写入完成。
4. 备份完成后，在该应用的备份记录里能看到按版本号排列的存档。

批量场景（比如刚整理完标签、想把某一组应用全部备份）可以配合多选操作一次做完，多选入口见 [标签分组与批量管理技巧.md](标签分组与批量管理技巧.md)；勾选前先看一眼 [备份失败常见原因与预防措施.md](备份失败常见原因与预防措施.md) 第二节——一次全量备份是开发者明确不推荐的用法。

## 四、让备份自动发生

手动备份容易忘，两个自动化选项：

- **定时备份**：按你设的周期自动执行。注意开发者说过这条主要对 **root 的数据备份**有意义；无 root 设备用它收益不大；
- **应用更新后自动备份**：每当某个应用更新，就自动存一份新版本的 APK。这条对「想留住旧版本」的人最实用——应用商店的更新是覆盖式的，旧包一更新就没了。

自动备份没生效时，优先查两件事：系统是否把 AppDash 当耗电应用杀了后台、你是否把定时备份当成了无 root 设备的主力手段，处理办法见 [备份失败常见原因与预防措施.md](备份失败常见原因与预防措施.md) 第四节。

另外「过期备份」这种状态会被面板提醒（旧备份对应的应用已经更新到更新的版本），见到提醒去补一次备份即可。

## 五、恢复备份

在对应应用的备份记录里选择要恢复的版本执行恢复。恢复前确认：

- 目标应用当前已卸载，或你接受被降级/覆盖（Android 对降级安装有限制，被系统拦时先卸载再恢复）；
- 备份位置可访问（比如存 SMB 的话，网络共享当时在线）；
- 恢复的是 APK 备份时，应用数据不会跟着回来，原因见第一节；
- root 数据备份还要多一层心理准备：开发者自己提醒过**有些应用不喜欢被备份和恢复**，恢复后可能异常——聊天、银行类应用尤其如此，处理思路见 [备份失败常见原因与预防措施.md](备份失败常见原因与预防措施.md) 第三节。

## 六、换机或重装后，备份文件还在吗

- 存 Google Drive / SMB 的，新设备上登录后重新指向位置即可访问；
- 存本地的，换机要自己把备份目录拷过去；
- 标签、备注这类你整理出来的信息，AppDash 支持在设置里保存与恢复，重装应用后可以找回，不用重新打一遍标签。

备份出来的是标准 APK 文件，除了 AppDash 内恢复，也可以直接用系统安装器或任何安装工具装回去。手头没有备份、只想先拿到一份安装包的话，用这份 **AppDash 安装文件资源（夸克网盘）**：[https://pan.quark.cn/s/989583a6dc76](https://pan.quark.cn/s/989583a6dc76)。
