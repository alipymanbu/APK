# 加密图片发给对方打不开怎么办

> 对方拿到 PicEncrypt 加密图却还原不出内容，多半不是加密坏了，而是图片被压缩或密钥没对上。本文给出排查顺序。

## 一、为什么加密图特别怕压缩

PicEncrypt 是把密钥信息编进**每一个像素的数值**里。图片被压缩一次，像素值就被重算一遍，编进去的数据可能跟着丢失 —— 于是对方按正确密钥解，也只能得到乱码，甚至直接解不出来。

这跟普通照片压缩后只是「糊一点」完全不同：普通图压缩损失的是观感，加密图压缩损失的是**能不能解开**。

会动你像素的常见操作：

| 操作 | 是否危险 |
| --- | --- |
| 聊天软件直接发送（不勾原图） | 危险，几乎必然被压缩 |
| 发朋友圈 / 微博等社交平台 | 危险，平台会重新编码 |
| 对着屏幕截图 | 危险，等于二次成像 |
| 从聊天记录里「保存图片」再转发 | 危险，保存下来的可能已是压缩版 |
| 网盘原文件分享 / 蓝牙 / 文件传输助手发原文件 | 安全，字节不变 |

## 二、按顺序排查

1. **确认发过去的那张是不是原图。** 让你自己重发一次并勾选「原图」；或者干脆走网盘分享文件、文件传输方式，绕开图片压缩通道。
2. **确认密钥逐位一致。** 最省事的办法是你直接把那串小数发给对方（换一个私密渠道），让他复制粘贴而不是手打 —— 手打最容易错的就是小数点后那位。
3. **确认对方装的是能解的版本。** 对方需要装 PicEncrypt 才能还原，没装的话先看他从哪拿安装包，见[下载与安装教程.md](下载与安装教程.md)。
4. **确认你加密时的设置。** 压缩系数、处理模式若在你这边选过非默认值，解的时候要用同样的设置。
5. **确认图没被中途处理过。** 只要有人裁剪、加滤镜、二次保存过，数据就变了，这时只能由你这边重新加密一张原图发过去。

## 三、发图的正确姿势

你这边重新加密一张，然后：

1. 加密完成后**先别发**，自己在 PicEncrypt 里解一遍，确认能还原。
2. 用聊天软件发送时**勾选原图**；对方收的时候也要从原图入口保存，不要在预览里截图。
3. 更稳的方式是把加密图当成普通文件发 —— 网盘分享、邮件附件、文件传输，字节不动，对方拿到的就是你生成的那一份。
4. 图发出去后，**密钥用另一条渠道告诉对方**（别把密钥写在同一张图里，也别写在同一条消息里紧接着发）。

## 四、解出来发白、偏色、花屏

这跟「打不开」是同一类问题的不同表现。应用自身的更新说明里记过一条修复记录：**图片解密后变色**，处理办法同样是「网络传输必须原图发送，原图下载后再解密」。也就是说：

- 对方反馈**颜色不对、发白、发紫** → 先按原图重发一遍，别急着怀疑密钥；
- 已经装了修复该问题的版本仍偏色 → 大概率还是拿到手的那张图被转码过，回到第三节重发；
- 你这边解出来正常、对方不正常 → 差异几乎总在「他拿到的那份」和「你生成的那份」不是同一个文件。

## 五、还是打不开的两种情况

- **对方解出来是乱码**：几乎可以断定图片被压缩过。回到第三节重新发一次原图，不要在原文件上反复折腾。
- **对方界面直接报错或选不了图**：检查他装的包是否完整、版本是否对得上（包名 `com.android.picencrypt`），以及 PicEncrypt 自身是否在闪退，见[忘记密钥或闪退怎么办.md](忘记密钥或闪退怎么办.md)。

如果对方只是想**看**内容而你并不需要强加密，也可以直接发原图 —— 加密图的价值在于「没有密钥看不懂」，对不需要这层保护的场景，多一道手续反而添乱。
