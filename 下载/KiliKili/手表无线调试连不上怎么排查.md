# KiliKili 手表无线调试连不上怎么排查

> 用 ADB 给手表装包时，「配对」和「连接」是两段不同的事、用的是不同端口；这篇按官方流程理一遍，再逐条对上常见报错。

## 一、先确认走的是官方那套流程

Wear OS 的无线调试分两步走，**顺序不能颠倒，而且两步用的不是同一个端口**。

**第一步：手表上开调试。** 启用开发者选项，然后进入「开发者选项」，打开 **ADB 调试**，再打开 **无线调试**；弹出的询问里选「允许」或「始终允许在此网络上」。

**第二步：与新设备配对**（同一台电脑只需做一次）。手表上进入「设置 → 开发者选项 → 无线调试 → 与新设备配对」，手表会显示一组 **WLAN 配对码、IP 地址、配对端口**。在电脑上执行：

```bash
adb pair 192.168.1.23:37821     # 换成手表上显示的 IP 与配对端口
```

提示时输入手表上那串配对码，出现配对成功的提示即完成。

**第三步：连接**（每次重启无线调试或换 Wi-Fi 都要重做）。回到「无线调试」这一页（注意不是「与新设备配对」那一页），记下这里的 **IP 地址与连接端口** —— 连接端口通常与配对端口不同：

```bash
adb connect 192.168.1.23:5555   # 换成「无线调试」页显示的连接端口
adb devices                     # 列表里出现手表即连接成功
```

两个前提缺一不可：**电脑与手表在同一个 Wi-Fi 网络**；**电脑上的 `adb` 版本不低于 30.0.0**（版本太低会不认 `pair` 这个子命令）。

## 二、按现象对号入座

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示 `pair` 不是有效命令 | `adb` 版本太低 | 更新电脑上的 platform-tools |
| 配对提示失败 / 配对码无效 | 配对码或端口抄错，或手表上的配对页已经超时关闭 | 手表上重新打开「与新设备配对」，重新抄一遍码与端口 |
| `cannot connect to 192.168.x.x:xxxxx` | 把**配对端口**当成连接端口用了 | 回到「无线调试」页取连接端口再 connect |
| `adb devices` 显示 `offline` | 手表侧还没允许，或连接中断 | 手表上重新选「允许」；电脑上 `adb kill-server` 后 `adb start-server`，再 connect |
| `adb devices` 里根本没有手表 | 两台设备不在同一网络，或网络不允许设备互访 | 见第三节 |
| 昨天能连、今天连不上 | 无线调试重启或换了 Wi-Fi，端口变了 | 重新读一遍连接端口再 connect |

官方给的排查顺序就是这三步：检查两台设备是否在同一网络且允许对等流量 → 在电脑上运行 `adb kill-server` 与 `adb start-server` 后重连 → 在手表上关闭无线调试再重新打开。

## 三、同一 Wi-Fi 不等于能互通

这是最容易白折腾的一层：**很多企业、酒店、公共 Wi-Fi 开了接入点隔离**，同一网络下的设备之间也互相看不到，此时 `adb connect` 一定失败。

- 换成手机开热点，**电脑和手表都连这个热点**，再按第一节的流程走一遍；
- 家里路由器如果开了「访客网络」「AP 隔离」「客户端隔离」之类的开关，先关掉再试，或者同样改用热点；
- 排查阶段别让手表走手机蓝牙共享的网络，无线调试要的是两台设备处在同一个 IP 网络里。

## 四、连上了但装不上包

`adb devices` 里能看到手表，说明调试链路已经通了，之后的失败都归安装环节 —— 报错码、架构、系统版本、签名、空间这几类，逐条对照 [手表上装不上怎么排查.md](手表上装不上怎么排查.md)。

## 五、两个收尾习惯

- **配对只需要一次，连接不是**：手表重启无线调试或换了 Wi-Fi 之后，都要重新 `adb connect`；
- **装完把调试关掉**：无线调试开着，等于对同网络开放了一个可安装应用的入口；装完就回开发者选项里关掉 ADB 调试与无线调试，也更省电。
