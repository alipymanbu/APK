## 一、同一个应用，会被用不同的名字收录

- 这份文档与网盘资源里用的名字是 **KiliKili**；
- 项目在代码仓库里叫 **BiliZepam**（仓库名 BiliZepam-Compose）；
- 部分下载站还会用「哔哩终端」之类的说法，那其实是它所在的那条开源项目支线的名字。

所以名字不能当判据：图标可以换、名字可以改，**包名不能改**。判断是不是同一个应用，一律看包名。

## 二、判据一：包名

这份包的包名是：

```
com.huanli233.bilizepam.compose
```

已经装上过的话，可以直接查：

```bash
adb shell pm list packages | findstr bilizepam
```

包名对不上就是另一个应用，本文档里的步骤、界面描述、版本号都不通用。

## 三、判据二：版本号格式

版本号形如 `0.3.2`，完整形式会再带一段 8 位提交号，例如 `0.3.2+7189720`：

- 前面三段跟着版本发布的节奏走，第三段变化才代表功能上有改动；
- 后面的提交号是构建时自动附上的，同一个 `0.3.2` 配不同的提交号，是同一次版本发布的不同构建；
- 手表上想确认，可以看应用设置里的关于页，也可以用下面这条命令：

```bash
adb shell dumpsys package com.huanli233.bilizepam.compose | findstr versionName
```

## 四、判据三：文件的 MD5

网盘里这份 0.3.2 的事实是：大小 18.96 MB（19,885,627 字节），MD5 为 `BD559E6837E616CE7A5022F70622417B`。

在电脑上算一遍手上的文件：

```powershell
certutil -hashfile "KiliKili_v0.3.2.apk" MD5
```

- 与上面对得上 → 和本文档描述的是同一份包；
- 对不上 → 要么版本不同，要么文件没下完整，后者按 [手表上装不上怎么排查.md](手表上装不上怎么排查.md) 第四节处理。

## 五、项目本身在哪儿

- 上游开源项目在 GitHub：[Re-BiliTerminal/BiliZepam-Compose](https://github.com/Re-BiliTerminal/BiliZepam-Compose)；
- 它是从一个更早的手表端 B 站开源项目重写而来的版本，界面框架换成了 Jetpack Compose；
- 更新说明、发布记录与问题反馈都以这个仓库的 Releases 与 Issues 为准，遇到问题先在那里搜一遍，多数能被别人踩过的坑能直接找到答案；
- 项目采用 GPL-3.0 开源许可，安装包从项目仓库或本文档给的入口获取，不涉及付费渠道；能看到哪些内容，仍然只取决于你自己的 B 站账号权限。

## 六、遇到同名不同包时怎么办

1. **先比包名**：不同 → 是两个应用，别照着这篇文档操作；
2. **再比版本号与大小**：包名相同但版本差得远，界面和设置项可能完全不同，本文档只对 0.3.2 这一版负责；
3. **拿不准就换一份包**：从文档对应的 **KiliKili 安装文件资源（夸克网盘）**：[https://pan.quark.cn/s/37157b70cd7b](https://pan.quark.cn/s/37157b70cd7b) 重新获取，拿到手再按第四节的 MD5 核对一次；
4. **装过来源不明的包之后**：如果已经在上面登录过账号，先退出登录，再按 [登录与账号同步.md](登录与账号同步.md) 第五节的思路评估一下。
