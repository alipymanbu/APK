## 一、两种用法：本地账户与云端账户

Read You 支持多账户，一个应用里可以并存两类账户：

- **本地账户**：订阅源与文章存在手机本地，加源、已读、星标都只在这台设备上。不依赖任何服务端，装完就能用（默认就是这种）。
- **云端账户**：接入一个 RSS 服务端，订阅与已读状态存在服务端；换设备登录同一个账户，数据跟着走。

两类账户可以同时添加、随时切换，平时「这台手机本地看、平板连服务端看」这类混用没有冲突。

## 二、官方支持接入的第三方服务

官方 README 列出的兼容服务 API 有：Fever、Google Reader、FreshRSS、Miniflux、Tiny Tiny RSS、Inoreader、Feedly、Feedbin。

| 服务 | 什么情况下你会用到它 |
| --- | --- |
| FreshRSS | 自建或使用公共实例的 RSS 服务端，自己有服务器 / NAS 的常见选择 |
| Google Reader | 老 Google Reader 的兼容 API 协议，不少自建或第三方服务端提供这个兼容接口 |
| Fever | 另一个常见的兼容 API 协议，部分自建服务端提供 |
| Miniflux | 自托管 RSS 服务端，适合自己部署的人 |
| Tiny Tiny RSS | 老牌自托管 RSS 服务端 |
| Inoreader / Feedly / Feedbin | 商业在线 RSS 服务，已有账号就能直接接 |

上面这份是官方 README 列出的兼容目标；你手上的版本实际能添加哪几类，以「添加账户」时给出的选项为准（公开评测里实测过的版本，添加对话框提供「本地」与「FreshRSS」两类）。

怎么选：

- 只在一台安卓机上看 → 本地账户就够，不用配任何服务端；
- 已经有 Inoreader / Feedly / Feedbin 账号 → 直接接现成服务；
- 自己有服务器或 NAS、想让数据在自己手里 → 部署 FreshRSS / Miniflux / Tiny Tiny RSS 之一后接入；
- 想多台设备同步又不想自己部署 → 用 Inoreader / Feedly / Feedbin 这类托管服务，或找可注册的公共 FreshRSS 实例。

## 三、添加云端账户的通用步骤

入口：设置 → 账户 → 「添加账户」，选服务类型、填地址与凭据。账户列表里点账户名可以切换当前使用哪个账户（默认的本地账户叫「Read You」）。

以资料最多的 FreshRSS 为例，要准备三样东西：

1. 服务端地址：部署实例或公共实例给你的根地址；
2. 用户名；
3. API 密码 —— FreshRSS 要求先在其网页端的用户设置里启用 API 访问并生成 API 密码，客户端填这个，不是网页登录密码（细节以 FreshRSS 官方文档为准）。

添加失败多半出在地址与凭据上：地址不要自己多拼路径，API 密码与登录密码别混用；逐项核对仍失败时翻 [常见问题排查](常见问题排查.md)。同步节奏与通知的配置见 [同步频率与文章通知](同步频率与文章通知.md)。

## 四、本地与云端怎么共存

- 云端账户接进来后，本地账户的订阅不会被合并，两套数据互不影响；
- 长期只用云端账户的话，本地账户可以一个源都不加，留着当备用；
- 想把订阅从本地搬到云端：先在本地导出 OPML，再到服务端网页端导入（多数 RSS 服务端支持），或直接在云端账户下重新加源。
