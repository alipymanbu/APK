## 一、判断能不能用，只看一条：作用域里有没有「系统框架」

FPA 是免 Root 方案，它只能作用于**你打包进去的那个应用自己**，碰不到系统进程。所以：

| 模块类型 | 例子 | 能不能用 |
| --- | --- | --- |
| 作用域是单个应用的 | 微X、哔哩漫游、知了、蚂蚁森林 | 可以 |
| 作用域包含「系统框架」的 | 各类系统级模块 | **不行**，免 Root 框架一律加载不了 |

装模块之前，先在模块说明里看它的作用域 —— 写着「系统框架 / System Framework」的，直接放弃，别浪费时间试。

## 二、已知可用与需要自测

公开资料里明确提到**实测可用**的只有少数几个：**FunBox**、**QAuxiliary**（QQ 相关模块）。其它模块一律「自测为准」—— 没人替你验过，你也别信任何「全兼容」的说法。

原因很直接：FPA 只实现了 Xposed Hook API 的一部分，不是完整实现。模块调用了它没实现的接口，就会走到异常分支 —— 表现为功能不生效、或者直接闪退。具体症状对照见 [注入后不生效怎么排查.md](注入后不生效怎么排查.md)。

**验证一个模块能不能用的步骤**：

1. 先只打包这一个模块，别一次挂好几个 —— 出问题才知道是谁的锅。
2. 装上后打开目标应用，看模块的功能入口在不在。
3. 入口在但功能不动作，属「部分生效」，多半是 API 没实现到，换模块版本或放弃。
4. 一打开就闪退，按签名 / 兼容性问题排查，别连续重试装同一个包。

## 三、系统要求：公开说法互相矛盾，别只信一个

关于 FPA 到底支持到哪个安卓版本，公开页面上能看到四种说法：

| 说法 | 出处类型 |
| --- | --- |
| 安卓 5.2 以上 | 本地这份 0.3 版安装包的标注 |
| 安卓 5.0 ～ 12.0 | 下载站的参数栏 |
| **仅支持安卓 10 以上** | 社区实测帖（基于 LSPlant / Pine 的那套） |
| 安卓 12 以上、解决安卓 15+ 失效问题 | 各下载站的功能介绍 |

两边并列给你：**老版本（0.3）按「安卓 5.2 以上」装**，实际能不能跑以装上后是否闪退为准；**新版本（3.x）按社区口径更接近「安卓 10 起」**，主打的正是安卓 12 / 15 以上旧框架跑不动的机型。以你手机上实测为准 —— 装上能开、能完成一次 patch，就说明这条路走得通。

## 四、CPU 架构

FPA 支持 **armeabi-v7a 与 arm64-v8a** 两种架构，覆盖绝大多数安卓手机。近几年的机型都是 arm64-v8a，不用特意挑；只有很老的 32 位机器需要确认安装包架构与系统一致，不一致的表现是安装时就报错或一打开即退。

## 五、别一次挂太多模块

模块之间可能互相打架，挂得越多越难定位问题，也越吃目标应用的运行开销。合理做法是：**一个应用先挂一个模块，跑稳了再加下一个**；不用的模块从打包配置里去掉重新打包，而不是留着关掉。
