# FPA 和 LSPatch 有什么区别

> 这篇对比两款免 Root Xposed 加载器的出身、系统要求与操作差异，帮你决定先试哪个。

## 一、两者解决的是同一个问题

你的手机没 Root，Xposed 模块装上却不起作用。LSPatch 与 FPA 都用同一条思路解决它：**把框架代码打进目标应用的安装包、重新签名，让模块跟着这个应用跑**。所以两者都会改变原签名，都要卸载原包再装，都会让支付 / 登录 / 分享这类依赖签名的功能受影响 —— 这些是方案本身的代价，不是哪家的缺陷。

区别在出身、维护状态和底层实现。

## 二、一张表看差异

| 对比项 | FPA | LSPatch |
| --- | --- | --- |
| 出身 | 独立项目，FunBox 作者开发 | LSPosed 团队出品（LSPosed 的免 Root 分支） |
| 底层 | 基于 LSPlant + Pine | 基于 LSPosed 那套实现，从 Xpatch 演化 |
| 维护状态 | **在更新**（公开页面版本已到 3.x，2026 年仍见新版） | 开发者已停止更新维护（公开资料口径） |
| 最低系统 | 说法不一，社区实测口径偏「安卓 10 起」 | 安卓 9 起（官方 README 口径） |
| 高版本安卓（12 / 15+） | 主打场景，宣传点就是旧框架在这些机型上失效 | 官方停更后，高版本机型问题较多 |
| Xposed API | 只实现一部分，模块需自测 | 兼容面更广，多数 LSPosed 可用模块能跑 |
| 作用域来源 | ContentProvider 读取，支持 Shizuku 提供作用域 | 手动 / 管理器里配置 |
| 操作入口 | 首页加号（动态加载）+ 钥匙图标（自定义打包签名） | 管理器里选应用与模块后打包 |
| 协议 | Apache 2.0 开源 | 开源 |

表里的系统要求与版本号会随时间变化，**以两边当时的页面为准**（截至 2026-09 的公开资料）。

## 三、怎么选

- **手机是安卓 12 / 15 以上、LSPatch 装上就跑不动** → 先试 FPA，它正是为这类机型出现的。
- **手机在安卓 9 ～ 11、要挂的模块兼容性要求高** → LSPatch 的成熟度更占优，API 覆盖更全。
- **两边都不行** → 多半是目标应用的签名校验太强，见 [注入后不生效怎么排查.md](注入后不生效怎么排查.md) 第二节，这跟选哪个加载器无关。
- 两者**不冲突**，可以都装着，按应用逐个试；但同一个应用一次只用一个方案打包，别套娃。

## 四、共同的底线

无论选哪个，这两条都成立：

1. **作用域含「系统框架」的模块一律用不了** —— 免 Root 方案碰不到系统进程，详见 [支持哪些Xposed模块.md](支持哪些Xposed模块.md)。
2. **打包 = 换签名 = 卸载原包重装**，数据该备份就先备份，规则见 [下载与安装教程.md](下载与安装教程.md) 第五节。

所以选型其实很简单：先按系统版本挑一个，装上拿一个模块实测一次，能跑就用它，不能换另一个 —— 比对着参数表纠结快得多。
