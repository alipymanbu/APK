# FPA 注入后不生效怎么排查

> 这篇按「装不上 → 打开闪退 → 功能不生效」的顺序，把 FPA 最常见的三类故障逐条对号入座。

## 一、装不上：提示签名不匹配 / 应用冲突

**原因**：打包后的 APK 换了签名，系统不允许用新签名覆盖安装原应用。

**解法**：卸载原应用 → 再安装打包后的版本。这一步没有任何绕开的办法，看到冲突提示先卸载，别反复点安装。

**代价提前知道**：卸载会清掉那个应用的本地数据。微信、QQ 这类先备份，别等卸载完才想起来。

## 二、一打开就闪退 / 无法加载

按出现频率排序：

| 现象 | 原因 | 怎么处理 |
| --- | --- | --- |
| 打开目标应用立刻闪退 | 该应用有**较完善的签名校验**，FPA 只实现了简单的过签名验证，挡不住 | 换校验弱的应用试，或放弃这个应用（没有通用解法） |
| 提示「请求参数不合法」或直接拒绝服务 | 应用检测到自身签名变了就**主动拒绝工作**，闪退与报错是同一件事的两种表现 | 同上，属该校验的正常反应 |
| 银行类、支付类应用装上就用不了 | 这类应用对签名校验最严，检测到变化会阻止修改后的版本运行 | 没有通用解法，日常别用它们的修改版 |
| 闪退、模块加载不出来 | 模块与当前 FPA **版本不匹配** | 换一个版本的 FPA 或模块再试，两边版本要凑对 |
| 部分功能异常后崩溃 | 重新打包后**唤醒支付、登录、分享**依赖原签名而失效 | 属正常现象，不是故障；用不了的功能绕开 |
| 修好的包装上后行为怪异 | 修补过程中**模块里的注入逻辑本身有错** | 见下节「勾选注入 MT 管理器」 |

## 三、装上了但模块功能没反应

公开资料给出的原因清单（几处来源一致），逐条对照：

1. **加载顺序问题** —— 注入模块执行的时机在目标逻辑之前或之后，没挂钩上；
2. **依赖没配好** —— 缺少模块需要的依赖项，或版本不兼容；
3. **权限不足** —— 运行环境没有模块执行所需的权限；
4. **路径配置错误** —— 模块路径、配置文件路径写错了；
5. **框架版本不匹配** —— 模块与你装的 FPA 版本对不上；
6. **模块自身注入逻辑有错** —— 模块代码里的问题。

**对应的两个通用解法**：

- **换自定义打包签名**：动态加载不生效时，回首页点钥匙图标，像以前用 LSPatch 那样把应用和模块手动加进来打包（步骤见 [下载与安装教程.md](下载与安装教程.md) 第四节）。手动指定模块，往往就绕开了加载顺序与依赖的问题。
- **勾选注入 MT 管理器**：动态加载时有这个选项 —— 勾上之后出问题能打开 MT 管理器，手动进包里看模块代码哪里错了。只在你确实会看代码时有用，普通用户跳过。
- **换个 patch 模式**：公开资料提到 patch 配置里可以切**普通模式 / 增强模式**，微信、支付宝这类应用「注入后唤不起支付」与它们的异步通信方式有关，换模式、并保证 FPA 是较新的版本（有资料点名 2.1 以上）再试一次。你手上的版本有没有这个选项，以界面实际显示为准。
- **作用域这一环单独查**：动态加载靠 Shizuku 提供作用域，服务没启动 = 模块没挂上。先看 [用Shizuku提供作用域怎么配置.md](用Shizuku提供作用域怎么配置.md) 第六节 —— 重启后服务停了是最常见的原因。

## 四、排查顺序（别跳步）

1. **先确认作用域**：模块作用域含「系统框架」的，免 Root 下必然不生效，标准见 [支持哪些Xposed模块.md](支持哪些Xposed模块.md) 第一节 —— 这条占了「不生效」的大头。作用域不含系统框架的，再看 Shizuku 服务是否在运行（[用Shizuku提供作用域怎么配置.md](用Shizuku提供作用域怎么配置.md)）。
2. **再确认只挂了这一个模块**：一次只测一个，多模块混挂分不清是谁的问题。
3. **再换打包方式**：动态加载 → 自定义打包签名。
4. **最后才怀疑版本**：FPA 版本与模块版本都换一轮。

每换一个变量就完整跑一遍，别一次改三样 —— 否则好了也不知道是哪个改动起的作用。

## 五、确认没救了就别死磕

如果某个应用无论换哪种打包方式、哪个版本都闪退，通常是它的签名校验或加固强度超出了 FPA 的处理范围 —— 换个目标应用，或者回到 [和LSPatch有什么区别.md](和LSPatch有什么区别.md) 里另一个方案试试。工具之间没有谁全面更好，只有「这个应用吃哪套」。
