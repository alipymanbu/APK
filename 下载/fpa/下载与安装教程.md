## 一、FPA 是什么

FPA 是一个**免 Root 的 Xposed 模块加载器**：它不需要你解锁、刷机、拿最高权限，而是把框架代码直接打进目标应用的安装包里，让模块跟着那个应用一起跑。你平时在别处下载的 Xposed 模块（微X、哔哩漫游、蚂蚁森林这类），装到手机上是没法自己生效的，得靠 FPA 这类加载器把它们挂进具体应用。

它的技术底子是 LSPlant 与 Pine，只实现了 Xposed Hook API 的一部分（详见 [和LSPatch有什么区别.md](和LSPatch有什么区别.md)），按 Apache 2.0 协议开源。

## 二、拿安装包

1. 打开 [FPA 安装文件资源（夸克网盘）](https://pan.quark.cn/s/160e2071b48d)，把 `fpa_v0.3.apk` 转存到你自己的网盘再下载到手机。
2. 下完可以核对一下 MD5 是否为 `DDA181537E9350C10284C785FE5798A0`（用任意校验工具），一致说明文件没损坏。
3. 手机上点开安装。若提示「已安装同名应用」且版本不同，先卸载旧版再装 —— FPA 本身是个工具容器，卸掉不影响你已经打包好的应用。

安装 FPA 本身不需要 Root，也不需要给它什么特殊权限。**真正要 Root 的场景它一个都没有**，这正是它存在的理由。

## 三、第一条路：动态加载（推荐先用这个）

动态加载是「选一个已安装的应用 → 让 FPA 把模块注入进去 → 装回手机」，不用你自己管签名。步骤：

1. 打开 FPA，点**右下角的加号**。
2. 在列表里选你要注入模块的应用，也可以直接选一个 APK 文件。
3. 进设置页，选项看不懂就**全部保持默认**，点右下角的 **patch**。
4. 等它执行完，点**安装**。
5. 安装时如果弹出「与原应用冲突 / 签名不同」，**先卸载原应用再装** —— 直接覆盖安装必然失败，因为打包后的签名已经不是原包的了。
6. 装完打开那个应用，模块功能应该就在了；没生效按 [注入后不生效怎么排查.md](注入后不生效怎么排查.md) 逐条对。

动态加载模式下，框架会通过 Shizuku 之类的方式拿作用域、并用 ContentProvider 读取作用域配置，所以**首次使用时留意它弹出的授权提示**，点了允许才走得通。

## 四、第二条路：自定义打包签名

如果你不需要动态加载，或者动态加载对某个应用不生效，就走这条路 —— 操作方式和以前用 LSPatch 差不多：

1. 回到 FPA 首页，点**钥匙图标**，进入「自定义打包签名」界面。
2. 点右下角的**添加**图标，把要注入的应用和要用的模块都选进来。
3. 执行打包，完成后安装（同样要先卸载原包）。

打包完成的 APK 默认会保存到手机的 **Download 目录**，方便你留底或换机时重装。两条路的最终结果一样：你得到一个「原应用 + 模块」的新安装包。

## 五、装完之后要注意的三件事

- **原应用的数据别弄丢**：签名变了就无法覆盖安装，卸载原包再装 = 那个应用的本地数据会被清掉。微信、QQ 这类先在应用内把聊天记录、登录状态的备份做好。
- **部分功能会失灵**：重新打包后，唤醒支付、第三方登录、分享这类依赖原签名的功能可能用不了，这是签名变化导致的正常现象，不是你操作错了。
- **模块要一个个试**：FPA 只实现了部分 Xposed API，模块能不能跑要实测，判断标准见 [支持哪些Xposed模块.md](支持哪些Xposed模块.md)。
