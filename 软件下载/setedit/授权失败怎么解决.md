# SetEdit 授权失败怎么解决

> 敲 `pm grant` 授权命令时报 SecurityException、或授权了 SECURE 表还是改不了——本篇按报错类型给出对应解法。
> **相关文档**：[下载与安装教程.md](下载与安装教程.md) · [改坏了怎么恢复.md](改坏了怎么恢复.md)

## 一、先看清报的是哪种错

授权命令本身很简单（命令全文见 [下载与安装教程.md](下载与安装教程.md) 第五节），失败时的报错基本是两种，对应两条完全不同的排查路线：

| 报错关键词 | 含义 | 跳到 |
| --- | --- | --- |
| `Neither user 2000 nor current process has android.permission.GRANT_RUNTIME_PERMISSIONS` | 设备拒绝 ADB 授权这个动作 | 第二节 |
| 执行成功但应用里还是提示无权限 | 授权到了，应用没接住 | 第三节 |

第一种错在国产系统上尤其常见——厂商在开发者选项里加了一道锁，默认不允许 ADB 授予运行时权限。

## 二、设备拒绝授权：先开开发者选项里的「第二道开关」

社区与多个工具类应用的官方文档给出了一致的解法：很多定制系统需要先打开一个额外的调试开关，重启后再执行授权命令。开关名称因品牌而异：

| 品牌 | 开关名称（开发者选项里找） |
| --- | --- |
| 一加 / OPPO / realme | 禁止权限监控（Disable Permission Monitoring） |
| 小米 / POCO / 红米 | USB 调试（安全设置） |
| 其他设备 | 找名字带「权限监控」「安全设置」的调试类选项 |

操作顺序：打开对应开关（弹警告框就确认）→ 重启手机 → 重新连电脑确认 `adb devices` 能看到设备 → 再跑一次授权命令。

开了开关还是不行的话，再补一步：把 SetEdit 彻底停掉再授权，有些设备不允许对正在运行的应用授予这种权限：

```shell
adb shell am force-stop io.github.muntashirakon.setedit
adb shell pm grant io.github.muntashirakon.setedit android.permission.WRITE_SECURE_SETTINGS
```

## 三、授权成功但应用里还是改不了

按这三条核对：

1. **关掉重开应用再确认**。授权完成后从最近任务里划掉 SetEdit 再重新打开，重新进一次 SECURE 或 GLOBAL 表看能不能改——应用界面上的权限提示不一定实时刷新，以实际能不能编辑为准；
2. **应用装在分身或副用户里吗**。ADB 默认只对主用户生效，装在副空间/工作资料里要先查用户号再带上参数：
   ```shell
   adb shell pm list users
   adb shell pm grant --user 10 io.github.muntashirakon.setedit android.permission.WRITE_SECURE_SETTINGS
   ```
   （`10` 换成上一条命令列出的目标用户 ID。）
3. **应用重装过吗**。这类授权跟着应用安装记录走，卸载重装后授权会被撤销，需要重新执行一遍 `pm grant` 命令——所以授完权建议顺手验证一次能不能改，别等到要用时才发现。

## 四、有 root 就不用折腾上面这些

root 设备在 root shell 里一条命令解决，绕开所有开发者选项限制：

```shell
su -c 'pm grant io.github.muntashirakon.setedit android.permission.WRITE_SECURE_SETTINGS'
```

而且 3.0 版的 SetEdit 会尝试自动用 root 授权（说明见 [下载与安装教程.md](下载与安装教程.md) 第六节），root 用户通常连这条命令都不用敲。

## 五、什么情况下可以不授权

只有查看需求的话，授权失败可以直接无视——浏览 SYSTEM、SECURE、GLOBAL 三张表的内容不依赖这个权限，只有改 SECURE 和 GLOBAL 才需要。确认自己用不上再回来折腾也不迟。
