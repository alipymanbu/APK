# SetEdit 改坏了怎么恢复

> 改完没反应、重启后被重置、改错值导致异常——本篇按症状给出排查顺序和回退方法，包括 ADB 命令兜底。

## 一、先说底线：原值是唯一的保险

SetEdit 直接改的是系统设置数据库，改错轻则某项功能失灵，重则界面异常。官方说明里也写得很直白：不保证误用造成的问题可以修复。所以每次改值之前，把原值记录下来（截图、拍照、记备忘录都行），是唯一可靠的保险——后面所有恢复方法的前提都是「你知道原来的值是什么」。

如果还没养成记录的习惯，先回 [怎么用.md](怎么用.md) 第三节补上这一步。

## 二、症状一：改了没生效

按顺序排查三件事：

1. **改的表对不对**。同名键可能同时存在于 SYSTEM 和 GLOBAL 两张表，值各管各的。回到应用顶部确认当前表名，必要时两张表里的同名键都改；
2. **要不要重启**。不少键值改完不会立即生效，重启手机或重新进入相关界面后才起作用。改完没动静，先重启一次再判断；
3. **键名对不对**。自己新建的键如果拼错（多字母、少下划线），系统不认识，等于没建。对照来源里的键名逐字符核对。

三条都确认过还是没反应，说明这个键在你这台设备的系统里不生效——键名集合因设备而异，别人的设备有效不代表你的也有效，正常，换键或放弃即可。

## 三、症状二：重启后被重置

部分机型会在开机时把某些键写回系统默认值，典型反馈是一加设备上的 `peak_refresh_rate`，重启后自动回到原值。应对办法：

- 重启后重新进 SetEdit 改一次（麻烦但有效）；
- 用 3.0 版新增的「重启后修改设置」选项，让应用在你重启后自动把值再写一遍，专治这类键（入口说明见 [怎么用.md](怎么用.md) 第六节）。

这不是你改坏了，是系统在跟你抢这个键，两种办法选一种即可。

## 四、症状三：改错值，要回退

### 1. 手机能正常操作时

在 SetEdit 里找到那条键，把值改回记录的原值，保存，重启。你自己新建的键直接删掉即可，系统原有的键优先改值、不要删。

### 2. 手机已经异常到用不了 SetEdit 时

连电脑用 ADB 兜底，三条命令覆盖查、改、删：

```shell
# 查看某个键的当前值（table 取 system / secure / global 之一）
adb shell settings get system peak_refresh_rate

# 把键改回原值
adb shell settings put system peak_refresh_rate 120

# 删掉自己误建的键
adb shell settings delete system 误建的键名
```

命令里 `system` 换成那条键实际所在的表，`peak_refresh_rate` 换成键名，最后的值换成你记录的原值。ADB 连不上的话，先确认手机开了 USB 调试（步骤见 [下载与安装教程.md](下载与安装教程.md) 第四节）。

## 五、两个常见误解

- **卸载 SetEdit 能恢复原状吗**——不能。它只是个编辑器，改动写进了系统数据库，卸载应用不会撤销改动，还是要按上面的方法改回原值；
- **恢复出厂设置之外还有别的全面回滚吗**——没有。SetEdit 改的是逐条键值，系统没有「一键撤销所有改动」的入口，这正是第一节强调记录原值的原因。
