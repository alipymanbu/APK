## 一、把数据存成 CSV 文件

传输协议选 `File`，开跑后数据不走网络，直接写进手机本地的 `.csv` 文件，保存位置固定在：

```text
{存储根目录}/Documents/HyperIMU.ianovir/Exports/
```

采完不必连电脑翻目录——抽屉菜单的 **Acquisitions（采集文件）**里可以浏览、管理这些文件，也能直接打开看内容。要把文件弄到电脑上分析，用任意文件管理器进上面的目录复制出来即可；文件到了电脑上怎么读、怎么画图，见[用Python和R读取传感器数据.md](用Python和R读取传感器数据.md)。

## 二、CSV 数据包的字段顺序

CSV 格式下所有数值用逗号分隔，每个传感器固定占三个位置（X、Y、Z 顺序），一行就是一条数据包。官方给出的字段排列：

```text
Timestamp, Accelerometer.x, Accelerometer.y, Accelerometer.z,
Gyroscope.x, Gyroscope.y, Gyroscope.z, Magnetometer.x, Magnetometer.y, Magnetometer.z,
..., GPS.lat, GPS.long, GPS.alt
```

实际顺序以你勾选的传感器为准，开跑前用 Packet Preview 对照一遍最保险（见[传感器选择与采样率设置.md](传感器选择与采样率设置.md)）。读包时按三个一组切分；开了包头附加项的话，时间戳、MAC、电量排在最前面，GPS 与 NMEA 排在最后面。

## 三、JSON 数据包（仅 TCP）

JSON 格式只走 TCP，每个传感器是带名字的数组，不用自己数第几组：

```json
{
  "op": "hyperimu",
  "Timestamp": 1518819953744,
  "Accelerometer": [0.09279, 0.148016, 9.7345703],
  "Gyroscope": [0.00313534, -0.014384, 0.0085291134],
  "Magnetometer": [-14.25, -1, -39.125],
  "Orientation": [92.046875, -0.3125, 0.5625],
  "GPS": [0, 0, 0]
}
```

## 四、坐标轴怎么理解

轴类传感器的数值遵循安卓标准坐标系：手机竖屏正常握持时，X 向右、Y 指向屏幕上方、Z 垂直屏幕朝外，屏幕背面方向为负 Z。适用这套坐标的传感器：加速度计、重力、陀螺仪、线性加速度、地磁。你写算法或画曲线时按这个方向理解正负号；如果发现「方向反了」，多半是手机的实际摆放和你预设的朝向不一样，不是数据错了。

## 五、解析时容易踩的几个点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| NMEA 段里出现分号 | 正常设计：NMEA 语句按三条一组放包尾，语句内部用分号分隔，避免和主 CSV 的逗号混淆 | 先按逗号切主包，再单独解析包尾的 NMEA 段 |
| 每条包切不开、黏在一起 | 电脑端切包符与手机端 `# Terminator` 开关不一致 | 两边统一：要么按换行切，要么按 `#` 切 |
| 第一条包是文字不是数字 | 开了 Prequel Packet，首包发的是传感器名称 | 跳过首包，或留着做字段对照 |
| GPS 一直是 0 0 0 | 没给定位权限，或室内搜不到星 | 检查权限，换到窗边或室外再试 |
| 数值怎么都对不上 | 包头/包尾附加项开了但解析没留位置，或传感器勾选后来改过 | 用 Packet Preview 看当前实际字段顺序，再对着改解析代码 |

推流链路上收不到数据的情形不在这篇范围内，见[连接不上与收不到数据的解决办法.md](连接不上与收不到数据的解决办法.md)；要电脑实时收包而不是存文件，看[数据推流到电脑的连接设置.md](数据推流到电脑的连接设置.md)。
