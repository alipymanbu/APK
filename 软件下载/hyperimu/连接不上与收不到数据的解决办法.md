# HyperIMU 连接不上与收不到数据的解决办法

> 本篇是排错清单：手机上转轮明明在转、电脑端却什么都没收到，或者图表不动、数据中断，按这里的顺序逐项查。

## 一、先查手机端这四项

按出现频率排序：

1. **协议还是 `None`**：默认就是不发送、只采样。去 Settings 把协议改成 UDP/TCP/JSON 之一再开跑，这是新装机后最常见的「假故障」；
2. **IP 填错**：要填电脑当前的局域网 IP，不是 `127.0.0.1`、也不是路由器地址。电脑 IP 会变（DHCP 重新分配），隔天连不上先重新 `ipconfig` 看一眼；
3. **不在同一个网络**：手机连着移动流量、或连了访客 Wi-Fi，和电脑不在一个网段，怎么发都收不到。两边必须同一局域网；
4. **端口不一致**：手机填的端口与电脑端监听的端口必须完全一致，两边逐字核对。

## 二、再查电脑端这三项

1. **收包程序没在跑**：先启动服务端，再点手机端转轮。UDP 发出去就不管，如果手机先开、电脑后开，前面那段时间的数据就没了（TCP 开了 Persistent 的会一直等电脑端回来）；
2. **防火墙拦截**：Windows 首次运行 Python 收包程序时弹的「允许访问」要点允许；没弹过窗就手动在防火墙里给该端口放行入站规则；
3. **协议对不上**：手机选 JSON 就必须用 TCP 收；手机选 TCP 就不能用 UDP 收。对照[数据推流到电脑的连接设置.md](数据推流到电脑的连接设置.md)的协议表逐字核对。

## 三、能收到但数据不对

| 现象 | 多半是 | 处理 |
| --- | --- | --- |
| 收到的一串数值对不上字段 | 包头/包尾附加项开了但解析没留位置，或传感器勾选变过 | 用 Packet Preview 对照实际字段顺序 |
| 每条包切不开、黏成一团 | 电脑端切包符与手机端 `# Terminator` 开关不一致 | 两边统一：要么换行，要么 `#` |
| 第一条包是文字不是数字 | 开了 Prequel Packet，首包是传感器名 | 跳过首包，或留着做字段对照 |
| NMEA 段里出现分号 | 正常现象，语句内部用分号分隔 | 先切主包再单独解析 NMEA |
| GPS 一直是 0 0 0 | 室内没信号或没给定位权限 | 换窗边/室外，检查应用定位权限 |
| 数据流突然停了 | 手机熄屏后系统休眠 | 开 Stay awake（只在主页面生效），采集时保持屏幕常亮 |

数值格式与字段位置的系统说明在[CSV文件保存位置与数据格式.md](CSV文件保存位置与数据格式.md)。

## 四、还是不行时的两招

- **换 File 协议先验证采集本身**：协议选 `File` 跑一小段，去 `Documents/HyperIMU.ianovir/Exports/` 看文件里有没有数据。有数据说明手机端正常，问题一定出在网络链路上；没数据就回头检查传感器勾选与权限；
- **按正确顺序重来一遍**：电脑端先跑起来 → 手机端填对 IP 和端口 → 再点转轮。顺序反了，UDP 前几条包就丢了。

以上都排过仍收不到，多半是网络环境特殊（路由器开了无线隔离、公司网络禁 UDP 等）。可以换手机开热点、让电脑连上来试一次：能通，问题就在原来的路由器上；仍不通，回头再查防火墙。
