## 一、先分清两边的角色

HyperIMU 在链路里是**客户端**：它主动把数据包发出去；电脑那边要有程序在指定端口收包，充当**服务端**。所以配置顺序永远是：先在电脑上把收包程序跑起来，再把电脑的 IP 和端口填进手机。官方在 GitHub 上提供了 Python 版服务端 [HIMUServer](https://github.com/ianovir/HIMUServer)，读包、切分这些基础逻辑都写好了，可以直接用，也可以照着[官方帮助文档](https://ianovir.com/works/mobile/hyperimu/hyperimu-help/)自己实现收包端。

## 二、传输协议怎么选

设置里可选的传输方式有五种，其中 `None` 表示只采样不发送（默认就是它）：

| 协议 | 载体 | 格式 | 适用情形 |
| --- | --- | --- | --- |
| UDP | UDP | CSV | 不做送达保证、丢了不补，胜在无连接等待；要低延迟、丢得起个别包时用它 |
| TCP | TCP | CSV | 一条都不能丢时用 |
| JSON | TCP | JSON | 想按字段名直接取值、不想按逗号数位置时用 |
| File | 本地文件 | CSV | 不联网，直接存手机里，见[CSV文件保存位置与数据格式.md](CSV文件保存位置与数据格式.md) |

JSON 只走 TCP。手机这边选了什么协议，电脑端就得用同样的协议、同样的端口去收——两边对不上是收不到数据的第一大原因。

## 三、手机端要填的两项

抽屉菜单 Settings 里：

1. **Server IP address**：填电脑在局域网里的 IP。Windows 用 `ipconfig` 看「IPv4 地址」，macOS/Linux 用 `ifconfig` 或 `ip addr`。注意电脑 IP 是路由器分配的，隔几天可能变，突然连不上先重新查一遍；
2. **Server Port number**：与电脑端监听的端口一致，官方示例用 `2055`，可以直接照抄；
3. 长时间跑建议把 **Persistent** 打开：电脑端中途重启或掉线时，手机端会一直等它回来，不用守在旁边重新点开始。

手机和电脑必须连在**同一个局域网**（连同一个路由器），手机开着流量、或连了访客 Wi-Fi，都不行。

## 四、电脑端：跑通官方 Python 服务端

HIMUServer 需要 Python 环境，取源码并安装：

```bash
git clone https://github.com/ianovir/HIMUServer.git
cd HIMUServer
python setup.py install
```

最小可用的收包脚本（以 TCP 为例）：

```python
from HIMUServer import HIMUServer

myHIMUServer = HIMUServer()

class SimplePrintListener:
    def notify(self, sensorData):
        HIMUServer.printSensorsData(sensorData)

myHIMUServer.addListener(SimplePrintListener())
myHIMUServer.start("TCP", 2055)   # 收 UDP 就改成 ("UDP", 2055)
```

几个构造参数与回调要点：

- `HIMUServer(bufferSize=1024, timeout=30, separatorIndex=0)`：`separatorIndex=0` 表示按换行符切包，`1` 表示按 `#` 切包——必须与手机端的 `# Terminator` 开关一致；
- 每收到一条包就回调一次 `notify(sensorData)`，`sensorData` 按传感器分组、每组三个值，用 `HIMUServer.strings2Floats()` 把字符串转成浮点数再算；
- 完整示例看仓库里的 `demo.py`。

不想引入这个库，也可以先用十几行裸 socket 验证链路通不通，Python 与 R 的具体读法都整理在[用Python和R读取传感器数据.md](用Python和R读取传感器数据.md)。
