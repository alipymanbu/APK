# Shizuku 频繁掉线的处理方法

> 用 Shizuku 授权后过一会儿又提示「服务未运行」，或重启手机就失效——免 root 路线的常见现象，本篇把原因和处理顺序列清。

## 一、先分清两种「掉线」

| 现象 | 性质 | 处理 |
| --- | --- | --- |
| 手机重启后 Shizuku 停止 | 机制如此，不是故障 | 重新启动一次服务（一般不用重新配对） |
| 用着用着自己停了 | 系统省电机制把后台进程杀了 | 按本篇第二、三节逐项设置 |

kbattery 里直驱供电这类深度功能依赖 Shizuku 常驻，掉一次线这些功能就跟着退回「Shizuku 服务未运行」，直到你重新启动服务。

## 二、把 Shizuku 留在后台（手机侧设置）

按 Shizuku 官方手册与多数用户的实践，下面几项做完能明显减少「随机停止」：

1. **电池不限制**：设置 → 应用 → Shizuku → 电池，选「无限制」或「不优化」（不同系统叫法不同）；
2. **别从最近任务里划掉 Shizuku**：划掉等于手动杀进程；
3. **开发者选项与 USB 调试保持开启**：官方手册明确「不要关闭」——很多人配置完就关掉开发者选项，服务跟着停；
4. **开发者选项里把 USB 使用模式改为「仅充电」**；
5. Android 11 及以上：开启开发者选项里的「停用 ADB 授权超时」（部分系统的叫法略有差异），减少授权会话被超时断开。

MIUI / HyperOS 这类自带激进后台管理的系统，有用户反馈还需要把 Shizuku 加进系统管家的白名单；各家系统差异大，以你手头机型的实测为准。

## 三、掉线之后怎么快速恢复

- **无线调试方式**：打开 Shizuku 点「通过无线调试启动」即可，配对只需一次，之后重启恢复不用再配对；
- **电脑 ADB 方式**：重新连电脑执行一次当初那条启动命令（`adb shell … start.sh`，以 Shizuku 应用内显示的为准），拔线后照常使用；
- 点启动没反应：官方手册给的口子是把系统的无线调试关掉再打开，然后重试。

某些机型上服务只活几分钟（有用户反馈存在这类省电特别激进的系统），这类情况没有一劳永逸的办法，接受「每次要用前先启动一下」的节奏即可。

## 四、kbattery 这边的连带影响

Shizuku 掉线期间，kbattery 的直驱供电等深度功能不可用，基础功能（看电池数据、清理后台）不受影响；服务恢复后功能即恢复，一般不用重新授权。首次授权流程在 [Shizuku授权开启方法.md](Shizuku授权开启方法.md)，功能开不动时的排查见 [直驱供电开启方法.md](直驱供电开启方法.md)。
