## 一、先安个心：那个「限制」警告不是条数墙

Janitor+ 上线后，长聊天里会弹出一条像是「消息用完了」的提示。按官方口径与多个独立评测的核对结果：**免费版 JanitorLLM 没有每日或单聊的条数上限**，这条提示说的是另一件事 —— 你的聊天总长度超过了模型一次能读进的文本量（上下文窗口，约 8000~9000 token），最老的那部分内容开始被挤出去了。你还能继续发消息，只是角色「记得的事」在变少。

顺带两个数字（截至 2026 年中，以官方页面为准）：

- 免费 JLLM 上下文约 8k~9k token；**高峰时段官方会把它临时压到 3800~6000 token** 保服务 —— 所以「昨天还好好的，今晚突然变笨」多半是这个原因，不是你改了什么。
- 付费的 Janitor+ 是 $12.99/月（2026-06-24 上线，宣称 5 倍上下文），官方从未有过所谓 $9.99 的 Pro 档。买不买自己权衡 —— 换外接模型通常更便宜，见 [模型与API设置教程.md](模型与API设置教程.md)。

## 二、为什么会忘：两类内容在抢同一块地方

每次发消息，系统会打包这些内容发给模型：角色的人格与场景、你的 Persona、**Chat Memory 框里的摘要**（以上是「永久 token」，每条消息都带）、加上最近的聊天记录（临时 token）。空间不够时，**最先被挤掉的永远是最老的聊天记录** —— 你们怎么认识的、第一幕发生了什么，最先消失。

| 症状 | 多半是因为空间被什么占了 |
| --- | --- |
| 聊了 25~30 条后开头的事开始模糊 | 正常淘汰，记录被挤出窗口 |
| 才聊几条就忘 | 角色卡本身太重，还没开聊就占掉大半空间 |
| 角色突然不按人设说话 | 永久内容堆太高（有评测认为逼近 8500 token 时模型会开始读不全人设） |
| 明明聊过的事只记得个大概 | Chat Memory 摘要写得太笼统 |

官方帮助中心给的记账口径：常驻内容（人格 + 场景 + 记忆 + Persona）建议压在 2500 token 以内；社区评测则更保守，建议 1500~2000 以内。两个口径并列供你参考 —— 共同点是**角色卡不是越厚越好，堆太厚反而先挤死聊天本身**。

## 三、能做的三件事（都不用花钱）

### 1. 给角色卡减负

回 [创建AI角色教程.md](创建AI角色教程.md) 的字段那节，把 Personality 里「其实模型每次都需要」的长篇背景砍成要点。判据很简单：删掉这段，角色说话会不会变个人？不会就删。

### 2. 用好 Chat Memory

聊天设置里有 **Chat Memory** 框，里面写的内容算永久 token，每条消息都带着走 —— 这是你能主动保住的「存档」。官方模板长这样：

```text
Environment:        （当前在哪、什么氛围，短语即可）
Relationship Dynamic: （你和角色现在什么关系）
Current Plot Points:  （正在推进的事）
{{char}} notes:      （角色的客观事实：持有物、状态）
{{user}} notes:      （你的客观事实：装扮、伤势）
Important Past Events: （影响后续的大事件）
```

写法要领：只列事实不写场景、全篇统一时态、每条一短句。写成小作文等于自己把窗口占满。

### 3. 主动让模型做小结

聊到一个章节结束，直接发一条场外指令让它交总结，拿到的摘要就是你下一步贴进 Chat Memory 的内容。官方帮助中心给的现成句式（可用中文改写）：

```text
<system>task: pause chat|roleplay, answer query(outside of roleplay,
succinct summary(starting from tavern fight onward,
list of all impactful events(+their effects)))</system>
```

相当于章节存档：几十上百条的长篇，靠一次次小结把关键事实留在窗口里，比指望模型自己记住划算得多。

## 四、什么时候才值得换模型

上面三招做完，健忘仍是长期连载的硬约束 —— 窗口就那么大。真要根治只有两条路：换付费档，或接外接模型（DeepSeek 等通道的窗口远大于免费 JLLM，成本每月通常几美元量级，具体以各家定价页为准）。配置方法在 [模型与API设置教程.md](模型与API设置教程.md)，换之前先把本篇的三件事做完 —— 不然再大的窗口也会被过重的角色卡吃掉。
