## 一、先分清两种故障

| 现象 | 属于哪类 | 去哪节 |
| --- | --- | --- |
| TCP 客户端点连接一直转圈/超时/拒绝 | 连不上 | 第二节 |
| UDP 发送显示正常，对方永远没反应 | 连不上（网络层） | 第二、四节 |
| 能连上，但发过去是乱码 | 参数不对 | 第三节 |
| 服务端开了，客户端连上后单向没数据 | 参数不对 | 第三节 |

UDP 没有连接动作，界面上的「发送成功」不代表链路通，判断依据永远是对端有没有收到。

## 二、连不上的排查清单

按命中率从高到低逐项过：

1. **两端不在同一个网络**：手机和电脑必须连同一个路由器的 Wi-Fi（或电脑插网线、手机连同一台路由器的 Wi-Fi）；没有路由器时用手机热点组网，频段设置与互访查法见《手机热点当调试网络的设置要点》；公司/学校网络常按网段隔离，不在这个范围就只能换网络验证；
2. **IP 填错**：远程地址要填对端的**局域网 IP**（192.168.x.x 一类），不能填 `127.0.0.1`——那个地址只在本机自测时用；手机重连 Wi-Fi 后 IP 可能变了，重新查一遍（查法见《TCP服务端与客户端互测步骤》第一节）；
3. **服务端没开监听**：手机端建了 TCP Server 但没点确认/开启，客户端一连就被拒绝；
4. **电脑端防火墙拦入站**：Windows 防火墙默认拦截外部入站连接——手机连电脑被超时、电脑自己连自己却正常，多半是它；把电脑端调试工具允许通过防火墙，或临时关闭防火墙再测一次；
5. **路由器开了 AP 隔离**：访客网络、公共 Wi-Fi 常开这个，隔离下设备互相不可见，任何连接都建不起来；家用路由器到无线设置里关掉「AP 隔离/访客隔离」；
6. **手机流量同开**：双卡或 Wi-Fi/数据同开时，个别系统会把流量跑在移动网络上，测试期间把移动数据关掉最省心。

## 三、连上但收不到、或是乱码

- **格式不一致**：一端按 HEX 发、另一端按文本显示，看到的就是十六进制当字符渲染的乱码；两端统一成 TXT 或统一成 HEX 再对；
- **编码不一致**：含中文的数据一端按 UTF-8、一端按 GBK 发，也会乱码，两端编码选项保持一致；
- **端口指错**：UDP 的本地端口与远程端口是两回事，互发时两端远程地址要分别指向对方的本地端口（对照《UDP通信与广播测试》第二节的填法）；
- **服务端只监听不回复**：一些被测程序本身不发数据，链路是通的只是对方沉默——用能回显的工具先验链路，再接真实程序。

## 四、UDP 广播发出去没人应

1. 设备确实没在监听你发的那个端口（核对模块的通信协议说明）；
2. AP 隔离把广播拦了（同上，换网络或关隔离）；
3. 路由器对组播/广播有限制，尤其多个路由器级联时，广播可能到不了另一台路由器下的设备。

排查顺序建议固定成「先本机自测 → 再同网段互测 → 最后才怀疑网络设备」，大多数问题在前两步就现形。链路验证通过后的进阶玩法（串口、配网）见《串口调试与EspTouch配网》。
