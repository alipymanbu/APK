# NetAssist TCP服务端与客户端互测步骤

> 本篇讲用 NetAssist 做 TCP 调试的两条完整链路：手机开服务端让别人连进来、手机做客户端去连别人的服务端，含 IP 与端口的准备、互发数据与十六进制发送。

## 一、开测前先备齐三样信息

| 要准备的 | 到哪拿 |
| --- | --- |
| 手机的局域网 IP | 设置 → WLAN → 点当前网络查看（一般在 IP 地址一栏，形如 192.168.x.x） |
| 端口号 | 自己定一个 1024~65535 之间的数，避开 80、8080 这类常用端口 |
| 对端 IP | 被测设备（电脑/开发板/模块）的 IP，测试时两端要在同一网络 |

TCP 是有连接的通信，一端当服务端先「监听」，另一端当客户端「连过去」，谁当哪端都行，两边的角色别填反。

## 二、手机当 TCP 服务端（电脑连手机）

1. 打开 NetAssist，新建一个连接，协议类型选 **TCP Server**；
2. 本地端口填你定的端口号（例如 9000），点确认后服务端进入监听状态；
3. 在电脑端用任意 TCP 客户端工具（电脑上的网络调试助手、你自己的测试程序都行），目标地址填**手机的 IP**、端口填 9000，发起连接；
4. 连接建立后，手机端会显示接入的客户端，收发记录以对话形式逐条排列；
5. 任意一端发数据，另一端立即可见——先各发一句文本确认链路通，再测业务报文。

服务端模式支持多个客户端同时接入，每个客户端的会话单独一条，可以分别查看与收发。

## 三、手机当 TCP 客户端（手机连电脑）

1. 电脑端先开一个 TCP 服务端并监听端口（例如 9000），这一步要在手机连接前完成；
2. 手机端新建连接，协议类型选 **TCP Client**；
3. 远程地址填**电脑的 IP**、远程端口填 9000，点连接；
4. 状态变为已连接后即可互发数据。

手机做客户端最常见的失败原因就是第 1 步没先做——电脑端没有监听，手机一连接就被拒绝；其余原因对照《连接不上与常见问题排查》。

## 四、发送格式：文本与十六进制

调试物联网模块、工控设备时经常要发十六进制报文：

- 发送前把格式从 **TXT（文本）** 切到 **HEX（十六进制）**，输入框里按 `01 03 00 00 00 02` 这样的写法填；
- 接收区同样可以按文本或十六进制显示，**两端格式不一致时看到的就是乱码**——这是「连上了但对不上话」的头号原因；
- 测 AT 指令类的模块时用文本格式发，注意指令尾部的回车换行是否需要（看模块说明书）：多数模块要求指令以回车换行结尾，文本模式下输入框不方便敲出控制符时，可在 HEX 模式下把整条指令按字符的十六进制值填入，末尾补 `0D 0A`（回车+换行），例如 `AT\r\n` 就是 `41 54 0D 0A`；
- 逐字节对照收发内容是定位协议问题的最快办法：两边都切 HEX，一个字节一个字节比，差在哪一眼就能看出来。

## 五、怎么算测通了

- 客户端能连上、服务端能看到客户端接入记录；
- 一端发送、另一端接收区出现对应内容，格式一致；
- 断开后重连还能恢复——TCP 链路本身就算验证完了。

如果服务端开了却始终没人能连进来，或客户端一直连接超时，按《连接不上与常见问题排查》的清单逐项排除。
