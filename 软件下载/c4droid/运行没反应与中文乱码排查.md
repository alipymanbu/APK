## 一、先分清三种「没反应」

| 现象 | 属于哪种 | 处理 |
| --- | --- | --- |
| 点编译后出红字报错 | 编译没过 | 按报错文本查 [常见报错与解决方法.md](常见报错与解决方法.md) |
| 编译通过，运行后停住、光标在闪 | 程序在等你输入 | 看第二节 |
| 编译通过，运行后立刻退出、什么都没有 | 运行期出错或终端被关 | 看第三节 |
| 跑出来了，中文是一排问号或怪字 | 编码问题 | 看第四节 |

## 二、停住不动：程序正在等输入

程序里写了 `scanf`、`getchar` 这类输入函数，跑到那里就会停下来等你喂数据 —— 这不是卡死：

1. 点一下终端区域，输入数据（多个数之间用空格或换行隔开）；
2. **按回车**，程序才继续往下走；
3. 想中途掐掉：点停止按钮，或在终端里按 Ctrl+X 关掉。

**读完数还一直等**的常见原因是 `scanf` 的格式串末尾多了空白：

```c
scanf("%d\n", &x);   // 反例：%d 读完后还会继续等一个非空白字符
scanf("%d", &x);      // 正确：读一个整数就走
```

`scanf` 把 `\n`、空格当成分隔符来跳过，末尾的 `\n` 会让它一直等下一个输入 —— 多份 C 教学资料对这个坑的结论一致，写读数代码时格式串末尾别加 `\n` 或空格。

## 三、运行后立刻退出、看不到输出

按顺序排查：

1. 先确认**编译输出窗里没有 error** —— 有 error 就不会执行，按 [常见报错与解决方法.md](常见报错与解决方法.md) 处理；
2. 编译没报错却直接结束：多数是运行期问题（除零、指针没赋值就用等）。在 `main` 里从上往下加几行 `printf("1\n");` 打点，看程序走到哪一步停的，这是定位最快的办法；
3. 报错文本里带 `Illegal instruction` 字样：是内置 TCC 编译器的问题，换 GCC，见 [编译器怎么选与GCC插件安装.md](编译器怎么选与GCC插件安装.md)；
4. 什么输出都没有、但刚才手动关过终端：Ctrl+X 或点关闭会把终端窗口收掉，重新点运行即可。

## 四、输出中文是乱码

典型表现：英文输出正常，`printf` 里的中文变成一排问号或怪字符。

**原因方向是编码不一致** —— 源文件里中文的存储编码和终端解析编码对不上（各类控制台环境的通病，结论多来源一致），它不是编译错误，程序逻辑是跑通了的。按这个顺序验证：

1. 把那几行中文临时改成英文再跑：还乱 → 问题不在编码，回头查代码；不乱了 → 确认是中文编码问题；
2. 确认是编码问题后，删掉那行重新在编辑器里**手动输入**中文 —— 从其他 App 粘贴进来的文本编码由来源决定，手输最干净；
3. 只是练习程序的话，先用英文或拼音占位把逻辑验证完，中文输出不影响对错判断。

c4droid 这版没有查到可调的终端编码选项，查不到的设置不写；乱码若只在特定某一行出现，优先按第 2 步处理那一行。
