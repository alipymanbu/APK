摇杆漂移的表现是你不碰摇杆，游戏里的角色或视角却自己在动。ckck 的摇杆测试页把这件事拆成三个互不相同的检查项：漂移测试、圆周率测试、分辨率测试，用法与结论各不相同。

## 一、漂移测试：手柄放桌上别碰

这是判断漂移最直接的一项，测的是「没有输入时摇杆会不会自己报数」。

1. 把手柄**平放在桌面上**，确认没有任何东西压着摇杆。
2. 进入摇杆测试页的漂移测试，点开始静止检测。
3. 测试期间**务必不要触碰摇杆**，保持静止 3 秒。
4. 看检测结果：页面上会分别给出左摇杆、右摇杆的状态（正常 / 异常）和各自的平均偏差值。

判读口径：

| 结果 | 含义 |
| --- | --- |
| 状态显示正常、平均偏差接近 0 | 静态下摇杆没有漂移 |
| 状态异常、平均偏差明显不为 0 | 静态漂移，且偏差值越大越严重 |

这一页没有统一的「多少算漂移」阈值，所以别拿网上的绝对数字硬套。两个更可靠的判据：**左右摇杆互相对比**（一侧明显比另一侧大，说明该侧有问题），以及**这台手柄自己的历史读数**（比上次测的明显变大，说明在恶化）。

测之前先把手柄放稳十秒再开始，避免刚松手时的余振被算进去。

## 二、圆周率测试：看轨迹是不是正圆

漂移看的是「静止时」，这一项看的是「运动时」：把摇杆贴着边缘转一圈，正常手柄画出来应是一个接近正圆的轨迹。轨迹被压扁、出现缺口、或者偏向某一侧，说明行程或某个方向的读值有丢失。

做法：照页面提示把摇杆**贴着最大行程匀速转圈**，转两圈以上再看轨迹图形。低于最大行程随手转，看不出问题。

## 三、分辨率测试：看小幅动作有没有被吃掉

分辨率测试关注的是摇杆的细微偏移能不能被识别出来 —— 小幅拨动时坐标变化越连续，精细操作的余地越大。操作方法是在摇杆的小范围内缓慢推移，看坐标数值是否连续变化，而不是一跳一大格。

| 测试项 | 手柄要摆成什么样 | 看什么 |
| --- | --- | --- |
| 漂移测试 | 平放桌面、完全不碰 | 状态与平均偏差值 |
| 圆周率测试 | 贴着边缘匀速转圈 | 轨迹圆不圆、有没有缺口 |
| 分辨率测试 | 小幅缓慢推移 | 坐标是否连续变化 |

## 四、死区：页面上的数值怎么理解

摇杆测试页上有个**模拟死区（Deadzone）** 的数值，默认 0.05。死区指的是「摇杆动了这么小幅，系统当作没动」的这段范围，它由手柄固件决定。

判断自己的手柄有没有死区，页面给了一条很明确的口径：

> 每次拨动摇杆、归中时数值一致不变，当前摇杆为**有死区**；反之则为**无死区**。

也就是说，反复拨动再松手，如果每次回中后读到的是同一个数，说明手柄自带死区；如果每次回中的数值都有轻微差异，说明是无死区设计。

还有一条容易误判的现象：**无死区的摇杆在静止时出现轻微抖动属于正常**，不必当成故障。死区本身也不是越小越好：

- 死区偏大：小幅拨动的操作没有反应，精细控制变差。
- 死区偏小：静止时更容易出现轻微漂移。
- 模拟死区的数值是拿来「套」着看的 —— 调到与实际手柄接近的值再观察，读数更贴近你在游戏里的手感。

## 五、读到什么程度该动手

| 读数情况 | 建议动作 |
| --- | --- |
| 平均偏差接近 0、轨迹接近正圆 | 无需处理，可以作为手柄健康状态的基线记下来 |
| 平均偏差明显不 0，但拨动后还能回中 | 按 [摇杆漂移了怎么处理.md](摇杆漂移了怎么处理.md) 的顺序处理：先在游戏里加大死区应急，再做清洁与校准 |
| 校准后复测依旧偏差明显 | 属于硬件老化，机构类问题校准解决不了 |
| 轨迹出现固定缺口 | 某个方向疑似读值丢失，同样先清洁、再校准复测 |

校准要用**手柄厂商自己的方式**（通常是组合键进入校准模式，或手柄配套 App 里的校准功能），ckck 只负责告诉你校准有没有起作用。校准完回到这一页重跑漂移测试和圆周率测试，对比偏差值有没有收小，是最可靠的验证方式。

各平台的官方校准入口在哪、清洁摇杆根部怎么做、什么情况下该停止自修，按 [摇杆漂移了怎么处理.md](摇杆漂移了怎么处理.md) 里的顺序走 —— 处理前后的对比，也请用这一页的同一项测试来做。

如果这一页连数据都没有（摇杆怎么拨都是 0 或界面没反应），那是连接层面的问题，先看 [手柄怎么连接和配对.md](手柄怎么连接和配对.md)。
