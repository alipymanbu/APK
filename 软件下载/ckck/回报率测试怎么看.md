# ckck 回报率测试怎么看

> 本篇讲摇杆回报率这一页怎么测才准、峰值与平均值差在哪、多少算正常，以及那些「异常次数」从哪来。

回报率指的是手柄每秒向设备上报多少次摇杆数据，它决定手柄能不能跟上你手速 —— 数值低的手柄在高速转向时会出现拖影一样的滞后感。这一页把这件事量化成几个可以直接对比的数字。

## 一、测前准备

1. 手柄建议用 **HID 模式**连接，这一页对连接方式比较敏感。
2. 把手柄拿稳，双手握住，别放在腿上或沙发上 —— 测的过程中手柄本体晃动会干扰结果。
3. 这一页有次数档位可选：**1000 次、2000 次、3000 次**。次数越多，结果越贴近真实水平，但同时要摇更久。
4. 选好次数后点开始，按页面提示摇动摇杆采集数据。

## 二、摇的时候有两个硬要求

| 要求 | 原因 |
| --- | --- |
| 全程只摇**一个**摇杆（通常按提示摇左摇杆） | 两个摇杆同时动，系统上报的数据会混在一起，统计口径就不对了 |
| 尽量**匀速**转、中途不要停 | 每次停顿都会在两次上报之间拉出一段空档，被算成异常次数，把回报率往下拉 |

次数满了之后会自动停止采集并给出结果，不用手动掐时间。测完想重来一次，执行重置即可。

## 三、结果页上的数字分别是什么意思

| 指标 | 含义 | 怎么看 |
| --- | --- | --- |
| 峰值回报率 | 采样期间最高的一瞬间上报频率 | 反映上限，容易受单次抖动影响，别只盯它 |
| 平均回报率 | 整个测试期间的平均值 | 这是最有参考价值的一个数 |
| 估算间隔延迟 | 基于当前回报率推算的理论最小更新间隔 | 数值越小，输入越跟手；它是由回报率换算来的，不额外说明新问题 |
| 抖动 | 上报间隔的波动幅度 | 同一台手柄多测几次，抖动越小越稳定 |
| 异常次数 | 不符合匀速采样规律的次数 | 中途停顿、来回变速都会把它抬高，先检查自己的手法再看手柄 |

看结论的顺序：**先看平均回报率，再看抖动，最后才看峰值**。只用峰值下结论很容易被一次偶然的高读数骗到。

## 四、多少算正常

官方网页版给出的性能参考值，可以拿来对照你测出来的平均回报率：

| 连接方式 | 参考上限 |
| --- | --- |
| 有线（USB） | 1~8K Hz |
| 蓝牙（Bluetooth） | 125 Hz |
| 2.4G 接收器 | 1~8K Hz |

回报率是「每秒上报多少次」，换算成上报间隔更直观：

| 回报率 | 上报间隔 |
| --- | --- |
| 125 Hz | 8ms |
| 250 Hz | 4ms |
| 1000 Hz | 1ms |
| 8000 Hz | 0.125ms |

看第一张表要分清一件事：**回报率不等于端到端延迟**。从你按下按键到画面响应，中间要经过传感器读值、手柄内部处理、传输、设备接收解析、游戏处理、屏幕刷新这些环节，回报率只是其中「上报密度」这一段。所以低回报率的手柄换根线也不会变成高回报率，反过来把回报率从 1000Hz 再往上提到 8000Hz，理论减少的等待时间也不到 1ms —— 收益取决于整条链路，不是只看这一个数字。

对照上面那张连接方式表要注意两点：

- 表里给的是**上限区间**，不是每台手柄都能跑到区间顶部；同一种连接方式下，具体手柄的能力差别很大。
- **蓝牙手柄测出 125Hz 左右是正常的**，想测更高的数字请换有线或 2.4G 接收器连接，用蓝牙测不出有线手柄的真实上限。

如果你是在**电脑浏览器的官方网页版**里测的，还有一层限制：浏览器默认只采样 200Hz 以下的读数，要测更高回报率得先点页面上的**连接手柄设备**按钮，否则数字会被浏览器卡住，看起来像手柄只有 200Hz。手机上用 ckck 测不受这一条限制，读数上限由系统和手柄本身决定。

## 五、测出来偏低怎么办

| 情况 | 可能原因 | 处理 |
| --- | --- | --- |
| 蓝牙连接测出来只有百来 Hz | 蓝牙通路本身的限制 | 正常现象，换有线再测一次对比 |
| 有线也远低于 1K Hz | 手柄本身规格较低，或线材 / 转接头是瓶颈 | 换一根数据线、去掉转接头重测 |
| 异常次数很高 | 摇的过程中停顿或变速了 | 重置后重测，保持匀速 |
| 前后两次结果差很多 | 测试时手柄晃动、或同时有别的动作 | 手放稳重测，两次都稳定才有参考价值 |

回报率不达标不代表手柄坏了 —— 它是一项性能指标，不是故障判据；漂移、串键那类才算故障。这两类问题分别看 [摇杆漂移与死区怎么看.md](摇杆漂移与死区怎么看.md) 和 [按键与方向键串键测试.md](按键与方向键串键测试.md)。
