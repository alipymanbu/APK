## 一、先做这一步：更新引擎

**Seal 的抓取能力来自内置的 yt-dlp，而站点几乎每周都在改版 —— 所以「突然下不了」的第一嫌疑永远是引擎旧了。** 按「设置 → 通用 → 更新 yt-dlp」更新（有的版本还能在该项的齿轮里选择更新通道，比如切到 stable）。这一步免费、无副作用，能解决下面表里标了「先更新」的大多数报错。

更新完重新发起一次下载再看结果。仍然失败，按报错对号入座。

## 二、对号入座的报错表

| 报错 / 现象 | 怎么处理 |
| --- | --- |
| `HTTP Error 403: Forbidden` | **先更新 yt-dlp**。更新后仍 403，说明是站点侧的访问校验变了：换一段网络（Wi-Fi / 流量）稍后再试，别连续高频重试 |
| `Sign in to confirm you're not a bot`（要求登录以确认你不是机器人） | **先更新 yt-dlp**。这是站点的机器人检查：请求太密、网络出口质量差时会被拦。策略是隔一段时间再试、换网络、把批量任务拆小；短时间内反复重试只会让拦截更久 |
| `Requested format is not available`（请求的格式不可用） | 你选的清晰度/格式该站点没提供。回到选项面板换成「自动」或更低的档位 —— 规则见 [支持的网站与格式.md](支持的网站与格式.md) |
| 合并 / 转换阶段失败 | 多发生在「画面与音轨分开提供」的高清晰度下载上。先更新引擎再试；仍失败就降一档清晰度或改选 MP4 |
| 提示私有视频 / 需要登录 | 内容本身需要授权，工具拿不到就看不了。换成你账号确实有权访问的公开链接 |
| 提示年龄限制 / 需要确认年龄 | 同上：站点要求已登录的会话才能看，Seal 默认不带你的登录态 |
| **下下来的视频没有声音** | 站点把画面与音轨分成两条流，合并那一步出了岔子。先更新引擎重下；仍没声音就降一档清晰度（低档位常是画面音轨合一的单流），或在格式里改选另一个封装。合并由 Seal 内置的 FFmpeg 完成，**你不需要另外装任何东西** |
| 「列表只下了几个就停」 | 批量请求触发了站点频控。把列表拆小、拉长间隔重跑；失败的几条单独重试（任务列表里可重试） |
| 一直转圈、很慢或中途断 | 先确认不是自己网络的问题；在「设置 → 网络」里打开 aria2c 外部下载器（说明见 [高级设置与自定义命令.md](高级设置与自定义命令.md)），大文件更稳 |

## 三、下载成功了却找不到文件

任务显示完成、文件管理器里翻不到 —— 这是另一个维度的问题，完整排查（看设置里的保存路径、按目录顺序找、相册不刷新的处理、换目录）见 [下载的文件在哪个文件夹.md](下载的文件在哪个文件夹.md)。最短路径就两步：

1. 去系统设置 → 应用 → Seal → 权限，确认存储权限是允许的；
2. 打开 Seal 的「设置 → 下载文件夹」，照着里面写的路径去文件管理器里进。

## 四、装不上 / 打不开

- 安装时提示「禁止安装未知应用」→ 去允许当前来源（浏览器或文件管理器）安装未知应用，返回重装。
- 提示「应用未安装 / 与系统不兼容」→ 架构选错了，按 [下载与安装教程.md](下载与安装教程.md) 第二节换一份对应 CPU 的包。
- 升级安装提示签名不一致 → 你手上是不同渠道签的包（比如 F-Droid 与 GitHub 版互装）。先卸载旧的再装新的，**卸载不会带走已下载的媒体文件**，但会清掉 Seal 内部的下载记录。

## 五、判断「该等还是该动手」

- **单个链接失败、其他链接正常** → 大概率是这个链接的问题（内容受限、格式特殊），换个链接验证。
- **所有链接同时失败、昨天还好好的** → 站点改版了，等引擎更新是常态；先手动更新 yt-dlp，仍不行就等几天看官方仓库的[更新日志](https://github.com/JunkFood02/Seal/releases)。
- **只有批量任务失败** → 频控，拆批、放慢节奏。
- **刚更新完引擎反而更糟** → 新版本与站点/设备的兼容偶有反复。回「设置 → 通用」把更新通道换回 stable 再更新一次（通道说明见 [高级设置与自定义命令.md](高级设置与自定义命令.md) 第三节）；仍异常就退回能用的那个组合，等下一轮修复。
