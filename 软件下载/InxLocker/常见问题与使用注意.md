## 一、模块装了但拦截不生效

按命中率从高到低逐项检查：

| 检查项 | 在哪看 | 什么算通过 |
| --- | --- | --- |
| 模块已启用 | LSPosed 管理器 → 模块列表 | InxLocker 开关是开的 |
| 作用域含系统框架 | LSPosed → InxLocker → 作用域 | 「系统框架（System Framework）」已勾 |
| 改过作用域后已重启 | —— | 勾选或取消勾选之后重启过系统或对应应用 |
| 目标安装器已选 | InxLocker → 默认安装器设置 | 列表里有明确选中的项，不是空着 |
| 发起安装的应用在作用域里 | LSPosed → InxLocker → 作用域 | 浏览器/文件管理器装包不生效时，把发起安装的那个应用勾进去 |
| 框架本身正常 | LSPosed 状态页 | 已激活、无报错 |

以上逐项过了还是不行，试着换一个小 APK 再测一次；个别应用把安装器写死，属于另一类问题，见下一节。用的是 ColorOS、MIUI 这类深度定制系统的话，还要考虑系统在安装通道上做的额外限制，对照 [定制系统换安装器踩坑.md](定制系统换安装器踩坑.md) 第二节逐条排查。

## 二、选了目标安装器却调不起来

现象：配置页里目标安装器选得好好的，实际装包时弹出来的还是系统安装器。原因是发起安装的应用硬编码了安装器组件，普通的重定向逻辑接管不了它。

处置：回到 InxLocker 的安装器列表，**长按**目标安装器条目，开启「强制组件调用」，让模块直接调起它的特定组件。开完再测同一个应用。

## 三、Android 14 及以上装包报权限问题

官方说明里提到：部分 Android 14 及以上环境下存在安装路径权限问题，模块在后续版本里提供了实验性修复。如果你手上这份是 1.4 版并在新系统上遇到「装包报权限/路径错误」，可以先确认报错是否只在个别应用出现；反复遇到时考虑升级到新版（版本情况见 [版本与更新说明.md](版本与更新说明.md)），或先关掉不必要的拦截项对照定位。

## 四、改了设置不生效 / 更新模块后要不要重启

- **改作用域**：必须重启系统或重启被勾选的应用，改完立刻测无效是正常的。
- **改默认安装器、开关拦截项**：改的是模块自己的配置，一般保存即可测；没反应就重启一次对应应用。
- **更新模块**：官方说明提到新版本支持热重载（更新后无需重启系统即时生效）；旧版本更新模块后，建议照旧重启一次再测，以实际效果为准。

## 五、图标隐藏后找不到入口

在 LSPosed 管理器的模块列表里点 InxLocker，可直接进入它的设置界面，不需要重新安装或取消隐藏。建议改动前先想清楚要改哪项，避免在列表和设置间来回折腾。

## 六、停用与卸载的正确顺序

不要直接卸 APK。顺序是：先在 LSPosed 里关闭 InxLocker 的启用开关 → 重启系统 → 再卸载 InxLocker 应用。直接卸载会让系统里残留一个已生效过的钩子配置，个别情况下卸载/安装行为会表现异常，重启后才会恢复。

## 七、来源与安全注意

InxLocker 的能力是接管系统的安装与卸载请求，这意味着你要对「模块本体来自哪」负责：

- 只从可信渠道获取安装包；拿不准时核对包名是否为 `io.github.chimio.inxlocker`；
- 它是开源项目（GPL-3.0 协议），代码与发布页都在 GitHub 上，项目地址见 [版本与更新说明.md](版本与更新说明.md)；
- 在二手渠道拿到的包无法核验内容，不建议刷入。
