## 一、为什么必须先搭环境

Xposed 模块的原理是挂在系统进程里工作，所以它依赖两样东西：系统已被 Root、且装有能加载模块的 Xposed 框架。缺任何一样，InxLocker 装上后都能正常打开界面，但拦截功能完全不会生效 —— 你会以为软件坏了，其实只是环境没到位。

如果你手机已经在用 LSPosed 跑其他模块，直接跳到 [下载与安装教程.md](下载与安装教程.md) 激活即可，本篇可以不用看。

## 二、环境三件套

| 组件 | 你要做的 | 判断是否就绪 |
| --- | --- | --- |
| Root（Magisk / KernelSU 等） | 解锁 Bootloader 后刷入 Root 方案；机型不同步骤差异很大，按「你的机型 + Magisk」搜教程 | Root 管理器 App 能打开、能授权 |
| Zygisk | 在 Magisk 设置里打开 Zygisk 开关，重启 | LSPosed 能被 Magisk 识别并加载 |
| LSPosed | 通过 Magisk 刷入 LSPosed 模块包，重启后通知栏会出现 LSPosed 入口 | 能打开 LSPosed 管理器、模块列表可见 |

三件套的顺序不能乱：先 Root，再开 Zygisk，最后装 LSPosed。每一步做完都重启一次再验证下一步。

注意：解锁 Bootloader 会清空手机数据，动手前先把照片、聊天记录等备份好；部分品牌解锁后会影响保修与支付类应用，介意的话先查清你机型的政策再决定。

## 三、快速确认框架能不能用

打开 LSPosed 管理器，看两点：

1. 状态页显示框架已激活、无报错；
2. 模块列表里能看到已安装的模块（装了 InxLocker 之后列表里就应有它）。

两点都满足，环境就算就绪，InxLocker 的激活步骤见 [下载与安装教程.md](下载与安装教程.md) 第四节。

## 四、不想 Root 有没有替代路径

LSPosed 团队另有一个 LSPatch 项目，可在免 Root 环境下把模块塞进单个应用运行。对 InxLocker 这类需要挂在系统框架上拦截全局安装请求的模块，免 Root 方案的覆盖能力有限，能不能达到你要的效果需要自行验证，以 LSPatch 与 InxLocker 各自项目页面的说明为准。

想省事且能接受解锁刷机的，直接按第二节的顺序搭标准环境，踩坑最少。

## 五、环境常见疑问

- **会变卡或费电吗**：Xposed 框架本身常驻系统，多勾一个模块就多一份开销；InxLocker 只拦截安装与卸载请求，日常待机时几乎无感。
- **系统更新后要重刷吗**：大版本升级（OTA）可能让 Root 与框架失效，需要按你的 Root 方案重新处理；升级前先确认你的机型有对应的新版教程。
- **模块之间会冲突吗**：同时启用多个改系统行为的模块时，出问题先逐个停用排查，别一次改三项设置。
