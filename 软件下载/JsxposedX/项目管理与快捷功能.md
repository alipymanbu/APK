## 一、项目工作区是什么概念

JsxposedX 的组织方式是「一个目标应用一个项目」：你选中哪个应用做分析，它后续的脚本、日志、功能开关、分析记录就都归到这个应用名下，互不混杂。你同时调几个应用时，各自的配置不会串。

每个项目里托管的数据包括：快捷功能的开关状态、AI 分析记录、Xposed 脚本、Frida 脚本、日志与加密记录。卸载应用或清理数据前，先想想这里面有没有你要留的东西。

## 二、添加目标应用

1. 底部导航栏点「项目」，进入项目管理页。
2. 点右上角的「+」，打开选择应用界面。
3. 顶部搜索框输入应用名关键词，点选目标应用即可加入。

加好之后回到项目列表，点开这个应用的菜单，就能看到它的四个入口。

## 三、四个入口怎么选

| 你要做的事 | 进哪个入口 |
| --- | --- |
| 不写脚本，开几个现成开关试试效果 | 快捷功能 |
| 看类、方法、SO、JNI 的结构线索，让 AI 出分析 | AI 分析 |
| 写模块侧脚本（Xposed 语法） | Xposed 项目 |
| 写注入侧脚本（Frida 语法） | Frida 项目 |

四个入口可以叠着用：先用快捷功能确认能拦到东西，再按需转入脚本或 AI 分析。AI 分析依赖 AI 配置先通过，见 [AI功能配置与使用.md](AI功能配置与使用.md)。模块与脚本两条路怎么分工、模块的作用域怎么划，见 [模块加载与作用域.md](模块加载与作用域.md)。

## 四、快捷功能开关清单

快捷功能是内置的开关式功能，官方文档列出的项目如下：

| 功能 | 作用 |
| --- | --- |
| 弹窗抑制 | 拦截与弹窗相关的逻辑 |
| 截图限制解除 | 去掉应用禁止截屏/录屏的限制 |
| 网络检测处理 | 应对部分网络、SSL、VPN、抓包相关的检测逻辑 |
| 注入提示 | 显示注入是否处于生效状态 |
| 版本伪装 | 改变应用看到的版本号检查结果 |
| 加密追踪 | 记录应用内的加密、解密与签名调用 |

使用路径固定四步：

1. 打开目标应用的快捷功能页；
2. 打开你要用的开关；
3. 启动目标应用；
4. 看屏幕效果或回项目里看日志。

开关只在 JsxposedX 里生效，目标应用要**从 JsxposedX 里启动**（或按当前运行模式重启一次）改动才会体现；停用开关后应用恢复原行为。个别系统版本和应用本身会限制部分拦截能力，开关开了没反应不代表操作错了，先对照 [常见问题与注意事项.md](常见问题与注意事项.md) 排一遍。

## 五、加密日志与规则编辑

打开「加密追踪」后，项目里会记录每次加密解密与签名调用，字段包括：算法名、Key、IV、输入、输出、调用堆栈、指纹。

日志之上还有一层「规则编辑」：你可以基于某条加密日志，把对应的调用目标替换、过滤或做其他处理。调试自己应用的数据收发逻辑时，这条链路（追踪 → 看日志 → 下规则）比直接写脚本快得多。

## 六、日志与数据都在哪

调试过程产生的日志统一存在对应项目的工作区里，回看调试过程、定位脚本问题都在项目内完成。日志会持续累积，长期使用记得定期清理或导出，免得把存储占满。
