## 一、先理解一件事：RPClient 只是客户端

你跟角色聊的每一句话，最终都由**你自己配置的模型服务商**生成。RPClient 负责拼提示词、发请求、渲染回复，不负责生成，也不提供任何模型服务 —— 所以模型 API 的**费用与内容责任由你自己承担**（官方 README 的免责口径）。

配置入口在 **设置 → 模型配置**。

## 二、用模板新建一条配置

官方内置了这些模板，选一个最接近你所用服务的即可：

| 模板 | 对应协议 | 你要填什么 |
| --- | --- | --- |
| ChatGPT（OpenAI 系） | OpenAI Compatible API | API Key、模型名、服务地址 |
| Gemini | Google Gemini API | API Key、模型名 |
| Claude | Anthropic Messages API | API Key、模型名 |
| DeepSeek | OpenAI Compatible | API Key、模型名 |
| Grok | OpenAI Compatible | API Key、模型名 |
| OpenRouter | OpenAI Compatible | API Key、模型名 |

不在表里也没关系：**新建配置时可以自定义服务地址、模型名、请求头与生成参数**，任何兼容 OpenAI / Gemini / Anthropic 三种协议之一的中转或自建服务都能接。

填完点**测试连接**，通过后再启用这条配置 —— 没启用的配置不会被会话使用。

## 三、三个必填项分别指什么

- **API Key**：服务商发给你的密钥。官方明确：**Key 只保存在应用本地，但会随每次模型请求发送给你配置的服务商**。
- **模型名**：服务商实际提供的模型标识（不同服务商写法不同，照服务商文档抄，别自己猜）。
- **服务地址**：请求发往的 base URL。用官方直连就填官方地址；用中转服务就填中转地址。

**只使用可信的 API 地址和中转服务** —— 地址填错或填了不可信的中转，你的对话内容与 Key 都会经它转发。这是官方在快速开始里单独强调的一条。

## 四、连不上时按这个顺序查

1. **测试连接**过不过 —— 不过先看是 Key 错、地址错还是模型名错（三者任一不对都会失败）。
2. 地址末尾的路径是否完整（有的中转要求带 `/v1` 之类路径，照服务商说明填）。
3. 手机网络能否直达该地址（部分服务在国内网络下需要自行解决连通性）。
4. 自建服务用了自定义证书链时，2026.3.1 起支持用户安装的系统级 CA 证书（**此条以版本为准**，旧版本无该能力）。

更完整的故障树见 [常见问题排查.md](常见问题排查.md)。

## 五、配置与对话的关系

- 一条会话跑在某条配置上；**换模型 = 换配置**，可以在模型配置里保留多条并切换。
- 生成参数（温度、最大回复长度这类）在配置里调，不同模型的合理取值不同，改动后观察几轮回复再定。
- 高级功能（提示词预设、宏展开、Token 预算、请求调试）也都围绕这条配置生效，属于 [世界书与提示词进阶.md](世界书与提示词进阶.md) 的范围。
- 官方提供**用量统计**（输入/输出 Token、请求数、按模型与主机汇总），随版本迭代会有增减，以你装的版本界面为准。

## 六、费用怎么算

RPClient 本身**免费开源**（MIT 许可），不向你收一分钱；你调模型 API 的花费由所选服务商按其价格计费，与 RPClient 无关。新手常见做法是先拿免费额度或低价模型跑通流程，确认体验后再换正式模型 —— 但**具体价格一律以服务商页面为准**，本文不写死数字。
