## 一、角色卡在 RPClient 里的地位

角色是这套客户端的核心对象：**没有角色就没法开会话**。角色相关的数据（人设、头像、开场白、示例对话、内嵌世界书与脚本）都存在本地，你可以随时导入外部卡，也可以把自己的卡导出带走。数据本地存储意味着换手机前记得先导出，别指望云端同步。

## 二、从零创建一个角色

1. 在首页点 **角色**。
2. 点 **创建**。
3. 在创建页填角色信息 —— 外表、性格、身世故事、对话风格这些都是你自由定义的字段，另有头像、**多个开场白**、示例对话与扩展字段可选。
4. 保存后回到角色列表，点该角色新建会话即可开聊。

角色建好后随时可以编辑；**示例对话**是给模型模仿说话风格用的，写几轮高质量对白比写一大段人设更管用（这是提示词层面的常识，不是官方结论，效果自己验证）。

## 三、导入现成的 JSON / PNG 角色卡

RPClient 兼容 SillyTavern 生态的角色卡格式：

| 格式 | 说明 |
| --- | --- |
| Character Card **V1** JSON | 早期通用格式 |
| Character Card **V2** JSON | 当前主流格式，字段更全 |
| **PNG 角色卡** | 元数据藏在图片里的卡，直接选 PNG 导入 |

- **单张导入**：角色列表里走导入入口，选文件即可。
- **批量导入**：2026.2.3 起文件选择器可一次多选，有解析/保存进度与成功失败汇总，单个失败不中断整批（**此条以版本为准**，网盘里 2026.1.2 是否包含以实际界面为准）。
- 卡里如果内嵌了世界书，导入时会提示低预算等情况；世界书本身怎么用见 [世界书与提示词进阶.md](世界书与提示词进阶.md)。

下载卡的时候留个心：**卡的版权与使用授权由其提供者和使用者负责**（官方免责声明原话口径），来路不明的卡别往里塞敏感个人信息。

## 四、导出与备份

- 可导出 **Character Card V2 JSON**，也可导出**带元数据的 PNG**（图即卡，方便分享与留档）。
- 官方强烈建议：**升级前备份重要角色卡、世界书与聊天记录** —— 项目仍在开发中，数据结构可能调整，导出的原始文件是你唯一的回退手段。
- 建议的备份节奏：每次大改人设后导一份、每次升级前导一份，JSON 与 PNG 择一即可（JSON 好读好改，PNG 好分享）。

## 五、导不进来 / 导入后不对劲

- **报格式错误**：先确认文件是 JSON 而不是改了后缀的网页文件；PNG 卡要确认图里真的带元数据。
- **人设缺字段**：部分卡用了 RPClient 尚未支持的高级字段 —— 官方明确它与 SillyTavern 在部分高级字段和运行行为上**仍可能存在差异**，这类差异不是你操作错了。
- **对话风格与预期差**：检查卡自带的世界书、Regex 脚本是否被启用（角色卡内嵌的 Regex 脚本**默认不会自动获得执行授权**，需要你手动放行），排查路径见 [世界书与提示词进阶.md](世界书与提示词进阶.md)。
- 反复失败时，用别的工具（或文本编辑器）打开卡确认内容完好，再对照 [常见问题排查.md](常见问题排查.md) 缩小范围。
