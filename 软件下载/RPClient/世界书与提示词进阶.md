## 一、这篇给谁看

模型和角色都配好之后，你大概率会撞上两类问题：**「设定明明写了，模型却不知道」**与**「世界书/脚本到底有没有生效」**。这篇讲的就是这两个问题的工具：世界书（知识注入）、Prompt 检查器（看真相）、Regex 脚本（消息改写）。每节都给你一条可执行的动作。

## 二、世界书：让角色带上世界观

世界书是 SillyTavern 风格的知识条目集合，RPClient 支持其**导入与导出**，以及这些触发配置：

| 配置项 | 你该怎么用 |
| --- | --- |
| 关键字扫描 | 给条目设触发词，消息里出现这些词就注入该条目 |
| 递归触发 | 条目内容里的词再触发别的条目，用于连锁设定；慎用，容易越滚越大 |
| 概率 | 同一关键字不一定每次触发，调低可减少重复灌入 |
| 优先级 | 多条命中冲突时，谁先注入 |
| 深度 | 注入到离当前消息多远的历史位置（越深越靠前，模型越当「背景」） |
| Token 预算 | 世界书总共允许占多少上下文，超预算的条目会被省略 |

操作路径：创建/编辑世界书 → 加条目与触发条件 → **关联到角色** → 新建会话时生效。**会话级**还可以单独选择本次用哪些条目 —— 同一个角色聊不同剧情时，只开相关那几条，能省下大量 Token。

几条写世界书的实操纪律（SillyTavern 生态文档的通行口径，RPClient 按同规则兼容）：

- **每条必须自含**：触发词本身不会发给模型，只有条目内容会 —— 写成「艾琳，22 岁，港口情报商，左眼有疤」这种独立成立的句子，别写「见上文」。
- **条目尽量短**：单条控制在几十 Token 量级（生态文档常建议 50 以内），长设定拆成多条按不同关键字分开触发。
- **预算耗尽就全停**：世界书的 Token 预算用完后，**即使后面的消息命中了关键字也不会再激活新条目** —— 所以常驻（固定注入）的条目优先占预算，非关键条目别设成常驻。
- **直接命中优先于连锁命中**：消息原文直接撞上关键字的条目，比从别的条目内容里间接触发的条目优先注入；递归触发开着时尤其要控制条目数量，否则几层连锁就把预算吃光了。

**自检动作**：设定没生效时别猜，直接看 Prompt 检查器（下一节）里「世界书命中」这一栏，命中了没、省略了没，一目了然。

## 三、Prompt 检查器：别靠猜

RPClient 内置 **Prompt Inspector**，能查看发给模型的**最终消息、Token 预算、世界书命中、Regex 处理与省略内容** —— 上一节说的「设定没生效」全靠它定位，用法：

1. 发一条消息后打开检查器（在会话的调试/检查入口，具体位置以你装的版本界面为准）。
2. 依次核对四件事：**最终消息**长什么样（人设有没有进去）、**世界书命中**哪些条目、**Token 预算**是否超了导致省略、**Regex** 有没有改写你的内容。
3. 结果与预期不符 → 回到对应章节改配置，改完再发一条验证。

配合**调试模式**（在本地记录并查看原始请求与响应 JSON）还能看到服务商实际返回了什么 —— 排查「是提示词的问题还是模型的问题」时，这两层对照着看最快。

## 四、Regex 脚本：改写消息的双刃剑

RPClient 兼容常见 SillyTavern Regex 脚本 JSON，关键概念：

- **作用域**：`Global`（全局生效）与 `Character`（仅当前角色）。
- **执行模式**：`Source`（处理原始文本）、`Markdown`（处理渲染后的文本）、`Prompt`（处理发往模型的文本）。
- 可排序、复制、**测试**、导入导出 —— 先测试再启用，别拿聊天记录赌正则。
- **安全闸门**：角色卡**内嵌**的 Regex 脚本**默认不会自动获得执行授权**，需要你手动放行。导入陌生卡后发现「消息被改了」，八成是这里。

## 五、提示词预设与宏

- **Prompt 预设**：一整套提示词组装方案，可保存切换，配合 [模型配置方法.md](模型配置方法.md) 里的多条模型配置使用。
- **宏展开**：提示词里用占位符，发送时替换成角色名、日期这类实际内容 —— 预设与角色解耦，换角色不用改预设。
- **Token 预算**：全局、预设、角色三级都有相应控制，检查器里能看到预算的去向。上下文塞不下时，先看预算表，再决定砍示例对话还是砍世界书条目。
