## 一、这条线跟普通聊天有什么不同

普通会话是一问一答的**聊天**；RPClient 另有两块玩法：**群聊**（多个角色互相说话，你旁观或插话）与**故事创作**（模型按你的引导在一篇连续正文的末尾续写，你改稿、分章、导出）。两块共用你在 [模型配置方法.md](模型配置方法.md) 里配好的模型与在 [世界书与提示词进阶.md](世界书与提示词进阶.md) 里配的世界书。

这篇只讲你会用到的操作与坑，界面细节以你装的版本为准。

## 二、群聊：让多个角色互相对话

1. 准备好几个角色（每个都要能独立说话，见 [角色卡导入与创建.md](角色卡导入与创建.md)）。
2. 走**新建群聊**的入口把角色都加进来（入口名称以界面为准）。
3. 发一条消息开局，之后模型会按群聊设定轮着生成各角色的发言。

注意两点：

- 群聊的上下文比单聊涨得快 —— 角色越多、人设越厚，越早撞上 Token 预算。预算怎么看、怎么砍，见 [世界书与提示词进阶.md](世界书与提示词进阶.md) 第五节。
- 发图片：2026.3.1 起支持单聊与群聊的图片消息（每条新消息最多 4 张，走 OpenAI-Compatible / Anthropic / Gemini 协议），**网盘里 2026.1.2 这版没有该功能**，以你装的版本为准。

## 三、故事创作：在文末续写连续正文

进入**故事创作**后，你面对的是一个连续正文编辑器，核心工作流：

1. **写引导**：开头给一段背景或大纲（相当于给模型的写作指令）。
2. **续写**：模型从文档末尾接着写；支持**流式生成、随时停止**，中断后能**恢复部分结果**。
3. **改稿**：直接编辑正文；会话内支持**多步撤销与恢复**，写崩了一路撤回来。
4. **分章**：按章节保存引导，之后每次续写都从该章末尾接着来 —— 长篇分段写靠的就是它。

支撑它的几件工具（都在故事界面内可达，位置以版本为准）：

| 工具 | 干什么 |
| --- | --- |
| Story Memory | 故事自己的长期记忆，跨章节记住设定 |
| 作者注释 | 你写给模型的指令，不混进正文 |
| 故事专属角色激活 | 只在本故事里启用某些角色 |
| 世界书匹配 | 续写时按 [世界书与提示词进阶.md](世界书与提示词进阶.md) 的规则注入设定 |
| Prompt Inspector | 看这次续写实际发了什么，正文没按设定走就查它 |

**自动保存**是本地防抖保存 —— 你正常打字它就存了，不用手动点保存；多设备/多窗口同时改同一份时有 revision 冲突保护，但别指望它做实时协作。

## 四、2026.2.3 起的生成过程可见

从 2026.2.3 开始，续写时有**实时生成状态卡**：分阶段显示上下文准备、等待响应、模型连接、构思、正文写入与保存；模型返回的**思考内容**可展开查看，且与章节正文分离、不会混进稿子（兼容 OpenAI-Compatible、Anthropic、Gemini 三种协议的推理内容）。生成耗时、慢响应也有提示。

也就是说：**卡住时先看状态卡停在哪个阶段** —— 停在「模型连接」是网络/配置问题（去 [常见问题排查.md](常见问题排查.md) 第一节），停在「构思」是模型在慢慢想。

## 五、导入导出：换设备与留档

- 正文可导出 **TXT / Markdown**，也可导出可迁移的 **`.rpstory.json` 归档**（含结构化数据，换设备或重装后导回）。
- 导入反向同样成立。**升级前先导一份** —— 官方对整个项目的态度就是「仍在开发中，重要数据先备份」，故事稿尤其如此（没有自动备份功能，全靠你手动导，见 [角色卡导入与创建.md](角色卡导入与创建.md) 第四节）。
- 世界书条目特别多的故事在导出时曾出过查询失败的问题（2026.3.1 修复），导不出时先升级版本再试。

## 六、三个高频问题

- **续写不按设定走**：打开 Prompt 检查器，依次看世界书命中、Token 预算、作者注释有没有进去 —— 排查路径与聊天模式完全一样，见 [世界书与提示词进阶.md](世界书与提示词进阶.md) 第三节。
- **续写跑飞 / 写偏**：先撤销回上一步，再把引导改具体（写清视角、人称、截止位置），比事后改稿省事。
- **摘要生成失败**：长期记忆与 Story Memory 的摘要也要花 Token，额度不足时应用会提示；新版不会用不完整结果覆盖已有有效摘要（旧版行为以版本为准），失败几次就去 [常见问题排查.md](常见问题排查.md) 第一节对表处理。
