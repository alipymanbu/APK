## 一、本篇解决什么

编译器报错分两种：**代码本身的问题**（头文件写错、语法错）和**环境的问题**（装不上、空间不够、库没装）。本篇按你实际会看到的报错原文排列，先对号入座再改。改完重新点运行按钮即可，报错窗口里的行号对应源码行。

## 二、`DEPRECATED HEADER` 警告：用了 `iostream.h`

报错原文类似：

```text
warning: DEPRECATED HEADER: You probably want to use <iostream> instead
```

**原因**：`#include <iostream.h>` 是上世纪 Turbo C 时代的旧写法，现代 C++ 标准里已经没有这个头。

**改法**：

```cpp
#include <iostream>
using namespace std;   // 或者在每个用到的地方写 std::cout
```

改完警告消失，`cout` / `cin` 正常可用。

## 三、`fatal error: 'graphics.h' file not found`

**原因**：`graphics.h` 是 Borland BGI 图形库的头文件，只存在于老的 DOS/TC 环境，Clang 工具链里根本没有它，网上抄来的老课件代码常带这一行。

**改法**（三选一）：

1. 删掉 `#include <graphics.h>` 及相关 BGI 调用（`initgraph`、`circle` 这类），先只保留逻辑部分；
2. 想在手机上画图形，改用 SDL2——先照 [安装第三方库教程.md](安装第三方库教程.md) 装好，再按 SDL2 的方式创建窗口绘制；
3. 只是想跑通作业代码：把图形段落换成控制台输出，验证算法部分。

## 四、`file not found` / 链接错误：库没装或没链上

| 报错形态 | 原因 | 处理 |
| --- | --- | --- |
| `fatal error: 'xxx.h' file not found`（非标准库头） | 该库没装，或头文件名拼错 | 照 [安装第三方库教程.md](安装第三方库教程.md) 装库；核对大小写 |
| `undefined reference to 'xxx'` | 头文件找到了但库没链接 | 确认库在包管理器里已安装完成，再重新编译 |
| 只在某个文件报、别的文件正常 | 该文件后缀不对，被按另一种语言编译 | 按 [新建文件与运行教程.md](新建文件与运行教程.md) 用 `Save as` 检查 `.c` / `.cpp` 后缀 |

## 五、中文输不进去

这是有用户反馈的高频问题，按命中率从高到低试：

1. **给应用输入法权限**：系统设置 → 应用管理 → Cxxdroid → 权限，确认输入法相关的权限已授予；
2. **换一个输入法试试**：部分输入法与该应用的兼容性差，切到系统自带输入法或另一款主流输入法（如搜狗）再试；
3. **手动切换输入模式**：用输入法自己的中英切换快捷键切到中文，而不是只点状态栏；
4. **升级版本**：旧版本存在中文输入适配问题，装新版本可能直接解决（以[官方商店页](https://play.google.com/store/apps/details?id=ru.iiec.cxxdroid)当时显示的最新版为准）。

代码里的中文注释要求文件编码是 utf-8，编码不对时注释会显示乱码（编码在编辑器里可切）。

## 六、装不上或打开就闪退

按 [下载与安装教程.md](下载与安装教程.md) 第二节核对两条硬条件：

- **提示未安装**：多半是 CPU 架构对不上——这份包是 `arm64` 的，32 位老手机装不了；
- **新款手机装旧版**：近年新机型改用 16KB 内存页，未适配的应用会装不上或一打开就闪退。5.6 的更新日志写明「16KB support」，先换 5.6_arm64 这份（见 [下载与安装教程.md](下载与安装教程.md) 第五节）再判断是不是别的问题；
- **装上但闪退/编译失败**：先查内部存储剩余空间，官方要求至少 150MB、推荐 200MB 以上，空间不足时编译大文件尤其容易出错。

## 七、找不到调试器

不用找了：官方把 Debugger 明确列在「尚未提供、正在开发」的清单里，这个版本没有断点和单步。实际排查靠两招——

1. **打印调试**：在可疑位置插 `printf` / `std::cout`，看变量走到哪一步；
2. **REPL 逐段验证**：把可疑的表达式拿到解释器模式里单独跑（见 [新建文件与运行教程.md](新建文件与运行教程.md) 第五节），先确认这段逻辑对不对再拼进程序。

另外按官方口径，程序运行时出错不会把整个 IDE 带崩——运行窗口挂了不代表应用坏了，关掉运行窗口接着改就行。
