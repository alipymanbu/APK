## 一、按症状对表排查

| 症状 | 常见原因 | 处理 |
| --- | --- | --- |
| 一直不开始画图 | 没听到有效信号；模式不在支持清单；静噪吞掉了图像开头 | 确认声源真的在发 SSTV；核对模式（见 [SSTV收图入门.md](SSTV收图入门.md) 的模式表）；接收机静噪全开 |
| 画面整体缓慢倾斜 | 收发两端采样时钟偏差，SSTV 的常见现象 | 轻微倾斜不影响辨认；解完后用图片工具旋转拉直（成因见下文「画面为什么会倾斜」） |
| 横向错位、撕裂 | 解码中途信号衰减或频率漂移 | 卫星接收按多普勒三步法跟频（见 [ISS空间站SSTV接收指南.md](ISS空间站SSTV接收指南.md)）；短波接收避开信号衰落时段重收 |
| 花屏、噪点密布 | 音量过载失真，或环境噪声混入 | 音量降到清晰不破音；换个安静环境；改用音频线直连（见 [音频线直连接收.md](音频线直连接收.md)） |
| 图像开头缺一截 | 没赶上校准头才开始解 | 等发送端发下一张；录音回放时从头播 |
| 颜色错乱、整体偏绿 | 信号弱导致频率判读出错；PD 系列模式对频率误差更敏感，校准偏差时常表现为偏绿（技术笔记反馈） | 把信号质量提上去，而不是反复调参数 |
| 切后台后停住 | 2.x 版不支持后台解码 | 保持应用前台亮屏，解码期间不要锁屏 |

## 二、画面为什么会倾斜

倾斜（slant）的成因是发送端与接收端的采样时钟有微小偏差，一行一行积累下来图像就歪了——这是 SSTV 的通病，不是 Robot36 独有的问题。

桌面解码软件对此有明确对策：MMSSTV、QSSTV 都提供斜率校正，量出你这块声卡的偏差并保存，之后自动修正（QSSTV 的常用修正量级在 0.001~0.005）。Robot36 没有对应的校正项（以你版本界面为准），倾斜明显时的实际选择：解完后用图片工具旋转拉直，或换一台时钟更稳的设备收。同一台手机收不同电台，倾斜程度会不一样——偏差来自两端。

## 三、关于后台解码

Robot36 从 2.x 重写版起不再支持后台运行：你切到别的应用或锁屏，解码就停了。收一张 PD120 要两分钟，期间把手机保持在前台、屏幕常亮（或临时把自动锁屏时间调长）。

## 四、录音回放补救

错过实时信号不代表丢图：

1. 接收机从信号出现前就开始录音（手机录音机、录音笔都行）；
2. 事后在安静房间把录音外放，用另一台装了 Robot36 的手机听；
3. 音质好的录音能完整还原一张图；录音本身失真严重的就救不回来了。

这段流程同样适用于「信号出现时你正好在忙」的场景——先录下来，晚上再解。

## 五、设置里可以动的项

2.14 里有「音频格式（Audio Format）」选项：解码遇到兼容性问题时（音质异常、偶发失败），在两个取值之间切换再试。其余显示类选项只影响观察、不影响解码结果；以你版本实际显示的选项为准。

## 六、都不行的时候

- 换一个声源验证应用本身正常：拿一段 SSTV 录音外放是最快的自检（示例见 [SSTV收图入门.md](SSTV收图入门.md)）；
- 同一段音频换台手机解，区分是设备麦克风的问题还是信号的问题；
- 确认是信号侧的问题后，把精力花在天线与摆放上，而不是反复重装应用。
