## 一、按用途选格式

导出前先想清楚作品要去哪，格式选错会白忙：

| 你要做什么 | 该导出什么 | 理由 |
| --- | --- | --- |
| 发朋友圈 / 微博 / 论坛 | GIF 动图 | 自动循环播放，平台直接支持 |
| 交游戏素材（Unity / Godot 等） | 精灵表 | 引擎按「一张大图 + 坐标」切帧，加载效率高 |
| 逐帧后期处理（剪辑软件、逐帧检查） | PNG 序列 | 每帧一个文件，方便逐张核对 |
| 静态图存档 / 打印 | PNG | 无损，调色板颜色不丢 |
| 继续回 Aseprite 编辑 | 应用自身的保存格式 | 保留图层、帧、标签信息 |

关键区别：保存（应用内右上角的保存图标）保住的是「可继续编辑的工程」，导出得到的才是「给别人看的成品」。工程文件在导出前一定要留一份。

## 二、导出 GIF 动图

GIF 是逐帧动画最常见的出口，导出时留意三个设置：

1. **播放循环**：循环开启后 GIF 会一直播；做一次性动效（比如开屏动画）才选不循环。
2. **帧时长**：按时间轴里设置的每帧时长生效；导出前先播放预览一遍，节奏不对回时间轴调。
3. **标签范围**：同一个文件里做了多段动画（用标签分组）时，按标签导出对应那一段，避免所有动作挤进一张 GIF。

导出后的 GIF 在手机相册或文件管理器里能看到，可以直接发出去。

## 三、导出精灵表给游戏引擎

精灵表（Sprite Sheet）把所有帧拼成一张网格大图。游戏引擎（Unity、Godot、GameMaker 等）导入后按格切帧即可驱动动画，这是像素游戏交素材的常规流程：

1. 在导出菜单选择精灵表输出。
2. 确认列数：例如 8 帧拼成 4×2，或按引擎要求的单行排列。
3. 引擎里导入这张大图，按「每格宽 × 高」切片，与帧顺序一一对应。

坐标换算有个省心诀窍：帧尺寸（画布大小）× 网格位置 = 每帧坐标，只要画布尺寸统一，引擎切片参数就是固定的。切完后在引擎预览里逐帧核对一遍顺序，与 Aseprite 时间轴一致才算交付完成。

## 四、导出 PNG 序列与单帧图片

- **PNG 序列**：每一帧存成一个独立 PNG 文件，命名按序号排列。适合需要逐帧在别的软件里加工、或想逐帧检查细节的情况。序号记得**补零**（`角色_01` 到 `角色_12`，而不是 `角色_1`），否则很多软件会按 1、10、11、2 的字典序排乱你的帧。
- **单帧静态图**：只要某一帧，选中那一帧导出 PNG 即可。透明背景会保留（画布外是透明的），放进别的软件时不会带白底。
- **给谁看决定导多大**：发社交平台、给朋友看，导出**放大整数倍**（×2、×4、×8）的 PNG，别人才能看清；进游戏引擎一律用原始尺寸，引擎自己负责缩放。非整数倍的拉伸（比如 ×1.5）会把像素挤糊，是像素图变「渣」的头号原因。

PNG、GIF、JPG、BMP 这类常见图像格式也能导入进来当素材改色、缩放——从 [Aseprite 安装文件资源（夸克网盘）](https://pan.quark.cn/s/8ea65b6f0dcf)装好应用后就能试。

## 五、导出后常见的坑

1. **GIF 颜色变脏**：GIF 最多 256 色，作品本身颜色远超这个数时会被压缩合并。导出前先把调色板收敛到 256 色以内（见[图层与调色板管理.md](图层与调色板管理.md)）。
2. **引擎里切帧切歪**：十有八九是帧尺寸对不上——检查画布尺寸是否统一，别中途改过画布。
3. **GIF 播放比预览快/慢**：帧时长设置和 GIF 播放器的最小间隔限制有关，导出前在预览里确认节奏，必要时把每帧时长整体调大一档。
4. **千万别用 JPG 存像素图**：JPG 的有损压缩专为照片设计，会在像素图的硬边周围抹出一圈圈杂色；静态图用 PNG，动图用 GIF。
5. **发出去的图发糊**：检查是不是被聊天软件二次压缩了——传原图，或导出前先放大整数倍再发（见第四节）。
