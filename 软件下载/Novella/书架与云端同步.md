## 一、书架上管什么

- **加书架**：详情页或阅读页把书加入书架，之后从书架直接续读，不用再搜。
- **阅读进度自动保存**：关掉应用再打开，回到上次那一章那一段。
- **书签与标记**：阅读中长按可加书签、做标记；下次从标记处直达。
- **阅读时长统计**：应用会累计你的阅读时长，按日/周/月/总的维度能查（具体分组以应用内为准）。

有人整理的资料里还写了「书架自定义分组（追更中 / 已完结 / 待看）」「划线高亮、笔记导出」这类条目——**这些在不同版本里可能有也可能没有，以你手上这版的界面为准**；本篇只把能多来源确认的部分当作结论。

## 二、同步是怎么走的：GitHub Gist

这是本应用与其他阅读器差别最大的一点，也是最容易卡住的一步：

- 同步载体是 **GitHub Gist**——你把书架、阅读进度、书籍标记、阅读时长写进一个自己的 Gist，另一台设备登录同一个账号、指向同一个 Gist，就能读到同一份数据。
- 换手机、重装应用之前**先做一次同步**，再折腾设备；装好后拉一次还原，书架与进度就回来了。
- 同步**免费**，没有隐藏付费项；前提是你得有一个 GitHub 账号。

## 三、换机/重装的推荐顺序

1. 旧设备：确认同步已开启且最近一次成功（联网状态下手动触发一次同步）。
2. 新设备：装好应用（见[下载与安装教程.md](下载与安装教程.md)）→ 登录同一账号（见[注册与登录教程.md](注册与登录教程.md)）→ 执行还原/同步，选择从 GitHub 还原。
3. 核对书架条目数与进度位置是否一致，再删旧设备上的应用。

**别在同步结果确认前清空旧设备**——数据只有一份时，顺序错了就找不回来。

## 四、同步、缓存、账号各管什么

三件事经常被混为一谈，出问题时先分清是哪一件：

| | 靠什么 | 换机时跟不跟着走 | 出问题看哪篇 |
| --- | --- | --- | --- |
| 登录 | 邮箱账号 | 账号本身当然通用 | [注册与登录教程.md](注册与登录教程.md) |
| 进度/书架/标记/时长 | GitHub Gist 同步 | 跟着走 | 本篇 |
| 书的文件（离线缓存） | 存储在本机 | **不跟着走**，要重下 | [找书与榜单筛选.md](找书与榜单筛选.md) |

同步出问题时也别急着清数据：先按下面的顺序排。

## 五、同步不生效时

- 两台设备必须指向**同一个 Gist、同一个账号**，这是最常见的错因。
- Gist 属于你的 GitHub 账号：token 失效、账号未授权，同步会静默失败。1.7.0 改进过「刷新令牌诊断」，同步异常时先看应用里的诊断提示。
- 有用户反馈同步会抽风、书架条目特别多时卡顿（第三方页面的用户评论，**单一来源，仅作参考**）——遇到时先手动触发一次同步、确认网络能访问 GitHub，再判断是不是版本问题。
- 仍解决不了的，见[常见问题与故障排查.md](常见问题与故障排查.md)。
