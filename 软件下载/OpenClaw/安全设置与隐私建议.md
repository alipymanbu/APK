## 一、为什么安全设置不能跳过

给助手接上渠道，意味着它有资格在你的主机上执行命令、读写文件、用你的账号发消息——这是它「能干活」的前提，也是风险的来源。官方文档开篇就建议从保守设置起步，下面这份清单照做一遍，能挡掉绝大多数意外。

这不是杞人忧天：据公开报道，有用户的长对话触发了上下文自动压缩，把「动手前先确认」的指令挤丢，邮箱被助手批量清空；中国国家互联网应急中心也在 2026 年 3 月专门发过针对 OpenClaw 的[风险提示](https://www.cert.org.cn/publish/main/11/2026/20260312144519429724511/20260312144519429724511_.html)，点名提示词注入、误删数据、恶意插件、已知漏洞四类风险。

## 二、上线前先做的七件事

1. **渠道加白名单**：只允许你自己的号码/账号跟助手说话（比如 WhatsApp 的 `allowFrom`），不要开「谁来都能聊」；
2. **给助手用专用号码/账号**：别把主力私人号接上去，误触发时损失可控；
3. **先关心跳**：默认每 30 分钟自动跑一轮任务，既消耗模型用量也可能自作主张，不熟之前把 `agents.defaults.heartbeat.every` 设为 `"0m"` 关掉，用熟了再按需开；
4. **设好访问认证**：控制台与网关的访问凭据（令牌或密码）别用默认值裸奔；
5. **别把网关端口暴露公网**：需要远程就走 Tailscale Serve 这类带加密的通道，明文连接只限局域网；
6. **只从可信渠道拿安装包**：官方渠道是 Google Play 与 GitHub 发布页；从别的途径拿包，先核对文件指纹（本次网盘里那份的 MD5 见 [下载与安装教程.md](下载与安装教程.md)）；
7. **及时升级版本**：项目已公开曝出过多个中高危漏洞，别长期停在旧版本，更新注意什么见 [常见问题排查.md](常见问题排查.md) 的更新一节。

清单里的命令白名单、文件读写边界怎么落成具体配置，见 [限制助手权限的配置方法.md](限制助手权限的配置方法.md)。

## 三、日常用的时候

- **看住它的记忆**：助手的工作区就是主机上的一个文件夹（默认 `~/.openclaw/workspace`），里面的笔记、记忆都是普通 Markdown 文件，你不放心它记了什么、给了它什么设定，直接打开看、直接改；
- **按需开工具**：命令执行、浏览器操作这类真会动你设备的工具，按需启用，用不到就关；
- **敏感操作留审批**：涉及发消息、动文件的任务，先在监督模式下看它打算怎么做，再逐步放开；
- **密钥当密码管**：模型 API 密钥与网关凭据不要写进聊天记录、不要发给别人，泄露过一次就全部更换。

## 四、出事了怎么办

- 怀疑助手行为异常：先停掉主机上的服务（主机上执行 `openclaw gateway stop`，以官方文档为准），再翻工作区文件夹和控制台日志，定位它做了什么；据公开报道，有用户在手机上拦不住正在跑的任务，最后是跑到主机上才停掉的——所以提前想好怎么远程管理主机；
- 渠道账号疑似被滥用：立刻改账号密码、吊销会话，检查渠道白名单是否失效；
- 主机被陌生人连过：检查网关是否暴露过公网、凭据是否是弱口令，然后按上面第二节重新收紧一遍。

更多取舍与官方建议以 [docs.openclaw.ai](https://docs.openclaw.ai/zh-CN/) 的安全章节为准；排查过程中的其他状况见 [常见问题排查.md](常见问题排查.md)。
