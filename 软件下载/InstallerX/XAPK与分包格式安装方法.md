## 一、先分清拿到的是哪种包

现代应用越来越多以"分包"形式发布（官方商店按你机型只发对应部分，第三方渠道则把全部分部打进一个容器），先看后缀：

| 后缀 | 里面是什么 | 系统能否直接装 |
| --- | --- | --- |
| .apk | 单个完整安装包 | 能，无需本篇 |
| .apks | base.apk 加按架构/语言/分辨率拆分的分包集合 | 不能 |
| .xapk | 本质是 ZIP 容器：分包 APK + OBB 数据文件 + 描述信息 | 不能，文件管理器会把它当压缩包打开 |
| .apkm | 分包的另一种容器格式（APKMirror 系） | 不能 |
| .obb | 单独的游戏数据文件，不独立安装 | 装完 APK 后要放到位（见第三节） |

大体积游戏最容易以 XAPK 形态出现：APK 部分装应用本体，OBB 部分装素材数据，两者缺一个应用都跑不起来。

## 二、用 InstallerX 装分包格式

1. 在文件管理器里点开 .xapk / .apks 文件，打开方式选 InstallerX；
2. 它会解析容器内容，分包自动按你设备的架构与语言挑选，你确认安装即可；
3. 含 APK 的 ZIP 压缩包同样可以直接指给 InstallerX，不用先解压。

有一点要记住：**分包必须一次事务装完**。手动把容器解开、逐个装里面的 APK 必然失败——系统要求全部分包在同一次安装里提交。这也是"用支持分包的安装器"这件事存在的意义。

## 三、装完应用打不开或提示缺数据

包装成功但应用闪退、或进游戏提示重新下载数据，最常见的原因是 OBB 没就位：

- 安装器一般会把容器里的 OBB 自动放到位；如果应用仍然提示缺数据，手动解包 XAPK，把 OBB 文件放进手机的 `Android/obb/<应用包名>/` 目录，目录名必须与包名逐字一致；
- 架构不匹配是另一类闪退原因：包里只有 64 位分包而设备是 32 位系统（或反过来），换对应架构的包重新装。

## 四、分包相关报错对照

| 报错关键词 | 原因 | 处理 |
| --- | --- | --- |
| INSTALL_FAILED_MISSING_SPLIT | 分包没装全 | 整包重新走 InstallerX 装一遍，别手动挑里面的单个 APK |
| INSTALL_FAILED_UPDATE_INCOMPATIBLE / 签名冲突 | 设备上已装同名应用但签名不同（别的渠道装的） | 先卸载旧版再装，数据会丢，先备份 |
| 解析失败 | 包损坏，或系统版本低于应用要求 | 重新下载包；核对应用的系统版本要求 |
| 下载校验不通过 | 包在传输中损坏 | 核对文件 MD5 后重新获取 |

不属于分包范畴的通用报错，去 [安装失败排查方法.md](安装失败排查方法.md) 对号入座；想调降级、装后删包这类安装行为，见 [安装选项设置指南.md](安装选项设置指南.md)。
