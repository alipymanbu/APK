# GKD 无障碍权限开启失败怎么办

> 无障碍开关点不动、提示「受限制的设置」、ADB 授权报错、每次开启都要等 10 秒警告 —— 四类问题对号入座，各给解法。
> **相关文档**：[下载与安装教程.md](下载与安装教程.md) · [后台保活与耗电优化.md](后台保活与耗电优化.md) · [常见问题与使用技巧.md](常见问题与使用技巧.md)

> **GKD 安装文件资源（夸克网盘）**：[https://pan.quark.cn/s/28645b53c722](https://pan.quark.cn/s/28645b53c722)

GKD 的自动点击完全依赖无障碍服务，这一步卡住后面全都免谈。国产系统对无障碍的限制一年比一年严，尤其对「不从应用商店装的应用」。先对照下面的现象表找到你的情况，再按对应小节处理。

## 一、先对号入座

| 你遇到的现象 | 看哪一节 |
| --- | --- |
| 无障碍列表提示「受限制的设置」「系统已拒绝向此应用授予访问权限」 | 第二节 |
| 提示受限制的设置，但应用信息里找不到「允许受限制的设置」选项；或开关能点但点了没反应 | 第三节 |
| 想用 ADB 授予「写入安全设置权限」，报 SecurityException 权限不够 | 第四节 |
| 能开，但每次开启都有 10 秒倒计时警告弹窗 | 第五节 |

另有一种不算「开不了」的情况：之前开着好好的，过段时间发现无障碍被系统**自动关掉了** —— 那是省电策略清理后台时顺手摘掉的，处理办法在[后台保活与耗电优化](后台保活与耗电优化.md)。

## 二、「受限制的设置」：允许受限制的设置

这是系统对非商店来源安装应用的普遍限制，解法是把 GKD 加入受信任范围：

1. 打开系统的 应用信息（长按 GKD 图标 → 应用信息）；
2. 找到「允许受限制的设置」开关并打开 —— 各系统位置不同：

| 系统 | 路径 |
| --- | --- |
| 原生类系统 | 应用信息 → 右上角菜单 → 允许受限制的设置 |
| 小米 / HyperOS | 应用信息 → 高级设置 → 允许受限制的设置 |

3. 开完回到无障碍列表重新开 GKD；仍然提示不可用的话，**重启设备**再试。

## 三、ColorOS 等更严格系统

OPPO/一加的 ColorOS 限制更进一层：要么找不到「允许受限制的设置」，要么开关能点但毫无反应。可行的几条路（按顺序试）：

1. **用系统文件管理器重装一遍**：在 GKD 内 设置 → 关于 → 分享应用，把 APK 存到本机，再用系统自带的文件管理器找到它点安装 —— 这是覆盖安装，不用卸载。系统对「经系统文件管理器安装」的应用更信任；
2. 如果你冻结过系统安装器 `com.oplus.appdetail`，先解冻再按第 1 条重装；
3. 用 [App Ops](https://appops.rikka.app/) 在权限管理里手动授予 `ACCESS_RESTRICTED_SETTINGS` 权限（适合有折腾经验的人）。

## 四、ADB 授权「写入安全设置权限」

授予这个权限后，你可以直接在 GKD 应用内开启无障碍，不再需要往返系统设置页。电脑连手机执行：

```bash
adb shell pm grant li.songe.gkd android.permission.WRITE_SECURE_SETTINGS
```

如果报 `SecurityException: Neither user 2000 nor current process has android.permission.GRANT_RUNTIME_PERMISSIONS`，是厂商系统额外锁了一道，按机型处理：

| 系统 | 解法（都在开发者选项里） |
| --- | --- |
| HyperOS / MIUI（小米、POCO） | 开启「USB 调试（安全设置）」——注意不是普通的「USB 调试」；仍报错可尝试在 adb 命令前加 sudo |
| ColorOS（OPPO、一加） | 关闭「权限监控」或打开「禁止权限监控」 |
| Flyme（魅族） | 关闭「Flyme 支付保护」 |

关掉对应开关后重新执行命令即可。

## 五、每次开启都有 10 秒警告弹窗

这是多数设备开无障碍时的固定流程，两种办法绕开：

- **给 GKD 授予「写入安全设置权限」**（见第四节），之后在应用内即可自行开启无障碍，不走系统弹窗流程 —— 官方推荐的做法；
- **利用无障碍页的「快捷方式」开关**：开启一次后，上面的开启按钮就不再弹警告。代价是屏幕侧边会出现一个小图标，不想要就在 无障碍界面 → 无障碍按钮 → 使用按钮或手势，切换为「手势」即可隐藏。

两种都解决不了的话（少数机型），那就老实等 10 秒 —— 开启是一次性操作，影响有限；比起这个，更要紧的是确认后台不被杀，见[后台保活与耗电优化](后台保活与耗电优化.md)。
