规则没跳对、想自己写规则、想找人帮忙看某个界面 —— 三件事的最后一步都是同一个动作：抓一份快照。快照把「当时屏幕长什么样、控件结构是什么」完整存下来，你不用反复守着一个出现频率很低的界面，拿到的人也能离线分析。

## 一、快照里存了什么

一个快照是一个 zip 文件，保存设备在某个时间点的状态，包含四类内容：截图、设备信息、界面信息、无障碍节点信息。对写规则的人来说最后一样最关键 —— 规则的 `matches` 选择器就是对着这些节点写的。

抓快照有一个硬前提：**无障碍权限必须开着**，否则拿不到界面信息和节点信息。截图部分分两种情况：Android 11 及以上可以直接通过无障碍权限取到截图；Android 10 及以下需要在 主页 → 设置 → 高级设置 → 截屏服务 里额外开启，不开的话快照里的截图会用一张同尺寸的透明图片占位（节点信息不受影响）。

## 二、五种抓取方式，挑顺手的

| 方式 | 怎么开 | 适合场景 |
| --- | --- | --- |
| 悬浮窗按钮 | 主页 → 设置 → 高级设置 → 悬浮窗服务 | 日常最常用，屏幕上出现一个可拖动的小按钮，在任意界面点它就抓 |
| 状态栏快捷开关 | 下拉状态栏 → 编辑 → 添加「捕获快照」 | 不想常驻悬浮按钮的 |
| 审查工具 | 主页 → 设置 → 高级设置 → HTTP 服务，在电脑浏览器打开 [i.gkd.li/device](https://i.gkd.li/device) 输入显示的地址连接，点右侧「快照」 | 想在电脑上直接分析节点结构的 |
| 截屏快照 | 高级设置 → 截屏快照，配置应用 ID 和特征事件选择器 | 想用系统截屏手势顺手抓快照的（配置较繁琐，官方文档有教程） |
| 调用服务 | 外部应用启动 GKD 暴露的服务（`sh /storage/emulated/0/Android/data/li.songe.gkd/files/sh/expose.sh`） | 配合快捷手势应用做自定义触发 |

抓完的快照在快照记录页查看（主页的快照记录，或深链 `gkd://page/2` 直接跳过去）。另外 GKD 每次执行点击前后都会留有快照记录，怀疑它「点错了」时翻这里能回放现场。

## 三、上传分享：先去掉隐私

把快照发给别人（订阅作者、GitHub issue）需要先上传拿到链接，常见做法是传到 GitHub 得到一个 `i.gkd.li` 开头的分享链接。两种入口：

- **审查工具**（电脑端）：生成分享链接时自动完成上传，最省事；
- **应用内生成链接**：需要你手动填 GitHub Cookie 作为上传凭证 —— 电脑浏览器登录 GitHub 后按 F12 打开调试面板，在网络（Network）里刷新出 `github.com` 记录，从请求标头里复制整串 Cookie，粘进 GKD 的高级设置里。

上传前必须知道的一条：**传到 GitHub 就等于公开**，快照里可能带着你的截图和界面内容。官方文档专门提供了「去除隐私信息」的处理流程，分享前先过一遍；涉及账号、聊天记录的界面宁可不传。

## 四、快照怎么用在规则上

- **自己写规则**：在审查工具里打开快照，可以直接测试选择器表达式能不能选中目标节点，选中了再抄回本地订阅的 `matches` 里，不用在手机上反复试错；
- **报给别人**：把快照链接贴进订阅仓库的 issue，作者对着快照改规则，比文字描述「某某应用开屏广告跳不掉」有效得多；
- **对照现成规则**：默认订阅和第三方订阅里的规则示例通常都带 `snapshotUrls` 字段，那就是该规则作者抓的快照链接，点开就能看到这条规则对应的界面长什么样。

想从快照走到写出第一条自己的规则，先看[订阅规则添加方法](订阅规则添加方法.md)里本地订阅一节；规则写了还是不生效的，去[开屏广告没跳过怎么排查](开屏广告没跳过怎么排查.md)按顺序过一遍。
