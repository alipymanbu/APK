GKD 装好、无障碍授权完之后还不会自动点任何东西 —— 它按规则工作，规则里写着「什么界面出现什么元素就点什么」。规则的来源是「订阅」：订阅页里勾上要用的规则组，它才会在对应应用里生效。本篇把订阅这件事从概念到操作讲完。

## 一、先分清：远程订阅与本地订阅

两者的文件格式完全一致（JSON5，JSON 的兼容扩展，支持注释），区别只在维护方式：

| 类型 | 谁维护 | 更新方式 | 适合谁 |
| --- | --- | --- | --- |
| 远程订阅 | 订阅作者 | 加一个链接，应用自动拉更新 | 绝大多数人 |
| 本地订阅 | 你自己 | 手动改，不自动更新 | 有个别应用想自己写规则的 |

位置都在：首页 → 订阅。本地订阅在「本地订阅」一项下，包括应用规则、全局规则、规则类别。

## 二、默认订阅是内置的，勾选启用即可

GKD 自带「GKD 默认订阅」，不用你加链接 —— 打开 订阅 页就能看到。它覆盖了大量常见应用的跳开屏广告、关闭弹窗场景，规则组按应用分组：

1. 打开 首页 → 订阅 → GKD 默认订阅；
2. 找到你常用的应用，把对应规则组的开关打开（也可以开「开屏广告」这类全局组）；
3. 开多少由你定 —— 规则组开得越多越耗电，官方 FAQ 原话是默认订阅规则数量有 1300+，全开并不划算，取舍见[后台保活与耗电优化](后台保活与耗电优化.md)。

只勾自己常用应用的那几组，是收益和耗电最平衡的用法。

## 三、添加第三方订阅源

想在默认订阅之外再加源：订阅页点添加 → 粘贴订阅链接 → 保存后它会自动检查更新。常见第三方订阅源（链接与规模随来源页面变化，以各订阅仓库当时说明为准，截至 2026-09 的公开介绍如下）：

| 订阅源 | 链接 | 介绍 |
| --- | --- | --- |
| AIsouler | `https://raw.gitmirror.com/AIsouler/GKD_subscription/main/dist/AIsouler_gkd.json5` | 覆盖约 684 个常用应用、1500+ 规则组 |
| Adpro-Team | `https://raw.gitmirror.com/Adpro-Team/GKD_subscription/main/dist/Adpro_gkd.json5` | 覆盖约 621 个主流应用、1400+ 规则组，第三方介绍称作者已停更 |

两个提醒：

- 这两个源都 fork 自默认订阅，**同时开启多个同源订阅等于重复规则叠加**，只多耗电不多办事，选一个用就好；
- 第三方订阅的规则质量参差，某个应用行为奇怪时先怀疑它的规则组，把它单独关掉试；
- 想再多翻翻，在 GitHub 上搜 `gkd-subscription` 还能找到更多社区维护的订阅源 —— 加之前先看它的仓库最近还有没有更新，久不更新的源规则会越来越失准。

## 四、本地订阅：自己写规则

入口：首页 → 订阅 → 本地订阅。有三层东西可以填：

### 应用规则（对单个应用生效）

```json5
{
  id: 'com.zhihu.android',
  name: '知乎',
  groups: [
    {
      key: 0,
      name: '开屏广告',
      rules: { matches: 'TextView[id="com.zhihu.android:id/btn_skip"]' },
      snapshotUrls: ['https://i.gkd.li/i/13070251'],
    },
  ],
}
```

`id` 填目标应用的包名，`matches` 是选择器表达式，写「什么控件」；`snapshotUrls` 放这条规则对应的快照链接（上面示例引自官方文档），点开就能看到规则作者对着哪个界面写的这条规则。想自己写但不知道控件长什么样，用快照功能先抓界面再照着写，完整流程见[快照捕获与规则调试](快照捕获与规则调试.md)。

### 全局规则（所有界面生效）

```json5
{
  key: 0,
  name: '开屏广告',
  fastQuery: true,
  matchTime: 10000,
  actionMaximum: 1,
  resetMatch: 'app',
  rules: [
    { key: 0, matches: '[text*="跳过"][text.length<10][visibleToUser=true]' },
  ],
}
```

这条的含义是：界面出现 10 个字以内带「跳过」的可见文字就点它，应用切换后重新匹配。`matchTime`、`actionMaximum` 这类限流参数建议保留，防止误点和反复触发 —— 它们决定规则触发几次后休眠、什么时候重新生效，具体含义和「跳过一次后不再跳」的关系见[开屏广告没跳过怎么排查](开屏广告没跳过怎么排查.md)。

### 规则类别

给规则组分类命名用，输入类别名确认即可，纯整理功能。

## 五、启停粒度建议

- 默认订阅按应用勾选，别整包全开；
- 第三方订阅最多开一个；
- 某个应用跳得不对时，先关它的规则组单独验证，而不是全局关掉；
- 自己写的规则先用小范围（单应用）验证，稳定了再考虑放进全局。

装好后规则该开的开了还是不跳，排查思路见[常见问题与使用技巧](常见问题与使用技巧.md)。
