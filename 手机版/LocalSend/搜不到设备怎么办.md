# LocalSend 搜不到设备怎么办

> 「附近的设备」列表空着、看不到对方？九成是网络没对齐、权限没给、或防火墙/路由器拦了。本篇按命中率从高到低给一套排查顺序，最后一节是一定能连上的兜底办法。

## 一、先花一分钟核对这四件事

- **是不是同一个网络**：手机和电脑的 Wi-Fi 名称要一样。注意路由器的「访客网络」——访客网和主网之间默认互相看不见，连访客网的设备永远发现不了主网设备。
- **两端 App 是不是都开着**：把 App 从后台划掉就不再广播了，两端都重新打开一次。
- **你在看哪一台**：设置里的「别名」就是你这台设备被别人看到的名字，改法见 [修改保存位置与自动接收设置.md](修改保存位置与自动接收设置.md)，排除「其实连的是别的设备」这种情况。
- **两端版本是否一致**：有用户反馈一台是很旧的版本、另一台是新版本时会连不上——把两端都升到同一版本再试，以官方下载页当时显示的版本为准。

## 二、手机这端：权限给了吗

- **安卓**：系统「设置 → 应用 → LocalSend → 权限」里，「附近设备」「位置」（部分机型扫描 Wi-Fi 要求位置权限）都要允许；通知权限也一并给了，否则收到了也没有弹窗。
- **iPhone**：「设置」里找到 LocalSend，打开「本地网络」开关。这一项是 iOS 独有的，没开就什么都搜不到。

权限问题的典型特征是：电脑能看到手机、手机看不到电脑（或反过来），只有一头瞎。

## 三、电脑这端：防火墙放行 53317

默认端口是 **53317**，入站方向的 **TCP 与 UDP 都要放行**，出站保持放行。Windows 上：

1. 开始菜单搜索「通过 Windows 防火墙允许应用」，点进去后按「更改设置」。
2. 列表里找到 LocalSend，「专用网络」和「公用网络」两列都打勾。
3. 列表里没有它，点「允许其他应用」，浏览到安装目录选中 `localsend.exe` 再勾上。

macOS/Linux 遇到同类问题也查本机防火墙规则。放行之后两端把 App 各重启一次再看列表。

## 四、路由器：关掉 AP 隔离

路由器开了「AP 隔离 / 客户端隔离 / 无线设备互相访问限制」时，同一 Wi-Fi 下的设备之间不转发流量——两台设备都联网正常，唯独互相找不到。处理：

1. 浏览器进路由器管理页（地址常见为 `192.168.1.1` 或 `192.168.0.1`，以机身铭牌为准）。
2. 在无线设置或安全设置里找「AP 隔离」「客户端隔离」「允许无线设备互相通信」这类开关，关掉隔离 / 允许互访。
3. 部分路由器把「访客网络」默认设为隔离，最省事的做法是所有设备都连主网络。
4. **没有路由器管理权限时**（公司网、咖啡厅、别人家的 Wi-Fi）改不动这条——直接换成手机热点自建网络，绕开隔离，步骤见 [没有WiFi时用手机热点互传.md](没有WiFi时用手机热点互传.md)。

## 五、VPN、虚拟网卡先临时关掉

VPN 会改写本机路由，局域网发现经常直接失效；Docker、安卓模拟器装出来的虚拟网卡偶尔也来捣乱。排查时先把 VPN 断开、相关虚拟网卡禁用，确认能搜到之后再逐个恢复——如果你的 VPN 支持「局域网流量不走 VPN」的分流选项，把它对 LocalSend 放开即可长期共存。

## 六、端口被别的程序占用

启动时报 `Failed to create server socket`，或怀疑 53317 被别的程序占了：

1. 两端都进「设置 → 高级设置 → 网络 → 端口」，改成同一个新端口（例如 `53318`）。
2. **两台必须改成一样的值**，只改一台会互相找不到。
3. 改完把 App 完全退出再打开。

## 七、兜底：手动输入 IP 直连

在对方设备的设置页能看到它的局域网 IP（形如 `192.168.1.23`）。在你的「发送」页用「输入地址 / 手动添加设备」，填入这个 IP，就能跳过自动发现直接连上。

这一步很有诊断价值：**手动能连、自动搜不到，问题一定出在发现环节**——回头重查第四节的路由器隔离与第二节的权限；手动也连不上，则多半是第三节的防火墙，或两端根本不在同一网络。
