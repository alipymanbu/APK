## 一、先记住一句：测速是"真下载、真上传"

测速不是发一个探测包看看延迟就完事，它要在几秒到十几秒里**把你的带宽压满**——只有把管道塞满，量出来的才叫最大速率。因此它下载和上传的都是真实数据，会实打实计入你的流量。

这也解释了那个反直觉的现象：**网速越快，一次测速消耗的流量越大**——测速程序会照着你的带宽去塞数据，管道越粗，同样几秒钟里灌进去的量就越多。所以"我什么都没干，流量怎么少了"这件事，如果刚好测过一次速，就不是异常。

## 二、一次完整测速大概用多少

华为在其官方支持页面给出过一组行业内通用的参考值，按带宽分档，可以用来估算（实际消耗还受当时网络是否稳定影响，以官方页面为准）：

| 连接带宽 | 一次完整测速的流量消耗 |
| --- | --- |
| 50 Mbps | 约 70 MB ~ 95 MB |
| 100 Mbps | 约 140 MB ~ 185 MB |
| 300 Mbps | 约 420 MB ~ 555 MB |
| 500 Mbps | 约 600 MB ~ 900 MB |
| 850 Mbps | 约 1000 MB ~ 1250 MB |

照这张表换算：家里是 300M 宽带，用移动数据测一次就是几百兆，连测三次就接近 1.5 GB，所以这类测试应该连 Wi-Fi 做；只有要验证"移动网络本身快不快"时，才值得用流量测一次。

## 三、哪些部分的消耗可以忽略

一次完整测速的流量几乎全在下载和上传这两段。下面这些部分的数据量小到可以忽略：

| 测的项目 | 流量量级 |
| --- | --- |
| 延迟（Ping） | 极小，几十字节的小包来回 |
| 抖动 | 极小，本质上就是反复测延迟 |
| 丢包率 | 极小，若干个小探测包 |
| 下载 / 上传速率 | **大头，按上表的量级走** |

也就是说，如果你的套餐流量很紧、只想看看网络卡不卡，那么"只关心延迟"这种需求是低成本的；一旦开始测速率，流量就按带宽成比例地花出去。

## 四、流量紧张时的几条做法

1. **先连 Wi-Fi 再测**：只有要验证"移动网络本身快不快"时，才断开 Wi-Fi 用流量测。
2. **别连着反复测**：连续测 3 次就是 3 份流量，不是只有第一份。要测就一次测到位、结果留在历史里。
3. **跑大流量的功能前先看一眼**：测速、网络诊断、边走边测都会真实走流量，其中边走边测因为持续时间长、次数多，是三者里最费的，见 [网络诊断与游戏测速怎么用.md](网络诊断与游戏测速怎么用.md)。
4. **流量套餐有封顶的要格外注意**：部分套餐到达流量上限后会被限速，测出来的速度会一直偏低，容易被误判成"网络出问题"。这种情况看 [测速不准和结果波动怎么排查.md](测速不准和结果波动怎么排查.md) 里的排查顺序，先确认是不是被限速了。
5. **在手机上查消耗**：系统的"流量管理 / 数据使用"里能看到这个应用走了多少，测完顺手对一下，心里就有数了。
