## 一、先如实说清性质

FunBox 通过 LSPosed 框架注入微信 / QQ 的进程来加面板 —— 这是你对自己设备上客户端行为的改动，**超出微信与 QQ 官方的支持范围**。由此带来三件事，用之前想清楚：

- **账号层面没有任何官方承诺**。出问题时这不是微信、QQ 官方客服会受理的范畴，取舍只能自己判断。
- **面板运行在聊天进程内**。它的保存、推荐功能会接触到你在聊天窗口里的内容，表情推荐就是据此做的；介意这一层的话，把推荐类开关关掉，只用手动存发。
- **没有可查的官网**。第三方插件仓库的收录信息标注开发者为 Hicores，版本更新跟着各分发渠道走，判断依据以渠道当时显示为准。

## 二、高危功能不要碰

- 开发者早在更新日志里**移除了自动抢红包功能**（v5.3.0），社区流传的集成版说明也把抢红包明确列成禁止的高危功能 —— 这类自动化操作是账号风控重点盯的行为，别去找替代实现。
- 宣称能「解锁隐藏功能」、或要你付费才给包的渠道，都不是这个模块的正常口径，绕路走。

## 三、把风险压低的几件事

| 做法 | 原因 |
| --- | --- |
| 作用域只勾微信 / QQ，不勾「系统框架」和不相干的应用 | 出问题的面最小，也降低被其他应用检测到框架的概率 |
| 拿常用小号先试跑几天 | 真有风控，损失可控 |
| 不在模块生效的客户端里登录支付、银行类应用 | 这类应用会检测运行环境，与模块无关但会一起出问题 |
| 想走免 Root 内置路线的，先读注意事项再决定 | 装的是第三方改过的聊天软件本体，来源与更新都受制于打包者，见 [免Root内置版注意事项.md](免Root内置版注意事项.md) |
| 微信 / QQ 自动更新后先观察面板是否正常 | 模块适配跟随聊天软件版本，本体大版本升级后入口或长按菜单失效是常态 |
| 折腾降级、重装前先备份聊天记录 | 用微信自带的「聊天记录备份与迁移」，任何回退操作前都先备份 |

## 四、卸载与回退

- **只想停用**：LSPosed 里关掉 FunBox 开关并取消作用域，再强制停止微信 / QQ。
- **彻底移除**：直接卸载 FunBox 这个应用即可。它不改微信 / QQ 的安装包，卸载后聊天软件回到原生行为，不需要额外清理。
- **本体升级导致模块失效**：先停用模块观察本体是否正常，等适配了再开。不要回退微信 / QQ 版本硬扛 —— 回退丢数据的风险比模块失效大得多。
