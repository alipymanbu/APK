## 一、三种模式一句话区分

- **Local 模式（MJPEG）**：手机和观看设备在同一个网络里，浏览器直接打开一个地址看画面。不用互联网，没有声音。
- **Global 模式（WebRTC）**：观看的人不在同一网络也能看，通过一个串流 ID 和密码在网页里连。要互联网，有声音。
- **RTSP 模式**：把画面推给 VLC 这类播放器或流媒体服务器，属于更"专业"的接法。有声音。

三个模式相互独立，同一时间你用哪个取决于你点开哪一个模式页去启动。

## 二、对照表

| 对比项 | Local 模式（MJPEG） | Global 模式（WebRTC） | RTSP 模式 |
| --- | --- | --- | --- |
| 观看入口 | 浏览器打开手机显示的地址 | 浏览器打开官方网页客户端，输入串流 ID + 密码 | VLC、FFplay、mpv 等播放器 |
| 要不要互联网 | 不用，局域网就能跑 | 要 | 服务器模式不用；客户端模式取决于外部服务器 |
| 声音 | 没有 | 有（麦克风和设备内部声音） | 有（随编码配置） |
| 画面 | 一连串 JPEG 图片 | WebRTC 视频 | H.264 或 H.265 视频 |
| 加密 | 无加密，可选 4~6 位 PIN 防陌生连接 | 端到端加密 + 密码 | 客户端模式支持 RTSP 身份验证与 RTSPS（TLS） |
| 观看人数 | 不限，但每个人各占一份带宽 | 不限，但每个人各占一份上行带宽 | 取决于播放器或服务器侧 |

## 三、按你的场景选

| 你要做的事 | 建议模式 | 理由 |
| --- | --- | --- |
| 给同事/学生演示手机操作，电脑能和手机连同一个 Wi-Fi | Local | 不用互联网、不装软件、浏览器就能看 |
| 远程帮家里人调手机，人在外地 | Global | 对方只要打开网页输入 ID 和密码，完整步骤见[不在同一wifi怎么远程投屏.md](不在同一wifi怎么远程投屏.md) |
| 把手机画面接进 OBS 录屏、或推给流媒体服务器 | RTSP | 播放器和服务器生态兼容（详见 [RTSP推流与播放器连接方法.md](RTSP推流与播放器连接方法.md)） |
| 在公共 Wi-Fi 下投屏 | 不建议 Local | 公共网络常有"设备隔离"，且 PIN 不加密，见[连接失败与画面延迟排查.md](连接失败与画面延迟排查.md) |

## 四、你装到的版本有哪种模式

官方渠道之间功能有差别，这是这个应用最容易让人困惑的一点：

- **Google Play 版**：三种模式全有，界面带广告。
- **F-Droid 版**：无广告，只有 Local 和 RTSP 两种模式，没有 Global。
- 除此之外官方源码仓库的 GitHub Releases 也提供无广告构建，模式范围以该构建页说明为准。

网盘里那份 4.3.7 安装包属于哪个渠道的构建，包名本身看不出来（都是 `info.dvkr.screenstream`）。判断办法很简单：装好后翻一遍主界面，有没有 Global 模式页一目了然。没有 Global 也不影响最常用的"投到同网浏览器"用法。

## 五、启动前先知道的两个官方提醒

这两条来自官方说明，三种模式都适用：

1. **延迟下限**：官方明确提醒这类投屏至少有 0.5~1 秒以上的延迟，设备慢、网络差、手机高负载时还会更大。你要做现场互动演示的话，把这个延迟算进节奏里。
2. **不适合高清视频**：官方明确说它不是为播放高清视频设计的。追剧、看大片请用别的方案；演示 App 操作、看网页、核对表格这类静态偏多的内容才是它的主场。
