## 一、先分清是哪类故障

投屏出问题时，现象只有三种，对应三个排查方向：

| 现象 | 大概率原因 | 跳到 |
| --- | --- | --- |
| 浏览器打不开地址 | 网络不通或地址不对 | 本篇第二节 |
| 地址能打开，但没有画面 | 授权没给、或应用被系统杀掉 | 本篇第三节 |
| 有画面，但延迟大、卡顿 | 带宽或手机负载不够 | 本篇第四节 |

先确认最基础的一条：手机上通知栏里的常驻通知还在不在。它不在 = 投屏服务已经停了，先回到应用里重新点启动，再看下面的方向。

## 二、浏览器打不开地址

按命中率从高到低逐条过：

1. **两台设备不在同一个网络**。手机用流量、电脑用公司网，这种"看着都有网"的组合连不通。让手机和电脑都连同一个 Wi-Fi，或用手机热点把电脑拉进来。
2. **IP 变了**。手机重连 Wi-Fi 后地址可能变（末尾数字不同），回应用主界面重新抄一遍当前显示的地址。这也是最常犯的错：拿十分钟前显示的地址输。
3. **Wi-Fi 开了设备隔离**。公司、酒店、访客网络常见，同一 Wi-Fi 下设备互相不可见。换成手机开热点让电脑连，绕开隔离。
4. **设了 PIN 而忘了**。浏览器页面会停在要 PIN 的地方，回应用的安全设置里重看或重设。
5. **运营商拦入站连接**。手机走流量网络时，部分运营商出于安全策略拦掉对手机的入站连接，官方文档明确提过这一点。这种情况别硬试，改走 Global 模式（对比见[三种投屏模式怎么选](三种投屏模式怎么选.md)）。

## 三、地址能打开但没有画面

1. **屏幕捕获授权被拒过**。应用每次启动都要系统弹窗授权"截取屏幕内容"，点成拒绝的话服务启动了也出不了画面。回应用里再点一次启动，这次点"立即开始"。
2. **系统把应用后台杀掉了**。国产系统的省电策略经常清后台。把 ScreenStream 从电池优化白名单里放出来（设置 → 电池 → 无限制，各品牌叫法不同），并保持通知栏常驻通知在。
3. **浏览器标签页缓存了旧流**。刷新页面，或换一个无痕窗口重开地址。

如果装都装不上、或一启动就闪退，先回[下载与安装教程](下载与安装教程.md)核对系统版本要求，再回来继续排。

## 四、画面延迟大或卡顿

官方说明里明确写过：这类投屏至少有 0.5~1 秒以上的延迟，且不为高清视频设计。所以先校准预期——**演示操作时延迟一两秒是正常的**，不是故障。下面这些才是能实际改善的：

| 手段 | 怎么做 | 适合 |
| --- | --- | --- |
| 降分辨率 | 图像设置里按百分比缩小输出 | Wi-Fi 一般、看文字为主 |
| 减少观看窗口 | 关掉多余的浏览器标签 | 多人同时看导致卡顿 |
| 拉近 Wi-Fi | 手机和路由器之间别隔两堵墙 | 信号弱导致花屏、跳帧 |
| 减轻手机负载 | 投屏时关掉后台大应用 | 手机发热、降频时 |
| 换传输方式 | 卡成幻灯片时试 RTSP over TCP，或换 Global 模式 | 网络环境本身差 |

另外有用户反馈：手机屏幕长时间保持完全静止时，观看端可能出现"重连中"的状态，在手机上动一下屏幕通常就恢复——演示中途别让手机一直停在静置状态。

调完还卡，换一种投法往往比死调参数快——三种模式的取舍见[三种投屏模式怎么选](三种投屏模式怎么选.md)；RTSP 播放器侧的问题另看[RTSP推流与播放器连接方法](RTSP推流与播放器连接方法.md)第五节。

## 五、Global 模式远程观看连不上

走 Global 模式（对方不在同一网络、用串流 ID 加密码连）时，故障点在互联网这一侧，按这几条查：

1. **串流 ID 或密码输错**。ID 是一长串，手抄容易错位；让两边对着屏幕逐位核，或干脆重新发一遍。
2. **密码没设就开播**。部分构建没设密码时对方进不来；回 Global 模式设置里补一个密码再开播。
3. **观众浏览器太旧**。这条路线要求浏览器支持 WebRTC，换近期版本的 Chrome、Edge、Firefox 重试。
4. **有一端断网或网不稳**。这条路线全程依赖互联网，任何一端掉线画面就断；手机端看投屏通知还在不在，观众端刷新网页重连。

手机端操作本身没走通的，回到[不在同一wifi怎么远程投屏](不在同一wifi怎么远程投屏.md)第二步重对一遍。

## 六、一个容易被忽略的收尾习惯

停止投屏认准手机通知栏里的**停止**按钮，这是官方设计的正规出口。直接从最近任务里划掉应用，通知可能残留、浏览器里的地址也可能还能打开一小会儿。演示结束先点停止，再锁屏，才算是真的关了。
