## 一、RTSP 模式和浏览器模式的区别

Local 和 Global 模式的观看入口是浏览器；RTSP 模式的观看入口是**播放器或流媒体软件**。适合这些场合：把手机画面作为一路信号接进 OBS 做混流、推给局域网里的流媒体服务器做录制或再分发、用 VLC 全屏看画面。代价是你要会操作播放器，比"浏览器输个地址"门槛高一点。

RTSP 模式分两个子模式，方向完全相反，先分清再动手：

| 子模式 | 谁当服务器 | 数据流向 | 典型用途 |
| --- | --- | --- | --- |
| **服务器模式**（默认） | 手机自己 | 播放器主动连到手机 | 用 VLC 直接看手机画面 |
| **客户端模式** | 外部媒体服务器 | 手机主动把流推到服务器 | 推给 MediaMTX 这类服务器做录制、分发 |

## 二、服务器模式：用 VLC 看手机画面

1. 手机上进入 **RTSP 模式**页，确认处于服务器模式，点启动，同意屏幕捕获授权。
2. 应用会显示 rtsp 开头的地址（形如 `rtsp://192.168.x.x:端口`），**以应用内实际显示为准**。
3. 电脑上打开 VLC：菜单"媒体"→"打开网络串流"，粘贴那个地址，播放。
4. 想停就在手机通知栏点停止；VLC 侧直接停止播放也行。

FFplay、mpv 的用法同理——在命令行里把 rtsp 地址作为输入打开即可。官方实测过的播放器清单：

| 播放器/工具 | 状态 |
| --- | --- |
| [VLC media player](https://www.videolan.org/vlc/) | 官方实测可用 |
| [FFplay](https://ffmpeg.org/ffplay.html) | 官方实测可用 |
| [mpv](https://mpv.io/) | 官方实测可用 |
| [gst-play-1.0](https://gstreamer.freedesktop.org/)（GStreamer） | 官方实测可用 |

## 三、客户端模式：推给流媒体服务器

客户端模式是把手机当作一路推流源，主动连到一个已经跑起来的 RTSP/RTSPS 服务器上。典型搭配是开源的 [MediaMTX](https://github.com/bluenviron/mediamtx)：在电脑或 NAS 上跑一个 MediaMTX，手机的 RTSP 客户端模式填入它的地址，之后任何能拉流的播放器都从 MediaMTX 取画面。这一路需要你先有一台配好的媒体服务器，具体参数以 MediaMTX 文档为准。

录制、转推这类需求都走这条路，因为手机端只负责推，后续怎么存、怎么转发由服务器侧决定。要把这路流接进 OBS 做直播或录制，具体操作路线见[OBS接入手机画面方法.md](OBS接入手机画面方法.md)。

## 四、编码与音频选项怎么配

RTSP 模式的设置页里有几组会直接影响兼容性和流畅度的选项：

| 选项 | 可选值 | 怎么选 |
| --- | --- | --- |
| 视频编码 | H.264 / H.265 | 播放器或服务器两边都认 H.264 最稳；H.265 更省带宽但兼容面窄 |
| 音频编码 | OPUS / AAC / G.711 | 按接收端支持选，拿不准选 AAC（以设备实际支持的编解码器为准） |
| 传输协议 | TCP / UDP | UDP 低延迟但网络差会花屏；TCP 稳但延迟略高 |
| ONVIF 发现 | 开/关 | 开了以后支持 ONVIF 的设备能自动发现这路流；仅 H.264 服务器模式可用 |

| 设置项在哪调 | 说明 |
| --- | --- |
| 服务器模式的协议、接口/地址过滤、IPv4/IPv6、端口 | RTSP 模式的服务器设置页 |
| 视频/音频编码 | RTSP 模式的视频、音频设置页 |

## 五、连不上时先查什么

RTSP 模式的故障大多和 Local 模式同源——不是同一网络、设备隔离、IP 变了，排查思路直接用[连接失败与画面延迟排查](连接失败与画面延迟排查.md)。另外多查两条：播放器侧的协议设置（VLC 里可强制 RTSP over TCP 试试）、以及编解码组合是否被接收端支持（H.265 放不出来就切回 H.264）。三种模式的取舍回头再看[三种投屏模式怎么选](三种投屏模式怎么选.md)。
