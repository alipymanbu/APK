## 一、先按症状对号

| 症状 | 大概率原因 | 先跳到 |
| --- | --- | --- |
| 弹密码输入框，输完说密码错误 | 密码抄错/有空格，或文件名被加密 | 第二节 |
| 能开包但文件名是乱码 | 压缩包的文件名编码与手机解码方式不一致 | 第三节 |
| 解到一半报错中断 | 分卷缺失或包损坏 | 第四、五节 |
| 根本打不开、提示未知格式 | 后缀不在支持范围 | [支持哪些压缩格式.md](支持哪些压缩格式.md) |
| 解压时卡住或提示空间不足 | 存储权限或目标目录空间 | 第六节 |

## 二、提示密码错误

1. 复制粘贴密码而不是手输——中文输入法容易把结尾空格、全角字符带进去；
2. 确认大小写与数字零/字母 O 的区别，发送方给的密码原样照抄；
3. 如果发送方说「连文件名都加密了」，你在文件列表里看到的文件名本身就是密文，必须输入正确密码后才能看到真名，这不是乱码；
4. 密码实在拿不到就回发件人处要，压缩包密码没有通用的找回办法，网上自称能恢复的工具只对**你自己设置过的密码**做暴力猜解，对别人的包没有意义。

密码本身丢了（而不是输错）时，按 [压缩包密码忘了怎么办.md](压缩包密码忘了怎么办.md) 的分支处理。

## 三、文件名乱码

收到的 zip 里文件名变成「鏂囦欢鍚.」这类乱码，是打包方用的文件名编码（GBK 等本地编码）与解压方的解码假设（UTF-8）不一致造成的：

1. 先在 BandiZip 里看能不能找到编码/字符集设置项，把代码页切到 GBK（936）再重新打开，多数乱码就此解决；
2. 没有该选项时，换电脑上的桌面版处理——桌面版官方支持代码页自动检测与手动设置，处理完再把解压结果传回手机；
3. 让发送方重新打包时选 7z 格式并使用 UTF-8 文件名，从源头避免。

乱码只影响**文件名的显示**，不影响文件内容本身，解出来的内容是完好的。

## 四、分卷包解压到一半失败

分卷包（`xxx.zip.001/.002…` 或 `xxx.z01+xxx.zip`）报「文件缺失」或「无法打开后续分卷」：

1. 核对所有分卷是否都在**同一目录**，缺一个都会中途断；
2. 核对各卷文件大小是否正常——传输中断会造成某个卷只有一半，重新下载缺失或异常的那个卷；
3. 必须从**第一个卷**（`.001` 或 `.z01`）打开，从中间卷打开永远失败；
4. 发送方那边卷没发全时，让 TA 把缺的卷补发，而不是把已有的卷重发一遍。

## 五、单个包解压报「文件损坏」

1. 回下载处重新下载一份，传输不完整是损坏的第一大来源；
2. 重下仍损坏的，核对安装包/文件完整性——如果是网盘资源里的安装包，MD5 应为 `207076411e4ca024ff755051b00aa34d`（v7.6.0.1、31.30M），核对方法见 [下载与安装教程.md](下载与安装教程.md) 第三节；
3. 压缩包本身损坏时，桌面版 Professional 有修复压缩包功能（付费），手机端没有对应工具，能解多少解多少后拿未损坏的部分。

## 六、解压卡住、空间不足

- **没给存储权限**：App 看不到目录也写不进文件，去「设置 → 应用 → BandiZip → 权限」打开存储权限；
- **目标目录空间不足**：解压前看一眼包的原始大小，确保目标目录（常是 Download）有至少 1.5 倍空间，手机存储告急时先清相册缓存；
- **解压大量小文件特别慢**：属正常现象，几十上百个小文件的包写入耗时不比大文件少，耐心等进度条，别中途杀进程。

以上都走不通时，换一台设备或电脑上的桌面版交叉验证，能定位到底是包的问题还是手机的问题。打包与解压的常规操作回 [怎么解压与压缩文件.md](怎么解压与压缩文件.md)。
