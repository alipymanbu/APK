## 一、为什么自己排查到这一步就该抓日志了

[常见问题与故障排查.md](常见问题与故障排查.md) 里那些常规手段都试过、问题还在，说明它需要看你这台设备的实际运行数据。Symfonium 的支持渠道（应用内 support 按钮、[官方支持论坛](https://support.symfonium.app/)）**明确要求附带新鲜日志**——不带相关日志的支持帖可能直接被关闭不处理。原因是同一个症状在不同设备、不同媒体源、不同播放方式下原因完全不同，没有日志就没法判断你属于哪一种。

## 二、抓日志的标准流程

照这五步做，顺序别乱（日志必须是「问题发生当时的」，事后补抓的没有用）：

1. `设置 → Advanced`（高级）里**打开 Debug mode（调试模式）**。
2. **完整复现一次问题**——从触发操作开始到症状出现，走完整个过程；顺手记一下大概的发生时间。
3. **立刻关掉 Debug mode**（调试模式会降低性能、日志文件也占空间，关掉后日志才停止写入）。
4. 马上点 **Share logs with support（与支持共享日志）**，填一段好认的描述（比如「Sonos 投屏 5 分钟后断开」）。
5. 据此开一个支持帖，**把你填的那段描述原样带上**，方便对上号。

## 三、开帖前的三件事

- **先搜一遍**：去 [支持论坛](https://support.symfonium.app/) 搜同样的症状，已有帖子在跟进就跟着回，不要另开一贴——重复帖会被合并或忽略。
- **一个帖子只报一个问题**：把好几个不相干的问题塞进同一份日志里，每个都难查。拆开来，一个复现路径配一份日志。
- **分清「问题」和「需求」**：行为跟预期不一样才是 bug；想要新功能是 feature request，走论坛的对应板块，别混着提。

## 四、日志里最好带上什么

一份能被快速定位的日志，描述里通常包含：

- 手机型号 + 安卓版本；
- Symfonium 版本号（`设置 → About` 里看）；
- 媒体源是哪个（本地文件 / 哪台服务器 / 网盘）；
- 复现步骤与发生时间点。

如果问题疑似出在系统层（比如音频路由、蓝牙），还可以附一份 **安卓系统 bug report**（官方文档有单独一节讲怎么生成），但先把手头这几样给全。

## 五、自己也能看日志文件

生成的日志与导出文件在应用可访问的输出目录里（`设置 → Advanced` 一带有直接访问入口）；手机连电脑后也可以从对应目录拷出来。注意：**只在需要抓的时候开着 Debug**，平时关着——调试日志写得勤，长期开着既费性能也占存储。

日志只是手段，先确认你遇到的问题不在 [常见问题与故障排查.md](常见问题与故障排查.md) 的清单里，能自己解决的就不用发帖了。
