## 一、官方自己写的三条提醒

这三条在官方仓库 README 的开头，**是开发者原话，不是转述**：

1. 「一切开发旨在学习，请勿用于非法用途」
2. 「如果某功能被大量运用于非法用途，那么该功能将会被移除」
3. 「鉴于项目的特殊性，开发团队可能随时**停止更新**或**删除项目**」

第三条对使用者的实际影响最大：**这个模块没有任何持续维护的承诺**。你今天跑通的组合（微信版本 + 模块版本），可能某天因为微信升级而失效，且不一定等得到修复。判断是否还在维护，看官方仓库 Releases 页面最后一条的日期即可，以当时显示为准。

另外，模块本身**免费、无内购**，官方分发走 GitHub Releases 与 LSPosed 模块仓库。任何向你收费卖这个包的渠道，都不属于官方口径。

## 二、Root 与框架层的风险

模块本身不改微信安装包，但**它依赖的 LSPosed 框架是装在 Root 环境里的**，这一层的风险与模块无关、却由你承担：

| 风险 | 触发场景 | 降低办法 |
| --- | --- | --- |
| 手机开机异常（bootloop） | 框架或模块与 ROM 冲突 | 作用域只勾微信，不勾「系统框架」与「全部应用」 |
| 银行 / 支付类 App 报环境异常 | 这类 App 会检测 Root 与框架 | 用框架的作用域隐藏功能把这类 App 排除在外 |
| 数据丢失 | 降级微信、清数据、刷机 | 动手前先用微信自带的「聊天记录备份与迁移」备份 |
| 后台被杀导致模块时灵时不灵 | 系统省电策略清理进程 | 把微信、WAuxiliary、LSPosed 三个都加入后台白名单 |

**作用域只勾微信**是这里面性价比最高的一条：模块需要的只有微信一个进程，勾得越多，与系统里其他 App 冲突的机会越大。

## 三、关于数据与账号，如实说

- **模块运行在微信进程内**。它能读到什么，取决于你给它开了哪些功能开关 —— 与所有 Xposed 模块同一性质，不是这个模块独有的问题。
- 源码是公开的（`HdShare/WAuxiliary_Public`），想核实某个行为可以自己读，也可以看社区的代码审查。
- 官方 README 里**没有任何关于微信账号层面的承诺或保证**，只写了上面第一节那三条。这一层的取舍只能你自己判断 —— 你改动的是自己手机上微信客户端的行为，超出微信官方的支持范围，出问题时这不是微信官方客服会受理的范畴。

## 四、常见问题

**Q：免费的还是收费的？**
官方渠道免费开源。版本号、包名以官方仓库为准。

**Q：必须 Root 吗？**
主流路径是 LSPosed，而 LSPosed 需要 Root 环境（Magisk / KernelSU 等）。免 Root 的容器类方案能否跑通，取决于容器工具自身对新版微信的支持，与模块本身无关，见 [下载与安装教程.md](下载与安装教程.md)。

**Q：装完微信变卡了怎么办？**
先在模块里关掉最近新加的功能开关再观察；仍卡就彻底停用模块（LSPosed 关开关 + 强制停止微信）。定位到具体是哪个功能引起的之后再决定开不开 —— 模块有几十个独立开关，逐个排除不难。

**Q：能用在微信分身 / 双开上吗？**
**有用户反馈**分身不会自动出现在 LSPosed 作用域列表里，需要手动添加分身包名；应用隐藏也可能导致模块失效。这是用户侧结论，各家 ROM 表现不一，具体见 [模块激活后不生效怎么排查.md](模块激活后不生效怎么排查.md)。

**Q：卸载模块后微信会有残留吗？**
模块不修改微信安装包，卸载模块并强制停止微信后，微信回到原生行为。若你曾用模块改过界面样式（如头像圆角），重启微信后即恢复默认显示。
