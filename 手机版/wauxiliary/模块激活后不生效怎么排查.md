## 一、先按顺序过这张清单

九成的「不生效」都出在前四条，**严格按顺序查，别跳着试**：

| # | 检查点 | 怎么确认 | 不对怎么办 |
| --- | --- | --- | --- |
| 1 | LSPosed 里模块开关是开的 | LSPosed 管理器 → 模块 → WAuxiliary | 打开开关 |
| 2 | 作用域里勾了微信 | 同上，进入作用域看列表 | 勾上微信，其他应用不用勾 |
| 3 | 改完之后强制停止过微信 | 微信进程有没有被杀掉重开过 | 设置 → 应用 → 微信 → 强制停止，再重开 |
| 4 | 微信版本在 8.0.44~8.0.65 之间 | 微信 → 我 → 设置 → 关于微信 | 出了区间就先别折腾模块，见 [支持的微信版本与功能适配.md](支持的微信版本与功能适配.md) |
| 5 | 模块版本比微信新 | 模块版本号与官方发布页对比 | 换最新模块（版本号含义见 [版本号怎么看与更新日志.md](版本号怎么看与更新日志.md)） |
| 6 | WAuxiliary 界面里这个功能确实开了 | 打开模块界面看那个开关 | 打开后再强制停止微信一次 |
| 7 | 该功能是实验功能（带 `[测]`） | 对照功能适配表 | 实验功能在部分版本上失效属正常 |
| 8 | 模块 App 被后台清理 / 冻结 | 手机的省电与后台管理设置 | 把 WAuxiliary 与 LSPosed 加入后台白名单 |
| 9 | 微信刚升级过 | 版本号是否变了 | 升级后必须重新强制停止微信 |

**第 3 条是最常见的翻车点**：Xposed 模块注入发生在微信进程启动时。你勾完开关直接切回微信看效果，看到的还是注入前那个老进程 —— 一定先强停再打开。

## 二、按症状定位

### 症状 A：模块界面能开，但微信里一点变化没有

基本就是清单的 1~4 条。逐条走完后，用一个最容易观察的功能验证（例如「阻止撤回」：让对方撤回一条消息，看聊天里是否留下了内容）。**选容易观察的功能验证，别拿「精确数量」这类要特定版本才生效的功能当探针**，否则你会以为全盘失效，实际只是这一个功能不适配。

### 症状 B：部分功能有效、部分没用

不是模块没挂上，是功能本身的版本适配问题。对照 [支持的微信版本与功能适配.md](支持的微信版本与功能适配.md) 的功能表 —— 标注只适配 8.0.45 的功能，在别的版本上本来就不工作。

### 症状 C：微信打不开、闪退、卡启动

1. 先回想最近改动过什么：新装的模块版本、新升级的微信、新勾的作用域。
2. 进 LSPosed 把 WAuxiliary 的开关关掉，强制停止微信，看能不能正常进 —— 能进就是模块这层的问题。
3. 还是闪退，就把微信降回上一个可用版本（**降级前先备份聊天记录**）。
4. 极端情况（手机反复重启进不去系统）：问题在框架层而不是模块层，进 Recovery 或用 adb 禁用 LSPosed 模块目录后再排查，这已超出模块自身的范围。

### 症状 D：分身 / 应用双开里的微信不生效

**有用户反馈**：微信被放进系统「应用隐藏」后模块失效；微信分身不会自动出现在作用域列表里，需要在 LSPosed 中手动添加分身的包名再勾选。这是论坛与问答站上的用户结论，不是官方文档口径 —— 各家 ROM 的分身实现差异很大，实测为准。

## 三、什么时候该放弃排查

排查到这一步还无效，通常是这两种情况，继续试下去没有意义：

- **微信版本已出官方承诺的区间**（8.0.44 之前 / 8.0.65 之后）：等模块更新支持，或把微信留在区间内。
- **官方已停止该项目**：官方 README 明确写了「鉴于项目的特殊性，开发团队可能随时停止更新或删除项目」。若你查到的最新版本发布日期已经很久远，说明这个组合大概率不会再有修复 —— 具体停更与否，以 [官方仓库](https://github.com/HdShare/WAuxiliary_Public) 的 Releases 页面当时显示为准。
