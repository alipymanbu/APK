Tasker 的所有自动化都由同一套结构拼出来：一条「什么时候」配上一条「做什么」。新手卡住通常不是因为操作难，而是没弄清设置界面问的到底是哪一层。本篇先用一张表把这几个词对上界面，再带你完整做完一条最实用的规则——连上家里的 WiFi 自动静音、离开后恢复，做完这条你就知道该往哪里加下一条。

## 一、几个关键词分别对应界面的哪一块

打开 Tasker，主界面顶部是四个选项卡：配置文件、任务、场景、变量。新手前两个就够用。

| 名称 | 通俗理解 | 在界面上长什么样 |
| --- | --- | --- |
| 配置文件（Profile） | 一条完整的规则：什么时候 + 做什么 | 「配置文件」选项卡里的一行 |
| 条件（Context） | 这条规则的触发前提 | 配置文件左边那几行小字 |
| 任务（Task） | 触发后要依次做的事 | 配置文件右边挂着的那一项 |
| 操作（Action） | 任务里最小的一步，例如「设为静音」 | 点进任务后那一列带图标的行 |
| 场景（Scene） | 自己搭的小弹窗、小面板，元素能挂任务（做法见 [场景怎么做自定义弹窗与面板.md](场景怎么做自定义弹窗与面板.md)） | 「场景」选项卡，新手可以暂时不管 |
| 变量（Variable） | 会随时间变的值，例如电量、时间 | 「变量」选项卡；进阶用法见 [变量与条件怎么用.md](变量与条件怎么用.md) |

两条容易搞混的对应关系，先记下来：

- **条件可以有多个。** 一条配置文件左边挂了几个条件，就要**全部满足**它才会激活——它们之间是「并且」的关系。
- **任务可以有两个。** 右边的任务分「进入任务」和「退出任务」：条件刚开始满足时跑进入任务，条件不再满足时跑退出任务。不是每条规则都需要退出任务，但「静音」这类改了系统状态的动作，配上退出任务才好还原。

配置文件名字变绿，表示它此刻处于激活状态；名字前面有勾，只表示它在启用中（还没被禁用），两者不是一回事。另外，「条件」和「上下文」指的是同一个东西，都是英文 Context 的译法，在界面与文档里会混着出现，看到别当成两个概念。

## 二、手把手做一个：连上家里 WiFi 自动静音

目标：手机连上家里的 WiFi 时自动切静音，断开后恢复。它用到「状态」类条件，是最适合练手的类型——不用等特定时间，切换 WiFi 就能反复验证。

1. **新建配置文件**：切到「配置文件」选项卡，点右下角加号。
2. **选条件类型**：在弹出来的列表里选「状态」→「网络」→「Wifi 已连接」（英文界面为 Wifi Connected）。
3. **填条件参数**：在 SSID 一栏填上家里 WiFi 的名称。**注意区分大小写**，填错了就不会触发；不确定就先去系统「设置 → WLAN」里把名字照抄过来。
4. **给这条规则配任务**：返回后 Tasker 会问要给这条配置文件配哪个任务，选「新建任务」，命名成「到家静音」。
5. **往任务里加操作**：进入任务编辑界面，点加号 → 选「音频」→「静音模式」→ 把值设为「静音」，返回保存。此时一条规则已经成型：**Wifi 已连接「家里 WiFi」→ 静音**。
6. **加退出任务还原**：在配置文件那一行上，长按右侧的任务区域，选添加退出任务，新建一个任务叫「离开恢复」，里面放一条「音频 → 静音模式 → 关」。

做完长这样：

```text
配置文件：Wifi 已连接（SSID = 你家 WiFi 名）
  ├─ 进入任务：到家静音
  │    └─ 音频 → 静音模式 → 静音
  └─ 退出任务：离开恢复
       └─ 音频 → 静音模式 → 关
```

## 三、怎么确认它真的在跑

配完最忌讳的是「以为成了」，下面三种方式从轻到重，都可以用：

- **手动跑任务**：切到「任务」选项卡，点任务左边的小三角，看动作有没有按预期发生。这一步只用来自检任务本身写对没有。
- **手动跑整条规则**：点配置文件名字展开它，再点挂着的任务，可以直接执行一次进入任务，绕过条件判断。
- **看激活状态与运行日志**：把手机 WiFi 断开再连上，观察配置文件名字有没有变绿；同时打开菜单里的运行日志，能看到哪个任务被触发、每条操作是否成功、失败在哪一步。

调试阶段建议一次只加一条操作，确认生效后再往上叠。一条任务里堆了七八个操作，出问题时你分不清是哪一步断的。

## 四、新手最容易踩的四个点

1. **权限没给全。** 界面能配、条件不触发，绝大多数是这个原因。动手前先按 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md) 把权限与后台省电两项过一遍。
2. **条件写得太宽。** 例如时间条件填成 `00:00` 到 `23:59`，等于全天都满足，看起来就像「一直在跑」。写完回看一眼条件范围是不是你真正想要的那一段。
3. **改了系统状态却没配退出任务。** 静音、调亮度、关蓝牙这类动作，没有退出任务就会一直保持在那条规则最后一次执行的结果上。
4. **测试时看不到提示。** 如果任务里用了「提醒 → 闪烁」，而规则本身把手机设成了静音或不打扰，提示可能被系统压掉。测试阶段先用运行日志确认，别只靠有没有弹窗判断。

第一个跑通了，下一步可以换「时间」这类条件做定时任务，或者用多个条件叠加（例如「连接到车载蓝牙」并且「屏幕亮着」）。各类条件的适用场景与耗电差别，见 [触发条件有哪几类怎么选.md](触发条件有哪几类怎么选.md)。
