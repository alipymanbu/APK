# Tasker 导入现成项目与备份恢复

> 不用从零开始：导入别人分享好的自动化、把自己的配置导出成链接或文件、换手机时整体搬过去，以及恢复之后必须补做的授权。

Tasker 的配置可以整体搬走，也可以单条分享。日常最常用的三条路径是：把别人分享的项目导进来、把自己的配置导成链接给别人、以及换手机时做一次整体备份与恢复。这三件事都走得到，但恢复之后有一件事必须手动补——权限不会被一起搬过去。本篇按这三条路径分别给出步骤，并列出容易漏的收尾动作。

## 一、TaskerNet 是官方的分享通道

Tasker 内置了一套官方的分享系统，叫 TaskerNet。别人长按自己的项目或任务、选「导出 → 作为链接」，就会生成一条以 `https://taskernet.com/shares/` 开头的链接；你打开这条链接，就能把那份配置导进自己的 Tasker。

它带来两个实际好处：**分享的是配置本身而不是截图**，导入后能直接改成自己需要的；**导入前可以先看描述**，知道它用到哪些权限、哪些插件、要做哪些操作，而不是闭着眼跑一段陌生代码。想要现成配置又不想自己搭，可以先去 [公开分享列表](https://taskernet.com/?public) 里翻一翻。

## 二、导入别人分享的项目

1. **在装了 Tasker 的安卓设备上打开那条链接**（一般在手机浏览器里点开）。前提是手机里已经装好 Tasker，没装的话先看 [下载与安装教程.md](下载与安装教程.md)。
2. **在摘要页点导入**。页面会显示这份分享的时间、名称和简介，确认是你想要的那一份再往下。
3. **在确认弹窗里先「查看描述」**。这里能看到它用到的权限、依赖的插件以及完整的操作列表。这一步值得花一分钟，尤其是来源你不熟悉的时候。
4. **点确认导入**。如果本地已经有同名的任务或配置文件，Tasker 会问你覆盖不覆盖——导入的是同一份东西的更新版时，选覆盖即可。
5. **最后会问你要不要立刻启用配置或运行任务**。不放心就先不启用，回到界面自己逐条看过再说。

## 三、安全导入的四个习惯

导入别人的配置，本质是把一段你还没读过的自动化放进手机，而 Tasker 的权限相当高。这四个习惯能把风险压到最低：

- **先禁用 Tasker 再导入。** 主菜单或快捷设置磁贴里都能一键禁用，导入完成后你就有充足时间逐条检查，而不是它一边导入一边就开始跑。确认没问题再启用。
- **看它依赖什么。** 描述里提到的插件没装，相关操作会直接报错；涉及读取屏幕内容、发送短信、读写文件的操作，要清楚它为什么要这么做。
- **别把陌生来源当作可信来源。** 公开列表里的项目质量参差不齐，官方也明确说明过：使用他人分享的配置，后果由使用方自己承担。
- **场景类的分享要格外小心。** 场景能做成全屏的透明覆盖层，也就是说它有办法遮住你的界面、截走你的点击，而它跑起来带的是 Tasker 的全部权限。这类分享务必先禁用再导入，逐个元素看完它的点击事件都干了什么再启用，元素用法见 [场景怎么做自定义弹窗与面板.md](场景怎么做自定义弹窗与面板.md)。

## 四、把自己的配置导出成链接

1. **长按要分享的对象**——项目、配置文件或任务都可以（最外层那个默认项目不能这样导出）；
2. **选「导出 → 作为链接」**；
3. **填一段描述**，写清它是干什么的、需要哪些插件。这段描述会跟着分享一起保存下来，下次更新同一份配置时不用重填；
4. **选分享方式**，可以直接发给别人，也可以复制链接；
5. **日后要管理这些分享**，登录 TaskerNet 网站上的分享列表即可，能看到、能取回链接、也能删除。

如果只是自己用、不想上传，那就跳过链接这一步，改用下面的文件导出。

## 五、导出成文件、换机整体迁移

不需要分享给别人时，推荐走文件这一路，不经过服务器：

1. **单条导出**：长按项目 / 配置文件 / 任务 → 导出，选导出成文件，会得到一个 XML 文件。存到手机存储或云盘即可，之后在任何设备上通过「导入」选这个文件就能还原。
2. **整体备份**：菜单里的数据相关入口可以把你全部的配置打包备份到本机存储或云端账号。换手机时用这一种最省事，不用一个个导。
3. **新机准备**：新手机先回 [Tasker 安装文件资源（夸克网盘）](https://pan.quark.cn/s/68cc03b45038) 装上 Tasker，再用同一路径把备份恢复进去。
4. **恢复后检查重名**：如果新机上已经有同名的任务或配置文件，恢复过程会询问怎么处理，逐条确认，别一路「全部覆盖」把新机上已有的东西冲掉。

## 六、恢复完必须补做的三件事

这是最容易漏的一步：**配置能搬走，权限搬不走。** 恢复之后，把下面三项补完，规则才会真正跑起来：

| 要补的东西 | 为什么要补 | 去哪补 |
| --- | --- | --- |
| 各项系统权限 | 新设备上从来没有授权过，无障碍、通知访问等全是关的 | 菜单 → 更多 → Android 设置 |
| 电池优化白名单与自启动 | 新机的后台策略和旧机不同，不一定是原来那套 | 系统设置里的电池与自启动管理 |
| 依赖的插件 | 分享里引用了你没装的插件，对应操作会报错 | 应用商店，按导入时描述里列出的插件逐个装 |

三项都补完，再按 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md) 末尾那份验证清单走一遍，确认定时规则在锁屏状态下也能触发，迁移才算真正完成。

另外提醒一句：恢复进来的配置里如果有用到位置、传感器之类的条件，**在新机上的耗电表现会不一样**（硬件和系统版本都变了）。跑一两天后回看一下电量消耗，必要时把这类条件换成更省电的写法，取舍标准见 [触发条件有哪几类怎么选.md](触发条件有哪几类怎么选.md)。
