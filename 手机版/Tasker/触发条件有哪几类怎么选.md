# Tasker 触发条件有哪几类怎么选

> 把七类触发条件（应用、时间、日期、位置、状态、事件、手势）的适用场景、触发方式和耗电差别摆在一起，帮你按需求对号入座。

配置一条规则时，真正需要思考的只有一件事：用什么当触发前提。Tasker 新建配置文件时列出的那一堆选项，本质上是七类条件，选错类的直接后果就是规则时灵时不灵、或者手机耗电明显上涨。本篇按「想做什么事」倒推该用哪类条件，并说明哪几类会拖累续航。

## 一、七类条件总览

| 类型 | 触发方式 | 会不会保持「激活」 | 相对耗电 | 典型用途 |
| --- | --- | --- | --- | --- |
| 应用（Application） | 某个应用来到前台 | 会，离开该应用时结束 | 低 | 打开某个应用时自动调音量、调亮度 |
| 时间（Time） | 到达设定的起止时间 | 会，区间内保持 | 极低 | 每晚固定时间静音、定时打卡 |
| 日期（Day） | 到达某月某日或星期几 | 会，当天内保持 | 极低 | 工作日与周末用两套规则 |
| 位置（Location） | 进入/离开某个地理范围 | 会，在范围内保持 | 高 | 到公司自动连接、到家自动静音 |
| 状态（State） | 某个系统状态成立 | 会，状态结束即退出 | 中 | 连上某个 WiFi、插上耳机、电量低于阈值 |
| 事件（Event） | 某一瞬间发生的动作 | 不会，瞬发即执行 | 低 | 收到短信、插上充电器、屏幕解锁 |
| 手势（Gesture） | 摇晃、翻转等动作 | 不会，瞬发即执行 | 高 | 摇一摇开手电筒 |

除了这七类，桌面小部件、桌面快捷方式、快捷设置磁贴、耳机线控按键这些属于**手动触发入口**——它们不走条件判断，点了才跑，适合用来给已经配好的任务开一个「按钮」。

## 二、状态和事件最容易搞混，先分清这两个

- **状态（State）是「一段持续的成立」。** 选了「连上家里的 WiFi」，那么连着的整个期间这条配置文件都是激活的；断开时才会去跑退出任务。凡是需要「离开后自动还原」的场景，都应该用状态类条件。
- **事件（Event）是「一个瞬间」。** 选了「收到短信」，触发只发生在收到的那一刻，之后没有「还在收短信」这种状态。

这个区别带来两个实际后果：

1. **事件类条件没有退出任务可言。** 因为激活与结束都是瞬发的，配置文件不会停留在激活状态，配了退出任务也不会按你预期那样在「之后」执行。官方文档里也写明：包含事件条件、或者重复/不连续时间条件的配置文件，两个任务都是立刻执行的。
2. **能拆成状态就不要用事件。** 例如「插上充电器」这件事，既有事件可以用，也有「充电中」这个状态可以用。如果你要的是「充满后提醒」，那就该用状态，因为要等电量走到 100。

## 三、位置类为什么最费电，怎么省

位置类会明显拉动耗电，因为它可能需要持续定位——按下面这份官方对照，几档之间差一个量级（星号越多越高）：

| 方式 | 能耗 | 精确度 | 适合的场景 |
| --- | --- | --- | --- |
| 状态：靠近基站（Cell Near） | 最低 | 最低 | 只求「大概在这个片区」，精度要求不高 |
| 位置：网络 | 低 | 低 | 附近有网络，不需要很准 |
| 位置：网络和 Wifi | 中 | 建筑密集区域很好 | 想要较准的位置，又不想开 GPS |
| 状态：靠近 Wifi（Wifi Near） | 较高 | 很高 | 公司、家、常去的店，这些地方基本都有 WiFi |
| 位置：GPS | 最高 | 最高 | 户外移动场景，只有它才够准 |

（官方文档的中文版与英文版在「靠近 Wifi」的能耗星级上并不一致，但两边方向一致：基站与网络类最省、GPS 最费。）

结论很直接：**只要目标地点有稳定的 WiFi，就优先用「靠近 Wifi」，不要一上来就用 GPS。** 三个补充点：靠近 Wifi 需要系统允许扫描周围网络（安卓 13 及以上对应的是「附近的 Wifi 设备」权限，见 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md)）；它的退出比进入慢，因为系统扫描周边 WiFi 本身有间隔，等它判定「已经离开」通常要过一会儿，这不是故障；「靠近基站」虽然最省，但必须你本人到过那个地点扫描登记一次才能用。

精度和能耗在这里是同向的——想省电就得接受粗一点的位置判断。够不够用的判断标准是：**这个条件触发后要做的事，经得起几十米的误差吗**。调音量、切 WiFi 经得起，那就没必要用 GPS。

## 四、多个条件怎么组合

一条配置文件左边可以挂多个条件，**它们之间是「并且」的关系**，全部成立才算激活。组合能解决不少实际问题：

- 「连接到车载蓝牙」并且「屏幕处于亮着」——避免在口袋里误触发；
- 「时间 22:00 到 07:00」并且「充电中」——只在睡前插着电的那段静音；
- 「应用是某个阅读软件」并且「耳机已连接」——只有戴耳机看书时才自动翻页朗读。

要注意的是，条件叠加会让规则变得更难触发而不是更容易。如果一个组合迟迟不生效，先把它拆成单条件逐个验证，再合起来。

**组合还有一个省电上的用法。** 官方给各类条件排过一个耗电顺序（从低到高）：其他状态 < 日期 / 时间 < 日历 < 靠近基站 < 应用 < 靠近蓝牙 < 网络定位 < 靠近 Wifi < GPS 定位 < 传感器与手势这一类。规则是——**只有耗电更低的那些条件都成立之后，更耗电的那个才会被开始监控**。所以把省电条件当「闸门」挂在耗电条件旁边，本身就是省电手段：想靠「靠近 Wifi」判断到家，就再挂一个半径很大的「位置：网络」，只有你先进入这个片区，Wifi 扫描才会启动。省电上还有哪些旋钮可调，单独整理在 [怎么控制耗电与后台占用.md](怎么控制耗电与后台占用.md)。

反过来，如果你要的是「满足甲**或者**满足乙」，一条配置文件做不到，得建两条独立的配置文件，各自配同一个任务。任务是可以被多条规则共用的，不用重复搭。

## 五、按需求对号入座

| 你想做的事 | 建议用的条件 |
| --- | --- |
| 每晚 23:00 自动静音 | 时间 |
| 到公司自动连内网、调低亮度 | 靠近 Wifi 或 位置 |
| 打开某个应用时自动横屏、调音量 | 应用 |
| 电量低于 20% 提醒 | 状态（电量） |
| 收到特定号码的短信后转发热点 | 事件（收到短信） |
| 摇一摇打开手电筒 | 手势 |
| 手动一键执行一组动作 | 桌面快捷方式 / 快捷设置磁贴 / 小部件 |

选完条件只是第一步。规则建好却完全不触发，多数时候和条件本身无关，而是权限或后台限制拦住了它——走不下去时按 [不生效与定时不准怎么排查.md](不生效与定时不准怎么排查.md) 的顺序逐层查一遍。
