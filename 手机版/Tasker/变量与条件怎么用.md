# Tasker 变量与条件怎么用

配一条规则时，你经常需要用到「现在是多少」——现在几点、电量还剩多少、刚收到的短信里写了什么。这些值在 Tasker 里叫变量。变量本身不难，难的是分清哪一类叫法能跨任务用、哪一类出了这个任务就消失，以及怎么让某一条操作只在满足条件时才跑。本篇只讲这两件事，够应付绝大多数日常配置。

## 一、变量分三类，先认命名规则

所有变量都以 `%` 开头，写在哪里就等于取它的当前值。区分三类靠的是名字的长相：

| 类型 | 命名特征 | 谁能用 | 例子 |
| --- | --- | --- | --- |
| 内置变量 | 全大写，由 Tasker 自己维护 | 任何地方 | `%BATT`、`%TIME`、`%LOC` |
| 全局变量 | 名字里**至少有一个大写字母** | 所有配置文件、任务、场景都能用 | `%MyVar`、`%DoorState` |
| 局部变量 | **全小写** | 只在创建它的那个任务（或场景）里有效 | `%count`、`%temp` |

命名规则带来的一个直接结论：**给全局变量起一个「大小写混合」的名字最省事**，因为内置变量都是全大写，混合写法的名字就不容易和它们撞车。局部变量用小写是硬性要求，写成全小写它才被当成局部变量处理。

变量名下面还能挂序号，用来一次存一组值：`%fruit1`、`%fruit2`……这就是数组。把一段用分隔符隔开的文本拆进去、或者遍历它，都有现成的操作，不必自己写循环去数。

## 二、常用的内置变量

日常配置里真正会反复用到的就这些，其余可以在变量列表里按需查：

| 变量 | 内容 | 常见用法 |
| --- | --- | --- |
| `%TIME` | 当前时间（时.分） | 拼进提醒文字、写进文件名 |
| `%DATE` | 当前日期 | 给备份文件命名 |
| `%DAYW` | 当前是星期几 | 工作日与周末分流 |
| `%BATT` | 当前电量（0~100） | 低电量提醒、省电模式判断 |
| `%WIFI` | Wifi 是开还是关 | 判断后决定要不要开流量 |
| `%BLUE` | 蓝牙是开还是关 | 进出车载场景时判断 |
| `%SCREEN` | 屏幕当前亮着还是熄着 | 决定要不要弹窗提醒 |
| `%LOC` | 最近一次定位的经纬度 | 拼成位置信息发出去 |
| `%CLIP` | 剪贴板里的内容 | 把刚复制的东西存起来或发出去 |

要记住一点：**内置变量的值由 Tasker 维护，你不能给它赋值**。想把「当前电量」记下来做对比，必须自己建一个全局变量存，例如把 `%BATT` 的值赋给 `%LastBatt`。

## 三、怎么赋值、怎么用

赋值用一个操作就能完成：在任务里点加号 → 「变量」→「变量设置」，名称填 `%MyVar`（名称里保留 `%`），值时可以写死一段文字，也可以写别的变量或表达式。

用的时候就简单了——**任何可以填文字的地方，直接把变量名写进去**，运行时 Tasker 会先把它替换成当前值再执行。例如提醒文字写成：

```text
当前电量 %BATT%，时间 %TIME
```

运行时会变成「当前电量 87%，时间 14.32」。

数组的用法类似，只是带序号：`%fruit1` 是第一个，`%fruit2` 是第二个，写成 `%fruit` 则代表整个数组。想省事可以直接用「变量拆分」把一段 `苹果,香蕉,橙子` 按逗号拆成数组，再用循环逐个处理。

## 四、让某条操作按条件执行

这是最实用的一块。在任务编辑界面里编辑某条操作时，操作编辑页下方有一个 If 条件区，可以给它加一条「仅当……时执行」的判断。加上之后，这条操作会先算条件，成立才跑。

条件可以比较两样东西，例如：

- 数值比较：`%BATT` 小于 `20`
- 文字比较：`%CLIP` 匹配 `*验证码*`
- 判断是否为空、是否已定义

需要「成立做甲、不成立做乙」时，用块结构更清楚：长按某条操作，可以把一段操作整体转成条件块，块里面就能分出成立分支与不成立分支，改完再收起来。6.2 这一版就补上了这类块编辑的便利操作，编辑时顺手试一下比手动嵌套判断省事。

## 五、拼一个能用的小例子

目标：跑一个任务，先播报当前电量和时间；如果电量低于 20%，再多提醒一次。

```text
任务：每日播报
  ├─ 操作 1：提醒 → 闪烁，文字「当前电量 %BATT%，时间 %TIME」
  └─ 操作 2：提醒 → 闪烁，文字「电量偏低，记得充电」
        └─ 条件：%BATT < 20
```

配完手动跑一次：先把操作 2 的条件临时改成 `< 100` 验证它能触发，确认格式没问题，再改回 20。**用明显能成立的条件验证语法、再用真实条件上线**，比反复猜哪里写错要快。

## 六、两个最容易搞混的点

1. **局部变量出了任务就没了。** 你在任务甲里写了个 `%temp`，任务乙里读不到它。需要跨任务传递时，要么用全局变量，要么用「执行任务」这类操作把值传过去。
2. **变量的值本质是文本，比较数字时要当心。** 数值比较请用数值类的比较方式，而不是文本比较；另外注意单位——不同内置变量的量纲不一样（电量是百分比，内存是数值），别拿两个单位不同的值直接比大小。

规则明明写对了却不按预期跑，多数还是权限或后台那一层的问题。按 [不生效与定时不准怎么排查.md](不生效与定时不准怎么排查.md) 走一遍排查顺序，比盯着变量设置页反复改更快找到原因。
