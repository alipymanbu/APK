# Tasker 不生效与定时不准怎么排查

> 规则建好了却一动不动，或者定时任务老是晚点、时灵时不灵——按本文的顺序逐层往下查，而不是到处改设置。

「没反应」在 Tasker 里是一个笼统的抱怨，底下可能是六种完全不同的原因：开关没开、条件没满足、任务写错、权限没给、被系统清了、或者这个动作在你的机型上本来就不支持。本文给一条固定的排查顺序，按顺序走一遍，比逐项试错误设置快得多。

## 一、按这个顺序查，不要跳步

从外到内一共六层，每一层都能用眼睛直接确认：

1. **Tasker 本身是否启用。** 主界面能看到启用状态，常驻通知也在就说明它活着。关掉它等于让所有自动化停摆。
2. **这条配置文件是否启用。** 看名字前面对勾还在不在——被禁用的规则不会跑，而它看起来和正常规则一模一样。
3. **条件此刻是否真的成立。** 手动把场景造出来（断开再连 WiFi、把时间调到范围内），看配置文件名字有没有变绿。不变绿就是条件没被感知到，往下走第 5 层。
4. **任务本身写对没有。** 切到「任务」选项卡，点任务左边的小三角手动跑一次。手动能跑通、自动不触发，说明问题在条件或后台，与任务内容无关。
5. **权限是否齐全。** 打开菜单 → 更多 → Android 设置，逐项回看。无障碍与通知访问这两项被系统「自己关掉」很常见，尤其是系统更新之后。
6. **后台是否被清。** 锁屏放两分钟再试同一件事。亮屏能跑、熄屏不能跑，基本可以锁定在这一层，处理办法见 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md)。

## 二、按症状直接对号

| 症状 | 最可能的原因 | 先动哪里 |
| --- | --- | --- |
| 完全没反应 | Tasker 未启用，或配置文件被禁用 | 第 1、2 层 |
| 手动能跑，自动不跑 | 条件始终没成立，或该类条件没被监控 | 第 3 层；核对息屏监控设置 |
| 亮屏正常，熄屏失灵 | 息屏监控没开，或应用被系统清理 | 开启息屏监控 + 电池优化白名单 |
| 定时任务总是晚几分钟 | 「使用可靠闹钟」被设成了「从不」 | 改为「息屏时」或「总是」 |
| 用了一阵突然全都不灵 | 无障碍服务被系统关掉 | 回 Android 设置重开 |
| 只有某个动作报错 | 该动作在当前机型/系统上受限 | 见第三节 |
| 应用类条件长期不稳定 | 缺少无障碍，或系统限制后台感知前台应用 | 按 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md) 逐项复查 |

## 三、几个常见报错与受限动作

**提示需要 root 或出现 `ACCESS_SUPERUSER`。** 说明这个动作在系统底层就需要 root 权限，属于安卓的安全策略，不是配置问题。官方给出的替代思路是改用能模拟界面操作的插件，用它去点系统的界面按钮，来达到同样的效果——做法见 [怎么让它自动点击其他应用.md](怎么让它自动点击其他应用.md)。

**出现 `ACCESS_NOTIFICATION_POLICY` 之类的通知策略错误。** 说明通知访问没开。路径是 Tasker 菜单 → 更多 → Android 设置 → 通知监听，把 Tasker 打开。

**开关 Wifi、切换移动数据不生效。** 这类动作在新版安卓上受系统限制，需要额外装官方的 Tasker Settings 小应用来代劳。装完之后有两件事别忘：给这个小应用也开电池优化白名单，否则后台调用会失败。这类依赖会随笔者的修复更新而变，遇到就先去官方更新日志看当前推荐的版本。

**怀疑是安装包坏了，或者版本太旧缺了某个操作。** 你手上这份是 6.2.22，官方在这之后还发过多个版本。可以回 [Tasker 安装文件资源（夸克网盘）](https://pan.quark.cn/s/68cc03b45038) 重新下一份覆盖安装，覆盖安装会保留已有配置；若覆盖失败，先导出备份再卸载重装（见 [导入现成项目与备份恢复.md](导入现成项目与备份恢复.md)）。

## 四、定时不准怎么查

定时问题是投诉最多的一类，原因集中在四处，按下面顺序排除：

1. **可靠闹钟设置。** 在菜单 → 首选项 → 监控里，把「使用可靠闹钟」设成「息屏时」或「总是」。选「从不」时系统会合并闹钟以省电，晚点几乎是必然的。
2. **电池优化白名单。** 没加白名单时，系统可能在到点前就把应用冻结了。
3. **国产系统的自启动与后台限制。** 这类机型常在锁屏数分钟后限制应用后台活动，需要单独放行。
4. **条件的写法。** 不连续的时间段、跨零点的时间区间都容易写反。把时间范围改成一个明显能马上触发的区间，验证一遍再说。

顺带说明一个正常现象：**如果规则里带了事件类条件，它的两个任务都是立刻执行的**，这与时间区间那类条件的表现不同，别把它当成故障。

## 五、位置类不触发怎么查

位置类的坑和上面不一样，单独列出来：

- **权限要含「后台位置」。** 只给「使用期间允许」，熄屏后定位就断了。
- **「位置：网络」也要系统定位开关是开的。** 它是网络辅助定位，但同样要系统允许访问位置，只把 WiFi 打开不够。
- **先确认是不是该用位置条件。** 目标地点只要有稳定 WiFi，改用「靠近 Wifi」会准得多、也省电得多，取舍见 [触发条件有哪几类怎么选.md](触发条件有哪几类怎么选.md)。
- **「靠近 Wifi」退出很慢是正常的。** 系统扫描周边网络有间隔，判定「已经离开」通常要等几分钟，这不是没生效。嫌反应慢可以去「首选项 → 监视器」调息屏检查频率，代价是更费电。
- **「靠近基站」反复失效就去补扫一次。** 这个状态靠登记过的基站编号判断，容易漏掉一些；回到该条件里用它自带的扫描入口再走一圈，把漏掉的补上。
- **用 GPS 的规则在室内可能一直不触发。** 室内长时间搜不到卫星会持续耗电，把该条件里的 GPS 超时调到「小到刚好还能用」，并且尽量避免用 GPS 判断室内位置。
- **「靠近基站」在基站切换频繁的地方会飘。** 城区高楼、地铁沿线这类场景，基站编号反复变化，它可能反复进出，要么放宽判断范围，要么换用其他条件。

这些规则长期不动、触发又特别频繁时，还会顺带把电量吃掉。是不是该改用别的条件，可以对照 [怎么控制耗电与后台占用.md](怎么控制耗电与后台占用.md) 里的耗电顺序来定。

## 六、什么时候该看运行日志

上面五步都试过还找不到原因，就该让 Tasker 自己说。打开菜单里的运行日志，它会按时间列出触发了哪些任务、每条操作有没有成功。三种信息最有用：

- **有没有触发记录**——没有记录，说明卡在条件或后台；有记录但任务没跑完，说明卡在具体某条操作。
- **哪一条操作标红**——直接锁定问题动作，不用再猜。
- **触发时间戳**——和定时任务对照，就能看出到底晚了几分钟、是不是被合并延后。

排查期间把日志开着复现一次，比对着设置页反复改要省事得多。定位到具体动作后仍然报错的，回到第三节按报错类型处理。
