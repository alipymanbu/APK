# Tasker 怎么控制耗电与后台占用

> Tasker 的耗电基本都花在「盯着条件有没有成立」上。本篇讲清官方给出的耗电规律、位置类方式的能耗差多少，以及几个明确的减负开关。

自动化工具耗电，消耗的不是「执行任务」那一下，而是长期盯着条件有没有成立。所以省电的思路是减少常驻监听，而不是减少任务里写了几条操作。好消息是这类取舍大多有官方给出的明确规律，不用靠试错。本篇把规律、对照表和可调的旋钮列出来，你按自己的需求取一个平衡点。

## 一、先记住官方给出的那条规律

Tasker 不会对所有条件一视同仁地同时盯着。它给各类条件排了一个耗电顺序，**只有在耗电更低的那些条件都成立之后，才会开始监控更耗电的那一个**。

官方给出的顺序（能耗从低到高）：

```text
其他状态  <  日期 / 时间  <  日历条目  <  靠近基站  <  应用
        <  靠近蓝牙  <  网络定位  <  靠近 Wifi  <  GPS 定位
        <  温度 / 湿度 / 距离 / 气压 / 磁场 / 光线 / 手势 / 方向（加速度传感器类）
```

这条规律可以直接拿来用：**把省电的条件当成耗电条件的「闸门」，挂进同一条配置文件。** 举例来说，你想靠「靠近 Wifi」判断到没到家，就再给这条配置文件挂一个半径很大的「位置：网络」条件——只有当你先进入这个片区，Wifi 扫描才会启动；平时它根本不扫。

同理，一条配置文件里既有「时间」又有「应用」条件时，只有时间落在范围内，Tasker 才会去判断当前是哪个应用在前台。写完一堆规则后，顺手回看一遍是不是给耗电条件配了个把关的，收益通常最大。

## 二、位置类到底差多少

位置类的差异最悬殊，官方给过一份能耗与精确度的对照（星号越多越高）：

| 方式 | 能耗 | 精确度 | 大致适用 |
| --- | --- | --- | --- |
| 状态：靠近基站 | 最低 | 最低 | 只求「在不在这个片区」 |
| 位置：网络 | 低 | 低 | 目标地点附近有网络、精度要求不高 |
| 位置：网络和 Wifi | 中 | 在建筑密集区域很好 | 想要较准的位置又不想开 GPS |
| 状态：靠近 Wifi | 较高 | 很高 | 家里、公司这类有固定 WiFi 的地方 |
| 位置：GPS | 最高 | 最高 | 户外移动场景，只有它才够准 |

两点补充：官方文档的中文版与英文版在「靠近 Wifi」的能耗星级上并不一致，方向上的结论倒是一致的——**基站与网络类最省、GPS 最费**；另外「靠近基站」虽然最省，但它需要你本人到过那个地点扫描登记一次才能用。

精度和能耗在这里是同向的：想省电就得接受粗一点的位置判断。绝大多数「到家 / 到公司」的需求，用「靠近 Wifi」就够了。

## 三、息屏之后它是怎么检查的

屏幕关闭后，机械地一个个条件轮流检查会让设备反复被唤醒，反而更费电。官方的做法是：**把当前需要的检查集中在同一次唤醒里一起做完**，把醒着的时间压到最短。

这个行为有频率上限，位置在「首选项 → 监视器 → 屏幕关闭全部检查」：

- **间隔调大**：更省电，但条件变化的反应会变慢——比如「靠近 Wifi」判定你已离开会更迟；
- **间隔调小**：反应更快，耗电更高。

这是一个明确的取舍旋钮，没有同时对两边都好的设置。只有在你确实觉得反应太慢时再调小。

需要提醒的是，调到再大也改不了「息屏期间能不能感知」这个前提——息屏监控本身要在首选项里按条件逐个开启，开都没开的话调频率没有意义，这一点见 [权限与后台省电怎么设置.md](权限与后台省电怎么设置.md)。

## 四、按这份清单减负

从收益最高的做起，不必全做：

1. **能拆成事件就不要用状态。** 事件类条件只在事情发生的那一刻唤醒应用，状态类则要持续盯着。例如「插上充电器」用事件，「充电到 100%」才需要状态。
2. **位置别再默认用 GPS。** 家、公司、常去的地方优先「靠近 Wifi」；只要个大概范围就用「靠近基站」或「位置：网络」，取舍见第二节那张能耗与精确度对照表。
3. **给耗电条件加把关条件。** 就是第一节那条规律，同一条配置文件里用省电条件限制耗电条件。
4. **只开你真正需要的息屏监控。** 息屏期间也要感知的条件才开，用不上的关掉。
5. **长期不用的规则禁用或删掉。** 被禁用的配置文件不再参与条件监控，也就不再消耗；留着只是占个位置。
6. **传感器和手势类条件要克制。** 它们排在耗电顺序的最末端，靠加速度传感器持续工作，不适合常驻监听一整天。
7. **用了 GPS 条件就去调 GPS 超时。** 室内长时间搜不到卫星会持续耗电，把超时调到「小到刚好还能用」比保持默认更省。

## 五、怎么确认到底是谁在耗电

只看「设置里 Tasker 占了百分之几」是不够的，那一栏看不出是哪条规则。两步定位：

- **看系统电池用量里的分项。** 有的系统会分「前台 / 后台」，后台占比高说明问题出在常驻监听上，而不是你偶尔跑一次的任务。
- **看运行日志的触发频率。** 打开菜单里的运行日志放一阵子，如果某条规则被反复触发，说明它的条件在边界上反复进出——常见于位置类的半径画得太小，人一晃动就进出一次。修法是放宽半径或改用更稳的条件。

要量化比较，可以用最笨但最准的办法：把所有配置文件禁用，观察一两天的电量基线；然后分批启用，看哪一批拉高了耗电。这比逐条猜测快。

顺便给个量级参考：有长期使用者反馈，一个配置文件大约占用 1 MB 左右的常驻内存，事件类任务只在运行时占用、跑完就释放。这属于个人实测的口径，机型、规则数量、系统的差异都会让它变化很大，只当量级参考，别当规格。

## 六、先分清两种「耗电」

排查时要先回答一个问题：是**待机耗电偏高**，还是**正常使用中电量掉得快**？

- 待机时掉得快：方向是常驻监听——按本文第四、五节处理；
- 使用中掉得快：往往是任务本身在做重活（大批量文件操作、频繁联网、反复定位取当前位置），该看的是任务里的操作，而不是加了多少条规则。

两种情况混在一起判断，很容易去改错地方。定不下来时，先用运行日志把频繁触发的规则找出来，通常答案就在里面；如果日志里没有异常触发，说明问题多半不在规则上。
