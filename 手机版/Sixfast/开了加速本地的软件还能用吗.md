# Sixfast 开了加速本地的软件还能用吗

> 加速器要接管网络流量，很多人装之前的第一反应是「那我本地的 Gmail、YouTube、Instagram 是不是就用不了了」。本篇讲官方给的说法、它在什么前提下成立、花三分钟怎么自己验一遍，以及哪几种情况下你确实会感觉到本地应用被拖慢。

## 一、官方给的说法：智能分流

官方在应用商店的产品说明里写得很直接：**「智能分流模式：智能识别国内外流量，仅加速需要回国的流量，不影响海外应用（如 Gmail、YouTube、Netflix）的正常使用。」** 按这个说法，你能用的东西取决于你自己那份加速清单，而不是「开了加速就全都回国内走一圈」。

**这条说法有个前提**：你用的是按应用走的加速，不是把所有流量一起推回国内的那种形态。加速器这一类产品里确实存在「全局加速」的做法，那种模式下本地应用会被一起接管。Sixfast 官方给出的形态是前者，但最终的判断依据应该是**你自己设备上的实测**——第三节给方法。

## 二、从实际表现看，它按什么决定哪条流量进通道

观察下来，它的分流看的不是「这是哪个应用」，而是「这条连接要去哪个方向」。这解释了几种看起来矛盾、其实正常的情况：

| 你的操作 | 通常的结果 |
| --- | --- |
| 视频 App 在加速清单里，你用它看国内内容 | 走回国通道 |
| 同一个 App 里点开一条指向海外站点的链接 | 目标在海外，通常不进通道 |
| 浏览器不在加速清单里，你用浏览器开国内网站 | 这个应用整体没被加速，速度不会有变化 |
| 一边加速着国内应用，一边刷本地社交应用 | 本地应用仍走原来的出口 |

这也解释了一个高频困惑：**明明「已经加速了」，某个国内服务还是打不开** —— 因为你正在用的那个应用压根不在加速清单里。加应用的路径见 [加速模式与线路怎么选.md](加速模式与线路怎么选.md) 第三节。

## 三、花三分钟自己验一遍

不用听任何人（包括这篇）打包票，做两个对照实验：

1. **本地服务对照**：加速前打开一个你常用的本地服务，留意打开速度；加速成功后再开一次，对比感受。
2. **同类目标对照**：在同一个应用里，国内目标与海外目标各打开一次，看哪一类变快、哪一类没变。

结果符合「只有国内目标变快、本地应用照常」，说明按应用分流在你这台设备上是成立的。如果本地应用也明显变慢，直接看第四节。

## 四、什么情况下本地应用真的会被影响

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 本地应用整体变慢 | 当前模式把所有流量都带进了通道 | 换回影音 / 应用这类按应用加速的模式 |
| 只有某一个本地应用变慢 | 它被误加进了加速清单 | 进「编辑加速应用」把它移到未加速那一栏 |
| 挂了一整天，整机网络都变慢 | 通道本身在占用上行带宽 | 不用时点「停止加速」断开，不要长期挂着 |
| 断开加速后网络仍不正常 | 系统里还留着通道配置没清干净 | 见 [后台掉线与防断线设置.md](后台掉线与防断线设置.md) 第七节 |

最后一行不是分流走错了，是配置残留，按那一节的处理办法清掉即可。

## 五、手机、电脑、电视上的差别

- **手机端**：加速范围由你选的那份「已加速应用」清单决定，清单之外的应用按官方说法不受影响。
- **电脑端**：加速对象是游戏本体、应用进程或浏览器；用 Chrome 插件时，插件只作用于浏览器内的流量，浏览器之外的程序不经过它。
- **电视端**：加速对象是电视上的播放应用，同一网络里的其它设备不在它的加速范围内。

**总结成一句**：它影响的是你指定的那部分应用访问国内网络时的流量，而不是整台设备的全部流量。这句结论要在你自己设备上按第三节的两个对照实验站住脚，才算数。
