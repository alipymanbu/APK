## 一、Teleport 是什么、前提是什么

Teleport 是 UniFi 网关自带的一种免配置 VPN：你人在外面，用手机上的 WiFiman 一键连回家里/公司的内网，像坐在局域网里一样访问 NAS、摄像头、内网页面。它基于 WireGuard 传输，流量在你的设备与网关之间直接走，不经第三方中转。

**前提（不满足就用不了）**：

- 家里/公司有一台 **UniFi 网关**（新一代网关或运行 UniFi OS 的 UniFi Cloud Gateway）；
- 网关侧已开启远程访问并绑定了 UI 账号；
- 手机装好 WiFiman（见[下载与安装教程](下载与安装教程.md)）。

没有 UniFi 网关的普通路由器环境，这个标签页连不上是设计如此，换别的 VPN 方案，别在这页反复试。

## 二、网关侧：生成邀请

操作在网关的管理界面里做（管理端位置以你的 UniFi OS 版本界面为准，一般在网络设置的 VPN / Teleport 相关项下）：

1. 登录网关管理页面，进入 Teleport 设置。
2. 打开 Teleport 开关。
3. 点「创建邀请」，得到一条邀请链接，发给自己或要授权的人。

两条硬规则，官方写死的：

- **邀请链接 24 小时后过期**；
- **一次邀请只能被一台设备使用**。

要给多台设备用，就一条一条另外生成。

## 三、手机侧：接受并连接

1. 点开邀请链接（手机上装了 WiFiman 会自动唤起它；没装会先提示安装，装完再点一次）。
2. 应用读到链接后自动把这条 VPN 加进 Teleport 列表。
3. 回到 WiFiman 的 Teleport 页，点连接，状态变成已连接即可。
4. 验证：浏览器打开内网设备的管理地址，或 ping 一个内网 IP，通了就是真连上。

连接建立后，手机的 DNS 会切到网关的 DNS——在外也能解析内网主机名。

## 四、撤销与管理

对方拿到的权限随时可以收回，两个位置：

| 情形 | 去哪撤 |
| --- | --- |
| 邀请已生成、对方还没接受 | 邀请历史（Invitation History）里撤销该邀请 |
| 对方已经接受、正在用 | 客户端设备（Client Devices）列表里找到那个 Teleport 客户端，删除/撤销 |

撤销后对方立即失去访问权。自己换了新手机要重装，也是走「重新生成邀请 → 新机接受」这条路。

## 五、连不上时的排查顺序

从最常见到最少见：

1. **邀请过期**：超过 24 小时的链接直接失效，重新生成一条。
2. **链接已被别的设备用过**：一次邀请一台设备，换设备要新邀请。
3. **网关远程访问没开**：管理端确认远程访问与 Teleport 开关都开着、UI 账号登录正常。
4. **网络环境特殊**：官方说明 Teleport 在网关与客户端都处于 NAT 后时仍可用；但**部分情况下网关的 WAN 侧需要 IPv6 连接**（LAN 不用开 IPv6）——家里宽带没有 IPv6 时，这可能是连不上的根因。
5. **旧版本的老问题**：本地这版 2.10.0 的更新日志写明修复了「Teleport 无法连接导致的崩溃」；如果手上的包是更早版本，连不上先换包重装。

更细的逐条判断见[常见问题与故障排查](常见问题与故障排查.md)。
