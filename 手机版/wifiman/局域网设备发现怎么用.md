## 一、这页能干什么

Discovery（发现）页做的事很直接：让手机摸一遍所在局域网，列出在线设备和它们的地址。典型用法有三个——

1. **找设备 IP**：知道某个设备在网里、但不知道地址（比如要进它的管理页面），扫一遍就出来。
2. **判断设备到底通没通**：新买的 UniFi 设备没被管理端识别、摄像头掉线，先看它在不在扫描结果里。
3. **看网络里都有谁**：排查「是不是有台陌生设备蹭网」，扫完对着 MAC / 主机名逐个认。

不依赖 UniFi 设备，普通路由器的网络一样能扫。装好后第一次用，权限按[下载与安装教程](下载与安装教程.md)给全，否则结果会缺。

## 二、操作步骤

1. 手机连上要扫描的那个网络（WiFi）。
2. 进 Discovery 页，开始扫描。
3. 等列表出来，按 IP、主机名或设备类型看结果。

它用来识别设备的手段包括 Bonjour、SNMP、NetBIOS 和 Ubiquiti 自家的发现协议——**认得越全的设备，列表里信息越多**：只回 ARP 的设备通常只有 IP 和 MAC，回 SNMP 或 NetBIOS 的还能带出主机名、设备型号。

## 三、能看到哪些字段

扫出来的条目里，你能查到的信息大致分三层：

| 层级 | 字段 |
| --- | --- |
| 本机所在网络 | IP 地址、子网掩码、网关、DNS 服务器、SSID、BSSID、信号强度、无线信道 |
| 每台设备 | IP 地址、MAC、主机名（能认出来的话）、厂商/型号（Ubiquiti 系设备信息最全） |
| 连接质量 | ping 延迟、丢包率 |

## 四、对单台设备继续下手

列表里点开任意一台设备，还能做几件事：

- **ping 它**：看通不通、延迟多少，判断是「设备死机」还是「服务没开」。
- **端口扫描**：查指定端口是否在监听，确认摄像头 Web 页、NAS 管理页这类服务是否活着。
- **服务识别**：设备若回应了发现协议，会列出它暴露的服务。
- **蓝牙信号强度**：附近蓝牙设备的连接质量也能在这里看，用来排查无线外设（键鼠、音箱）断连是距离问题还是干扰问题。

这套「先扫出来、再对单台深挖」的顺序，也是官方排障文档里查设备 IP 的标准路子——扫描的边界见下一节。

## 五、扫不到？先认清它的边界

这是本页被问得最多的问题，边界先说清楚：

- **只能扫到同一个网络里的设备**。官方文档明确写了：没有 UniFi 网关时，只能检测到与手机所连 WiFi **相同网络 / 相同 VLAN** 的设备。手机连着访客 WiFi、设备在另一个网段，扫不到是正常结果。
- **AP 隔离（客户端隔离）开着时**，被隔离的设备对手机不可见，这不是扫描失败。
- **设备不响应任何发现协议**（防火墙把探测包全丢了）也进不了列表。

如果设备确实在同一网段却还是不出现，按[常见问题与故障排查](常见问题与故障排查.md)逐条查：手机与设备是否真的同网段、有没有开 AP 隔离、UniFi 设备与管理端之间的 8080 端口是否通。

## 六、配合找 UniFi 设备的 IP

官方排障流程里，WiFiman 正是「找不到设备 IP 时」的标准工具：

1. 手机连到与待查设备相同 VLAN 的 WiFi。
2. 打开 Discovery 扫描。
3. 在结果里找那台 UniFi 设备。

如果它显示的地址是 `192.168.1.20`，那是设备没拿到 DHCP 地址时的后备 IP——问题在网线、交换机端口或 DHCP 上，不在扫描这步。拿到正确 IP 后，设备纳管、进管理页面这类操作才能继续。

在电脑前排查时不必掏手机：[桌面版与手机端功能区别](桌面版与手机端功能区别.md)里说了，桌面版保留的功能正好就包含这一页。
