# 谷歌验证器和微软验证器的区别

> 两款最常被拿来比较的验证器应用：都免费、都出 6 位动态码，但定位差别不小。本篇按实际用途说清怎么选。

## 一、先说结论

- 只想给 GitHub、交易所、游戏平台这类站点加两步验证 → **谷歌验证器够用**，体积小、操作路径短；
- 公司/学校要求你装验证器、或你想用微软账号的「无密码登录」→ **微软验证器**，那是它的主场；
- 拿不定主意就装谷歌验证器，它是这个品类的最小集：把「出验证码」这一件事做完。

## 二、功能对照

| | Google Authenticator | Microsoft Authenticator |
| --- | --- | --- |
| 安装包体积 | 几 MB | 几十 MB |
| 核心用法 | 生成动态验证码 | 验证码 + 推送批准 + 无密码登录 + 通行密钥 |
| 云端备份 | 同步到 Google 账号 | 同步到 Microsoft 账号 |
| 企业场景 | 一般不涉及 | 工作学校账号（Entra ID）常用，企业策略可能强制安装 |
| 通知与交互 | 无推送，打开应用看码 | 登录时弹推送，点批准（新版本还要求输入屏幕上显示的数字做匹配） |
| 平台 | 安卓 / iOS | 安卓 / iOS，另有配套的桌面登录体验 |

两款应用的详细用法各自成篇：谷歌验证器侧的绑定与迁移见本目录其他几篇；微软验证器侧的关键词是「推送批准」和「无密码」，不再展开。

## 三、出验证码这件事，两者是通用的

两款应用都遵循同一套验证码标准（基于时间的一次性密码）：平台绑定页给出的那张标准二维码，谁扫都能用。所以：

- 同一个平台账号，绑定在谷歌验证器里还是微软验证器里，登录体验没有区别——都是输密码后填 6 位码；
- 反过来，**同一个账号的密钥只应存在一个应用里**。两个应用绑了同一个密钥虽然都能出码，但会让「到底哪份是有效的」变得混乱，改绑平台时容易漏删一份；
- 两款应用可以共存于同一部手机：一部分账号用谷歌验证器管，另一部分（比如公司要求的）用微软验证器管，互不干扰。

## 四、怎么在两者之间搬家

想从一款换到另一款，最稳妥的路子是**逐个平台重新绑定**：登录平台安全设置 → 重新生成二维码 → 用新应用扫。虽然账号多时麻烦些，但每一步都可控。

直接扫码搬有格式门槛：谷歌验证器导出**单个账号**时生成的二维码是通用格式，多数验证器（含微软验证器）都能扫；但**多账号批量导出**的二维码是谷歌自家格式，只有另一台谷歌验证器认。具体导出步骤与注意事项见[换手机账号迁移方法](换手机账号迁移方法.md)。

## 五、云端备份的口径差异

两者都把「绑定账号的密钥」同步到各自家的云账号上，但注意两点：一是同步的是**验证码密钥**，不是平台账号本身，平台侧的绑定关系不受影响；二是把密钥交给哪家云，就意味着你要把对应的 Google / Microsoft 账号本身守护好——账号一旦失守，密钥跟着失守。谷歌验证器云同步的安全讨论与应对见[账号云同步设置](账号云同步设置.md)；不管选哪款，各平台的备用验证码都要按[添加账号与扫码绑定](添加账号与扫码绑定.md)第五节说的当场存好。
