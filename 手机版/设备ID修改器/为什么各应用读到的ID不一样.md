# 为什么各应用读到的设备ID不一样

> Android 8 之后同一台手机上不同应用读到的 Android ID 本就可能不同——改完 ID 后怎么核对、哪些现象算正常。

## 一、先说结论

你在两个不同应用里查看 Android ID，读到的值**可能本来就不一样**——这不是没改成功，而是 Android 8.0 起系统的既定规则。所以核对「改没改生效」，要固定用同一个应用查看、或回 [修改设备ID步骤.md](修改设备ID步骤.md) 的应用界面看当前值，别拿两个不同应用互相对照。

## 二、Android 8.0 起的官方规则

Android 官方文档（Android 8.0 行为变更）写明的三条事实：

1. **Android ID 按「应用签名密钥 + 用户 + 设备」的组合来定范围**——每个组合拿到一个唯一的 ANDROID_ID；
2. 因此**同一台设备上、签名不同的两个应用，读到的 Android ID 不相同**（即使登录的是同一个用户）；
3. **同一个应用只要签名没变，卸载重装后读到的 ID 不变**（前提是此前没有以「还原备份数据」的方式装过它）。

这三条只讲「应用读到什么」，不讲系统内部怎么存的——你只需记住对照规则：**换应用对比 ID 没有意义，同应用前后对比才有意义**。

## 三、改完之后怎么核对才对

| 核对方式 | 结果怎么读 |
| --- | --- |
| 在设备ID修改器界面看当前值 | 重启后等于你设的值 → 修改已生效，这是标准判据 |
| 同一个应用里前后各看一次 | 前后不同 → 生效 |
| 两个不同应用各看一次 | 值不同属正常（第二节规则），不能作为没生效的证据 |
| 系统设置里某些机型展示的「设备 ID」 | 展示的未必是应用读到的那个值，不建议拿它当判据 |

改完仍不生效的排查路径在 [常见问题与排查.md](常见问题与排查.md) 第一节，本篇不重复。

## 四、只改 Android ID，有的应用可能还是不认

有用户反馈：把 Android ID 改掉后，个别应用（尤其是要求「设备唯一」的办公/管理类应用）仍然认得这台设备。原因可能是这类应用除了 Android ID 还绑定了其他标识（比如序列号、硬件信息），或者用的是它们自己汇总的设备识别方案——**Android ID 只是其中一个输入**。

对此你只有两个选择，都在你自己的设备与自己的账号范围内：

- **恢复原始 ID**（[修改设备ID步骤.md](修改设备ID步骤.md) 第三节），让一切回到改动前的状态；
- **接受现状**：设备ID修改器改的就是 Android ID 这一项，别的标识它管不着，也不该指望它管。

除这两条外的「更深层修改」办法，本篇不提供也不推荐——超出正当使用范围的路子风险高，别往那个方向找。

## 五、这些场景提前有个预期

- **重装应用不丢 ID**：签名不变的同一应用卸载重装，读到的 Android ID 依旧（第二节第 3 条），所以「重装一下让新 ID 生效」是无效操作，该做的是重启手机。
- **恢复出厂设置会换 ID**：官方说明过恢复出厂设置后设备 ID 可能发生变化——这也是 [下载与安装教程.md](下载与安装教程.md) 里建议改前先备份的原因：备份能让你在不恢复出厂的情况下随时回到原值。
- **系统更新不保证**：ID 作用域规则自 Android 8.0 起生效，后续版本是否调整以 [Android Developers](https://developer.android.com) 的官方文档为准（截至本文记录时未见变更说明）。
