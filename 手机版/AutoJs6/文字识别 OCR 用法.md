# AutoJs6 文字识别 OCR 用法

> 屏幕上的文字读不到控件、或者字长在图片里时，用 AutoJs6 的 ocr 模块把文字识别出来，本篇讲两种工作模式、最短可用代码和前置的截图授权。

## 一、什么场景用得上

控件操作（`text()` / `id()` 那套）只能读「控件树」里的文字，遇到下面这些情况它就抓瞎了，OCR 是补位的手段：

- 文字画在图片、视频帧或游戏画面里，根本没有对应控件；
- 界面是 WebView 或自绘控件，布局分析里读不到文本属性；
- 想识别的不是当前屏幕，而是相册里的某张图、某张扫描件。

OCR 模块从 6.3.0 起可用，6.5.0 的这份安装包里已经带上了。

## 二、先解决截图授权

识别当前屏幕的前提是能截屏。第一次跑截图相关代码时，系统会弹「屏幕录制 / 投屏授权」确认框，点允许；重启手机后授权通常失效，要重新弹一次。授权相关的完整坑（后台弹不出授权框、定时任务里首次要手动授权等）见 [常见问题排查.md](常见问题排查.md) 第三节。

## 三、两种工作模式

| 模式 | 基于 | 说明 |
| --- | --- | --- |
| `mlkit`（默认） | Google ML Kit 文字识别 | 多数设备开箱即用 |
| `paddle` | 百度 PaddlePaddle（Paddle Lite） | 备选引擎 |

读取和切换用 `ocr.mode`：

```javascript
console.log(ocr.mode);      // 查看当前模式
ocr.mode = "paddle";        // 切换到 paddle 模式
```

如果设备上缺 Google 相关服务组件导致 `mlkit` 模式识别异常，切 `paddle` 模式试试；两种模式的细节差异以官方 [ocr 模块文档](https://docs.autojs6.com/#/ocr) 为准。

## 四、最短可用代码

识别当前屏幕上的全部文字：

```javascript
// ocr() 一行等价于：请求截图授权 → 截屏 → 识别
let texts = ocr();
console.log(texts);   // 输出字符串数组，每个元素是一段识别出的文字
```

`ocr()` 不传参数就是识别全屏。常用的几个变体：

```javascript
ocr.recognizeText();                          // 与 ocr() 等价的别名写法
ocr([100, 200, 500, 300]);                    // 只识别屏幕上一块区域 [左上角x, 左上角y, 宽, 高]
let result = ocr.detect();                    // 返回检测结果，带每个文字块的位置信息
```

「识别到再点它」的场景走 `detect()` 拿到位置后操作对应坐标区域；具体的返回结构和区域参数写法，官方 ocr 文档里都有完整说明。

## 五、识别不准、识别不到时

按影响从大到小排：

1. **图源质量**：分辨率低、压缩严重、文字模糊的图，识别率明显下降——这是文字识别引擎的共性（Google 对 ML Kit 的输入建议里也明确要求图片清晰）；
2. **识别范围太大**：全屏识别速度慢、噪声多，用区域参数把范围缩到目标那一块，又快又准；
3. **模式与语言不匹配**：个别语言在不同引擎下的支持度不同，识别结果明显异常时先换一种模式对比；
4. **截图时机太早**：页面还没加载完就截了图，识别出来的自然不是你要的内容，截屏前加 `sleep()` 等页面稳定。

识别只是读，点不准的问题（点到偏移位置）是坐标换算的事，见 [常见问题排查.md](常见问题排查.md) 第六节。
