## 一、无障碍服务频繁被关闭

症状：早上还好好的，下午脚本就点不动了；或者重启手机后服务直接消失。

- 常规处理（自启动、电池白名单、任务卡片加锁）见 [无障碍权限开启教程.md](无障碍权限开启教程.md) 第三节；
- 判断服务是否还活着的最快办法：打开布局分析，读不到屏幕控件就是服务掉了；
- 部分系统（尤其深度定制的国产系统）在内存吃紧时会强制回收无障碍服务，设置压不住时，把 AutoJs6 加进系统的「后台清理白名单 / 加速白名单」；
- 用无障碍的应用不止 AutoJs6 一个时，注意系统对无障碍服务的数量限制，个别系统同时只保一个活跃服务。

## 二、定时任务到点没跑

按 [定时任务设置方法.md](定时任务设置方法.md) 第三节的顺序查：自启动 → 电池 → 锁定 → 无障碍状态 → 时间配置 → 日志。多数情况死在前三条（省电策略杀后台）。

一个有用的区分：**日志里到点有记录**说明定时触发是好的，问题在脚本运行环节；**日志里什么都没有**说明应用当时已经被杀了，先解决保活。

## 三、截图、找色功能用不了

脚本里用到截图、找色、找图时，系统会弹出「屏幕录制 / 投屏授权」的确认框：

1. 首次运行截图相关脚本时，会弹出系统的媒体投影授权框，点「立即开始」；
2. 弹框里有「不再询问 / 始终允许」选项的，勾上，下次免确认；
3. 很多系统在**手机重启后**授权会失效，脚本报截图相关错误时先重新跑一次、重新授权；
4. 截图必须在前台弹出授权框才能完成——如果脚本是在定时任务里后台跑的，第一次先把脚本手动跑一遍完成授权，之后定时里才能正常截图。

找不到颜色 / 找不到图还可能是另一个原因：目标页面是视频或动态壁纸类内容，帧内容变化快，用固定截图去匹配自然时灵时不灵。

## 四、脚本打包成 APK

AutoJs6 支持把脚本文件或整个项目打包成独立的 APK 文件（在脚本或项目的菜单里找「打包」类入口）。打包时按向导填应用名称、包名、图标等基本信息。注意：

- 打包出的 APK 是独立应用，装到手机上不依赖 AutoJs6 本体；
- 打包功能的界面和选项随版本变化，以你手上版本的向导提示为准；
- 打包脚本里引用的外部文件（图片、配置）要一并放进项目目录才会被带上；
- 别用打包功能分发来路不明的脚本，打包出的 APK 责任在打包的人。

## 五、脚本在别的手机上跑不动

同一份脚本换台手机就出问题，常见原因按出现频率排：

| 原因 | 表现 | 处理 |
| --- | --- | --- |
| 分辨率 / 像素密度不同 | 坐标点击点到空处 | 改用控件选择器（文本、ID）定位，不用固定坐标 |
| 系统版本差异 | 某个 API 报不存在 | 查官方文档各模块对系统版本的说明，对高版本系统特性做降级处理 |
| 厂商定制系统 | 控件树读不全、点击无效果 | 无障碍设置里把目标应用的相关开关打开；个别控件只能换定位思路 |
| 目标应用版本不同 | 界面改版、控件文本变了 | 选择器条件写宽松一点（比如只匹配部分文本） |

核心思路一句话：**依赖控件属性，少依赖坐标**，脚本的可移植性会好很多。

## 六、语法报错与引擎差异

AutoJs6 用 Rhino 引擎执行脚本，支持 ES5 全部与 ES6 部分特性。从网上抄的脚本报语法错误时：

- 先看报错行用了什么语法，箭头函数、`let` / `const`、模板字符串等在较新版本里可用，但个别 ES6+ 特性仍不支持；
- 报错信息在日志面板里，长按可复制，拿去搜索或贴到社区提问；
- 各 API 的准确用法以官方文档站 [docs.autojs6.com](https://docs.autojs6.com/) 为准，文档站也有专门的疑难解答（Q&A）章节。

## 七、安全提醒与反馈渠道

- 脚本能读屏、模拟点击、联网，**别运行来路不明的脚本**，跑之前通读一遍代码，重点看有没有读验证码、发短信、上传文件之类的动作；
- 无障碍权限同理，只给你信任的应用开；
- 遇到疑似程序缺陷，可以去官方仓库的 Issues 页（[github.com/SuperMonster003/AutoJs6/issues](https://github.com/SuperMonster003/AutoJs6/issues)）搜索或提交，附上日志和复现步骤更容易被处理。

安装、版本信息相关的问题（装不上、版本区别）先看 [下载与安装教程.md](下载与安装教程.md)。
