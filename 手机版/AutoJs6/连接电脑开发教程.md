## 一、为什么连电脑写脚本

手机上改代码的效率大家都懂：没键盘、屏小、报错信息看不全。连上电脑后，你在 VSCode 里写、保存，脚本直接在手机上运行，日志也回显到 VSCode 的输出面板，改一行验证一行的循环快很多。

要准备三样东西：

1. 电脑装 [VSCode](https://code.visualstudio.com/)；
2. VSCode 里装 **AutoJs6-VSCode-Extension** 插件，插件项目在 [github.com/SuperMonster003/AutoJs6-VSCode-Extension](https://github.com/SuperMonster003/AutoJs6-VSCode-Extension)，装法与命令以插件页说明为准；
3. 手机与电脑能互相访问（同一局域网最省事）。

## 二、方式一：客户端模式（局域网，推荐先试这条）

手机作为客户端去连电脑上开的服务：

1. 电脑 VSCode 里执行插件命令 **Start Server**（`Ctrl+Shift+P` 打开命令面板输入插件名能找到），状态栏或输出面板会显示服务地址和端口（默认端口 9317，以插件当时提示为准）；
2. 手机和电脑连同一个 WiFi；
3. 打开 AutoJs6，侧边栏里找「连接电脑」类入口，选客户端模式，输入电脑的局域网 IP 和端口；
4. 连接成功后 VSCode 侧会有提示。

之后在 VSCode 打开的 `.js` 文件上执行插件的运行命令（或用快捷键，以插件说明为准），脚本就推到手机上跑了；停止脚本的命令同理。日志在 VSCode 输出面板里看。

## 三、方式二：服务端模式（可走局域网或 ADB）

方向反过来：手机开服务端，电脑去连手机。AutoJs6 的服务端模式支持局域网连接，也支持 USB 连接（借助 ADB 转发）。这条路的典型用法：

- 局域网里客户端模式连不上（如路由器开了 AP 隔离）时换它试试；
- 手边有数据线时，USB + ADB 的方式不依赖 WiFi 稳定性，延迟也更稳。

用 ADB 方式需要电脑装好 Android 平台工具（platform-tools）并开启手机的 USB 调试，具体转发命令以 AutoJs6-VSCode-Extension 项目页的文档为准。操作入口：AutoJs6 侧边栏的连接设置里切到服务端模式打开开关。

顺带一提：这里装的 ADB 环境不是一次性的——以后如果要用 Shizuku 给 AutoJs6 提权（Android 10 及以下的机型走「连接电脑启动」），用的就是同一套 platform-tools，装一次两处受益，见 [Shizuku 提权与授权配置.md](Shizuku%20提权与授权配置.md)。

两种方式对比：

| | 客户端（LAN） | 服务端（LAN/ADB） |
| --- | --- | --- |
| 谁连谁 | 手机连电脑 | 电脑连手机 |
| 前提 | 同一网段、无 AP 隔离 | 局域网同上，或电脑有 ADB |
| 稳定性 | 受 WiFi 影响 | USB 方式最稳 |

## 四、连不上时查这几处

1. **IP 对不对**：手机侧填的是电脑的局域网 IP（`ipconfig` 看 IPv4 地址），不是 127.0.0.1——那是手机自己；
2. **同一网段**：手机别用流量；确认路由器没开「AP 隔离 / 访客网络隔离」，开了的话设备之间互相看不见；
3. **Windows 防火墙**：第一次开服务时弹的允许框别点取消；已经拒了的，到防火墙设置里放行 Node.js 或对应端口；
4. **端口被占**：输出面板报端口占用就换一个端口再开；
5. **路由器换了**：DHCP 分配的 IP 会变，连不上先重查 IP，或给电脑设固定 IP。

## 五、开发期的几个习惯

- 把脚本目录放在电脑上用 git 或其他方式备份，手机侧只当运行环境，换手机不丢代码；
- 日志用 `console.log()` 或 `toastLog()` 打在关键节点，VSCode 输出面板里排错比在手机上看快得多；
- 脚本写飞了（死循环、点不到控件狂重试）时，直接用手机浮动按钮的停止功能掐掉，见 [基础使用入门.md](基础使用入门.md)；
- 稳定后想让脚本脱离电脑、到点自动跑，转应用内定时任务，见 [定时任务设置方法.md](定时任务设置方法.md)。
