## 一、认识主界面

打开 AutoJs6 后你会看到一个文件列表式的界面，核心区域是脚本文件的浏览和运行入口：

- **脚本列表**：默认展示应用自带示例脚本所在的目录，点目录进入，点 `.js` 文件弹出操作菜单（运行 / 编辑 / 重命名等）；
- **编辑器**：应用内置了带代码补全、变量重命名、代码格式化的编辑器，点开脚本即可改；
- **侧边栏**：从屏幕边缘左滑，有文档、日志、设置等入口，设置里能开夜间模式、切界面语言。

你写的脚本就是普通的 `.js` 文件，放在手机存储里哪个目录都行，在应用里浏览到它就能运行。建议给脚本建一个自己的专用目录，和示例脚本分开。

## 二、跑第一个脚本

无障碍权限开好之后（没开的先看 [无障碍权限开启教程.md](无障碍权限开启教程.md)），按这个顺序试：

1. 在脚本列表新建一个文件，比如 `hello.js`；
2. 写入一行代码：

```javascript
toastLog("你好，这是我的第一个脚本");
```

3. 保存后点文件，选「运行」；
4. 屏幕下方会弹出一个悬浮提示并自动消失，同时日志里有记录。

再试一个带控件操作的，验证无障碍通道是通的：

```javascript
// 打开系统设置应用
app.launchApp("设置");
sleep(2000);
toastLog("当前包名：" + currentPackage());
```

能弹出当前应用的包名，说明无障碍服务在正常工作。`sleep(2000)` 是等 2 秒——脚本动作比手速快，操作之间留等待是这类脚本的基本习惯。

## 三、浮动按钮：最常用的快捷入口

在 AutoJs6 的设置或侧边栏里开启「悬浮窗 / 浮动按钮」后，屏幕上会多一个小圆球，展开后通常有这些功能：

- **运行 / 停止脚本**：不用切回应用就能停掉正在跑的脚本（脚本跑飞了全靠它）；
- **录制**：录下你的点击、滑动操作，生成可回放的脚本；
- **包名与活动**：显示当前屏幕对应的应用包名和 Activity 名称，写「打开某应用某页面」的脚本时直接照抄；
- **布局分析**：见下一节。

第一次开悬浮窗时系统会要求「显示在其他应用上层」权限，允许即可。

## 四、布局分析：写脚本前的侦查工具

布局分析打开后能看到当前屏幕的控件树：每个按钮、文本框的文本内容、控件 ID、位置边界都在里面。它类似 Android Studio 的 Layout Inspector，作用是让你写脚本前先「看清」要操作的对象：

1. 打开目标应用，停在你要自动化的那个页面；
2. 点浮动按钮里的布局分析，悬浮窗会列出控件信息；
3. 记下目标按钮的 `text` 或 `id` 值；
4. 回到编辑器，用选择器写操作，比如：

```javascript
// 点文本为"登录"的按钮
let btn = text("登录").findOne(5000);
if (btn) {
    btn.click();
} else {
    toastLog("5 秒内没找到登录按钮");
}
```

用控件属性定位（文本、ID）比用固定屏幕坐标点击可靠得多——换手机、换分辨率后坐标会偏，控件属性通常还在。找不到控件时，八成是目标页面结构变了或者无障碍服务被杀了。

## 五、录制与回放

浮动按钮里的「录制」走的是另一条路：不用写代码，直接把你的手部操作（点击、滑动）录下来存成脚本，之后可回放。适合一次性的简单重复操作。

录出来的脚本回放效果依赖页面元素位置不变——应用改版或换了设备就可能点错位置。所以录制适合临时凑合，想长期稳定运行的还是按第四节的思路用选择器写。

## 六、脚本放哪、从哪来

- 自己写的脚本建议放在自建目录，命名清楚用途；
- 官方文档站 [docs.autojs6.com](https://docs.autojs6.com/) 有各模块的 API 说明和示例，写的脚本里用到的每个函数都能在那查到用法；
- 控件树读不到的文字（图片、游戏画面里的）要用文字识别，`ocr` 模块的用法单独整理了一篇，见 [文字识别 OCR 用法.md](文字识别%20OCR%20用法.md)；
- 网上流传的现成脚本要谨慎：脚本能读屏、能点击、能联网发请求，运行来路不明的脚本等于把手机交给陌生人，跑之前至少通读一遍代码。

脚本变多之后想「到点自动跑」，用应用内的定时任务，见 [定时任务设置方法.md](定时任务设置方法.md)；想在电脑上写脚本、保存即推到手机运行，见 [连接电脑开发教程.md](连接电脑开发教程.md)。
