# AutoJs6 无障碍权限开启教程

## 一、不开无障碍会怎样

AutoJs6 属于基于无障碍服务的自动化工具：你写的脚本里那些「找控件、点按钮、滑动屏幕、读取文字」的动作，走的都是安卓的无障碍通道。无障碍服务没开时：

- 控件选择器（`text()` / `id()` 这类）查不到任何东西；
- 自动点击、滑动直接报错或没反应；
- 布局分析打开是空的。

只有纯计算、弹对话框、文件处理这类不碰屏幕的脚本不受影响。所以装完应用后的第一件事就是把这个权限开起来。

## 二、开启步骤（通用路径）

1. 打开手机「设置」；
2. 找到「无障碍」（有的系统叫「辅助功能」「无障碍功能」）；
3. 进入「已下载的应用」或「已安装的服务」分类（各系统叫法略有差别，有些系统要先点「更多已下载服务」）；
4. 在列表里找到 AutoJs6，点进去；
5. 打开开关，系统会弹出权限说明，点「允许」或「确定」；
6. 回到 AutoJs6，侧边栏或通知栏里能看到服务已启用的状态提示。

也可以从应用内进：AutoJs6 侧边栏有「开启无障碍服务」的快捷入口，点它会直接跳到系统的对应开关页。

部分系统开启时会再弹一层「此服务可以读取屏幕内容」的确认框，属正常流程，允许即可。

## 三、开了很快又被关掉（国产系统最常见）

无障碍服务被系统当成了「耗电的后台应用」，下面这几项逐个检查，处理完再观察：

| 检查项 | 操作位置 | 做什么 |
| --- | --- | --- |
| 自启动权限 | 设置 → 应用管理 → AutoJs6 → 权限 | 允许自启动，否则重启手机后服务不会恢复 |
| 电池策略 | 设置 → 应用管理 → AutoJs6 → 电池 | 改成「无限制 / 不受限 / 允许后台运行」，别用「智能限制」 |
| 后台锁定 | 最近任务界面 | 把 AutoJs6 的任务卡片下拉或长按加锁（MIUI 等系统的做法），防止一键清理时被杀 |
| 后台弹出界面 | 设置 → 应用管理 → AutoJs6 | 允许「显示悬浮窗 / 后台弹出界面」，悬浮按钮等功能依赖它 |

不同系统的措辞差异很大，但方向一致：**让系统别杀它**。改完之后最简单的验证方式是把手机锁屏放几分钟，回来点一下布局分析，还能正常读到屏幕控件就没问题。

小米 / Redmi / POCO（MIUI、HyperOS）这类管得最严的系统，上面四项之外还有几处藏得深的：

- **手机管家（安全中心）里的自启动**：管家应用 → 应用管理 → 权限 → 自启动，找到 AutoJs6 打开（和设置页里的自启动是两个入口，管家这个更容易漏）；
- **省电与电池 → 更多电池设置 → 睡眠待机优化**：夜里长待机时它会冻结未加白名单的应用，把 AutoJs6 移出优化范围；
- **流量节省模式**：开着的时候后台数据默认被拦，脚本要联网的（HTTP 请求类）给它「无限制的数据访问」；
- **开发者选项 → 后台进程限制**：确认是「标准限制」，以前手动改小过就会全局杀后台。

另外要有个合理预期：即便全设置了，也有用户反馈小米系统（尤其开着「内存扩展」功能时）仍会偶尔冻结后台应用——设置只能大幅缓解，不能承诺根绝。服务被关的常见触发点有三个：**重启手机**、**切换用户或进入隐私空间**、**应用自身更新**，碰上这三件事就回来看看服务状态。

## 四、权限之外：Shizuku 是另一条线

先把概念分清：第三节解决的是「无障碍服务被系统杀」，Shizuku 解决的是另一件事——AutoJs6 的部分功能需要 ADB 特权才能用（官方说明它支持通过 Shizuku 获得 ADB 特权并使用系统 API）。如果你用到提示「需要 Shizuku」的功能，就得单独把 Shizuku 配起来，完整的安装、启动、授权流程见 [Shizuku 提权与授权配置.md](Shizuku%20提权与授权配置.md)。它不是必须的，普通的无障碍自动化不碰它也能跑。

无障碍服务还涉及一个误解要澄清：开启它不代表 AutoJs6 在「偷数据」，但任何拥有无障碍权限的应用理论上都能读取屏幕内容，所以**别给它之外不相干的应用乱开无障碍权限**，也别运行来路不明的脚本（脚本同样能调用这套能力，见 [常见问题排查.md](常见问题排查.md) 的安全提示）。
