# AutoJs6 定时任务设置方法

> 本篇讲怎么让 AutoJs6 里的脚本在指定时间自动运行（应用内定时任务与 Tasker 插件两种路子），以及到点没跑时按什么顺序排查。

## 一、两种定时路子怎么选

| 方式 | 适合场景 | 依赖 |
| --- | --- | --- |
| 应用内定时任务 | 每天固定时间跑签到、整理类脚本 | AutoJs6 存活于后台 |
| Tasker 插件触发 | 到点之外还想按事件触发（连上 WiFi、到达某位置等） | 装 Tasker（付费应用） |

先试应用内的定时任务，够用就不必引入 Tasker。

## 二、应用内设置定时任务

1. 打开 AutoJs6，在主界面找到「定时任务」入口（侧边栏或列表页的任务面板，不同版本入口位置略有差异）；
2. 添加任务，选择要执行的脚本文件；
3. 选触发类型：
   - **一次性**：指定某个日期时间跑一次，跑完即止；
   - **每日 / 每周**：按天或按星期几循环；
   - **间隔 / 周期**：每隔 N 分钟或小时跑一次；
4. 保存后任务列表里能看到下一条的触发时间。

两个前提别忽略：

- **无障碍服务开着**：脚本里只要有控件操作，服务被杀就等于任务白跑（见 [无障碍权限开启教程.md](无障碍权限开启教程.md)）；
- **应用要在后台活着**：定时触发靠的是系统把 AutoJs6 拉起来，应用被杀得干干净净就没人守着闹钟。

## 三、到点没跑，按这个顺序查

定时任务不触发是新用户最常撞上的问题，原因几乎都在系统省电策略上。从上往下逐条对：

1. **自启动权限**：设置 → 应用管理 → AutoJs6 → 允许自启动。手机重启后定时任务能不能恢复，全看它（小米机型记得手机管家里的自启动入口也要开，见 [无障碍权限开启教程.md](无障碍权限开启教程.md) 第三节）；
2. **电池优化**：把 AutoJs6 加入电池优化白名单（或把电池策略改成「无限制」），省电激进是「到点没反应」的第一大原因；小米系还要把「睡眠待机优化」里的它移出优化范围，夜里长待机被冻结是隔天早上发现任务没跑的常见原因；
3. **最近任务里锁定**：一键清理会连着把守时的应用一起杀，把 AutoJs6 的任务卡片加锁；
4. **无障碍服务还在不在**：进 AutoJs6 看服务状态，被系统关了就重开（这也会导致「任务触发了但脚本一跑就停」）；
5. **后台弹不出界面**：从 Android 10 起，应用在后台不能自己弹界面——如果你的定时脚本第一步是打开某个应用或弹对话框，到点可能直接没动静；给 AutoJs6 开「后台弹出界面 / 显示在其他应用上层」类权限，多数系统能绕开这个限制（个别系统管得死，只能改成亮屏时段跑）；
6. **流量节省模式**：脚本要联网的，确认流量节省没把它的后台数据拦掉；
7. **触发时间写对没有**：部分系统的定时粒度对齐到分钟，保存后核对列表显示的「下次运行时间」；
8. **用日志确认**：AutoJs6 有运行日志入口，如果日志里到点有记录但脚本没跑完，问题就不在定时，而在脚本本身或无障碍状态。

一个实测有效的习惯：定时脚本放在晚上跑的，睡前确认应用还在后台任务列表里，比任何设置都直接。

## 四、用 Tasker 按事件触发

AutoJs6 支持作为 Tasker 插件使用。场景举例：手机连上家中 WiFi 时自动执行备份脚本，或每天早上闹钟响过后自动执行天气播报脚本。

1. 手机装好 Tasker（商店付费应用）；
2. Tasker 里新建一个「配置文件」，定义触发条件（时间、WiFi、位置等）；
3. 关联一个「任务」，任务里添加动作 → 插件 → AutoJs6；
4. 在插件配置里指定要执行的脚本路径，保存。

这样时间类触发走 Tasker 的时间条件，脚本执行交给 AutoJs6，两边各管一段。Tasker 侧同样要给它后台保活权限，否则触发条件到了它自己却被杀了。

定时之外想让脚本跑得更省事（电脑上编辑、保存即运行），见 [连接电脑开发教程.md](连接电脑开发教程.md)；脚本到点跑了但中途停、报错，见 [常见问题排查.md](常见问题排查.md)。
