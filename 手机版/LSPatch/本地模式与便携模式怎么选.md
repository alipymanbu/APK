# LSPatch 本地模式与便携模式怎么选

> 修补应用时要二选一的模式决定了模块放在哪、以后能不能改，本篇用一张对照表讲清差别与选择思路。

## 一、两种模式的差别

| 对比项 | 便携模式 | 本地模式 |
| --- | --- | --- |
| 模块放在哪 | 修补时勾选的模块直接嵌进产物 APK | 模块不进包，留在 LSPatch 管理器里 |
| 运行时是否依赖 LSPatch | 不依赖，装好即可独立运行 | 依赖，LSPatch 必须留在手机上并保持后台运行 |
| 能否把产物发给别人用 | 可以，对方不装 LSPatch 也能用上嵌入的模块 | 不行，只能在装了 LSPatch 的这台手机上用 |
| 事后增删模块 | 改不了，要加新模块就得用 APK 重新修补一遍 | 在管理器里随时调整该应用的模块作用域 |
| 换目标应用版本 | 每次都要重新修补 | 重新修补一次后，作用域照样可用 |

顺带一提：部分教程把便携模式写作「集成模式」（把模块集成进包的意思），指的就是同一件事，看到两种叫法不必疑惑。

## 二、什么情况选便携模式

- 目标应用和模块的搭配已经想清楚，短期内不会换；
- 打算把装好的 APK 直接发给别人（家人、另一台自己的设备）；
- 不想常驻一个管理器占后台。

代价是僵化：模块列表焊死在包里，想加一个、换一个，都得回到 [修补应用完整流程.md](修补应用完整流程.md) 把修补重来一次，并再次经历「卸载原应用 → 装新包」。

## 三、什么情况选本地模式

- 你还在试不同模块、经常调整作用范围；
- 同一台手机上想给多个应用灵活开关模块，不想每改一次就重修补一次；
- 能接受 LSPatch 常驻后台。

本地模式下给应用配模块的入口在管理器里：找到修补好的应用条目，**长按它 → 选「模块作用域」→ 勾选模块**，改完后重启目标应用（不放心就重启手机）再验证。

## 四、本地模式的保活问题

本地模式下，模块的加载由手机上的 LSPatch 负责，后台被系统杀掉，模块就会失效。能做的应对：

1. 在系统设置里允许 LSPatch 自启动、取消电池优化（不同品牌入口不同，一般在「电池 / 应用管理」里）；
2. 别在最近任务里手动划掉 LSPatch；
3. 官方在 0.6 版更新中移除了前台保活服务，意味着新版对系统的保活手段更少，上面两条更要做好。

如果保活让你头疼、模块搭配又固定，直接换便携模式重修补一次更省心。装好后模块没反应，先到 [常见问题排查.md](常见问题排查.md) 过一遍排查清单。
