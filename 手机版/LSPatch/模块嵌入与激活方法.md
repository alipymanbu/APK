# LSPatch 模块嵌入与激活方法

> 模块装上不等于生效 —— 本篇讲 Xposed 模块在两种修补模式下分别怎么带进应用、怎么确认它真的在跑。

## 一、先建立一个认知：模块是普通应用

Xposed 模块本身就是一个 APK，单独装到手机上不会有任何效果 —— 它需要框架来加载才会作用于目标应用。LSPatch 扮演的就是这个框架，而「带进应用」的方式取决于你选的修补模式。

## 二、便携模式：修补时一次性嵌入

1. 先把模块 APK 装到手机上（它此刻只是待命，还没生效）；
2. 按 [修补应用完整流程.md](修补应用完整流程.md) 走到选模式那一步，选便携模式；
3. 点「嵌入模块」，在弹出的列表里勾选要带的模块（这里列出的是已安装的模块；0.6 版起也支持直接从存储里选模块文件），确认后开始修补；
4. 修补完成并装上新包后，模块已经内置在应用里，不需要再开 LSPatch。

## 三、本地模式：在管理器里勾作用域

1. 修补时选本地模式，模块不会进包；
2. 修补完成并安装后，打开 LSPatch 管理器，找到这个应用的条目，**长按它 → 选「模块作用域」→ 勾选要让它加载的模块**；
3. 改完作用域后，重启目标应用（不放心就重启手机）再验证 —— 刚勾完就打开应用，加载的可能还是旧配置；
4. 保持 LSPatch 在后台存活 —— 被杀掉模块就失效，应对办法见 [本地模式与便携模式怎么选.md](本地模式与便携模式怎么选.md) 的第四节。

## 四、怎么确认模块已经生效

- 打开修补后的目标应用，进它的「设置」，多数模块会在这里出现自己的入口或状态页，能直接看到「已激活」之类的字样；
- 没有入口的，直接看功能本身有没有变化 —— 模块该改的地方变了，就是生效了；
- 模块自己的界面里如果显示未激活，回到上两节核对你对应模式的做法。

## 五、模块用不了的三个常见原因

1. **修补时没勾上**：便携模式下最常见，漏勾的模块不会进包，只能重新修补；
2. **作用域没勾 / 后台被杀**：本地模式的典型问题，对照上一节处理；
3. **模块本身不适配免 Root 环境**：官方提醒过非 Root 框架能力有限，一部分模块依赖 Root 环境才有的条件，在 LSPatch 下就是不工作。这类情况没有解决办法，换支持免 Root 的模块是唯一出路。

排到这一步还解决不了的，把现象带到 [常见问题排查.md](常见问题排查.md) 里对号入座。
