## 一、为什么会有渲染模式这个东西

Minecraft Java 版按电脑上的 OpenGL 标准画画面，而手机的 GPU 只直接认移动端的 OpenGL ES——中间必须有一层转换，游戏才能把画面画出来。这层转换就是渲染模式，转换方式不止一种，各有取舍，所以启动器把它做成了选项。

HMCL-PE 提供 **GL4ES** 与 **VirGL** 两个渲染模式（这是最终版 2.0.8 里的选项集合；项目已停更，不会有新的渲染方式加进来）：

| 模式 | 特点 | 代价 |
| --- | --- | --- |
| GL4ES | 覆盖游戏常用的那部分 OpenGL 功能，转换开销小，兼容面广，是大多数设备的日常之选 | 功能覆盖有限，跑不了光影 |
| VirGL | 提供更完整的 OpenGL 支持，光影画面只有它能出 | 开销大得多，性能不足的设备会明显掉帧、发热 |

## 二、按你的情况选

| 你的情况 | 建议 |
| --- | --- |
| 只玩原版或轻模组，机器一般 | GL4ES，省电省心 |
| 想开光影 | 只能 VirGL，没有第二条路（官方把光影绑定在 VirGL 上） |
| 机器性能强，想要更好的画面表现 | 可以日常用 VirGL；一旦掉帧严重就退回 GL4ES |
| 黑屏、花屏、材质异常 | 先切到另一个渲染模式再进游戏，能排除一大类渲染问题 |

切换位置在启动器设置里，切完重新启动游戏再验证。同一台机器两个模式都试一遍花不了五分钟，比看任何人的推荐都准——渲染表现和具体手机芯片强相关，别人的「最佳选择」未必是你的。

## 三、开光影前的预期管理

VirGL 加光影能出很好看的画面，但先把预期摆正：

- **性能代价是乘法级的**：光影叠在游戏本身的开销上，中端机器掉帧、发烫是正常现象，不是故障。4 GB 内存级别的机器基本告别光影；
- **从轻量光影试起**：先装资源占用小的光影确认能跑，再逐步换重的；直接上最重的光影黑屏了，先降低要求再排查（流程见 [常见问题与故障排查.md](常见问题与故障排查.md)）；
- **光影与模组可能打架**：OptiFine 一类画质模组本身带光影接口，和独立光影的搭配关系以模组说明为准，装两个都管画面的东西之前先想清楚谁负责什么。

光影与材质包的装法、入口在 [模组与整合包安装.md](模组与整合包安装.md)；画面异常的逐项排查在 [常见问题与故障排查.md](常见问题与故障排查.md)。
