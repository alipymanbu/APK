## 一、为什么模型不能随便挑

模型跑在手机内存里，**文件多大，运行时基本就要占多少内存**——而且还要额外留出上下文缓存和系统本身的开销。挑大了的后果按轻重排：加载直接失败 → 聊到一半闪退 → 一个字一个字往外蹦（还在跑，但慢到没法用）。三种症状的排查都在 [常见问题与解决方法.md](常见问题与解决方法.md)。

## 二、按手机内存对照着挑

**文件体积不等于内存占用**：一个 2GB 的文件，实际运行时想要的空闲内存会明显超过 2GB。下面按「运行内存」给对照（社区教程的通行经验，具体以你的实测为准）：

| 手机运行内存 | 建议模型体积 | 对应参数量级 | 说明 |
| --- | --- | --- | --- |
| 4GB 及以下 | 1~2GB | 1B~2B（如 SmolLM2 1.7B、Qwen 1.5B~2B） | 只求能跑，回答质量有限 |
| 6GB | 2~3GB | 3B 上下（如 Llama 3.2 3B、Qwen 1.7B） | 多数教程给 6GB 机型的推荐档 |
| 8GB | 3~4GB | 4B 上下（如 Gemma 3 4B、Qwen3 4B） | 有教程明确建议 8GB 内存选 4GB 以下的模型 |
| 12GB 及以上 | 4~7GB | 7B 量化版 | 仍有余量再往上看，先跑通再说 |

判断步骤：先看 Models 页每个模型显示的 **Size**，跟你手机「设置 → 关于手机/内存」里的可用空间、剩余内存对一遍——**文件放得下 ≠ 跑得动**，两个都要留余量。

## 三、量化档位怎么选

同一个模型在 Hugging Face 上会有多个 GGUF 文件，那是不同**量化档位**：

- 数字越小（如 Q2/Q3）：文件越小、越省内存，但回答质量掉得越多；
- 数字越大（如 Q8、F16）：越接近原始质量，内存需求也越高；
- **通用取法是 Q4 档**（如 `Q4_K_M`）——体积约砍半、质量损失可接受，是社区默认推荐的档位；内存紧张再往下降，余量充足也**没必要**追高。

拿不准就在 [模型下载与加载教程.md](模型下载与加载教程.md) 的下载页里对比同名文件的 Size，先下最小的 Q4 试跑，不行再调整。

## 四、中文对话优先选哪些系列

界面切中文只是壳，回答质量全看模型本身（见 [设置中文界面方法.md](设置中文界面方法.md)）。中文场景常见选择：

| 系列 | 特点 | 适合谁 |
| --- | --- | --- |
| Qwen（通义千问） | 中文语料充足，小参数版本多 | 中文日常对话首选 |
| DeepSeek（R1 系列小参数版） | 推理型，1.5B/7B 有 GGUF 版 | 想要「会思考」的回答、能接受慢一点 |
| Gemma | 中英均衡，4B 档表现稳 | 中英混用 |
| Llama | 英文最强、生态最大 | 英文场景 |
| Phi / SmolLM2 | 极小参数、跑得快 | 低配机、只做简单任务 |

**第一步建议**：先在内置列表里下一个小的 Qwen 或 Gemma 跑通全流程，确认你的手机能正常加载对话，再按需要换更好的——不要一上来就下 7B。

## 五、生成速度和质量怎么微调

跑通之后觉得慢或答得不好，按这个顺序动参数（都在 Settings 或模型设置里）：

1. **先换模型**：慢 = 模型对该手机太大，降参数量或降量化档位最有效，比调参数管用；
2. **温度（temperature）**：数值越大越发散，越小越死板；闲聊可 0.6~0.7，事实问答调低；
3. **上下文长度（Context Size）**：有教程建议首次用 8000 起步，在输出质量与性能间平衡（第三方经验，以你的实测为准）；
4. Models 页的**自动加载/卸载**保持默认开启，内存不够时它会兜底；
5. **确认加速有没有生效**：骁龙 Adreno GPU 的手机会走 OpenCL 硬件加速，其余情况回退到 CPU——同样大小的模型在不同手机上差出好几倍速度是正常的，聊天界面实时显示的每秒 token 数就是你这台手机的实际速度，换模型前后对比它最直观。
