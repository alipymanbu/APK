# MaaMeow 运行环境准备（Shizuku 授权）

MaaMeow 在普通应用拿不到的权限层面工作（创建虚拟显示器、模拟触控），所以它需要一条获得系统级权限的通道：要么设备已 Root，要么运行 Shizuku 并授权。绝大多数人走的是 Shizuku 这条路 —— 不用 Root、不刷机，本篇按这条路写。

## 一、先核对你的设备

| 项目 | 要求 |
| --- | --- |
| 系统版本 | Android 9.0 及以上（API 28） |
| 权限通道 | Shizuku 已运行并授权，或设备已 Root |
| 设备架构 | arm64-v8a 或 x86_64 |

三条件都满足再往下走。系统版本在手机「设置 → 关于手机」里看；架构方面，近几年的真机基本都是 arm64，一般不用操心。

## 二、Shizuku 是什么

Shizuku 是一个独立的安卓应用：它在你的手机上启动一个具备 ADB 级权限的服务进程，其他应用（这里是 MaaMeow）向它申请授权后，就能借这个进程使用系统级接口。它不修改系统、不需要 Root，官方手册见 [shizuku.rikka.app](https://shizuku.rikka.app/zh-hans/)。

对使用 MaaMeow 来说，你只需要记住两件事：

1. **Shizuku 必须处于「运行中」状态**，MaaMeow 才能被授权；
2. **手机每次重启后，Shizuku 服务会停**（非 Root 设备），需要重新启动一次 —— 不用重新配对，只是再点一次启动。

## 三、三种启动方式，选一种

| 启动方式 | 适合谁 | 要点 |
| --- | --- | --- |
| 无线调试 | Android 11 及以上、没电脑 | 全程在手机上完成，推荐首选 |
| 连接电脑 | Android 10 及以下 | 需要电脑与数据线，用 ADB 命令启动 |
| 通过 Root | 已 Root 设备 | 打开 Shizuku 直接启动，最省事 |

**Android 11+ 未 Root 用户走「无线调试」**，步骤如下：

1. 先开启系统的「开发者选项」（各机型方法不同，在 B 站搜「你的品牌 + 开发者选项」即可），并打开「USB 调试」与「无线调试」。
2. 打开 Shizuku，选「通过无线调试启动」→「配对」。
3. 进入系统的「无线调试」页面，点「使用配对码配对设备」，记下弹出的配对码。
4. 回到 Shizuku（它通常会以通知形式等待输入），填入配对码，完成配对。**配对只需要做一次。**
5. 回到 Shizuku 点「启动」，**停在启动界面别切走**，直到出现「Service started」字样 —— 官方 FAQ 特别强调：没等它跑完就切出去，是「显示已在后台启动但界面仍是未运行」的最常见原因。

Android 10 及以下没有无线调试入口，需要用电脑 ADB 启动，具体命令照 Shizuku 应用内的引导复制执行即可。

## 四、给 MaaMeow 授权

Shizuku 显示「运行中」之后：

1. 打开 MaaMeow，首次使用时应用会提示需要 Shizuku 权限，点「去授权」（入口一般在设置页）。
2. 系统会弹出「是否允许 MaaMeow 使用 Shizuku」的确认框，勾选允许。
3. 回到 MaaMeow 主界面，不再提示权限缺失即成功。

授权之后就可以去配日常任务了：[一键长草日常任务设置.md](一键长草日常任务设置.md)。

## 五、启动失败先看这三处

1. **配对成功但「启动」后仍显示未运行** —— 按第三节第 5 步处理：把 Shizuku 从后台划掉重新启动，启动过程中停留在界面等「Service started」。
2. **厂商系统的额外限制** —— 小米要单独开「USB 调试（安全设置）」、OPPO 系要开「禁止权限监控」等，各品牌开关对照表见[常见问题与故障排查.md](常见问题与故障排查.md)。
3. **启动日志报 `TimeoutException`** —— 属于 Shizuku 启动层面的故障，逐条尝试方案也整理在故障排查篇里。

这几种情况的详细处理步骤都在[常见问题与故障排查.md](常见问题与故障排查.md)，遇到就翻那篇。
