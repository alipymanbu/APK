主机记录你的操作并实时下发给多台从机，从机同步执行 —— 操作一次就能覆盖多机型的兼容性检查，不用每台设备各录一遍用例，也不用写自动化脚本。

## 一、和录制回放的区别

| 对比项 | 录制回放 | 一机多控 |
| --- | --- | --- |
| 设备数量 | 单台 | 一台主机 + 多台从机 |
| 用例的复用 | 用例存本地，可跨设备迁移后回放 | 操作实时下发，不依赖预先录制 |
| 典型用途 | 功能回归、冒烟 | 兼容性测试、批量安装与验证 |
| 网络要求 | 无 | 主从机需处于同一局域网 |

批量安装、查看设备信息这些也在这一页里。

## 二、准备工作

**每台参与测试的设备**（主机与所有从机）都需要：

1. 安装同一份 SoloPi 安装包——从 [SoloPi 安装文件资源（夸克网盘）](https://pan.quark.cn/s/9dc1f415070a) 获取后逐台装好；
2. 完成首次启动的权限配置（读写、adb、悬浮窗、后台白名单）；
3. 打开开发者选项中的 USB 调试，并在连接电脑后执行过 `adb tcpip 5555`。

一机多控会额外申请**相机**与**录屏**权限：相机用于主机扫描从机二维码建立连接，录屏用于响应耗时计算。这两项要在第一次进入一机多控时授权。

权限细节与机型差异（vivo 的 USB 安全操作、小米的 USB 安装与后台弹出界面、魅族的支付安全等）统一写在 [下载与安装教程.md](下载与安装教程.md) 里，配好再往下走。

## 三、主机模式

1. 打开 SoloPi，进入一机多控页面，**选择待测应用**，模式配置为**主机模式**，点击开始执行；
2. SoloPi 会提示开启辅助功能（无障碍）。点击前往开启并手动打开；如果遇到"辅助功能已开启但仍校验不通过"，先把辅助功能关闭再重新开启，仍然不通过就重启设备；
3. SoloPi 弹出操作悬浮窗，并自动跳转到被测应用的首页。这一步依赖 `android.intent.category.LAUNCHER` 解析启动页，被测应用没有正确声明时会跳转失败，需要手动打开；
4. **先扫描从机二维码，再点连接**。扫描过的设备会进入"未连接设备"区域，点击连接后才会真正建立连接；
5. 在悬浮窗中点击开始按钮，进入主机操作状态；
6. 正常操作被测应用。SoloPi 会拦截操作、高亮当前点击的控件并弹出操作选择框。若红框圈中的控件与预期不符，在全局操作里把模式切换到 **H5 增强模式**再试；
7. 处理弹窗、scheme 跳转等动作走全局操作：点击悬浮窗上的小葫芦图标唤起操作选择弹窗（Android 5.0 及以上；4.x 设备从屏幕底部上滑唤起）；
8. 全部操作完成后，在全局操作选择框中选择**结束**，断开与从机的连接，回到 SoloPi 一机多控页面。

> 执行期间留意悬浮窗图标颜色：**红色表示正在执行动作，动作完成后变为黄色**，转黄之前不要连续点击，否则容易丢步。

## 四、从机模式

1. 在 SoloPi 一机多控页面选择**从机模式**，点击开始执行。从机不需要选被测应用，主机会把应用信息传过来；
2. SoloPi 显示包含本机 IP 信息的二维码，等待主机扫码；
3. 主机扫码后，从机会收到连接提示，但**此时不会自动收起悬浮窗**，需要主机侧点击连接后才正式建立连接；
4. 连接建立后，从机进入受控模式，悬浮窗缩小到屏幕右侧；
5. 主机操作时，从机同步回放。部分从机会因为机型差异、系统弹窗等原因与主机产生不一致的操作，需要在从机上手动辅助处理，这是多机型测试的正常现象；
6. 主机点击结束，从机退出一机多控页面。若个别设备悬浮窗没有正常退出，手动退出 SoloPi 即可。

## 五、多机型批量执行的注意点

- **必须有线连接调试**。Android 目前不支持通过 Wi-Fi 同时调试多台设备，所以主从机在初始化阶段都要用数据线连电脑执行 `adb tcpip 5555`；设备重启后需重做一次。
- **自动安装的密码**。一机多控支持自动安装应用，OPPO 与 vivo 设备安装时需要输入密码，SoloPi 默认使用 `a1234567`，可在设置页的「OPPO/VIVO 密码」项中改成实际密码，否则自动安装会失败。
- **辅助功能校验失败优先重启设备**，这类校验问题多数由系统侧状态残留引起，重启比反复切换开关更有效。
- **从机数量越多，单次操作耗时越长**，下发与回放本身有网络往返，建议按同一局域网、网络稳定的条件组织设备。

所有参与测试的设备都装同一个包即可，包从 [SoloPi 安装文件资源（夸克网盘）](https://pan.quark.cn/s/9dc1f415070a) 取。
