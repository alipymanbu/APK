在手机上点一遍就得到用例很方便，但要让它进入持续集成流水线、或跑在云测平台上，还得把它变成 Appium 或 Macaca 这类框架能执行的脚本。SoloPi 另外配了一个独立的转换器项目专门做这件事，本篇讲清这条链路怎么走通。

## 一、为什么要把 JSON 用例转出去

SoloPi 录制的用例以 JSON 形式保存在设备本地，录完就能在本机回放，不依赖电脑，也不依赖测试框架。问题在于它融不进已有工程体系——比如团队已经用 Appium 建好了用例管理和报告体系，或者要把用例提交到云测平台做多机型分发。

转成框架脚本正好补上这两块：脚本可以被版本管理、可以被 CI 调度，也能被云测平台直接消费。

## 二、用例怎么从手机里出来

导出这一步在手机上完成，所以设备上要先装好 SoloPi 并授予文件读写权限——安装包从 [SoloPi 安装文件资源（夸克网盘）](https://pan.quark.cn/s/9dc1f415070a) 取，权限配置见 [下载与安装教程.md](下载与安装教程.md)。

1. 在 SoloPi 录制回放页面点击「查看全部」，长按目标用例；
2. 选择**导出用例**，文件会保存到 `/sdcard/solopi/export` 目录；
3. 用数据线或任意传输方式把导出的 JSON 文件拷到电脑上。

如果设备没有授予 SoloPi 读写权限，导出目录会退到 `/sdcard/Android/data/com.alipay.hulu/files/solopi/export`。反向导入的操作（把外部 JSON 用例放回设备）在 [录制回放用例怎么录.md](录制回放用例怎么录.md) 第七节里写得更细。

## 三、用转换器转成脚本

转换由一个独立的转换器项目完成，仓库在 `https://github.com/soloPi/SoloPi-Convertor`，目前支持转成 **Appium** 与 **Macaca** 两种脚本。

使用前的准备：

- 电脑上准备好 Java 运行环境与 Android SDK（如果只在电脑上做转换、不涉及真机调试，按转换器项目的说明准备即可）；
- 按转换器仓库 README 的说明获取其发布包或源码，版本与用法以该项目页面当时显示为准，本文不写死具体版本与命令；
- 明确目标框架：团队已有 Appium 工程就转 Appium，使用阿里的 Macaca 工具链就转 Macaca。

转换完成后，用例的每一步会被映射成对应框架的操作语句，之后的调试、维护、断言补齐都在框架侧完成。

## 四、接入流水线或云测平台

转换后的脚本可以走常规的自动化流程：

| 目标 | 做法 |
| --- | --- |
| 本地/自建 CI | 脚本纳入代码仓库，用 Jenkins 之类的工具在流水线中调度执行 |
| 云测平台 | 按平台要求提交脚本与测试包，由平台分发到多机型执行 |

需要区分的是：**如果想做的是"多台设备同时跑同一条流程"，不需要转换，直接用 SoloPi 的一机多控即可**，见 [一机多控做兼容性测试.md](一机多控做兼容性测试.md)。只有在需要把用例沉淀为工程资产、交给别的系统执行时，才走转换这条路。

## 五、转换前后的差异与限制

- **控件定位方式的差异**。SoloPi 录制时会记录控件的 ID、文字、相对布局甚至截图信息，回放时用综合属性的智能查找定位控件；转成框架脚本后定位策略由目标框架决定，跨设备、跨版本执行时可能需要在框架侧补更强的定位表达式。
- **图像类步骤要谨慎**。录制时若使用了图像查找模式，这类步骤依赖截图与坐标匹配，屏幕分辨率或界面样式变化后容易失效，转出脚本后建议先在小范围设备上验证。
- **逻辑分支的对应**。SoloPi 支持在用例中加入 IF、WHILE 逻辑，但并不是所有框架脚本都能一比一还原相同的结构，转换后需要人工核对分支是否等价。
- **信息以项目仓库为准**。转换器支持的框架范围、参数与限制会随仓库更新变化，落地前先看该项目的 README 与 issue 区。

SoloPi 本体的安装包与后续版本统一从 [SoloPi 安装文件资源（夸克网盘）](https://pan.quark.cn/s/9dc1f415070a) 取用；转换器是独立项目，按其仓库说明获取。
