## 一、先说排查的总原则

AstrBot 安卓 App 的初始化（下载 Ubuntu 容器环境、装 AstrBot 核心、装 NapCatQQ）是全自动的，但也因此「看不见发生了什么」。所有排查都从同一个动作开始：**点一下屏幕，切到终端日志页**，看它到底卡在哪一行——是下载不动、还是报错、还是在慢慢装。对症才好下药。

## 二、症状对照表

| 症状 | 多半是 | 这样处理 |
| --- | --- | --- |
| 白色进度条长时间不动 | 下载被网络卡住 | 换家用 Wi-Fi 或手机流量；点屏幕切到日志页确认卡点 |
| napcat 安装卡住或报错 | 这一步耗时长、对网络敏感 | 直接关闭 App 重新打开，会从断点继续装 |
| 重启几次仍初始化失败 | 本地环境包损坏 | 系统设置 → 应用管理 → AstrBot → 清除应用数据，重新初始化 |
| 终端出现 `dpkg was interrupted, you must manually run 'dpkg --configure -a'` | 系统软件包安装被中断 | 别按提示修，清除应用数据重新初始化最干净 |
| 初始化完成但 QQ 二维码一直不弹 | napcat 组件安装失败 | 关闭 App 重新打开，多数能自愈 |
| 机器人突然不回消息了 | 常驻通知被清掉了 | 重新打开 App 让服务跑起来；以后别清那条通知 |
| 服务还在、就是不回，且日志无报错 | 同一个 QQ 号刚在电脑端被登录，协议端被挤下线 | 电脑 QQ 上退出该号；重启 App 重新扫码（背景见 [封号风险与账号安全.md](封号风险与账号安全.md)） |
| 日志里一堆英文看不懂 | 正常现象 | 只盯关键词：`error`、`failed`、`timeout` 出现的位置，对照上表处理 |

## 三、几条预防措施

- **网络**：初始化只用家用 Wi-Fi 或手机流量。校园网、公司内网、公共 Wi-Fi 经常拦大文件下载，是「卡在进度条」的头号原因。
- **初始化期间别锁屏**：保持屏幕常亮、盯着日志，出问题第一时间能看到。初始化完成后就没这么多讲究了。
- **通知权限必须给**：机器人靠常驻通知保活。当时点了拒绝的，去系统设置 → 应用管理 → AstrBot → 通知，手动打开。
- **别让系统杀后台**：部分手机的省电策略会冻结后台应用。把 AstrBot 加进电池白名单 / 允许后台运行（各品牌入口不同，一般在电池或应用管理设置里），不然息屏久了服务可能被系统掐掉。

## 四、清数据等于回到出厂

「清除应用数据」会把容器环境、配置全部清空重来，相当于重新初始化一遍。你之前填的 API Key、改的密码、装的插件都会没，需要按 [QQ登录与密钥配置步骤.md](QQ登录与密钥配置步骤.md) 重配一遍；QQ 登录态本来就在你的 QQ 账号里，不存在丢失问题。多次重启 App 都无效时，这是项目说明里给出的最终手段。

## 五、还不行怎么办

该项目是开源社区项目，说明里留了两个 QQ 群（777156380、952573476）作为社区支持入口；框架层面的问题可以查 AstrBot 官方文档 `https://docs.astrbot.app/`。提问时把终端日志页的报错一起发，能得到更快的回复。两条路线的差异背景见 [和电脑版部署有什么区别.md](和电脑版部署有什么区别.md)。
