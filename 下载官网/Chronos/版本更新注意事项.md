## 一、版本号怎么读

Chronos 从 2025 年起改用「年份.序号」的版本号：

| 版本 | 备注 |
| --- | --- |
| 1.x 系列（1.4.0 ~ 1.8.0） | 早期编号 |
| 2025.1.0 | **你网盘里这份就是这一版**（2025 年的第一个版本） |
| 2025.2.0 | 内部大重写；发布说明顶部用警告标着「更新前务必备份闹钟」 |
| 2025.3.0 | 界面用 Jetpack Compose 重写，支持 Material 3 / Material You、可导入导出闹钟、平板大屏布局初版 |
| 2025.3.1 | 修复首页布局与自定义配色问题 |
| 2026.1.0 | 闹钟支持 emoji、修复闹钟启动问题、法语翻译更新 |

以 [GitHub Releases](https://github.com/meenbeese/Chronos/releases) 页面当时显示的为准。判断新旧：年份大的新，同一年份内序号大的新。

## 二、更新前最重要的一件事：备份闹钟

官方在 2025.2.0 的发布说明里用全大写警告：**更新前务必备份你的闹钟**（那一个版本内部重写了数据结构，不备份直接升，旧闹钟可能丢失）。之后的 2025.3.0 才加入「导入 / 导出闹钟」功能。

所以按你的情况分两种：

- **你从 2025.1.0 往上升**：2025.1.0 这版还没有导出功能，最稳的做法是**先把所有闹钟的时间、重复日、铃声抄一遍记在备忘录里**，升完级按记录重建；或者干脆停留在 2025.1.0，等哪次要升再一次性弄。
- **你已经用上 2025.3.0 及之后的版本**：升级前在应用设置里找「导入 / 导出」（Import/Export），把闹钟导出存一份文件，再更新。

## 三、从哪里更新

Chronos 不在 Google Play 上架，没有应用商店的自动更新，三个更新渠道：

1. **GitHub Releases**（[github.com/meenbeese/Chronos/releases](https://github.com/meenbeese/Chronos/releases)）—— 官方发布页，手动下载 APK 覆盖安装；
2. **IzzyOnDroid 仓库**（[apt.izzysoft.de 的 Chronos 页](https://apt.izzysoft.de/fdroid/index/apk/com.meenbeese.chronos)）—— 用支持该仓库的 F-Droid 客户端（Neo Store、Droid-ify 等）可以收到更新提示；
3. **Obtainium** —— 官方 README 提供了 Obtainium 深链，配好后它会盯着 GitHub Release 自动提醒你更新；完整设置步骤与后台自动安装的条件见 [Obtainium自动更新设置.md](Obtainium自动更新设置.md)。

无论走哪条路，**更新动作本身都是覆盖安装**：不用先卸载，装完闹钟数据保留（但按第二节，保留不等于不丢 —— 大版本跨度仍要先备份）。

## 四、校验安装包

从网盘或任何第三方渠道拿到 APK 后，校验 MD5 能确认文件完整无损：

```powershell
# Windows PowerShell
Get-FileHash .\Chronos_v2025.1.0.apk -Algorithm MD5
```

2025.1.0 这份的预期值是 `D7B3434AD4828DE524F68BE548AF288C`，输出一致即文件完好；不一致说明下载不完整，重新下载一次。

## 五、升完级出问题怎么办

升级后闹钟没反应、界面异常时，按这个顺序回退：

1. 先看 [闹钟不响怎么办.md](闹钟不响怎么办.md) —— 大概率是通知或电池白名单在升级后被系统重置了（覆盖安装后权限被收回是常见现象）；
2. 权限都正常但版本本身有 bug，就到 [GitHub Releases](https://github.com/meenbeese/Chronos/releases) 下载上一个稳定版（目前是 2025.3.1）覆盖装回去 —— 降级前若闹钟数据结构不兼容，会回到第二节的备份问题，所以备份永远做在动手之前。

至于要不要追新版本：Chronos 的更新多是修复与翻译，你日常只用闹钟的话，2025.1.0 能一直用下去；想要 emoji 闹钟标签、平板布局和导出功能，再按第二节备份后升。
