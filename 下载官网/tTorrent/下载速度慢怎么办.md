## 一、先看网络条件，再看设置

BT 下载的速度主要由「有多少人在做种」决定，来源越多越快，这一条任何设置都替代不了：

- 冷门种子（做种 0~1 人）速度慢是正常现象，换个热门任务对比一下，就能分清是种子的问题还是设置的问题；
- 部分运营商在高峰期对 P2P 流量限速，换个时段对比可以验证；
- 官方对网络的要求很直白：高带宽的 Wi-Fi 或 4G 是必要的，弱网环境下谈不上速度。

## 二、应用内逐项核对

| 检查项 | 在哪 | 判断 |
| --- | --- | --- |
| 仅 WiFi 模式 | 设置 | 开着时移动网络下任务不动，属正常 |
| 文件优先级 | 详情页 Files 标签 | `0` 不下载，`3` 最先完成 |
| 顺序下载 | 任务设置 | 边下边看用，整体完成时间会变长 |
| 下载 / 上传上限 | 设置 / Limits | 默认是 No limit；确认没设成很小的值 |
| 最大同时下载数 | 设置 / Limits | 设得太小会让后面的任务排队 |
| 监听端口 | 设置 / Network settings | 默认 6890（以你的设置页显示为准）；配合路由器端口映射提升可连接性 |

熄屏后速度归零、亮屏又恢复的情况不属于上面的任何一项 —— 那是系统在限制后台，处理见[锁屏后下载停止怎么办.md](锁屏后下载停止怎么办.md)。

## 三、加密与代理

- 支持加密连接；某些校园网 / 公司网会直接掐断 BT 流量，加密不一定救得回来，换个网络对比最快；
- 支持 SOCKS、HTTP 代理 —— 走代理通常明显更慢，排查速度问题时先关掉代理再测。

## 四、端口与 NAT

- 支持 UPnP 与 NAT-PMP，路由器会自动做端口映射；长期连不上 peer 的情况多与 NAT 有关（监听端口默认 6890，可在 Network settings 里改）；
- DHT 支持无 tracker 任务；删完任务后仍有每秒几字节的流量是 DHT 在工作，设置里可以关，但官方 FAQ 明确不推荐。

## 五、存储别拖后腿

保存位置的写入速度也会把下载拖慢。1.8.5 起有「先下载到应用私有目录」的选项，官方 FAQ 提到它可能改善下载速度或存储框架引发的问题；外置 SD 卡的权限细节见[存储路径与SD卡权限.md](存储路径与SD卡权限.md)。
