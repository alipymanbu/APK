## 一、手机在这里是个「随身传感器」

除了当遥控器，手机端会把自身状态上报成 Home Assistant 实体，自动化就能拿「人」的信号触发。前提仍是位置权限与后台权限（见 [位置不更新怎么排查.md](位置不更新怎么排查.md)），否则大部分实体不会更新。

## 二、默认就有 vs 要手动开

登录并授权后，**默认上报**的有电量类：`battery_level`（电量百分比）、`battery_state`（充电状态）、`charger_type`（充电方式），以及你在配对时点过「允许」的那些权限对应的传感器。

其余默认关闭，去 **Settings → Companion App → Manage Sensors** 逐个打开。常用的几类：

| 实体（示例 ID） | 内容 | 典型用途 |
| --- | --- | --- |
| `sensor.ssid` / `sensor.bssid` | 当前 Wi-Fi 名 / 路由器 MAC | 判定人在哪个网络，代替不准的 GPS |
| `sensor.geocoded_location` | 由坐标反查的地址 | 展示与粗粒度判定 |
| `sensor.last_update_trigger` | 最近一次上报由什么触发 | 排查位置问题的入口 |
| `sensor.connection_type` | 当前是蜂窝还是 Wi-Fi | 省流量自动化 |
| `sensor.app_version` | 手机端 App 版本 | 反馈问题时截图用 |
| 步数 / 活动类（Activity） | 计步与活动状态 | 「走够一万步触发场景」类 |
| Health Connect 相关 | 心率、运动、血糖等（取决于你授权共享哪些） | 健康数据联动 |

数据只在你自己的 Home Assistant 里存，分享哪些由你在手机上勾选，随时可关。

## 三、权限给到什么程度，决定能玩什么

- 位置权限给 **仅使用期间**：App 在前台还能定位，后台一概不报，`device_tracker` 基本躺平；
- 给 **始终允许**：后台位置、围栏进出、基于到家/离家的自动化才可用；
- 拒绝位置权限：位置与依赖位置的实体全部失效，其余传感器（电量、Wi-Fi 等）还能用 —— 也可以在实体注册表里单独禁用 `device_tracker`，效果等价于「不要位置、要传感器」。

## 四、两个直接能抄的自动化

到家天黑开灯（配合位置实体）：

```yaml
automation:
  - alias: "到家且天黑开灯"
    trigger:
      - platform: state
        entity_id: device_tracker.你的设备名
        to: "home"
    condition:
      - condition: sun
        after: sunset
    action:
      - service: light.turn_on
        target:
          entity_id: light.玄关灯
```

手机开始充电就关掉一些东西（配合电量传感器）：

```yaml
automation:
  - alias: "手机插上充电器时进入夜间模式"
    trigger:
      - platform: state
        entity_id: sensor.你的设备_battery_state
        to: "Charging"
    action:
      - service: scene.turn_on
        target:
          entity_id: scene.夜间
```

实体 ID 里「你的设备名」以你配对时起的名字为准，可在服务器的集成面板 → Mobile App 里逐个查看和改名（改名时保留 `sensor.` / `device_tracker.` 前缀）。

## 五、几条边界，先知道能省事

- 多台手机连同一个服务器时，传感器名字会很像，**在配对时就起能区分的名字**，事后改要逐个实体改；
- 手机端传感器数量多，每个多开一个都会增加后台上报频率，只开用得上的；
- 基于位置/传感器的自动化出问题，先看 [位置不更新怎么排查.md](位置不更新怎么排查.md)；要往手机推结果，看 [收不到通知怎么排查.md](收不到通知怎么排查.md)；
- 手机换机或重装后，记得到集成面板清掉旧设备条目再配对，否则 person 实体会挂着一台永远不会动的设备（这会把人的状态判断带偏）。
