# EasyClaw 指令怎么写才会照着做

在手机上发一句「帮我弄一下电脑」，结果无非两种：它反复回来问你，或者它按自己的理解做完一件你没想要的事。这不是它笨，是那句话里缺了执行需要的信息。这篇只讲一件事：怎么把话说到能执行。

## 一、先接受一个前提

指令是你发的，动作是电脑做。中间隔着一次理解——它要把中文拆成「打开什么、对哪个文件、做到什么程度」。你省掉的每一个限定条件，都会变成它的一次猜测；猜错的代价是重来一遍，还要多扣一次积分。

## 二、把「一句话」改成「有终点的任务」

对照着改最有效，左边是常见写法，右边是能直接执行的写法：

| 你原本会说 | 改成这样说 |
| --- | --- |
| 帮我整理下电脑 | 把「下载」文件夹里 30 天以前的安装包移到 D 盘的「旧安装包」文件夹，移动完告诉我移了几个 |
| 帮我看看邮件 | 打开邮箱，把今天的未读邮件按发件人分组，摘要成一张表发给我 |
| 做个报告 | 把这个月每天的销量数据汇总成一张表，最后一行放合计，存到桌面，文件名「本月销量」 |
| 桌面太乱了 | 桌面上的图片按月份分文件夹归档，其余文件不动 |

规律是三条：**先说清在哪做（哪个文件夹、哪个软件、哪个页面），再说清对什么做（具体对象），最后说清做到什么算完成（产出物、存放位置、要不要回报数量）。**

## 三、需要它记住的事，让它写下来

对话上下文一长就会被清掉，聊天渠道之间也互不相通。凡是「以后每次都要这样」的偏好——称呼、格式模板、常用目录——不要指望它自己记住，直接交代一句：「把这条写进 `MEMORY.md`」。写进持久化文件的内容，删掉对话历史也不会丢。

## 四、上下文什么时候该清

**判断依据是任务变了，而不是轮数到了。** 一件事聊完、换另一件不相干的任务时，发一次 `/new` 是干净的起点；同一件事还在追问细节时就别清，清了它得从头问一遍。

官方给的参考是每 10 到 20 轮清一次，主要目的是控制上下文长度——上下文越长，每次请求的消耗越大，响应也越慢。

## 五、跑得慢、来回确认，按这三步调

1. **先把话说全**。来回确认多半是提示词缺信息，它只能靠反问补齐。把第二节那三个要素一次说完，能省掉好几轮。
2. **换模型**。复杂任务用低倍率的小模型，它往往理解不到位、更容易反复；换到更强的模型反而更快出结果。
3. **直接问它哪里能优化**。可以原话问：「这个工作流还有哪里可以优化？帮我提出改进建议。」复杂流程跑第二遍之前问一句，通常比你自己盯半天有效。

## 六、长任务跑起来之后

本地端的任务跑在你电脑上，电脑一睡任务就断，前面跑完的部分可能白费。派长任务之前，先把「别让它睡」这件事办掉：

| 系统 | 要改的地方 |
| --- | --- |
| Windows 10 / 11 | 设置 → 系统 → 电源和电池 → 屏幕和睡眠，把「接通电源时」的睡眠时间改为「从不」；笔记本再进控制面板的电源选项，把「合上盖子时」改成「不采取任何操作」 |
| macOS | 系统设置 → 锁定屏幕，把无操作关闭显示器的时间设为「永不」，并打开「显示器关闭时防止 Mac 自动进入睡眠」；这一项在不同 macOS 版本里的位置略有差异，找不到就在设置里搜「睡眠」 |

Windows 上也可以直接用命令改掉接通电源时的睡眠超时（需管理员权限）：

```powershell
powercfg /change standby-timeout-ac 0
```

macOS 上不想动系统设置，可以临时顶一下（关掉这个终端窗口即失效）：

```bash
caffeinate -i
```

另外几件事：

- **电源接上、切到高性能模式**，并关掉系统的节能与自动关机设置。笔记本不要只靠电池跑长任务。
- **代价是功耗和发热会上去。** 笔记本合盖塞进包里时别这么设，散热跟不上。
- **别指望它无人值守到天亮**，除非你确认过这台电脑不会睡。真要 7×24 的场景，考虑云端那套，见 [不用电脑时的云Bot怎么用.md](不用电脑时的云Bot怎么用.md)。
- **想中途看进度**，在手机上直接问它「现在做到哪一步了」，比翻记录快。

## 七、三个可以直接抄的例子

- 定时类：「每天早上 8 点把昨天几家店铺的销量、库存、差评汇总成一份日报发我。」
- 清理类：「把下载目录里超过 30 天没动过的安装包移到 D 盘『旧安装包』，其他文件别动，移完回报数量。」
- 汇总类：「把这几份 Excel 合并成一张表，按日期排序，生成一份 PDF 放到桌面。」

改的时候只换掉里面具体的目录名、时间、数量，句子结构不用变——结构就是它在拆步骤时依赖的东西。

指令写得再准，也可能因为电脑休眠、额度耗尽、渠道掉线而不执行，这几类问题的判别方式都在 [常见问题与排查.md](常见问题与排查.md)。
