## 一、先选方式：你的区服决定走哪条路

导入的核心思路只有一种：拿到 FGO 登录时服务器返回的那份数据（含从者、技能、灵衣、素材、礼装图鉴），喂给 Chaldea。不同区服拿这份数据的难度差别很大：

| 区服 | 推荐方式 | 说明 |
| --- | --- | --- |
| 国服 / 台服 | 抓包导入 | 官方客户端 Android、iOS 都支持；国服 iOS/Android 已互登 |
| 日服 / 美服 | 官方客户端 + 抓包（Android） | 日服 2.80.5 起官方包在 Android 上可抓（证书需装系统层）；iOS 不可用 |
| 任何区服 | 导入 Chaldea 备份 | 已有别人的 `userdata.json` 或自己旧备份时最省事 |
| 任何区服 | 服务器上传/下载备份 | 换手机时用，前提是数据已经在 Chaldea 里 |
| 桌面端批量改数据 | CSV 模板 | 导出成表格编辑再导回，灵衣/纹章字段是 json 格式别乱改 |

**韩服目前没有任何导入方式**（官方文档明确写「no way yet」）。另外**截图识别类导入（素材截图、技能截图）已标注不再维护**，别把时间花在它上面。

## 二、抓包导入：常在哪一步失败

这是国服玩家的主力方式，也是最容易卡住的方式。按失败现象对号入座：

**1. 抓不到包 / 证书被拒**
日服、美服、韩服的客户端有证书绑定（cert-pinning），会拒绝抓包软件的自定义证书 —— 日服官方安卓包要证书装到系统层才行，美服官方包目前不支持。国服、台服没有这个限制。

**2. 证书过期**
抓包工具的 CA 证书有有效期（例如 Charles 的证书只有 1 年），过期后会一直失败。处理：删除旧证书 → 重新生成 → 重新安装，三步缺一不可。NGA 上有用户反馈装了证书仍反复弹安全警告，多数与证书未装到系统层或已过期有关。

**3. 导出的文件格式不对**
导出内容**必须只有响应体（Response body）**，不能带响应头；且日服/美服要的是合法 json，国服/台服是 base64 编码的字符串。拿错文件类型导入必然失败。

**4. 找错了请求**
目标请求是登录那一条：国服形如 `...bilibiligame.net/...ac.php?_userId=xxx&_key=toplogin`（关键在 `_key=toplogin`），日服是 `https://game.fate-go.jp/login/top?_userId=xxx`。域名会随区服、渠道、地域变化，认准 `_key=toplogin` 这一段就不会抓错。

**5. 导入后数据不对**
导入前**先确认 Chaldea 里选中的是目标账号** —— 导到别的账号上就得重来。有用户分享的完整流程（模拟器 + Charles 保存登录响应 → 从文件导入 Chaldea）在 NGA 国服区有帖，可作参照；官方文档的「导入抓包」章节有各工具的分篇教程。

一个安全边界要清楚：抓包拿到的数据**不含用户名密码**，只是账号内的游戏资源信息；但日服/美服的引继文件（`54cc` / `authsave2`）包含完整登录凭据，**别发给任何人**。应用内那种「读取账号文件模拟登录」的方式，官方已因日服 2.87.0（2024-02-14）变更验证方式而标注**请勿继续使用** —— 别再照老教程走这条。抓包完成后，记得把装上的证书删除或取消信任。

## 三、导入 Chaldea 备份文件

如果你拿到的是 Chaldea 自己的备份（`user/userdata.json`）：

1. 设置 → 用户数据 → 导入，选中 json 文件；
2. 导入前确认目标账号，导入即覆盖当前账号数据；
3. 不同版本的数据结构可能不兼容，老备份在新版本里可能恢复失败。

来源可以是自己的历史备份（应用每天自动生成一份），也可以是服务器上传/下载的那份。这条例子也说明为什么日常要留备份 —— 详见 [常见问题与数据备份.md](常见问题与数据备份.md)。

## 四、导入之后核对三件事

1. **从者列表对不对** —— 数量、技能等级、宝具级与游戏里是否一致，错了这轮规划全白算；
2. **素材数量对不对** —— 去统计页看「已消耗素材」勾「包含库存」，数量级应该与游戏内接近；
3. **区服对不对** —— 别把国服数据导进日服账号的坑，第一眼就能从从者有没有国服限定看出。

核对无误后再去排规划（见 [新手使用指南.md](新手使用指南.md)）。
