## 一、为什么分三种模式

App Manager 能干什么，取决于你给它多大权限：装好直接用是「无 root 模式」；愿意配一次 ADB 就是「ADB 模式」；设备已经 root 再授权给它，就是「root 模式」。三档的切换入口在设置的「运行模式」里（以应用内显示为准），同一批按钮在低档位下可能直接不可用 —— 先对照下面的表确认你处在哪一档，再排查「功能点不动」的问题。

## 二、三档能力对照

| 能力 | 无 root | ADB | root |
| --- | --- | --- | --- |
| 查看应用信息、组件、权限、签名、共享库 | 有 | 有 | 有 |
| 扫描追踪器与第三方库 | 有 | 有 | 有 |
| 安装 / 卸载 / 导出 APK，备份与恢复 APK | 有 | 有 | 有 |
| 撤销 / 授予危险权限 | 无 | 有 | 有 |
| 修改 App Ops（隐藏权限） | 无 | 有 | 有 |
| 清除应用数据与缓存 | 无 | 有 | 有 |
| 强行停止 / 结束进程，查看运行中应用 | 无 | 有 | 有 |
| 联网策略、电池优化管理 | 无 | 有 | 有 |
| 冻结 / 解冻应用 | 无 | 有 | 有 |
| 拦截活动、广播、服务、提供器等组件 | 无 | 见下方说明 | 有 |
| 查看 / 编辑应用的共享偏好（shared preferences） | 无 | 无 | 有 |
| 含数据、规则与附加项的完整备份 | 无 | 无 | 有 |
| 查看系统配置、修改 SSAID | 无 | 无 | 有 |

上表按官方功能清单整理：撤销权限、App Ops、清数据、进程管理、联网策略、电池优化、冻结/解冻属「root/ADB 均可」；组件拦截、共享偏好编辑、含数据备份、系统配置属「仅 root」。组件拦截在 ADB 下的可用性取决于所选的拦截方法，以应用内按钮的实际状态与官方常见问题说明为准。

## 三、无 root 模式：装好即用

这是默认状态，不需要任何设置。你能看信息、扫追踪器、安装卸载导出、备份 APK；但它改不了别人的权限、清不了别人的数据 —— 相关按钮会不可用。另外 F-Droid 页面写明该应用平时不联网（网络权限是 ADB 模式才需要的），所以纯查看的用法不涉及把数据传出去。

只想看、不想改，停在这一档就够。

## 四、ADB 模式怎么开

两条路选一条：

1. **无线调试（Android 11 及以上，全程在手机上完成，不用电脑）**：先在开发者选项里打开 USB 调试，再进「无线调试」用配对码完成配对，然后在 App Manager 里选择无线调试方式连接。它会先尝试自动连配置好的端口，失败了才让你手动配对或连接。
2. **ADB over TCP（需要一台电脑）**：开发者选项里打开 USB 调试，按官方指南在电脑上装好 ADB，再在 App Manager 里启用 TCP 模式。官方指南：[经由 TCP 的 ADB](https://muntashir.dev/AppManager/zh-rCN/#sec:adb-over-tcp)。

两种接法任一失败，或 ADB over TCP 没启用，应用都会**自动回落到无 root 模式** —— 表现就是一批按钮突然变灰，这时先检查 ADB 连接，不用怀疑应用坏了。

## 五、root 模式：需要一台已 root 的设备

设备取得 root（Magisk、KernelSU 等方案）并给 App Manager 授权后，解锁的是仅 root 那一列：组件拦截、共享偏好编辑、含数据的完整备份、系统配置与 SSAID。root 授权本身由你的 root 管理器发放，App Manager 只是被授权方。

## 六、动手前的两条提醒

- 清数据、改权限、改 App Ops 都是系统级的真改动，改错了对应应用会出问题（甚至启动即崩）。每改一项之前先弄清它是什么，出问题的处理见 [常见问题与故障排查.md](常见问题与故障排查.md)。
- 档位按需要选：要清数据、管权限这类操作，配一次 ADB 即可覆盖，不必动 root；只有组件拦截、共享偏好、含数据备份这几件事才非 root 不可（对照第二节的表）。
