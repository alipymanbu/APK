## 一、不给 root、不配 ADB，用着安全吗

安全边界很清晰：不给特权时，App Manager 只能做读取和它自身权限内的事，改不了别的应用。F-Droid 页面写明该应用平时不联网（网络权限是 ADB 模式才需要的），所以纯查看的用法不涉及上传数据。真正的风险来自**你主动授予的权限和亲手做的修改**，而不是这个应用自己在后台干什么 —— 授权与改动清单都能在它的设置和操作历史里查到。

## 二、ADB 模式重启后失效，一批按钮变灰

手机重启会关掉 ADB over TCP 和无线调试，App Manager 拿不到 ADB 就**自动回落到无 root 模式**。处理：重新启用 TCP 模式或重新做一次无线调试配对，回到 ADB 模式后按钮会恢复。这是每次重启都会遇到的正常现象，不是应用坏了。

## 三、列表状态不准：显示「已停止」其实还在跑

官方文档明确注明：主页是缓存查询结果、**并非实时更新**，停用、停止这类状态可能滞后。要判断当前实况，重新进入页面或以「正在运行的应用」页面的结果为准（后者在无 root 下只显示它自己的运行情况）。

## 四、改了权限 / App Ops 后，某个应用打不开或闪退

这是改错项的典型后果。有第三方教程实测过：对某个应用把 `GET_AUDIO_FOCUS` 这类 App Ops 设成「忽略」（而非「允许」），应用会启动即崩。

- 动手前：先弄清这一项是什么、拒绝的后果，再改；
- 已经改坏：回到该应用的 App Ops / 权限页，把刚改的那一项设回允许；
- 拿不准的项：不改 —— 这些设置没有「恢复出厂」兜底，一项一项记着自己动过什么。

## 五、拦截组件后，应用的某个功能不工作了

拦错组件的直接表现就是对应功能失效。处理见 [追踪器扫描与组件拦截.md](追踪器扫描与组件拦截.md) 第四节：在组件页对同一对象「取消阻止」，或到设置的「规则」里批量管理、移除规则。拦截是可撤回的，前提是知道拦了什么。

## 六、想换个渠道装，系统说签名不一致

F-Droid 渠道的包由 F-Droid 构建并签名，与 GitHub Releases 的包签名不同，无法直接覆盖安装。要换渠道只能先卸载再装（会丢该应用自身数据）。认准包名 `io.github.muntashirakon.AppManager`，它是跨渠道不变的唯一身份。

## 七、搜索结果里混进别的东西

搜「App Manager」时会出现 Meta App Manager 之类的条目 —— 那是另一家公司的组件，与本应用无关。核对时只认包名：`io.github.muntashirakon.AppManager`。

## 八、官方说明在哪看

- 应用内：选项菜单里的「用户手册」打开离线版手册；未安装文档组件或设备缺少可加载手册的 WebView 时会打开在线版。
- 在线版（有简体中文）：[muntashir.dev/AppManager/zh-rCN/](https://muntashir.dev/AppManager/zh-rCN/)，功能细节、FAQ、更新日志都在里面。
- 遇到疑似 bug：在 [github.com/MuntashirAkon/AppManager/issues](https://github.com/MuntashirAkon/AppManager/issues) 报告，官方要求偏离手册的行为都提到那里。
