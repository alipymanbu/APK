## 一、点开一个文件，实际发生什么

在文档库里点文件名，走的是这条链：**先看文件类型支不支持预览** → 支持就在线打开预览 → 你要改，再交给对应的 Office 应用（Word / Excel / PowerPoint）编辑。

- 装了对应 Office 应用：点编辑会直接唤起它，改完保存，内容写回站点里的原文件。
- 没装：只能在内置预览里看，或者下载到本地。想改就先装齐这三件套。
- 不支持预览的格式：给你的就是下载提示 —— 下载 → 本地改 → 再上传回去（流程同 [手机上传照片和文件.md](手机上传照片和文件.md)）。

## 二、在线改 vs 离线改，存的地方不一样

| | 在线编辑 | 离线 / 下载后编辑 |
| --- | --- | --- |
| 保存方式 | 保存即写回，不用你管 | 改完是本地文件，要**手动传回文档库** |
| 与原文件关系 | 就是那个文件 | 上传同名文件时会提示「1 项未上传」，点它选**替换原文件** |
| 版本历史 | 正常累积 | 站点开了版本控制的话，替换也不是真覆盖 —— 是多出一个版本 |

**离线改完忘了传回去**是最常见的丢工作场景：手机上看着改好了，别人在站点上看到的还是旧的。判断标准只有一条 —— 回到文档库刷新，看你改的那份内容是不是最新的。

## 三、打开就是「只读」的几种原因

有编辑权限 ≠ 一定能改。按这个顺序排：

1. **别点标题，点三点菜单 → 编辑**。这是官方给过的处理：某些场景下点标题会进只读打开，从菜单进编辑入口就正常了。
2. **库开了「必须签出」**：文档库要求先签出才能独占编辑。没签出就打开，文件保持只读。让站点所有者看库设置，或你先签出再编辑。
3. **账号权限只有读**：Read 权限的用户看不到「新建 / 上传」，打开文件也只能看。要改得让你进成员组（Contribute 及以上）—— 这个只能找站点所有者。
4. **组织侧把站点设成了只读**：站点被锁定、存储配额用尽、生命周期策略归档，都会让所有人（包括管理员）传不上去、改不了。表现是「全站都这样」而不是「就我一个人」，直接报给 IT。

## 四、几个人同时改

同一份文件多人同时编辑是支持的（共同创作），条件是：

- 文件是新式格式：`.docx` / `.xlsx` / `.pptx`；老格式（`.doc` / `.xls`）不行。
- 每个人对该文件都有**编辑**权限。
- 在线编辑时实时合并；**离线期间**你改的别人看不到，你恢复联网后系统提示有新版本，冲突由保存时的提示引导你处理。

判断「谁改了什么」：网页版里看文件的**版本历史**，手机端要看得借浏览器。

## 五、没网时的取舍

- 只是**要看**：提前在线打开过一次让预览进缓存，再配合系统的离线网页缓存，勉强能看，但不保证。
- 要**改**：先确认自己在离线改完后**有能力传回来**（有网的时机、能进那个库的权限）。做不到就别在离线状态下动重要文件。
- 站点的「保留供脱机查看 / 稍后保存」类入口存的是**链接与入口**，不等于整份文件下载到本地 —— 真要断网可用，还是得把文件下载下来。
