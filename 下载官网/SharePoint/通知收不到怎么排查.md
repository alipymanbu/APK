## 一、先降低预期：能推的就这几类

SharePoint 移动应用的推送不是「什么动态都提醒你」。截至官方文档口径，会触发通知的只有这些：

| 动作 | 推给谁 |
| --- | --- |
| 你关注的站点发布了 SharePoint 新闻 | 按相关性推给用户 |
| 有人评论你写的页面 | 页面作者 |
| 有人回复页面评论 | 页面作者 + 被回复评论的作者 |
| 评论里 @ 提到了你 | 被 @ 的人 |
| 有人给你写的页面点赞 | 页面作者 |

**文件被共享给你**这类提醒走的是 OneDrive/文件活动通知那条线，由另一个管理员开关控制。除此之外的动态（列表更新、任务到期之类）本来就不推 —— 你以为「没收到」，其实它压根不在推送清单里。

两个环境边界：

- **通知在美国政府环境和 21Vianet（中国）运营的 Office 365 中不可用**。如果你单位是这类租户，手机端永远不会有推送，不是你设置错了。
- 安卓走的是 Firebase Cloud Messaging 通道，所以**手机上还得有 Google Play 服务**才能收到 —— 没有 GMS 的安卓设备（部分国产 ROM 默认阉割）这一通道先天不通。

## 二、逐层自查（从手机到组织）

按顺序走，前一层过了再看下一层：

1. **系统通知权限**：安卓 13 及以上首次安装要单独征求通知许可，当初点了拒绝就什么都收不到。路径：设置 → 通知 → 应用通知 → 找到 SharePoint → 允许；顺手确认里面各个通知类别没被单独静音。
2. **电池与后台限制**：症状是「只有打开应用才看到提醒」。设置 → 应用 → SharePoint → 电池 → 选「不受限制」；三星机还要看设置 → 电池 → 后台使用限制，别让它落进「休眠应用 / 深度休眠应用」。同时确认「后台数据」是开着的。
3. **勿扰与省电**：勿扰、省电模式、数据省流会压掉弹窗或延迟推送。测试期间先关掉。
4. **应用内开关**：应用自己的设置里确认通知是开着的；登出再登入一次，让推送通道重新注册。
5. **你关注了那个站点吗**：新闻类通知按「关注 + 相关性」发。你没关注的站点、或系统判定与你无关的新闻，不推。
6. **组织侧总开关**：SharePoint 管理中心 → 设置 → SharePoint 的通知 → 「允许通知」。管理员关掉它，全员一起收不到；PowerShell 用 `Get-SPOTenant` 看 `NotificationsInSharePointEnabled` 字段可确认（这条是管理员的活）。
7. **都对还不来**：这属于产品侧问题，个人用户无从修起 —— 找单位管理员在 Microsoft 365 管理中心提支持单，把上面 1~6 的检查结果带上能省很多来回。

## 三、一个别搞混的情况

Authenticator（或其他验证应用）的推送和 SharePoint 的推送是两回事：前者是登录验证请求，后者是站点动态。你「频繁收到推送」时先看推送内容属于哪类 —— 登录验证类的异常频繁另有原因，见 [登录不了怎么办.md](登录不了怎么办.md) 的「总是被要求重新验证」。
