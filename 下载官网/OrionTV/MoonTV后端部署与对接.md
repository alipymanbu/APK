## 一、MoonTV、LunaTV、MoonTVPlus 是什么关系

都是同一系的开源影视聚合站，OrionTV 对接的是「站点地址」这一层，哪个都能连：

- **MoonTV**：原版（作者 senshinya），功能基础、部署路径最成熟；
- **LunaTV**：MoonTV 的深度增强二开（同一作者的延续项目），在原版基础上加了网盘搜索、AI 推荐、短剧、IPTV 直播、弹幕等一大批功能；
- **MoonTVPlus**：另一个从 MoonTV fork 出来的增强分支。

差别主要在功能多少与默认源的有无 —— 有的分支自带一批默认接口源，开箱就有片；有的默认是「空壳」，一个源都没有。装哪个不影响 OrionTV 侧的配置方法，填地址、登录的流程都一样。

## 二、部署方式怎么选

| 方式 | 适合 | 要点 |
| --- | --- | --- |
| Docker / Docker Compose | 家里有 NAS、服务器、软路由 | 最稳，局域网内 `http://内网IP:3000` 直接访问；出门在外连不上，除非另做内网穿透 |
| Vercel / Cloudflare Pages | 没有服务器、想零成本 | 免费额度够个人用；部署送的默认域名在境内可能无法直接访问，社区普遍做法是绑一个自己的域名 |
| Railway / Zeabur 一键模板 | 想省事 | 一键把应用带存储（Redis / Kvrocks）整套拉起来，按量计费 |

具体部署步骤以你选的分支仓库文档为准（MoonTV 原版在 [github.com/senshinya/MoonTV](https://github.com/senshinya/MoonTV)）。部署完成、浏览器能打开站点页面，就具备了对接条件。

## 三、部署时必做的三个决定

1. **设站长账号密码**：部署参数里的 USERNAME / PASSWORD 就是以后 OrionTV 里要填的登录账号。站点公开在公网上，不设密码等于谁都能用，务必设强密码；
2. **选存储类型**：纯本机存储（如 localstorage 模式）记录只存在单机；选 Redis、Kvrocks、D1、SQLite 这类数据库存储，播放记录与收藏才能跨设备同步 —— 这直接决定 [收藏与播放记录同步.md](收藏与播放记录同步.md) 第二节那几条能不能成立；
3. **记住最终访问地址**：这个地址就是回 OrionTV 里要填的「服务器地址」。

## 四、对接回 OrionTV：填哪个地址有讲究

- **局域网部署**（Docker 在家里）：家里的设备连同一 Wi-Fi 时填 `http://内网IP:端口` 最快；但这串地址出了家门就没意义，手机在外面用不了；
- **公网部署**（Vercel / Cloudflare / 服务器）：填 `https://你的域名`，家里家外都能连，流量走公网；
- **想两头都快**：家里的电视填内网地址、随身手机填公网域名。注意前提 —— 两个地址指向**同一个服务端实例**时，背后是同一份数据，收藏与播放记录照常互通；如果是部署了两个独立实例，那就是两套数据，互不相通。

填法本身（手机直填 / 电视端局域网网页配置）见 [服务器地址配置方法.md](服务器地址配置方法.md)；填完连不上，按 [常见问题与播放失败排查.md](常见问题与播放失败排查.md) 从「浏览器先打开站点」那一步查起。

## 五、部署完首页是空的？

先看你部署的分支带不带默认源：带的开箱就有片；默认空壳的分支（部分增强版是这样），首页和搜索都是空的 —— 这不是故障，源要在服务端的管理后台里加，怎么加见 [搜不到想看的片怎么办.md](搜不到想看的片怎么办.md)。
