# SafeInCloud 云同步失败排查

> 同步出问题时大多不用重装、不用丢数据——按「单台设备」「提示密码不匹配」「多台互不同步」三种情况各有一套固定步骤。本篇把官方的排查顺序和云端数据库文件的禁忌整理成清单。

## 一、先了解同步什么时候发生

判断「是不是真不同步」之前，先知道它什么时候动：

- 你登录应用之后；
- 你切到别的应用时；
- 最后一次改动 **1 分钟后**。

也有手动入口：主界面的菜单里选 **同步**。两点日常习惯要改：用完**别立刻从后台划掉应用**——改动可能还没推上去，反复这样做甚至可能损坏数据库；工具栏出现**黄色三角警告图标**就点它，那是同步出问题的信号，详情可以在 **设置 → 关于 → 显示日志** 里看。

## 二、单台设备不同步：按顺序过一遍

一台设备推不上去或拉不下来，按官方给的顺序逐条试，多数在前几步就好：

1. 确认网络可用；换一张网络（Wi-Fi 或流量）再试。
2. 看云账号还有没有剩余空间——数据库虽然小，但云盘满了照样同步失败。
3. 重启设备。
4. 到 **工具 → 配置云**，把云先切成 **无**，再重新选云服务、重新登录账号。这一步重置授权，是解决率最高的一招。
5. 换一朵云试试（比如从 Google Drive 换到 Dropbox）。
6. 过几个小时再试——也可能是云服务自己临时抽风。

电脑端对应路径是 **选项 → 数据库 → 操作 → 配置云**（mac 是偏好设置里），同样是切成「无」再重连。另外两个电脑特有的嫌疑：杀毒软件或防火墙拦了应用的网络认证（把应用加白名单试试）、系统代理设置不对（关掉代理或加本地绕过再试）。

## 三、提示「Passwords mismatch」（密码不匹配）

这个警告的意思是：**本地数据库和云端的数据库用的是两个不同的主密码**。常见于你在一台设备上改了密码、其他设备还没跟上。

点警告图标，应用给你两个选项：

- **以云端的密码为准**：把这台设备的密码改成云端那份数据库的密码（前提是你知道云端那份的密码）。
- **以这台设备为准**：用本机数据**覆盖**云端副本——云端旧数据会被替换掉。选这条前确认本机数据确实是你想要的版本，否则会丢掉其他设备上较新的改动。

拿不准就先别点覆盖，去其他设备上核对一下哪份数据新。

## 四、多台设备互相不同步：整体重置一遍

各台设备各推各的、谁也合不到一起时，官方的做法是每台设备**逐台**过一遍这套流程：

1. 应用更新到最新版。
2. 关闭云同步（切成「无」）。
3. 确认每台设备上的主密码**完全一致**（改密码的方法见[忘记主密码怎么办.md](忘记主密码怎么办.md)第二节）。
4. 重启设备。
5. 全部重新连到**同一个**云账号。

还不行就做一次「云端刷新」：把云里的 `SafeInCloud.db` 移出标准位置（或删掉），然后从应用里手动触发一次同步——云端副本会由本地数据重新生成。做之前确认至少有一台设备上的数据是完整的，那台就是新的源头。

## 五、云端数据库文件：在哪、别动它

云同步的载体是一个加密文件，名字固定：

- `SafeInCloud.db` —— 主数据库；
- `SafeInCloud(名字).db` —— 附加数据库（多数据库功能）。

各云的存放位置：

| 云 | 位置 |
| --- | --- |
| Google Drive（推荐方式） | 应用的专属隐藏文件夹，浏览器里打不开文件，只能在 Drive 的「设置 → 管理应用」里管理 |
| Google Drive（建同步时选了根目录） | Drive 根目录 |
| Dropbox | `/Apps/Safe In Cloud/` |
| OneDrive | `/Apps/SafeInCloud/SafeInCloud.db` |
| WebDAV / NAS / Nextcloud | 你配置同步时自己填的那个路径 |
| iCloud | 浏览不了具体文件，只能在系统设置的 iCloud 存储管理里看到 |

三条禁忌，官方反复强调：**不要移动、不要重命名、不要删除**这些文件——应用按确切的名字和文件夹找它，动了就同步不了。另外文件是加密的，直接点开看不到内容，想看数据就装免费的桌面应用。

## 六、要找客服前，先导出日志

上面都试过没解决，给官方写邮件（`support@safe-in-cloud.com`）前做一件事，能少来回好几轮：

- 手机：**设置 → 关于** → 右上角的日志按钮，导出同步日志；
- 电脑：**帮助 → 关于 → 显示日志**。

邮件里附上：日志、你用的是哪家云、报错现象的描述（截图更好）。
