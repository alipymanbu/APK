## 一、按现象找原因

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 签名时报 unknown error | 中文文件名 / 中文路径（有用户反馈过） | 改成纯英文名、放浅层目录再试 |
| 提示密钥库密码错误 | 密码或别名输错 | 核对文件、密码、别名三样全对 |
| 签名成功但安装提示「未安装」 | 设备上已有同包名、不同签名的旧版本 | 卸载旧版再装 |
| 新系统装不上、报签名问题 | 包只带了 V1 签名 | 重签时至少勾上 V2 |
| 签完名过段时间又失效 | 签名后包又被改动过 | 改完再签，签完别动 |
| 中途报空间不足 | 输入包 + 输出包同时占空间 | 留出至少两倍包体积的空间 |

## 二、逐项展开

### 报 unknown error：先试改英文文件名

商店评价里有用户反馈：给文件名带中文的本地 APK 签名时报 unknown error，换成英文名后正常。这一条来自个别用户反馈，不代表唯一原因，但零成本、值得第一个试：把文件重命名为纯英文、放到下载这类浅层目录，再签一次。还报错的话再按表里往下走。

### 密码与别名

签名要三样全对：密钥库文件、密码、别名（alias），别名还区分大小写。忘了就在「密钥库」标签里把文件重新导入一遍，可以查看里面的别名列表（以界面为准）。建议养成习惯：导入时就确认一次密码可用，别等到签名时才发现记错了。

### 签名方案与系统版本对不上

Android 11 起平台要求目标版本较新的应用至少带 V2 签名，只签 V1 的包会被直接拒绝——表现是签名步骤一切正常，安装时报签名相关错误。处理：重签时勾上 V1 + V2（选择依据见 [签名与验证使用教程.md](签名与验证使用教程.md) 第三节）。

反过来也有兼容问题：只签 V2 的包在 Android 7.0 以下的设备上装不上。手上老设备多，就 V1 + V2 都勾。

### 签名之后又动了包

签名对整个安装包做校验，签完之后哪怕只是重新压缩一下，验证就会报「已修改」、安装也可能失败。这不是故障，是机制：所有改动做完再签名，签完直接分发或安装。

### 先验证再安装

签名完成后先在「验证」标签里过一遍，确认完整再装，能省掉大量「装到一半失败」的来回。反复排查不出原因时，换一台设备签一次、装一次，能帮你判断问题出在包上还是这台设备上。
