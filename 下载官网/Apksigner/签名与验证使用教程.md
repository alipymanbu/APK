## 一、你什么时候需要它

- 你自己编译或修改过 APK，安装时提示没有签名 / 签名无效，需要重新签一份。
- 你从别处拿到一个安装包，想确认它有没有被改过、签名是否完整。
- 你手上的旧包只带了 V1 签名，在新系统上装不上（安卓 11 起不放行只签 V1 的包），想重签一次。

打开应用后，功能按标签页分布在顶部（签名、验证、密钥库等，个别版本的分组与叫法以实际界面为准），下面按操作流程讲。

## 二、签名一个 APK 的完整步骤

1. 切到「签名」标签，选择要签名的 APK 文件。
2. 选择密钥库文件，输入密码和别名。还没有密钥库的话先看 [密钥库管理与备份.md](密钥库管理与备份.md)——免费版支持导入现成的密钥库，自建是 Pro 功能。
3. 按需勾选签名方案（怎么选见下一节，拿不准就保持默认）。
4. 点开始签名，等进度走完。签名结果一般会生成在输入文件所在目录的 done 文件夹里（不同版本行为略有差异，以界面提示为准）。

两条容易踩的规矩，签之前记牢：

- **签名之后再改动 APK，签名立即失效**。改图标、替换资源、重新压缩，都算改动——先改完，再签名。
- **如果要做对齐优化（zipalign），先对齐、后签名**，顺序反了签名会失效。本应用自带对齐选项，保持默认顺序即可。

## 三、签名方案 V1~V4 怎么选

安卓的 APK 签名方案有四代，一代比一代严格，但对系统版本的要求不同：

| 方案 | 从哪代系统开始认 | 特点 | 怎么选 |
| --- | --- | --- | --- |
| V1 | 最早的安卓 | 最老的 JAR 签名方式，单独用它的新包在新系统上装不上 | 只为兼容很老的设备时勾 |
| V2 | Android 7.0 | 对整个安装包做整体校验，更严格也更快 | 常规必选 |
| V3 | Android 9 | 在 V2 基础上支持密钥轮替 | 有密钥轮替需求再勾（应用在 6.10.0 版加入了 V3 / V4 开关） |
| V4 | Android 11 | 辅助增量安装的签名 | 有对应需求再勾 |

给一个稳妥的默认做法：**V1 + V2 都勾**，新系统与老设备兼顾。要知道背景的话：从 Android 11 起，目标版本较新的应用必须带 V2 及以上签名，只签 V1 的包会被直接拒绝安装；反过来，只签 V2 的包在 Android 7.0 以下的老设备上装不上，所以两头都要顾就全勾。

## 四、验证一个包的签名

切到「验证」标签，选中要检查的文件（支持 apk / jar / zip 一类压缩包格式，以界面为准），它会告诉你两件事：有没有签过名、签名是否完整（文件有没有被改动过）。

两个典型用法：

- 签名完成后先验证一次再安装，避免装到一半才发现签名有问题。
- 对比同一个应用的两个包：一个验证完整、一个报「已修改」，报错的那个多半被改过或损坏。

## 五、报错与装不上

签名过程报错、或签完装不上，先翻 [签名失败常见问题排查.md](签名失败常见问题排查.md) 按现象对号入座；其中密钥库密码与别名相关的报错占比最高，多半是输入问题而不是包的问题。
