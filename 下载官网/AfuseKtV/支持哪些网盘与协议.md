# 支持哪些网盘与协议

> AfuseKtV 播放的片子不放在本机，而是来自你挂上去的各种来源。本篇把网盘、媒体服务器、协议挂载三类来源分开对照，写清每一种要准备什么、有什么已知限制，以及先挂哪一个更省事。

## 一、三类来源，先分清

读者常把「网盘」和「协议」混着说，实际上它们要准备的东西完全不同：

| 类 | 代表来源 | 你要先有什么 |
| --- | --- | --- |
| 网盘直连 | 阿里云盘、百度网盘、115、123、OneDrive | 网盘账号（授权登录） |
| 媒体服务器 | Emby、Jellyfin、Plex | 服务器地址与账号 |
| 协议挂载 | WebDAV、SMB、Alist、Local | 共享地址与访问凭据，或本机文件 |

三类的刮削行为也不一样：网盘与协议挂载由 App 自己扫描刮削，媒体服务器直接用服务器上的元数据，不重新刮。

## 二、逐个来源的实际情况

| 来源 | 上手要做什么 | 已知限制 |
| --- | --- | --- |
| 阿里云盘 | 授权登录 → 选要挂的文件夹 | 部分下载站标注挂载需 Android 11；官方发布页只写了整端最低 Android 6，两处口径不一致 |
| 百度网盘 / 115 / 123 | 授权登录后选目录 | 出现在官方电视端发布页的来源列表里 |
| OneDrive | 授权登录 | 出现在官网的来源列表里 |
| Alist | 填服务地址与凭据 | 常被用来把多个存储聚成一个入口 |
| WebDAV | 填地址、账号密码 | 官方在 SMB 那条里建议改用它 |
| SMB | 填共享地址与凭据 | **只能用 VLC 播放**，官方建议改用 WebDAV |
| Emby / Jellyfin | 填服务器地址与账号（直连） | 用服务器自带元数据，不重新刮；剧集排序功能需 Emby 4.8 及以上 |
| Plex | 填服务器地址与账号 | 是后加入的来源，老版本里没有 |
| Local（本地） | 直接读本机或外接存储里的文件 | 出现在手机端发布页与官网的来源列表里，电视端发布页的列表里没有它 |

各版本列出的来源会增减，以官方发布页与官网当时列出的为准；上面这张表是官方页面与发布页里出现过的来源。

## 三、先挂哪一个

| 你的情况 | 建议 |
| --- | --- |
| 已经有 Emby 或 Jellyfin | 先挂它，省掉一整套刮削 |
| 片子存在网盘里，没有媒体服务器 | 从网盘直连开始，见 [阿里云盘挂载与海报刮削.md](阿里云盘挂载与海报刮削.md) |
| 片子在 NAS 上 | 优先 WebDAV，别用 SMB |
| 来源很杂，好几种都要 | 用 Alist 收成一个入口，减少来回切库 |

一次别挂太多。每个来源都会触发一轮扫描，来源多、目录大时第一次建库会拖很久。

## 四、挂载这件事只能在手机端做

电视端没有「添加来源」的入口，所有的挂载都在手机端 AfuseKt 上完成，再同步给电视，步骤见 [手机端注册与电视端同步资源库.md](手机端注册与电视端同步资源库.md)。

## 五、两个容易和挂载混在一起的问题

- **加了来源却播不动**：那是播放内核的问题，不是挂载失败。判断方法见 [三个内置播放内核怎么选.md](三个内置播放内核怎么选.md)。
- **加了来源却没有海报**：那是刮削的问题，和来源本身无关，命名规则是关键，见 [阿里云盘挂载与海报刮削.md](阿里云盘挂载与海报刮削.md)。

另外一点预期管理：网盘直连走的是你的网盘账号，播放是否顺畅与账号自身的情况有关，App 侧不改变网盘的速度策略。
