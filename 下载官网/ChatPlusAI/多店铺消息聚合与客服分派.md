多店铺卖家最大的时间浪费，是不断在几个平台卖家后台之间切来切去，还得自己记住哪条消息回没回。ChatPlusAI 的做法是把不同平台、不同站点的会话聚到一个列表，再按规则分给具体客服。本篇讲清聚合了什么、怎么分、以及几个多人协同的坑。

## 一、聚合的范围

接进来的店铺，下面这些内容会一起聚到后台：

| 聚合对象 | 说明 |
| --- | --- |
| 买家会话 | 各平台、各站点的聊天消息汇总到一个会话列表，不用再逐个后台切换 |
| 订单状态 | 订单处理进度实时聚合，接待时能直接看到这单到哪一步了 |
| 评价 | 多店评价聚合，好评、中差评一起看，便于及时回评与挽回 |
| 退货退款 | 退款、退货这类申请同步过来，配合跟单做挽回 |

能做到这一步的前提是每个店铺都已完成授权，见 [注册登录与添加店铺.md](注册登录与添加店铺.md)。**店铺数量本身不限**，受限的是工作子账号数。

## 二、会话怎么分到人

人一多，最容易出的问题就是「这条消息谁在回」和「一个人被分到好几个店铺」。官方给的分流规则有三种优先方式：

- **按店铺优先**：谁负责这家店，消息就归谁，适合一店一人的分工。
- **按订单优先**：同一笔订单的会话始终归同一个人，避免前后说法不一致。
- **按最近接待客服优先**：谁上次接的这条线，后续还归谁，买家体验最连贯。

按官方套餐说明，**「会话智能分流」在个人版里不开放，从初创版起才有**（官方定价页里这项也叫「智能任务分配」），具体以你套餐页的勾选状态为准（见 [套餐计费与免费试用.md](套餐计费与免费试用.md)）。人少的时候手动接也能跑，人一多这项几乎是必需的。

## 三、接待时会用到的几个工具

- **自动翻译**：买家用外语发来，你按中文看懂并回复，系统负责来回转换。支持印尼语、菲律宾语、泰语、越南语、英语、西班牙语、葡萄牙语、中文 8 种，清单见 [支持哪些平台与站点.md](支持哪些平台与站点.md)。
- **快捷回复**：常用话术与图片模板存成型，一键发出。
- **超时自动回复**：没人及时接时先自动安抚一条，避免「已读不回」。
- **值班模式**：按营业时段切换由谁主要接待，非营业时段交给 AI。
- **买家星标**：把重点买家标出来，回来优先处理。
- **买家黑名单**：反复骚扰、恶意下单的买家挡在外面。
- **买家打标**：给买家贴标签，便于归类处理和后续统计。

这些工具的作用是让一个人能扛住更多的会话量，而不是让接待本身变复杂——用法与 AI 部分的配合见 [AI客服机器人怎么设置.md](AI客服机器人怎么设置.md)。

## 四、重要消息别漏：强提醒怎么用

会话一多，普通通知就失去意义了。ChatPlusAI 对重要消息给的是「强提醒」，出口有两个：

1. **应用内高亮并置顶**——适合守在电脑前接待的人；
2. **推到站外通讯软件**——适合人不在工位、但必须随时被叫起来的情况。

值得设成强提醒的一般是这几类：高价值买家、明确要退款或投诉的、以及 AI 判断需要人工介入的场景。**把提醒泛滥化等于没有提醒**，宁可只挑真正需要立刻处理的那几类。

## 五、多人协同的几个实用做法

| 场景 | 建议做法 |
| --- | --- |
| 一个客服管多家店 | 用「按店铺优先」把这几家店都分给他，别让消息在人之间跳 |
| 同一笔订单多人碰过 | 用「按订单优先」锁定承接人，避免两个人给出两种答复 |
| 新人上手 | 先只放开少量店铺，等话术熟了再扩，绩效也看得清 |
| 大促期间临时加人 | 注意工作子账号数受套餐限制，临时加不出来就要提前升级套餐 |
| 店长想总览 | 用店长视角看各店整体情况，不必逐个店铺点进去 |

配套的管理侧能力是客服绩效统计——官方说明准备了 80 多项接待绩效指标，配合实时监督看各店表现与每个人的状态，怎么拿这些数字做复盘见 [客服绩效与数据看板怎么看.md](客服绩效与数据看板怎么看.md)。

## 六、常见误解

- **「聚到一个列表」不等于「一个人能接无限量」。** 聚合省的是切后台的时间，接待能力还是取决于人手与 AI 分担的比例。
- **「店铺不限」只对店铺成立。** 工作子账号、AI 跟单的每月买家数是按套餐算的，人一多要按这两个数去算够不够。
- **分流规则要提前定。** 先加人再想怎么分，很容易出现两个人重复回一条消息；建议加员工之前就把规则想好，见 [注册登录与添加店铺.md](注册登录与添加店铺.md)。

消息接进来之后，如果还要覆盖「买家不主动说话但订单状态在变」的场景，看 [智能跟单与催单催付怎么用.md](智能跟单与催单催付怎么用.md)。
