## 一、先弄清角色卡是个什么文件

角色卡只有两种合法形态：**一张 PNG 图片**，或**一个 JSON 文本文件**。PNG 卡的玄机在于角色数据以 Base64 藏在图片的 `tEXt` 元数据块里 —— 图是立绘，数据才是人设；JSON 卡则把数据明着写。卡文件规范有 v1 / v2 / v3 三个版本（v3 最新、向下兼容），不同客户端对老版本的支持程度不一。

理解了这一层，下面的失败原因就都好懂：**卡 = 文件里的数据**，数据没进来，导了也等于没导。

以下排查依据的是卡文件本身的通用机制（多个独立来源互相印证），MineChat 具体支持到哪个卡版本以导入时的实际表现为准；先按通用层排查，八成问题在这一步就解决了。

## 二、失败原因对照表（按出现频率排）

| 症状/原因 | 一句话判别 | 怎么修 |
| --- | --- | --- |
| 传输环节压缩了 PNG | 微信、QQ 直接当图片发 = 数据大概率被抹掉 | 让对方以「文件」方式发送，或打包 zip 再传 |
| 下载到的本来就是纯图 | 站点给的「立绘下载」不含卡片数据 | 找「下载角色卡」入口重新下原文件 |
| JSON 编码损坏 | 打开是乱码（聊天软件转发、安卓另存为常见） | 重新下载，用文本编辑器确认能正常打开 |
| 随手改了后缀 | `.png` 改 `.json`（或反过来）不会转换格式 | 改回真实格式，两头都不认的文件等于废了 |
| 老卡版本太老 | 2023 年以前的 v1 卡，部分客户端直接拒收 | 找 v2/v3 版本的同一张卡 |
| 重名角色冲突 | 已有同名角色时部分客户端静默失败 | 先删掉旧的同名角色再导 |
| 文件名特殊字符 | 文件名带 emoji、全角括号、超长名 | 改成简单的文件名再导入 |
| 文件太大 | 大立绘 + 大世界书容易超上限 | 换小体积版本，或拆开单独导 |
| 选到的是缩略图 | 从相册选图，机型自动转码重新编码 | 用**文件管理器**选原始文件，不是相册 |

## 三、30 秒自检流程

按顺序走，别跳：

1. **看大小**：正常带数据的 PNG 卡多在 100KB~3MB 之间；只有几十 KB 的「精美立绘」多半已被某个环节重新编码过；
2. **换选文件的入口**：用文件管理器（不是相册、不是聊天软件的预览）选原始文件；
3. **还是失败 → 找 JSON 版本的同一张卡**：JSON 不依赖元数据，绕开 PNG 被压的问题；
4. **JSON 也失败 → 用文本编辑器打开看是不是乱码**，乱码就是编码损坏；
5. **都正常还导不进**：才是 MineChat 这侧的问题（版本不支持该卡格式等），换一张已知能导的卡对照验证。

## 四、手机端特有的三个坑

卡在「下载 → 转发 → 保存 → 导入」这条链上时，每一步都可能被转码：

- **相册转码**：部分机型开了「智能优化存储」之类的选项后，从相册选图会送出重新编码的副本，元数据被抹掉 —— 改用文件管理器选原文件；
- **浏览器保存的是预览图**：长按保存的图常是站点压缩过的预览，要点页面提供的下载按钮拿原文件；
- **跨应用分享链越长越危险**：「微信 → 保存 → 相册 → 导入」每一步都可能转码，能一步从文件管理器选就别绕三步。

## 五、导进去了但「半生效」

卡导进列表了，世界书却没跟上 —— 这也算一种失败。世界书分两种：

- **嵌在卡里的**（角色书随卡走）：导卡即得；
- **单独发的外置世界书**：要**再导一次**，并选择绑定到角色还是全局启用。

只导了卡、没导外置书，聊起来会觉得「模型变笨了」「设定时有时无」—— 先检查世界书是不是还躺在文件管理器里没进来（[角色卡与预设导入.md](角色卡与预设导入.md) 第五节）。

## 六、导入成功但人设不对

文件层没问题了，剩下是内容层：人设没生效先确认**当前选中的助手/预设是不是刚导的那个**；选对了还不对，是卡里的描述太笼统 —— 补具体的说话方式与身份背景比堆形容词管用（[角色卡与预设导入.md](角色卡与预设导入.md)）。症状更多的话走[常见问题排查.md](常见问题排查.md) 的通用清单。
