## 一、先算内存账：你的手机能跑多大的模型

本地推理是把模型整个装进内存里算，模型文件大小只是下限，运行时还要再吃一块内存。业界通行的判断（Arm 开发者站给手机端 GGUF 的建议口径）：

- 模型大小要**明显小于**手机运行内存（RAM），给系统和 App 留余量（至少 1~2 GB）；
- 按经验估算：Q4 一类的 4 比特量化下，4B（40 亿参数）级别的模型文件约 2~3 GB，适合 8 GB 内存的手机；1.5B~3B 的小模型对中端机更友好。具体文件大小以模型发布页标注为准；
- 手机动态内存会再砍掉一块（系统常驻 + 后台应用），实际可用比标称少得多，8 GB 手机的真实可用往往只有 4~5 GB。

一句话结论：先看你手机的 RAM，再倒推模型上限，别看别人跑什么你就跑什么。

## 二、模型怎么选：参数量与量化

| 选择维度 | 怎么判断 |
| --- | --- |
| 参数量 | 越小越快越省内存，能力也越弱。手机端常见 1.5B~7B；先从小模型试起 |
| 量化格式（GGUF） | Q4_0、Q4_K_M 这类 4 比特量化体积小、跑得快，是手机端首选；Q8 更准但更大更慢（量化速度差异是 Arm 开发者站的实测口径） |
| 多模态需求 | 纯文本模型收不了图；要识图就得选带视觉的模型或改走云端接口 |
| 从哪下载 | GGUF 模型在 Hugging Face、ModelScope（国内直连更稳）等社区都有，搜「模型名 + GGUF」 |
| 文件放哪 | 下载到手机存储后，在 App 的模型配置里导入（入口以 App 内实际界面为准）；文件没下完整会加载失败 |

## 三、三种离线路线怎么挑

| 路线 | 适合谁 | 说明 |
| --- | --- | --- |
| 内置 MNN | 想最省事的 | App 内置支持，按 App 内引导加载即可 |
| llama.cpp 跑 GGUF | 想自己挑开源模型的 | GGUF 生态模型最多，上文的选择逻辑都适用 |
| 连 Ollama / LM Studio | 有电脑或性能强的设备 | 模型跑在局域网另一台设备上，手机只当操作台；大模型也能用，但要保证那台设备开着、和手机在同一局域网 |

路线一、二在 App 的模型设置里切换；路线三需要先在另一台设备上把 Ollama 或 LM Studio 跑起来，再在 Operit 里填那个服务的局域网地址（见 [API密钥获取与模型配置.md](API密钥获取与模型配置.md) 中自定义接口的填法）。

## 四、跑不起来时的排查顺序

1. **加载失败 / 闪退**：先查内存——后台应用全清掉再试；还失败就换更小的量化版本；
2. **加载极慢或卡死**：模型文件可能没下完整，删掉重新下载，核对文件大小与发布页标注一致；
3. **能跑但一个字蹦半天**：换更小的参数量或更激进的量化；关掉其他后台应用；本地推理速度基本由手机芯片决定，软件层面能做的有限；
4. **机身发烫、掉电快**：本地推理是持续满载运算，属正常现象；长时间用建议插电、摘手机壳散热。

这些与 [常见问题排查.md](常见问题排查.md) 第五节「占用与性能」是同一族问题，那边还有通用处理。

## 五、什么情况下别硬上本地

- 手机 RAM 只有 4~6 GB：能跑的模型太小，回答质量有限，不如云端接口；
- 你主要用识图、长文档分析这类重活：手机端小模型承担不了，云端模型更合适；
- 只是偶尔用用：云端按量付费其实花不了多少，省下的折腾时间更值钱。

本地模型的价值在于离线、隐私、零边际成本，不在于比云端强。两头都配好（云端打底、本地应急断网时用）是不少用户的实际用法。
