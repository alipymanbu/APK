## 一、什么情况下你会需要自定义源

自定义漫画源从 3.0.0 版本开始支持（你手里的 4.0.4 自然包含），它解决两个现实问题：

- **内置源配置过期**：项目已停止维护，内置源的地址、接口不会有人再更新，源站一改版，对应源就废了——这时用自定义源补一份新配置是唯一的修复手段；
- **想接入应用不认识的源**：任何有公开接口的漫画站，理论上都能通过一份源配置接进来。

前提是你已经装好了应用，PicaComic 安装文件资源（夸克网盘）在页面开头。

## 二、源文件从哪来

自定义源的本质是一份用 JavaScript 写的配置文件（`.js` 文件），通常由别人写好、你拿来导入。两条获取路径：

1. **社区分发的现成源文件**：各种漫画工具的社区里经常有人分享 `.js` 源文件或收集包。省事，但可信度完全取决于分享者——源文件能以你的身份发起网络请求，**来历不明的不要导入**；
2. **官方模板仓库**：作者在 GitHub 上维护了一个配置仓库，地址是 [github.com/wgh136/pica_configs](https://github.com/wgh136/pica_configs)，里面的 `template.js` 是带详细注释的官方模板，改源、写源、验证一个源文件写得对不对，都以它为准。

## 三、把源加进应用

1. 打开应用设置里的漫画源管理，选择添加自定义源（入口名称随版本略有差异，以应用内实际显示为准）；
2. 按应用内提供的方式导入：选择本地 `.js` 文件，或粘贴指向该文件的链接；
3. 导入成功后，这个源会出现在源列表里，像内置源一样切换使用（切源操作见[漫画源管理与切换.md](漫画源管理与切换.md)）。

**兼容性是最大的坑**：3.1.0 版本对自定义源机制做过一次大改造，3.0 时代的老格式源文件在 4.x 上很可能直接失效。你导入的源如果加载不出、或报格式错误，先确认这份文件是不是为 3.1.0 之后的格式写的。

## 四、想自己改一份源，看这三样东西

愿意折腾的话，需要的材料官方都备齐了：

- **模板**：上面提到的 [template.js](https://github.com/wgh136/pica_configs/blob/master/template.js)，注释详细，从它改起；
- **API 文档**：官方仓库里的 `doc/comic_source.md`。能力分三块——`Network`（发 HTTP 请求，Cookie 由应用自动管理）、`Convert`（Base64 编解码、MD5/SHA 哈希、AES/RSA 解密）、`HtmlDocument`（HTML 解析与元素查询）；
- **运行环境**：源脚本跑在应用内置的 JS 引擎里，不是完整浏览器环境，浏览器里能用的 API 这里未必有。

一个现实提醒：写源需要看懂目标网站的结构，改源的时间成本远高于导入一份现成的，先确认没有现成的再动手。

## 五、加载失败时，去日志里找原因

自定义源调试有一个专门的观测点：**设置 → App → Logs**。源脚本里的日志输出会显示在这里（调试模式下还会打到控制台）：

1. 源脚本执行出错、请求失败，日志里通常有对应记录，先看这里再猜；
2. **源列表里根本不出现** → 多半是文件没导入成功或格式不对，换一份确认过兼容 3.1.0+ 格式的文件；
3. **源出现了但搜索 / 详情报错** → 源里写的接口地址可能已经变了，这一层问题只有等源文件作者更新，或者你自己按第四节改；
4. 自己改完验证时，在脚本里加几条日志输出，比反复试错快得多。

改不动、也找不到能用的源文件时，能兜底的只剩两条路：换回还能用的内置源，或考虑迁移到作者的新项目 venera（[https://github.com/venera-app/venera](https://github.com/venera-app/venera)）——它延续了同样的 JS 源思路，社区活跃度更高。其他通用问题再看[常见问题与解决办法.md](常见问题与解决办法.md)。
