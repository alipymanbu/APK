# Blocker 组件误禁用后的恢复步骤

> 本篇讲禁用组件后应用出现异常时，怎么判断是哪个组件出的问题、按什么顺序恢复，以及最坏情况下的处理办法。

误禁组件是每个用组件控制器的人都绕不开的事：症状是应用闪退、通知消失、某个功能失灵，但你往往记不清刚才关了哪个。按本篇的顺序走，绝大多数情况几分钟内能恢复。

## 一、先对症状定位组件类型

| 症状 | 最可能的组件类型 |
| --- | --- |
| 应用打开就闪退 | 禁了核心 Activity 或被依赖的 Provider |
| 收不到某类通知 / 不自启了 | Receiver（推送或开机广播被禁） |
| 某个页面打不开，但应用能开 | 对应 Activity 被禁 |
| 后台任务不跑、下载不工作 | Service 被禁 |
| 其他应用读不到它的数据 | Provider 被禁 |

判断不了就跳过这步，直接按第二节恢复——先恢复，再研究。

## 二、恢复路径（由轻到重）

1. **Blocker 里开回来**：回到该应用的组件页，把「最近一次调整里关掉的组件」逐个开回来。这是最快路径，开关即时生效，不用重启应用；开回来后如果应用还在异常，彻底杀掉应用进程再打开；
2. **核对规则文件**：如果你调整前导出过规则（方法见 [规则导出导入与备份.md](规则导出导入与备份.md)），打开导出文件对照——文件里记的就是你禁用的完整清单，逐项核对哪些是后来误加的；
3. **卸载重装**：Package Manager 的禁用状态随应用卸载而清除，卸载后重装等于把组件状态彻底重置。代价是应用本地数据，动手前先在应用内备份；重装渠道见 [下载与安装教程.md](下载与安装教程.md)。注意如果你用过 Intent Firewall 控制器，IFW 规则是系统级的，是否随卸载清除请以你的设备实测为准，重装后先验证拦截是否仍在。

## 三、误禁系统应用的最坏情况

误禁普通应用最坏也就是重装；误禁**系统应用**的关键组件（如系统桌面、系统界面相关）可能造成界面卡死、无法正常进入系统。预防永远优于恢复：

- 动系统应用前想清楚这个组件关掉后系统还能不能进设置、能不能开 Blocker；
- 一次只改一个系统应用的少量组件，改完立刻验证再继续。

如果已经进不了系统：手机连电脑，用 adb 执行 `pm enable 包名/组件名` 把组件开回来（需要此前开启过 USB 调试）。连 adb 都不可用（未开 USB 调试且界面锁死）时，剩余的手段只有恢复出厂——所以动系统组件前的每一步谨慎都是在给自己留退路。

## 四、恢复后防复发

- 批量调整前先导出规则存底（一分钟的功夫，出事后省半小时）；
- 每关一个组件组就验证一次，不要一口气关十个再验证；
- 被某些应用「复活」的组件，换 Intent Firewall 控制器再禁（原因见 [Root与Shizuku授权准备.md](Root与Shizuku授权准备.md)）；
- 拿不准的组件先跳过，只关看得懂说明的。
