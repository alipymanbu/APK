# Blocker 常见问题与报错处理

> 本篇集中列出 Blocker 用起来最常碰到的几类问题：报错弹窗、开关没反应、组件自己恢复、重启后失效、装不上安装包。

## 一、点开关报 SecurityException

报错形如 `Shell cannot change component state for 'xxx' to state 'xxx'`。

这是 Shizuku 路线的典型问题：shell 权限改不动未修改的普通应用组件。两个解决方向（官方 FAQ 口径）：

- 以 root 权限启动 Shizuku，再让 Blocker 走 Shizuku 控制器；
- 或者干脆放弃 Shizuku 路线，改用 root 下的 PM / IFW 控制器。

反复点开关没有用，先解决权限，再回来操作。

## 二、组件禁了又自己打开

Package Manager 控制器的固有行为：组件被禁用后，应用再尝试启动它会收到异常，开发者可以捕获异常后把组件重新启用，于是你看到开关又弹回去了。

处理办法：把该组件换到 Intent Firewall 控制器再禁一次。IFW 只拦截、不改组件状态，应用检测不到，也就不会试图恢复。两种控制器的行为对照见 [Root与Shizuku授权准备.md](Root与Shizuku授权准备.md)。

## 三、重启手机后失效

用无线调试启动的 Shizuku，重启后服务就停了，Blocker 的 Shizuku 控制器随之失联——这是系统限制，不是故障。Shizuku 官方说明也注明：无论哪种启动方式（含 root 启动）都无法开机自启，重启后需要手动再启动一次 Shizuku，然后确认 Blocker 还在授权列表里。

每次开机后要做的就这一件事；嫌麻烦就给设备 root，然后直接用 PM / IFW 控制器，不依赖 Shizuku 在线。

## 四、应用更新后组件状态异常

应用更新后，你之前禁掉的组件有可能回到启用状态（有较多用户反馈遇到；不同系统与版本表现不完全一样）。更新完一个应用后，回到它的组件页把开关重新核对一遍即可。如果你用 IFW 控制器处理过这些组件，也顺手确认下拦截仍然生效。

## 五、打不开、闪退或组件列表为空

- **授权没就绪**：确认 root 授权已给到 Blocker，或 Shizuku 正在运行且 Blocker 在授权列表里（回 [Root与Shizuku授权准备.md](Root与Shizuku授权准备.md)）；
- **装的变体不对**：到系统应用详情确认包名是 `com.merxury.blocker`；foss 与 market 包名相同、互相覆盖安装，不会同时存在两个；
- **系统版本过低**：对照 [下载与安装教程.md](下载与安装教程.md) 里的系统要求；
- **组件列表为空**：多为控制器与服务失联，重新拉起 Shizuku 或重启 Blocker 再试。

误禁组件后应用闪退、功能异常需要逐项恢复的，按 [组件误禁用后的恢复步骤.md](组件误禁用后的恢复步骤.md) 的顺序处理。

## 六、安装包装不上

- 「未知来源」权限没给到来源应用（文件管理器、浏览器各自要单独允许）；
- 安装包不完整：对照下载篇版本信息表里的 MD5 校验；
- 存储空间不足、或系统版本低于要求时，系统安装器会直接拒绝，提示语各系统不同，但结论一致——先满足条件再装。

环境与操作都正常但仍有异常时，可以到官方仓库的 issue 区（[github.com/lihenggui/blocker/issues](https://github.com/lihenggui/blocker/issues)）搜关键词，别人踩过的坑大概率也在那里。
