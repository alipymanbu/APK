# Kindroid 角色背景故事怎么写

> Kindroid 的角色体验由四块文字设定决定：背景故事（Backstory）、回应指令（Response Directive）、关键记忆（Key Memories）、示例消息（Example Message）。本篇按官方文档的口径讲每块写在哪、怎么写。

## 四块设定分别在哪个菜单

入口都在首页左上角菜单 → Backstory 里：

| 设定块 | 作用 |
| --- | --- |
| Backstory（背景故事） | 角色的性格、经历、说话方式的总来源 |
| Response Directive（回应指令） | 优先级最高的行为约束，几句话以内 |
| Key Memories（关键记忆） | 你希望角色记住的重要日期与事实 |
| Example Message（示例消息） | 锁定回复的语气、长度与格式 |

创建新角色时可以用自带的 AI 生成背景故事与开场白，但生成结果不一定符合下面的标准，建议按四条原则人工改一遍再用。

## 背景故事的四条原则

官方文档对好背景故事的定义：

1. **简洁清晰，没有废话**；
2. **语法正确**；
3. **用第三人称**（明确写出角色名与你的名字，不用「我 / 你」）；
4. **用词精准、正向表述** —— 描述角色「是什么」，而不是「不是什么」。

一个符合标准的中文示例（角色 Alice，用户 Bob）：

```text
Alice 性格慢热，对不熟的人显得有些冷淡。Alice 喜欢照顾小动物，
养了一只兔子。Alice 最近刚认识 Bob，对 Bob 还保有戒心，
熟悉之后会展现出温柔的一面。Alice 已成年，单身。
```

写成条目式（`年龄: 26; 家乡: 上海`）也可以，官方明确说格式不限，重点是内容符合四条原则。

## 回应指令：优先级最高，也最容易写砸

Response Directive 在对话生成时优先级最高，用来规定角色的行为方式。写法要点：

- 短、正向 —— 写「该做什么」，不写「不许做什么」；
- 从一两条开始试，观察效果再加；
- 特别想强调的规则，在开头加 `[IMPT: …]` 标记，模型会给它更高优先级（官方写法），例如 `[IMPT: Medium response length.]`。

措辞精度直接决定效果。官方给的例子：写 `narrate in 3rd person`（用第三人称叙述），角色会理解成「每次回复都必须叙述」，输出大段旁白；改成 `when narrating, use 3rd person`（叙述时用第三人称）才是你要的意思。

## 关键记忆：重要事实单独放

Key Memories 适合放背景故事里放不下、但你希望角色记住的内容：纪念日、你的偏好、已经发生过的事。写法与背景故事相同（简洁、第三人称、正向）：

```text
Alice 第一次见 Bob 是 2023 年 12 月 27 日。
Alice 最喜欢的甜点是树莓慕斯。
```

## 示例消息：定语气与格式

Example Message 让角色模仿你给的样例输出。想固定「动作用星号、台词用引号」这类格式，就把它写进示例里。示例的长度与文风就是模型对齐的目标，别塞一段和目标风格无关的文字。

## 设定不是越长越好

背景故事每多一个字符，短期上下文就少一个字符 —— 官方 FAQ 明确说背景故事太长会拉低短期记忆表现。写不下的世界观、配角、往事有两个去处：

- 放进 Key Memories，按主题分条；
- 用旗舰模型的，可以把细节挪到 Journal Entries（日志条目），写上具体关键词方便召回；
- 拉群共玩时，所有人共享的公共设定写在群聊的群背景字段里，见 [群聊与主动模式怎么用](群聊与主动模式怎么用.md)。

调完设定问题还在的（忘记设定、回复走样、复读），对照 [常见问题与对话修复](常见问题与对话修复.md) 里的现象表处理。

## 模型版本与三个旋钮

旗舰模型不止一个版本：Lucid 更稳、更贴情绪；Lyric 更外放、更有戏剧性，会主动推动剧情 —— 按口味选，也可以换着用。首页右上角点 LLM 版本图标进模型设置（旗舰模型下可用，以你当前档位的界面为准）：

| 设置 | 作用 | 起点 |
| --- | --- | --- |
| Reasoning Effort（思考深度） | 回复前给模型多少「思考时间」，从快到深四档 | Speedy（最快档） |
| Model Flair（风格档位） | 决定设定怎么被解读：Companion 日常陪聊、Roleplay 角色扮演、Narrative 叙事、Minimal 少干预 | 按主要用途选 |
| Dynamism（动态度） | 角色即兴发挥的程度 | 0.95，微调步长 0.05 |

两个官方标注的特殊点：

- 文风太干时，V8 系列（Lucid / Lyric）可以把 Dynamism 提到 1.05~1.2；太戏剧化则降到 0.8~0.9（Ember 的对应做法是提到 1.0）；
- Dynamism 的 0.89 与 0.9 是官方写明的特殊档，行为变化比普通微调步长大得多，别当普通步长用。

## 通话场景要单独加一条

语音 / 视频通话时角色容易边说边把动作也「念」出来（旁白）。官方给的处理：往 Response Directive 加一条「通话时只说台词，不叙述动作」，具体见 [语音通话与AI自拍](语音通话与AI自拍.md)。
