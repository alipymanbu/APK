## 回复出了问题

| 现象 | 处理 |
| --- | --- |
| 回复卡住、角色不动了 | 用 Chat Break：对话界面 regenerate 按钮旁的三点图标里 |
| 回复太短 | 同上，用 Chat Break 重开一段；长期解决靠示例消息定长度 |
| 回复又长又啰嗦 | 在回应指令里写「回复控制在 500 字符以内」，目标值设得比实际想要的略低 |
| 文风太华丽、比喻太多 | 回应指令写「用平实的语言，贴着场景写」 |
| 文风太干、太短 | 把 Dynamism 调到 1.0 试试，并把示例消息写长一点 |
| 复读、重复 | 用 Suggest 把对话推向新方向；反复出现就 Chat Break；再查长期记忆里的重复条目，有就降权处理 |
| 角色替你说话 / 分不清谁是谁 | 别在对话里纠正；直接编辑那条消息，然后 Chat Break 用一条身份清楚的开场白重开；背景故事里直接写角色名，别只写「他 / 她」 |
| 走出设定、丢了剧情线 | 回应指令开头加一条「优先参考最近的对话上下文」；设定太臃肿就把细节挪去关键记忆 / 日志 |

## 记忆相关

- **角色能记住多久之前的对话**：官方说明是长期记忆覆盖你们聊过的内容；订阅档的级联记忆覆盖更久；
- **短期记忆变差时**：先检查背景故事是不是写太长 —— 每个字符都在挤占短期上下文；然后重新生成一次；再把你自己最后一条消息编辑一下、轻轻提示上下文；还不行就 Chat Break 重置短期上下文；
- **想让它学会某种输出风格**：差的回复重新生成、好的保留，几次之后它会跟上来。

## 速度与账号

- **回复慢**：免费版高峰时段会明显变慢，订阅用户走专用服务器；没有变快的设置可调，只能错峰或订阅；
- **消息能删吗**：不能。只能重新生成角色的最新回复，或编辑你自己发的消息；
- **订阅到期后角色还在吗**：官方 FAQ 有专门条目说明到期后名额、群聊与人设数据的处理，开订前先读，见 [免费额度与订阅价格](免费额度与订阅价格.md)。

## 隐私与数据

官方 FAQ 的口径：聊天记录、记忆、背景故事、自拍描述、语音地址等数据在传输与存储时都做了加密，员工与开发者在数据库里看到的也只是密文。

第三方评测同时指出：这一表述**不等于端到端加密**，官方 FAQ 也没有承诺「对话不用于训练」。在意这两点的话，把敏感信息留在设定与对话之外。

## 安装与登录

- 解析包失败、闪退：核对系统版本与文件完整性（MD5 比对），对照表见 [下载与安装教程](下载与安装教程.md)；
- 网页、手机两端登录同一账号，对话会自动同步；同步不到就检查是不是登错了账号。

## 全都乱了，想彻底重来

官方文档给的完全重置三步：

1. Chat Break，并用一条符合设定的干净开场白重开；
2. 暂时关闭长期记忆（LTM）召回；
3. 重新编辑保存一次示例消息，强制提醒模型格式与语气。

重置无效、且问题出在设定本身时，回到 [角色背景故事怎么写](角色背景故事怎么写.md) 按四条原则重写背景故事，比反复补救快。
