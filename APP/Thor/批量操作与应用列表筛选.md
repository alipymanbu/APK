# Thor 批量操作与应用列表筛选

> 本篇讲清 Thor 应用清单的排序与筛选怎么用、批量动作各自动的是什么、以及批量处理时的稳妥顺序。

手机里装了几百个应用之后，逐个点进详情做操作是不现实的。Thor 的做法是先在清单上把范围缩小、再一次性对选中的多个应用执行同一个动作。本篇按「先筛、再选、后执行」的顺序讲，重点是每一步会改到什么，以及哪些动作做错了没法回头。

## 一、清单能按什么排、按什么筛

清单本身既可以排序，也可以筛选，两者可以叠加使用：

| 维度 | 能选的项 | 典型用法 |
| --- | --- | --- |
| 安装来源 | 按来源排列（应用商店、侧载、厂商渠道等） | 找出所有不是从正规商店装进来的应用 |
| 应用类型 | 用户应用 / 系统应用 | 清理预装应用时只看系统这一类 |
| 应用状态 | 正常 / 已冻结 / 已挂起 / 已隐藏 | 确认某个应用现在处于哪种状态 |
| 拆分应用 | 带标记，表示它是分片安装的 | 导出安装包前先确认类型，见 [应用安装包怎么提取与分享.md](应用安装包怎么提取与分享.md) |
| 搜索 | 按名称或包名搜 | 知道包名时直接搜最准 |

排序与筛选只改变「你看到什么」，不动任何应用，可以放心试。

## 二、三步筛出要处理的那一批

1. **先切类型**：要清理预装应用就把类型筛选切到系统应用，日常整理就切到用户应用；
2. **再缩范围**：用搜索框输名称片段，或用来源排序把同一来源的应用排在一起；
3. **最后勾选**：在列表里逐个勾选目标，或按当前筛选结果整体选中。

勾选时留意一件事：**同一批里不要混进「不确定要不要动」的应用**。批量动作是同时生效的，混进去之后你就分不清是哪一个引起的异常。

## 三、批量动作各自动的是什么

不同版本收录的批量动作略有差别，以你手机里实际出现的为准。常见的有这几类：

| 动作 | 实际改变 | 能不能回退 |
| --- | --- | --- |
| 冻结 | 停用应用，后台不再运行 | 能，解冻即恢复 |
| 解冻 | 让被冻结的应用恢复正常 | —— |
| 挂起 | 让应用进入系统层面的暂停状态，比冻结更接近「暂时不让用」 | 能，取消挂起 |
| 卸载 | 从当前用户移除应用 | 系统应用的退路有限，见 [冻结和卸载预装应用怎么做.md](冻结和卸载预装应用怎么做.md) |
| 重新安装 | 用已安装的包重新安装一次，常用于修复异常状态 | —— |
| 结束进程 | 停掉当前正在运行的那个进程 | 不用回退，但它不是持久状态，应用之后还会被系统重新拉起 |
| 清除数据 | 清掉该应用的用户数据 | **不能**，数据清掉就没了 |

**把这几个动作按危险程度排一下**：搜索、排序、勾选最安全；冻结与挂起可逆；结束进程只是临时效果；重新安装会改动安装记录；卸载与清除数据属于不可逆或难回退的操作。批量执行时，尽量把不可逆的动作单独拎出来做。

## 四、状态标记怎么读

清单和详情页上会出现几种状态标记，含义不一样，别混着理解：

- **已冻结**：应用被停用，桌面图标通常也不再显示，但数据还在；
- **已挂起**：应用还在，只是被系统挡在门外，图标多半还在，点开会被拦住；
- **已隐藏**：这类状态通常出现在用设备所有者模式（Dhizuku）处理过的应用上；
- **拆分标记**：只说明这个应用是分片安装的，与状态无关。

看到某应用「图标不见了但 Thor 里还在」，基本就是被冻结或被隐藏了，不是被卸载。

## 五、批量执行的稳妥顺序

1. **先筛选，再动一个试试**。挑一个最无关紧要的应用，先单独执行一次目标动作，确认按钮点得动、效果符合预期；
2. **再整批执行**。同一批只做同一件事，不要一批里又冻结又卸载；
3. **留观察期**。批量冻结之后用一两天再决定要不要升级成卸载；
4. **清数据放在最后**。它不可逆，且往往在你已经确认前面几步都对了之后才需要。

批量操作依赖权限引擎，遇到「部分成功、部分失败」的情况先别重复点，去 [常见问题与排查.md](常见问题与排查.md) 确认权限状态——权限中途失效是批量动作失败最常见的原因。
