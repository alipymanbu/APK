# Thor 冻结和卸载预装应用怎么做

> 本篇讲清冻结与卸载对应用的实际区别、哪些预装应用碰了会出事、怎么冻结与解冻，以及卸载前的退路怎么留。

清理预装应用这件事，Thor 给的是「冻结」和「卸载」两个动作。两者在手机上留下的后果差别很大：冻结基本是一次可逆的操作，卸载则要看你的机型与权限模式给不给退路。先分清这两件事，再动手，比事后找恢复方法省事得多。

## 一、冻结和卸载到底差在哪

| 对比项 | 冻结 | 卸载（系统应用） |
| --- | --- | --- |
| 应用还能不能运行 | 不能，进程起不来、通知也不出 | 不能，从当前用户里消失 |
| 桌面上还看得到吗 | 多数启动器不再显示它的图标 | 看不到 |
| 应用数据 | 保留 | 视实现而定，通常一并清掉 |
| 恢复方式 | 在 Thor 里点解冻，基本一步到位 | 依赖权限模式与机型，不一定有现成的恢复入口 |
| 系统分区里的原始文件 | 不动 | 一般不删除，只是移除当前用户的安装记录 |
| 需要权限 | 需要（Root 或 Shizuku；Dhizuku 走另一套） | 需要，且要求更高 |

一句话判断：**拿不准就先冻结**。冻结会得到一个近似「应用消失」的效果，但随时能退回去；卸载拿到的干净程度更高，退路却更窄。

## 二、这几类应用不要碰

有些系统应用停掉之后，手机当场就没法正常用，或者开机卡住。下列几类，除非你非常清楚自己在做什么，否则不要冻结、更不要卸载：

- **桌面与启动器**：冻结它，你连回到应用列表的入口都没有；
- **系统界面（System UI）**：状态栏、通知、导航都会一起消失；
- **输入法**：冻结后所有需要打字的地方都没法输入，包括解锁界面；
- **电话、短信、联系人**：直接影响通话与收验证码；
- **名字里带 Framework、Services、Provider、Telephony 的系统组件**：多为系统运行的底层依赖；
- **账号、支付、应用商店相关组件**：可能导致账号被锁在锁屏界面，或无法再安装应用；
- **带设备管理员身份的应用**：这类应用会拒绝被停用，即使操作成功也可能留下管理残留。

判断顺序上有个省事的做法：**先在 Thor 的应用详情里看一眼它是不是系统应用、包名长什么样，再决定**。名字里带系统组件关键词的，一律先放过；确实想清理的，也只处理那些一眼能看出功能、且停掉不影响打电话和上网的应用（预装游戏、推广工具、厂商自家的小工具通常属于这一类）。

## 三、冻结一个预装应用的步骤

1. 先确认权限已就绪——工作模式一项不是「无权限」，按钮才点得动。权限怎么给见 [Shizuku授权与工作模式怎么选.md](Shizuku授权与工作模式怎么选.md)；
2. 回到应用列表，用筛选把范围缩到系统应用，或直接搜出目标应用；
3. 进它的详情页，点冻结；
4. 验证三件事：桌面图标是否消失、它的通知是否不再出现、Thor 里这个应用的状态是否标成了已冻结；
5. **把应用名记下来**（截图或记在便签里）。被冻结的应用在桌面上是找不到的，回头只能靠这份记录或 Thor 的冻结列表把它捞出来。

一次只处理一到两个，观察一天再决定下一批。冻结之后要留意的是功能类故障而不是报错——比如某个系统功能悄悄失灵，往往就是刚刚冻结的那个组件在起作用。

## 四、怎么解冻、怎么确认解冻成功

1. 打开 Thor，进冻结列表（或直接从应用列表搜到它）——被冻结的应用不会从 Thor 的清单里消失；
2. 进详情点解冻。**用哪个模式冻的，就用哪个模式解**，中途切换权限引擎容易报错；
3. 验证：桌面图标回来了、能正常点开、Thor 里的状态标记恢复成正常。

有一件事最容易卡住人：**没 root 时 Shizuku 服务在重启手机后会停**。冻结状态会一直保持，但你想解冻时会发现操作做不了——这不是解冻失败，而是权限引擎没在跑。把 Shizuku 重新启动一次，再回来解冻即可。

## 五、决定卸载系统应用前，先确认三件事

1. **确认它不影响开机与基础功能。** 最稳的做法是先冻结用几天，没问题再卸载；
2. **记下它的包名**，而不是只记名字。同名应用很多，恢复时按包名才找得准；
3. **确认你有把它弄回来的手段。** 无 root 时对系统应用的卸载一般只是「对当前用户移除」，系统分区里的原始文件还在，因此多数情况下能用同一权限模式把它装回来；但不同机型、不同权限模式下 Thor 提供的恢复入口不一样。最坏的情况要恢复出厂设置或重刷官方固件，两者都会清掉手机数据——所以卸载前先确认自己能承受这个后果。

## 六、系统更新之后要复查一遍

厂商推送系统更新时，系统分区会被整体替换，固件里预置的应用连同它出厂时的启用状态一起回来。所以处理过一轮之后，下一次更新完，被停用或卸载过的那几个有可能重新出现。

这件事的准备动作很简单：**处理完就把应用名记一份清单**，更新之后照着清单核一遍、缺的补上。相对地，用冻结处理的那批在 Thor 的状态筛选里一眼能对上，卸载掉的那些回来之后跟全新应用没区别，只能靠清单认。更新后的完整复查顺序写在 [系统更新后预装应用又回来了怎么办.md](系统更新后预装应用又回来了怎么办.md)。

准备成批清理的，不要逐个来回切页面，用列表里勾选多个应用再统一执行的方式效率更高，各种批量动作的差别与执行顺序写在 [批量操作与应用列表筛选.md](批量操作与应用列表筛选.md)。操作中途出现「权限不足」「操作被拒绝」这类提示，对照 [常见问题与排查.md](常见问题与排查.md) 逐项查。
