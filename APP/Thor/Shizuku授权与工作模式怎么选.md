# Thor Shizuku 授权与工作模式怎么选

> 本篇讲清 Thor 的 Root、Shizuku、Dhizuku 三种权限模式分别能干什么，以及没有 root 的机型怎么把权限拿到手。

Thor 里能点到的操作分成两类：看清单、搜应用、导出安装包这类只要普通应用权限，装上就能用；冻结、卸载系统应用、清除数据这类要越过应用沙箱，必须先有一个更高权限的引擎撑着。Thor 自己不去争这个权限，而是让你在设置里指一个已经拿到权限的引擎给它用，这就是「工作模式」。本篇把三种模式的分工和取得方式讲清楚。

## 一、三种模式的分工

| 模式 | 权限从哪来 | 重启手机后 | 主要能做什么 |
| --- | --- | --- | --- |
| Root | 手机已 root，装好授权管理应用 | 仍然有效 | 能力最全，等于以系统最高权限执行操作 |
| Shizuku | 用无线调试或电脑 ADB 把 Shizuku 服务启动起来，Thor 再向它申请授权 | **失效，要重新启动一次** | 大部分日常管理操作，免 root、不动系统分区 |
| Dhizuku | 把 Dhizuku 设为设备的「设备所有者」 | 仍然有效 | 设备所有者能做的事，主要用于冻结/隐藏应用，覆盖面比前两种窄 |

选哪一条，取决于你的手机状态：已经 root 的用 Root；没 root 但系统是 Android 11 及以上的，用 Shizuku 最省事；不想每次都重新启动服务、又能接受把手机交给一个设备所有者应用管理的，才考虑 Dhizuku。

## 二、没 root 的机型：把 Shizuku 跑起来

Shizuku 是另一个独立应用（包名 `moe.shizuku.privileged.api`，官方站点与说明见 [shizuku.rikka.app](https://shizuku.rikka.app/zh-hans/guide/setup/)），Thor 只是它的使用者。启动方式按系统版本分两种：

**Android 11 及以上：用无线调试，不需要电脑。** 顺序是「开开发者选项 → 开无线调试 → 配对 → 启动」，具体为：

1. 在系统设置里打开「开发者选项」，再打开其中的「USB 调试」；
2. 进入「无线调试」并把它打开；
3. 打开 Shizuku，选「通过无线调试启动」，点其中的配对入口；
4. 回到系统的「无线调试」页，点「使用配对码配对设备」，系统会给出一个六位配对码和一个端口号；
5. 在 Shizuku 的通知或配对弹窗里填入那个配对码——配对只需要做这一次；
6. 回到 Shizuku 点启动。启动失败时，把无线调试关掉再打开一次，通常能恢复。

**Android 10 及以下：只能连电脑用 ADB 启动。** 这一步没法规避，用电脑的数据线连上手机，在电脑端执行启动命令即可。所用命令以官方说明页当时给出的为准，不要从第三方教程里抄一段来源不明的命令。

两条路都有一个共同限制：**没 root 时，Shizuku 服务在每次重启手机后都会停**，需要重新走一遍启动步骤。这不是 Thor 的问题，也不是配置错了。

## 三、让 Shizuku 稳定跑起来：厂商设置要改哪几项

Shizuku 官方手册里专门留了一段给「厂商改过的系统」，因为国内定制系统常把调试通道管得更严。要改的项按厂商对号入座，官方给出的清单是：

| 厂商 / 现象 | 要改的设置 |
| --- | --- |
| 所有设备（通用） | 允许 Shizuku 在后台运行；不要关掉「USB 调试」与「开发者选项」；把 USB 使用模式改成「不进行数据传输」（Android 9 及以上）或「仅充电」（Android 8）；Android 11 及以上再打开「停用 adb 授权超时功能」 |
| MIUI（小米、POCO），输入配对码后立刻失败 | 在「通知管理 → 通知显示设置」里把通知样式切换为「原生样式」 |
| MIUI，提示 adb 权限受限 | 在「开发者选项」里打开「USB 调试（安全设置）」——它与「USB 调试」是两个分开的选项，只开后者不够 |
| MIUI，开发者选项被莫名关掉 | 不要用「手机管家」的扫描功能，它会禁用开发者选项 |
| ColorOS（OPPO、一加），adb 权限受限 | 在「开发者选项」里关闭「权限监控」 |
| Flyme（魅族），adb 权限受限 | 在「开发者选项」里关闭「Flyme 支付保护」 |
| EMUI（华为、荣耀） | 在「开发者选项」里打开「『仅充电』模式下允许 ADB 调试选项」 |
| Sony | 别去点插上 USB 后弹出的那个对话框，它会把 USB 使用模式改掉 |
| 一直显示「正在搜索配对服务」 | 搜索配对服务要访问本地网络，很多厂商在应用不可见后立刻断掉网络权限；给 Shizuku 开放后台运行权限 |

上表来自 Shizuku 官方用户手册的常见问题一节，各厂商在系统大版本更新时改过入口名称，以你手机上实际看到的为准。**改完之后仍按第二节的顺序启动**：先开无线调试，再在 Shizuku 里点启动；如果启动失败，官方给的第一招是把无线调试禁用再启用一次。

另外补一个实操细节：**配对只需要做一次，重启后不必重新配对**，只需重新把无线调试打开、回 Shizuku 点启动。只有当启动反复失败时，才需要重新走一遍配对。

## 四、在 Thor 里授权并切换模式

1. 先确认 Shizuku 已经处于「正在运行」状态；
2. 打开 Thor，回到应用列表或设置页，它会提示检测到 Shizuku 并弹出授权申请；
3. 允许之后，进设置找到工作模式选项，把它切到 Shizuku；
4. 随便点一个应用进详情页，看冻结、清除数据这类按钮是不是变成可用的状态——可点即已生效。

如果第 2 步没有弹出任何授权提示，说明 Shizuku 当时没有在运行，或者 Thor 还没被系统刷新出新权限。先回 Shizuku 确认服务在跑，再重开一次 Thor，多数情况就能看到。

## 五、Dhizuku 走的是另一条路

Dhizuku（包名 `com.rosan.dhizuku`，官方说明页 [iamr0s.github.io/Dhizuku](https://iamr0s.github.io/Dhizuku/)）借的是安卓的「设备所有者」身份，它不像 Shizuku 那样靠调试通道拿 shell 权限，所以能跨重启存活。代价是开启条件苛刻：**设备在设置设备所有者时必须没有其他账号和用户**，已经登录过账号的设备要先移除，官方明确说明带着账号的设备它可能无法提供支持。设置本身要通过电脑 ADB 执行一条命令（以 Dhizuku 官方说明为准）：

```bash
adb shell dpm set-device-owner com.rosan.dhizuku/.server.DhizukuDAReceiver
```

成功之后，在 Thor 里同样会出现授权提示，允许并把工作模式切到 Dhizuku 即可。要在实际使用前先清楚两点：设备所有者能操作的范围比 root 和 shell 权限窄，Thor 在 Dhizuku 模式下会有一小部分功能不可用（界面上会说明原因）；另外设备所有者身份不容易随手解除，想退出得按 Dhizuku 官方的卸载流程走。因此仅在「不能 root、又不想每次重启都重新启动 Shizuku」时才值得考虑。

## 六、已 root 的机型更简单

手机已经 root 的，直接在 Thor 里授予 root 权限、把工作模式切到 Root 就行，不用碰 Shizuku 与 Dhizuku。这样做的好处是重启后权限仍在、可操作范围也最全；代价是 root 本身会带来系统完整性校验和保修方面的连带影响，这部分取舍与 Thor 无关。

## 七、模式不对时会看到什么

| 现象 | 多半的原因 |
| --- | --- |
| 操作按钮是灰的，点不动 | 工作模式还停在「无权限」，或者授权弹窗被跳过 |
| 提示权限不足、操作被拒绝 | Shizuku 服务停了（典型是刚重启过手机），或授权已被撤销 |
| 冻结成功但解冻时报错 | 两次操作用的不是同一个引擎，切回原来的模式再解冻 |
| 部分功能提示当前模式不支持 | Dhizuku 模式下该功能本身不在设备所有者的能力范围内 |

前两种现象的重启与重授权顺序写在 [常见问题与排查.md](常见问题与排查.md)。权限齐了之后，第一步建议从「冻结」而不是「卸载」开始，理由与操作步骤见 [冻结和卸载预装应用怎么做.md](冻结和卸载预装应用怎么做.md)。
