# Thor 系统更新后预装应用又回来了怎么办

> 停用或卸载过的预装应用在系统更新后又冒出来，是厂商推送更新的正常结果，不等于你之前白做了。这篇讲怎么确认属于哪种情况、更新后按什么顺序复查。

清过一轮预装应用之后，下一次厂商推送系统更新，被停用或卸载的那几个可能又出现在桌面上。这是系统更新整体替换系统分区的结果——厂商预置在固件里的应用与它出厂时的启用状态跟着一起回来了，跟你用哪个应用、哪种权限模式无关。本篇讲更新之后怎么把这件事重新收拾好，以及怎么让下次的返工量小一点。

## 一、先分清是「回来了」还是「又是新的」

进 Thor 找到那个应用，看两处：

| 看到的 | 说明 |
| --- | --- |
| 状态是正常，版本比之前高，安装来源是厂商渠道 | 更新带回来的那一份，按原先的处理办法再处理一次即可 |
| 状态是正常，版本跟之前一样，来源也和之前一样 | 多半是停止冻结时被系统重新启用，不是更新装了一份新的 |
| 状态是已冻结 | 它没回来，你看到的是别的东西（例如桌面上的快捷方式、或另一个同名应用） |

还有一种情况容易误判：**你看到的其实是它的桌面快捷方式或者残留通知**，应用本身并未运行。回到 Thor 的状态筛选里看一眼，比在桌面上判断准。

顺带说明一个认识上的误区：用 root 直接删掉系统分区文件的处理方式不在本篇范围内——那种做法更新后系统分区被整体替换，结果反而更难预料，本篇讲的是用 Thor 冻结或卸载的情况。

## 二、更新之后按这个顺序复查

1. **先把权限引擎恢复**。系统更新一定会重启手机，没 root 时 Shizuku 服务必然已经停了，此时 Thor 里所有需要权限的操作都做不了。先把 Shizuku 重新启动起来（见 [Shizuku授权与工作模式怎么选.md](Shizuku授权与工作模式怎么选.md)），再往下走；
2. **看冻结清单还剩什么**。用状态筛选把范围切到已冻结，对照你上次处理的那一批，缺哪几个就是被更新清掉的；
3. **再把厂商来源的排一遍**。用安装来源排序，把同一厂商渠道的应用集中起来看，有没有多出来的；
4. **补一遍**。缺的那几个重新冻结或重新卸载，同一个动作一次做完，见 [批量操作与应用列表筛选.md](批量操作与应用列表筛选.md)。

顺序不要颠倒：**先确认权限、再动手**。权限没恢复时去点按钮，只会得到一串失败提示，还容易误判成「更新后应用坏了」。

## 三、怎么让下次的返工小一些

- **留一份处理清单**。处理完就把应用名列出来（必要时带上包名），存在便签或备忘里。更新之后照着清单核对，比凭记忆找快得多；
- **优先冻结，少直接卸载**。冻结过的应用在 Thor 里状态明确，复查时一眼能对上；卸载掉的那些回来之后，跟一个从没处理过的应用长得一样，只能靠你自己的清单认出来；
- **同类的攒一批一起做**。厂商自家的小工具、预装游戏这类通常是一批更新、一批复活，放在一次里处理完更省事；
- **更新后隔一会儿再操作**。刚更新完系统还在做自己的初始化，清单可能加载不全，等它稳定下来再处理，避免重复操作。

## 四、更新前要不要先把冻结的解除掉

不用。官方没有要求更新前解除冻结，系统更新也不会因为你停用了一部分应用而装不上；更新过程本身会重启手机，真正需要提前准备的是**那份处理清单**，而不是把冻结一个个解开。

如果你是怕更新出问题后不好排查，那就在更新前把清单记全、并确认自己知道怎么解冻（用冻结时的同一个权限模式），这就够了。

## 五、回来了但处理不了怎么办

更新后重新操作时如果一直失败，先按这个顺序排除：

1. 权限引擎是不是没起来（最常见，见 [常见问题与排查.md](常见问题与排查.md) 第一节）；
2. 是不是批量勾选时混进了一个带设备管理员身份的应用，把整批拖失败了；
3. 清单是不是还没刷新，你点的其实是已经消失的那条旧记录。

三种都排除之后仍然失败，回到 [冻结和卸载预装应用怎么做.md](冻结和卸载预装应用怎么做.md) 对照一下这类应用是不是本来就不适合动——更新之后系统组件之间的依赖有可能变化，上次能冻的不代表这次也能。
