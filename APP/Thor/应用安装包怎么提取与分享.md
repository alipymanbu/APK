# Thor 应用安装包怎么提取与分享

> 本篇讲清怎么用 Thor 把已装应用导出成安装包、拆分应用为什么不能只传一个文件，以及安装器与安装来源记录怎么用。

手机里装着的应用，安装包未必还留在存储里。Thor 能直接从已安装的应用里把包取出来，用于备份、换机、装到别的设备。本篇讲清导出这一步怎么做、导出来的东西是什么，以及它做不到什么。

## 一、导出一个已装应用的包

1. 在应用列表里找到目标应用（用搜索框按名字或包名搜最快），进它的详情页；
2. 点「分享 APK」这类导出入口；
3. 系统会弹出分享面板，选择存到本地（文件管理器）或直接发给对方；
4. 存到本地的包，去文件管理器里确认一下文件确实落下来了、体积不是 0，再删掉原应用或做下一步。

整个过程不需要额外权限，属于普通应用就能做的操作。导出的是**当时手机里那一份**——如果这个应用是从别处侧载的旧版本，导出的也就是那个旧版本，不是商店里的最新版。

## 二、导出来的到底是什么

先看它在列表里有没有拆分标记，再决定怎么传：

| 类型 | 导出后得到 | 怎么用 |
| --- | --- | --- |
| 普通应用 | 一个 `.apk` 文件 | 直接安装，直接传给别人 |
| 拆分应用 | 多个分片文件 | 分片要一起带走才装得上，见下一节 |
| 带独立数据包的应用 | 主包之外还有额外的资源包 | 资源包与主包要配套，只传主包会出现装上也打不开的情况 |

所以导出之后，先看分享面板里给的是「一个文件」还是「一堆文件」。给了一堆的，就按下一节处理。

## 三、拆分应用为什么不能只传一个文件

拆分应用的代码和资源被切成了多份，安装时系统会把它们拼在一起。由此带来两个必须记住的点：

- **只导出其中一个分片，装到别的设备上会失败**，因为缺的部分补不回来；
- **不同机型拿到的分片可能不一样**（按屏幕密度、CPU 架构分发），所以你导出的一整套，换到另一台手机上有小概率装不上或表现异常。

要备份这类应用，最稳的做法是在目标设备上重新装一份，而不是靠搬包。

## 四、安装器与安装来源记录

Thor 里除了管理已装应用，也能用来装包，这里有两条与「来源」相关的功能：

- **选择安装器**：安装时可以走系统安装界面，也可以借 Root 或 Shizuku 走受权限的安装通道，前者每步都要你点确认，后者更省事；
- **修复安装来源记录（Fix Store）**：有的应用因为安装渠道被改过，导致商店里显示不出更新或更新失败。这个功能把安装来源记录改回商店，**需要 Root 或 Shizuku 权限**，没有权限时该项不可用。

修复的是「记录」，不是应用本身的数据或版本，所以操作后大概率需要重新从商店更新一次才生效。

## 五、它能备份什么、不能备份什么

| 想做这件事 | Thor 能不能做 |
| --- | --- |
| 把应用本体导出成安装包 | 能，不需要额外权限 |
| 把应用的使用数据一起备份、换机还原 | 不能，导出的只是安装包 |
| 清掉某个应用的数据重来 | 能，见 [批量操作与应用列表筛选.md](批量操作与应用列表筛选.md) |
| 把导出的包装到另一台安卓设备 | 能，普通应用直接装；拆分应用按上文的限制处理 |

所以「用它做换机备份」的正确预期是：**带走的是应用，不是应用里的内容**。聊天记录、登录状态、本地文档这些要另外处理——多数应用自身提供了账号同步或应用内导出，优先用它们自己的方式。另外，个别应用（尤其是金融、支付这类）对自身安装包做了保护，导出的包在别的设备上可能装不回或装回后无法正常登录，遇到这种情况不是导出步骤错了，而是它本身的限制。

## 六、把包传给别的设备

导出的包本身就是一个普通文件，传输方式随你：数据线、即时通讯工具、局域网传输都行。传完之后在目标设备上打开安装包即可，遇到「应用未安装」，通常是下面三种原因之一：

- 目标设备已有同包名但签名不同的版本，要先卸载旧的；
- 目标设备的系统版本低于该应用要求的最低版本；
- 拆分应用只传了部分文件。

这三种情况的判断与处理，写在 [常见问题与排查.md](常见问题与排查.md)。
