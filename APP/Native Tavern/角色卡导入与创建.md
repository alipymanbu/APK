## 一、角色卡是什么、从哪进角色管理

角色卡是一份打包了角色设定的文件：名字、性格、故事背景、开场白、对话示例都写在里面，导入后应用按这套设定驱动 AI 回复。它是 SillyTavern 社区多年积累下来的通用格式，所以网上能搜到大量现成卡片。

进入方式：打开应用后点底部「角色」按钮；或从左上角的三横线菜单按钮进角色页。

## 二、四种添加方式

点「新建」或「+」按钮后可以看到以下入口：

| 方式 | 适合场景 |
| --- | --- |
| 创建新角色 | 心里已有设定，从零填一份 |
| 从文件导入 | 手里已有 `.json` 角色文件 |
| 从照片导入 | 手里已有 PNG 角色卡图片 |
| 从URL导入 | 想直接用 Chub.ai 等社区卡片的链接 |

从文件、照片或 URL 导入成功后，应用会先展示角色信息让你确认，再点「保存」进入角色列表。

## 三、支持的格式

官方文档列出的支持范围：

| 格式 | 说明 |
| --- | --- |
| PNG V2 | 图片里嵌 `chara` 文本块的角色卡 |
| PNG V3 | 图片里嵌 `ccv3` 文本块的角色卡 |
| CharX | ZIP 归档，含 card.json 与配套资源 |
| JSON | 纯文本角色文件 |

社区分享的卡片绝大多数是 PNG V2/V3 与 JSON 两种。注意区分：普通人物图片（插画、头像）不是角色卡——它里面没有嵌入设定数据，导入时会报「PNG图片内不包含任何文本块」，详见 [常见问题与解决方法.md](常见问题与解决方法.md)。

## 四、从 URL 导入与角色卡社区

选「从URL导入」，粘贴角色卡链接后点「导入」，确认信息并保存即可。官方文档说明其支持 Chub.ai 等平台的链接。

常被提到的社区站点（站点内容与授权政策以各站当时为准）：

| 站点 | 特点 |
| --- | --- |
| [Chub.ai](https://chub.ai/) | 规模最大的角色卡社区 |
| [Character Hub](https://characterhub.org/) | 角色收藏 |
| [Pygmalion.chat](https://pygmalion.chat/) | 社区创作 |
| [JanitorAI](https://janitorai.com/) | 角色库 |

导入失败时官方文档给了三种常见原因：角色被作者设为私有、平台未授权抓取、链接格式不对。卡片页面的分享链接和卡片文件的直链有时不是同一个 URL，用页面提供的导出/下载功能拿到真实卡片地址再试。

## 五、从零新建一个角色

选「创建新角色」后逐项填写：

- **头像**：角色图片；
- **名称**：角色的名字；
- **描述**：详细设定，外貌、经历、与你的关系都写在这里；
- **性格**：说话风格与行为倾向；
- **场景**：故事发生时的背景；
- **开场白**：角色说的第一句话，直接决定对话的起点氛围；
- **对话示例**：给 AI 看的示范回合，想让角色用某种口吻说话就照那个口吻写示例。

填完点「保存」。示例对话写得越像你期望的回复风格，角色后续表现越稳。

## 六、导出与迁移

换手机前不想丢角色：在角色列表长按某个角色，选「导出」，可选三种格式——PNG V3（带元数据的图片）、CharX（含全部资源的压缩包）、JSON（纯文本）。导出的文件在新设备上用第二节的「从文件导入」装回去即可。

角色聊起来之后还有不少进阶操作（多版本回复、群聊、书签分支），见 [聊天功能使用技巧.md](聊天功能使用技巧.md)；API 没配好的话角色也只会报错，配置步骤在 [API配置与密钥获取.md](API配置与密钥获取.md)。

## 七、角色卡之外的三类配套资源

SillyTavern 生态里与角色卡搭配使用的还有三类东西，官方说明对它们的格式保持兼容：

- **预设（Preset）**：一套生成策略与提示词组合，控制 AI 回复的文风与行为，不同预设下同一个角色会表现出明显差异；
- **世界书（World Info / Lorebook）**：装世界观条目的库，触发关键词出现时自动把对应设定注入上下文，长剧情里保持世界观一致的常用手段；
- **正则脚本**：对 AI 的输出做查找替换与排版处理，比如把特定标记渲染成你习惯的格式。

三者的导入入口与支持细节随版本演进，以你手上版本的实际界面为准（本文对应 v0.1.4，官方新版本的入口可能更多）。用上这些之后，模型与连接层面的选项见 [API配置与密钥获取.md](API配置与密钥获取.md)。
