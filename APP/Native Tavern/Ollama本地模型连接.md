# Native Tavern 连接 Ollama 本地模型教程

> 不想为聊天按量付费、或在意对话数据外流，可以把模型跑在自己电脑上：电脑装 Ollama，手机里的 Native Tavern 通过局域网连过去，本篇讲完整流程与连不上的排查。

## 一、什么情况下选本地模型

Native Tavern 官方支持把 Ollama 作为模型平台接入。与云端 API 相比，本地方案的特点：

| | 云端 API | Ollama 本地 |
| --- | --- | --- |
| 费用 | 按用量计费（部分平台有免费额度） | 不产生按量费用，吃电脑硬件 |
| 速度 | 取决于服务商 | 取决于电脑配置与模型大小 |
| 隐私 | 对话发到服务商 | 全程不出你的局域网 |
| 前提 | 注册、拿密钥 | 一台与手机同一 Wi-Fi 的电脑 |

先想清楚再动手：手机和电脑必须在**同一个局域网**里才能连上；出门在外（手机走流量）就连不回家里的电脑。另外，小模型对复杂角色卡的还原明显不如云端大模型，别期望过高。

## 二、电脑侧：装 Ollama、拉一个模型

1. 到 [https://ollama.com](https://ollama.com) 下载并安装（支持 Windows / macOS / Linux）；
2. 开终端，拉一个角色扮演可用的模型，例如：

```bash
ollama pull llama3.1:8b
```

3. 装好后 Ollama 会在本机 11434 端口提供接口，可以先在终端里 `ollama run llama3.1:8b` 试聊一句确认模型本身正常。

选模型可以参考下表（社区常用经验值，内存占用与效果以 [https://ollama.com/library](https://ollama.com/library) 当时的模型页为准）：

| 模型 | 内存占用参考 | 特点 |
| --- | --- | --- |
| llama3.1:8b | 约 8 GB | 指令跟随稳，通用起点 |
| qwen2.5:7b | 约 6 GB | 中文与多语言角色卡表现好 |
| mistral | 约 6 GB | 速度快的老牌选择 |
| gemma2:9b | 约 8 GB | 对话自然 |

两条经验：8 GB 内存是 7B~8B 模型的起步线，16 GB 更从容；**3B 以下的模型不建议配复杂角色卡**，设定再多它也记不住。

## 三、把 Ollama 开放给手机

Ollama 默认只接受本机（127.0.0.1）访问，手机直连会被拒绝。二选一：

- **桌面客户端**：在 Ollama 的设置里开启「Expose to network」（局域网访问 / 暴露到网络，不同版本叫法略有差异）；
- **命令行方式**：停掉当前服务后，用环境变量重启，监听所有网卡：

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

改完记得确认服务在运行（`ollama ps` 能列出已加载模型即正常）。

## 四、手机侧：在 Native Tavern 里填地址

1. 查电脑的局域网 IP：Windows 开终端跑 `ipconfig` 看「IPv4 地址」，一般是 `192.168.x.x`；macOS 在系统设置的 Wi-Fi 详情里看；
2. 打开 Native Tavern 的 API 设置（步骤见 [API配置与密钥获取.md](API配置与密钥获取.md)），新建一个连接：
   - **模型平台**：选 Ollama；
   - **API地址**：填 `http://192.168.x.x:11434`（换成你电脑的实际 IP）；
   - **API密钥**：本地连接通常留空；
   - **模型**：选你刚拉下来的那个；
3. 保存，看到连接成功即完成。

三个容易填错的点：协议是 **http** 不是 https；端口是 **11434**；手机与电脑必须在**同一个 Wi-Fi** 下。

## 五、连不上时按这张表排查

| 可能原因 | 处理 |
| --- | --- |
| Ollama 服务没在运行 | 电脑上跑 `ollama ps` 确认，没运行就重新启动服务 |
| 手机不在同一 Wi-Fi | 检查手机是否连到了家里 Wi-Fi，而不是流量或访客网络 |
| 没开放局域网访问 | 回到第三节，确认开了 Expose to network 或 OLLAMA_HOST=0.0.0.0 |
| IP 填错或 IP 变了 | 电脑重启后局域网 IP 可能变化，重新查一遍再填 |
| 电脑防火墙拦了 11434 端口 | 在防火墙设置里放行 Ollama 或该端口 |

连上之后，回复质量与角色一致性的调优思路见 [聊天功能使用技巧.md](聊天功能使用技巧.md)；本地模型聊久了忘设定的问题同样存在，对策也在那篇里。
