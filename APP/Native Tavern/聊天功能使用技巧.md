## 一、开始一段对话

三条路都通向同一个聊天界面，挑顺手的用：

1. 角色管理页里直接点角色；
2. 三横线菜单按钮里点最近聊过的角色；
3. 主界面点「开始聊天」再选角色。

进入对话后角色会先说出开场白（开场白在角色卡里定义，改它要去角色编辑里改）。

## 二、长按消息：一个菜单管六件事

长按任意消息（你发的、AI 回的都行）会弹出操作菜单：

| 操作 | 什么时候用 |
| --- | --- |
| 编辑 | 改错字、微调剧情走向，让上下文接着你改后的版本走 |
| 删除 | 把不想要的回合从上下文里拿掉 |
| 重新生成 | 这条回复不满意，让 AI 换个说法重来 |
| 左右滑动 | 在同一条消息的多个版本之间切换 |
| 复制 | 把这段内容拷走 |
| 书签 | 在这个位置建节点，之后可以从这里开分支 |

其中「编辑 + 删除」组合是对剧情最直接的控制：AI 跑偏了，直接把跑偏那段改掉或删掉，比反复重新生成省 token。

## 三、Swipe：一条回复留好几个版本

对同一条 AI 回复，点消息下方的左右箭头可以在已生成的版本间切换；点「+」会再生成一个新版本。每个版本都保留着，随时切回去。剧情探索期多刷几个版本再挑一条顺眼的往下聊，是这类应用的典型用法。

## 四、回复被截断：续写

长回复被截断时，在输入框发 `/continue` 命令，或点消息下方的「继续」，AI 会从未写完的地方接着往下写，而不是另起一段。斜杠命令不止这一个，完整清单见官方文档的斜杠命令与宏系统页面（`https://docs.nativetavern.com/features/slash-commands.html`）。

## 五、群聊：多个角色同场

群聊里可以放多个 AI 角色，让它们在同一场景里互动。官方支持五种响应模式：

| 模式 | 效果 |
| --- | --- |
| 轮流 | 按顺序一个个接话 |
| 随机 | 每轮随机挑一个角色回复 |
| 全部 | 所有角色都回复 |
| 指定 | 你手动点名谁回 |
| 自动 | AI 自己判断该谁接话 |

多人对手戏（比如辩论、聚会、冒险小队）用「自动」或「轮流」最省心；想精确控制谁说话就切「指定」。

## 六、影响回复走向的三个小工具

- **作者注释（Author's Note）**：写一句「接下来场景变得紧张」这类阶段性指示，它会动态注入上下文，比每次都在正文里叮嘱省事；
- **书签**：在关键剧情节点打书签，之后从书签处另开分支，一个存档试不同走向，不用怕把主线聊崩；
- **Markdown 输入**：输入支持 Markdown，用 `*斜体*` 标动作与心理、`**粗体**` 标重音，是酒馆类对话的通行排版习惯。

## 七、你自己的身份：用户人设

应用里可以配置「我的身份」（用户人设）：你的名字、形象与设定。角色会以这个人设为对象展开剧情；多角色群聊时，统一的人设也能让 AI 分清「你」是谁。人设入口在官方帮助中心叫「用户人设」，设置一次后各角色通用。

## 八、聊久了角色「忘事」怎么办

每次你发消息，应用都会把角色设定加上近期对话历史一起交给模型；一次能带的内容有上限，历史越长，最早的部分越先被挤出去——角色于是「忘了」开头的剧情。这不是故障，是所有这类客户端共有的机制。缓解办法：

1. **精简历史**：跑偏、废掉的回合直接删除或编辑合并（第二节的长按菜单），把上下文的位置留给有效剧情；
2. **书签开分支**：别在一条几千层的长线上硬聊，关键节点打书签另开分支，每条分支的历史都更短更聚焦；
3. **作者注释锚定**：把「当前场景要点」写进作者注释，它比位于历史深处的旧消息更起作用；
4. **长期设定写进角色卡**：重要的世界观与关系设定直接更新到角色的描述字段里，保证每一轮都带上。

各模型的可用上下文长度不同，同一个聊在不同模型上的「记忆长度」也会不一样，以你实际接入的模型表现为准。
