# 反编译与重新打包教程

> 走一遍完整流程：反编译一个 APK、改资源或代码、打包回去，以及构建失败时先检查哪几处。

## 一、先分清两条路

| 做法 | 改什么 | 适合 |
| --- | --- | --- |
| 快速编辑 | 只改名称、图标、包名这类基础信息，不重打包 | 几分钟出结果，见 [快速编辑与克隆应用.md](快速编辑与克隆应用.md) |
| 完整反编译 | 资源、代码全部展开成可读文件，改完再打包 | 改界面文字、翻译、动代码逻辑 |

动手前先想清楚要改的东西在不在「快速编辑」的清单里，在就不必走完整流程——大应用完整反编译又慢又占存储。

## 二、反编译

1. 在内置文件管理器里找到目标 APK 点它；已安装的应用可以从「应用」页先导出成 APK 再操作（导出到哪由设置里的输出目录决定）。
2. 弹出菜单里选「反编译」。
3. 勾选要展开的内容：
   - **反编译资源** —— 改界面文字、布局、图标必勾；
   - **反编译 classes.dex / 全部 \*.dex** —— 要动代码才勾；「全部 dex」管的是嵌在 assets 等子目录里的 dex 文件；
   - 需要时再勾「附加资源」。
4. 等待完成，结束时有提示音和弹窗（前提是设置里开了通知）。

想批量处理时可以多选同类文件再长按调菜单，但官方 FAQ 建议一个一个排队做：同时跑几个大包，内存可能不够。

## 三、改内容

- `res/values/strings.xml`：应用里绝大部分文案在这一处，改字、汉化从这里下手；批量翻译可以用内置翻译器，见 [应用翻译与汉化.md](应用翻译与汉化.md)；
- `res/` 下的其他 XML：布局、颜色、尺寸；
- `smali/`：代码在这个目录，格式是 smali 汇编。看不懂没关系，内置编辑器可以查看对应的 Java 源码来定位逻辑，再回来改 smali；
- 也可以不改，把准备好的文件直接复制进项目目录再打包。

编辑器带语法高亮与代码提示，支持导入自己的高亮主题；长文件里可以按关键字、类名、方法名快速查找跳转。

## 四、打包回去

1. 进入项目目录，点文件浏览窗口上方的「构建项目」。
2. 选资源编译工具：**aapt 或 aapt2**。新应用一般 aapt2 更顺；报错就换另一个试（官方 FAQ 给的第一解法）。
3. 需要的话勾选自动签名并选一个签名文件——没签名的包装不上，签名规则见 [签名与密钥管理.md](签名与密钥管理.md)。
4. 构建日志实时滚动，能看到每个阶段的输出；成功后日志停住，底部会直接问你要不要安装刚打好的包。
5. 成品 APK 存在项目根目录（`apktool.json` 旁边）；设置里开了「全部到输出目录」的话会自动挪过去。

## 五、构建失败先查这三处

1. **换 aapt / aapt2 再构建一次。** 大量「什么都没改也构建失败」的情况，换个资源编译工具就过了。
2. **翻日志里 Warning 级别的内容。** 失败原因基本都写在日志里，照着修。
3. **检查刚改过的 XML 有没有改坏语法。** 少了引号、标签没闭合，资源编译阶段就会失败。

## 六、电脑上的 Apktool 项目可以直接接过来

电脑上用桌面版 Apktool 反编译出来的项目（目录里是 `apktool.yml`）可以拿给 Apktool M 构建，构建前应用会自动把 yml 转成自己的项目文件。适合「电脑上展开、手机上打包」这类接力。

## 七、系统应用要多做一步

改系统应用（系统自带的桌面、相机之类）之前，先长按该 APK，用菜单里的导入项把对应的 framework 文件导进来——framework 一般在 `/system/framework/` 目录下，不导入的话资源解码会出错。导完之后反编译、构建和普通 APK 一样操作。

另外，反编译时勾「匹配到原始版本」可以保留原 META-INF 和清单哈希——注意这个模式下只有 smali 的修改会生效，`res/` 下改过的文件打包时会被丢掉，要改资源就别开它。
