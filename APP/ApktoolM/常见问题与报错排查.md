## 一、修改后的包装不上

按这个顺序查，命中率从高到低：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 快速编辑/重打包后安装直接失败 | 包没有签名（快速编辑默认「不签名」） | 重做一遍并选签名文件，见 [签名与密钥管理.md](签名与密钥管理.md) |
| 报「应用未安装」或 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名和已装版本不一致 | 卸载原版再装（数据先备份）；或改走克隆路线保共存 |
| 提示缺 split 组件 | 拆分包没合并完整 | 用 [拆分包合并教程.md](拆分包合并教程.md) 里的 Antisplit 合并，或快速编辑里去掉 `isSplitRequired` |
| 系统版本低于应用要求 | min SDK 不满足 | 快速编辑里降最低 SDK（装上了也可能缺功能） |
| 文件本身坏 | 下载不完整 | 比对 MD5 后重新获取 |

## 二、构建失败 / 反编译失败

1. **第一反应：换 aapt 或 aapt2 再来一次。** [官方 FAQ](https://maximoff.su/apktool/faq/faq_en.html) 把这条列为构建失败的首选解法，「什么都没改就是打不过」多半是它。
2. **翻构建日志里 Warning 级别的内容。** 日志实时滚动，失败原因基本都写在里面，照着修。
3. **刚改过的 XML 检查一遍语法。** 标签没闭合、引号漏了，资源编译阶段就会失败。
4. **内存不足。** 同时反编译几个大包容易把内存吃满，官方 FAQ 的建议是一个一个排队来。
5. **系统应用反编译资源报错。** 先长按该 APK 把 framework 导入，再反编译。

## 三、名称改不动、改了不生效这类怪事

- **名称栏是灰的**：应用要求的最低 SDK 高于你的系统版本，编辑被锁；先降最低 SDK。
- **「匹配到原始版本」模式下改了 res 却不生效**：这个模式本来就只保留 smali 的修改，`res/` 下改的文件打包时会被丢掉，要改资源就别开它。
- **删了 `res/values/public.xml` 里的条目后构建出问题**：资源 ID 的排布被打乱了。不确定用途就别动 public.xml 里的东西。
- **翻译功能找不到**：翻译器只在资源反编译之后的项目目录里才有入口，进法见 [应用翻译与汉化.md](应用翻译与汉化.md)。

## 四、拆分包合并相关

- 加固过的应用合并不了（社区教程普遍反馈），只能找未加固的包；
- 合并成品大了一圈：全选了分片所致，属正常；
- 要精确控制合并哪些分片，合并前那个勾选列表就是干这个的。
