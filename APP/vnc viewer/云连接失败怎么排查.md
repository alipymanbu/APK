# 云连接失败怎么排查

## 一、这种失败长什么样

用云端方式（登录账号那条路）连接时，Viewer 报 `VNC Server is not currently listening for cloud connections`，或者一直转圈后提示连接问题。它的含义很具体：**手机和电脑之间的链路没能通过 RealVNC 的云服务搭上**——问题多半在电脑侧或网络侧，不在手机 App 本身。

## 二、官方给出的排查顺序（逐条做）

按 RealVNC 帮助中心的清单，顺序执行：

1. **先看官方服务状态页**：打开 [status.vnc.com](https://status.vnc.com/)，确认 RealVNC 云服务没有在故障中。这一步别跳——官方社区出现过整段云连接不可用的故障日（如 2023-08-19，用户在社区集中反馈、状态页更新滞后），那种时候你做什么都没用，等恢复即可。
2. **电脑连网了吗**：电脑断网时云端方式必然失败。
3. **电脑是不是睡了**：睡眠 / 休眠中的电脑不会回应。Windows 在控制面板的电源选项里把「使计算机进入睡眠状态」设为「从不」；macOS 在系统设置里勾上「显示器关闭时防止电脑自动进入睡眠」。
4. **Server 里云端连接没被关掉**：打开 RealVNC Server 的 Options，在 Connections 一节确认云连接处于勾选状态。
5. **Viewer 里选对 team 了吗**：登录了多个团队 / 换过 team 的账号，列表里可能看的不是这台电脑所在的 team——切换到正确 team 再连。
6. **买订阅后 team 变了**：如果你是在试用 team 之外新买的订阅，需要把电脑加入那个付费 team 才连得上（在 Server 侧重新加入，线上管理页里可能要先删掉旧条目）。
7. **确认能看到电脑名与 team 名**：Server 的 Connectivity 段里要同时列出你的电脑名和 team 名；缺了就重新加入一次。
8. **Linux 特有**：Wayland 会话下连不上时，按官方条目把 Wayland 禁用（换用 X11 会话）。
9. **重启 Server，必要时重启电脑**：Windows 可在 `services.msc` 里重启 RealVNC 相关服务；Mac / Linux 在托盘图标上先 Stop 再启动。

## 三、网络侧的硬要求（代理 / 防火墙环境必看）

云端方式要能连上 RealVNC 的云服务，官方列的条件是：

- 终端要能访问 RealVNC 云服务的指定地址（TCP 443 端口，域名为 `*.services.vnc.com` 等，完整 IP 与端口清单见官方 Network Access Requirements 条目）；办公网的代理或防火墙拦掉这些出站连接时，云连接建立不起来。
- **SSL 拦截代理会让连接直接失败**：RealVNC 家的应用做严格证书校验，会「中间人式」重签证书的 SSL 代理（不少企业上网行为管理就是这么干的）会导致连接失败——这种情况要在代理侧把官方地址加入白名单，普通用户遇到多半只能改走直连方式。
- 只用直连方式（填 IP）的话，上面这些网络要求都不适用。

## 四、还是不行：看服务端日志

Server 侧的真实报错写在日志里，Viewer 上看到的往往只是表象：

- Windows：`C:\ProgramData\RealVNC-Service\vncserver.log`（同目录还有 `.bak`）
- macOS：`/Library/Logs/vncserver.log`
- Linux：`/var/log/vncserver-x11.log`

也可以在 RealVNC Server 的 Options → Troubleshooting 里点「Show in folder」直接打开。日志里出现的错误原文，可以再拿去官方帮助中心搜对应条目。

## 五、判断「该等」还是「该修」

| 现象 | 结论 |
| --- | --- |
| 状态页显示故障、多个设备同时连不上 | 等官方恢复，别反复重试折腾账号 |
| 只有你这台手机连不上、电脑在别的网络能连 | 查手机网络（有些 Wi-Fi 拦出站 443） |
| 只有这台电脑连不上 | 回到本文第二节逐条查电脑侧 |
| 报错是账号 / 密码类（不是云连接类） | 那是认证问题，见[连不上电脑或黑屏的排查方法.md](连不上电脑或黑屏的排查方法.md) |
