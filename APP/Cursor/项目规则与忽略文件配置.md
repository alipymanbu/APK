# Cursor 项目规则与忽略文件配置

> 想让 AI 每次都按你项目的规矩干活、并且不看不该看的文件，靠项目里的两类配置：规则（Rules）与忽略文件（.cursorignore）。本篇讲它们放哪、怎么写、什么时候生效。

## 一、规则：把「每次都要交代的话」固定下来

没有规则时，你得在对话里反复交代「用 TypeScript」「别动 dist 目录」这类要求。规则就是把它们写成文件，每次对话自动带上。

| 放哪 | 作用范围 | 怎么建 |
| --- | --- | --- |
| 项目根 `.cursor/rules/*.mdc` | 只对这个项目生效，可提交进 git 给全组共用 | 命令面板跑 **New Cursor Rule** |
| 项目根 `AGENTS.md` | 同上，写纯 Markdown 即可，最省事 | 自己建一个文件 |
| 用户规则（User Rules） | 你名下所有项目，随账号跨设备同步 | Cursor Settings 的 Rules 页里填 |

项目根那个单个的 `.cursorrules` 文件是更早的老写法，官方已列为将来废弃；老项目里见到它，建议迁到 `.cursor/rules`。规则冲突时的优先级是：团队规则 > 项目规则 > 用户规则。

## 二、规则怎么写才算写对了

官方文档给的建议，核心是「短、具体、可执行」：

- 一条规则别贪长（官方建议控制在 500 行以内，按主题拆成多个文件）；
- 写具体动作，不写空话——「新文件一律用 TypeScript」能执行，「代码要整洁」不能；
- 引用现成文件而不是复制内容：写「参考 `components/Button.tsx` 的写法」，比贴一大段代码不容易过期；
- 触发时机按需选：每次对话都生效（Always）、文件匹配才生效（globs）、AI 按描述自行判断、只在对话里 `@规则名` 时生效——高频要求选 Always，只对某类文件要紧的选按文件匹配；
- 从「AI 犯了两次同样的错」开始加，别一上来写一大本。

一个能直接抄的最小例子（`.cursor/rules/style.mdc`）：

```mdc
---
description: 项目代码风格约定
globs: src/**/*.ts
alwaysApply: false
---
- 新文件一律用 TypeScript
- 组件用命名导出，不用默认导出
- 改完跑 npm run typecheck 验证
```

## 三、忽略文件：不让 AI 看某些文件

在项目根建一个 `.cursorignore`，语法与 `.gitignore` 完全一样。被列进去的文件会从索引、Tab 补全、Agent、行内编辑、`@` 引用里排除：

```text
dist/
*.log
secrets/
config/credentials.json
```

要点：

- `.gitignore` 已有的、以及默认清单（`node_modules/`、`.env*`、各种锁文件、二进制与媒体文件）本来就忽略，不用重复写；
- 只想挡索引、但仍允许自己手动 `@` 引用的大文件（生成的产物之类），用 `.cursorindexingignore`；
- 用 `git check-ignore -v 路径` 可以验证某个文件被哪条模式匹配。

## 四、别把忽略文件当成保险箱

官方文档明确写着：`.cursorignore` 是「尽力而为」，不保证列出的文件绝不被上传；而且 Agent 跑终端命令、调 MCP 工具时不受它限制，仍可能读到被忽略的文件。真正的机密（密钥、凭证）应该放环境变量或密钥管理器，这个文件只当噪音过滤器用。

## 五、什么时候该配

- 同一句话在对话里说了两遍以上 → 写进规则；
- AI 总引用你不想让它看的目录 → 写进忽略文件；
- 团队协作 → 把规则提交进 git，全组共享同一套。
