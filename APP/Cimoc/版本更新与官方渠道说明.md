## 一、官方渠道一览

| 渠道 | 地址 | 能拿到什么 |
| --- | --- | --- |
| GitHub 仓库 | [https://github.com/Haleydu/Cimoc](https://github.com/Haleydu/Cimoc) | 源码、README、issues |
| GitHub Releases | [https://github.com/Haleydu/Cimoc/releases](https://github.com/Haleydu/Cimoc/releases) | APK 安装包、各版本更新说明 |
| Telegram 频道 | [https://t.me/cimoc_haleydu_Channel](https://t.me/cimoc_haleydu_Channel) | 版本与图源相关通知 |
| Telegram 群组 | [https://t.me/cimoc_haleydu](https://t.me/cimoc_haleydu) | 用户交流 |
| 微信公众号 | 在官方 README 中扫码关注 | 作者称最新版本会经此发布 |

项目为 GPL-3.0 开源，release 安装包由 CI（Travis CI）自动编译发布。官方 README 还提到一点：**如果 Release 页某个版本没有 APK，说明它要么正在编译、要么编译失败了**，过段时间再看即可。

## 二、版本号对不上号，以哪个为准

用 Cimoc 会遇到一个现象：**不同渠道出现的版本号并不同步**。例如 GitHub Releases 页面上最新的发布说明停在 1.7.20（其中提到 1.7.19 版本兼容安卓 4.x），而你在各种分发渠道看到 1.7.2xx 的包并不稀奇（第三方渠道甚至出现过 1.7.27x 的包，相邻的小版本号也会因渠道而异）——作者经由 Telegram、公众号等渠道发出的新包，不一定每次都同步到 GitHub Release。

给你的实操结论：

1. **你手上那份安装包的版本就是有效版本**，本文网盘里的 Cimoc 安装文件资源对应 1.7.275，安装后以「设置 → 应用」里显示的为准；
2. 想追新版本，去第一节表格里的渠道找最新的发布时间，而不是盯着某一个页面；
3. 系统要求没有官方写死的最低安卓版本数字，旧机用户可参考「1.7.19 兼容安卓 4.x」这条历史说明，具体以官方发布页为准。

## 三、pre-release 与正式版怎么选

Release 页里的 pre-release（预发布）版本用于先行测试：**每次启动都会弹检查更新提示**，这是设计如此。日常使用选正式版；想第一时间拿到修复就装 pre-release，容忍那个启动提示即可。

## 四、更新前后要注意的两件事

1. **更新前备份一次**：收藏、历史与设置都靠备份保护（方法见 [备份与恢复教程.md](备份与恢复教程.md)），官方更新说明里出现过「修复备份后在新手机恢复失败」这类条目，说明备份链路本身也在随版本修复。
2. **图源跟着版本走**：站点改版后旧版解析会失效，官方在更新说明里频繁出现「修复某源」的条目。搜不到某源的内容时，先升级版本再看 [搜索不到漫画的原因与解决.md](搜索不到漫画的原因与解决.md)。

## 五、别信「永久有效的地址」

这个项目最常翻车的点是历史发布过的各种地址会失效，已有两个先例：作者在 Gitee 上的图源列表仓库后来被封禁；更早发布在 Release 说明里的 `gitcode.net` 源列表地址也随域名变更加废弃。包括本文提到的所有地址在内，**任何地址打不开时，一律回到第一节表格里的官方渠道找最新入口**。
