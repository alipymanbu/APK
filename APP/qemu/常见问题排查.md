## 一、启动后 VNC 客户端连不上

按顺序查：

1. **顺序对不对**：必须先按播放键把虚拟机跑起来，再去 VNC 客户端连——启动器只在虚拟机运行期间开着 VNC 服务。
2. **地址与显示编号**：连接写法是 `127.0.0.1:0`，冒号后是显示编号，对应启动器里的「VNC端口」：端口填 0 就连 `:0`，填 1 就连 `:1`。
3. **地址别填错**：`127.0.0.1` 指本机；VNC 客户端和启动器在同一个手机上，不需要填局域网 IP。
4. **多开撞端口**：同时跑两台虚拟机，端口必须错开（0 和 1），两台都用 0 会互相顶掉。

## 二、按了播放键没反应 / 闪退

- 配置不完整或没保存：确认「保存配置」点过；「启动方式」与实际挂载一致——比如选了软盘启动，软盘A 却是「无」，就会直接失败。
- 虚拟运存太大：降到手机内存的四分之一以下再试，参数依据见 [性能参数怎么调.md](性能参数怎么调.md)。
- 镜像文件被移动过：手机里挪过文件位置的话，在镜像栏重新选一遍路径。

## 三、画面黑屏 / 提示没有可引导设备

- **VNC 连得上但黑屏**：大概率没有可引导设备。检查「启动方式」与挂载的介质是否对应：挂了安装 ISO 就选光盘启动；挂了装好系统的硬盘就选硬盘。
- **停在 No bootable device**：硬盘镜像里还没有系统。空磁盘不能引导，先挂安装盘把系统装进去（空盘的创建见 [镜像工具箱与磁盘管理.md](镜像工具箱与磁盘管理.md)）。
- **架构不匹配**：位数与架构对不上会直接起不来，对照下表检查「CPU架构」。

| 镜像 | 架构 |
| --- | --- |
| 32 位 x86 系统（多数老系统、32 位 Linux/Windows） | `i386` |
| 64 位 x86 系统 | `x86_64` |
| ARM / MIPS 镜像 | 对应架构项 |

## 四、跑到一半被杀 / 整机卡死

- 虚拟运存超了：安卓的内存回收会毫不犹豫干掉虚拟机，降到四分之一以下。
- 核数开多了：回到 1 核。
- 同时跑了多台：总内存加起来别超预算，端口也别撞。
- 手机在低电量模式或过热降频：虚拟机是重度负载，先解决手机侧状态再跑。

## 五、配置丢了 / 参数「不生效」

- 改完必须点「**保存配置**」，界面上的修改不会自动落盘。
- 「删除文件」删的是当前选中的那份 `.sh` 配置；误删只能重建一份并重新填参数。
- 「额外参数」里写了无效参数会让 QEMU 直接拒绝启动——清空这一栏确认能启动，再逐条往回加，定位是哪条参数惹的祸。

## 六、第一次打开反复要求安装 QEMU

- 初始化时中途退出过：解压不完整会反复触发安装询问。到系统设置里清掉这个应用的数据，重新走一遍首次流程（存储权限给够、解压期间别切走），完整步骤见 [下载与安装教程.md](下载与安装教程.md)。
- 存储权限没给：解压写不进去，也会一直卡在这一步。

## 七、关于跑 Windows 的一点说明

在这类模拟器里跑 Windows，安装镜像与授权要你自己通过正规渠道解决——启动器只是把镜像跑起来的工具，不附带任何系统的安装包。镜像怎么准备见 [镜像工具箱与磁盘管理.md](镜像工具箱与磁盘管理.md)；装到一半极慢、进桌面后只有小时级的启动速度，都是这类纯模拟方案的正常表现，专项流程与提速清单见 [手机装Windows全流程.md](手机装Windows全流程.md)。

## 八、虚拟机里上不了网

联网模式必须选 `user`，网卡先试 `rtl8139`、认不出再换 `e1000`；完整的排查顺序（手机先有网 → 模式 → 网卡型号 → DNS）单独写在 [虚拟机联网怎么设置.md](虚拟机联网怎么设置.md)。
