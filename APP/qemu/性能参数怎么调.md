## 一、先建立预期

手机上的 QEMU 走的是**纯软件模拟**（把虚拟机的指令逐条翻译给手机 CPU 执行），不是电脑上那种硬件加速虚拟化。这意味着：

- 轻量系统（KolibriOS、FreeDOS、微型 Linux）可以流畅到接近实时；
- Windows 这类桌面系统「能装能开」，但操作有可见的迟滞，适合验证与体验，不适合当主力干活环境；
- 调参的目标是「不崩、不被杀、尽量不卡」，不是快到飞起。

## 二、一套稳定的起步参数

下面是社区教程里反复出现、实测稳定的组合，第一次配置建议照抄，跑通之后再微调：

| 参数 | 推荐值 | 原因 |
| --- | --- | --- |
| CPU架构 | `x86_64`（32 位镜像用 `i386`） | 与镜像位数对应，拿不准先 x86_64 |
| CPU类型 | `qemu64`（或默认） | QEMU 官方默认型号，兼容最稳；另有推荐 `IvyBridge`、`core2duo` 的口径，遇到兼容问题再换 |
| CPU核数 | `1`（最多试到 2） | 软件模拟没有真多线程，核数开多互相抢资源反而更慢 |
| 虚拟运存 | 手机总内存的 1/4 | 再大安卓会杀后台、虚拟机崩溃 |
| 启动方式 | 装系统时选安装介质，装完改「硬盘」 | 一直停在安装盘上，重启会又进安装程序 |
| 图形界面 | `VNC`（端口 0） | 兼容性最好；SDL 更直接但各设备表现不一 |
| 网卡 | `user` 模式 + `rtl8139` | 用户态网络，不 root 也能上网 |
| 声卡 | `es1370` | 老型号，兼容面广 |
| 显卡 | `vmware` | 社区教程常用组合 |

不同版本的界面栏位可能略有出入，以你手上版本的界面为准；每一栏在界面上的位置见 [首次配置与运行镜像.md](首次配置与运行镜像.md)。

## 三、三个最容易踩的坑

1. **虚拟运存拉满**。给虚拟机分 2G、3G 看着豪爽，结果安卓一杀后台，虚拟机当场崩，进度全没。记住四分之一原则：8G 手机给 2G 封顶；轻量系统给 128~512M 就够。
2. **核数贪多**。「CPU核数开 8」这类写法在旧教程里流传很广，但实测大多数设备只能稳定跑 1~2 核，多开的部分是纯负收益。
3. **改完不保存**。所有栏位改完必须点「保存配置」，否则下次打开全部回到旧值，看起来就像参数「没生效」。

## 四、按场景微调

- **装系统阶段卡**：把虚拟运存降一档试试——安装程序对内存敏感，太紧太松都卡。
- **进入桌面后卡**：核数回到 1，并到虚拟机系统里把视觉特效关掉（比如 Windows 关掉主题动画）。
- **想同时开两台**：1.1.0 支持多开，但两台的内存加起来不要超过手机内存的四分之一，VNC 端口也要错开。
- **CPU 兼容问题**：个别系统对 CPU 型号挑剔（报错、装不上），按 `qemu64` → `core2duo` → `IvyBridge` 的顺序换着试。

## 五、重系统的现实预期

Windows 这类重型桌面系统在纯软件模拟下的表现，同类方案（Limbo、Bochs 等同样跑完整系统的模拟器）的第三方评测记录比较一致：启动以小时计、可用程序有限。这不是参数能解决的——参数只能决定「不崩」，决定不了「快」。具体到把 Windows 装起来的流程与装完的提速清单，专项写在 [手机装Windows全流程.md](手机装Windows全流程.md)。
