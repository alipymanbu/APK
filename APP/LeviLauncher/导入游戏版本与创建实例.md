# LeviLauncher 导入游戏版本与创建实例

LeviLauncher 把「装游戏」和「启动游戏」拆成了两步：先把一份官方安装包导入进来，再基于它建立一个实例，之后每次启动都是启动这个实例。本篇按这个顺序讲清楚每一步点哪里、等什么，以及一台设备上放多个版本时该怎么摆布。

## 一、动手前确认三件事

1. **官方客户端在本机装过、账号能登录**。启动时的授权校验依赖它，这一环不通，后面都是白忙。
2. **手上这份安装包是官方那份**。启动器按你给的文件启动游戏，来源不明的包既跑不稳，也没有使用的必要。
3. **存储留够**。一个实例加上游戏本体数据，要按几个 GB 来准备，官方给的底线是 2 GB、建议留 5 GB 空闲。

## 二、导入安装包，建立实例

1. 打开 LeviLauncher，在首页找到导入安装包的入口，选中你放在手机里的那份官方 APK。
2. 确认后启动器会解包并准备数据，这一步要等一会儿：包越大、机器越旧，等待越久，期间保持应用在前台。
3. 解包完成后建立实例（有的界面叫「创建实例」），给它起一个名字。
4. **先启动一次游戏，把「游戏存储」改成外部**，再回来装资源包、放模块。安卓 11 及以上系统对 `Android/data` 的访问有限制，数据放在外部目录才便于读写；这么做的原因和目录位置见 [游戏数据存在哪与安卓11存储限制.md](游戏数据存在哪与安卓11存储限制.md)。
5. 回到首页/版本列表，选中刚建好的实例，点启动。

名字别只留版本号，过几天就认不出来了。按用途命名更实用：

| 名字 | 用途 |
| --- | --- |
| `Release 生存` | 正式版，日常玩的那个 |
| `Preview 测试` | 预览版，试新内容用 |
| `模块调试` | 专门拿来试模块和资源包，坏了直接删 |

## 三、版本隔离：开还是不开

隔离的含义是：打开后，这个实例的游戏数据存在它自己的工作目录里，而不是和默认数据目录混在一起。差别只有在「同时存在多个实例」时才看得出来。

| 你的情况 | 建议 |
| --- | --- |
| 只玩一个版本，也不折腾模块 | 可以不开 |
| 正式版和预览版都要放 | 开 |
| 要试模块、资源包，又不想连累主存档 | 开 |
| 不同用途的世界想各放各的 | 开 |

官方对这条的态度是：隔离不是必须的，但在测试环境、预览版、带模块的场景下强烈建议打开。不开隔离时，多个实例读的是同一份默认数据目录，你换一个实例进去，看到的还是原来那批世界和资源包——拿这种实例做测试，改动会直接落到日常存档上。

## 四、一个实例就是一个版本

- 安装新版本、重命名、删除、启动，都在版本/实例列表里完成，多个版本可以同时留着互不影响。
- 删除实例要当心：它会带走这个实例托管的那份数据。动手前先把重要存档导出备份，做法见 [多账号与存档资源包管理.md](多账号与存档资源包管理.md)。
- 实例多了以后按用途分类命名，比按版本号好认；哪个是主力、哪个是可随时删的，一眼能分清最好。

## 五、启动不了时按这个顺序排除

1. 官方客户端还在不在本机、微软账号还登着吗——启动卡在验证那一步，多半是这里。
2. 换一个新建的干净实例对照测一次。它能进、原来那个不能进，说明问题出在原实例里的内容上，先移除最近加的模块或资源包。
3. 看剩余存储还有多少，解包和启动都要写临时数据。
4. 上面都排过还是不行，按现象查 [常见问题与排查.md](常见问题与排查.md)，或带上机型、系统版本、启动器版本和复现步骤去官方仓库提问题。
