## 一、写入前必须知道的三件事

1. **写入需要带写权限的密钥**。很多卡用 A 钥读得动、写要靠 B 钥；访问条件没开放写权限的块，密钥对了也写不进去。
2. **写入不可逆**。数据覆盖上去没有撤销这一说。往任何一张卡写之前，先用 Read Tag 把这张卡的现状存一份 dump 备底。
3. **原厂卡的块 0 写不了**。0 扇区 0 块（制造商块，存 UID）在正规渠道的卡上是只读的——这是芯片出厂就封死的，不是软件限制。

## 二、四种写入方式对照

主菜单 → Write Tag，四条路：

| 方式 | 干什么 | 典型场景 |
| --- | --- | --- |
| Write Block | 按块写，一次 16 字节十六进制 | 只改某个块的少量数据 |
| Write Dump | 把整份 dump 按块写入 | 把一张卡的内容写到另一张（克隆） |
| Factory Format | 数据块清零、尾块恢复出厂值 | 把一张卡恢复到出厂状态 |
| Incr./Decr. Value Block | 对标准值块做加值/减值 | 卡里存的是余额型的值块 |

## 三、克隆一张卡到另一张（Write Dump 流程）

1. 用 Read Tag 把源卡完整读出来，Save 成 dump（源卡上读不出的扇区，之后也没有数据可写到目标卡）；
2. 再把**目标卡**读一遍、存 dump——这是写坏时的救命备份；
3. Write Tag → Write Dump，选源卡的 dump；
4. 勾选要写入的扇区与块（默认全选；源卡读不出的扇区先取消勾选）；
5. 贴上目标卡开始写，过程中别挪卡。

源卡与目标卡容量不同（1K / 4K）时注意别勾选目标卡上不存在的扇区。

## 四、块 0 与特殊卡（magic tag）

想把 UID 也一起克隆，就得写块 0，这只有特殊卡支持：

| 卡的类型 | 市面常见叫法 | MCT 能不能写块 0 |
| --- | --- | --- |
| 原厂卡 | — | 不能，只读 |
| gen2 / CUID | 可写 UID 卡 | 能，直接写 |
| FUID / UFUID | 一次性或混合型写 UID 卡 | 官方说明未充分验证，需自行测试 |
| gen1 / gen1a / UID | 需要特殊指令序列解锁的卡 | 不能——安卓 NFC API 发不出那组指令 |

另外两条官方明说的规则：在特殊卡上写 UID 时，BCC、SAK、ATQA 三个值必须填对，乱填可能把卡写死；如果只想换 UID 不搬数据，用 Tools 里的 Clone UID 工具更省事（见[内置工具用法一览](内置工具用法一览.md)）。

## 五、Factory Format 的具体数值

恢复出厂 = 所有数据块写成 `00000000000000000000000000000000`，每个扇区的尾块写成 `FFFFFFFFFFFFFF078069FFFFFFFFFFFF`。只想恢复个别块的，用 Write Block 手动写这两串值也一样。

写入反复失败时，先解码目标扇区的访问条件、确认写权限在哪把钥匙上，再回头检查密钥文件用没用对——排查思路见[不兼容设备与常见问题](不兼容设备与常见问题.md)。
