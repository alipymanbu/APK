# VPlayer 支持哪些格式与编码

> 官方的格式清单看着很长，这篇把它拆成「容器 / 视频编码 / 音频编码 / 传输协议」四张表，并给出「这个文件到底能不能播」的判断顺序。

VPlayer 是安卓上一款靠硬件解码吃下多种容器与编码的本地播放器，选它的人多半是手上有系统自带播放器打不开的文件。它的官方清单把支持范围写成四项独立能力：能装住什么容器、能解什么视频编码、能出什么声音、能接什么传输方式。这四关得一起过同一个文件才能正常播放，所以下面分开列，最后给一套判断顺序。

## 一、容器：文件本身是什么类型

容器是文件的外壳，扩展名就是这个东西。官方清单里列出的有：

| 类别 | 扩展名 |
| --- | --- |
| 常见网络片源 | `MP4`、`M4V`、`FLV`、`MKV` |
| 移动端录制 | `3GP`、`3G2` |
| 老牌封装 | `AVI`、`MOV`、`ASF`、`WMV` |
| 广播 / 光盘转录 | `TS`、`TP`、`MTP`、`M2T` |

对读者最实际的一条：**`MKV`、`FLV`、`AVI` 是大多数人真正用到 VPlayer 的理由** —— 它们在不少安卓系统自带的播放器里会直接提示打不开，原因通常不在外壳，而在下一节的编码。另外 `.rmvb` 也常被归进这一类，但官方清单没把它算在容器里，而是列在下一节的软件解码编码中，判断时要按编码那一栏看，不要因为这张表里没有就判定放不了。

需要提醒的是，**容器在清单里不等于一定能播**，还要看里面的视频编码和音频编码是否也被支持。一个 `MKV` 可以装 H.264，也可以装别的更冷门的编码，两种情况结果不一样。

## 二、视频编码：硬解一套、软解一套

这是最容易出问题的一关。官方把视频编码分成两组，两组的脾气完全不同：

| 解码方式 | 官方列出的编码 | 实际表现 |
| --- | --- | --- |
| 硬件解码 | MPEG-4、H.264/AVC、H.263 | 交给设备的解码芯片做，省电、发热低，高码率的 720p / 1080p 也能跟上 |
| 软件解码 | MPEG-4、H.264、RMVB、XVID、MS MPEG-4、VP6、H.263、MPEG-1、MPEG-2、HEVC、VP9 | 全靠 CPU 算，兼容面广得多，但吃性能、耗电、机身容易热 |

几点要知道的：

- **两组有重叠，重叠的那几个优先走硬解。** H.264 和 MPEG-4 在两边都出现，说明它们既能硬解也能软解 —— 硬解那一档能满足时就别强制软解，否则白白多耗电。
- **RMVB、XVID、VP6、VP9、HEVC 只在软解那一列。** 这些就是系统播放器最容易翻车的地方，也正是需要一个第三方播放器的主要原因。
- **硬解能不能用，最终取决于你的设备。** 官方描述里对此的说法是「视频能力取决于设备硬件解码器的能力」，同一部片子在不同芯片上表现不一样。所以「别人能放」不等于「你也能放」。
- **遇到 HEVC 和 VP9 要有预期。** 这两个编码本身很吃性能，官方是放在软解一列的。老机器上放 1080p 的 HEVC 会明显吃力，换成 H.264 的片源往往比换播放器更管用。

## 三、音频编码与多音轨

| 项目 | 官方列出的范围 |
| --- | --- |
| 音频编码 | AAC、Vorbis、FLAC、MP3、MP2、WMA |
| 多音轨 | 支持多音轨切换 |

这里有两个常见现象：

1. **有画面没声音。** 视频能出画面，说明容器和解码没问题，问题多半落在音轨上 —— 先切一条别的音轨试，双语片源里第一条音轨是空轨的情况并不少见。
2. **无损音乐文件（FLAC）也能识别。** FLAC 在列表里，所以音轨是无损的 MKV 一类文件不需要额外处理。

至于怎么切音轨、切完之后字幕跟不跟得上，见 [字幕加载与乱码解决.md](字幕加载与乱码解决.md)。

## 四、字幕与传输：另有两篇专讲

- **字幕格式**：官方列出了 SSA/ASS、SAMI、SubViewer、SubRip（`.srt`）、MicroDVD、MPL2、WebVTT，另外支持从 MKV 里提取字幕、支持多字幕轨、支持多字节字符集。加载方式与乱码处理单独写在 [字幕加载与乱码解决.md](字幕加载与乱码解决.md)。
- **传输协议**：官方列出 HTTP、RTP/RTSP/RTMP、MMS，以及多码率的 HLS；网络来源那边还提到 NAS、局域网、UPnP、DLNA、DVR 等。这些入口怎么用、NAS 上的片子怎么放，见 [局域网与网络视频怎么播.md](局域网与网络视频怎么播.md)。

补充一句许可信息：VPlayer 的官方描述里写明它使用了 FFmpeg 的代码，按 LGPLv3 授权。这不影响你使用，只是说明它的解码能力来自一个成熟的开源解码库。

## 五、判断一个文件能不能播：按这个顺序试

不要一上来就换播放器，按下面四步走，多数情况第二三步就能定位：

1. **看扩展名**。在第一节的表里？在，进下一步。不在的先看一个例外：`.rmvb` 要按下一节的编码来判（官方把它列在软解那一栏），其余不在表里的扩展名基本可以直接放弃，转成 `MP4` 再说。
2. **看视频编码**。这需要工具：手机端多数播放器在播放界面的菜单里有「媒体信息」一类的入口，电脑上则可以用 MediaInfo 这类专门读媒体信息的工具。看视频轨的编码是不是在第二节两张表里。HEVC、VP9、RMVB 这类只走软解的，要接受掉帧的可能。
3. **切换解码方式再试一次**。同一个文件，硬解失败软解成功、或者反过来，都有可能出现 —— 这是最省事的一次尝试，不用动文件本身。
4. **换一个片源对比**。找一部你确定能正常播放的片子放一下：正常的能放、这个放不了，基本可以判断问题在这个文件上；正常的也放不了，多半是设备或权限层面的问题，去找 [常见问题与排查.md](常见问题与排查.md)。

如果一部片子四步走完还是不行，那就不是 VPlayer 的设置问题，而是这个文件的编码超出了这类播放器的能力范围 —— 转码成本最低，继续折腾播放器通常没有收益。
